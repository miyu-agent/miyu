## 施工单 LW-8：核心启动、连上头这一路少执行用不着的代码

状态：做完，待验收（2026-11-22）；门禁 `cargo xtask check` 照项目主人 2026-11-22 定，这一批改完再一起跑。LW 线（轻量化）的第八步，接 2026-11-21 的轻量化研究第三节 3.1、第五节第 8 项。

### 目的

LW-1 以后核心的发行程序按执行顺序排函数，执行过的函数整个留在内存里，所以「少执行」就等于「少占」。2026-11-21 用 QEMU 记下的执行过的函数里有两类用不着的：核心进程为了认出 `miyu core [--idle-seconds N]` 搭了整棵命令行树（266 kB）；一批只有一处调用的大函数被编译器并进了分派它们的那一个，走到其中一支也算执行过整块。这一步把前者换成快路，把后者拆开，行为不变。

### 蓝图改哪几节

- `core.md`「起来的先后」：开头加「进核心之前」一段，写快路认哪三种写法、认不出的照整棵树解析、为什么。
- 拆函数不改蓝图：只是代码在哪个函数里，协议、报错、先后都没变。

### 不做什么

- 不改协议、不改任何报错的字、不改起来的先后。
- 不动 `miyu-heap`、`crates/miyu-core/src/models.rs`、时区相关的代码（另有施工在改）。
- 不为拆而拆：执行过的函数里没走到的那一截主要是展开（unwind）时的收尾、出错时逐个放掉已经造好的字段的，这些不是分支，拆不出去；`panic` 仍然展开（`Cargo.toml` 的 release 一节）。
- 照数据走的循环（列会话、列包、一家家供应商）不拆：真用时这些都会走到。

### 验收

1. `cargo test -p miyu`：`the_fast_way_into_the_core_parses_as_clap_does` 拿三十多组参数（对的、写错的、带 `--help`、`-V` 的、管理用的子命令）对照快路和整棵树的结果，一样；不是 UTF-8 的参数快路不认。
2. 改到的 crate（`miyu`、`miyu-kernel`、`miyu-assemble`、`miyu-basesystem`、`miyu-store`、`miyu-endpoint`、`miyu-core`）的 clippy、测试全过，已有测试的断言一条没改。
3. 照下面「量到的」的办法量：连上头、空闲时执行过的函数变少。

### 风险

- **快路认的和 clap 认的不一样**：快路只认三种写法，秒数用同一个 `str::parse`，其余一律交给 clap；测试逐条对照。
- **拆出去的分支借用、生命周期不对**：都编过了；异步的那几处是把要等的 future 放到堆上（`miyu_kernel::apart::future`），每次多一次分配，只在答一条请求、订阅一次流时发生。
- **拆开以后热路径慢**：会话照输入分派多一次函数调用，相对一次分派里的事可以忽略。

### 量到的

量法：核心放进 QEMU 用户态模拟器（`qemu-x86_64 -d in_asm`），真的终端界面原生连上来，分阶段记下执行过的指令；「函数口径」是执行过至少一条指令的函数的整个大小之和（排函数以后约等于留在内存里的代码），「指令口径」是执行过的指令字节。改前是 main 上的 ebe63021d，改后是这一步，都是 `cargo build --release` 的 `miyu`，同一份发行包目录、同一个剧本。

没拆成、没留下的：

- `ResourceRoot::core_texts`（48.8 kB，执行到 14 kB）：没走到的是哪一份读不出来时逐个放掉已经读好的字段，不是分支；把读法挪进不内联的函数量下来只少 0.3 kB，撤回。要省得改成读不出来时先记下、读完再报，这会改变读的先后，不做。
- `Core::new`、`miyu_core::main`、`start`、`run` 剩下的、`methods::call` 里 `model.list`、`command.catalog` 的那几支：没走到的多是展开时的收尾（`panic_in_cleanup`、放掉临时值）和出错时的那几行，拆不出去。起不来时的几个原因（`not_started.rs`）单拎出去只少 0.7 kB，撤回。
- 握手认凭据（`hello`）、`config.get` 要每一层的、`model.list` 要刷新的：拆了反而大了或者一样，撤回。
- `run` 里把 `serve_then` 整个放到堆上：起来的那一段并进了 `start`，加起来反而大了 7 kB，撤回；留下的是 `serve_then` 里停下时的那几截。
- `models::begin` 里照整份目录重建记下的那一份（拆了少 1.4 kB）：在 `crates/miyu-core/src/models.rs`，这一步不碰那个文件，撤回。
- `event::Event` 的 `Clone`（20.8 kB，执行到 2.5 kB）：是 `derive` 出来的，要手写才拆得开，不做。
- 「连上头、空闲」没到 3.2 MB：剩下最大的是连上来时真的走到的（TLS 握手、HTTP 客户端约 400 kB，模型列表、包列表），和上面说的展开收尾。

量尺（.91，`cargo xtask perf --idle-wait 0 --gate 1`，排过函数、打包过重定位表）：核心空闲、没有会话载入 8.2 → 7.6 MB；核心空闲、连着一个头 12.0 → 11.7 MB；冷启动到 `ready` 的中位数 21.0 → 20.9 ms；时间类的各行都在原来的抖动以内。
