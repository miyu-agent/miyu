## 施工单 DOC-15：用户手册、开发者文档按语言分目录，根 README 跟着适配

状态：待验收（2026-11-18）。项目主人定：文档是「一个文档目录，里面按语言分子目录，再往下才是完整的文档」；根 README 做好适配，框架用他写好的，他写好的、给用户看的字不改，只有留给我示意的地方由我填。

### 改了什么

- 搬目录（`git mv`，74 个文件）：
  - `docs/guide/<页>.md` → `docs/zh/guide/<页>.md`，`docs/guide/<页>.en.md` → `docs/en/guide/<页>.md`；`docs/dev/` 同样。两边的页名一样，一一对应。
  - `docs/README.md` → `docs/zh/README.md`，`docs/README.en.md` → `docs/en/README.md`；`docs/README.md` 新写成两行的入口，指到两种语言的总目录。
- 链接：全仓库的 Markdown 里指到这些页、和这些页里指出去的相对链接照新位置改写，593 处（脚本逐个照原位置解析、照新位置重算）；`SECURITY.md`、`packaging/README.md` 里的 5 处在内。互指的那一句的字从文件名改成「English」「中文」。
- 两份总目录里讲目录结构的句子照现状改。
- 根 README 的中文版 `README.zh-CN.md`：项目主人自己写的那一份（他写在主检出目录里、还没提交的：介绍、预览图片、极致性能、快速上手、许可证、Star 趋势），连同五张截图 `docs/assets/{web-use,tui-use,web-new,tui-new,web-settings}.webp`。和他的文件逐行比，只多三处：
  - 最顶上加一行居中的「🚧 施工中」（英文版是「🚧 Under construction」），项目主人让加的。
  - logo 和标签下面、「# Miyu」上面加语言切换（`English | 简体中文`，居中），前后各一个空行。原来「# Miyu」紧挨着上面的 `</p>`，Markdown 会把它算进那一块 HTML，标题渲染成一行「# Miyu」的字；隔开以后是标题。
  - 「快速上手」一节「请阅读以下文章…」后面是留给我示意的，接上两行链接：快速上手、完整文档，都指到中文文档。
- `README.md`：英文版，仓库页默认显示它（项目主人定）。照中文逐段翻，骨架（logo、Star 趋势）原样，「官网」「赞助」两个标签换成 Website、Sponsor；语言切换在同一个位置；链接都指到英文文档。项目主人定：中文的 README 进中文文档，英文的进英文文档，中文里不再给英文的跳转。

头两版我做错了：先是自己另写了四段正文，后来又把快速上手的稿子整份放了进去。项目主人说的「框架用我已经写好的」指的是他这一份 README，我没去看主检出目录里没提交的文件。

### 没搬的，和为什么

`docs/authors/`（作者教程）、`docs/reference/`（协议参考）照旧是两种语言放在一个目录、英文叫 `<页>.en.md`。它们接着门禁和测试：`xtask` 的 `reference.rs`、`anchors.rs`、`frozen.rs` 写死了 `docs/reference`，五处测试 `include_str!` 着这两处的文件，CI 的路径规则里有 `docs/authors/**`；别的会话每加一个协议方法都要改 `docs/reference` 两份。要搬得连门禁的代码一起改、挑一个没人在改的空档，已交主会话排。

### 核实

- 新写的检查脚本（中英两棵树一页对一页：行数、标题层级、表格行列、代码块个数、署名、互指；所有相对链接指得到文件和标题；不串语言）：中文 37 页、英文 37 页，1056 个链接，问题 0。
- 根 README 和项目主人的文件逐行比：只有上面说的两处不同；中英两份里指到的文件、图片都在，都不指到另一种语言的文档，标题都渲染成标题；五张截图和他那几份逐字节相同。
