## 施工单 WD-9：`/undo` 在界面上统一叫「撤回」

状态：做完了，等合并（和 WD-8 在同一个分支 `step/WD-8-安装脚本只认新版本号` 上，各一个提交）。主会话 2026-11-22 派；项目主人同一天定：`/undo` 在界面上统一叫「撤回」，不叫「撤销」；`/restore` 仍然叫「恢复」。

### 改了什么

核心的字表（`resources/core/human`）里没有 `/undo` 自己的句子：这条命令由各个界面实现，核心这边给人看的字在命令行、帮助页和拒绝原因里。

| 位置 | 原来 | 现在 |
|---|---|---|
| `miyu undo`（`crates/miyu-cli/src/language/undo.rs`） | `已撤销「{said}」这一轮` | `已撤回「{said}」这一轮` |
| | `已撤销「{said}」起的 {turns} 轮` | `已撤回「{said}」起的 {turns} 轮` |
| | `已撤销最后一轮` | `已撤回最后一轮` |
| | `已撤销压缩，上下文恢复到压缩前` | `已撤回压缩，上下文恢复到压缩前` |
| | `已撤销清空，上下文恢复到清空前` | `已撤回清空，上下文恢复到清空前` |
| `miyu restore` | `已恢复撤销的那一轮` | `已恢复撤回的那一轮` |
| `miyu redo` | `· 已撤销「{said}」这一轮，重新做`、`· 已撤销最后一轮，重新做` | `· 已撤回「{said}」这一轮，重新做`、`· 已撤回最后一轮，重新做` |
| 帮助页 `help/zh` 的 `miyu.txt`、`undo.txt`、`redo.txt`、`restore.txt` | `撤销上一轮`、`恢复上一次撤销的内容` | `撤回上一轮`、`恢复上一次撤回的内容` |
| 拒绝原因 `nothing_to_revert` | `没有可撤销的回合。` | `没有可撤回的回合。` |
| 拒绝原因 `nothing_to_unrevert` | `没有可恢复的撤销。` | `没有可恢复的撤回。` |
| 拒绝原因 `restoring` | `正在撤销或恢复。` | `正在撤回或恢复。` |

- 英文没有改动（`undid`、`Nothing to undo.`）。命令行和拒绝原因只有中文、英文两种，没有日文。
- 给模型看的字没有改动。
- 核心字表里 `/loop` 的三句回执（FX-12）原来就写「撤回」，没有变化。
- 代码注释、测试的名字和说明里的「撤销」是内部的说法，没有改动。

### 连带的修改

- **测试**：`miyu-cli`、`miyu`、`miyu-endpoint` 的 7 个测试文件里逐字断言的句子换成新话。
- **样本**：`internal/designs/samples/cli/` 的 `undo-text.txt`、`undo-clear-text.txt`、`undo-jobs-text.txt`、`redo-text.txt`，蓝图里对应的样本块和两页帮助的样本块同步。
- **蓝图**：`cli/undo.md`、`cli/redo.md`、`compaction.md`、`protocol.md`、`kernel/history.md` 里引用的这几句程序原话换成新话，一共 25 处。蓝图自己的行文仍然写「撤销」，没有改动。
- **手册**：中文手册 20 页里说 `/undo` 的「撤销」都改成「撤回」，一共 67 行，包括会话页的小节标题「撤回、恢复、重做」和指向它的链接。`docs/zh/dev/manifest.md` 里「批准会被撤销」说的是撤销对能力的批准，不是 `/undo`，没有改动。英文手册没有改动。快速上手和仓库首页是项目主人手写的页，里面没有这个词。

### 留给其他会话的

- 终端界面、网页界面、通讯平台自己的字表和菜单里的「撤销」，由界面那边自己修改。
- 各界面的测试如果钉了上表的拒绝原因或者命令行的句子，换钉时按上表修改。
