# 接 MCP 服务

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

现成的 MCP 服务（Model Context Protocol）可以直接接入 Miyu：核心启动服务的进程，通过标准输入输出和它用 MCP 通信；如果服务只提供一个网址（Streamable HTTP），核心就直接连接那个网址。服务提供的工具会登记给 AI 使用。接入的方法有两种：写进配置（只给自己用，最快），或者做成一个软件包（可以发给别人）。

## 最快：写进配置

打开 `~/.miyu/etc/config.toml`（或者运行 `miyu config edit`），每个服务写一张表：

```toml
[mcp.files]
command = ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/home/me/notes"]
```

如果服务只提供网址（例如 GitHub 这类服务），就写 `url`，令牌写在 `bearer` 里：

```toml
[mcp.github]
url = "https://api.githubcopilot.com/mcp/"
bearer = { secret = "github" }       # 令牌用 miyu provider login 或设置页存入；发送时写成 Authorization: Bearer …
```

保存以后立即生效，不需要重启。终端界面、网页界面的 `软件包` 页会显示服务有没有在运行；运行 `miyu check` 可以检查配置有没有写错。

有的服务只接受浏览器授权、不能发个人令牌（例如 Notion、Linear 这类服务），这种服务只写 `url`，不写 `bearer`。它会停在「要登录」状态（`needs_login`），此时运行 `miyu mcp login <服务>`，在浏览器里点击同意就连上了；令牌会存进密钥文件，你不需要经手，令牌快过期时核心会自动续期。如果浏览器在另一台机器上，授权完成后把地址栏里的整段地址粘贴回命令行即可。不再使用时运行 `miyu mcp logout <服务>`。

## 做成一个包

只带 MCP 服务的软件包，文件夹里只需要一份 `package.toml`：

```text
notes-mcp/
└── package.toml
```

```toml
[package]
name = { en = "Notes", zh = "笔记" }

[[mcp]]
name = "notes"                                    # 服务名：以小写字母开头，只包含小写字母、数字和 -，共 1 到 32 个
command = ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/srv/notes"]
env = { TOKEN = { secret = "notes" } }            # 可以不写；值可以是文字，也可以引用密钥 { secret = … } 或环境变量 { env = … }
venues = ["local"]                                # 可以不写：给哪种会话使用，不写时只给本机的会话
timeout_ms = 600000                               # 可以不写：一次调用最多等待多久，范围 1000 到 3600000
clicall = false                                   # 可以不写：false 表示 AI 不能在命令里用 miyu call 调用这个服务的工具
```

如果包只带服务、不带程序，就不需要写 `protocol`、`[command]`、`[process]`。一个包可以带多个服务；扩展包也可以带服务，这些服务会跟着扩展一起启动和停止。

安装：运行 `miyu pkg install ./notes-mcp`。只带服务的包安装以后是**关闭的**，到 `软件包` 页里打开它即可。

## 每一格

下面逐格说明一个 MCP 服务可以写的内容：

| 格 | 说明 |
|---|---|
| `name` | 服务名（在配置里就是表名），以小写字母开头，只包含小写字母、数字和 `-`，共 1 到 32 个；在全局范围内不能重复。 |
| `command` | 命令和参数。第一项先在包的 `bin/` 里查找，找不到再到 `PATH` 里查找（例如 `npx`、`uvx`、`docker` 这类）。`command` 和 `url` 写其中一个。 |
| `url` | 服务的网址，以 `https://` 开头；`http://` 只能用于本机的服务（`localhost`、`127.0.0.1`），其他机器上的服务不会连接，以免令牌被明文发出去。`url` 和 `command` 写其中一个。 |
| `bearer` | 和 `url` 一起使用，表示令牌，发送时写成 `Authorization: Bearer <值>`；写法和 `env` 的值相同，令牌请写成 `{ secret = … }`。 |
| `headers` | 和 `url` 一起使用，表示其他请求头，例如 `{ X-Api-Key = { secret = "key" } }`，写法和 `env` 相同。 |
| `env` | 传给服务的环境变量。密钥写成 `{ secret = "<名字>" }`（密钥用 `miyu provider login` 或设置页存入），不要把值直接写在清单里。 |
| `venues` | 从 `local`、`private`、`group` 里选一个或几个，分别表示本机的会话、聊天平台的私聊、群；不写时只给本机的会话。 |
| `timeout_ms` | 一次调用最多等待多久，单位是毫秒，范围 1000 到 3600000；不写时是 600000。 |
| `clicall` | AI 在命令里写脚本时，能不能用 `miyu call` 调用这个服务的工具；不写时可以调用。如果服务会写入东西、发送东西，就写 `false`。 |

## AI 看到的样子

- 工具名是 `mcp__<服务名>__<工具名>`，工具的说明和参数使用服务给出的原样（说明超过 2048 个字时，超出的部分会被截掉）。
- 在预设里，一个服务算作一个功能（`mcp-<服务名>`），可以整个关掉，也可以逐个关掉其中的工具。
- **问不问人**：工具的注解里写了 `readOnlyHint: true` 的，在任何权限级别下都不问人；其他工具按照联网的一类处理：完全放开（默认）时不问，打开只读以后每次都要人确认。如果你自己写服务，请给只读的工具标上它。

## 服务的说明、提示词和资源

- **说明**（`instructions`）：服务提供的那一段说明会放在 AI 的 system 提示的最后，一个服务一段，带上服务名，最多 4000 个字符。只有工具出现在这个会话里的服务才会带上说明。在说明里写清楚它的工具什么时候使用、几个工具之间怎么配合。如果会话进行到一半服务换了说明，要等到工具有变化的那一轮才会换上新的说明（这样不会每一轮都打断缓存）。
- **提示词**（`prompts`）：每个提示词会变成一个斜杠命令 `/<服务名>:<提示词名>`，在命令菜单里可以看到。人在命令后面输入的文字按空白切开（带空格的值用英文双引号括起来，例如 `/weather:forecast "San Francisco" CA`），按照你声明的参数顺序依次对应，最后一个参数拿到剩下的整段；服务返回的文字、图片会作为这个人说的一句话发给 AI。名字里不符合 `[A-Za-z0-9_-]` 的字符会换成 `_`，替换以后重名的提示词不会登记，`miyu check` 会指出来。提示词只能在本机的会话里使用。
- **资源**（`resources`）：服务开放出来的资料（文件、文档、表结构……），每一份有一个地址，服务也可以给出地址模板（`file:///logs/{day}.txt`）。声明了 `resources` 的服务会让 AI 多两个工具：`mcp__<服务名>__list_resources` 分页列出资源和模板，`mcp__<服务名>__read_resource` 按地址读取一份资源。读回来的文字原样交给 AI，图片按照工具返回图片的方式接收，其他二进制内容只用一句话说明类型和大小。这两个工具跟随这个服务的开关、场所和 `clicall` 设置；如果你的服务自己有同名的工具，就使用你的工具。只开放资源、没有工具的服务也可以接入。

## 跑起来的样子

- 服务的工作目录是 `~/.miyu/var/lib/mcp/<服务名>/`，这个路径也会通过 `MIYU_STATE_DIR` 传给服务，服务不在沙盒里运行；标准错误写在 `~/.miyu/var/log/mcp/<服务名>.stderr`，服务无法启动时先看这个文件。
- 无法启动或者崩溃的服务会按退避间隔重试，连续失败 5 次后停止；`软件包` 页上可以看到原因和标准错误的最后几行，点击重启可以再试一次。
- 新旧两个版本的 MCP 都能识别，服务使用哪一版都可以。Miyu 接入工具、服务的说明、提示词和资源；`sampling` 这类功能不接入。
- Miyu 不会替人安装 Node、Python：如果服务用 `npx`、`uvx` 启动，就在说明里写清楚要先安装什么。

## 配置和包里都有同名的

如果配置里和包里有同名的服务，配置里的那个生效，包里的那个会被覆盖（`软件包` 页上可以看到）。
