# 接入通讯平台

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

这一页介绍怎样把 Miyu 接入 QQ 或 Telegram，在私聊和群里和 AI 对话：从安装软件包、接入账号，到管理谁能叫 AI、AI 在群里能做什么，以及聊天记录和用量。

## 什么是接入通讯平台？

软件包 `im` 在界面上叫 `接入通讯平台`。它是一个常驻运行的扩展，带有一个自己的后台页（网页）。安装了这个软件包才有 `miyu im` 命令。它可以安装在 `linux-x86_64`、`macos-aarch64`、`windows-x86_64` 上；Linux aarch64 上没有这个软件包，在那里运行 `miyu pkg install im` 会报错 `不支持该系统。`。

| 平台 | 接入方式 | 你需要准备的 |
|---|---|---|
| QQ | 通过 OneBot v11 的反向 WebSocket 接入：im 开一个端口，由 OneBot 实现连接进来。 | 另外安装一个 OneBot v11 实现，例如 NapCat、SnowLuma，并登录 AI 要使用的 QQ 号。 |
| Telegram | 通过官方的机器人接口（Bot API）接入：由 im 向外连接，不开端口。 | 在 BotFather 里创建一个机器人，拿到它的令牌。 |

一个 im 可以同时接入几个 QQ 号和几个 Telegram 机器人，每个号是一个「连接」。

## 安装和打开

1. 安装软件包，运行：

   ```sh
   miyu pkg install im
   ```

   确认屏上的 `需要的能力` 会列出以下几项，输入 `Y` 一并批准：提供工具、操作会话、代平台用户发言、读取会话、写入会话记录、联网、调其他软件、往系统提示词里放内容、在界面上显示内容、替本机页面换登录票。能力的含义见 [软件包](../packages.md#能力)。

2. 安装程序询问 `现在启用 'im'？[Y/n]` 时，输入 `Y`。如果当时回答了不启用，以后可以运行：

   ```sh
   miyu im start
   ```

   启用以后，核心每次启动都会启动 im。运行 `miyu im stop` 可以关掉它，之后核心不再启动它。

3. 打开后台页。有三种方法，任选一种：

   ```sh
   miyu im web        # 在浏览器里打开；im 没有启动时先启动它
   miyu pkg page im   # 作用同上；加上 --print 只输出网址
   ```

   或者在网页界面里输入 `/im`，后台页会在新标签页里打开。

后台页的默认地址是 `http://127.0.0.1:8302/`。`miyu im web` 给出的链接在 1 分钟内有效。在这台电脑上打开后台页，或者从网页界面、终端跳转过来时，都不需要登录。

后台页左边的一列依次是：`首页`、`会话设置`、`消息记录`、`数据统计`、`使用限制`；`AI` 下面是 `人格`、`预设`、`模型`（和设置页里修改的是同一份数据）；`软件` 下面是 `已安装`、`软件后台`、`下载软件`；最下面是 `设置`。

## 接入 QQ

先安装好一个 OneBot v11 实现（例如 NapCat、SnowLuma），登录 AI 要使用的 QQ 号。这个实现需要能创建 `WebSocket 客户端`，也就是反向 WebSocket：由它连接到 im，im 不会去连接它。

1. 在后台页的首页点击 `新建连接`，选择 `QQ`（下面写着 `OneBot（NapCat 等）`），点击 `下一步`。
2. `在支持 OneBot 协议的软件里新建反向 WebSocket`：页面会给出一个地址，例如 `ws://127.0.0.1:8301/ws`。点击 `复制`，到 NapCat 的网络面板里新建一个 WebSocket 客户端，填入这个地址，然后点击 `我已填写`。
   - 如果 NapCat 在其他机器上或者在 Docker 里，把 `127.0.0.1` 换成这台机器的地址。
   - 端口直接在地址里修改，必须在 `1024` 到 `65535` 之间，并且不能和其他连接、后台页的端口重复。第一个连接默认使用 `8301`，之后新建的连接依次往后顺延。
   - 路径写 `/ws` 或 `/onebot/v11/ws` 都可以。
3. `获取反向 WebSocket 验证 Token`：NapCat 在创建反向 WebSocket 时多半已经自动生成了一个 Token，把它粘贴过来，点击 `保存并连接`。如果连接没有设置 Token，NapCat 连接进来时会被拒绝。
4. `你的 QQ 号`：填写你自己的 QQ 号，AI 就能在私聊和群里认出你（见下面的「绑定你本人的账号」）。不想填写可以点击 `跳过`。
5. `等它连上`：在 NapCat 那边保存以后，几秒钟就能连上。连上以后页面显示 `连接成功`，下面一行是机器人的号码和连接上的实现，例如 `机器人 10001 · 连上的是 NapCat 4.8.0`。

连上以后，首页的 `连接` 一栏里每个机器人有一张卡片，上面有头像、名字、`QQ · <实现> <版本>` 和 `<号> · 已连 N 分钟`。断开的连接的卡片会保留，显示 `断开 N 分钟，在重连`。如果设置了 Token、但还没有号连接进来过，卡片显示为 `等 NapCat 连上`，上面写着端口。要在命令行里查看连接状态，运行：

```sh
miyu im status
```

如果已经连上，会输出 `NapCat 已连接：<实现> <版本>，机器人 <号>`；如果没有连上，会输出 `NapCat 未连接` 和 `NapCat 连接地址：ws://127.0.0.1:<端口>/ws`。

卡片上的齿轮按钮是 `连接设置`，里面有以下几项：

| 项 | 说明 |
|---|---|
| 监听地址 | 默认是 `0.0.0.0`，其他机器和 Docker 里的程序也能连接进来，外人由 Token 挡住。设置成 `127.0.0.1` 时只接受本机的连接。这一项必须写成 IP 地址。 |
| 反向 WebSocket 端口 | NapCat 连接进来的端口。 |
| 反向 WebSocket 验证 Token | 留空表示不修改。 |
| 填到 OneBot 实现里的地址 | 根据上面几项拼好的地址，可以直接复制。 |

修改以后不需要重启，NapCat 下次连接进来时就按新的设置验证。如果连接不止一个，下面会多出一个 `删除这个连接`，需要点击两次才会删除。

如果要接入几个 QQ 号，每个号对应一个 OneBot 实现和一个连接，各自使用自己的端口和 Token。每个号都按照上面的步骤再走一遍 `新建连接` 即可。

## 接入 Telegram

1. 在 Telegram 里找到 `@BotFather`，发送 `/newbot`，按照提示设置好名字和用户名，记下它给出的令牌。
2. 在后台页的首页点击 `新建连接`，选择 `Telegram`（下面写着 `机器人接口（Bot API）`），点击 `下一步`。
3. `在 BotFather 新建机器人`：把令牌粘贴到 `令牌` 里。`代理` 有三个选项，选择其中一个：
   - `跟随联网设置`：按照核心的环境变量 `HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY` 等设置使用代理，见 [联网搜索和抓网页](../web-search.md#代理)。
   - `直连`：不使用代理。
   - `自定义`：填写 `http://地址:端口` 或 `socks5://地址:端口`，也支持 `https://`。

   如果在国内的网络下连不上 Telegram，选择一个能用的代理。然后点击 `检查并连接`。
4. `检查结果`：页面会显示令牌是否有效（写着机器人的名字、用户名和号码）、能否连上 Telegram，以及隐私模式是否开着。点击 `下一步`。
5. `你的 Telegram ID`：填写你在 Telegram 上的数字编号，或者点击 `跳过`。
6. 页面显示 `连接成功`，接入就完成了。

令牌保存在密钥文件 `~/.miyu/etc/private/secrets.toml` 里（数据根默认是 `~/.miyu`，Windows 上是 `%USERPROFILE%\.miyu`），配置文件里只写一个引用。在连接卡片的齿轮里可以更换令牌（提示是 `已设，留空不改；在 BotFather 换了令牌的填新的`）、修改代理、查看隐私模式。

### 隐私模式

用 BotFather 创建的机器人默认开着隐私模式。隐私模式开着时，机器人在群里只能收到回复 AI 的消息和发给它的命令，连 `@` 它的消息也收不到。如果只在私聊里使用，可以不用处理这一项。要在群里叫它，按下面的步骤关掉隐私模式：

1. 在 Telegram 里给 `@BotFather` 发送 `/setprivacy`。
2. 选择这个机器人，再选择 `Disable`。
3. 如果机器人已经在群里，需要把它移出群再重新拉进来，设置才会生效。

也可以把机器人设置成群管理员，管理员能收到全部消息。修改完成后，在连接设置里点击 `重新检查`。隐私模式开着的群，会话卡片上会标着 `隐私模式`。

### Telegram 的其他注意事项

- 一个令牌只能有一个程序在接收消息。如果连接卡片上显示 `别处也在收消息`，说明还有其他程序在使用这个令牌。
- 在私聊里输入 `/` 会列出 Miyu 的命令。命令名里的 `-` 换成了 `_`，例如 `/clear_memory`。
- 开启了话题的群（会话卡片上标着 `话题群`）整个群是一个会话，AI 会在原来的话题里回复。
- 如果你自建了 Bot API 服务，把它的地址写进 `im.tg.api`。

## 绑定你本人的账号

这一步告诉 Miyu 平台上哪个号是你。这项设置写在核心的配置里，下面三个地方修改的是同一份数据：

- 新建连接时的 `你的 QQ 号`、`你的 Telegram ID` 这一步。
- 后台页的 `设置 → 绑定 → 本人的平台 ID`：点击 `新绑定`，先选择平台，再填写号码；点击 `解除绑定` 可以去掉绑定。QQ 号只能写数字；其他平台的号不能含空格和冒号，最多 48 个字。
- 设置页（在终端界面或网页界面里输入 `/settings`）的 `高级 → 平台账号`，或者手动编辑 `~/.miyu/etc/config.toml`：

  ```toml
  [external.bindings]
  "qq:10001" = "owner"
  "tg:20002" = "owner"
  ```

填写以后，这个号有以下待遇：

- 它的私聊不会被限制起来，和你在终端里开的会话一样按照权限级别处理；需要确认的事情不会执行，因为通讯平台上没有确认框。见 [权限和沙盒](../permissions.md#通讯平台上的会话)。
- 在群里叫 AI 时不经过主动回复判断，AI 直接回复。
- 不受限流、睡眠时间和用量上限的限制。
- 可以使用 `access` 是 `admin` 的命令，以及群里的 `/model`、`/persona`、`/preset`、`/loop`。
- 加 AI 为好友的请求会自动通过。
- 可以叫 AI 到其他群或私聊里发消息，也可以叫 AI 搜索所有会话的聊天记录。

修改以后，im 最多 60 秒就会按照新的设置识别。

## 会话的划分

在一个连接下，一个群是一个会话，一个私聊也是一个会话。如果群里同时有几个人叫 AI，会话里会多开几条支线并行回复，最多开几条由卡片上的 `会话内并行数量` 决定。

每个会话有一张卡片，在后台页的 `会话设置` 里。如果连接不止一个，先在标题旁边的下拉框里选择连接。卡片墙分成四段：

| 段 | 卡片 | 作用范围 |
|---|---|---|
| 默认 | `群聊默认值`、`私聊默认值` | 群卡片、私聊卡片上没有修改的项使用这两张卡片的设置。 |
| 名单以外 | `陌生群`、`陌生私聊` | 不在名单里的群和人。出厂设置是都不回复，只记录。 |
| 群聊名单 | 每个群一张 | 出厂设置是回复。 |
| 私聊白名单 | 每个人一张 | 出厂设置是回复。 |

点击 `新建` 可以添加一个群或一个人：先选择 `群聊` 或 `私聊`，再搜索 AI 所在的群、AI 的联系人，或者直接填写号码，然后点击 `添加并设置`。在 QQ 上，加进私聊白名单的人加 AI 为好友时会自动通过。

如果一项没有填写，就使用下一级的设置：群卡片使用 `群聊默认值`，私聊卡片使用 `私聊默认值`，默认值卡片使用核心的设置（默认人格 `persona.default`、默认预设 `preset.default`、默认模型 `models.chat`）。如果一项显示的是 `跟随群聊默认值（…）` 这样的文字，括号里是它现在实际使用的值。

群和私聊的出厂设置不一样：

| | 群 | 私聊 |
|---|---|---|
| 什么时候回复 | 由主动回复判断决定（见下一节）。 | 每条有文字的消息都回复；只有图片、表情的消息只记录。 |
| 限流 | 60 秒 30 轮；`陌生群` 是 300 秒 5 轮 | 300 秒 5 轮；私聊白名单里的人出厂不受限流 |
| 会话内并行数量 | 3 | 一条一条地处理 |
| 回复时带多少条群聊记录 | 30 | — |
| 仅发送最终消息 | 开 | 关 |
| 让 AI 看到号码 | 开 | 开 |

### 会话卡片的分页

点击一张卡片可以打开它，卡片上有以下几页：

| 页 | 内容 |
|---|---|
| 概况 | `是否回复` 开关（关掉以后只记录不回复）；这个会话今天、7 天、30 天的统计；`最近判断`（群）和 `最近处理`（私聊）：每条消息有没有回复、为什么；自主循环上一次和下一次的时间；名单里的卡片底部还有 `移出群聊名单` 或 `移出私聊白名单`。 |
| 人格和模型 | `AI 人格`、`预设`、`额外提示词`（只在这个会话生效）、`对话模型`、`上下文窗口`、`多模态模型`、`主动回复判断模型`、`回复时带多少条群聊记录`，以及是否让 AI 看到发言人的号码。 |
| 触发方式 | 设置什么时候说话、主动回复判断和权限，见下面两节。 |
| 定时任务 | 给这个会话创建定时任务和循环任务，见下面的「定时任务」。 |
| 限流与并发 | `限流`（几条 / 几秒）、`睡眠时间`、三项 `用量上限` 和 `会话内并行数量`。 |
| 发送消息处理 | 说话方式、发送方式和长文的处理，见「消息的显示方式」。 |
| 管理插件 | 设置这个会话里开启哪些插件。 |
| 插件加的页 | 已开启的插件在这个会话里添加的页，例如 `群管理面板`。 |
| 实时日志 | AI 在这个会话里做的事，一件事一行：收到了什么、怎么判断、想了什么、调用了什么工具、发出了什么。 |
| 查看会话 | 安装了网页界面时才有这一页：在新标签页里打开这个会话的时间线，只能查看。 |

修改人格、预设或模型以后，已有的会话也会跟着更换：模型当场更换；人格和预设会先压缩一次上下文，下一轮再换上。如果把卡片上的人格、预设清空，已有的会话不变；要换回去，在卡片上重新选一个。

如果想让 AI 在一个群里从头开始：在后台页的 `消息记录` 里点进这个群，点击右上角的 `删除 AI 会话`（需要点击两次）。删除的只是 AI 的上下文，聊天记录仍然保留。

在聊天里也可以更换：你本人和卡片上 `允许使用管理员命令的用户` 里的人可以发送 `/model`、`/persona`、`/preset`：

| 写法 | 作用 |
|---|---|
| `/model` | 说明现在使用的是哪一个，下面附上用法。 |
| `/model search [<关键词>]` | 列出可以选择的项，带序号。 |
| `/model <序号>`、`/model <名字>` | 更换，并写进这个会话的卡片。 |
| `/model 默认` | 改回跟随默认设置。 |

`/persona`、`/preset` 的用法相同。其他人发送这些命令时，会被当成普通的话交给 AI。

## AI 什么时候说话

### 私聊

对私聊白名单里的人和你本人，AI 会回复每一条有文字的消息。陌生私聊的出厂设置是不回复。

### 在群里叫 AI

在群里，下面两种情况算作叫了 AI：

- 消息里 `@` 了 AI。
- 一句话以 `额外触发关键词` 里的某个词开头。关键词区分大小写；如果希望喊名字就能叫 AI，需要把名字也写进去，人格的名字不会自动加上。

只回复了 AI 的消息、但没有 `@` AI 的，不算叫了 AI。

在 `是否开启主动回复判断` 关着的群里，叫了 AI 就回复，不叫就不回复；如果开启了 `概率触发主动回复`，被抽中的消息也会交给 AI。

### 主动回复判断

主动回复判断开着时（这是群的出厂设置），一条消息只要符合下面任意一个条件，就会交给一个判断模型打分，分数通过门槛 AI 才回复；一个条件都不符合的消息只记录：

| 条件 | 什么时候成立 |
|---|---|
| 叫了 AI | 见上一节。 |
| 续聊 | AI 回复了某人以后的 30 秒内，这个人又说了话。 |
| 刚说过话 | AI 发完消息以后的 30 秒内，任何人说的话都算。 |
| 回复中跟进 | AI 正在回复某人时，这个人又发了消息；通过判断的会并进这一轮。 |
| 概率抽中 | 不符合其他任何条件的消息按概率抽取。出厂关闭，开启后默认是 5%。 |
| 疑似违规 | 消息里有违规关键词时，判断模型会检查一遍，严重程度达到 7（范围是 0 到 10）就回复。 |

- 你本人、白名单成员，以及卡片上 `跳过主动回复判断的用户` 里的人叫了 AI 时，AI 直接回复，不打分。
- 如果关掉 `被叫时也过主动回复判断`（出厂开启），任何人叫了 AI 都直接回复。
- 判断模型使用轻量池里的模型；轻量池为空时，使用这个会话的对话模型。要指定判断模型，在卡片上设置 `主动回复判断模型`。
- 门槛的出厂值是 `0.8`。AI 刚说过话、同一个人叫得太频繁、AI 最近在这个群里回复得多，这几种情况都会抬高门槛；卡片上的 `回复克制` 控制的是第一种。
- 门槛、五项权重、续聊和观察窗口的秒数，以及违规严重程度的门槛，都在 `触发方式` 页的 `高级` 里。
- 违规关键词在后台页的 `已安装 → 群管理 → 设置` 里修改；你本人发的消息不检查。

AI 也可以自己决定这一轮不说话（使用工具 `qq_skip_reply`、`tg_skip_reply`）。

### 自主循环

开启自主循环后，AI 会时不时看一眼群聊，自己决定回复什么、做什么。这个功能出厂关闭，只有名单里的群卡片和私聊卡片上才有：

- 在 `触发方式` 页打开 `自主循环`。
- `多久看一眼`：AI 没有自己定下一次的时间时，隔多久看一次，出厂是 7 分钟。如果 AI 用 `qq_glance`、`tg_glance` 定了时间，就按 AI 定的时间。
- `看一眼带几条新消息`（群）：上次看过以后没有回复的消息，最多交给 AI 几条，出厂是 50。
- `自主循环的额外提示词`：看一眼时要做的事，比如留意什么、收集什么。

如果上次看过以后群里没有新消息，就不请求模型，按间隔重新安排下一次。私聊到点时不检查有没有新消息，只要私聊闲着，就让 AI 决定要不要开口。睡眠时间里到点的会顺延到睡眠时间结束。

在群里看一眼时，这一轮请求的最后会接上一句提示（不进入会话历史），内容是：没有人叫 AI，它像一个平时多半只看不说的群友在往回翻；只为新东西开口：没有人回答的提问（开口时引用那一条）、跟进某个人、对话题确实有补充；这里说过的话不重复；不开口是常态。私聊到点的那一轮带的提示只说明没有人叫 AI、是它自己在看，不劝它少说话。如果卡片上写了 `自主循环的额外提示词`，群里和私聊里都会照样带上。

在群里，你本人和 `允许使用管理员命令的用户` 里的人可以发送：

| 写法 | 作用 |
|---|---|
| `/loop` | 打开这个群的自主循环，回复 `这个群的自主循环开了`。 |
| `/loop off` | 关掉这个群的自主循环。 |

群里的 `/loop` 只有这两种写法，带上间隔或其他文字时，会回复一句用法；它开关的是卡片上的 `自主循环`，不交给核心处理。私聊里的 `/loop` 会交给核心，是核心的循环，写法和终端里相同：只输入 `/loop` 开启的是核心的自主循环，它跟着这个私聊的会话运行，和私聊卡片上的 `自主循环` 是两回事，开启它不会打开卡片上的那一项。核心的循环见 [让 AI 自己接着干](../automation.md#循环-loop)。

### 定时任务

名单里的群卡片和私聊卡片有 `定时任务` 页：点击 `新建任务`，写清要做什么、什么时候做（`每天几点`、`每隔多久`、`某一刻一次`、`cron（高级）`）。到点以后 AI 会在这个会话里执行任务，睡眠时间里也会执行；`是否回复` 关着时不执行。任务可以暂停、恢复、编辑和删除。定时任务的其他用法见 [让 AI 自己接着干](../automation.md#定时任务)。

### 让 AI 在群里保持安静

- 只是不说话：关掉卡片上的 `是否回复`，AI 仍然记录消息，但不开口。
- 少说话：关掉主动回复判断，只有叫了 AI 才回复；或者调低 `限流`。
- 某段时间不说话：把 `睡眠时间` 写成 `23:00-07:00` 这样的格式，按本机的时间计算。这段时间里 AI 只回复你本人和白名单成员。
- 完全不理这个群：点击 `移出群聊名单`，这个群就会使用 `陌生群` 那张卡片的设置，出厂设置是不回复。

### 其他只记录、不回复的情况

原因可以在卡片的 `最近判断` 和实时日志里看到：

- `限流满了，只记录`、`用量到了上限，只记录`：你本人和白名单成员不受这两条限制。
- `睡眠时间，只记录`。
- `AI 被禁言了，只记录`，或者 `AI 被禁言着，解禁后回复`。
- `几个人在复读同一句，只记录`：2 分钟内别人刚说过一模一样的话。
- 叫 AI 的那条消息被撤回了，这一轮会停下来。

## 设置谁能使用

| 名单 | 修改位置 | 作用 |
|---|---|---|
| 群聊名单 | 在 `会话设置` 里新建群聊；`miyu im access group add <群号>` | 名单里的群，AI 出厂会回复。 |
| 私聊白名单 | 在 `会话设置` 里新建私聊；`miyu im whitelist add <号>`；配置键 `im.whitelist` | 可以私聊 AI；加 AI 为好友时自动通过；不受限流和睡眠时间影响；在群里叫 AI 时直接回复。 |
| 跳过主动回复判断的用户 | 群卡片的 `触发方式`；`miyu im access skip <群号> add <号>` | 在这个群里叫 AI 时直接回复。 |
| 允许使用管理员命令的用户 | 群卡片的 `触发方式 → 权限` | 在这个群里算作管理员，见下文。 |

在 `陌生群`、`陌生私聊` 两张卡片上打开 `是否回复` 以后，AI 也会回复名单以外的群和人。

命令行里的 `whitelist`、`access` 只修改 QQ 的名单，号码写纯数字。

### 处理请求

- 加好友：白名单成员和你本人的好友请求会自动通过。其他人的请求会放着不处理，需要你自己到 QQ 里处理。
- 邀请 AI 进群：放着不处理，需要你自己到 QQ 里处理。
- 有人申请加入一个群：如果 AI 是那个群的管理员、群管理插件开着，并且那个群的 `群管理面板` 里写了 `通过条件`，AI 会按照条件审核：通过、拒绝或者留待人工处理，拿不准的和出错的一律留待人工处理。没有写条件时不处理。

### 群管理员

群卡片上 `允许使用管理员命令的用户` 里的人，在这个群里：

- 对于 `access` 是 `admin` 的命令，算作管理员。QQ 的群主和群管理员不算，需要写进这一项才算。
- 可以使用 `/model`、`/persona`、`/preset`、`/loop`。
- 命令被拒绝时，会收到被拒绝的那一句回复；其他人的命令被拒绝时什么都不回复。
- 可以叫 AI 删除群文件。

在通讯平台上发送以 `/` 开头的消息时，消息会先交给核心当作命令识别，识别不出的当作普通的话交给 AI。谁能使用哪条命令由 `commands.<命令名>.access` 决定，见 [斜杠命令](../commands.md#设置谁能使用命令)。

在群里，`im.recall_receipts` 里那几条命令成功后的回执会在 3 秒后撤回，出厂是 `clear`、`clear-memory`；命令被拒的那一句回复都会撤回；私聊里的回执不撤回。可以在后台页的 `设置 → 通用 → 回执自动撤回的命令` 里修改。

## 群里的 AI 能做什么

群会话和不是你本人的私聊是被限制起来的会话，和权限级别无关：

- 文件工具只能访问这个会话的工作区，技能文件夹只能读取。
- 命令在一个连读取也限制在工作区内的沙盒里运行。Windows 上不能运行命令；在 Linux 上，如果沙盒限制不住 Unix 套接字，也不能运行命令。
- 不能安装、卸载软件包。
- 需要确认的事情一律不执行。

详细的见 [权限和沙盒](../permissions.md#通讯平台上的会话)。另外还有以下几点：

- 没有子代理和长期目标，也不能向人提问，见 [让 AI 自己接着干](../automation.md)。
- MCP 服务出厂只提供给本机的会话，在 `mcp.<服务名>.venues` 里加上 `private`、`group` 才会提供给这些会话，见 [配置键全表](../config-keys.md)。脚本和技能按照它们的 `Venues` 提供，见 [扩展 Miyu](../extending.md)。
- 别人让 AI 抓网页时有额外的限制，见 [联网搜索和抓网页](../web-search.md#通讯平台上别人让-ai-抓取的网页)。
- 设置里写的关于你的内容（`profile.about`）不会带进群聊。

### 记忆和知识库

群里的 AI 同样有记忆和知识库的工具：`remember`、`forget`、`memory_search` 使用的是这个人格的那一份记忆，和你在终端里使用的是同一份；`kb_save`、`kb_edit`、`kb_delete` 写入的是你的知识库。群里的人说一句话，AI 就可能把内容记下、改掉或者翻出来。

如果不想让群里的人碰到这些工具，给这些群设置一个关掉它们的预设，在 `群聊默认值` 或群卡片上选择这个预设：

```toml
# 在 ~/.miyu/root/presets/group.toml 里加上
[features]
memory = false

[tools]
kb_save = false
kb_edit = false
kb_delete = false
```

预设的写法见 [人格和预设](../personas-presets.md)，记忆见 [记忆](../memory.md)，知识库见 [知识库](../knowledge.md)。

### 内置插件

QQ 带有三个插件，可以在后台页的 `已安装` 里开关、修改设置，也可以在会话卡片的 `管理插件` 里按会话开关：

| 插件 | 作用 |
|---|---|
| 识人术 | 如果有人借用了你、AI 或 `识人映射` 里某个人的名字，号码却对不上，就提醒 AI 这不是那个人。 |
| 查询信息 | 提供查聊天记录、取图片和文件、看头像、群成员、群公告、群文件、通讯录、发言排行、token 用量这几个工具。 |

群管理插件会在会话卡片上多加一页 `群管理面板`，里面有：`开启刷屏处理`（同一个人连续发三次同样的话时，撤回重复的消息并禁言；`几秒以内` 出厂是 60，`禁言几分钟` 出厂是 10）、`入群审批` 的 `通过条件`，以及最近的管理记录和排行榜。

## 消息的显示方式

`发送消息处理` 页有以下几项：

| 项 | 出厂 | 作用 |
|---|---|---|
| 去掉末尾句号 | 开 | 去掉回复末尾的一个 `。`。 |
| 智能引用 | 开 | 原消息后面别人又说了 2 条以上时，引用原消息。 |
| 智能艾特 | 开（群） | 引用对方时顺带 `@` 对方；智能引用关着时，回复晚于 20 秒才 `@`。 |
| 确认主动回复后贴表情 | | 判断要回复以后，先给那条消息贴一个表情，回复完再摘掉（群）。 |
| 分多条发送 | 开 | 像真人聊天那样在句号处断开，有时也在逗号处断开；太长的、带换行的消息仍然作为一条发送。 |
| 消息间停顿 | 开 | 每条消息之间按打字速度停一会儿。 |
| 打字速度 | 120 字/分钟 | `20` 到 `600` |
| 按顺序发送 | 开 | 前一条发出去以后才发下一条。 |
| 仅发送最终消息 | 群开、私聊关 | AI 调用工具时说的中间的话不发送。 |
| 长文处理 | 自动转图片 | 超过阈值的长文画成图片；QQ 上还可以选择 `合并转发`。 |
| 长文处理阈值 | 300 字 | |
| 这个会话的说话方式 | | 写下这里的人平时怎么说话，AI 每一轮都会看到（群）。 |

画成图片需要安装 `render` 软件包，没有安装时长文会拆成几段发送，见 [附加软件](../addons.md)。发送表情包需要安装 `memes` 软件包，安装后就会开启，可以在会话卡片的 `管理插件` 里按会话关掉。

AI 能看到的内容：

- 引用：被引用的那条消息。
- 图片：叫 AI 的那条消息和它引用的那条消息里的图片，各自最多 4 张，每张不超过 20 MB。其他的图片、视频、文件由 AI 用 `qq_fetch_media` 去取。如果对话模型看不了图片，就交给 `多模态模型`（卡片上没有设置时使用 `models.vision`）。
- 合并转发（QQ）：一条消息最多展开 4 个，最多嵌套 3 层，每个最多 20 条，每条最多 500 字。

## 限额和用量

用量按 token 限制，分三条线：最近 5 小时、7 天、30 天。达到上限后只记录不回复，你本人和白名单成员不受限制。

- 单个会话的上限：在卡片 `限流与并发` 页的 `5 小时用量上限`、`每周用量上限`、`每月用量上限` 里设置，不填写就不限制。
- 单个人的上限：在后台页的 `使用限制` 里设置。`所有人` 的三项对所有人生效，一个人在所有群和私聊里的用量合起来计算；`单独设置` 里的人使用自己的三项，整组替换 `所有人` 的设置。下面的 `最近 30 天` 列出用过的人，显示为红色的是已经达到上限的人。数字可以写成 `200k`、`1.5m`。这些设置保存在 `~/.miyu/etc/im/limits.toml`：

  ```toml
  [default]
  limit_5h = 2000000

  [[person]]
  id = "qq:10002"
  limit_month = 50000000
  ```

后台页的 `数据统计` 可以查看今天、7 天、30 天的数据：token 和花费、请求构成、按会话、按人、按模型的统计、每天的走势、按小时的消息数，以及 im 自己的 CPU、内存和运行时间。CPU 和内存用 `ps` 测量，Windows 上测量不了，这两项会空着。连接不止一个时，可以按连接查看。

## 聊天记录

im 会把群和私聊的消息、群事件（禁言、踢人、进群、退群、撤回），以及每条消息有没有回复、为什么，保存在 `~/.miyu/var/lib/im/records.db` 里。图片和文件只记录占位和平台上的编号，不保存内容。记录不会自动删除，会一直保留到你清理为止。

后台页的 `消息记录` 里，每个连接是一组，组里列出有记录的群和私聊，并写着条数和大小。点进一个就能查看记录，上面可以按关键词、号码或名字、日期搜索。

清理记录的方法：点击 `清理记录`，选择场所和范围（`保留近 7 天`、`保留近 30 天`、`保留近 90 天`、`全部清空`、`自定义`：哪段时间、谁发的），再点击两次 `清理`。清理后不能恢复，AI 的会话和记忆不受影响。AI 自己不能删除记录。

如果要把从旧版 Miyu 迁移出来的 QQ 记录导入进来，运行：

```bash
miyu im records import ~/qq-records.jsonl
```

```powershell
miyu im records import "$HOME\qq-records.jsonl"
```

已经有的记录不会重复导入；只要有一行不对，整个文件都不会导入，并输出是哪几行。迁移的方法见 [从 0.7 旧版迁过来](../migrate.md)。

## 插件

im 可以安装自己的插件，在后台页的这几处管理：

- `已安装`：已经安装的插件，可以开关、批准能力、修改设置，查看 `用在哪`。
- `下载软件`：软件源里 im 的插件，可以搜索、安装。
- `软件后台`：已开启的插件带的后台页。

### 赞助记录

`im-sponsor`（`赞助记录`）是 im 的一个插件：你本人或群里的管理员可以叫 AI 记一笔赞助，任何人都可以问 AI 某人累计赞助了多少，或者查看排行榜。安装它，运行：

```sh
miyu pkg install im-sponsor
```

安装好以后就会运行，出现在后台页的 `已安装` 里，可以按会话开关。修改、删除记录在它的后台页里操作。其他币种会按记账时的汇率换算成默认币种，默认币种由配置键 `im-sponsor.currency` 决定，出厂是 `CNY`。

## `miyu im` 命令

| 命令 | 作用 |
|---|---|
| `miyu im start` | 启动 im，之后核心每次启动都会启动它。 |
| `miyu im stop` | 停止 im，之后核心不再启动它。 |
| `miyu im restart` | 重启 im。 |
| `miyu im status` | 查看运行状态和 NapCat 的连接。 |
| `miyu im web` | 在浏览器里打开后台页（链接 1 分钟内有效）；im 没有启动时先启动它。 |
| `miyu im logs` | 输出运行日志；标准错误里有内容时先输出标准错误。 |
| `miyu im logs -f` | 持续输出新写入的日志。 |
| `miyu im logs watch [<会话>]` | 实时查看 AI 在会话里做什么。会话写成 `qq:<群号或对方的号>`，不写时查看全部；如果一个号既是群又是私聊，写成 `qq:group:<号>` 或 `qq:private:<号>`。按 `Ctrl+C` 退出。 |
| `miyu im venue show <场所>` | 查看一个场所每一项设置的值和来源。场所写成 `<平台>:<机器人号>:group:<群号>` 或 `<平台>:<机器人号>:private:<号>`。 |
| `miyu im records import <文件>` | 从 JSON Lines 文件导入聊天记录。 |
| `miyu im whitelist [list \| add <号> \| remove <号>]` | 查看、修改私聊白名单，不写子命令时是 `list`。 |
| `miyu im access` | 列出私聊白名单、群聊名单，以及各群跳过判断的人。 |
| `miyu im access whitelist [list \| add <号> \| remove <号>]` | 作用同 `miyu im whitelist`。 |
| `miyu im access group [list \| add <群号> \| remove <群号>]` | 查看、修改群聊名单。 |
| `miyu im access skip <群号> [list \| add <号> \| remove <号>]` | 查看、修改这个群里跳过主动回复判断的人；这个群需要先在群聊名单里。 |

在每条命令后面加上 `--help` 可以输出它的用法。用法写错时退出码是 `2`，出错时退出码是 `1`。例如：

```sh
miyu im venue show qq:10001:group:123456
miyu im access skip 123456 add 20017
```

## `im.*` 配置键

这些键都写在系统配置 `~/.miyu/etc/config.toml` 里，修改后当场生效。标着「藏」的键不在设置页上列出，需要在后台页上修改；也可以手动编辑配置文件。

后台页和名单相关的键：

| 键 | 默认 | 作用 |
|---|---|---|
| `im.web.port` | `8302` | 后台页的端口，范围是 `1024` 到 `65535`。对应后台页的 `设置 → 访问 → 端口`。 |
| `im.web.listen` | `127.0.0.1` | `127.0.0.1` 表示只给本机使用，`0.0.0.0` 表示向局域网开放。对应后台页的 `设置 → 访问 → 向局域网开放`。 |
| `im.whitelist` | — | 私聊白名单，每一项写成 `qq:<号>`，例如 `qq:20017`。 |
| `im.recall_receipts` | `["clear", "clear-memory"]` | 群里的回执会在几秒后撤回的命令，不带斜杠。 |

QQ 连接相关的键（藏，在连接设置里修改）：

| 键 | 默认 | 作用 |
|---|---|---|
| `im.qq.hosts` | — | 每个连接的监听地址，和端口一一对应。 |
| `im.qq.ports` | — | 每个连接的端口。 |
| `im.qq.tokens` | — | 每个连接的 Token（密钥）。 |
| `im.qq.host` | `0.0.0.0` | `im.qq.ports` 没有写过时，第一个连接的监听地址。 |
| `im.qq.listen` | `8301` | 同上，第一个连接的端口。 |
| `im.qq.token` | — | 同上，第一个连接的 Token（密钥）。 |

Telegram 连接相关的键（藏，在连接设置里修改）：

| 键 | 默认 | 作用 |
|---|---|---|
| `im.tg.tokens` | — | 每个连接的机器人令牌（密钥）。 |
| `im.tg.proxies` | — | 每个连接的代理，和令牌一一对应：空的或者 `env` 表示跟随联网设置，`direct` 表示直连，其他值是代理地址。 |
| `im.tg.api` | `https://api.telegram.org` | Bot API 的地址，只有自建 Bot API 服务时才需要修改。 |

识人术（藏，在 `已安装 → 识人术 → 设置` 里修改）：

| 键 | 默认 | 作用 |
|---|---|---|
| `im.qq.identity_on` | `true` | 插件的总开关。 |
| `im.qq.identity_admin` | `true` | 有人用了你的名字、号码却对不上时，提醒 AI。 |
| `im.qq.identity_card` | `true` | 有人把群名片改成和 AI 一样时，提醒 AI。 |
| `im.qq.identity_people` | `[]` | 识人映射，每一项写成 `名字=QQ号`，例如 `老板=10001`。 |

查询信息（藏，在 `已安装` 里开关）：

| 键 | 默认 | 作用 |
|---|---|---|
| `im.qq.lookup_on` | `true` | 插件的总开关；关掉以后这几个工具都没有。 |

群管理（藏，在 `已安装 → 群管理 → 设置` 里修改）：

| 键 | 默认 | 作用 |
|---|---|---|
| `im.qq.admin_on` | `true` | 插件的总开关。 |
| `im.qq.admin_mute` | `true` | 禁言工具，关掉以后 AI 没有这个工具。 |
| `im.qq.admin_mute_min` | `1` | 最短禁言几分钟，范围是 `1` 到 `43200`。 |
| `im.qq.admin_mute_max` | `43200` | 最长禁言几分钟（30 天），范围是 `1` 到 `43200`。 |
| `im.qq.admin_kick` | `true` | 踢人工具。 |
| `im.qq.admin_log` | `true` | 查看管理记录的工具。 |
| `im.qq.admin_records` | `true` | 记录每个群里的禁言、解禁、踢人。 |
| `im.qq.admin_keep` | `500` | 每个群最多保留几条管理记录，超过时从最旧的开始删除，范围是 `10` 到 `100000`。 |
| `im.qq.admin_summary` | `true` | 按人统计被禁言、被踢的次数，排成榜。 |
| `im.qq.admin_sync_unmute` | `true` | 群里其他管理员给某人解禁时，也记录下来并告诉 AI。 |

所有会话的发送设置（藏，会话卡片上没有修改的项使用这些值）：

| 键 | 默认 | 作用 |
|---|---|---|
| `im.strip_period` | `true` | 去掉回复末尾的一个 `。`。 |
| `im.humanlike` | `true` | 分多条发送。 |

下面三个键已经改到会话卡片上设置。如果配置里还写着它们，im 启动时会把它们挪进 `群聊默认值` 卡片，并从配置里去掉：

| 键 | 默认 | 作用 |
|---|---|---|
| `im.sleep` | — | 睡眠时间，格式是 `HH:MM-HH:MM`。 |
| `im.keywords` | — | 群里的触发词。 |
| `im.show_ids` | `false` | 让 AI 看到 QQ 号。 |

## 从其他设备打开后台页

在后台页的 `设置 → 访问` 里打开 `向局域网开放`，同一个局域网里的手机、电脑就能打开后台页，开关下面会显示网址和二维码。从其他设备打开时，需要用网页界面里设置的访问密码登录，见 [网页界面](web.md)。不要把 im 放在反向代理后面，要从局域网使用就打开这个开关。在 macOS 上，如果其他设备打不开后台页，到 `系统设置 → 网络 → 防火墙 → 选项` 里允许 `miyu-im` 的传入连接。

## 文件位置

| 位置 | 内容 |
|---|---|
| `~/.miyu/var/lib/im/` | 会话卡片 `cards.json`、聊天记录 `records.db`，以及各平台自己的状态。 |
| `~/.miyu/var/log/im/miyu-im.log` | 运行日志。 |
| `~/.miyu/var/log/im/stderr` | im 崩溃时输出的信息。 |
| `~/.miyu/etc/im/limits.toml` | 每个人的用量上限。 |
| `~/.miyu/etc/im/moderation.txt` | 违规关键词，在 `已安装 → 群管理 → 设置` 里修改的内容保存在这里。 |
| `~/.miyu/etc/im/venues.d/` | 手写的场所规则，`miyu im venue show` 根据它和会话卡片算出每一项设置来自哪里。 |

## 常见问题

| 看到的现象 | 解决方法 |
|---|---|
| `miyu im status` 输出 `NapCat 未连接` | 核对 NapCat 里填写的地址和 `miyu im status` 输出的地址一致，路径是 `/ws` 或 `/onebot/v11/ws`；如果 NapCat 在其他机器上，把 `127.0.0.1` 换成这台机器的地址，并且监听地址必须是 `0.0.0.0`。 |
| `没有设置 Token，NapCat 的连接会被拒绝` | 运行 `miyu im web`，在连接设置里粘贴 NapCat 的 Token。 |
| 首页日志显示 `有人连续猜错 NapCat 的口令（…），已拦下` | 两边的 Token 不一致，按照 NapCat 那边的 Token 修改。 |
| `端口 … 已被占用`、`这个端口已经被占用了` | 在连接设置里换一个端口，NapCat 里填写的地址也跟着修改。 |
| 连接卡片上显示 `令牌失效，在连接设置里换一个`、`令牌不对` | 到 BotFather 获取新的令牌，填进连接设置。 |
| `连不上 Telegram，在重连`、`连不上 Telegram，检查代理` | 在连接设置里更换代理；如果选择的是 `跟随联网设置`，核对核心的 `HTTPS_PROXY`。 |
| `代理地址不对，在连接设置里改` | 写成 `http://地址:端口` 或 `socks5://地址:端口`。 |
| `别处也在收消息` | 停掉其他使用这个令牌的程序。 |
| `隐私模式开着，群里 @ 收不到` | 按照上面「隐私模式」一节的方法关掉隐私模式。 |
| AI 在群里不回话 | 打开那个群的卡片查看 `概况 → 最近判断`，或者运行 `miyu im logs watch qq:<群号>`：`没叫 AI` 表示消息既没有 `@` AI，也没有以触发词开头；`关着，只记录` 表示这个群不在名单里，或者 `是否回复` 关着；`… 没过门槛 …` 表示判断模型认为不该回复；另外还有限流、用量、睡眠时间、被禁言这几种情况。 |
| 实时日志里出现 `模型请求出错` | 核对会话卡片上的对话模型和核心的默认模型能正常使用，见 [模型](../models.md)。 |
| 卡片上的人格、预设写了不存在的名字，这个会话不回复 | 在卡片上重新选择一个。 |
| `miyu im web` 输出 `接入通讯平台未运行` | 运行 `miyu im start`；如果还不行，查看 `miyu im status` 和 `miyu im logs` 的输出。 |
| `管理页面的端口 … 已被占用，页面无法打开` | 运行 `miyu config set im.web.port 8312` 换一个端口。 |
| `miyu im status` 输出 `接入通讯平台已停止，不再自动启动：…` | 按照输出的原因修好问题，然后运行 `miyu im restart`。 |
| 后台页显示 `连不上接入通讯平台` | 说明 im 停止了，运行 `miyu im start`。 |
