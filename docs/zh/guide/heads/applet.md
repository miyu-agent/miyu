# 系统托盘

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

系统托盘是显示在系统托盘区域里的一个 Miyu 图标（macOS 上在菜单栏里），程序名是 `miyu-applet`。它可以查看核心是否在运行、启动和停止核心、用浏览器打开网页界面；浏览器关着时，它也会弹出 `回答完了`、`等你确认` 这类通知。系统托盘没有自己的窗口，聊天都在网页界面里进行，详细的见 [网页界面](web.md)。

## 安装和打开

系统托盘有两种安装包：完整的安装包把核心、网页界面和系统托盘打包在一起（不包含终端界面），安装以后就能使用；只包含系统托盘的安装包，需要另外安装好核心和网页界面。各个系统可用的安装包如下：

| 系统 | 完整的安装包 | 只装系统托盘 |
|---|---|---|
| Linux x86_64 | `.deb`、`.rpm` | AUR 的 `miyu-applet`；系统托盘发行版页面上的 `miyu-applet-<版本>-linux-x86_64.tar.gz` |
| Linux aarch64 | 没有 | AUR 的 `miyu-applet`；`miyu-applet-<版本>-linux-aarch64.tar.gz` |
| macOS Apple 芯片 | `.dmg` | Homebrew 的 cask `miyu-applet` |
| Windows x86_64 | `.msi` | 没有 |

安装方法见 [安装、升级、卸载](../install.md)。

从应用菜单打开 `Miyu`。系统托盘启动以后会做两件事：

- 用浏览器打开网页界面的首页；如果网页界面、核心没有在运行，会一起启动它们。
- 图标留在托盘里，并连接核心，显示核心的状态。

如果已经有一个系统托盘在运行，再打开 `Miyu` 不会启动第二个，只会让正在运行的那个再打开一次网页界面。一个数据根（默认是 `~/.miyu`，Windows 上是 `%USERPROFILE%\.miyu`）对应一个系统托盘；设置了 `MIYU_HOME` 的系统托盘使用它指向的数据根，各自独立运行。

系统托盘为了显示状态而连接核心时，不会启动核心，只连接已经在运行的核心；核心只在打开网页界面、点击 `启动` 时才启动。如果核心是从其他地方启动的（终端、`miyu web`、服务），系统托盘同样会显示 `运行中`。

## 点击图标

左键和右键点击图标的效果如下：

| | Linux | macOS | Windows |
|---|---|---|---|
| 左键 | 打开网页界面 | 弹出菜单 | 打开网页界面 |
| 右键 | 弹出菜单 | 弹出菜单 | 弹出菜单 |

双击和中键点击没有单独的动作。

## 菜单

菜单从上到下依次如下，各组之间有一条分隔线：

| 菜单项 | 点击后 |
|---|---|
| 状态行（不能点击） | 见下面的「状态」。 |
| `停止` 或 `启动` | 停止：先停止网页界面，再停止核心（`miyu web stop`，再 `miyu core stop`）。启动：启动核心，不打开浏览器。 |
| `重新启动` | 停止核心再重新启动；网页界面不停止，已经打开的页面会接着连接新的核心。 |
| `打开网页界面` | 运行 `miyu web`，用浏览器打开首页。 |
| `设置…` | 运行 `miyu web --settings`，用浏览器打开网页界面的设置页。macOS 上可以按 `⌘,`。 |
| 软件包的几行 | 带有后台页、并且在清单里写了 `[tray]` 的软件包，每个占一行，点击后运行 `miyu pkg page <编号>`，打开它的后台页。没有这样的软件包时不显示这一组。 |
| `局域网访问`（勾选项） | 打开或关闭其他设备通过局域网访问网页界面，详细的见下面的「局域网」。 |
| `在手机上打开…` | 只有打开了局域网访问时才显示。运行 `miyu web --settings access`，打开网页界面设置里的 `访问`，那里有地址和二维码。 |
| `开机时启动`（勾选项） | 登录时启动系统托盘，详细的见下面的「开机时启动」。 |
| `打开日志所在的文件夹` | 用文件管理器打开 `~/.miyu/var/log/`。 |
| `关于 Miyu` | 打开一个对话框，显示系统托盘、核心和网页界面三者的版本。 |
| `退出 Miyu` | 先停止网页界面和核心，然后系统托盘退出。macOS 上可以按 `⌘Q`。 |

如果网页界面的版本太旧，不支持 `--settings` 这类参数，系统托盘会改为打开网页界面的首页。

### 状态

状态行显示核心的状态，前面有一个小圆点：

| 显示的文字 | 圆点 | 出现的时机 |
|---|---|---|
| `运行中` | 绿色 | 已经连接上核心。 |
| `运行中 · 局域网` | 绿色 | 已经连接上核心，并且局域网访问已打开。 |
| `正在启动…`、`正在停止…` | 黄色 | 系统托盘正在启动或停止核心。 |
| `没有响应` | 黄色 | 能连接上核心，但发出的请求迟迟没有回应。 |
| `已停止` | 灰色 | 核心没有在运行。 |
| `出错了` | 红色 | 启动失败，或者连接被拒绝；下面一行会写出原因。 |

托盘图标本身不会随状态变化，鼠标悬停时显示 `Miyu`。

菜单项在不同状态下能否点击：

- 正在启动时，那一行是灰色的 `停止`；正在停止时，是灰色的 `启动`。
- `重新启动` 在运行中、没有响应、出错了三种状态下可以点击。
- `局域网访问` 只在运行中可以点击。

### 局域网

`局域网访问` 修改的是网页界面的 `web.listen`：打开时写入 `0.0.0.0`，关闭时恢复成出厂的 `127.0.0.1`。网页界面会当场切换过去，不需要重启。

- 如果还没有设置访问密码就打开，系统托盘不会修改配置，而是先用浏览器打开网页界面设置里的 `访问`，你需要在那里设置密码并打开局域网访问。
- 如果没有安装网页界面，或者系统托盘还没有连接过核心，不显示这一组。

局域网访问使用明文 HTTP，只在你信得过的网络里打开它。其他设备怎么打开网页界面、访问密码怎么设置，见 [网页界面](web.md#访问和安全)。

## 退出后核心是否继续运行

关掉系统托盘时，核心是否继续运行取决于关掉的方式：

- `退出 Miyu`：网页界面和核心一起停止，然后系统托盘退出。即使没有停止成功，系统托盘也照样退出，并在日志里记一行。停止核心最多等待 70 秒，点击以后图标会先消失。
- `停止`：网页界面和核心停止，系统托盘保留，显示 `已停止`。
- 如果系统托盘不是从菜单退出的（例如崩溃了、被结束了），核心会继续正常运行。

## 通知

系统托盘连接着核心时，会接管后台的通知：没有在网页界面里打开的会话，由系统托盘弹出系统通知；网页界面只为自己标签页里打开的会话弹出通知，所以两边不会重复。

| 通知 | 出现的时机 |
|---|---|
| `回答完了` | 一轮已经做完。 |
| `等你回答` | AI 在向你提问。 |
| `等你确认` | AI 要做的事需要你确认。 |
| `定时任务跑完了`、`定时任务没跑完` | 每次新开会话的定时任务，那一轮做完或出错时。 |
| `定时任务的记录坏了，已换成新的一份，原来的定时任务都没了` | 定时任务的记录无法读取。 |

- 通知的标题是会话所用人格的名字，如果人格有头像，会带上头像；没有人格时显示 `Miyu`。正文是 `<会话标题> · 回答完了` 这样的格式；会话没有标题时使用第一句话，第一句话也没有时只写原因。
- 子代理的会话、一次性的会话和整理记忆的会话不弹出通知。
- 点击通知或通知上的 `打开` 按钮，会用浏览器打开那个会话；定时任务记录损坏的那一条通知会打开网页界面的首页。在 Windows 上，系统托盘退出以后点击通知中心里的通知，同样会启动系统托盘并打开那个会话。
- 在 Linux、Windows 上，同一个会话的同一种通知，新的会替换旧的；在 macOS 上会一条条保留。

系统托盘的菜单里没有关闭通知的开关。

## 开机时启动

勾选 `开机时启动` 后，登录时会启动系统托盘。开机启动的系统托盘只常驻在托盘里，不打开浏览器，也不启动核心。这个设置写在以下位置：

| 系统 | 写入的位置 |
|---|---|
| Linux | `~/.config/autostart/miyu-applet.desktop`（设置了 `XDG_CONFIG_HOME` 时在它下面） |
| macOS | `~/Library/LaunchAgents/io.github.miyu-agent.miyu-applet.plist` |
| Windows | 当前用户注册表 `Run` 项里的 `Miyu` |

系统托盘是按照 `MIYU_HOME` 或 `--home` 指定的数据根启动的，开机时也会使用同一个数据根启动。如果在 Linux 桌面的 `自动启动` 设置里关掉了它，系统托盘也会当作已关闭处理。

它和 `miyu service enable` 的区别如下：

| | `开机时启动` | `miyu service enable` |
|---|---|---|
| 登录时启动的程序 | 系统托盘 | 核心 |
| 核心 | 不启动，等你打开网页界面或终端时才启动 | 登录时就启动，通讯平台、定时任务不需要等待 |

两个都打开时：登录时核心由服务启动，系统托盘启动后连接上它，显示 `运行中`。这时点击系统托盘的 `退出 Miyu` 或 `停止`，核心会正常退出，服务管理器不会再启动它，直到下次登录才会启动。如果只使用电脑上的界面、不接入通讯平台，打开 `开机时启动` 就够了；如果要让核心一直在后台运行，需要安装服务，见 [常驻和服务器](../service.md#开机或登录时启动核心)。

## 三个平台

系统托盘在三个平台上的位置和要求如下：

| 系统 | 显示位置 | 需要的条件 |
|---|---|---|
| Linux | 系统托盘 | GTK 3；桌面的托盘需要支持 StatusNotifierItem。KDE、waybar 这类桌面自带支持；GNOME 需要安装 AppIndicator 扩展才能显示。 |
| macOS | 菜单栏，图标按照菜单栏的颜色绘制 | Apple 芯片，macOS 12 或更新的版本。不占用程序坞的位置。 |
| Windows | 通知区域 | 通知要从安装包安装的程序发出，才会带有 Miyu 的名字和图标。 |

系统托盘菜单的文字跟随系统的语言：中文、日文，其他语言都显示英文。

## 日志和托盘自己的目录

系统托盘会写日志，并使用一个自己的目录：

- 日志：`~/.miyu/var/log/miyu-applet.log`，和核心、网页界面的日志放在一起，满 1 MiB 时改名为 `miyu-applet.log.1`。如果核心一次都没有启动过，`var/log/` 还不存在，这时不写日志文件。
- 系统托盘自己的目录用来存放单实例的锁和通知用的头像：

  | 系统 | 位置 |
  |---|---|
  | Linux | `~/.local/state/miyu-applet`（设置了 `XDG_STATE_HOME` 时在它下面） |
  | macOS | `~/Library/Application Support/miyu-applet` |
  | Windows | `%LOCALAPPDATA%\miyu-applet` |

系统托盘没有其他设置。

## 常见问题

| 看到的提示 | 解决方法 |
|---|---|
| 看不到托盘图标（Linux） | 桌面的托盘不支持 StatusNotifierItem。GNOME 上需要安装 AppIndicator 扩展；如果桌面只支持老式托盘，需要换一个托盘。 |
| `找不到 Miyu 的主程序。重新装一次 Miyu 试试。` | 系统托盘查找 `miyu` 的顺序是：系统托盘程序旁边、`PATH`；Linux、macOS 上还会查找 `~/.local/lib/miyu/`、`~/.local/bin/`，macOS 上再查找 `/opt/homebrew/bin`、`/usr/local/bin`；Windows 上只查找系统托盘程序旁边和 `PATH`。如果 Miyu 安装在其他位置，设置环境变量 `MIYU_PROGRAM` 指向它即可。 |
| `打不开网页界面。`，下面是 `miyu` 的原话 | 按照原话处理；在终端里运行 `miyu web` 能看到更完整的信息，网页界面那边的问题见 [网页界面](web.md#常见问题)。 |
| `等了太久，没有回音。` | 打开网页界面最多等待 90 秒，停止核心最多等待 70 秒。再点击一次；如果还是不行，查看日志。 |
| 状态行显示 `出错了`，下面写着数据根无法识别这类话 | 按照那句话处理，详细的见 [出了问题怎么查](../troubleshooting.md#核心无法启动或无法连接)。 |
| `Miyu 没能启动。`、`Miyu 没能停下来。` | 查看下面那句原因和日志。 |
| `没能改局域网访问。` | 核心没有在运行，或者没有接受修改；等状态变成 `运行中` 再点击。 |
| `没能改开机时启动。` | 自动启动的文件或注册表项写不进去，查看下面那句原因。 |
| `还没有日志：Miyu 运行过一次以后才有。` | 先点击 `启动` 或 `打开网页界面`。 |
| 点击菜单像是没有反应 | 正在启动或停止时，其他启动、停止的请求不会被接受；等状态行变化以后再点击。 |
