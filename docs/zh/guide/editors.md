# 在编辑器里使用

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

这一页讲怎么在 Zed 这类编辑器里把 Miyu 当作 AI 助手使用。编辑器和 Miyu 之间说的是 ACP（Agent Client Protocol，编辑器和 AI 助手之间的通用协议）：编辑器启动 `miyu acp`，`miyu acp` 再连接本机的核心。因为编辑器里的会话就是 Miyu 的会话，所以你在编辑器里开始的对话，在终端界面、网页界面里也能看到、接着说。

## 准备

1. 安装 Miyu

   按 [安装、升级、卸载](install.md) 装好 Miyu，确认在终端里运行 `miyu --version` 能输出版本号。

2. 接入模型

   如果还没有接入模型，先运行：

   ```bash
   miyu setup
   ```

   编辑器里用的模型、人格、预设都是 Miyu 自己的设置，和编辑器里配置的模型无关。

## 在 Zed 里添加 Miyu

1. 打开设置文件

   在 Zed 里打开 `Agent Settings`，进入 `External Agents` 页，点击 `Add Agent`，选择 `Add Custom Agent`，Zed 会打开设置文件并加上一段 `agent_servers`。也可以直接编辑设置文件：Linux 和 macOS 上是 `~/.config/zed/settings.json`，Windows 上是 `%APPDATA%\Zed\settings.json`。

2. 写上 Miyu

   把 `agent_servers` 那一段写成下面这样，保存即可：

   ```json
   {
     "agent_servers": {
       "Miyu": {
         "type": "custom",
         "command": "miyu",
         "args": ["acp"],
         "env": {}
       }
     }
   }
   ```

   - `command`：Miyu 的程序。如果 Zed 找不到 `miyu`（例如在 macOS 上从程序坞打开的 Zed 不一定读到你在 shell 里设置的 `PATH`），就写成绝对路径，在终端里运行 `command -v miyu`（PowerShell 里是 `(Get-Command miyu).Source`）可以查到它在哪里。
   - `args`：固定写 `["acp"]`。
   - `env`：一般留空。如果你的数据根不是默认的 `~/.miyu`，就在这里写上 `"MIYU_HOME": "<数据根的绝对路径>"`，让 `miyu acp` 连接那个数据根里的核心。

3. 开始对话

   打开 Agent Panel，在新建对话的菜单里选择 `Miyu`，就可以开始对话了。如果核心没有在运行，`miyu acp` 会先启动它，第一句话可能要多等一两秒。

> 其他支持 ACP 的编辑器（例如 JetBrains 系列）的添加方法见它们自己的文档：添加一个自定义的 agent，命令是 `miyu`，参数是 `acp`。

## 编辑器里能做什么

| 做什么 | 怎么做 |
|---|---|
| 说一句话 | 在输入框里输入，按回车发送。可以用 `@` 提到文件、贴图片：提到的文件会作为附件交给 AI，图片和在终端界面里贴的图片一样处理。 |
| 看 AI 在做什么 | AI 的思考、回答会边写边显示；它用的每件工具显示成一张卡片，标题和终端界面里的那一行相同。改了文件的卡片上会显示改前和改后的对比，点击文件名可以跳过去。 |
| 确认 | AI 要运行需要确认的命令时，编辑器会弹出确认框，框里会显示要运行的命令原文，选项是 `仅允许本次`、`拒绝`，有的还有 `在本会话内允许`。AI 用提问工具问你时，选项也会显示在确认框里；如果编辑器支持表单，会弹出一张表单，你可以选择，也可以自己写。 |
| 打断 | 点击编辑器里的停止按钮，这一轮会被打断；如果你的这句话还在排队，就会被退回。 |
| 切换权限 | 编辑器的模式选择器里有 `开放权限` 和 `只读` 两种，对应 Miyu 的两种权限级别，新会话默认是开放权限，见 [权限和沙盒](permissions.md)。 |
| 换模型、思考强度 | 编辑器的配置选择器里列出了你能用的模型和模型池（要密钥的供应商要先配好密钥），新装的软件包带来的模型在 Miyu 取到模型列表以后会自动出现；当前的模型带思考档位时，还可以切换思考强度。 |
| 斜杠命令 | 输入 `/` 会列出 Miyu 的斜杠命令，例如 `/clear`、`/todo`，还有 `/compact`（手动压缩上下文），用法见 [斜杠命令](commands.md)。 |
| AI 自己接着做 | 后台任务报回来、AI 被叫醒接着做的那一轮，编辑器里会先显示一行，例如 `后台任务「跑测试」已完成`，再显示 AI 的回答。 |
| 待办和用量 | AI 的待办清单显示成编辑器里的计划；上下文用了多少、累计花了多少也会显示（金额算不准时不显示）。 |
| 打开以前的会话 | 在编辑器的对话历史里选择一个会话，Miyu 会把这个会话以前的对话重新显示出来，你可以接着说。列出的是工作目录和当前项目相同的 Miyu 会话。 |

## 需要知道的

- AI 读写的是磁盘上的文件。编辑器里还没有保存的改动 AI 看不到，所以在让 AI 读文件之前要先保存。
- 编辑器里配置的 MCP 服务不会交给 Miyu。要让 AI 用 MCP 服务，就在 Miyu 里添加，见 [扩展 Miyu](extending.md)。
- 核心停止或重启时，编辑器里正在进行的那一轮会报错，例如 `核心停了，这一轮没有做完`，之后的操作照常：Miyu 会重新连上核心，如果核心没有在运行就先启动它。
- 核心使用的是启动它的那个程序的环境，包括 `PATH`、`HOME` 和其他环境变量。如果核心没有在运行，由编辑器里的 `miyu acp` 启动，那么它用的就是编辑器的环境，之后终端界面、网页界面连接的也是这个核心。从程序坞、开始菜单或者桌面打开的编辑器，`PATH` 往往比终端里的短，也没有你在 shell 配置文件里设置的变量。这时 AI 运行命令可能找不到你在 shell 里安装的程序（例如 `npx`），核心也读不到写在环境变量里的密钥。所以建议先在终端里运行 `miyu core start` 启动核心，再打开编辑器。如果核心已经由编辑器启动了，先运行 `miyu core stop`，再在终端里运行 `miyu core start`。
- 用 `miyu service enable` 安装服务以后，核心在登录时就会启动，不会再由编辑器启动。但是服务启动的核心同样读不到你在 shell 里设置的变量，详细的见 [服务和环境变量](service.md#服务和环境变量)。编辑器设置里 `env` 写的变量，也会带进由 `miyu acp` 启动的核心。
- 关闭编辑器不会停下正在进行的那一轮：Miyu 会在后台接着做完，你可以在终端界面、网页界面里看到结果。如果这时 AI 正在等你确认，确认请求会按 `permission.confirm.timeout` 到时自动拒绝，出厂是 5 分钟。

## 出了问题

- 如果编辑器里显示 Miyu 无法启动，先在终端里运行 `miyu acp`，看标准错误上的报错（按 `Ctrl+D` 退出）。最常见的原因是编辑器找不到 `miyu`，按上面第 2 步把 `command` 改成绝对路径即可。
- 如果 AI 在编辑器里运行命令时找不到程序，或者扩展驱动提示要先登录，但是在终端里一切正常，那么核心很可能是由编辑器启动的、用的是编辑器的环境。按照 [需要知道的](#需要知道的) 里的方法，改成在终端里启动核心。
- 在 Zed 的命令面板里运行 `dev: open acp logs`，可以看到编辑器和 Miyu 之间来回的每一条消息，报告问题时可以附上它。
- 其他问题见 [出了问题怎么查](troubleshooting.md)。
