# 记忆

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

AI 会记住你和它聊过的事情，下一次新开会话时还能想起来。这一页讲 AI 记住哪些内容、什么时候记住和想起、怎么查看和修改记忆，以及怎么不让它记住。

记忆功能由出厂软件包 `base-memory` 提供，它在界面上的名字是 `人格记忆`。这个软件包安装以后，记忆功能就是打开的。

## 记忆的格式

一条记忆是一句话，最多 120 个字。每条记忆有一个编号，写法是 `m` 加上序号，例如 `m12`。每条记忆属于下面的一类：

| 类 | 网页界面上的名字 | 记住什么 |
|---|---|---|
| `user` | 关于用户 | 关于你的事情 |
| `feedback` | 对 AI 的要求 | 你希望 AI 怎么做 |
| `episode` | 发生过的事 | 你和 AI 一起经历的事情 |
| `reference` | 资料位置 | 长期有效的事实，以及资料放在哪里 |
| `person` | 认识的人 | 关于另外某个人的一件事，同时记着这个人是谁（名字或平台编号，例如 `qq:10086`） |

一条记忆还可以另外带一行关键词，关键词之间用逗号隔开，最多 200 个字。关键词只用来让搜索找到这条记忆，AI 看不到这一行。

除了一条一条的记忆，还有两样内容，它们都是在整理记忆时写出来的：

- 对你的了解：一段关于你的摘要。
- 认识的人的卡片：每个人一张，最多 400 个字，由 `认识的人` 这一类的记忆合成。

AI 还可以搜索同一个人格以前的对话，但只搜索由你发起的那几轮。

## 记忆和人格的关系

每个人格有一份自己的记忆，使用这个人格的会话共用这一份。不使用人格的会话共用另外一份。

- 如果在会话中途换了人格，从换人格的那一轮开始，新的记忆保存进新人格的那一份；以前保存的记忆留在原来那一份里，不会搬过去。
- 子代理既不保存记忆，也不召回记忆。

## 什么时候保存记忆

记忆可以通过下面几种途径保存：

| 谁保存 | 怎么保存 |
|---|---|
| 自动 | 会话空闲下来以后，AI 会从上一次保存以后的对话里挑出值得记住的内容保存下来。如果 AI 在某一轮里已经自己记住或忘掉了什么，那一轮就不再重新看 |
| AI | AI 调用 `remember` 工具保存。这个工具也能修改一条记忆：用新的一条替换旧的一条 |
| 你 | 在本机的会话里输入 `/remember <内容>`，内容会保存成 `关于用户` 这一类，回复是 `记下了：…` |
| 你 | 运行 `miyu memory add`，或者点击网页界面记忆页上的 `记一条` |

自动保存要同时满足两个条件：

1. 从上一次自动保存以后，AI 至少回答了 `memory.extract_turns`（默认 2）轮。
2. 会话已经空闲了 `memory.extract_idle`（默认 30 分钟）。

有的会话一直空闲不下来，例如群里一直有人说话。这种情况下，如果从上一次保存以后已经结束了 `memory.extract_max_turns`（默认 20）轮，或者最早一轮还没保存的对话已经过了 `memory.extract_max_wait`（默认 1 小时），就不再等待空闲，直接在后台保存。

自动保存使用日常池（`normal`）里的模型；如果池是空的，或者池里的成员都在冷却、出错，就使用会话自己的模型。池的配置方法可以看 [模型](models.md#池便宜的干杂活贵的干正事)。

## 什么时候召回记忆

AI 会在下面这些时候把记忆带进上下文：

| 什么时候 | 带上什么 |
|---|---|
| 会话的第一轮，以及压缩以后的第一轮 | 常驻的一块内容：对你的了解，加上在它之后新保存的记忆，新的在前，总共不超过 3000 字节。如果放不下，最后一行会说明还有几条没放进来，让 AI 用 `memory_search` 去搜索 |
| 在通讯平台上，别人说话的那一轮 | 这个人的卡片，在一段上下文里只带一次 |
| 你发起的每一轮 | 联想：根据你这一轮说的话查找记忆，最多 3 条，不超过 500 字节；一段上下文里（压缩以后重新计算）最多带 40 条，这个数和知识库的自动召回合在一起计算。只有关键词和意思都对得上才会带上，拿不准时宁可不带 |
| AI 自己要查找时 | AI 调用 `memory_search` 工具，搜索记忆、认识的人和以前的对话 |

联想需要语义模型（`models.embedding`，见 [模型](models.md#三个用途)），默认使用本机的 `embed` 软件包（见 [附加软件](addons.md)）。如果没有安装、设置成了 `off`，或者换成了远程模型，就不会联想，但常驻的那一块、卡片和 `memory_search` 照常工作。如果没有安装或者设置成了 `off`，`memory_search` 只按关键词查找。

召回了哪几条记忆，时间线上不会显示。你可以在下面这些地方看到相关的信息：

- 终端界面：`/context` 的上下文明细里，会列出 `常驻记忆` 和 `召回的记忆` 各占多少 token；`/status` 里的 `回忆 N 次 · 记住 N 条` 是 AI 调用 `memory_search` 和 `remember` 的次数。
- AI 调用记忆工具时，时间线上和其他工具一样会显示一行。

## 整理

整理是把新保存的记忆和相关的旧记忆放在一起重新梳理一遍，具体会做这些事：

- 重复的记忆作废，只留下一条。
- 被后来的记忆推翻的作废。
- 用不着的作废。
- 写得不准确的记忆会改写：改写后的内容存成新的一条，旧的那条作废。
- 写一段新的「对你的了解」。
- 根据 `认识的人` 这一类的记忆，合成每个人的卡片。
- 给没有关键词的记忆补上关键词。
- 顺带重新检查最多 20 条旧记忆。

作废的记忆可以找回；整理不会清空任何东西。

整理会在下面这些时候进行：

- 自动：自动保存了新的记忆以后，如果离上一次整理已经过了 `memory.merge_every`（默认 16 小时），就在后台整理。如果这一份记忆从来没有整理过，就马上整理。
- 在会话里输入 `/dream`：先把这个会话里还没保存的内容保存下来，再一直整理到没有剩下的为止。完成后会回复 `整理完成：…`，说明检查、修改、作废了几条，摘要有没有更换，以及用了多长时间。
- 运行 `miyu memory dream`：整理默认人格的那一份记忆，或者整理 `--persona`、`-s` 指定的那一份。
- 点击网页界面记忆页上的 `整理`。

如果要停止整理，可以在会话里输入 `/dream stop` 或 `/stop`；在终端界面里连按两次 `Esc`；运行 `miyu memory dream` 时按 `Ctrl+C`；在网页界面上点击 `停止整理`。已经整理好的那几批会保留，正在整理的那一批下次再重新整理。

整理和自动保存一样，使用日常池（`normal`）。每一份记忆会保留最近 `memory.dream_keep`（默认 20）次整理的过程，可以在网页界面记忆页的 `整理记录` 里查看。

## 查看和修改记忆

记忆可以在命令行或网页界面里查看和修改。

### 命令行

```text
miyu memory [<子命令>] [<选项>]
```

不写子命令时运行的是 `list`。如果没有写 `--persona` 或 `-s`，就使用默认人格（`persona.default`）的那一份记忆；如果没有设置默认人格，会报 `记忆不可用`。不使用人格的会话的那一份记忆，要写 `--persona _none`。

| 子命令 | 做什么 |
|---|---|
| `list` | 列出最新的 50 条记忆，一条一行：编号、日期、正文 |
| `search <词>…` | 搜索记忆，最多列出 10 条，最相关的在前 |
| `add <内容>…` | 保存一条记忆，输出 `已添加 m…` |
| `edit <编号> [<内容>…]` | 修改正文：修改后的内容存成新的一条，旧的作废，输出 `已修改，新编号 m…`。如果只修改 `--keywords`、`--who`，就不写内容 |
| `forget <编号>` | 作废一条记忆 |
| `clear session [<会话>]` | 清除一个会话保存的记忆。不写会话时使用 `-s` 指定的会话；如果也没有写 `-s`，就是上一次 `miyu ask` 的会话 |
| `clear me` | 清空这一份记忆，包括卡片和对你的了解 |
| `dream` | 马上整理 |
| `cards` | 列出认识的人的卡片 |

| 选项 | 做什么 |
|---|---|
| `--persona <编号>` | 使用这个人格的记忆。不能和 `-s` 一起写 |
| `-s`、`--session <编号>` | 使用这个会话所用的那一份记忆 |
| `--forgotten` | 让 `list`、`search`、`cards` 把作废的也一起列出来 |
| `--class <user\|feedback\|episode\|reference\|person>` | `list` 只列出这一类；`add` 保存成这一类，不写时是 `user` |
| `--why <原因>` | `forget` 时写明作废的原因 |
| `--keywords <词>` | 用于 `add`、`edit`：关键词，用逗号隔开；`edit` 时写成空的就是去掉关键词 |
| `--who <是谁>` | 用于 `add`、`edit`：`认识的人` 这一类的记忆说的是谁。`add --class person` 必须写这个选项 |
| `--format <text\|json>` | `list`、`search` 的输出格式 |

例如：

```sh
miyu memory search 咖啡
miyu memory add --keywords 编辑器,vim 写代码用 Neovim
miyu memory add --class person --who 小林 小林是做前端的同事
miyu memory edit m12 --keywords 饮料,早餐
miyu memory forget m15 --why 已经换工作了
miyu memory --persona captain list --class feedback
```

清除的记忆找不回来；作废的记忆可以在网页界面的记忆页上点击 `找回`。全部参数可以看 [命令行](cli.md#miyu-memory)。

### 网页界面

记忆页在设置的 `记忆` 页面，也可以在会话里输入 `/memory` 直接打开。终端界面没有记忆页。

- 在页面顶上选择要看哪一份记忆：每个人格一份，另外还有 `无人格` 的一份。
- `记忆` 页签：可以按内容和关键词搜索，按类别筛选，勾选 `显示作废的`；点开一条记忆可以修改内容和关键词、作废、找回；点击 `记一条` 保存新的记忆；点击 `清空` 清空这一份记忆（和 `clear me` 一样，清空后找不回来）；还有 `整理` 和 `整理记录`。
- `认识的人` 页签：可以查看、搜索、修改每个人的卡片，点击 `认识一个人` 新写一张。

## 关闭和清除记忆

不让 AI 记住，可以按不同的范围来做：

| 范围 | 做法 |
|---|---|
| 一次 `miyu ask` | 运行 `miyu ask --no-memory "…"`：新开的会话既不召回也不保存记忆。不能和 `-c`、`-s` 一起写 |
| 使用某个预设的会话 | 在预设里关掉 `人格记忆`：在 `[features]` 下写 `memory = false` |
| 全部 | 运行 `miyu pkg remove base-memory`。已经保存的记忆留在数据根里，重新安装（`miyu pkg install base-memory`）以后还在 |
| 一条记忆 | 让 AI 忘掉它（AI 会调用 `forget` 把它作废），或者运行 `miyu memory forget <编号>` |
| 一个会话保存的记忆 | 在那个会话里输入 `/clear-memory`（别名 `/reset-memory`），不会再询问，回复 `清掉了这个会话记下的 N 条记忆。`。也可以运行 `miyu memory clear session <会话>` |
| 一整份记忆 | 运行 `miyu memory clear me`，或者点击网页界面上的 `清空` |

一个会话开不开记忆，是在新建会话时决定的，之后换预设也不会改变。`/remember`、`/dream`、`/clear-memory` 只能在开着记忆的会话里使用；如果会话的预设没有开记忆，输入这些命令会提示 `预设「…」未启用记忆。`。

预设的写法可以看 [人格和预设](personas-presets.md)。

清除一个会话的记忆时，只清除来源全部在这个会话里的记忆：你自己保存的记忆（`/remember`、`miyu memory add`）没有来源，不会被清除；在其他会话里也说过的内容，不会被清除；卡片保持不变。

## 设置

可以在设置页（`/settings`）的 `软件包` 里修改人格记忆的设置项，也可以写进 `~/.miyu/etc/config.toml`。修改以后从下一轮开始生效。

| 键 | 默认值 | 可以填写的范围 | 作用 |
|---|---|---|---|
| `memory.extract_idle` | `"30m"` | `1m` 到 `1h` | 会话空闲多久以后自动保存 |
| `memory.extract_turns` | `2` | `1` 到 `100` | 从上一次自动保存以后，至少过几轮才保存 |
| `memory.extract_max_turns` | `20` | `2` 到 `500` | 一直空闲不下来的会话，攒够几轮就不再等待空闲 |
| `memory.extract_max_wait` | `"1h"` | `10m` 到 `24h` | 一直空闲不下来的会话，最早一轮没保存的对话过了多久就不再等待空闲 |
| `memory.merge_every` | `"16h"` | `1h` 到 `720h` | 每隔多久自动整理一次 |
| `memory.dream_keep` | `20` | `0` 到 `1000` | 保留最近几次整理的过程，`0` 表示整理完就删除 |

例如：

```toml
[memory]
extract_idle = "10m"
merge_every = "24h"
```

## 通讯平台上的会话

记忆不按群、不按人分开：同一个人格不论在哪个群里、和谁私聊，用的都是同一份记忆，在任何地方都能想起全部内容。保存记忆时，还会另外记下这句话是在哪个场所、哪个群里说的（群名是保存那一刻的群名）。如果群里的某个人有了 `认识的人` 这一类的记忆，整理时会给这个人合成一张卡片，这个人说话的那一轮会带上这张卡片。

`/remember`、`/dream`、`/clear-memory` 只能在本机的会话里使用。通讯平台上的会话使用哪个人格、怎么设置，可以看 [接入通讯平台](heads/im.md)。

## 存放位置

记忆存放在数据根里：

| 位置（数据根默认是 `~/.miyu`，Windows 上是 `%USERPROFILE%\.miyu`） | 是什么 |
|---|---|
| `~/.miyu/root/memory/<人格编号>/` | 这个人格的记忆日志；不使用人格的那一份是 `_none` |
| `~/.miyu/var/cache/index/recall/` | 搜索用的索引，根据日志和会话计算出来 |

记忆日志只往后追加：修改一条记忆就是新写一条，作废和清空也是另外写一行，原文一直保留在日志里。不要手动修改这些文件，需要修改时使用 `miyu memory` 或者网页界面的记忆页。

备份记忆、把记忆搬到另一台电脑，可以看 [数据和备份](data.md)。

## 哪些内容会发给模型供应商

- 召回的记忆和卡片会进入上下文，随每次请求发给会话使用的模型。
- 自动保存和整理是另外发请求给日常池里的模型（或者会话的模型）完成的，请求里会带上相关的那一段对话和相关的记忆。发送之前，配置里引用的密钥原文和常见的 key 写法会被遮掉。
- 如果 `models.embedding` 设置的是远程模型，记忆和对话的文字会发给那一家供应商计算向量。本机的 `embed` 不会把内容发出这台电脑。

## 排查问题

| 看到的现象 | 怎么办 |
|---|---|
| `miyu memory` 报 `记忆不可用` | 没有设置默认人格。加上 `--persona <编号>`；不使用人格的那一份记忆写 `--persona _none` |
| `/remember` 提示 `预设「…」未启用记忆。` | 这个会话的预设没有打开人格记忆。换一个打开了人格记忆的预设新建会话，或者在预设里打开人格记忆 |
| `人格记忆未安装。` | 运行 `miyu pkg install base-memory` |
| `正在整理记忆。` | 这一份记忆正在整理，等整理完成即可 |
| `记忆过长：N 字，上限 120 字` | 把这条记忆写短一些，或者拆成几条 |
| AI 从来不联想 | 运行 `miyu check`，看末尾和语义模型有关的那几行；如果没有安装，运行 `miyu pkg install embed` |
