# 安全

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

把一个能运行命令的 AI 放在自己的电脑上，你需要知道 Miyu 替你挡住了什么、没有挡住什么、哪些东西会发送出去。这一页讲这些，以及几种常见用法应该怎么设置。

## 信任模型

Miyu 以你这个系统用户的身份运行。开放权限下，AI 几乎能做你在终端里能做的一切事情：读写你的文件、运行命令、联网。

下面这些防护针对的是两件事：一是 AI 一时糊涂做错事，二是 AI 被它读到的网页、文件、群消息里的话带偏。这些防护不是用来关住一个故意找漏洞的程序的。如果不想让 AI 碰到某样东西，就不要让它够得着：使用只读，或者不要把东西放在 AI 能读到的地方。

## Miyu 能挡住的

Miyu 会挡住下面这些情况：

| 风险 | 怎么挡住 | 详细说明 |
|---|---|---|
| AI 修改你的文件 | 切换到只读：文件工具不写入，命令在系统的沙盒里运行，任何位置都写不进。Windows 上沙盒只在已登录的桌面会话里能用，不在桌面会话里时，每条命令都会被拒绝。 | [权限和沙盒](permissions.md#两种权限级别) |
| 危险命令 | 开放权限下，破坏性 git 操作、递归删除、关机和重启、下载后直接执行、容器使用宿主设备这几类命令会先问你；删除根目录和家目录、格式化磁盘、直接写入磁盘设备、让容器接管整台电脑这几类命令会被直接拒绝。Windows 上按 PowerShell、cmd 的写法识别，但不识别直接写入磁盘设备那一类。 | [权限和沙盒](permissions.md#要确认的命令) |
| AI 删除 Miyu 自己的数据 | 删除整个数据根（默认是 `~/.miyu`，Windows 上是 `%USERPROFILE%\.miyu`）或者包含它的目录、把它们移走或扔进回收站时，会先问你，这属于 `递归删除` 那一类。数据根里面的文件、目录不会问你，其他读写也不会拦截，见下一张表。 | [权限和沙盒](permissions.md#要确认的命令) |
| 通讯平台上别人让 AI 做事 | 群和不是你本人的私聊会被限制起来：文件只能访问那个会话的工作区，命令在连读取也限制住的沙盒里运行（Windows 上不能运行命令），不能安装软件包，需要确认的事情不执行；默认不给这些会话提供 MCP 服务。 | [权限和沙盒](permissions.md#通讯平台上的会话)、[接入通讯平台](heads/im.md#群里的-ai-能做什么) |
| 网页里的话骗 AI 去连接本机或内网 | `web_fetch` 和链接卡片不会访问本机、内网、链路本地这类地址，每一跳重定向都会重新检查。 | [联网搜索和抓网页](web-search.md#碰不到的地址) |
| 安装来路不明的软件包 | 安装之前会列出它需要的能力，你同意之后才授予；软件源的索引会验证签名，软件包文件会核对 SHA-256；社区的软件包和从本机文件安装的软件包会被标出来。 | [软件包](packages.md#软件源) |
| 被篡改过的 Miyu 程序 | 安装脚本和 `miyu upgrade` 会核对签名和 SHA-256，不一致就不安装。 | [安装、升级、卸载](install.md#脚本的校验步骤) |
| 密钥被写进文件、日志、命令里 | 配置里只写引用，密钥放在密钥文件里（Linux、macOS 上的权限是 `0600`，只有你能读写；Windows 上沿用数据根继承的访问控制）；AI 运行的命令拿不到名字里带 `KEY`、`SECRET`、`TOKEN`、`PASSWORD`、`PASSWD`、`CREDENTIAL` 的环境变量；核心的日志不记录密钥和对话内容。 | [配置](config.md#密钥)、[工具](tools.md#shell)、[常驻和服务器](service.md#日志) |
| 其他设备连接你的网页界面 | 默认只监听本机；其他设备要连接，需要输入访问密码（保存的是 argon2id 哈希，同一个来源 60 秒内输错 5 次就会先被拒绝）；只接受 `Host` 是本机地址或这台电脑 IP 的请求，不接受域名；对话的连接会核对 `Origin`。 | [网页](heads/web.md#访问和安全)、[常驻和服务器](service.md#从其他电脑和手机打开网页界面) |
| 本机其他用户连接你的核心 | Linux、macOS 上，套接字放在只有你能进入的目录里；Windows 上是只对你本人开放的命名管道，连接之后还会核对另一端的进程属于你。界面连接核心时还要出示本机令牌。 | [出了问题怎么查](troubleshooting.md#核心无法启动或无法连接) |
| 别人的仓库借项目配置放宽权限 | 项目配置只能收紧权限，目前只认 `permission.start_read_only = true`；没有信任的项目配置不起作用，内容一变就要重新信任。 | [配置](config.md#为一个仓库单独设置) |
| 别人连接 QQ 的接口冒充 | OneBot 实现连接进来时必须带上 Token，没有 Token 的会被拒绝。 | [接入通讯平台](heads/im.md#接入-qq) |

## Miyu 不挡或挡不全的

下面这些情况 Miyu 不挡，或者挡不全，需要你自己注意：

| 风险 | 实际情况 | 你可以做的 |
|---|---|---|
| 换个写法的危险命令 | 受保护的命令只按字面写法识别，故意绕开的写法识别不出来。 | 不放心的工作使用只读。 |
| Windows 上识别不出的危险命令 | `-EncodedCommand` 里经过编码的命令、直接写入磁盘设备、`Set-ExecutionPolicy`、删除注册表，Windows 上的规则都不识别：开放权限下既不会先问你，也不会拒绝。 | 做没有把握的事情时使用只读，见 [权限和沙盒](permissions.md#windows-上的写法)。 |
| 开放权限下的命令和文件工具 | 命令不在沙盒里运行。Miyu 不对数据根做额外的保护：命令和文件工具都能读写 `~/.miyu`，包括密钥文件 `~/.miyu/etc/private/secrets.toml`、配置和会话。 | 和上一行相同。 |
| 密钥文件 | 三个平台都不使用系统的钥匙串，密钥以原文写在 `~/.miyu/etc/private/secrets.toml` 里。Linux、macOS 上，Miyu 每次写入它时都会把权限设成 `0600`；Windows 上不单独设置权限，沿用数据根继承的访问控制。以你的身份运行的程序都读得到它。AI 也读得到：两种权限级别下，文件工具和命令都读得到数据根，包括这个文件，读到的密钥会进入上下文，并且发送给模型供应商。 | 不要让 AI 去读它；不要以你的身份运行来路不明的程序；不要把数据根放在其他用户也读得到的目录里。 |
| 提示词注入 | AI 读到的网页、文件、仓库里的 `AGENTS.md`、群消息、MCP 服务的回答都会进入上下文，里面写的话可能把 AI 带偏。Miyu 不识别这类话；能挡住的只有上面那张表里那些不看 AI 说了什么的规则。 | 读取不熟悉的内容时使用只读；不要随手点掉要紧的确认。 |
| 你的文件被发送给模型供应商 | 开放权限和只读下，AI 都读得到你这个系统用户读得到的任何文件，包括 `~/.ssh`、浏览器的数据、其他程序的登录信息、Miyu 自己的数据根；读到的内容会进入上下文，并且发送给模型供应商。只读只负责不让写入，不会替你隐藏文件。 | 不要让 AI 在存放私人文件的目录里随意翻找；不想让 AI 读到的内容，需要你自己把 Miyu 关进另一层沙盒，或者换一个系统用户运行。 |
| 只读下联网 | 只读下的命令照样可以联网，能读到的文件都发得出去。 | 和上一行相同。 |
| 环境变量 | 去掉名字里带 `KEY` 这类字样的变量，只能防止密钥被顺手带出去，并不是一道墙：命令和核心都以你这个系统用户的身份运行，系统本来就不防范同一个用户的程序之间互相访问，核心进程的环境变量照样可能被读到（例如 Linux 上的 `/proc/<进程号>/environ`），用 `{ env = "…" }` 引用的密钥就在那里面。 | 用 `miyu provider login` 把密钥存进密钥文件。 |
| 局域网访问 | 使用的是明文 HTTP：同一个网络里的人能看到访问密码、登录令牌和对话内容。 | 只在信得过的网络里打开；在外面时先连接 Tailscale、WireGuard 这类加密隧道。 |
| 通过 SSH 端口转发进来的连接 | 网页界面会把 `ssh -L` 这类不加转发头的连接当成本机：不需要密码，还能修改访问密码。 | 这种连接方式只留给自己用。 |
| 扩展 | 扩展以你的身份运行，不在沙盒里。你授予它的能力，它拿去做什么，Miyu 不会审查。被授予 `使用模型供应商的密钥` 能力的扩展，拿到的是那一家密钥的原文，你换了密钥之后，它也会拿到新的密钥。 | 不安装来路不明的扩展，见下面的「安装社区软件包之前」。 |
| 脚本、MCP 服务 | 开放权限下的脚本和所有 MCP 服务都以你的身份运行，不在沙盒里。 | 只接入你看过代码、信得过的脚本和 MCP 服务。 |
| 群里的人用到记忆和知识库 | 群里的 AI 照样有 `remember`、`forget`、`memory_search` 和写入知识库的工具，用的是和你同一份记忆，以及你的知识库。 | 给群设置一个关掉这些工具的预设，见 [接入通讯平台](heads/im.md#记忆和知识库)。 |
| 绑定成你本人的平台账号 | 这个账号的私聊按你的权限级别处理，不会被限制起来。如果账号被别人拿到，别人就能在这台电脑上以你的权限做事。 | 只绑定你自己使用、保管好的账号。 |
| 抓取不下来的网页 | 网址会交给 Exa、Firecrawl、Parallel 代为抓取；只有你的内网认得的主机名，连接不上时也一样会被交出去。如果联网服务选了 DeepSeek，要抓取的网址会先交给 DeepSeek。 | 见 [联网搜索和抓网页](web-search.md#隐私)。 |
| 撤销 | 撤销只回退对话，AI 修改过的文件、运行过的命令不会回退。 | 使用 git 这类版本管理工具，或者先备份，见 [会话](sessions.md#撤销恢复重做)。 |
| 花费 | 没有自动的花费上限。 | 留意用量，设置请求次数的上限，见 [让 AI 自己接着干](automation.md#没人看着时)。 |

## 哪些东西会离开这台机器

下面这些情况下，数据会离开你的电脑：

| 发给谁 | 发送的内容 | 什么时候发送 | 不想发送时 |
|---|---|---|---|
| 模型供应商 | 系统提示词、人格、对话、附件、工具的结果、想起的记忆、带进来的知识库片段。 | 每次请求模型时。 | 使用本机运行的模型服务，见 [模型](models.md)。 |
| OpenCode Go 的额度接口（`https://opencode.ai/inference/go/v1/usage`，如果改了 `providers.<编号>.quota.url`，就发到改过的地址） | 一次 GET 请求，带着这一家的密钥，不带对话内容。 | 会话使用 OpenCode Go 时，每轮结束后在后台查询一次。同一家 60 秒内查询过就不再查询；查询失败不报错。 | 不使用 OpenCode Go。 |
| 日常池的模型（没有配置时使用会话的模型） | 要整理的那段对话和相关的记忆，配置里引用的密钥原文和常见的密钥写法会先被遮掉。 | 自动记忆、整理记忆时。 | 在预设里关掉人格记忆，见 [记忆](memory.md#关闭和清除记忆)。 |
| 远程的语义模型 | 记忆、对话、知识库的文字。 | `models.embedding` 设置成远程模型时。 | 使用本机的 `embed`，见 [附加软件](addons.md#内置语义模型-embed)。 |
| 联网服务（你选的那一家，以及它用不了时自动尝试的几家） | 搜索的关键词。 | AI 搜索网页时。 | 关掉 `网络搜索`，见 [联网搜索和抓网页](web-search.md#关闭)。 |
| 代抓服务（Exa、Firecrawl、Parallel；联网服务选了 DeepSeek 时还有 DeepSeek） | 网址。 | Miyu 自己抓取不下来的网页；如果选了 DeepSeek，AI 每次抓取网页都会先交给它。 | 关掉 `抓取网页`。 |
| 网页所在的网站 | 一次普通的访问。 | AI 抓取网页时；时间线里的链接显示成卡片时。 | 和上一行相同。 |
| 远程的 MCP 服务 | AI 调用它的工具时传入的参数。 | 调用的时候。 | 不接入，或者在预设里关掉。 |
| 软件源 `https://miyu-agent.github.io/packages/` | 获取索引、下载软件包文件。 | 运行 `miyu pkg update` 时；搜索、安装、升级时本机的索引已经超过 24 小时。 | 不使用软件源。 |
| models.dev | 获取模型目录和各家的图标。 | 核心在后台运行，并且手上那份目录比 `models.catalog.every`（默认 `24h`）旧时。 | 运行 `miyu config set models.catalog.update false`。 |
| 汇率服务（Frankfurter，备用的是 open.er-api.com） | 币种和日期，不带用量。 | 用量的金额需要换算成其他币种时。 | 不查看换算后的金额。 |
| GitHub | 查询最新的发行版、下载。 | 你运行 `miyu upgrade`、运行安装脚本时。 | 不运行它们。 |
| 通讯平台 | AI 的回复和它发送的文件。 | 接入了通讯平台时。 | 不安装 `im`。 |
| 扩展自己连接的地方 | 取决于那个扩展。 | 被授予了 `联网` 能力的扩展。 | 不授予这个能力，或者不安装这个扩展。 |

Miyu 没有遥测：不会向任何地方报告你的用法、对话、报错，也不发送崩溃报告。终端界面崩溃时留下的调用栈只写在本机的缓存目录里。

## 常见用法的设置

下面是几种常见用法推荐的设置。

### 查看不熟悉的仓库

让 AI 帮你看一个不熟悉的仓库时，推荐这样做：

1. 用只读新建会话：

   ```bash
   miyu ask -C ~/src/unknown-repo --permission read-only "讲讲这个仓库是做什么的"
   ```

   ```powershell
   miyu ask -C $HOME\src\unknown-repo --permission read-only "讲讲这个仓库是做什么的"
   ```

   在终端界面或网页界面里，可以在打开会话以后按 `Shift+Tab` 切换到只读。
2. 仓库里的 `AGENTS.md` 每一轮都会交给 AI，里面写了什么 AI 都会读到。只读下 AI 改不了文件，但照样能读取你的磁盘、能联网。
3. 如果仓库里带了 `.miyu/config.toml`，`miyu ask` 会提示 `项目配置 … 尚未信任，本次没有使用`。项目配置只能收紧权限，所以无论信任与否，它都不会放宽权限。
4. 让 AI 动手修改之前，先运行 `git status` 确认工作区是干净的，修改完成后对照 diff 检查。

可以看：[权限和沙盒](permissions.md)、[会话](sessions.md)。

### 长时间无人值守运行

让 AI 长时间在没人看着的情况下工作时，推荐这样设置：

1. 定时任务每次新建的会话都没有人看着：需要确认的事情一律不执行，AI 也不能问你。因此受保护的命令那几类不会运行。
2. 给它一个只开启需要的功能的预设，用 `--preset` 指定。
3. 在那个预设里限制一轮最多请求几次模型：

   ```toml
   [limits]
   unattended_steps = 100
   ```

4. 如果只要它读取、不要它修改，就设置 `permission.start_read_only true`，这样新建的会话就是只读。
5. 隔一段时间查看用量：在终端界面里输入 `/usage`，或者打开网页界面设置里的 `用量` 页面。

可以看：[让 AI 自己接着干](automation.md#没人看着时)、[人格和预设](personas-presets.md)。

### 接入群聊

把 AI 接进通讯平台的群聊时，推荐这样设置：

1. 群里的会话本来就会被限制起来，不需要另外设置权限。
2. 给群设置一个收紧的预设，在 im 后台页的 `群聊默认值` 里选择它：关掉人格记忆，关掉 `kb_save`、`kb_edit`、`kb_delete`，只保留群里用得到的工具。
3. 后台页的 `设置 → 绑定 → 本人的平台 ID` 里只填写你自己的账号。
4. 名单以外的群和人，默认只记录、不回复，不要随手打开 `陌生群`、`陌生私聊` 的 `是否回复`。
5. 如果 NapCat 和 im 在同一台电脑上，把连接的监听地址改成 `127.0.0.1`。默认是 `0.0.0.0`，只靠 Token 挡住别人。
6. 如果你有内网域名，把它们写进 `net.internal_domains`，这样别人让 AI 抓取网页时，AI 不会访问这些域名。
7. 给群里的人设置用量上限和限流，见 [接入通讯平台](heads/im.md#限额和用量)。

### 部署到服务器

把核心放到服务器上运行时，推荐这样设置：

1. 用一个专门的系统用户运行核心，数据根放在 `/var/lib/miyu`，不要用某个人的家目录。仓库里的系统服务样例只有 Linux 的（systemd、OpenRC、runit、dinit）。
2. 网页界面只监听 `127.0.0.1`（默认就是这样），从你自己的电脑通过 `ssh -L` 或者 Tailscale、WireGuard 连接进去使用。
3. 如果要让其他设备直接打开网页界面，先设置一个足够长的访问密码，再打开局域网访问。不要把网页界面的端口直接暴露到公网上。
4. 如果通过反向代理访问，代理要加上 `X-Forwarded-For` 这类转发头，不加的请求会被当成来自服务器本机，不需要密码。

可以看：[常驻和服务器](service.md#部署到服务器)。

### 安装社区软件包之前

安装来自社区的软件包之前，建议按下面的步骤检查一遍：

1. 查看它是什么：

   ```sh
   miyu pkg info weather
   ```

   查看输出里的 `来源`（官方、社区、本机文件）、`上游` 仓库和 `需要的能力`。
2. 如果它要的能力比它说的用途多，就不要安装。例如一个查天气的软件包要求 `读取会话`、`写入文件`。
3. 社区的软件包没有经过审查。安装之前，去 `上游` 那个仓库看一眼代码，看看有没有人在用。
4. 别人直接发给你的文件夹或 `.miyu` 文件没有签名，比社区的软件包还少一层核对。
5. 安装之后，运行 `miyu pkg check <编号>` 可以看出软件包里的文件有没有被改过。

## 报告安全问题

不要在公开的地方贴出利用漏洞的细节。在核心仓库的 Security 页面点击 **Report a vulnerability** 私下报告（[直接打开](https://github.com/miyu-agent/miyu/security/advisories/new)，需要登录 GitHub），报告只有你和维护者看得到。其他仓库的问题也报告到这里。报告里要写什么，可以看 [SECURITY.md](../../../SECURITY.md)。
