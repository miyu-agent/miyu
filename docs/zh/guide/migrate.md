# 从 0.7 旧版迁移

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

如果你用过旧版 Miyu（0.7.x），并且已经安装了这一版，可以按照这一页把以前的人格、会话、记忆、设置和文件搬过来。

这一页路径里的 `~/.miyu` 指的是数据根（默认是 `~/.miyu`，Windows 上是 `%USERPROFILE%\.miyu`；如果设置了 `MIYU_HOME`，就是它指向的目录）。

## 开始之前

迁移之前，先了解下面几点：

- 这一版不认旧版的数据目录，也不会自己去搬。搬数据要用软件包 `migrate` 带来的命令 `miyu migrate`，需要先安装这个软件包。
- 旧版的数据目录默认也在 `~/.miyu`，和这一版的数据根在同一个位置。只要旧目录还在那里，这一版的核心就启动不了。所以第一步是把旧目录挪到别处。
- 迁移不会修改、删除旧目录。它会先把整个旧目录打包成一个压缩包 `miyu-0.7.tar.zst`，逐个文件核对，之后只从解压出来的副本里读取。压缩包放在 `~/.miyu/root/documents/旧版 Miyu 迁移/<时刻>/`，卸载 `migrate` 时也不会删除。
- 迁移没有「先看看、不动手」的模式。动手之前，它会检查旧版有没有停止、磁盘空间够不够；只要有一项不满足，就什么都不写。
- 迁移可以重新运行。已经迁移过的内容不会多出一份，详细的见下面的「重新运行和中途失败」。

迁移支持 Linux x86_64、macOS（M 系列）和 Windows x86_64。Linux aarch64 上没有这个软件包，运行 `miyu pkg install migrate` 会报 `不支持当前系统。`。

## 步骤

1. 关闭旧版：退出旧版的窗口和后台进程。如果旧版还在运行，迁移会拒绝开始。

2. 把旧目录挪到别处：

   ```bash
   mv ~/.miyu ~/.miyu-0.7
   ```

   ```powershell
   Rename-Item $HOME\.miyu .miyu-0.7
   ```

3. 安装这一版，方法见 [安装、升级、卸载](install.md)。如果你是在 AUR 上从旧的 `miyu` 包升级上来的，这一版已经安装好了。

4. 配置模型：

   ```sh
   miyu setup
   ```

   不配置模型也可以迁移：旧版配置的供应商、密钥和默认模型会被补进来。但是迁移记忆的那一步要让 AI 整理一次记忆，整理需要用到模型；如果那时还没有模型，这一步会被跳过，报告里写着 `整理没成（…）`，这种情况下迁移完成后再运行 `miyu memory dream` 即可。模型的配置方法见 [模型](models.md)。

5. 如果想把下面这些内容一起迁移过来，先安装对应的软件包（现在不安装的话，以后也可以补，见下面的表）：

   ```sh
   miyu pkg install im          # QQ 消息记录
   miyu pkg install memes       # 表情包
   miyu pkg install im-sponsor  # 赞助记录
   miyu pkg install goofish     # 闲鱼的登录态
   ```

6. 安装迁移用的软件包：

   ```sh
   miyu pkg install migrate
   ```

7. 开始迁移：

   ```bash
   miyu migrate ~/.miyu-0.7
   ```

   ```powershell
   miyu migrate $HOME\.miyu-0.7
   ```

   如果核心没有在运行，迁移会先把核心启动起来。迁移成功后会输出两行：

   ```text
   报告：/home/me/.miyu/root/documents/旧版 Miyu 迁移/20261114T083000Z/报告.md
   给 agent 的：/home/me/.miyu/root/documents/旧版 Miyu 迁移/20261114T083000Z/给agent.json
   ```

   输出的是完整路径，上面是 Linux 上的样子；在 macOS、Windows 上，输出的是那个系统上数据根的完整路径。

8. 阅读 `报告.md`，按照下面「阅读报告」一节核对。

`miyu migrate` 只接受一个参数：

| 写法 | 做什么 |
|---|---|
| `miyu migrate <旧目录>` | 把 `<旧目录>` 迁移进这一版的数据根 |
| `miyu migrate -h`、`--help` | 输出用法 |

如果参数的个数不对，会输出用法，退出码是 `2`。迁移进哪个数据根由 `MIYU_HOME` 决定，没有设置时是 `~/.miyu`。

## 迁移的内容

下面这张表列出了会迁移哪些内容，以及它们在这一版里变成了什么：

| 内容 | 来自旧版的哪里 | 在这一版里变成什么 | 需要先安装的软件包 |
|---|---|---|---|
| 人格 | 内置的 Miyu、开发模式，以及 `prompts/` 里你自己写的人设 | 内置的 Miyu 会新建成一个名字叫 `Miyu` 的人格，使用旧版的人设原文，你改过的角色扮演提示和示范对话覆盖在上面；开发模式对应出厂的 `软件工程师`（`software-engineer`）；你自己写的人设，每个都新建成一个人格。如果这一版里已经有同名的人格，就不再新建，直接使用已有的那个 | |
| 会话 | 会话库 `conversation.db` | 每个会话变成一个只读存档：可以查看、可以搜索，但不能接着聊，放在会话列表的 `存档` 一组里（见 [会话](sessions.md)）。文字、工具调用和结果、附件、AI 问你的问题、你中途插进去的话都保留着；子代理的会话作为子会话一起导入；旧版压缩时挤出去的轮次会插回原来的会话，如果原来的会话已经不在了，就归进 `旧版被挤出的对话` | |
| QQ 上的会话 | 会话库里绑定了 QQ 群、私聊的会话 | 变成那个群、私聊的只读存档。群里的一轮会按照每行开头的号码拆成每个人说的话 | |
| QQ 消息记录 | `history.sqlite3` | 转换成 `qq-records.jsonl` 放进这一次迁移的目录，再交给 `miyu im records import` 导入 im 的聊天记录 | `im`：如果没有安装，报告里会写明安装以后要运行哪一行命令 |
| 记忆 | 每个人格的 `memory.db` 里的知识点 | 导入对应的那个新人格，保留原来记下的时刻。说的是别人的事，就记成那个人的；说的是你的事，就记成你的。导入完成后整理一次，合并掉和已有记忆重复的内容 | |
| 配置和密钥 | `config.jsonc`，以及关于你的那份档案 | 迁移的内容包括：供应商（地址、密钥、模型的上下文窗口、温度、价格），默认模型（`models.chat`）、多模态模型（`models.vision`），远程的语义模型（`models.embedding`），三个挡位的模型分别进入 `lite`、`normal`、`flagship` 三个池，Tavily、Exa 的密钥和 SearXNG 的地址，关于你的介绍（`profile.about`），旧版的管理员 QQ 号会被认作你本人。只补充这一版里还没有的，已经配置过的保持不变。密钥会存进密钥文件 | |
| 表情包 | 你自己的表情包库，每个库一个文件夹 | 每个库做成一个图包 `legacy-memes-<库名>` 并安装 | `memes`：如果没有安装，图包会留在这一次迁移的目录里，报告里会写明安装以后要运行哪一行命令 |
| 技能 | 你自己写的技能 | 复制进 `~/.miyu/root/skills/<名字>/`。如果有同名但内容不一样的技能，就改名成 `<名字>-legacy`。旧版里停用的技能，在这一版里是打开的 | |
| 知识库 | 你自己放进知识库的文档 | 复制进一个新的知识库 `旧版知识库`（`~/.miyu/root/kb/legacy/`），这一版会自己建立索引。如果有同名但内容不一样的文档，就改名成 `<名>-legacy.<扩展名>` | |
| 文件 | 图片、文档、工具的产物、工作目录 | 图片放进 `~/.miyu/root/pictures/`；文档放进 `~/.miyu/root/documents/`；产物按会话分好，放进 `~/.miyu/root/documents/旧版产物/`；工作目录放进 `~/.miyu/root/workspace/旧版/`。如果有同名但内容不一样的文件，就改名成 `<名> (旧版 N).<后缀>` | |
| 闲鱼的登录态 | 闲鱼搜索的登录文件 | 复制进 `goofish` 软件包的状态目录。新的软件包不保证认得旧的格式；如果不认，按照新软件包的说明重新登录 | `goofish`：如果没有安装，就不复制 |
| 赞助记录 | 会话库里的赞助记录 | 导入 `赞助记录` 插件的账本，原来的时刻、金额、汇率保持不变 | `im-sponsor`：如果没有安装，安装以后重新运行迁移 |

复制过去的文件会逐个按照 SHA-256 核对。

## 不迁移的内容

下面这些内容不会迁移，它们都留在压缩包里，报告会逐项写明它们在压缩包里的哪个路径、是什么格式。需要的时候，可以让 AI 读取同一个目录里的 `给agent.json`，接着迁移。

| 内容 | 原因和处理方法 |
|---|---|
| 你自己写的脚本 | 这一版的脚本格式不一样。报告会逐个列出这些脚本；如果官方软件源里有同名的新软件包，报告会提示应该安装哪个 |
| 旧版包管理器安装的技能、脚本 | 不会复制。报告会写出软件源里对应的新软件包，用 `miyu pkg install` 安装即可 |
| 人格的子系统和插件开关、开发模式的提示词、没有选择人格时的系统提示词 | 这一版里没有对应的东西。人格和预设的用法见 [人格和预设](personas-presets.md) |
| 配置里的 CLI 中转供应商（`claude-code`、`codex`、`antigravity`、`codebuddy`） | 这一版的核心里没有对应的驱动。`antigravity` 有一个社区软件包 `antigravity` 带着驱动（只支持 Linux、macOS），安装以后手写这一家供应商；其他三家需要换成通过 API 接入的供应商。见 [模型](models.md#手写一家供应商) |
| 配置里的 `context`、`tools`、`cache`、`display`、`notifications`、`voice`、`skills` 段，以及看图、搜索以外的插件设置 | 这一版里没有对应的配置项 |
| 配置里的 `mcp` 段 | 需要在这一版里重新添加 MCP 服务，见 [扩展 Miyu](extending.md#mcp-服务) |
| QQ 的接入设置（管理员号码以外的部分） | 需要在 im 里重新接入 QQ，见 [接入通讯平台](heads/im.md#接入-qq) |
| 用量记录 | 这一版的用量账本暂时还收不进这些记录 |
| 终端的上键历史 | |
| QQ 收到的图片、文件、头像 | 这一版的 im 只记录占位，不保存内容 |
| 好感度、情绪这类 QQ 插件的数据 | 需要在这一版的 im 里重新做 |
| 记忆里的日记、逐轮经历、改动记录、旧的向量 | 只导入知识点。向量由这一版自己计算 |
| AI 自己的记忆、不在使用的记忆、超过 120 字的记忆 | 超长的记忆会写进 `给agent.json`，改短以后还可以接着导入 |
| 一次性的 `ask` 会话、成员的会话、QQ 以外平台的会话 | |
| 成员的家目录 | 这一版只给一个人使用 |
| 定时提醒 | 如果需要，按照报告里的内容重新设置，见 [定时任务](automation.md#定时任务) |
| 旧网页的登录密码、自定义样式 | 这一版的网页界面有自己的登录和外观设置 |
| 知乎、小红书、B 站搜索的登录态 | 这一版暂时还没有对应的软件包。B 站开播可以安装 `bilibili-live-stream`，在里面重新登录 |
| 旧版内置的默认知识库、默认表情包 | 不迁移 |
| 以前分享给别人的内容 | 不迁移 |
| 日志、缓存、索引 | 这一版会自己重建 |

旧版在数据根外面安装过的东西不会放进压缩包。迁移只检查下面这些位置，报告的 `数据根外面` 一节会列出其中存在的那几处：

- 家目录下的六个位置：`~/.local/bin/miyu`、`~/.config/fish/conf.d/miyu.fish`（如果设置了 `XDG_CONFIG_HOME`，检查的是它下面的 `fish/conf.d/miyu.fish`）、`~/.gemini/config/agents/miyu`、`~/.gemini/antigravity-cli`、`~/.cache/miyu/voice-models`、`~/.local/state/miyu`。
- 旧版终端集成写进 shell 启动文件的那一段：检查 `~/.bashrc`、`~/.bash_profile`、`~/.bash_login`、`~/.profile` 和 `~/.zshrc`（如果设置了 `ZDOTDIR`，也检查它下面的 `.zshrc`）。报告会写明这一段在第几行到第几行，例如 ``第 3～5 行、第 7～9 行是旧版终端集成写的一段，迁移不动它；在新版里跑 `miyu shellhook install --shell bash` 装上 bash 的集成时会先备份再删掉它，不用终端集成的可以自己删这几行。``

迁移只读取这些文件，不会修改它们，旧版终端集成的处理方法见下面的「迁移完成以后」。在 macOS、Windows 上也只检查这些位置；旧版装在其他地方的东西，报告里不会列出，需要你自己找出来、自己清理。

## 阅读报告

每运行一次迁移，就会新建一个目录 `~/.miyu/root/documents/旧版 Miyu 迁移/<时刻>/`，时刻是 UTC 时间，写法是 `20261114T083000Z`。如果界面语言是英文，这个目录叫 `Old Miyu migration`，两个文件叫 `report.md` 和 `for-agent.json`，报告也是英文的。目录里有这些文件：

| 文件 | 是什么 |
|---|---|
| `报告.md` | 给你看的报告 |
| `给agent.json` | 同一份报告的 JSON 版本，给 AI 读取，用来接着迁移没有迁移的内容 |
| `miyu-0.7.tar.zst` | 整个旧目录的压缩包 |
| `miyu-0.7.manifest.json` | 压缩包里每个文件的 SHA-256 |
| `qq-records.jsonl` | 有 QQ 消息记录时才会有 |
| `legacy-memes-<库名>/` | 有你自己的表情包库时才会有 |

`报告.md` 从上往下依次是：

- 开头：迁移的时刻、旧目录在哪里、压缩包在哪里。
- `人格`：一张表，列出旧版的每个人格对应到了这一版的哪个人格，结果是 `新建`、`已经有同名的`、`出厂的软件工程师` 或 `没映射上`。
- `每一类`：每一类内容一节，节名是这一类的英文名（例如 `sessions`、`memories`、`config`）。每一节先写结果：`迁了`、`迁了一部分`、`没迁，在压缩包里` 或 `不用迁`，然后写迁移了几条、跳过了几条、迁移到了哪里，最后是一句补充说明。如果没有安装对应的软件包，补充说明里会写明安装以后要运行哪一行命令。
- `数据根外面`：旧版在数据根外面安装过的东西。
- `没迁的`：一张表，列出每一项在压缩包里的路径和旧的格式。
- `旧数据根`：压缩包的大小和 SHA-256，以及什么时候可以删除旧目录。

报告里只写名字和条数，不会写密钥、cookie 和聊天内容。

## 确认迁移成功

迁移完成后，可以在下面这些地方确认内容已经迁移过来：

- 人格：设置页的人格列表里有 `Miyu` 和你自己的那几个人格。
- 会话：会话列表里的 `存档` 一组。
- 记忆：运行 `miyu memory list --persona <编号>`。
- 知识库：运行 `miyu kb list legacy`。
- 设置：运行 `miyu config get` 和 `miyu provider list`。
- 技能：查看 `~/.miyu/root/skills/`。

## 重新运行和中途失败

再运行一次 `miyu migrate ~/.miyu-0.7` 是安全的，适合在补装了漏装的软件包以后，把剩下的内容补迁过来：

- 会话：新会话的编号根据旧会话的编号算出来，已经导入过的会话不会再导入。
- 记忆：每条记忆都记着它来自旧版的哪一条，已经导入过的、你后来删掉的，都不会再导入。
- 配置：只补充还没有的配置。
- 人格：如果有同名的人格，就使用已有的，不会重新新建。
- 技能、知识库、文件：内容一样的算作已经迁移过；同名但内容不一样的会改名，和原来的并列放着。
- QQ 消息记录、赞助记录、表情包：接收的一方能认出已经有的内容，不会多出一份。

每运行一次都会重新打一个压缩包、多出一个目录，需要占用旧目录两倍大小的磁盘空间。如果在同一秒里运行了两次，后一次会报 `… already exists; wait a second and run again`。

如果迁移中途失败，会在标准错误上输出 `miyu migrate: <原因>`，退出码是 `1`。失败之前已经写进去的内容会保留，按照原因改好以后重新运行即可，已经迁移过的内容会被跳过。失败的那一次会留下：

- `~/.miyu/root/documents/旧版 Miyu 迁移/<时刻>/`：里面有压缩包，没有报告。确认以后可以删除。
- `~/.miyu/var/lib/migrate/<时刻>/`：解压出来用于核对的副本，里面有旧配置里的明文密钥。无论迁移成功还是失败，这个副本都会当场删除，平常不会留下；如果删除不了，会输出 `无法删除解包出来的旧数据副本 <路径>（<原因>）；里面有旧配置里的明文 Key，请手动删除`，这时需要你按照提示自己删掉它。

## 迁移完成以后

迁移完成以后，还剩下这几样东西需要处理：

- 旧程序：AUR 上旧的 `miyu` 包升级以后，就换成了过渡包 `miyu`，它自己不带任何文件，只依赖 `miyu-agent`；旧版的程序已经没有了。新版的 `miyu-core` 和 0.7 那一代的 `miyu` 互斥，见 [安装、升级、卸载](install.md#从-aur-安装arch-linux)。如果是用其他方式安装的，按照报告的 `数据根外面` 一节，确认是旧版的东西以后再删除。如果 `~/.local/bin/miyu` 是这一版的（安装脚本放的链接，或者早先的包装脚本），报告里会写 `这是新版的 miyu，不是旧版的，别删。`，这时不要删除它。
- 旧版的终端集成：迁移不会修改它，报告的 `数据根外面` 一节会列出它在哪个文件、第几行。如果要在这一版里使用终端集成，运行 `miyu shellhook install --shell <shell>`，安装时会先备份再清理旧版的那一份，见 [终端界面](heads/tui.md#清理旧版的终端集成)。如果不使用终端集成，可以按照报告里写的行号自己删除那几行；fish 的那一份是 `conf.d/miyu.fish`，可以直接删除。
- 旧目录 `~/.miyu-0.7`：迁移不会删除它。确认全部内容都迁移过来、用了一段时间也没有问题以后，再自己删除。
- 压缩包：保留着。以后想让 AI 接着迁移没有迁移的内容，需要用到它和 `给agent.json`。不再需要时，删除整个 `<时刻>/` 目录。
- `migrate` 这个软件包：用完以后可以运行 `miyu pkg remove migrate` 卸载。迁移的目录在 `~/.miyu/root/documents/` 里，卸载软件包时不会删除。

## 排查问题

| 看到的现象 | 怎么办 |
|---|---|
| 这一版启动不了，提示 `… 无法确认它是 Miyu 的数据根 …` 或 `… 是旧版 Miyu 的数据根，当前版本无法使用 …` | 旧目录还在 `~/.miyu`。按照上面的第 2 步把它挪开 |
| `old Miyu is still running (pid <进程号>); stop it first` | 旧版还在运行。关闭旧版，或者运行 `kill <进程号>`（Linux、macOS） |
| `old Miyu is still running; stop it first` | 旧版还在运行，但是迁移找不到它的进程号。Windows 上报的都是这一句。关闭旧版 Miyu 的窗口和后台程序以后再迁移；在 Windows 上，可以在任务管理器里找到它并结束 |
| `<路径> is not an old Miyu data folder` | 这个目录不是旧版的数据目录。检查一下是不是写错了路径 |
| `old Miyu did not finish moving its files (…); start the old version once to let it recover` | 旧版上一次搬移自己的文件时没有完成。用旧版启动一次，让它收尾，关闭以后再迁移 |
| `not enough disk space for the archive and its check under <目录>: need <N> MiB, have <M> MiB` | 磁盘空间不够：放压缩包的位置需要旧目录两倍大小的空间。腾出空间以后再运行 |
| `cannot reach the core: …` | 连接不上这一版的核心。见 [出了问题怎么查](troubleshooting.md) |
| ``run this as `miyu migrate <old folder>`: MIYU_STATE_DIR is not set`` | 你直接运行了软件包里的程序。需要改用 `miyu migrate` |
| 报告里写着 `整理没成（…）` | 迁移记忆时还没有可用的模型。配置好模型以后运行 `miyu memory dream --persona <编号>` |
| 报告里某一类是 `没迁，在压缩包里`，补充说明里说某个软件包没有安装 | 安装那个软件包，然后运行补充说明里的那一行命令，或者重新运行迁移 |
| 报告里写着 ``技能 `<名字>` 里有 N 个链接没拷…`` | 迁移不会跟随技能目录里的链接（它们可能指向技能外面），这些链接留在压缩包里。需要的话自己从压缩包里复制出来 |
| 报告里写着 `` `<路径>` 的 SKILL.md 是链接，指到技能目录外面…整个技能没拷 `` | 这个技能的 `SKILL.md` 是一个链接，迁移没有跟随它，整个技能都没有复制，留在压缩包里。需要的话自己从压缩包里复制出来 |
| 报告里写着 `知识库的清单 kb_meta.db 读不了（…），文档没迁` | 旧版知识库的清单读取不了，文档留在压缩包里。需要的话自己取出来，用 `miyu kb add` 添加进一个知识库 |
| 报告里写着 `会话库读不了（…），赞助记录没迁` | 旧版的会话库读取不了，赞助记录留在压缩包里 |
| 报告里写着 `N 笔时间读不懂，没迁` | 这几笔赞助记录的时间读取不了，迁移只跳过它们，其他记录照常导入；跳过的记录留在压缩包里 |
