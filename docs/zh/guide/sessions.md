# 会话

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

和 AI 的每一段对话就是一个会话。这一页讲怎么新建会话、怎么继续以前的会话、怎么指定 AI 工作的目录、怎么退回上一轮、上下文满了怎么处理，以及怎么重命名、导出、导入和删除会话。

会话的数据存放在数据根里（默认是 `~/.miyu`，Windows 上是 `%USERPROFILE%\.miyu`）。每个会话有一个编号，编号的写法是 UUID，也就是 `0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90` 这样按 8-4-4-4-12 位分组的十六进制数。终端界面、网页界面上经常只显示编号的最后 8 位，叫作短编号。

## 新建会话

在终端界面、网页界面和命令行里都可以新建会话。

终端界面：

1. 运行 `miyu`。直接运行 `miyu` 会打开设置里 `默认界面`（`ui.head`）指定的那个界面，出厂设置是终端界面。如果标准输入、标准输出不是终端（例如在脚本、管道里），就只输出帮助，退出码是 `2`。
2. 先在框里选择人格，再选择预设，选好以后才能打字。人格和预设是什么，可以看 [人格和预设](personas-presets.md)。
3. 输入第一句话，回车。

打开界面时是新建会话还是接着最近的那个会话，由设置页的 `通用 → 显示 → 启动时打开`（`ui.startup`）决定：可以选 `新会话`（`new`，出厂设置）或 `最近的会话`（`recent`）。如果已经在界面里了，输入 `/new` 就可以新建一个会话。

网页界面：

1. 点击左栏的 `新会话`。
2. 输入框上方有 `选择人格`、`选择预设`、`设置工作区` 三个按钮，没有点击的按钮使用默认设置。
3. 输入第一句话。第一句话发出去时，会话才会建好。

命令行：`miyu ask "<话>"` 会新建一个会话，说完这一句话、输出回答以后就退出。例如：

```bash
miyu ask "这个项目是做什么的"
cat 报错.log | miyu ask "为什么失败" -
miyu ask -C ~/src/app --preset full "跑一遍测试，修掉失败的"
```

```powershell
miyu ask "这个项目是做什么的"
miyu ask --file 报错.log "为什么失败"
miyu ask -C $HOME\src\app --preset full "跑一遍测试，修掉失败的"
```

如果没有写话，就从标准输入读取整段内容；如果话里有一个词正好是 `-`，就读取标准输入，接在话的后面。`miyu ask` 的全部参数如下：

| 参数 | 做什么 | 能不能和 `-c`、`-s` 一起写 |
|---|---|---|
| `-c`、`--continue` | 继续上一次 `miyu ask` 新建的会话 | 不能和 `-s` 一起写 |
| `-s`、`--session <编号>` | 继续这个会话 | 不能和 `-c` 一起写 |
| `-C`、`--cd <目录>` | 在这个目录里工作，这个目录必须已经存在。没有写时，使用你运行命令时所在的目录 | 不能 |
| `--add-dir <目录>` | 把另一个目录也算进这个会话的工作区，可以写好几次 | 能。继续会话时写了这个参数，原来加的那几个目录会整份换成这次写的 |
| `--persona <人格>` | 使用这个人格 | 不能；也不能和 `--no-persona` 一起写 |
| `--no-persona` | 不使用人格 | 不能 |
| `--preset <预设>` | 使用这个预设 | 不能 |
| `--permission <read-only\|full>` | 会话一开始的权限级别：只读或开放权限，见 [权限和沙盒](permissions.md) | 不能 |
| `--model <模型>` | 使用这个模型或 `@池`。继续的会话从此换成这个模型，见 [模型](models.md) | 能 |
| `--no-memory` | 这个会话既不召回记忆，也不保存记忆，见 [记忆](memory.md) | 不能 |
| `--file <文件>` | 附上一个文件，可以写好几次，见下面的「给 AI 文件和图片」 | 能 |
| `--format <text\|json\|jsonl>` | 输出格式。`text`（出厂）一边接收一边输出；`json` 在最后一行输出一个 JSON；`jsonl` 每行输出一个事件 | 能 |
| `--timeout <时长>` | 最多等待多久，例如 `30s`、`10m`、`1h`，不写单位时是秒。到时间后打断这一轮，退出码是 `3` | 能 |
| `--from <名字>` | 其他 agent 调用时报上自己的名字，例如 `claude-code`，这句话会记录成是它说的 | 能 |

如果 AI 派出了子代理，`miyu ask` 会等子代理都回报完、回答结束后才退出。退出码的意思如下：

| 退出码 | 意思 |
|---|---|
| `0` | 这一轮正常结束 |
| `1` | 出错，例如连接不上核心、被拒绝、模型出错 |
| `2` | 参数不对 |
| `3` | 被打断（`Ctrl+C`），或者到了 `--timeout` 的时间 |
| `4` | 这一轮结束了，但是有几步需要你确认，所以没有执行 |
| `5` | 没有可用的模型 |

## 继续以前的会话

在终端界面、网页界面和命令行里都可以找到以前的会话，接着聊下去。

终端界面：

- 输入 `/sessions`（别名 `/resume`）打开会话列表，列表可以搜索，按 `Enter` 切换到选中的会话。在列表里按 `Ctrl+P` 置顶，按空格勾选几个会话，按 `Ctrl+D` 删除。
- `/jump` 列出你在这个会话里说过的话，选一句就能跳过去。
- `/status` 的第一行 `会话 ID` 是完整的编号；侧边栏上显示的是短编号 `#…`。
- 从 shell 直接打开某个会话：运行 `miyu tui --resume <编号>`，如果打不开，会报错并退出。

网页界面：

- 左栏按时间分组列出会话。点击 `查看全部会话` 可以进入全部会话页面，在那里可以筛选和搜索。
- 输入 `/sessions <词>`，会在输入框上方打开会话列表，并用这个词搜索。
- 每个会话右边的 `⋮`（会话操作）菜单里有 `复制会话编号`。
- 从 shell 直接打开某个会话：运行 `miyu web --session <编号>`。

命令行：

```sh
miyu ask -c "测试怎么跑"                                     # 继续上一次 miyu ask 新建的会话
miyu ask -s 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90 "接着改"    # 继续指定的会话
```

`-c` 只认 `miyu ask` 新建的会话；在终端界面、网页界面里新建的会话，要用 `-s` 写上完整的编号。如果一次都没有用过 `miyu ask`，`-c` 会报 `没有可继续的 miyu ask 会话`。如果要在脚本里拿到会话编号，可以加上 `--format json`，输出最后一行里的 `session` 就是编号。

`miyu undo`、`restore`、`redo`、`compact`、`recap`、`rename`、`session export` 也都接受 `-s <编号>`；没有写时，使用上一次 `miyu ask` 新建的那个会话。

## 设置会话的工作目录

每个会话都记录着一个工作目录，AI 运行命令、写相对路径都从这个目录算起。会话建好以后会一直使用这个目录，只有你明确地更换，它才会改变；在一个界面里更换以后，其他界面也会跟着改变。

新会话的工作目录取决于从哪里新建：

| 从哪开 | 工作目录 |
|---|---|
| 终端 | 打开终端时所在的目录；如果新建会话前用 `/workspace <路径>` 换过目录，就使用换过的目录 |
| 网页 | 如果没有点击 `设置工作区`，就是这个会话自己的默认工作区 `~/.miyu/root/workspace/<会话编号>/`，界面上显示为 `默认工作区` |
| `miyu ask` | 运行命令时所在的目录；如果写了 `-C`，就使用 `-C` 指定的目录 |

更换工作目录的方法：

- 终端界面：输入 `/workspace <路径>`，相对路径从终端所在的目录算起。
- 网页界面：输入 `/workspace <路径>`；不带路径时，会打开选择目录的菜单。新会话还没有建好时，点击 `设置工作区`。
- 命令行：`-C` 只对新建的会话有效；继续的会话使用它自己记录的目录，如果这个目录和你所在的目录不一样，开头会输出一行 `· 会话的工作目录：…`。

在网页界面里，路径要写成绝对路径或者以 `~` 开头：Linux、macOS 上写 `/…`、`~/…`；Windows 上写 `C:\…`、`C:/…`，`~/…`、`~\…` 也可以识别。在数据根里面，只有 `~/.miyu/root/workspace/` 下面的目录能作为工作目录，其他目录会报不能使用；如果在数据根里运行 `miyu ask`，会改用这个会话的默认工作区，并提示 `工作目录 … 范围过大，改用 …`。

范围太大的工作目录也可以照常使用，命令会从那里开始运行；用 `/workspace` 换过去时，回执会显示 `工作区已切换到 …（范围较大）。`。根目录（Linux、macOS 上的 `/`，Windows 上 `C:\` 这样的盘根）在三个平台上都算范围太大；在 Windows 上，家目录本身和包含数据根的目录也算。Windows 上打开终端时一般就在家目录，如果要让 AI 在某个项目里工作：先 `cd` 进项目目录再运行 `miyu`；`miyu ask` 要写 `-C <目录>`；已经打开的会话输入 `/workspace <路径>` 换过去。

`--add-dir` 加的目录不能是 `~` 本身、家目录、根目录或者包含数据根的目录，也不能在数据根里面；如果写了这样的目录，整条命令都不会被接受。

## 撤回、恢复、重做

撤回只退回对话，不会把文件改回去。AI 在被撤回的那一轮里改过的文件、运行过的命令，仍然留在磁盘上。要找回文件，需要用 git 这类版本管理工具，或者用你自己的备份；Miyu 没有把文件改回去的命令。在终端界面输入 `/files`，或者查看网页界面右栏的文件修改那一块，可以看到这个会话改过哪些文件、每一步的差异，然后按照差异手动改回去。

| | 终端、网页 | 命令行 |
|---|---|---|
| 撤回最后一轮 | `/undo`（别名 `/rewind`） | `miyu undo`（别名 `miyu rewind`） |
| 恢复刚撤回的 | `/restore` | `miyu restore` |
| 撤掉最后一轮、原话重来 | `/redo`；网页界面里点击 AI 那一轮末尾的 `重做` | `miyu redo` |
| 撤掉最后一轮、换一句话重来 | `/edit`；网页界面里点击你那句话下面的 `编辑` | `miyu redo <新的话>` |

撤回的效果如下：

- 撤回的是最后一轮，也就是你的那句话和 AI 的回答，AI 从此看不到它们。从别处来的内容会保留，例如子代理的回报、定时触发、其他会话发来的消息，撤回的只是 AI 对它们的回应。
- 那一轮派出去、还在运行的后台命令和子代理会一起停止，回执会写明停止了几个。
- 如果被撤回的几轮里压缩过或者清空过上下文，上下文会一起回到压缩前、清空前的状态。
- 在终端界面、网页界面里，被撤回的那句话会放回输入框。如果 AI 正在回答，而你还有排队没有发出去的话，`/undo` 会先撤回排队的那一句。

恢复要在发出下一句话之前进行。如果连续撤回了几次，可以一次一次地恢复回来。重做以后就不能恢复了。

重做和编辑只对最后一轮有效，而且这一轮必须是由你的话开始的；AI 正在回答时不能重做或编辑。

## 上下文满了

AI 每次请求模型时都会带上会话的上下文。当上下文用到模型窗口的一定比例时，Miyu 会自动把旧的部分压缩成一段摘要，最近的一段保留原文，然后继续工作。

查看上下文用了多少：

- 终端界面的侧边栏会显示 `上下文`：用了多少 / 窗口多大 · 百分比。`/context` 会打开明细，显示每一块各占多少。
- 网页界面的输入框下面有显示上下文的一格，`/context` 会打开同样的明细。
- `/status` 里也会显示。

手动压缩可以使用：

```sh
/compact                         # 终端、网页里
/compact 保留数据库迁移那部分的细节   # 后面写给摘要的要求
miyu compact -s <编号> 只留结论      # 命令行
```

自动压缩有两项配置，在设置页的 `高级 → 压缩` 里，也可以用 `miyu config set` 修改：

| 键 | 设置页上 | 出厂值 | 做什么 |
|---|---|---|---|
| `compaction.line` | 压缩触发线 | `85` | 上下文用到窗口的百分之几时自动压缩，可以写 `20` 到 `95`。窗口小的模型需要给回答留出空间，所以实际会更早压缩：20 万的窗口调到 85 以上不起作用，百万的窗口才能用到 95 |
| `compaction.prepare` | 预压缩 | `true` | 快到压缩线时，先在后台把旧的那一段压缩好，到线时直接换上，不需要停下来等待。关掉以后，到线时才压缩 |

这两项都从下一轮开始生效。如果只想修改当前会话：

- `/compact-line 70`：这个会话用到 70% 时压缩，可以写 `20` 到 `95`；`/compact-line off` 恢复为跟随设置；只输入 `/compact-line` 会显示现在的值和它的来源。
- `/context 128k`：给这个会话设置上下文上限，数字后面可以接 `k`（千）、`m`（百万）；`/context off` 或 `/context unset` 会去掉上限，改为使用模型的窗口。如果上限太小、算不出压缩线，就不会被接受，网页界面会提示 `上下文上限至少要 …`。

如果不想要以前的内容了：

- `/clear`（别名 `/reset`）清空上下文，会话还是同一个，回执是 `已清空上下文。`。清空以后输入 `/undo`，会撤回清空前的最后一轮，清空也会一起被撤回。
- 或者用 `/new` 新建一个会话。

## 回顾

`/recap` 或 `miyu recap` 会让 AI 写一段回顾：正在做什么、做完了什么、还剩下什么。生成回顾要请求一次模型，但不会开始新的一轮。在命令行里，它只把这段回顾输出到标准输出，所以可以接管道。

## 停止

AI 正在回答时，可以用下面的方法让它停下来：

- 终端界面：AI 回答时按两下 `Esc` 打断，排队的话会接着发出去；按 `Ctrl+C` 打断，排队的话会退回输入框。
- 网页界面：AI 回答时按两下 `Esc` 打断。
- 命令行：按 `Ctrl+C`，退出码是 `3`。
- `/stop`：打断这一轮，排队的话保留但不发送，再停掉这个会话派出去的后台命令和子代理，这个会话的循环也会一起停止。回执是 `已全部停止。`。

## 重命名会话

会话的标题默认由 AI 根据对话起。

- 终端界面、网页界面：`/rename <标题>` 把标题改成你写的标题；只输入 `/rename` 会让 AI 根据最近几轮重新起一个；`/rename -` 会去掉你起的标题。
- 网页界面：在会话右边 `⋮` 菜单里选择 `重命名`，可以在列表里直接修改。
- 命令行：`miyu rename <标题>`，几个词之间用空格连接；不写标题时会让 AI 重新起一个。改好以后不会输出任何内容。

## 导出、导入

导出的会话有两种格式：

- 原始包（ZIP）：包含会话日志的原文、子代理的会话、分叉来源和附件，用于换电脑、换数据根时搬运会话。包里还有一份可以直接阅读的 `transcript.md`。导出的内容不会打码，需要你自己保管好。
- Markdown：给人阅读，或者贴给其他 AI。你配置过的密钥在里面会被替换掉。

Markdown 有三种用途：

| 命令行的 `--for` | 界面上 | 写成什么样 |
|---|---|---|
| `read`（出厂） | 仅导出对话为 Markdown 文件 | 带有标题、时间段、模型和用量，思考和长输出会折叠起来 |
| `agent` | 用于给其他 agent 继续 | 开头说明这是一段会话记录，工具写真实的名字和参数原文，默认从最近一次压缩开始，不带思考，全部使用英文 |
| `chat` | 用于网页端聊天对话 | 开头写 token 的估算，每个工具用一行写完，子代理只写回报，不带思考 |

命令行的用法如下：

```bash
miyu session export                                   # 上一次 miyu ask 的会话，写到 ./miyu-session-<编号前 8 位>.zip
miyu session export 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90 -o ~/备份/app.zip
miyu session export --md --for agent --last 20 -o -    # 最近 20 轮的 Markdown 输出到标准输出
miyu session import ~/备份/app.zip                     # 输出新导入的会话编号
miyu session import 旧会话.zip --archive               # 导入为只读存档
```

```powershell
miyu session export
miyu session export 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90 -o $HOME\备份\app.zip
miyu session export --md --for agent --last 20 -o -
miyu session import $HOME\备份\app.zip
miyu session import 旧会话.zip --archive
```

| 参数 | 做什么 |
|---|---|
| `export [<编号>]` | 导出会话，没有写编号时导出上一次 `miyu ask` 的会话。写好以后会输出文件写到了哪里 |
| `-o`、`--output <文件>` | 写到这个文件。没有写时，写到当前目录下的 `miyu-session-<编号前 8 位>.zip`，Markdown 是 `.md`。导出 Markdown 时写 `-` 会输出到标准输出 |
| `--md` | 导出为 Markdown |
| `--for <read\|agent\|chat>` | Markdown 的用途，只能和 `--md` 一起写 |
| `--last <轮数>` | Markdown 只导出最近几轮，只能和 `--md` 一起写 |
| `import <文件>` | 导入原始包，并输出新导入的会话编号；已经存在、并且内容一样的会话不会重复导入 |
| `--archive` | 导入为只读存档：可以查看、可以搜索，但是不能接着聊 |

导出的文件不能写进数据根里，已经存在的同名文件不会被覆盖。

终端界面：输入 `/export`，先选择用途（`完整存档` 或三种 Markdown），再选择 `复制到剪贴板` 或 `存成文件`。存档只能存成文件；超过 512 KiB 的 Markdown 也只能存成文件。文件会写在终端所在的目录里。复制使用终端的 OSC 52，如果终端不支持 OSC 52，内容复制不进剪贴板，也不会报错，见 [终端](heads/tui.md)。

网页界面：在会话右边的 `⋮` 菜单里选择 `导出…`。导出 Markdown 时可以选择范围（全部、现在的上下文、最近几轮）、是否带上思考、工具写成什么样，然后选择 `复制` 或 `下载`；`完整存档` 只能下载。导入在 `全部会话` 页面顶部的 `导入会话…`，选择一个 `.zip` 文件即可。

存档在会话列表里单独成一组，叫 `存档`。

## 给 AI 文件和图片

可以给 AI 的有图片、PDF、文本和其他文件。图片 AI 可以直接看到；如果模型看不了某种文件，界面会提示你。一个附件最大 20 MiB，图片最大 5 MiB，并且每边不超过 8000 像素。

终端界面：

- 把文件拖进终端窗口，或者输入 `@` 从列表里选择。图片、PDF、音频、视频会作为附件；其他文件和目录会以路径的形式写进话里，AI 需要查看时会自己去读取。
- 按 `Ctrl+V` 把剪贴板里的图片贴成附件。在 Windows Terminal 里贴图片要用 `Alt+V`。
- 超过 1 MB 的一段话会自动转成文字附件发出去。
- 超过大小上限的文件，只把路径交给 AI。

网页界面：

- 把文件拖进窗口、在输入框里粘贴，或者输入 `@` 从列表里选择。在用手指点击的设备上，输入框下面有一个回形针按钮。
- 一次最多 10 个文件。
- 对于超过上限的文件，网页界面会在这台电脑上找到原文件，只把路径交给 AI；如果找不到，点击这个文件填写完整的路径。如果网页界面是在其他设备上打开的，超过上限的文件无法发送。

命令行：使用 `--file <文件>`，可以写好几次。例如：

```sh
miyu ask --file 截图.png --file 日志.txt "这个报错和截图对得上吗"
```

数据根里的文件不能作为附件。

## 待办

AI 做多步的工作时会列一张待办清单。在网页界面的右栏可以查看；`/todo` 会列出现在的待办和每一项的状态（未开始、进行中、已完成），`/todo clear` 会清空待办。

## 删除会话

在终端界面和网页界面里都可以删除会话：

- 终端界面：`/delete` 删除当前会话，并换到一个新会话。AI 正在回答时不能删除，需要先打断。在 `/sessions` 列表里按两下 `Ctrl+D` 删除选中的会话，用空格勾选几个会话可以一起删除。
- 网页界面：在会话右边的 `⋮` 菜单里选择 `删除`；也可以点击左栏的 `多选`，勾选几个会话一起删除。

删除一个会话时，它派出去的子代理的会话会一起删除，正在运行的子代理会先停止。删除的会话会挪到 `~/.miyu/root/trash/sessions/<会话编号>/`，保留 7 天，核心下次启动时会清理掉已经满 7 天的会话。Miyu 没有把删除的会话找回到会话列表里的命令。

## 排查问题

下面是使用会话时常见的问题和解决方法：

| 看到的 | 怎么办 |
|---|---|
| `没有可继续的 miyu ask 会话` | `-c` 只认 `miyu ask` 新建的会话。在终端界面、网页界面里新建的会话，要用 `-s <编号>` |
| `工作目录 … 范围过大，改用 …` | 你在数据根里运行了 `miyu ask`。换到数据根外面运行，或者用 `-C` 指定目录 |
| `没有可恢复的撤回` | 撤回以后已经发出了新的话，或者已经重做过，所以无法恢复 |
| `无法重做` | 最后一轮不是由你的话开始的，或者这个会话还没有任何一轮 |
| `这是存档，不能接着说` | 导入时写了 `--archive` 的会话只能查看。如果要接着聊，不带 `--archive` 再导入一次原始包 |
| `上下文上限至少要 …` | `/context` 设置的上限太小，按照提示的数字往上调 |
