# 让 AI 自动工作

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

这一页介绍五种让 AI 不等你开口也能工作的功能：子代理、后台命令、定时任务、循环、长期目标，以及它们在没人看着时受哪些限制、怎么停止。

| 想做的事 | 使用 |
|---|---|
| 把一件大的工作拆给几个帮手并行完成 | 子代理 |
| 让一条耗时长的命令在后台运行，运行完再处理 | 后台命令 |
| 每天早上自动做一件事 | 定时任务 |
| 每隔几分钟检查一次某样东西 | 循环 `/loop` |
| 给出一个目标，让 AI 一直做到完成 | 长期目标 `/goal` |

这五种功能各由一个出厂软件包提供，只有预设里打开了对应的软件包才能使用：子代理是 `base-subagent`、后台运行是 `base-jobs`、定时任务是 `base-schedule`、循环是 `base-loop`、长期目标是 `base-goal`。出厂的 `全部功能`、`常规开发` 两个预设都打开了这五个软件包；预设的开关方法见 [人格和预设](personas-presets.md)。

## 子代理

子代理是 AI 另外开的一个会话。AI 用 `subagent` 工具把一件事交代给子代理，子代理在后台完成，做完以后把最后说的话作为报告，送回派它的会话。AI 在一步里调用几次 `subagent`，就会同时派出几个子代理。

### 派出子代理

直接告诉 AI 就可以，例如「派三个子代理，分别检查 `api/`、`web/`、`cli/` 三个目录里没用到的函数，汇总给我」。要不要派、派几个，由 AI 决定。

AI 派出子代理时可以选择这些选项：

| 选项 | 做什么 | 不写的时候 |
|---|---|---|
| 模型池 `pool` | 子代理使用这个池里的模型。只能选择 `subagent = true` 的池，见 [模型](models.md) | 使用派它的会话当时正在用的模型 |
| 人格 `persona` | 子代理使用这个人格。只能选择在 `persona.toml` 里写了 `subagent = true` 的人格，出厂的人格里只有 `software-engineer` 符合 | 不使用人格 |
| 接着当前对话 `fork` | 子代理从这个会话当前这一步的对话接着做，能看到前面聊过的全部内容，模型、人格和派它的会话一样。写了 `fork` 就不能再选择模型池和人格；fork 出来的子代理不能再 fork | 子代理只能看到交代给它的那段话，看不到这个会话的内容 |
| 只读 `read_only` | 子代理只能读取，不能修改 | 按照派它的会话的权限 |
| 附件 `attachments` | 一起交给子代理的文件，最多 8 个 | 没有附件 |

子代理和派它的会话使用同一个工作目录、同一份预设、同一个权限级别；如果派它的会话是只读的，子代理也是只读的。

子代理还可以再派出一层子代理，但不能再往下派。只有本机上的会话能派出子代理，通讯平台上的会话没有这个工具。

### 查看运行状态

子代理运行时，可以在界面上看到它们：

- 终端界面：输入框下面空出一行，然后是 `● 主会话` 一行，每个子代理各占一行，写着名字、正在做什么、用了多少 token 和多长时间。输入框空着时按 `↓` 移到这几行上，按 `Enter` 切换到那个子代理的会话；选中 `● 主会话` 那一行按 `Enter` 切换回来；选中一个子代理按 `x` 停掉它。
- 网页界面：输入框下面那一行的中间写着 `N 个后台任务`，点击展开后，列出这个会话的后台命令和子代理，子代理再派出的子代理挂在它下面。点击 `进入子代理会话` 切换进去。右侧边栏的 `后台任务` 卡片里也列着它们，点击后在主区域打开子代理的会话。

切换到子代理的会话以后，你可以直接对它说话。它的报告里会注明 `你在它做事时跟它说过话`，派它的 AI 能看到这一句。

### 接收报告

子代理做完一轮、空闲下来以后，会把这一轮最后说的话送回派它的会话。报告最多 30000 个字，超出时保留开头和结尾各一半。如果派它的会话正空闲，收到报告就会开始新的一轮接着工作；如果正在工作，会在下一步看到报告。AI 和子代理之间还可以用 `send_message` 互相留言。

### 停止子代理

可以用下面几种方式停止子代理：

- 让 AI 用 `jobs` 工具停掉某一个子代理。
- 终端界面：在主会话里、并且这一轮没有在运行时，连按两下 `Esc` 停掉这个会话派出的全部子代理；切换到某个子代理的会话时，连按两下 `Esc` 或者按 `Ctrl+C` 停掉它。也可以选中那一行，按 `x`。
- 网页界面：在 `后台任务` 里点击 `停止` 或 `全部停止`。
- `/stop`：打断这一轮，然后停掉这个会话派出的后台命令和子代理，这个会话的循环也会一起停止。

### 关掉后台运行时

如果预设里关闭了 `后台运行`（`base-jobs`），AI 派出子代理以后会原地等待它的报告，等到报告以后才进行下一步。

## 后台命令

AI 用 `shell` 运行命令时，可以把命令放到后台：AI 会马上拿到一个任务编号（例如 `j1`），然后接着做其他事；命令运行完以后，结果会自动送回来，不需要 AI 去查询。这个功能需要预设里打开 `后台运行`。

### 把命令放到后台

有两种情况命令会在后台运行：

- 你告诉 AI「在后台跑 `npm run build`，好了告诉我」。
- 前台的命令超过了时间限制（AI 没有指定时是 120 秒，最多可以指定 600 秒）还没有运行完，就会移到后台继续运行。

### 盯着日志

AI 运行后台命令时，可以要求「盯着」这条命令：命令的标准输出每输出一行，就马上交给 AI 一次，适合用来等待日志里出现某一行。如果几行挨着输出（间隔在 200 毫秒以内），会合并成一次交给 AI。标准错误不交给 AI，只写进输出文件。

如果一条盯着的命令在一小时里交给 AI 满了 120 次，这条命令会被停掉，并记录 `输出太频繁，已停止`。

### 查看运行状态

后台命令运行时，可以在界面上查看：

- 终端界面：输入框下面有一个 `N 个后台命令` 按钮。输入框空着时按 `↓` 移到这个按钮上，按 `Enter` 打开 `后台` 面板：用 `↑`、`↓` 选择，按 `Enter` 展开查看输出，按 `x` 停止，按 `Esc` 关闭。命令结束时，时间线上会记录一行 `后台命令完成 · <标题> · <用时>`，失败和被停掉的命令另有写法。
- 网页界面：和子代理一样，在 `N 个后台任务` 和右侧边栏的 `后台任务` 卡片里，点击 `查看命令和输出` 查看输出。

### 停止后台命令

可以用下面几种方式停止后台命令：

- 让 AI 停止：AI 会用 `jobs` 工具列出命令、读取输出、停掉命令。
- 在终端界面的 `后台` 面板里按 `x`；在网页界面里点击 `停止`。
- `/stop` 会停掉这个会话所有的后台命令和子代理。

核心停止或重启时，正在运行的后台命令都会被停掉，并记录 `核心重启时已停止`。

### 限制和默认值

| 限制 | 值 |
|---|---|
| 一条后台命令最多运行多久 | 由 `jobs.max_running` 决定，默认 `30m`，可以设成 `1m` 到 `2h`。到时间后命令会被停掉，并记录 `超时已停止` |
| 一条后台命令最多输出多少 | 5 GB，达到后命令会被停掉，并记录 `输出太大已停止` |
| 盯着的命令一小时内最多交给 AI 几次 | 120 |

如果要修改最长运行时间，可以在设置页（在终端界面、网页界面里输入 `/settings` 打开）的 `通用 → 会话 → 后台命令最长运行时间` 里修改，或者运行：

```sh
miyu config set jobs.max_running 1h
```

修改从下一轮开始生效。这个上限只对后台命令有效，不限制子代理。

## 定时任务

定时任务会在设定的时间把一句话交给一个会话，让 AI 运行一轮。任务记录在 `~/.miyu/root/schedules.db` 里（数据根默认是 `~/.miyu`，Windows 上是 `%USERPROFILE%\.miyu`）。

### 用命令添加

时间有三种写法，下面各给一个例子：

```sh
# cron：工作日早上 8 点
miyu schedule add --cron '0 8 * * 1-5' 看一眼昨晚的 CI，有失败的列出来

# 某个时刻跑一次
miyu schedule add --at '2026-12-01 09:00' 提醒我交月报

# 每隔一段时间，至少 60 秒
miyu schedule add --every 2h --session 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90 看一眼构建队列
```

任务在哪个会话里运行：

- 写了 `--session <编号>`：每次都交给这个已有的会话。
- 没有写：每次都新开一个会话。`--persona`、`--no-persona`、`--preset`、`--cwd` 决定新会话使用哪个人格、预设和工作目录；没有写人格、预设时使用默认的人格和预设，工作目录是每个新会话自己的默认工作区 `~/.miyu/root/workspace/<会话编号>/`。

查看、暂停、删除任务可以使用：

```sh
miyu schedule                 # 列出全部，每行开头是任务编号，例如 t1
miyu schedule pause t1        # 暂停
miyu schedule resume t1       # 恢复，从现在起重新算下一次
miyu schedule rm t1           # 删掉
```

每个参数的说明见 [命令行](cli.md#miyu-schedule)。

### 在网页界面里添加

网页界面的设置页里有一页 `定时任务`：每个任务占一行，写着那句话、什么时候运行、在哪个会话里运行、下一次几点运行，可以打开或关闭、暂停、继续、删除任务。点击 `新建`，填写 `说什么`，在 `什么时候` 里选择 `每天`、`每隔`、`一次` 或 `自定义`（自定义需要写五段的 cron），在 `在哪跑` 里选择 `每次新开会话` 或 `跑在会话`。点击一个任务可以看到上一次运行的结果。

右侧边栏的 `定时任务` 卡片里列着在这个会话上运行的任务，循环也列在里面。

终端界面里没有定时任务页，需要使用 `miyu schedule` 命令。

### 让 AI 创建定时任务

你可以告诉 AI「每天晚上 10 点提醒我写日记」，AI 会用 `cron_create` 在这个会话上创建一个定时任务，到时间后把这句话发回这个会话。

- AI 写的是五段的 cron，按照本机的时区计算。只运行一次的任务，运行完会自动删除。
- 在一个会话里，AI 最多创建 20 个定时任务。所有定时任务加起来（你创建的、AI 创建的、软件包创建的）最多 200 个，满了以后只会拒绝新建。
- AI 创建的任务和你用命令创建的任务记录在同一张表里。`miyu schedule` 和网页界面的 `定时任务` 页都能列出 AI 创建的任务（网页界面上标着 `AI 建的`）；AI 用 `cron_list` 能看到在这个会话上运行的全部任务，包括你用 `--session` 指定到这个会话上的任务，也能用 `cron_delete` 删除它们。
- AI 创建的任务到时间时，如果这个会话的预设关闭了 `定时任务`，这一次就不运行。你创建的任务不受预设影响。

### 到时间以后

定时任务到时间后，会按下面的情况处理：

- 如果会话正在运行一轮，这句话会排在这一轮的后面。
- 如果交给的是 `miyu ask` 开的会话、而且这时没有终端界面或网页界面打开着它：你创建的定时任务照常运行。AI 自己在这种会话里创建的定时任务和循环，只会把话记进会话，不开始新的一轮，等你下一次在那个会话里说话时一起看到；`miyu schedule` 里的上一次运行结果会写 `已记下，下次对话时处理`。
- 如果交给的会话已经被删除：任务会停止，留在表里等你删除。
- 核心没有运行时错过的任务不会补上。核心启动以后，从现在开始计算下一次。如果要准时运行，需要让核心常驻，见 [常驻和服务器](service.md)。如果没有人登录时也要运行，只有 Linux 做得到（`loginctl enable-linger`，或者安装成系统服务）；macOS、Windows 上的服务只在你登录时运行，见 [几个系统各自要知道的](service.md#各系统的差异)。

### 权限和确认

- 每次新开的会话：按照新会话的规则，使用开放权限；如果设置了 `permission.start_read_only`，就是只读。这种会话没有人看着：需要确认的事一律不做，时间线上会记录 `需要确认，无人确认`，AI 会换其他办法；AI 也不能向你提问。确认的规则见 [权限和沙盒](permissions.md)。
- 在已有会话上运行的任务：按照那个会话自己的权限。在终端界面、网页界面里打开的会话会弹出确认框，如果到了 `permission.confirm.timeout`（默认 300 秒）还没有人回答，就自动拒绝。

### 查看结果

定时任务运行完以后，可以在这些地方查看结果：

- 每次新开的会话运行完以后，终端界面、系统托盘会弹出一条系统通知 `定时任务跑完了` 或 `定时任务没跑完`，点击通知会打开那个会话。终端界面能不能弹出通知，取决于终端和系统：在 Windows 上，只有 WezTerm 这类自己能识别通知序列的终端才能弹出，见 [终端界面](heads/tui.md#通知)。系统托盘在三个系统上都能弹出通知，见 [系统托盘](heads/applet.md#通知)。
- 这些会话和其他会话一样列在会话列表里，打开就能看到时间线。
- 在网页界面的 `定时任务` 页里点击一个任务，可以查看上一次的结果；如果跳过了，会写明原因，例如 `会话已不在，任务停了`。

## 循环 /loop

循环让一句话在这个会话里反复运行。循环有三种写法：写固定间隔、不写间隔、什么都不写。输入 `/loop` 命令以后，会马上先运行一次。

### 固定间隔

```text
/loop 5m 看一眼 CI，有失败的告诉我
```

间隔可以写成 `30s`、`5m`、`2h`、`1d`，也可以写在后面：`/loop 看一眼 CI every 5m`。最短间隔是 60 秒，写得更短的按照 60 秒计算。

### 不写间隔：由 AI 决定下一次

```text
/loop 盯着部署，到了下一步再看
```

在每一轮里，AI 用 `schedule_next` 决定下一次在多久以后运行（至少 60 秒），也可以用它停止循环。如果某一轮 AI 没有决定下一次，循环就会停止。

### 什么都不写：自主循环

```text
/loop
```

不给具体要求时，由 AI 自己决定做什么、下一次什么时候运行，回执是 `已开始循环：由 AI 自己定做什么、下一次什么时候`。它和不写间隔的写法一样，会马上运行一次，每一轮用 `schedule_next` 决定下一次，不决定就停止；唯一的不同是，每次交给 AI 的不是你写的话，而是一句固定的英文：

```text
No new instructions. Continue on your own judgment, then schedule the next round or stop.
```

终端界面侧边栏 `循环` 那一部分、`miyu schedule` 列出的这个循环，显示的那句话也是它。

在网页界面里，如果在还没有开始的新会话里只输入 `/loop`，不会开始会话，只会提示 `请输入要循环说的话`；需要先说一句话开始会话，再输入 `/loop`。

### 写法错误

如果只写了间隔、没有写要说的话（`/loop 5m`、`/loop every 5m`），不会创建循环，而是返回用法：

```text
参数不对。用法：
/loop　不给具体要求，由 AI 自己定做什么、什么时候
/loop <间隔> <要说的话>　每隔一段时间说一次，例如 5m、2h
/loop <要说的话>　由 AI 自己定下一次什么时候
/loop off　停止此会话的循环（也可以写 clear、stop）
```

如果间隔写得认不出来（`/loop 5x 看看`），不算错误，整句会当作不写间隔的那种话处理。

### 查看运行状态

循环运行时，可以在界面上查看：

- 终端界面：输入框上面那一行的右边写着下一次运行的时间，如果有长期目标，显示在它的左边；侧边栏会多一个 `循环` 部分，写着多久运行一次、下一次的时间和那句话。
- 网页界面：输入框的右上方写着下一次运行的时间；右侧边栏的 `定时任务` 卡片里也列着它，标着 `循环`。

### 停止循环

运行：

```text
/loop off
```

这条命令会停掉这个会话的循环，回执是 `已停止此会话的循环。`。`off` 也可以写成 `clear` 或 `stop`（如果后面还跟着其他字，仍然会当作要说的话）。`/stop` 也会停止循环：它在打断这一轮的同时，会把这个会话的循环一起关掉。如果在 AI 正在一步步工作时输入 `/loop`，要等这一轮结束后才会运行第一次。

### 和定时任务的区别

循环和定时任务记录在同一张表里，`miyu schedule` 也能列出循环。区别在于循环跟随这个会话：

- 循环只在输入 `/loop` 的那个会话上运行，一个会话同时只能有一个循环，再输入一次 `/loop` 会替换掉原来的循环。
- 会话被删除后，循环也跟着停止。
- 只有预设里打开了 `循环` 的会话才有 `/loop` 命令，否则会回答 `没有这条命令`。

和定时任务一样，循环由核心负责运行，不需要开着终端界面或网页界面；核心停止时错过的运行不会补上。

## 长期目标 /goal

长期目标是给会话设定的一个目标。目标打开时，会话一空闲下来就会自己开始下一轮，直到 AI 报告完成或者卡住。只有本机上的主会话能使用长期目标，子代理和通讯平台上的会话没有这个功能。

### 设置、查看、停止目标

| 输入 | 做什么 |
|---|---|
| `/goal 把 tests/ 下失败的测试全修好` | 设定一个目标，会话空闲时就开始运行。如果已经有一个没有完成的目标，就是修改它；暂停或卡住的目标修改后会接着运行 |
| `/goal --rounds 20 把 tests/ 下失败的测试全修好` | 和上一行相同，但最多运行 20 轮。`0` 表示不限制，不写也是不限制；修改目标时，没有写的设置保持原来的值 |
| `/goal` | 查看进度：目标、状态、第几轮 |
| `/goal pause` | 暂停 |
| `/goal resume` | 继续 |
| `/goal clear` | 清除 |

AI 也可以自己用 `goal` 工具设定目标，但如果这个会话已经有目标，只有你能修改它。

### 完成和卡住

- 完成：AI 认为已经做完时，会用 `goal` 工具报告完成，然后写一段收尾的话给你。状态会变成 `已完成`，不再开始新的一轮。
- 卡住：AI 报告卡住时会写一句原因，状态变成 `受阻：<原因>`。目标至少运行过 3 轮才能报告卡住；如果这期间你说过话，就不受这条限制。卡住的目标和暂停的目标处理方式相同：运行 `/goal resume`，或者修改一下目标，它就会接着运行。
- 运行到 `--rounds` 设定的轮数时，记录为卡住。
- 如果有一轮 AI 一个工具都没有使用就结束了，状态会变成 `等待回复`，要等你说一句话以后才接着运行。
- 后台命令还在运行时，不会开始下一轮，而是等后台命令报告结果；最多等待 20 分钟，到时间后照常开始下一轮。
- 核心重启以后，打开着的目标会变成暂停，需要你运行 `/goal resume` 恢复。

除了 `--rounds`，长期目标没有时间和花费的上限。每一轮自己的上限见下面的「没人看着时」。

### 查看进度

- 终端界面：输入框上面那一行的右边写着 `长期目标 · 第 N 轮`（设定了轮数上限时写 `第 N/M 轮`），目标暂停、等待回复、受阻时，这里会换成显示状态。用鼠标点击它，会打开一个浮窗，显示目标、状态、轮数、用时和用量。
- 网页界面：输入框的右上方写着目标和第几轮。点击它会打开一个浮层，可以修改目标的原文，也可以点击 `暂停`、`继续`、`清除`。

## 没人看着时

上面这些自动开始的轮次（定时任务、循环、长期目标开始的轮次，以及后台命令和子代理的报告触发的轮次）都受下面这些限制：

| | 有人看着的会话里你开始的一轮 | 有人看着的会话里自动开始的一轮 | 没人看着的会话 | 子代理 | fork 出来的子代理 |
|---|---|---|---|---|---|
| 包括哪些 | 在终端界面、网页界面里你说一句话开始的轮次 | 定时任务、循环、长期目标、报告开始的轮次 | 定时任务每次新开的会话、通讯平台上的会话、`miyu ask` | `subagent` 派出的子代理 | `subagent` 带 `fork` 派出的子代理 |
| 一轮最多请求几次模型 | 不限制 | 由预设的 `[limits] unattended_steps` 决定，默认 `500` | 和左边一列相同，每一轮都计算 | `800`，不受预设影响 | `500`，不受预设影响 |
| 需要你确认的事 | 弹出确认框，等待 `permission.confirm.timeout`（默认 300 秒），没有人回答就自动拒绝 | 和左边一列相同 | 不做，记录 `需要确认，无人确认` | 按照派它的会话：如果派它的会话有人看着，确认框会弹到你那边，并标明是哪个子代理 | 和子代理相同 |
| AI 向你提问（`ask_user`） | 可以，并且一直等你回答 | 可以，并且一直等你回答 | 没有这个工具 | 没有 | 没有 |

如果一轮请求模型的次数达到上限，这一轮就会停在那里，网页界面上会显示 `已达请求次数上限`。如果要修改上限，在预设文件里写：

```toml
[limits]
unattended_steps = 200
```

详细的见 [人格和预设](personas-presets.md)。

花费没有自动的上限。如果要关注花费，可以看 [模型](models.md#用量和花费) 里的用量一节：在终端界面里运行 `/usage`、`/context`（按用途分开统计，子代理单独列出），在网页界面里查看设置中的 `用量` 页。

如果要全部停止，可以使用：

| 停止什么 | 怎么做 |
|---|---|
| 这一轮、后台命令、子代理 | `/stop` |
| 循环 | `/loop off`，或者 `/stop` |
| 长期目标 | `/goal pause` 或 `/goal clear` |
| 定时任务 | `miyu schedule pause <编号>`、`miyu schedule rm <编号>`，或者在网页界面的 `定时任务` 页里操作 |

## 排查问题

| 看到的现象 | 怎么办 |
|---|---|
| `需要确认，无人确认` | 定时任务新开的会话里没有人能确认。改成用 `--session` 在你开着的会话上运行，或者在 [权限和沙盒](permissions.md) 里关掉那一类受保护的命令 |
| 网页界面的定时任务写着 `会话的预设关了这个功能，这次没跑` | 这是 AI 创建的任务，而那个会话的预设关闭了 `定时任务` 或 `循环`。在预设里打开它们即可 |
| `会话已不在，任务停了` | 任务交给的会话已经被删除。删除这个任务，重新创建一个 |
| `新会话开不成，这次没跑` | 创建任务时指定的人格、预设或工作目录现在用不了。删除这个任务后重新创建 |
| `定时任务表坏了，原来的定时都没了` | 定时任务表读取不了，核心换成了一份空的表。需要重新创建定时任务 |
| 后台命令显示 `输出太频繁，已停止` | 盯着的命令输出的行太多。让 AI 用 `grep` 这类命令只保留需要看的行 |
| 长期目标停在 `等待回复` | 回复一句话，或者运行 `/goal resume` |
| 核心重启后长期目标不动了 | 运行 `/goal resume` |
| `/loop` 回答没有这条命令 | 这个会话的预设没有打开 `循环` |
