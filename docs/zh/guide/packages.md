# 软件包

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

这一页讲怎样查找、安装软件包，查看它需要的能力，启用和关闭它，升级和卸载它，怎样添加其他软件源，以及 Miyu 出厂带了哪些软件包。想自己写软件包，可以看 [写一个 Miyu 软件包](../dev/packages.md)。

下文路径里的 `~/.miyu` 指数据根：默认是 `~/.miyu`，Windows 上是 `%USERPROFILE%\.miyu`；如果设置了 `MIYU_HOME`，数据根就是它指向的目录。

## 软件包能带什么

一个软件包就是一个文件夹，文件夹的名字就是它的编号。一个软件包可以带下面任意一样东西，也可以几样混着带：

| 带的内容 | 安装后的效果 |
|---|---|
| 工具 | AI 多了几件可以调用的工具。 |
| 技能 | AI 多了一套做事的方法，你也可以在输入框里用 `$技能名` 点名使用它。 |
| 脚本 | 每个脚本就是一件工具。 |
| 斜杠命令 | 多了几条 `/命令`。 |
| 子命令 | 多了一条 `miyu <名字>` 命令。 |
| 界面 | 终端、网页这类和 AI 对话的地方。 |
| 外观 | 终端或网页的主题、吉祥物。 |
| 人格、预设 | 人格列表、预设列表里多了几项。 |
| 知识库 | 一套供 AI 查阅的资料。 |
| MCP 服务 | 接入一个现成的 MCP 服务。 |
| 常驻的程序（扩展） | 接入通讯平台、替你做事的程序，由核心启动并一直运行。 |
| 后台页 | 这个软件包自己的网页，可以在浏览器里管理它。 |

安装以后，软件包会是下面三种情况之一：

- 安装后自动运行：清单里写明了随核心一起启动的扩展。安装完成、你批准了它需要的能力之后，它就会在后台运行。
- 需要你手动打开：其他扩展，以及只带 MCP 服务的软件包。它们安装后是关闭的，安装时会问一句 `现在启用 '<编号>'？[Y/n]`，以后也可以在软件包页里打开。
- 只增加内容：只带技能、脚本、斜杠命令、人格、知识库的软件包。它们安装后就是打开的，可以关闭整个软件包；其中每个技能、脚本、命令还可以在预设里单独开关（见 [人格和预设](personas-presets.md)）。

## 查找和安装

软件包可以在命令行里查找和安装，也可以在终端界面、网页界面里操作。

### 使用命令行

在命令行里安装一个软件包，按下面的步骤操作：

1. 搜索软件包：

   ```sh
   miyu pkg search ocr
   ```

   结果一行一个软件包，格式是 `<编号>  <名字>  <说明>`。已经安装的软件包后面会加上 `（已安装）`，不是官方的加上 `（社区）`，被拉黑的加上 `（已拉黑：<理由>）`。如果写了几个词，结果里必须包含全部的词；不写词时列出全部软件包。如果一个都没有搜到，命令什么都不输出，退出码是 `1`。

2. 查看一个软件包的详情：

   ```sh
   miyu pkg info ocr
   ```

   如果这个软件包已经安装，显示的是本机那一份的信息；如果没有安装，就去软件源里查。每一行的格式是 `键 : 值`：软件源里的软件包多出 `软件源`、`来源`、`下载大小` 这几行，已经安装的多出 `被依赖`、`安装时间` 这几行。其余几行是 `编号`、`名称`、`版本`、`描述`、`依赖`、`推荐`、`提供`、`需要的能力`、`作者`、`上游`、`许可证`、`安装后大小`。没有值的行不显示，`依赖`、`推荐` 没有内容时写 `无`。如果只想查已经安装的软件包，运行 `miyu pkg -Qi <编号>`；只想查软件源，运行 `miyu pkg -Si <编号>`。

3. 安装软件包：

   ```sh
   miyu pkg install ocr
   ```

4. 查看确认屏，输入 `y` 或者直接按回车就会安装；输入其他字符则不安装，并提示 `已取消`。

5. 安装完成后会输出 `已安装 <编号> <版本>`，接着输出一行 `已批准 <编号> 的能力：…`。如果这个软件包有开关、而且还是关着的，会问 `现在启用 '<编号>'？[Y/n]`：回答是，就会打开它；回答否，会输出 `未启用 <编号>`，以后可以在软件包页里打开。

`miyu pkg install` 也可以安装本机上的软件包：

```sh
miyu pkg install ./hello            # 一个包含 package.toml 的文件夹
miyu pkg install ./hello-0.1.0.miyu # 一个 .miyu 包文件
```

如果写的内容带有 `/` 或 `\`、本身是 `.` 或 `..`、或者以 `.toml`、`.miyu` 结尾，都会被当作路径；其他情况当作编号。所以当前目录下的文件夹要写成 `./hello`，如果只写 `hello`，会去软件源里找。如果只想看一眼、不安装，运行 `miyu pkg info ./hello`：它会按安装时的规则检查清单，写错的地方在这一步就会报出是第几行。

加上 `--yes`（和 `--noconfirm` 相同）就不再询问：安装、升级、卸载都按回答「是」处理，需要的能力一并批准，推荐的软件包不安装，安装好的软件包直接打开。如果标准输入是关闭的（例如在脚本里运行），又没有加 `--yes`，命令会报 `已取消：没有收到确认`，并提示加上 `--yes`。

### 确认屏

从软件源安装时，命令先在标准错误上输出 `正在解析依赖…` 和 `正在检查冲突…`，然后显示确认屏：

```text
软件包 (1)  weather-0.3.0

下载大小    : 1.2 MiB
安装后大小  : 3.4 MiB
来源        : 社区，签名已验证（github.com/ann/weather）
需要的能力  : 联网：访问网络、开端口
              提供工具：给 AI 添加可以调用的工具

注意：这是个社区包，没有经过官方审核，可能存在风险。
安装 'weather' 并批准它要的能力？[Y/n]
```

- `软件包 (N)`：这一次要安装的软件包，缺少的依赖排在前面，一起安装。如果有推荐的软件包，会另起一行 `推荐 (N)`，问完主软件包之后再问一句 `同时安装推荐的 N 个软件包？[Y/n]`；如果推荐的软件包需要能力，会先列出 `推荐的包要的能力`。
- `来源`：官方的软件包写 `官方，签名已验证`；官方软件源里收录的社区软件包写 `社区，签名已验证`，后面接着来源仓库；你自己添加的软件源写它的名字。如果一次安装几个来源不同的软件包，每个软件包占一行，行首是编号。
- `需要的能力`：每项能力占一行，格式是 `名字：说明`。以前批准过、这一次仍然保留的能力，后面会加上 `（已批准）`。如果没有需要批准的能力，最后一句是 `安装 '<编号>'？[Y/n]`。
- `注意`：只有社区的软件包和从本机文件安装的软件包才会显示这一行。

安装本机的文件夹或包文件时，确认屏是另一种样子：

```text
将安装 hello 0.1.0
包含：扩展程序、技能 take-notes、脚本 dice
需要：联网：访问网络、开端口
来源：本机文件
大小：12.0 KiB，5 个文件

注意：这个包来自本机文件，没有经过官方审核，可能存在风险。
安装 'hello' 并批准它要的能力？[Y/n]
```

`包含` 这一行列出这个软件包带的内容，可能出现的有 `界面程序`、`扩展程序`、`小程序`、`内置功能`、`命令 miyu <名字>`、`后台页`、`吉祥物`、`主题`、`接入 <平台>`、`MCP 服务 <名字>`、`模型驱动 <名字>`、`技能 <名字>`、`脚本 <名字>`、`斜杠命令 /<名字>`、`人格 <编号>`、`预设 <编号>`、`知识库 <编号>`、`N 项设置`。读取失败、装上也用不了的技能和脚本会列在 `无法读取：` 后面，并附上原因。如果同一个编号已经装着一份，第一行后面会加上 `（替换 <旧版本>）`。

如果软件包里的模型驱动在清单里写明了会让模型供应商自己运行哪些工具，`包含` 下面每个这样的驱动会多一行，例如 `模型驱动 antigravity 会让供应商自己运行：search_web`；`miyu pkg info` 里也会显示这一行。在网页界面里由 AI 替你安装软件包时的确认，以及 `下载软件` 页面里已安装软件包的详情，也会在 `包含` 下面写这一句。

### 能力

能力是扩展这类常驻程序需要的权限。安装时会把它们列出来，你同意之后才会授予。没有批准的那一项，程序就用不了对应的功能。出厂的软件包视为已经批准了它声明的全部能力，但 `替本机页面换登录票` 和 `使用模型供应商的密钥` 这两项除外，即使是出厂的软件包，这两项也需要你批准。

| 确认屏上的名字 | 清单里写 | 说明 |
|---|---|---|
| `提供工具` | `tools` | 给 AI 添加可以调用的工具。 |
| `工具会运行命令` | `tools.commands` | 它提供的工具会运行命令，这些命令可以用当前会话的身份调用 AI 的工具。 |
| `提供命令` | `commands` | 添加斜杠命令。 |
| `在界面上显示内容` | `widgets` | 在首页、侧边栏、底栏和它自己的整页里显示它的内容。 |
| `往上下文里加内容` | `context.inject` | 在每一轮开始时往 AI 看到的内容里添加内容。 |
| `往系统提示词里放内容` | `context.system` | 在 AI 每一轮都会看到的系统提示词末尾放一段内容。 |
| `拦截工具调用` | `tool.guard` | 在工具执行之前放行、拒绝，或者先向你确认。 |
| `修改工具结果` | `tool.rewrite` | 在工具执行之后改写结果。 |
| `读取会话` | `events.read` | 读取会话里的全部记录。 |
| `写入会话记录` | `events.write` | 往会话里追加它自己的记录。 |
| `操作会话` | `sessions.drive` | 在会话里发消息、开新会话。 |
| `调用其他软件包` | `packages.call` | 调用其他软件包提供的方法。 |
| `提供联网服务` | `search` | 出现在联网服务的列表里；如果你选了它，搜索词会交给它处理。 |
| `提供模型驱动` | `model.driver` | 使用它提供的模型时，发给模型的全部对话都会经过它。 |
| `使用模型供应商的密钥` | `provider.key` | 它会拿到你在模型设置里配置好的某一家供应商的密钥。软件包会写明要哪一家的，确认屏上会显示 `这个软件包会拿到你 DeepSeek 的密钥` 这样的一句。你配置的哪一家算作那一家，判断方法和 [联网服务借 DeepSeek 的密钥](web-search.md#使用-deepseek) 相同；其他家的密钥不会给它。 |
| `代平台用户发言` | `act_for_external` | 替聊天平台上的人发消息、发命令。 |
| `替本机页面换登录票` | `login.page` | 它可以让本机打开的页面不用密码就登录进来。 |
| `联网` | `network` | 访问网络、开端口。 |
| `读取文件` | `fs.read` | 读取指定的文件和目录。 |
| `写入文件` | `fs.write` | 写入指定的文件和目录。 |
| `使用麦克风` | `audio.record` | 录制本机麦克风的声音。 |
| `播放声音` | `audio.play` | 通过本机的音箱、耳机播放声音。 |
| `写入记忆和知识库` | `memory.write` | 替 AI 记住、修改、忘掉记忆，创建、修改、删除知识库和里面的内容。 |

这一层权限管的是程序通过核心能做什么。扩展的程序本身以你的身份在这台电脑上运行，不在沙盒里。来路不明的软件包不要安装，详细的见 [安全](security.md)。

### 使用终端界面和网页界面

除了命令行，也可以在终端界面和网页界面里查找、安装软件包：

- 网页界面：输入 `/market` 打开设置页的 `下载软件` 页面。页面顶部是搜索框、`N 个可升级` 和 `刷新软件源`，下面有两排筛选（`全部`、`已安装`、`可升级`、`官方`、`社区`，以及按种类筛选），可以按 `默认`、`最新`、`下载量`、`趋势` 排序。点击一张卡片可以查看详情（来源、许可证、包含、提供、所需权限），然后点击 `安装`。社区的软件包会标着 `社区软件可能存在风险，避免随意安装`。
- 终端界面：输入 `/settings`，进入 `软件包`，第一页就是 `下载软件`。按 `/` 搜索，`空格` 勾选，`Enter` 安装，`s` 切换排序，`r` 刷新软件源，`,` 和 `.` 翻页，`Esc` 返回。安装之前同样会列出来源和能力，并问 `安装并批准所需的能力？ [Y/n]`。

AI 也可以替你查询软件源、安装软件包，这是出厂的「软件包」功能提供的。开放权限下 AI 每次都会先问你，只读下不会执行，详细的见 [权限和沙盒](permissions.md)。

## 启用和关闭

每个软件包都有一个 `启用` 开关，只带技能、脚本、内容的软件包也有，外观、界面、小程序、吉祥物也一样。关掉以后，它带来的工具、技能、脚本、命令、预设、知识库、内容、外观都会消失，扩展和它带的服务会停止；重新打开就会恢复。正在进行的会话从下一轮开始跟着变化。

| 在哪里 | 怎么操作 |
|---|---|
| 网页界面 | 输入 `/pkg` 打开设置页的 `软件包` 页面，每一行右边有一个开关。`基础系统` 这类组会收成一行，点进去可以看到组里的软件包。 |
| 终端界面 | 输入 `/settings`，进入 `软件包` → `已安装`，选中后按 `空格`。 |
| 命令行 | 运行 `miyu config set packages.<编号>.enabled false`，重新打开时写 `true`。 |
| 系统托盘 | 托盘里没有开关。如果软件包带后台页、清单里写了托盘入口，它开着时会在托盘菜单里占一行，点击这一行会打开它的后台页。 |

打开一个扩展时，如果它还有没批准的能力，会先列出来问你：网页界面显示 `启用前需批准以下权限：`，点击 `批准并启用` 即可；终端界面会问 `打开 <名字> 需要批准这些能力：`。

出厂的内置功能包比较特殊：关闭就是卸载，打开就是重新安装，详细的见下面的「三层」。

### 使用命令行开关

`packages.<编号>.enabled` 就是这个软件包的开关，和软件包页上的开关是同一个，`true` 表示打开：

```sh
miyu config set packages.base-jobs.enabled false
```

命令会回复 `已设置 packages.base-jobs.enabled = false（立即生效）`。这一项不会写进配置文件，手动写进 `config.toml` 的这一项不会被识别。出厂的内置功能包关闭就是卸载，此时 `miyu pkg list` 里它的后面会加上 `（已卸载）`，写 `true` 就会重新安装。

### 单独开关包里的内容

软件包带的每个技能、脚本、斜杠命令模板、MCP 服务，在预设里各是一个功能，可以单独开关，也可以逐个关闭它的工具。详细的见 [人格和预设](personas-presets.md)。

### 包的设置

软件包可以在清单里声明自己的设置项，这些设置存在 `~/.miyu/etc/config.toml` 里，键的格式是 `<前缀>.<名字>`。修改的方法有三种：在网页界面的 `软件包` 页面里点击一个软件包，进入它的页面修改；在终端界面的 `已安装` 里选中它，按 `Enter`；或者使用 `miyu config set`。详细的见 [配置](config.md#软件包的设置)。

### 后台页

如果软件包带后台页，可以用下面的命令在浏览器里打开它：

```sh
miyu pkg page im
miyu pkg page im --print   # 只输出网址
```

命令总会输出网址，所以即使浏览器没有打开，也能复制到网址。后台页由软件包自己的程序提供，如果程序没有在运行，会报 `<编号> 没有在运行，启用它以后再打开`。网页界面设置页的 `软件后台` 页面、终端界面 `软件包` 的第三页 `软件后台`，都列出了全部带后台页的软件包。

## 查看已安装的软件包

下面这些命令可以查看已安装的软件包和它们的文件：

| 命令 | 输出什么 |
|---|---|
| `miyu pkg list`（`miyu pkg` 相同） | 已安装的软件包一行一个，格式是 `<编号>  <名字>`。关闭的后面加上 `（已关闭）`，已卸载的出厂软件包加上 `（已卸载）`，清单写错的加上 `（清单有误：<哪里不对>）`。 |
| `miyu pkg files <编号>` | 列出它安装的文件，一行一个，格式是 `<编号> <绝对路径>`。 |
| `miyu pkg owns <路径>` | 输出 `<路径> 属于 <编号>`；如果路径在软件包的目录里、但安装时没有这个文件，会说 `不是安装时带的`；如果没有任何软件包包含这个路径，会报 `没有软件包包含 <路径>`，退出码是 `1`。 |
| `miyu pkg check [<编号>]` | 检查已安装的文件有没有被修改过：没有问题的软件包输出一行 `<编号>：正常`，有问题的每个文件输出一行 `已修改`、`缺失` 或 `多出`。如果有文件被修改或缺失，退出码是 `1`；`多出` 只是提示，软件包运行时自己写入的文件也算在内。出厂的软件包不检查；系统包管理器安装的只检查清单能不能读取、程序在不在。 |

这些命令都可以加上 `--format json`，输出一行 JSON。

日志在下面几个位置：

- 扩展的标准错误：`~/.miyu/var/log/<编号>/stderr`。网页界面的软件包页里，已经停止的扩展有一个 `查看输出`。
- 软件包带的 MCP 服务的标准错误：`~/.miyu/var/log/mcp/<服务名>.stderr`。
- 核心的运行日志：`~/.miyu/var/log/core.log`。

## 升级和清理

下面三个命令分别用来获取新的索引、升级软件包和清理缓存：

```sh
miyu pkg update    # 获取新的索引
miyu pkg upgrade   # 升级
miyu pkg clean     # 清理缓存
```

- `update`：每个软件源输出一行 `已更新 <源>：N 个包（<时刻>）`。不手动运行也可以：搜索、安装、升级时，如果本机的索引已经超过 24 小时，会自动去获取。如果连不上软件源，会继续使用本机的那一份，搜索时会提示 `无法连接软件源，使用本机索引（<时刻>）`。
- `upgrade`：只升级从软件源安装的软件包。从本机文件夹、包文件安装的软件包不会升级；出厂的软件包跟着 Miyu 自己升级（`miyu upgrade`）；用系统的包管理器（例如 `pacman`、Homebrew）安装的软件包由系统的包管理器升级，`miyu pkg upgrade` 不处理它们。只要软件源里的版本和已安装的不一样就会升级，所以如果作者撤回了新版，也会跟着退回去。确认屏上每个软件包一行 `将升级 <编号> <旧版本> → <新版本>`，新版额外需要的能力列在下面的 `新要：` 里，然后问 `升级 '<编号>' 并批准新要的能力？[Y/n]`。设置、状态、开关和以前批准过的能力都会保留。如果不批准新版额外需要的能力，打开它时会再问一次。
- `clean`：删除缓存里不是当前安装版本的包文件，输出 `已清理 N 个包文件，释放 <大小>`。

下面五种情况不会升级，命令会在标准错误上分别提示一句，继续使用已安装的版本，其他软件包照常升级：

| 提示 | 原因 |
|---|---|
| `跳过设为不升级的 <编号>` | 这个软件包在 `packages.hold` 里。 |
| `<编号> 已不在软件源中，保留已安装的版本` | 软件源里已经没有它了，或者安装它的那个软件源已经从配置里删除。 |
| `<编号> 已被拉黑：<理由>` | 软件源拉黑了它。要不要卸载由你自己决定，提示里会说明怎么卸载。 |
| `<编号> 改由 <仓库> 提供，未升级` | 这个编号换了来源仓库。因为换来源就是换了你要信任的人，所以不会自动升级。 |
| `<编号> <版本> 需要 Miyu <版本>，跳过` | 软件源里的新版要求更新的 Miyu。先更新 Miyu，再运行 `miyu pkg upgrade`。 |

如果想钉住一个软件包、不让它升级，运行：

```bash
miyu config set packages.hold '["im"]'
```

```powershell
miyu config set packages.hold "['im']"
```

写入的是整份列表。在 PowerShell 里，按上面的写法外面用双引号、里面用 TOML 的单引号字符串，Windows PowerShell 5.1 和 PowerShell 7 都可以直接复制使用。

网页界面的 `下载软件` 页面顶部有 `N 个可升级` 和 `全部升级`；在终端界面的 `已安装` 里，按 `u` 升级选中的软件包，按 `U` 全部升级。

## 卸载软件包

卸载软件包使用 `miyu pkg remove`：

```sh
miyu pkg remove ocr
miyu pkg remove --purge ocr   # 连同配置一起删除
```

运行后会显示确认屏：

```text
将卸载 ocr 0.2.0
会删掉 /home/me/.miyu/var/lib/ocr（3.1 MiB）
配置留在 /home/me/.miyu/etc/ocr，另有 2 项设置
大小：18.4 MiB，12 个文件

卸载 'ocr'？[Y/n]
```

中间两行显示的是完整路径。上面是 Linux 上的样子；macOS 上的路径类似 `/Users/me/.miyu/var/lib/ocr`，Windows 上类似 `C:\Users\me\.miyu\var\lib\ocr`。

- 会删除的：软件包文件夹 `~/.miyu/opt/<编号>/`；`~/.miyu/` 下 `var/lib/`、`var/cache/`、`var/log/`、`tmp/`、`run/` 里属于它的 `<编号>/`；它带的脚本的状态目录。
- 会保留的：配置目录 `~/.miyu/etc/<编号>/`，以及 `~/.miyu/etc/config.toml` 里它的设置项。重新安装同一个编号时会继续使用它们。只有加上 `--purge`（和 `-n` 相同）才会一起删除。
- 如果其他已安装的软件包依赖它，它就卸载不掉，会报 `其他软件包依赖它，无法卸载`。

在网页界面里，软件包的页面上有 `卸载` 和 `卸载并删除配置`；在终端界面的 `已安装` 里，选中后按 `d`。

## 三层

同一个编号的软件包可能在三个地方各有一份：

| 层 | 位置 | `miyu pkg info` 的 `来源` |
|---|---|---|
| 出厂 | 随 Miyu 一起安装的资源目录里的 `packages/<编号>/`。 | 出厂 |
| 系统的包管理器安装的 | Linux：`$XDG_DATA_DIRS` 里每一个目录下的 `miyu/packages/<编号>/`，没有设置时是 `/usr/local/share/miyu/packages/` 和 `/usr/share/miyu/packages/`，排在前面的优先；Linuxbrew 安装的不会被自动识别，需要你自己把 Linuxbrew 的 `share` 目录写进 `XDG_DATA_DIRS`。macOS：Homebrew 前缀下的 `share/miyu/packages/<编号>/`，前缀是 `miyu` 所在目录的上一级。Windows 没有这一层，只有出厂的和你安装的。 | 系统装的 |
| 你安装的 | `~/.miyu/opt/<编号>/` | 官方、社区、本地 |

如果同一个编号在几层都有，你安装的优先，其次是系统包管理器安装的，最后是出厂的；被盖住的那几份不会加载。如果系统包管理器安装的那份比你安装的新，`miyu check` 会提示一句，并说明怎么换回去。

- 和出厂软件包编号相同的软件包无法安装，会报 `编号与内置软件包重复`。
- 卸载出厂的、系统包管理器安装的软件包时，不会删除文件，只在 `~/.miyu/etc/removed/<编号>` 里记一笔，之后不再加载。要删除系统包管理器安装的文件，需要使用系统的包管理器。
- 重新安装：运行 `miyu pkg install <编号>`。网页界面的开关、终端界面 `已安装` 里的 `空格` 也可以装回来。
- 整组操作：`miyu pkg remove tasks` 会卸载 `任务和定时` 整组，`miyu pkg install tasks` 会把组里卸载掉的装回来。网页界面在组那一层有 `全部卸载` 和 `全部装回`。

## 软件源

默认的软件源是 `https://miyu-agent.github.io/packages/`，`miyu pkg search` 和 `miyu pkg install <编号>` 用的就是它。

- 索引文件是 `index.json`，签名是旁边的 `index.json.sig`，使用 Ed25519。官方的公钥编译在 `miyu` 程序里，签名验证不通过的索引会被整份拒收。本机保存的那份索引每次读取时都会重新验证一遍。
- 包文件会按照索引里写的 SHA-256 核对，对不上的不会安装。
- 软件源里有官方的软件包和社区的软件包。社区的软件包是作者给自己的 GitHub 仓库打上 `miyu-package` 话题之后，由软件源每天收录一次收进来的，没有人审核过。可以这样分辨它们：`search` 的结果行末有 `（社区）`，`info` 的 `来源` 写着 `社区，没有经过官方审核`，安装之前有 `注意`，网页界面的卡片上标着 `社区`。
- 不在任何软件源里的软件包（例如别人发给你的文件夹、`.miyu` 文件）没有签名，也没有人审核过，安装之前确认屏会显示 `这个包来自本机文件，没有经过官方审核，可能存在风险。`。详细的见 [安全](security.md)。

软件源的设置都写在 `~/.miyu/etc/config.toml` 里，修改后立即生效：

| 键 | 默认 | 做什么 |
|---|---|---|
| `packages.source` | `"https://miyu-agent.github.io/packages/"` | 官方软件源的地址。换了地址以后，那边的索引也必须是官方签名的。 |
| `packages.mirrors` | `[]` | 官方软件源的镜像，按先后顺序尝试，都失败时再试 `packages.source`。镜像改不了内容，因为照样会验证签名、核对哈希。 |
| `packages.hold` | 没有 | 升级时跳过的软件包的编号。 |
| `packages.sources.<名字>.url` | 没有 | 其他软件源存放索引的那一层目录。 |
| `packages.sources.<名字>.key` | 没有 | 给那个软件源的索引签名的 Ed25519 公钥，base64 格式，最多 64 个字符。 |

例如，添加一个朋友的软件源：

```toml
[packages.sources.friends]
url = "https://friends.example.com/miyu/"
key = "bWl5dS1leGFtcGxlLWtleS1ub3QtcmVhbC0wMDAwMDA="
```

- `url` 和 `key` 都写了才算一个软件源；添加一个软件源就表示你信任它，它的索引会用这把公钥验证。
- 软件源的名字不能是 `official`。
- 安装时先在官方软件源里找，再按名字的先后顺序在你添加的软件源里找。软件包从哪个软件源安装，升级时也只从那个软件源升级。
- 确认屏的 `来源` 会写这个软件源的名字，例如 `friends，签名已验证`。

在网页界面的设置页里，这几项设置在 `高级` 页的 `软件源` 那一组。

带程序的软件包是按系统分别打包的，只有下面这些系统有对应的包。在其他系统上安装会报 `不支持当前系统。`：

| 编号 | Linux x86_64 | Linux aarch64 | macOS（M 系列） | Windows x86_64 |
|---|---|---|---|---|
| `tui`、`webui`、`embed`、`office` | 有 | 有 | 有 | 有 |
| `im`、`im-sponsor`、`ocr`、`render`、`memes`、`migrate` | 有 | 没有 | 有 | 有 |

其他软件包不区分系统，在哪里都能安装。表里标着「脚本」的软件包都是用 Python 写的，需要本机安装了 Python 3；在 Windows 上需要自己安装 Python，并且 `python` 要能在 `PATH` 里找到，详细的见 [扩展 Miyu](extending.md#怎么跑)。`office` 自带 Python 和 LibreOffice 引擎，不需要另外安装。

换了操作系统以后，带程序的软件包需要重新安装新系统的那一份，详细的见 [数据和备份](data.md#迁移到其他操作系统)。

下面这些编号曾经被社区收录过，已经被占用：`antigravity`、`fake-id`、`github-bot`、`gray-intel`、`luckin-coffee`、`shorin-niri-use`、`webui-theme-claude-style`、`webui-theme-deep-whale`。

软件源每天更新，所以这张表会过时。现在有哪些软件包，以 `miyu pkg search` 的结果为准；一个软件包具体带了什么，可以用 `miyu pkg info <编号>` 查看。

## pacman 写法

如果你用惯了 pacman，下面这些写法也可以使用：

| pacman 写法 | 等同于 |
|---|---|
| `miyu pkg -S <编号>…` | 从软件源安装这几个软件包 |
| `miyu pkg -Sy` | `update` |
| `miyu pkg -Sy <编号>…` | 先 `update` 再安装 |
| `miyu pkg -Ss [<词>…]` | `search` |
| `miyu pkg -Si <编号>` | 只查软件源的 `info` |
| `miyu pkg -Su` | `upgrade` |
| `miyu pkg -Syu` | 先 `update` 再 `upgrade` |
| `miyu pkg -Sc` | `clean` |
| `miyu pkg -U <路径或编号>` | `install` |
| `miyu pkg -R <编号>` | `remove`，`-Rn` 等同于 `remove --purge` |
| `miyu pkg -Q` | `list` |
| `miyu pkg -Qi <编号>` | 只查已安装软件包的 `info` |
| `miyu pkg -Ql <编号>` | `files` |
| `miyu pkg -Qo <路径>` | `owns` |
| `miyu pkg -Qk [<编号>]` | `check` |
| `--noconfirm` | `--yes` |

`-S` 后面什么都不写会报 `没有指定目标`，退出码是 `2`。`-Qi`、`-Si` 只接受编号，写路径会报错；要查看文件夹、包文件，使用 `miyu pkg info <路径>`。

全部参数可以看 [命令行](cli.md#miyu-pkg)。

## 排查问题

报错会输出在标准错误上，以 `miyu: ` 开头。

| 看到的报错 | 怎么解决 |
|---|---|
| `未找到软件包 '<编号>'`、`软件包不存在` | 编号写错了，或者索引太旧：运行 `miyu pkg update` 之后再搜索。安装当前目录下的文件夹要写成 `./<文件夹>`。 |
| `软件源连不上` | 网络不通或者地址不对。检查 `packages.source`；如果连不上官方软件源，可以添加 `packages.mirrors`。 |
| `软件包下载失败` | 所有地址都没有下载成功，或者下载下来的文件哈希对不上。过一会儿再试，或者换一个镜像。 |
| `不支持当前系统。` | 这个软件包没有为你的系统打包。 |
| `无法安装 <写的>：package.toml:<行>: …` | 清单写错了，按照报错里说的那一行修改；如果不是你写的软件包，需要找作者。 |
| `无法安装 <写的>：<哪一样> <名字> 已在 <包> 中` | 它带的工具、技能、命令、MCP 服务等和已安装的其他软件包重名，每一处重名占一行。卸载那一个软件包，或者找作者改名。 |
| `编号与内置软件包重复` | 本机的软件包用了出厂软件包的编号，需要修改文件夹名。 |
| `缺少依赖的软件包` | 依赖的软件包不在软件源里，或者版本不够新。 |
| `无法安装 <写的>：…这个软件包要求 Miyu <版本> 或更高版本，需要先更新 Miyu` | 运行 `miyu upgrade`。 |
| `其他软件包依赖它，无法卸载` | 先卸载依赖它的那几个软件包。 |
| `程序未安装` | 软件包里的程序不存在，需要重新安装这个软件包。 |
| `扩展权限未批准` | 打开它时批准它需要的能力。 |
| `已取消：没有收到确认` | 在脚本里运行时，加上 `--yes`。 |
| 网页界面的软件包页上，扩展显示 `已停止` 或 `连续失败 5 次，已停止` | 点进去使用 `查看输出`，或者查看 `~/.miyu/var/log/<编号>/stderr`。 |
| 软件包页上显示 `缺少依赖：<编号>` | 安装缺少的那几个软件包。 |
