## UC-2：旁路请求的用量记场所

状态：主会话做。接入QQ（onebot 会话）要的：im 的统计页照场所分用量，判官、入群审批这些经 `model.call` 发的请求一行都看不到，主人看「请求构成」只有回复。

### 一、做了什么

1. `model.call` 写了 `session` 的（旁路请求，只跟着 `side`），记账时挂上那个会话的场所：账号日志 `usage.oneshot` 的 `body` 多 `venue`，用量汇总那一行的 `venue` 照它填。`usage.query` 照 `venue`、`purpose` 分组就分得出「这个群的判官用了多少、缓存命中多少」。
2. 没写 `session` 的（入群审批）照旧不挂场所；替看图、向量化、记忆的后台请求也不挂。
3. 不加扩展自报场所的参数：扩展报的不可信，照会话算最稳。
4. 老的账号日志没有这一格，照旧读（`serde` 默认没有）。

### 二、怎么验

1. 存储 `usage.rs`：带场所的一行照场所、用途分得出来，删掉汇总照账号日志重建以后照样分得出。
2. 端点 `model_call_side.rs`：写了 `session` 的那一次挂上那个会话的场所（`local`），没写的不挂。
3. 手写变异 3 个全杀：调模型时场所写成空、记账时场所写成空、写进账本那一行删掉。
4. 本机门禁。
