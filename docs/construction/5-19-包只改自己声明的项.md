## 施工单 5-19：包只改自己声明的项

状态：合了（2026-10-22，f692bc11）。漏洞排查会话 2026-10-22 查出、复现测试是红的（补丁 `~/.cache/miyu-audit/core-audit-tests.patch`，中）；主会话排给 core2。只有技术细节，直接做。

### 目的

核心拉起的扩展改配置（`config.set`，施工 T-9 补）只看「键以自己的包编号开头、是清单里有的项、不是密钥」。包编号和核心模块同名的包（叫 `ui`、`sandbox`、`external` 的），只要自己不声明 `[settings]`，起来时的 `settle` 就不拦它（`settings_taken` 只查声明了配置项的包），于是它改得了核心自己的项：`ui.*`，换个名字就是管理员才能定的 `sandbox.tools.<名>`、`external.bindings.<外部身份>`。做完以后只认这个包清单里声明的项：配置清单里那一项的 `ui.package` 是这个包。

### 蓝图改哪几节

- `config.md`「`config.set`」的例外那一句：键以自己的包编号开头、是这个包清单里声明的项，写明为什么光看开头不够。
- `extensions.md`「守着它的」：加审计那一条。

### 不做什么

- 不拒装和核心模块同名的包：没声明配置项的同名包照旧装得上、跑得起来，只是改不了核心的项。拒装是产品取舍，要问项目主人，不在这一步。
- `secret.set`、`config.trust` 本来就对扩展回 `local_only`，不动。

### 验收

1. `cargo test -p miyu-endpoint --test all audit_extension_core_key`：叫 `ui` 的扩展改 `ui.language` 回 `local_only`，系统配置里没写进去。修之前是红的。
2. `cargo test -p miyu-endpoint --test all extension_config`：扩展改自己声明的项照旧改得了（施工 T-9 补的那几条）。
3. 手写变异：去掉 `ui.package` 那一条判断，审计那条红；把它写成 `!= Some(package)`，自己的项改不了的那几条红。
4. 门禁全过。

### 风险

- 核心替包登记、`ui.package` 写着这个包的项（现在只有包清单里声明的）同样认：本来就是这个包的。
