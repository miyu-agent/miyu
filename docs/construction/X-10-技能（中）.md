## 施工单 X-10 中：沙盒里的命令读得到技能文件夹

状态：合了（2ef7054e，三台 CI run 1902；2026-10-12 主会话）。图纸 `docs/blueprint/skills.md`「技能」第 3 条、`sandbox.md`。

### 目的

技能文件夹在数据根里，X-10 上只放开了文件工具；沙盒里的命令（`cat`、技能里带的脚本）照旧读不到，因为沙盒藏着整个数据根。这一步让沙盒里也读得到开着的技能文件夹，写照旧不行。

### 做了什么

1. **规格多一格 `reveal`**（`miyu-sandbox` 的 `spec.rs`）：藏起来的里面单独放开只读的。没有的不写，规格的字节和以前一样（样本 `spec.json` 不变）。
2. **Linux**（Landlock）：`reveal` 的每一条再放一条读的规则。Landlock 的规则互相叠加，藏起来的那一片本来没放，这里补上一块；写照旧不放。
3. **macOS**（Seatbelt）：`reveal` 的每一条照只准读的那一种写（`READ_<n>`），照深浅排，比藏起来的深、排在它后面，压过它；写的那几样照旧被藏起来的那一条拦着。路径同只准读的换成真实的位置、去重。
4. **Windows**：沙盒还没收紧（5-9 停着），规格照收、不用动。
5. **会话层**：执行器的沙盒（`Sandbox::with_shelves`）和权限策略拿同一份技能文件夹（造会话、载入时照这一刻找到的）。本机的会话两级（工作区、只读）都写进 `reveal`；外部身份的会话（群会话这些）加进只准读的名单（名单里的、比数据根深，读得到）。

### 定了的（主会话，技术题照推荐）

- **新开一格，不复用 `read`**：`read` 一写就是「只准读名单里的」，整盘读不到了；放开技能文件夹不能顺手把别处关掉。
- **外部身份的会话不用新格**：它本来就照名单读，技能文件夹进名单就够了。

### 验收

- 规格：`reveal` 没有的不写、有的照原样读回来。
- Linux 真跑：藏起来的数据根里放开的文件夹读得到、列得出，写不进、新建不了，旁边的令牌照旧读不到。
- macOS：配置里它排在藏起来的后面、照旧整盘能读；路径换成真实的位置、去重；CI 上真跑同 Linux。
- 会话层：本机的会话规格带上技能文件夹（真实的位置），数据根照旧藏着；群会话的只准读名单里有它；Linux 上真经助手跑 `shell`：`head` 读得出 `SKILL.md`，追加写不进，旁边的数据根读不到。
- 变异 9 个全报红（Landlock 不放 `reveal` 那一个就是不修时的样子：沙盒里读不到技能）；`cargo xtask check` 八项；三台 CI（macOS 上沙盒的真跑测试 18 → 19 条全过）。
