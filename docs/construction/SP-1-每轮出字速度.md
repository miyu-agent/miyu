## 施工单 SP-1：每一轮的出字速度

状态：已合（2026-10-26）。主会话派的（2026-10-26），网页要的：项目主人定了每秒多少 token 挪到每轮回答末尾那一行。图纸 `docs/blueprint/view.md`「条目」的 `end`、「会话状态」的 `speed`，协议参考 `docs/reference/view.md`（中英两份）。

### 为什么

会话状态里的 `speed` 只有最近一次主请求，跟着状态走、会变：要写在每一轮末尾，就得在那一轮的收尾条目上记下这一轮自己的，翻页、重新订阅也看得到。

### 做了什么

1. 视图流一轮收尾那一条（`kind: end`，带 `took_ms`、`usage` 的）多一格 `speed: {output, ms}`，只加不改：
   - `output` 是这一轮每次主请求的输出 token 加起来；
   - `ms` 是每次「首字到结束」的毫秒加起来，没报首字的那一次照整次。
2. 口径同会话状态的 `speed`：单次请求的速度提成 `Speed::of`（`miyu-view` 的 `status.rs`），会话状态和一轮收尾都调它，两边不会各算各的。
   - 用量、用时都记下了的那一次才算；
   - 旁路请求（回顾、起标题这类）、摘要请求不算，整理会话的主请求（`purpose: memory`）照主请求算，同 `usage`；
   - 调工具、等人的时间不在请求里，自然不算。
3. 没有数据的不写：一次都没记下用时的（以前的日志、请求没调成的）没有这一格。只有一部分记了的，照记下的那几次算，没记的不掺进来。
4. 视图投影照日志算：以前的日志重新投影，记了用时的照样算得出来，不用新事件、不动内核。

### 验收

- 测试（`crates/miyu-view/tests/speed.rs`），日志照脚本模型跑出来，喂给投影之前改写每次请求记下的数：
  - 两次主请求加起来，会话状态照旧是最近一次；
  - 中间工具跑一分钟，一轮的用时变长，速度不变；
  - 夹一次起标题的旁路请求，收尾和会话状态都不算它；
  - 没报首字的照整次；
  - 旧日志没记用时的不写这一格，用量照旧加；只有一次记了的照那一次算。
- 手写变异 11 处全抓住：不减首字、没首字时减成零、没记用时当零、加法丢输出、加法丢前面的毫秒、只留最后一次、不累加、收尾不写、写出空值、会话状态不记、会话状态算上旁路。
- 门禁、三台 CI。

### 留下的

- 两个头：网页照 `speed` 在每轮回答末尾那一行写每秒多少（`output ÷ ms × 1000`），终端要不要跟着写由它那边定。
