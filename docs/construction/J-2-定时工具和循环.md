## J-2：她的定时工具和 `/loop`

状态：主会话做（miyu-call 写了工具、包、标签的字和测试，2026-10-26 关会话前交接；主会话接上唤醒表、写 `/loop`、收尾）。设计 45（定时和循环）第三节第 3、4 条，项目主人 2026-10-26 定：照 Claude Code，固定、动态两种循环都有；人和她都能建，她建不用问；做成预设里能开关的两个包 `schedule`、`loop`。

### 一、做了什么

1. **四件工具**（`miyu-schedule` crate，说明照 Claude Code 原文改短、登记簿量过）：
   - `schedule` 包：`cron_create {cron, prompt, recurring}`（183）、`cron_delete {id}`（60）、`cron_list`（40）。访问类别读，她建不问人；一个会话里她最多挂 20 个（`miyu_tool::PER_SESSION`），满了叫她先删。
   - `loop` 包：`schedule_wakeup {delay_seconds, prompt, reason, stop}`（152）：动态循环定下一次（60～3600 秒，超了照边界），每次把同一句原话传回来，`stop` 停掉。没开循环的说没有在跑的循环。
2. **端口**：`miyu_tool::SchedulePort`，会话层照属主交给工具；端点的实现 `schedules/port.rs` 直接调唤醒表（施工 J-1 上的 `Core::schedules()`）。「这个会话上的」是她在这里建的（`by: model`）和跑在这里的（`target` 是这个会话，例如人敲的 `/loop`）；动态循环是跑在这里、`loop` 是 `dynamic` 的那一行。造会话、载入、子代理的会话都交端口，整理记忆的不交。
3. **`/loop`**（`commands/looping.rs`）：只在工具面上有 `schedule_wakeup` 的会话里认（循环包装了、预设开着），别的照「没有这条命令」答、菜单里不列。
   - `/loop <间隔> <话>`（也认 `every <间隔>` 写在前后）：一行固定循环，每隔那么久一次，第一次就是现在；
   - `/loop <话>`：一行动态循环，马上跑一次，交过以后停着等她用 `schedule_wakeup` 定下一次，不调就停；
   - `/loop off`：删掉这个会话的循环。一个会话同时只有一个循环，再敲一次换掉原来的（主会话定，技术题）。人敲的记成属主建的。回执三种语言。
4. **标签**：到点交进会话的话由组装照 `by: schedule` 包一层（施工 J-1 上的写法），字在 `software/schedule/common/message-{open,close}.txt`（`<scheduled-task id>`）和 `software/loop/common/`（`<loop-wakeup id>`，收尾多一句 `Call schedule_wakeup to continue the loop.`）；带不带、怎么写做过 A/B（数据在主人机器的 `~/.cache/miyu-remake/j2/ab`）。
5. **包和预设**：`resources/packages/{schedule,loop}/package.toml`，在基础系统组里（施工 BS-1 上中），各一个同名功能；常规开发开着，极简开发照 `unlisted = "off"` 关着。核心照包登记。
6. **字**：登记簿（设计 26 第十节）23 行，设计 10 第九节的预算一条；给人看的字三语，一个的时候说单数（`cron/listed/one`）。

### 二、不做什么

- 命令行 `miyu schedule`、系统通知是 J-3；场所会话（群里）的循环是 J-4。
- `schedule.add` 建每次新开的时不查工作目录（J-1 下记着，归 J-3）。

### 三、怎么验
