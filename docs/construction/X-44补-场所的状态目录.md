## 施工单 X-44 补：场所会话的状态目录照场所分

状态：做完了（2026-10-22）。主会话 2026-10-22 排、定了做法（项目主人经 shorin-ac 点头：按场所分，不按会话分），插在 Z-1 前面。修的是已经在 main 上的行为。

### 目的

X-44 的 `MIYU_SCRIPT_STATE_DIR` 照会话属主分（`state/scripts/<账号>/<来处>/<工具名>/`）。群、陌生人私聊的场所会话都归包的系统账号，几个群、几个陌生人共用同一格：A 群里跑的脚本读得到 B 群里存的东西（登录态、上一次的结果），设计 11 修过的「A 群翻得到 B 群」又回来了。按会话分也不行：同一个群会不断开新会话，旧的状态接不上。

### 蓝图改哪几节

`skills.md`「脚本」第 3 条的状态目录那一段：

1. **场所会话的照场所分**：`state/scripts/<会话属主>/@<场所>/<来处>/<工具名>/`；本机的会话（`local`）照旧 `state/scripts/<账号>/<来处>/<工具名>/`。场所照这一次调用的事实（`Call` 的 `caller.venue`，施工 X-43）。会话外面的调用（没有属主）照旧不给。
2. **场所编号落到目录名**：前面一个 `@`（包编号、`~home` 都不以 `@` 开头，分得清这一层是场所），后面照字节写：小写字母、数字、`-` 原样，别的（大写字母、`.`、`_`、冒号、中文……）写成 `_` 加两位小写十六进制。可逆、不会撞；大小写不分的盘上（Windows、macOS）也撞不上；不会碰到 Windows 的保留名（`CON` 这些）、末尾的点和空格。`qq:group:123` 是 `@qq_3agroup_3a123`。写出来超过 200 个字的（场所编号最长 128 字节，全要转写才会这么长）这一次不给、记一行 `WARN script state not prepared`。
3. **清**：卸包照旧删每个账号下这个来处的，场所那一层下面的也删（`state/scripts/*/@*/<编号>/`）；`miyu check` 的 `script_state_left` 照这一层往下多看一层。
4. 已经存在旧位置的（X-44 合了以后场所会话里跑过的）不挪：那几格本来就是几个群混在一起的，挪到哪个群都不对；`miyu check` 照「有状态但没有这个脚本」报不出它，说明里写一句可以手删。

别的几处（中英）：作者文档 `scripts-skills` 的状态目录那一条加「群、私聊里每个场所一格」。

### 代码放哪

- `miyu-store` 的 `scripts.rs`：`venue_dir`（场所编号转目录名、转回来）；`state_dir` 多一个场所；`states`、`forget_states` 认 `@` 那一层。
- `miyu-basesystem` 的 `shell/script.rs`：照 `call.caller` 的场所给。

### 不做什么

- 不挪旧位置的状态（上面第 4 条）。
- 不改本机会话的路径。

### 验收

1. 先写会红的测试：
   - `miyu-store`：转写可逆、大小写不同的转出来不一样、保留名和点转写过；路径照场所多一层；`states`、`forget_states` 认场所那一层。
   - 脚本工具：两个群的调用拿到两格，同一个群再调（新会话）还是那一格、写的还在；本机的会话照旧账号那一层。
   - 沙盒里：A 群的脚本读不到 B 群的状态。
2. 手写变异 8 个左右；`cargo xtask check` 全过；本机跑 Windows 的 clippy；碰文件系统，推 `step/` 过三台 CI。

### 风险

- 场所编号很长的给不了状态目录：现有的桥的场所编号都在三十个字以内。

### 做下来的

- `miyu-store` 的 `scripts.rs`：`venue_dir`、`venue_of`（`@` 加照字节转写，小写字母、数字、`-` 原样，别的 `_xx`；读回只认唯一那一种写法：大写的十六进制、转写了本来能原样写的字节都不认）；`state_dir` 多一个场所，本机的、没说场所的照旧，写不成目录名的交回没有；`states`、`forget_states` 照账号那一层加它下面认得出的场所那几层找来处（`places`），`miyu check` 的 `script_state_left` 跟着多看这一层。
- `miyu-basesystem` 的 `shell/script.rs`：照 `call.caller` 的场所给；场所太长的不给，记一行 `WARN script state not prepared`（只有工具名，场所编号不进日志）。
- 测试：`miyu-store` 三条（转写和读回，含大小写、保留名、点和空格、中文、`_` 本身、太长；路径；列出来、卸包时清），桩代码下红 3 条，实现后 10 条全绿；脚本工具一条（两个群两格、同一个群再调接得上、本机照旧，`script_state.rs`）；沙盒里经真助手跑一条（A 群的脚本读不到 B 群的那一格、同一个群新开会话写的还在）。`tests/script.rs` 和 main 上 5-14 改下加的测试合起来超了 500 行，状态目录那几条（X-44 的两条和这一条）挪进新的 `tests/script_state.rs`。
- 手写变异 11 个，全抓住：大写字母原样留下、不限长度、十六进制写成大写、读回不查唯一写法、读回认大写十六进制、本机的也分场所、不分场所、列的时候不进场所那一层、来处里混进场所那一层、卸包不清场所那一层、脚本工具不交场所。
- 文档：蓝图 `skills.md`「脚本」第 3 条、作者文档 `scripts-skills`（中英）。
- `cargo xtask check` 全过（含 LG-1 上的「日志」一项）；本机 `cargo clippy --target x86_64-pc-windows-gnu` 过；碰文件系统，推 `step/` 过三台 CI（见交接的消息）。
