## 施工单 X-37：脚本、技能、MCP 的三处小毛病

状态：主会话审过（2026-10-21），X-32 补合了以后开工（同时最多两张）。三处互不相干：一张施工单，每处单独一个提交（AGENTS.md「施工的规矩」第 2 条：无关的改动单独成提交）。碰文件系统、子进程：先推 `step/` 分支过三平台 CI。

### 一、链接（2026-10-21 项目主人定）

现在三处不一样：家目录的 `scripts/` 认链接（连指向目录的也收了，读的时候才报错），`skills/` 只认真目录、斜杠命令模板只认真文件（`read_dir` 的文件类型不跟链接）。别的 harness 都认：Codex 官方文档写明「supports symlinked skill folders and follows the symlink target」，Claude Code、opencode 社区里普遍用链接接技能（skillshare、skman 这类工具就靠它）。

- 三处都认链接，照链接指到的东西认：指到文件的算文件，指到目录的算目录，断了的跳过、`miyu check` 照「跳过」报原因。
- **放行出沙盒的不认链接**：`sandbox.tools.<名字>` 放行了的脚本，它的文件是链接的不算放行，照旧在沙盒里跑，`miyu check` 报 `sandbox_tool_linked`。为什么：链接可以指到工作区，AI 改得了它，等于改了一件在沙盒外跑的工具（X-36「同一个来处里内容改了照旧算放行：改它的只有管理员」碰上链接就不成立）。普通脚本在沙盒里跑，被改了也越不出沙盒；技能是她读的提示词，不越权。
- 怎么认：`Tool` 多一个默认是假的 `linked()`，权限策略、执行器判放行时照它；不看「脚本」这个概念，同 X-36 不向上依赖。脚本照「判那一刻」的文件再看一眼（主会话审时提）：载入以后人把文件换成了链接，下一次重新登记以前也不放行。
- 沙盒里读得到，但收窄（主会话审时提：不然一个链接就能把数据根里的东西拉进沙盒可读，例如 `system/` 下的本机令牌、密钥文件）：
  - 只放开链接最终指到的那一样：文件就是那个文件，目录形态的（技能文件夹）就是那个目录，不放开它的上级。
  - 真实位置落在数据根里的，只认这个账号的 `home/<账号>/` 下面（`scripts`、`skills`、`packages` 这几处）；落在 `system/`、`state/`、别的账号下的不放开，这一件照「跳过」报（`script_link_outside`、`skill_link_outside`、`slash_link_outside`），`miyu check` 说清指到了哪一片。
  - 断了的、绕回自己的照跳过。

### 二、参数太长，脚本起不来

参数照原样放进环境变量 `MIYU_ARGS_JSON`，同时写进标准输入。环境变量有上限：Linux 上一个不能超过 128 KiB（`MAX_ARG_STRLEN`），Windows 上一个不能超过 32767 个字符；超了的连起都起不来（Linux 是 `E2BIG`），她只看到「跑不起来」。

- 超过 32 KiB 的不放进环境变量，只在标准输入里（本来就有完整的一份）；脚本没有这个变量的照标准输入读。按字节算 32 KiB，同时在 Linux 的 128 KiB、Windows 的 32767 个字（UTF-16 计）以内（主会话审时补）。
- 作者文档「怎么跑」写清：长的参数只在标准输入里，稳妥的写法是读标准输入。
- 出厂的两个技能（写脚本的那个）里的示例照读标准输入（现在 `dice.py` 已经是）。

蓝图改：`skills.md`「脚本」第 3 条；作者文档 `scripts-skills`（中英）。

### 三、MCP 工具没登记，人看不到

服务列出来的工具，名字照写法清理、截到 64 个字以后撞了别的，或者参数格式不对的，不登记，只在运行日志里记一行 `WARN mcp tool skipped`。`mcp.list`、软件包列表、`miyu check` 都看不到，人只会发现工具少了。

- 看管那一格多记一份「没登记的」：工具的原名、为什么（`name_taken`、`parameters`）。只记这一次列出来的，照目录缓存先登记的那一回不算；每次列完、服务重起以后照新的换（主会话审时补）。
- `mcp.list` 的一项、软件包列表上服务的那一格多 `skipped: [{"tool", "why"}]`，没有的不写。
- `miyu check` 每个服务有没登记的报一条警告 `mcp_tool_skipped`，说哪几件、为什么。
- 给人看的字照 `package-problems/…` 加，中英日。

- 链接：不另设「只认指到数据根里的」这一档（项目主人选了照别家的做法）；不跟链接改 `MIYU_SCRIPT_IMAGES_DIR` 收图的规矩（那里照旧不跟，X-35）。
- 参数：不另开参数文件。
- MCP：不改名字的清理、截断规则。

### 风险

- 链接指到很大的目录、绕回自己：照现在找技能、脚本只看一层，不往下走，绕不起来。
- Windows 上建链接要开发者模式：测试照现有的做法，Windows 上建不了的跳过那一条（注明）。

### 做下来的

三处各一个提交：之三（MCP）、之二（参数）、之一（链接）。

**一、链接**

- 列一层目录收成一份（`miyu-store` 的 `links.rs`），技能、脚本、斜杠模板三处都用它，装之前看包带了什么（`carried`）也用，那里不碰数据根、哪里都认（装包本来就照链接指的拷）。
- 记哪个位置：技能照真实位置记，写给她的也是真实路径（沙盒只放开那一个文件夹，链接本身在藏着的数据根里，照链接的路径读不到），另记链接本身；脚本记链接本身（放行时照它看），起的时候照真实位置起、放开；模板照它指到的读进来。
- 围栏比施工单多认一处 `commands`（斜杠模板自己放的地方）。几处的位置照数据根的真实位置接上家目录的相对路径，不一处处换成真实位置：家目录的 `skills/` 本身是指到 `system/` 的链接时，换了就把 `system/` 当成认的地方了。不是链接、所在目录是链接的项同样照真实位置查。
- 和施工单原文不一样、多做的：指到目录的脚本不再收（原来收了、读的时候才报错）；`skill.remove` 删链接成的技能只挪链接本身（原来找技能不跟链接，删也删不到；现在列得出来，就得删得了，又不能删到指到的文件夹）；Windows 上真实位置带 `\\?\`，写给她的技能路径去掉它。
- 端点、会话的测试只在 Unix 上建链接（Windows 上要开发者模式）；找法的测试在 `miyu-store` 里三个平台都跑，CI 上建不了链接算错（同 `miyu-fs` 的做法）。
- 没做的：判放行时再看一眼的是脚本文件本身，不往上看它所在的目录（`scripts/` 本身是链接的照算放行）：施工单定的是「它的文件是链接的」，目录是管理员自己摆的。

**二、参数**：照施工单。

**三、MCP**

- 列的时候就认不出的也算：没写名字的（`name`，`tool` 是空的）、参数格式不是对象的（`parameters`），`miyu-mcp` 的 `Listed::skipped` 从一句话改成分得出是哪一种的 `Unread`。`name_taken` 也含撞了别的包、自带的工具。照原名排，每次列完说的一样。
- 照缓存先登记的那一回不记：`spec::register` 交回没登记的，只有列完的那一处记进看管那一格。停下了的留着上一次列的（它的工具也留在目录里）。

**变异**：手写 21 个（链接 12、参数 2、MCP 7），第一遍抓住 20 个。没抓住的「链接的脚本不照真实位置起」：Linux 上的两种收紧手段照链接本身也读得到被放开的文件，真沙盒那一条照样跑通；要靠它的是 macOS（Seatbelt 照真实路径认）。补了一条：链接成的脚本 `$0` 是真实路径，再跑这一个红了。
