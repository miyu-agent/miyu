## 施工单 V-52：脚本规格不进缓存

状态：已完成（2026-11-05）。V-50 施工单「顺带看到的，没改」那一条：脚本工具每次调用的交图目录（`MIYU_SCRIPT_IMAGES_DIR`）是随机名，又放进沙盒规格的 `write`，V-47 的规则集缓存对脚本从来认不上。core1 2026-11-05 定两点：**每次都不一样的规格不进缓存，照 V-47 以前让助手从头建；判据写死在规格那一层（脚本这条路给规格带一个「不缓存」的标），不许靠猜路径长相**。交图目录共用一个上级（让规格每次一样）那种做法不做。

### 为什么

V-47 的缓存按规格的 `hidden`、`write`、`reveal` 认键。脚本工具的 `write` 里有这一次调用新建的交图目录（`images-<16 位随机十六进制>`），键次次不一样，于是每次调脚本：

1. 核心照旧认一遍指纹（列目录、逐条 `fstatat`、读挂载表），认不上，当场新建一份规则集（V-47 量的「没认上次次重建」，比 V-47 以前还多约 0.7 ms），再放进缓存——这一份以后再也用不上；
2. 缓存最多 8 份、满了丢最久没用的：接连调 8 次以上脚本，`shell` 那份被挤掉，下一条 `shell` 要重建；
3. 没用的那几份占着核心的内存（每份内核里约 130 KB、指纹约 105 KB），要闲 5 分钟才丢；规则集拿着它放行的每个文件，家目录里删掉的文件也要等它们丢了才真正释放。

### 做什么

1. **标放在 `Sandboxed` 上**（`crates/miyu-sandbox/src/wrap.rs`，新的公开字段 `uncached: bool`）：`Sandboxed` 是「一次调用带的沙盒」（助手在哪、规格、要设的环境变量），只在核心里用、不序列化；`Spec` 是写成 JSON 交给助手的那一份（`deny_unknown_fields`）。「缓存不缓存」只是核心怎么造命令，不是能读能写什么，助手用不着，所以不放进 `Spec`、不进助手的参数：`--spec` 的字节和以前一字不差，助手一行不改。放在 `Spec` 上还得在约 130 处规格字面量里补一格；`Sandboxed` 的字面量 16 处，都补 `uncached: false`（别的调用方照旧缓存）。
2. **库里两处都照标判**：`command` 标了的不碰缓存，和 `argv` 拼的一样（参数里没有 `--ruleset`，助手从头建，同 V-47 以前）；`checks_files` 标了的为假（不认指纹，当场造，不多一次线程往返）。别的平台本来就不缓存，标不起作用。
3. **脚本工具造规格时显式设**（`crates/miyu-basesystem/src/shell/script.rs` 的 `Script::command`）：交图目录放进 `write` 的同时 `sandboxed.uncached = images.is_some()`。这一次交图目录建不成的（没有那一格），规格每次一样，照旧缓存。`shell` 那条路一行没动。
4. 不加常驻、不落盘：少的是缓存里那几份用不上的。

### 行为差别

没有。脚本起的命令拿到的 `--spec` 和改前一字不差（strace 核对：改前改后起助手的命令行去掉 `--ruleset <号码>`、交图目录的随机名以后逐条一样），助手照第 1 条从头建，能读能写的范围、报的错和 V-47 以前、和不能缓存的规格一样（V-47 核对过两条路生效的规则逐项一样）；`shell` 照旧缓存、照旧在阻塞线程认指纹。

### 验收

1. **新测试**（都只在 Linux 上编；Landlock 用不了的机器不跑）：
   - `crates/miyu-sandbox/src/linux/cache/tests.rs` 的 `uncached_specs_stay_out_of_the_core_cache_and_leave_the_others_in_it`：经核心那一个缓存（`crate::command`），先让 `shell` 那样的规格进缓存，拿着这一条命令（里面拿着规则集）；再接连 10 份各不一样、标了的（每份多一个交图目录）：每份 `checks_files` 为假，拼出来的程序、参数和 `argv` 的一字不差，缓存里没有它的键、条数不变；之后 `shell` 那份交出来的号码和拿着的一样（被挤掉重建的话，旧的还开着，新号码一定不一样）。同一份不标的照旧进缓存（差别只在标）。路上别处有人改、`shell` 那份因此重建的那一次再来，5 次里有一次对上就算。调试版 0.01 s。
   - `crates/miyu-basesystem/tests/script_uncached.rs`（并进 `tests/all.rs`）：真的脚本工具，假助手 `/bin/echo` 印出收到的参数；`shell` 先调一次，测试再直接拼一条同规格的拿着；接连调 10 次脚本，每次参数里都没有 `--ruleset`；之后 `shell` 再调一次，交给助手的号码还是那一个。藏起来的摆在 cargo 的输出目录下（`/tmp` 里同一个测试程序别的测试一直在建删）。调试版约 0.05 s。
   - `crates/miyu-sandbox/tests/linux_cache.rs`：`both` 每个脚本多跑一遍标了不缓存经 `command` 起的，退出码、输出和从头建的逐字一样（读藏起来的、旁边的、放开只读的、跨目录改名和硬链接、连套接字……全部情形）；拼法那一条加上标了的和从头建的一样。
2. **改的测试** `crates/miyu-basesystem/tests/sandbox_thread.rs`（V-50）：脚本那一处原来判「认指纹挪到阻塞线程」，现在脚本根本不认指纹（`checks_files` 为假），照旧在原来的线程当场包。改成：假助手换成 `/bin/echo`，参数里没有 `--ruleset`；另一个任务最晚晚的照旧不到认一遍的一半（没东西占着线程）。前台、后台两处不变。
3. **手写变异 3 个，都逮住**（`scratchpad/v52/mutants.txt`）：
   - `command` 不看标：缓存测试（拼法和从头建的不一样）、`linux_cache.rs`（拼法）、`script_uncached.rs`、`sandbox_thread.rs`（脚本带了 `--ruleset`）都红；
   - `checks_files` 不看标：缓存测试红（「标了的不认指纹」）；别的几份照过（只是多一次线程往返，造出来的命令一样）；
   - 脚本工具不标：`script_uncached.rs`、`sandbox_thread.rs` 红（库里的测试照过，标本身照旧管用）。
4. 原有的照过：`miyu-sandbox`、`miyu-basesystem`、`miyu-session` 全部（`knowledge_formats` 那一条要先编 `miyu-extract`，本机没编，和这一步无关；门禁上编）。`cargo clippy`（Linux、`x86_64-pc-windows-gnu`）无警告；门禁、三平台 CI。

### 实测

2026-11-05，本机，release，改前 origin/main `cdb98e9d5`（另开的工作树编）、改后这一步，同一套编译设置。照 V-50 的 `e2e/sbx.sh` 改（`scratchpad/v52/e2e/`）：`unshare -rn` 里只有 Landlock 那一路；数据根里放一个空脚本 `root/scripts/noop.sh`（工具 `noop`）；假模型一轮照顺序轮着调，3 轮；核心套 `perf stat`（task-clock 连子进程），另读核心 `/proc/<pid>/stat` 自己的和收掉的子进程的 CPU；改前改后交替先后各 3 遍，绑 12～15 号核。机器忙（负载 5.6～11，第 3 遍时轻一些，两边一起变快）。这份规格藏 14 条（数据根在临时目录下，家目录里藏了几处），一级级要放行的比 V-40 那份多，认指纹、建规则集都更贵。

**只调脚本**（一轮 40 次）：

| 每次调脚本 | 改前 | 改后 |
|---|---|---|
| 模型看到的一步 p50 | 19.49 / 19.38 / 19.45 ms | 13.57 / 13.43 / 11.07 ms |
| 工具自己报的 `duration_ms` p50 | 17 / 17 / 17 ms | 11 / 11 / 9 ms |
| 核心自己的 CPU | 14.33 / 14.50 / 14.67 ms | 3.50 / 3.42 / 2.67 ms |
| 收掉的子进程的 CPU | 4.92 / 4.75 / 4.83 ms | 10.75 / 10.58 / 8.75 ms |
| task-clock（核心连子进程） | 20.00 / 19.98 / 20.13 ms | 14.90 / 14.67 / 12.22 ms |
| 上下文切换 | 52.6 / 52.6 / 52.1 次 | 47.7 / 47.9 / 46.4 次 |

改前每次在核心里认一遍指纹（认不上）、建一份规则集、放进缓存；改后核心只拼参数，助手从头建（CPU 挪到子进程，合起来每次少约 5 ms：认指纹那一遍和核心建规则集比助手从头建多的那些都省了）。

**`shell`、脚本交替**（各 40 次一轮）：

| | 改前 | 改后 |
|---|---|---|
| `shell` 一步 p50 | 13.31 / 13.16 / 8.19 ms | 12.59 / 12.35 / 8.00 ms |
| 脚本一步 p50 | 19.53 / 19.51 / 12.60 ms | 14.24 / 14.47 / 9.61 ms |
| task-clock 每步 | 16.73 / 16.32 / 11.51 ms | 14.18 / 14.11 / 9.70 ms |
| `shell` 缓存命中（strace 一遍） | 114 / 120 | 119 / 120（没中的是头一次） |

一比一交替时，缓存满了丢的总是最久没用的脚本那几份，`shell` 那份本来就挤不掉；改前没中的 6 次是指纹变了（一级级走要列 `/tmp`、家目录，别的程序在里面建删东西，strace 拖慢以后碰上的更多），不是被挤掉。`shell` 每条略快 0.2～0.8 ms（核心少占 CPU）。

**一条 `shell` 接 9 次脚本**（一轮 80 次：`shell` 8 次、脚本 72 次）：

| | 改前 | 改后 |
|---|---|---|
| `shell` 一步 p50 | 19.99 / 18.97 / 17.94 ms | 12.35 / 11.95 / 12.15 ms |
| 脚本一步 p50 | 19.78 / 19.30 / 17.86 ms | 13.60 / 13.62 / 13.98 ms |
| task-clock 每步 | 19.95 / 19.47 / 17.24 ms | 13.19 / 14.50 / 14.65 ms |
| `shell` 缓存命中（strace 一遍） | 0 / 24 | 20 / 24（头一次 1 次，指纹变了 3 次） |

改前 9 次脚本把 `shell` 那份挤出 8 份的缓存，每条 `shell` 都重建；改后照旧命中，每条快 6～7 ms。

**行为核对**：strace（`-f`，抓 `execve`、`landlock_create_ruleset`）三种调法各一遍，改前改后起助手的命令行去掉 `--ruleset <号码>`、交图目录的随机名、`shell` 每条命令的套接字以后逐条一样（交替 120 + 120 条、接连 24 + 216 条、只调脚本 120 条）；改后脚本全都不带 `--ruleset`、核心不为它建规则集。

**内存**：不常驻、不落盘。改前缓存里最多 8 份用不上的脚本规则集（V-47 量的每份内核里约 130 KB、指纹约 105 KB，这份规格更大），要闲 5 分钟才丢；改后没有。
