## 施工单 F-9 下：核心起个人设置里的 MCP 服务

状态：已合（2026-10-13，feb583c7，CI run 1989，F-9 上、下一起跑的）。图纸 `docs/blueprint/mcp.md`「个人设置里的一张表」第 4 到 7 条，接着 F-9 上（读、查）。

### 做了什么

1. 起来时：拉起扩展、起 `bundle` 的服务以前，先照手里的个人设置定下有哪几个服务（谁盖住谁）；包里的服务被个人设置里同名的盖住的不起；最后起个人设置里的，挂在 `~home` 下（同家目录里放的脚本），工具 `mcp__<名字>__…`。
2. 跟着配置换（`Core::follow_home_mcp`，核心起来后开始）：配置服务每换上一份新的（手改个人设置被看到），照个人设置的字换，只动变了的：
   - 删掉的、改了的先停下、工具出目录；
   - 删掉的那个名字，包里被它盖住的照包的开关起回来（`bundle` 照开关，扩展照它在跑）；
   - 新写的那个名字，包里同名的停下、工具出目录；
   - 最后起新写的、改了的。只差在第几行的不算改（加一行注释不重起）。
   开始时先照手里的一份对一遍：起来和开始跟着之间的手改也认得。
3. 预设：一个服务一个功能 `mcp-<名字>`，`preset.get` 列出来，工具是目录里挂在 `~home` 下、归它的；包里被盖住的那个功能不列。
4. 软件包列表：包里的服务被盖住的不算进包的合并状态（不然一直卡在「起着」），都被盖住了的包照关着算。
5. 命令第一项：`~/` 开头的换成家目录下的绝对路径，只有名字的先找家目录下的 `bin/`，再照 `PATH`。
6. 写错的：核心读的时候各记一行 `WARN mcp settings problem`（行、原因、哪一格），不收。

### 验收

- 端到端（真起测试用的服务）：写了就起、调到的是它（环境变量是个人设置写的）、包里同名的不起、那个包照关着算、预设里只有一个 `mcp-probe`、工具列在它下面；手改个人设置：新写的起、包里同名的停（调到的换成个人的），改了环境变量的停下照新写的再起，删掉的停、包里的照开关起回来。
- 单元：只差在第几行的算一样，先后、命令、环境变量、时限、给哪种会话变了算变；`~/` 照家目录换，只换第一项，不知道家目录的照原样。
- 扩展带的服务：扩展在跑的，被个人设置盖住时照样不起，放开以后起回来；扩展没开的，放开以后照样不起。
- 变异 14 处全抓住：包里的不让、起来时不读、起来时不起、删掉的不停、不起回包里的、新写的不停包里的、一律当没变、改了的当没改（环境变量）、功能表不加、预设不列个人的、预设照列被盖住的、合起来算被盖住的、扩展的照开关、扩展的一律不起。原来功能表里滤掉被盖住的那一行改了测不出来（那个服务不起，目录里没有挂在包下的工具），删了。
- 真服务、真模型走一遍（2026-10-13，沙盒数据根，官方的 `everything` 参考服务经 `npx` 起）：个人设置里写 `[mcp.everything]`，核心起来 0.7 秒上下列出 13 件工具；她调 `mcp__everything__echo`、`get-sum` 不问人（只读注解）、答对；核心开着把表名改成 `demo`，半秒内旧的停下、工具出目录、新的起来，下一轮她调 `mcp__demo__echo` 答对。
