## 施工单 X-32 补：真服务走出来的两处

状态：合了（2026-10-21，efe34929；先过了三台 CI）。扩展线的会话做，主会话审过。

### 真服务走了一遍（X-32 验收第 3 条）

2026-10-21，GitHub 官方的远程 MCP 服务 `https://api.githubcopilot.com/mcp/`。项目主人给的细粒度只读令牌存成密钥 `github`，个人设置写 `bearer = { secret = "github" }`；值不进仓库、不进施工单。

- 用的是 X-32 下的构建、临时数据根，模型 `deepseek/deepseek-flash`。
- 服务连上，登记 46 件工具，照老时代握手（`2025-11-25`），写进目录缓存。
- 她照「要先加载」加载了 `mcp__github__search_repositories`、`mcp__github__list_branches`，调了一次，查 `miyu-agent/miyu-sdk` 的描述和默认分支，答对了。

走的时候撞见三处：

1. **新时代经网址连不上**：探 `server/discover` 时 GitHub 回 `HTTP 400: Mcp-Protocol-Version header is required for requests carrying "io.modelcontextprotocol/protocolVersion"`。新时代的请求在 `_meta` 里写了版本，经 HTTP 发还要在 `MCP-Protocol-Version` 头里写同一个；X-32 上的转接只在握手以后带这个头。客户端退回老时代照样能用，但新时代经网址一次都连不成，每次连服务的日志里多一行 400。**这一步修。**
2. **先配服务、后存令牌，服务不会再连**：没有令牌时连了 5 次都是 401、停下；之后 `miyu login github` 存进去，引用它的服务照旧停着，没有任何提示，要人点重启或者重开核心。项目主人 2026-10-21 定：**存了、删了、改了密钥，引用它的服务重新连**。**这一步修。**
3. **冷启动的第一问看不到刚起的服务的工具**：`miyu ask` 一起核心就开会话，这一轮的工具面在服务登记以前就定下了。目录缓存写下以后，再起核心照缓存先登记，只有头一回连上以前会这样。照设计如此，**不修**。

### 蓝图改哪几节

- `mcp.md`「网址的服务怎么说话」第 1 条：每个请求的 `MCP-Protocol-Version` 先照它自己 `_meta` 里写的版本（新时代），没有的照握手认出来的（老时代）；老时代的 `initialize` 那一次照旧不带。头名照规范写 `MCP-Protocol-Version`，读回应的头不分大小写。
- `mcp.md`「个人设置里的一张表」第 4 条（跟着换）：密钥变了，`env`、`bearer`、`headers` 里引用了这个名字的服务（个人设置里的、包里带的）停下再起，连续失败从零数。
  - 怎么醒：不轮询。`secret.set`、`secret.delete`（`miyu login` 走的就是它）落了盘、手改密钥文件被看到，配置服务都换上新的一份（`hub.publish`），`follow_home_mcp` 本来就是被这一下叫醒的；醒来时拿这一刻每个密钥值的摘要和上一刻的比，变了的名字就是要重起的。摘要只在内存里，不落盘、不进日志。
  - 只重起开着的：人关掉的（功能开关关着的、包没开的）不因为密钥变了被拉起来。在跑的、引用的值变了的也停下再起，不只救 401 停下的那种。
  - 多用户：密钥是账号自己的，只重起这个账号的服务表（个人设置、这个账号装的包带的）。现在只有管理员一个账号、密钥文件只有一份（`system/secrets.toml`），照它做；多用户那一段照账号分开（`24-威胁模型.md`），测试里注明。
  - 重起时记一行 `INFO mcp restarted service=… why="secret changed" secret=<名字>`，不写值。
- `mcp.md`「守着它的」跟着改；施工单 X-32 下补记真服务那一遍。

### 不做什么

- 扩展进程的环境不跟着密钥换：扩展拿配置走 `extension.config` 推送，自己的事。
- 第 3 条不修。

### 验收

1. 先写会红的测试：
   - 假网址服务多一种新时代的：带 `_meta` 版本的请求，头里没有同一个版本的回 400。转接连它认成新时代，服务的日志里没有 400。另断言老时代的假服务照旧连得上：老时代的请求不因为缺这个头被拒，`initialize` 那一次不带它。
   - 真核心：个人设置写 `bearer = { secret = "t" }`、密钥没存的服务停下；`secret.set` 存进去以后它自己连上，`failures` 从零数，假服务收到的带 `Bearer`；`secret.delete` 以后停下重连（又是 401）。在跑的、`secret.set` 换了值的停下再起，假服务收到新的令牌。没引用这个名字的服务不动（同一个进程号、没重连）；功能开关关着的服务不因此被拉起来。运行日志里有 `secret changed` 那一行，没有值。
2. 手写变异 15 个左右。
3. `cargo xtask check` 全过。
4. 临时数据根上换上这一步的构建，GitHub 那个服务认成新时代（如果它认新时代）。测完删掉这个临时数据根（只删自己建的这一个，密钥文件跟着它一起没），项目主人自己的数据根一个字节不碰。

### 风险

- 密钥变了要重起的服务找错了：照服务表里写的引用名字找，测试里放一个不引用它的服务看着不动。

### 做下来的

- 第①处：转接照每条请求 `params._meta["io.modelcontextprotocol/protocolVersion"]` 带 `MCP-Protocol-Version`，没有的照握手认出来的。假网址服务多一种新时代的（`HttpServer::modern`），照 GitHub：`_meta` 的版本和头对不上回 `400`（正文 `-32020`）。
- 第②处：挂在 `follow_home_mcp` 那个循环上（`mcp/secrets.rs`），醒来时比每个密钥值的摘要（`DefaultHasher`，只在内存里）。个人设置里的服务一个个重起（`restart_home_mcp`），包里带的照 `restart_services` 连同这个包的别的服务。看管那一格是关着的不动。假网址服务多一个认令牌的开关（`HttpServer::demand`）。
- 运行日志那一行放在 `secrets_log.rs` 那个单独的测试程序里验：它本来就守着「整份运行日志里搜不到 key」，这条路走一遍也搜不到。
- 新测试先在原来的转接、循环上跑，红了两个（新时代的版本头、密钥变了重连）；换上新的全绿。
- 手写变异 12 个全抓住。
