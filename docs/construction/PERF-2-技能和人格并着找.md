## 施工单 PERF-2：开着记忆的投影查尖，技能和刷新人格并着找

状态：核心的分会话做。perf 闸门「一次请求的投影：开着记忆的大会话」2026-10-27 又两趟过 5 ms：f6fa76067 那一趟 8.2 ms（同一趟关着记忆的也到 5.1 ms），6a7f3649a 那一趟 5.6 ms；两趟复跑都绿。主会话派（2026-10-27）：闸门不放宽，在 CI 那种条件下拆开着记忆那条的分段，看是什么随大会话涨，找到根因再给方案。方案 A 主会话同意；量尺照旧取尾 30 轮的 p95（项目主人定）。

### 查下来的

1. **CI 的机器不一样**：四种 CPU（EPYC 7763、9V74、9V45，Xeon 6973P），都是 4 个逻辑核。今天红的两趟都在 7763 上，复跑绿的那一趟有一次换到了 9V74。拉最近 100 份 `perf-raw` 照 CPU 分开比，PERF-1 在 CI 上只让 p50 降了约 0.3 ms（7763），尾巴没压住，PERF-1 施工单的 CI 表照这个改正了。
2. **本机复现不出**：绑 4 个核、同步全跳过（预加载小库），开着、关着记忆的 p95 一样（2.8 ms）。
3. **在 CI 上原地量**：实验分支（只跑 perf、带插桩、尾 300 轮，不合并，量完删了）跑了 5 趟，4 趟 7763、1 趟 Xeon。7763 上开着记忆的这一段（回合开始到假模型读完请求，p50，ms）：

   | 段 | 等阻塞线程 | 干活 |
   |---|---|---|
   | 冻结配置、换模型、私密目录 | | 0.43 |
   | 刷新人格 | 0.07 | 0.46 |
   | 找技能（排在人格后面） | 0.11 | 0.50 |
   | 项目指令（和挂接点并着） | | 0.12 |
   | 记忆的摘要、卡、联想（p99） | | 0.12、0.07、0.02 |
   | 内核组装 | | 0.34 |
   | 编码 | | 0.51 |
   | 发出到假模型读完 | | 0.21 |

4. **结论**：记忆本身不是它，两组的请求体一样大（中位差 1.6 KB），开着记忆的 p50 只多约 0.28 ms、零散分在各段。随大会话涨的是内核组装、编码（锯齿，PERF-1 说过），两组一样。偶发的尖是虚机上的调度停顿，落在不同的段：Xeon 那一趟一轮 15.7 ms，14.5 ms 在等技能、项目指令的阻塞线程；7763 那一趟一轮 2.9 ms 在发出。底子里刷新人格、找技能每轮都重新读盘，两样约 1 ms，原来串着：技能等人格看完（换了人格工具面会变），底子高，一抖就过线。

### 做了什么（方案 A）

- `actor/model.rs` 回合开头：技能照这一刻的快照先找起来，和刷新人格放进同一个 `join`；刷新人格交回新快照的哈希的（人格、预设真换了，很少见）照新快照再找一次，不换的直接用并着找的。行为不变。
- 测试：`miyu-endpoint` 的 `preset_skills.rs` 加一条：会话中途从关着 `notes` 的预设换成全开的，下一轮尾巴上有它、文件夹放开只读。
- 图纸 `session/actor.md` 跑挂接点那一行、`perf.md` 闸门第 6 条；PERF-1 施工单的 CI 表改正。
- 方案 B（人格、技能每轮读盘的结果照文件的修改时间缓存，约再省 1 ms，判「没变」有风险）先不做，A 不够再另开一步。
