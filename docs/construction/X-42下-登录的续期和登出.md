## 施工单 X-42 下：登录的续期、权限不够、登出、手贴回调

状态：主会话审过（2026-10-22：续期写回不重起服务同意，照「刚写进去的那一份的摘要」判，人自己 `secret.set`、`mcp.login` 存的照旧重起；补一条测试：续期期间在跑的调用不断）。照 `X-42-远程MCP的OAuth.md` 的拆法，`mcp.md`「待定（施工 X-42）」第 5、6、8 题和第 2 题后半（主会话 2026-10-21 审过推荐）；排在 G-14 之后（主会话 2026-10-22 排）。分支从 X-42 上的头（`abebbee45`）开，X-42 上合了以后变基到 main。

### 目的

X-42 上做完以后能登录，但令牌一到期（多半一小时）服务就停在 `needs_login`，人得再点一次浏览器；服务说权限不够的、人想退出登录的、浏览器不在核心那台机器上的，都没有路。这一步补上这四样。

### 蓝图改哪几节

`mcp.md`「怎么走」第八条接着写，「待定」里只留第 9 题（头的按钮）和 CIMD：

1. **续期**（第 5 题）：
   - 网址的转接每个请求现场问一次令牌（`miyu-mcp` 的 `http.rs` 多一个可选的「凭据」，没有的照旧用固定的请求头，写了 `bearer`、`headers` 的服务都是这一种）。登录来的服务由看管的一头给凭据：离 `expires_at` 不到 60 秒的先续再给；回 `401` 的续一次、照新令牌把这一次请求重发一遍，再 `401` 的照 X-42 上停在 `needs_login`。
   - 续：`grant_type=refresh_token`，带同一个 `resource`、原来的 `scope`、客户端（有密钥的照 `client_secret_post`）。成了的存回 `mcp-oauth-<服务名>`（新给了 `refresh_token` 的换上，没给的留旧的），照密钥现有的写法整份重写、照读到的版本防并发改（撞了重读再写，人手改的不丢，主会话补的第 1 条）。
   - **续期写回不重起服务**（主会话 2026-10-22 同意）：X-32 补的「密钥变了、引用它的服务重起」会把正在用的服务停掉再起，一小时一次、在跑的调用跟着断。看管的一头记下自己刚写进去的那一份的摘要，跟着个人设置的那一圈比密钥时，这个名字的摘要和记下的一样的不算变了；人自己改的、`mcp.login` 存的照旧重起。
   - 没有 `refresh_token`、续不成的（`invalid_grant` 这类）：停在 `needs_login`，运行日志一行 `WARN mcp oauth refresh failed service=… error=<OAuth 的 error 码>`，不写令牌、不写授权服务器的原话。
   - 连之前已经过期的（核心停了一阵）：起之前先续，续不成的照上一条。
2. **权限范围不够**（第 6 题）：服务回 `403`、`WWW-Authenticate` 的 `error="insufficient_scope"` 的，这一次调用照服务回错交给她，服务停在 `needs_login`（规范的 step-up，不自动弹浏览器：核心不能替人点同意），挑战记在看管那一格；下次 `mcp.login` 要的 `scope` 是存着的 `scope` 加上挑战里的（去重、照先后），授权页照它写。
3. **登出**（第 8 题）：`mcp.logout {service}`（只给人）删掉 `mcp-oauth-<服务名>` 那一份（客户端、端口一起，主会话 2026-10-21 说的「端口和 `client_id` 同进退，登出时一起清」），在等回调的那一次登录一起取消；服务照密钥变了那一路重起、回 `401`、停在 `needs_login`。没登录过的回 `not_logged_in`。命令行 `miyu mcp logout <服务>`。
4. **手贴回调**（第 2 题后半）：`mcp.login_finish {service, url}`（只给人），`url` 是浏览器跳到的那一整段（`http://127.0.0.1:<端口>/callback?code=…&state=…`）。交给在等的那一次登录，和本机收到的回调走同一处判（`oauth::callback`、`state`、`iss`，主会话补的第 3 条）：对得上的换令牌、存、回 `{}`；对不上的回 `oauth_failed`，那一次登录照旧等着（本机的回调还可能来）；没有在等的回 `not_waiting`。命令行 `miyu mcp login` 印出网址以后加一句「浏览器在别的机器上的，授权完把地址栏整段贴到这里回车」：标准输入是终端的同时读一行，读到的调 `mcp.login_finish`。

别的几处（中英）：协议参考 `packages` 的 `mcp.logout`、`mcp.login_finish`，原因码 `not_logged_in`、`not_waiting`（`errors`）；作者文档 `mcp` 的登录那一段补「令牌到期自己续」「退出登录」；`cli` 蓝图 `mcp.md` 加 `logout`、手贴。

### 代码放哪

- `miyu-mcp`：`oauth/flow.rs` 多 `refresh`；`http.rs` 的凭据（一个 trait：现场给令牌、续一次）；`403` 的挑战同 `401` 记下来。
- `miyu-endpoint` 的 `mcp/login/`：凭据的实现（读存着的、续、写回、记摘要），`logout`、`login_finish`；`mcp/secrets.rs` 比摘要时跳过自己写的；`supervise.rs` 认 `403` 的 step-up。
- `miyu-cli` 的 `mcp.rs`：`logout`，`login` 读贴回来的一行。

### 不做什么

- 头的「登录」按钮（第 9 题，主会话和两个头另排）、CIMD（等项目主人定网址）。
- 续期不另开定时器：用到才续（请求前、`401` 时），没人调的服务令牌过期了也不要紧，下一次用时续。
- 不吊销令牌（RFC 7009）：登出只删本机的一份；规范没要求，授权服务器多半不给吊销的端点。

### 验收

1. 假授权服务器多「给 `refresh_token`、令牌几秒就过期」「续的时候拒（`invalid_grant`）」「`403 insufficient_scope`」三种配法。先写会红的测试：
   - 令牌快过期时请求前续了一次，假服务器收到 `refresh_token` 的那一次、带 `resource`；服务没重起（假服务器只收到一次 `initialize`），调用照常。
   - 服务回 `401` 的续一次、重发，那一次调用成了；续不成的停在 `needs_login`，日志里有 `refresh failed` 那一行、没有令牌。
   - 续期写回密钥以后服务不重起；人用 `secret.set` 改了这一份的照旧重起。
   - 续期期间在跑的调用不断（主会话审时加）：一次调用正跑着、另一个请求撞上过期触发续期，那一次调用照常拿到结果。
   - `403 insufficient_scope`：停在 `needs_login`，下一次 `mcp.login` 的授权页 `scope` 是旧的加新的。
   - `mcp.logout`：密钥里那一份没了，服务停在 `needs_login`；没登录过的 `not_logged_in`。
   - `mcp.login_finish`：贴对的换到令牌、服务连上；`state` 不对的 `oauth_failed`、那一次登录还在等；没在等的 `not_waiting`；`iss` 不对的同本机回调一样拒。
   - 运行日志、事件、协议回应里搜不到新的令牌、`refresh_token`（`oauth_log` 那个单独的测试程序加上续期这一路）。
2. 手写变异 15 个左右。
3. `cargo xtask check` 全过；本机跑 Windows 的 clippy；碰网络、终端，推 `step/` 过三台 CI。
4. 真服务走一遍（X-42 的第 4 条）：挑一个只认 OAuth 的公开服务，项目主人在自己的终端里点同意，等过一次续期；临时数据根，走完只删它。

### 风险

- 两个请求同时撞上过期：凭据里续期一次只跑一个，别的等它的结果，不各续各的（有的授权服务器续一次就作废旧的 `refresh_token`，并着续会把自己登出）。
- 授权服务器续期时换了 `refresh_token`、写回失败了（磁盘满）：这一次照新令牌用，记一行 `WARN`；下次起核心照旧的续，多半被拒、停在 `needs_login`，人再登录一次。
