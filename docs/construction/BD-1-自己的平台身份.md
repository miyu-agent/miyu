## BD-1：自己的平台身份

状态：主会话做，一步，2026-10-28 做完。项目主人 10-27 定的形状；接入通讯平台设计 07「核心-己」。

### 一、为什么

成员接上自己的 im 以后，他在 QQ 上的号说话，核心认不出是他：主人对应表是主人的，只在主人那一份里认（IM-2）。项目主人 10-27 定：每个账号一张自己的平台身份对应表，本人改，只能指自己，只在他自己那份 im 里认，平台照连接定，号填错是用户自己的事。

### 二、定下的（技术题，主会话定）

1. **写法**：个人设置 `external.me = ["qq:12345", "tg:7890123456"]`，一格列表。f4 提的：设置页一行一个号，增删就是改这一格；元素是字，最长 128，不查写法。只有个人设置那一层。值就是「这几个号是我」，没有写别的账号的地方，「只能指自己」由形状保证。
2. **在哪认**：
   - 他名下的场所会话：他那一份 im 问 `venue.binding` 他写的号回他本人；会话里这个号说的话（`as`）记成他本人，带 `via`。
   - 别人名下的会话不认。
   - 主人的系统表照旧，只在主人那一份认；主人自己也能写 `external.me`，在他那一份里同样认。
3. **平台桥名下的不认**：平台桥（系统账号）的配置是机主那一份，认了会把机主写的号记成平台桥本人。
4. **前缀归头**：头照连接的平台拼 `qq:`、`tg:`，核心照前缀认，同主人对应表。

### 三、做了什么

1. `settings.rs`：`EXTERNAL_ME`，进起来时就认的那几项；`miyu-core` 的配置清单跟着登记；给人看的字三种语言。
2. `venues/me.rs`：`mine`（平台桥的一个都没有）、`claims`。
3. `venues.rs`：`venue.binding` 每人一份的先认他自己写的；`speaker`（`as`）属主自己写的号记成他本人，别的照主人表的规矩。
4. 配置样本、蓝图 `config.md` 表和样本块、`venues.md`「自己的平台身份」，协议参考 `venues.md` 中英两份。
