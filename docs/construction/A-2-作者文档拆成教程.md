## 施工单 A-2：作者文档拆成教程

状态：2026-10-18 做了。项目主人定的（「mcp 接入、scripts 接入、扩展编写、onebot 扩展编写，这些都需要文档」）；「给接入QQ 写插件」那一篇归接入QQ 仓库，由它的会话写。

### 起因

`docs/authors/README.md` 一页 272 行，什么都挤在里面（MCP 是一条、脚本和技能是一条），写法像条款、夹着施工号和「定了的」，没有从零走一遍的完整例子。

### 做了什么

`docs/authors/` 拆成五篇，中英各一份，不带施工号：

| 篇 | 讲什么 |
|---|---|
| `README` | 入口：包能带什么、看哪一篇、包长什么样、装试查、三个平台、给模型看的字 |
| `manifest` | 清单每一张表、每一格；能力表 |
| `mcp` | 接 MCP 服务：写进个人设置、做成包、每一格、她看到的样子、跑起来的样子 |
| `scripts-skills` | 脚本、技能、命令模板，各带能直接用的例子 |
| `extensions` | 写扩展：最小的完整例子、被拉起、握手和配置、`provide`、`tool.call`、退出和崩了、更多本事（斜杠命令、加上下文、系统提示词、按意思搜、界面块、包之间调用、带内容、记事件） |

方法的完整参数都链到 `docs/reference/`（A-1）。

### 测试

只改文档。照代码、蓝图核过各格（能力表照代码里的十五个，脚本开头的键照 `miyu-policy` 的读法）。
