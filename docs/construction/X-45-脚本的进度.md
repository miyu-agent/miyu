## 施工单 X-45：脚本的进度

状态：主会话审过（2026-10-22：标准输出、标准错误都认、不另开管道，理由成立；文档照写「写到标准错误」）。排在 X-44 之后（主会话 2026-10-22 排）。

### 目的

shorin-ac 会话移植旧 Miyu 的脚本时撞见的：下载、转码这类脚本跑得久，想一边跑一边说到哪了（「下好 3/10」），现在印出来的每一行都进结果，进度一多结果就被冲掉，交给她的字还白花钱。这一步给脚本一个只给人看的进度行。

### 蓝图改哪几节

`skills.md`「脚本」第 3 条（跑）：

1. **进度行**：一整行以 `miyu-progress: ` 开头的（前缀照字面，分大小写，后面带一个空格），不进交给她的结果。照旧边跑边推给头（`Progress::push`，头上现在就一边跑一边显示脚本的输出），所以人看得到、她看不到。别的行照旧进结果，已有的脚本不受影响。
2. **标准输出、标准错误都认**（和主会话原来说的「只认标准错误」不一样，主会话 2026-10-22 审过同意）：现在两样接在同一根管道上，照写出来的先后读（`process.rs`）。只认标准错误就要另开一根管道，两边的先后对不准了，结果里的字和现在不一样；真的结果里一行以 `miyu-progress: ` 开头的想不出来。作者文档写「写到标准错误」：标准错误不缓冲，写了马上到；Python 的标准输出接管道时整块缓冲，进度会攒到最后才出来。
3. **只管脚本工具**：她跑的命令（`shell`）照旧，什么行都进结果。
4. 截长（结果太长时留头尾）照去掉进度行以后的算；结果里报的行数、字数也是。到时被杀、退出码不是 0 的一样去掉。

别的几处（中英）：作者文档 `scripts-skills`「怎么跑」加一条进度行，带一个 Python 的例子（`print("miyu-progress: 3/10", file=sys.stderr, flush=True)`）。

### 代码放哪

- `miyu-basesystem` 的 `shell/output.rs`：一个按行滤的小东西，接在 `Capture` 前面，半行留着等下一段，读完时剩下的半行照一整行判。
- `shell/process.rs` 的 `start` 多一个开关，只有脚本工具打开；`shell` 照旧。

### 不做什么

- 不给进度另开协议、另造事件：头上本来就显示边跑边出来的字。
- 不认别的写法（JSON 的进度、百分比）：要的照这一行自己写。
- 不改结果里别的字。
