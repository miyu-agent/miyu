## 施工单 V-31：走目录读文件少做白工

状态：已完成。2026-10-31 项目主人批 V-29 建议的头两条「照推荐的做」：不为数字好看省，只砍真浪费，行为一个字节都不变。

### 目的

`grep`、`glob` 往下走目录，`read` 读大文件，把 V-29 剖析出来的白工砍掉：每进一个目录拿这棵树碰不到的私密目录、数据根比一遍；每个文件一段段比、一段段拼相对路径；不在这一页的行也解成字、拷进新的 `Vec`；一个字节一个字节地找换行。交回的字、挡哪些目录、行号、哈希都和原来一样。

### 查下来的（V-29 的剖析，`docs/construction/V-29-工具一步多快.md`「慢在哪」第 2、3 条）

- `walk.rs` 的 `Fence::keeps_out` 每进一个目录拿数据根和这台机器上每个私密目录（Linux 出厂 45 个）逐个 `within`，约占 `grep` 的 23%。`Fence::from` 只去掉了包住起点的那几个。走到的目录都是起点再往下接几段（`ignore` 照上一层 `join` 名字，`read_dir` 交回的就是这样），`within` 又是一段段比的：`within(dir, fenced)` 成立只有两种，`fenced` 包住起点（含等于），或者落在起点下面。两样都不是的，每个目录都答「不挡」，比了也白比。
- `walk::relative` 每个文件 `strip_prefix` 再一段段转字、拼起来，约 14%。都是 UTF-8、名字里没有分隔符时，照起点的长度截下来就是同一条。
- `read/lines.rs` 每一行都 `from_utf8_lossy` 成一个新的字串、拷进新的 `Vec`，页外的也一样（约四成）；找换行用 `iter().position`（约 25%）。整份的 SHA-256（约 28%）是 `write` 前核对用的，省不掉，不动。
- `memchr` 工作区里本来就有（`miyu-store` 直接用，`ignore`、`grep-searcher` 也带着），Unlicense OR MIT，`Cargo.lock` 里只多 `miyu-basesystem` 依赖它一行。

### 做了什么

1. `Fence::from`：私密目录只留落在起点下面、又不包住起点的；数据根只留包住起点或者落在起点下面的。判断用的还是挡的时候那个 `miyu_fs::within`（一段段比；macOS、Windows 不分大小写），口径和原来一样；`keeps_out`、`held` 不动。
2. `walk::relative`：先照字面截（`quick`）：起点写得成 UTF-8、最后一段是名字或者根、Windows 上开头是前缀（`quick_root`，一次走一遍算一次），路径的字面以起点开头，后面是「平台原生的分隔符 名字……」、每个名字不空不是 `.`、Windows 上不带 `/`，才截；Windows 上 `\` 换成 `/`。别的（不是 UTF-8、多一个分隔符、夹着 `.`、Windows 的 `C:`、`\\?\C:` 后面没有 `\` 这种再接一段会多出一个根的，没有前缀的 `\\server` 这种再接一段整个成了 UNC 前缀的）照原来的一段段比（`slow`，就是原来的代码）。
3. `read/lines.rs`：`page` 先看下一行要不要，再读：不要的 `Source::skip` 只往后数到换行，不拷不解；要的照原来留开头 8004 个字节、解字、去 `\r`。找换行用 `memchr`。叫停照旧每读一块看一眼，跳过时也看；哈希照旧读到结尾。`offset` 不过 `i64::MAX`、`limit` 不过 2000，先算「下一行要不要」不会溢出。

### 蓝图改哪几节

- `tools/glob.md`「走目录」第 4 条：加一款「走之前先剪掉这棵树里碰不到的」（改前：只写数据根、私密目录不进，搜的目录在私密目录里的那一个不挡；改后：再写剪掉碰不到的、用同一个比法、挡哪些和不剪一样）。第 7 条：加「相对的路径照搜的目录的长度直接截，截不了的照旧一段段比，交回的一字不差」。「守着它的」加 `walk/tests/fence.rs`、`walk/tests/relative.rs` 两行。`tools/grep.md` 走目录照 `glob.md`，不另改。
- `tools/read.md`「怎么走」当 UTF-8 读的那一款：加「不在这一页的行只往后数到换行，不拷、不解字；找换行一次比一整段（`memchr`）；跳过的那一段里叫停了也不往下读」。「守着它的」`lines/tests.rs` 一行加上新的对照。

### 不做什么

- 不动哈希：整份的 SHA-256 照旧读一遍算一遍。
- 不并行走目录、不改 `ignore` 找 `.gitignore`（V-29 第 2 条里另外两件，要不要并行另定）。
- 不改 `Fence::of` 每次调用换真实位置的那几十次 `canonicalize`：一次调用一回，不是每个目录。
- 不改 UTF-16 边读边解的那一层：页外的行在它上面照样只数不解，解码本身没动。
- 量尺不进提交：用的是临时的测试（下面「实测」），V-29 的量尺场还没合。

### 验收

1. `walk/tests/fence.rs`：起点在私密目录、数据根上面、里面、旁边、等于它，有没有工作目录、工作目录在数据根里、换了大小写的写法，每种组合下一批目录（含私密目录、数据根本身、里面一层），剪了的和剪之前的（测试里留着原来的 `from`）`keeps_out` 逐个一样，比了一千多个；剪下来只剩碰得到的；真的建目录走一遍：上面的不进、旁边的不碰、就是它和在它里面的照走、起点在数据根里只有工作目录那一片照进。
2. `walk/tests/relative.rs`：直接截和一段段比交回的一字不差：一层层接出来的（中文、emoji、`...`）、起点以分隔符结尾、多一个分隔符、夹着 `.`、结尾的分隔符、字面是前缀不是一段段的前缀、空的和相对的起点、`/`、名字里的 `\`（Unix）、不是 UTF-8 的名字（Unix）、Windows 的盘符、`\\?\`、UNC、`/` 当分隔符、只有前缀没有根、没有前缀的（`\\server`、`\x`、相对的）、盘符大小写不一样。第一次推上去 Windows 的 CI 就是这一条拦下的：起点 `\\server` 再接 `\share\a`，一段段比认成另一个 UNC 前缀、不在起点下面，直接截却截出 `share/a`；改成 Windows 上起点开头要有前缀才直接截。
3. `read/lines/tests.rs`：原来的 `page` 原样留在测试里（`page_before`），每一行都解的老读法和新读法对一批输入（长过 8004 字节的行、`\r\n`、坏字节、跨过 8 KiB 的行、结尾没换行带 `\r`、BOM、六十来行就满 64 KiB 的、两万个空行、UTF-16 两种字节序）、十六种从哪起读几行（页前、页后、最后一行、过了结尾、停在 64 KiB）逐字一样，哈希都是整份的；只跳过时叫停了照样交回 `Interrupted`。原有的 `read`、`grep`、`glob`、`walk_private`、`read_memory` 照旧全过。
4. 手写变异四个都红：剪的时候忘了包住起点的、截的时候不查怪名字、跳过的边界差一行、跳过时不看叫停。
5. Windows 版 clippy、`cargo xtask check` 全过；三平台 CI 过（动了路径的判断）。

### 实测

机器：Ryzen 9 7940H，btrfs（zstd 压缩）的 NVMe；量的进程绑在 12-15，别的会话一直在编译，负载 16～23。release（`lto = "fat"`、`opt-level = "s"`，同发行版），改前是 main 91481c366，改后是这一步。

量法：`miyu-basesystem` 里临时加一个 `#[ignore]` 的测试（不进提交），经工具的接口直接调：场地照 V-29，工作区里一份 main 的 `crates/`（3155 个文件、26 MB），起成新的 git 仓库，起点是它；假家目录里 45 个出厂私密目录都建上（真机上有的多，篱笆才有东西比），数据根在。8 MB 文件 10 万行、一行 80 个字节，读第 99801 行起 200 行。先调一次热页缓存，再连调 100 次，每次交回的字和第一次一样（改前改后的输出指纹也一样）。`perf stat -e instructions:u,task-clock` 数调 0 次和 100 次两个进程，差除以 100 是一次调用的；p50 是那 100 次的墙上时间。每种调用三遍，每一遍改前改后挨着量。只量工具本身，不含 V-29 那一步里核心的几跳。

| 调用 | 用户态指令（百万条/次）改前 → 改后 | CPU（毫秒/次）改前 → 改后 | p50（毫秒）改前 → 改后 |
|---|---|---|---|
| `grep` 只列文件 | 131.0 → 69.8（少 47%） | 36.0～37.6 → 29.8～30.8 | 37.4～39.0 → 30.9～32.1 |
| `grep` 带行 | 133.9 → 73.0（少 45%） | 29.1～30.1 → 24.3～30.2 | 28.9～30.2 → 24.8～31.4 |
| `glob` | 107.0 → 46.2（少 57%） | 17.7～22.4 → 13.2～14.8 | 18.0～23.8 → 13.8～15.5 |
| `read` 8 MB 末尾 200 行 | 178.1 → 39.9（少 78%） | 14.9～17.2 → 7.3～8.1 | 14.9～18.0 → 7.3～8.3 |

- 指令数三遍之间差不到 0.2%，看它最稳；CPU 和墙上时间跟着负载走，同一行里看挨着量的两列。前一轮（负载 19～23）同样的趋势：`grep` CPU 30.5～36.4 → 24.2～31.4，`read` 13.0～15.5 → 6.7～7.8。
- `grep`、`glob` 的指令少了一半，CPU 只少两三成：剩下的大头是系统调用（开目录、读 `.gitignore`、取修改时间、开文件），指令数只数用户态。`read` 剩下的 4000 万条大半是整份的 SHA-256。
- V-29 里 jcode 读同一份文件末尾 14.5～16 ms（连核心的几跳），Miyu 这一项本身现在 7～8 ms。

### 风险

- 剪篱笆靠「走到的目录都是起点再往下接几段」：`ignore` 改成交回别的写法（例如换真实位置、跟着链接走）就不成立。现在 `follow_links(false)`，`relative` 也靠同一个前提（不是前缀的交 `None`）；`fence.rs` 的真走一遍守着。
- 直接截只认平台原生的分隔符，Windows 上起点以 `/` 结尾、夹 `/` 的走慢的那条路：交回的一样，只是不快。
- 三平台的差别（大小写、Windows 的前缀）只在 CI 上跑到；本机只跑了 Linux 和 Windows 版 clippy。
