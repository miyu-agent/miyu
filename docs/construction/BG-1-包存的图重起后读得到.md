## 施工单 BG-1：包存的图重起后读得到

状态：已完成（2026-11-11）。

### 为什么

项目主人 2026-11-11 报：本机核心重起以后，表情包后台页所有的图都是灰块。UI 会话在测试台复现，查到两处，这是第一处（第二处是 YC-5补）。

表情包把图只存在核心的 blob 里，自己只记哈希。扩展不带 `session` 调 `blob.get` 只读得到它拿得到的（施工 W-6 三补），这份许可只记在核心的内存里，当时的规矩是「核心重起以后再存一次，同样的内容是同一个哈希」。可是包手里只有哈希、没有内容，没法再存一次：重起以后它读自己存的图一律 `unknown_blob`。

### 蓝图改哪几节

- `protocol.md`「`blob.get`」第 1 条：它自己存的另落盘、核心起来时读回；经 `package.call` 拿回来的、别人交来的照旧只在内存。测试表加一行。
- `store.md`「在哪」的表加 `blob/grants.rs`；目录布局 `var/lib/` 加 `blob-grants/<编号>`；保留的编号加 `blob-grants`。设计 55 第二节的图、第三节第 3 条的保留表跟着加。
- `packages.md`「卸就是清干净」：这一份一起删。
- 参考 `blob.md`、`blob.en.md` 的「谁能调」。

### 做了什么

1. 只落盘「它自己存的」（`blob.put`、分块上传 `blob.close` 的回应那两处，`Grants::grant`）。经 `package.call` 转来的（`pass`）、人的连接交来的（`hand`）不落盘：那是一次调用里临时给的，落了盘就成了永久的。
2. 放在 `var/lib/blob-grants/<包的编号>`（`DataRoot::blob_grants`），一个包一份，纯文本，一行一个哈希，只追加。依据：设计 55 第三节，丢了就没了、不是人写的状态放 `var/lib/`，核心自己的和包的 `<编号>/` 并排，名字进保留表（同 `leftover` 在施工 PK-5补 加进去的办法）。不放进包自己的状态目录 `var/lib/<编号>/`：那里包自己写得进，等于自己给自己开门。
3. 写法照 `journal.jsonl`（`miyu_store::blob::grants`）：目录经 `durable::create_dir` 建（数据根不在了的不建回来，0700），每追加一行都重新打开、追加、`sync_data`，新建的文件另同步目录，一个核心里一把锁一行一行来。上一次写到一半、最后没有换行的，下一次追加先补一个换行。
4. 同一个哈希只写一行：内存里另记一份「落了盘的」，只有头一次存才写。先经别的包拿到过、后来自己又存的，照样写。写不进的记一行 `WARN`、从「落了盘的」里拿掉（下一次存再试），存照算成。
5. 核心起来时读回（`Grants::load`）：坏行跳过，一份记一行 `WARN`（哪个包、几行）；一份读不了的不拦别的几份。
6. 卸包（`Grants::forget`）：内存里的扔掉、文件删掉；删不掉的记一行 `WARN`，卸照算成。

### 不做什么

- 不清 blob 本身，不查记下的哈希在存处里还在不在：不在的读的时候照旧 `unknown_blob`。
- 不给文件设上限、不整理重复：一行 72 字节，同一个哈希只写一次。
- 以前存的（这一步之前只在内存里的）在这一步里补不回来；施工 BG-1补 另做了一次性的补登记，见下面「补登记」。

### 补登记（施工 BG-1补，2026-11-11 项目主人同意）

状态：已完成（2026-11-11）。

BG-1 之前存的 blob，核心从来没记过是谁存的。表情包把图只存在核心里、自己的状态目录里只记哈希，升级到带 BG-1 的核心以后老图照样 `unknown_blob`。

1. **什么时候做**：核心起来、拉起扩展之前（`miyu-core` 里 `Core::backfill_blob_grants`，紧挨在 `start_extensions` 前面等它做完；不然扩展起来就读图、还没补上），只在数据根里**还没有 `var/lib/blob-grants/` 这个目录**时做：升级后第一次起来，或者全新的数据根。做完把目录换进去，哪怕一个包都没补到；目录在了就不再做。换不进去的记一行 `WARN`，下次起来整个重做。
2. **为什么只做这一次**：包以前能把哈希记进自己的状态，说明它当时拿得到；BG-1 以后许可都落盘了，不用再从状态目录认。要是每次起来都扫，包就能靠往自己目录里写别处看来的哈希给自己开门。
3. **扫哪里**：装着的每个包（`Core::system_packages` 里清单读得成的）自己的状态目录 `var/lib/<编号>/`（`DataRoot::package_state`，也就是 `MIYU_STATE_DIR`、扩展的工作目录）。只扫这一处：设计 55 第四节交给包的几个目录里，表情包这样的索引放的是状态目录；配置 `etc/<编号>/` 人也写得进，缓存、日志、暂存不是记账的地方。
4. **怎么找**（`miyu_store::blob::grants::scan`）：普通文件照字节找 `sha256:` 后面跟 64 位小写十六进制，照 `ContentHash::parse` 认；二进制的也这样找（SQLite 库里存着的）。后面紧跟着别的字符的也认，反正下一条还要查存处。
5. **限制**：不跟链接、不出这个目录（上一层 `var/lib/` 换成真实的位置，状态目录本身是链接的不扫，里面的链接跳过，文件照 `miyu_fs::open_file` 打开，路上一层链接都不跟）；一份文件大于 64 MiB 的跳过；一个包最多扫 20000 份文件；状态目录下面最多进 16 层子目录。有跳过的、没进去的、读不了的，这个包记一行 `WARN`（`blob grants backfill: package state not fully scanned`，带各有几个）。
6. **登记谁**：找到的哈希只留 blob 存处里确实有的（`Blobs::path` 上是一份文件，同 `Blobs::put` 认「已经有了」），登记给这个包：进内存、落盘。落盘是一下子换进去的（`blob::grants::seed`）：全扫完以后，先删掉上次剩下的暂存目录 `var/lib/.blob-grants.new/`（`DataRoot::blob_grants_staging`；点开头的不合包编号的写法，不用进保留表，同装包的 `.<编号>.new`），在里面一个包写一份、同步，再一次改名成 `var/lib/blob-grants/`、同步上一层（改名照装包换文件夹的办法，`fs::rename` 到一个还没有的名字，三个平台一样）。以后它自己再存同一个，不多写一行。
7. **日志**：找到了哈希的包记一行 `INFO`：`blob grants backfilled package=<编号> found=<几个> granted=<几个>`；最后记一行总的 `blob grants backfill done packages=<几个> granted=<几个>`，一个包都没有、什么都没补到也记。
8. **出错**：一个包的状态目录扫不了（是链接、是文件、列不出来）记一行 `WARN`、接着扫别的包；换不进去的（写不进、改不了名）记一行 `WARN`，这一次起来照旧读得到；整个补登记失败不拦核心起来。扫描、写盘在阻塞线程里。

不做：不认包的配置、缓存、日志目录里的哈希；不认脚本的状态目录 `root/state/scripts/`；不给人留「再补一次」的命令（要重做就停掉核心、删掉 `var/lib/blob-grants/`，那等于连 BG-1 以后落盘的一起从状态目录重认）。

- `crates/miyu-store/src/blob/grants/scan/tests.rs`（BG-1补）：文本里的、二进制里的、跨着两块的找得到；写法不对的不认；链接不跟、状态目录本身是链接的不扫；太大的跳过、文件太多、目录太深的数得出。`crates/miyu-endpoint/src/attach/grants/backfill/tests.rs`：存处没有的不登记、落盘只写一次、目录在了不再做、一个包扫不了不拦别的；留着半截的暂存目录、没有正式目录时照样完整补上、暂存目录没了。`crates/miyu-store/src/blob/grants/tests.rs`：一下子换进去、空的也建目录、目录在了的不盖。
- `crates/miyu-endpoint/tests/blob_grants_restart.rs`：扩展 `blob.put` 以后停掉核心、同一个数据根上再起一份，同一个包 `blob.get` 读得到，别的包照旧 `unknown_blob`。先红：改之前重起以后那个包读到的是 `unknown_blob`。
- `crates/miyu-endpoint/src/attach/grants/tests.rs`：自己存的落盘、新起的一份读得回；同一个哈希只写一行；`pass`、`hand` 的不落盘；先经别的包拿到、后来自己存的照样落盘；卸了文件删掉；坏行跳过。
- `crates/miyu-store/src/blob/grants/tests.rs`：追加、读回、删；坏行数得出；写到一半的最后一行；不合编号写法的名字、读不了的一份；数据根不在了的不建回来。`root/places/tests.rs` 的保留表对得上。
- 人验：装着表情包、存过图的核心（这一步以后存的），停掉再起，后台页的图照常显示。

### 风险

- 追加时崩了留下半行：读的时候当坏行跳过，下一次追加先补换行。
- 补登记写到一半核心被杀（BG-1补）：「目录在不在」就是「补没补完」。各包的那一份先写进暂存目录 `var/lib/.blob-grants.new/`、同步好，最后一次改名成 `var/lib/blob-grants/`、同步上一层；改名之前被杀的只剩暂存目录，下次起来先删掉它、整个重做。
- 补登记多认了（BG-1补）：升级前包往状态目录里写过别处看来的、存处也有的哈希的，这一次会登记给它。只有这一次，以后写进去的不认。
- 包自己伪造这一份：文件在核心自己的目录里，不在包的状态目录；扩展现在不在沙盒里跑（`extensions.md`「还没有的」），做沙盒时这个目录不交给包。
