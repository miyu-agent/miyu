## 施工单 K-2 修：知识库照意思的下限照模型

状态：已完成（2026-10-13 写、做；验收手册实测查出来，待定 11；项目主人 2026-10-13 定先修抽取、再修它，看了测评集的数定 bge 0.50）。

### 目的

装了内置语义模型以后，知识库搜什么都有结果（验收手册：`kb search 不存在的词`、`kb search 食べる --kb world` 都印出不相干的段，`kb search 鸡胸肉` 把语法笔记排在猫的照顾前面）。只照意思找到的那一路的下限是 0.40（施工 R-5 下照记忆量的起点），知识库的块长、bge 上不相干的短句也常在 0.4 到 0.5 之间。

### 蓝图改哪几节

- `knowledge.md` 第四条「搜」：下限照模型，表在 `resources/core/knowledge/search.toml`；「在哪」「守着它的」「施工步子」跟着改。
- `knowledge/eval.md`：多一节「搜的下限」，量的表和定的数。
- `log.md`：核心起来时表读不出来的那一行。

### 定了的

1. **下限照模型**：表的写法同自动想起的门槛表（`[thresholds]`，模型 → 数，`miyu_recall::associate::Thresholds`），数据在 `resources/core/knowledge/search.toml`，进门禁登记簿的豁免（同 `core/knowledge/recall.toml`）。`local:bge-small-zh-v1.5` 是 0.50（项目主人 2026-10-13 定）；表里没有的照 0.40（`miyu_recall::FLOOR`，远程的模型没量过，照旧）。
2. **只改知识库**：记忆的搜、以前的对话照旧 0.40（`fuse` 不变，知识库换用带下限的 `fuse_above`）。
3. **在哪定**：核心起来时读一次交给知识库（`Knowledge::with_floors`）；她的 `kb_search`、人经协议的 `kb.search`、命令行都走同一份。读不出来的记一行 `WARN knowledge search floors unreadable`，都照 0.40。

### 不做什么

- 记忆搜索的下限（没问到，另说）。
- 关键词那一路两字切分带出来的不相干的段（只走关键词也是平常的话四成多搜得出东西，K-6 上就量过）。
- 远程模型的下限：没有测评集上的数，照旧 0.40。

### 验收

1. 先量：测评集上照几种下限量 `kb_search` 的准头，拿数给项目主人定（`measure_the_search_floor`）。
2. 先写测试，没实现时要红：
   - 合并：带下限的那一个，只看只有向量一路找到的，`fuse` 就是照 0.40 的它。
   - 知识库：表里的模型照表、没有的照 0.40；出厂的表 bge 是 0.50。
   - 核心：照资源目录交下限，读不出来的都照 0.40。
3. 手写变异全被逮住；门禁全过；三台机器的 CI 全绿。

### 做了以后

- 先量（`measure_the_search_floor`，bge）：照 0.40 平常的话十四句里十二句搜得出东西，0.50 起和只走关键词一样是六句；有答案的各种下限都是 97% 带对了；测评集里换了说法的多半还有字对得上，另量四句一个字都对不上的，该找的那一段都在最像的前三、相似度 0.418 到 0.577，0.60 全丢、0.50 留两句。拿这张表给项目主人，定 0.50（原说 0.60）。基线写进 `knowledge/eval.md`「搜的下限」。
- 端点那一层用假服务器测不出下限（假的向量都一样，相似度都是 1）：给知识库加了 `floor`，在端点的单元测试里直接看核心交的下限（出厂的表、表里没有的、表读不出来的）。
- 资源目录读知识库两张表的两个函数并成一个（`knowledge_table`，照名字读 `core/knowledge/<名>.toml`），`resources.rs` 不过行数上限。
- 手写变异 8 个全被逮住。

### 风险

- 字一个都对不上、又没那么像的问句（0.40 到 0.50）照意思找不到了：量的四句里丢两句。宁可少给，她还能换个说法再搜。
