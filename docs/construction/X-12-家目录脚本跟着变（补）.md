## 施工单 X-12 补：家目录里的脚本跟着变

状态：已合（2026-10-13，d73723ee，CI run 38421693081）。验收手册核心待定第 4 条（C-70 自测时她在家目录里放了脚本却找了三分多钟），项目主人同一天照推荐定。图纸 `docs/blueprint/skills.md`「在哪」脚本登记那一行、`store.md` 的 `watch.rs`。

### 为什么

脚本照 X-12 中只在核心起来时、装卸包以后登记：往 `home/<账号>/scripts/` 放一个，核心在跑时她看不到。技能是每一轮开头重新找的，个人设置里的 MCP 服务也是当场生效的，就脚本不是。

### 做了什么

1. 监视件多一种用法 `watch_dir`：看一整个目录，点开头的以外哪个名字变了都算，交出去的是这个目录；不递归；200 毫秒合并一次，系统的监视起不来的退回轮询，和看配置文件的同一套。
2. 核心起来时跟着管理员家目录的 `scripts/`（`Core::watch_scripts`）：没有的先建上；有变动就照原来的规矩再找一遍、整份换进工具目录，下一轮的工具面跟着变。没动的时候不重找，工具面一字不变。
3. 再找一遍的一次一个：起来时、装卸包、目录变了可能同时来，后到的等前一个做完。建不了目录、监视起不来的记一行 `WARN`，照旧只在起来时、装卸包时找。

### 验收

- 测试：监视件看目录的认法（点开头的、子文件夹里的、只读的不算）、真目录里新建和删掉的都交出来；真核心在跑时放进一个脚本当场登记、下一轮的工具面里有它，删了下一轮就没有（`crates/miyu-endpoint/tests/scripts/follow.rs`）。
- 手写变异 3 处全抓住：点开头的也算、变了不重找、不建目录。核心起来时调不调它没有测试守着（入口的接线）。
