## 施工单 V-17（上）：投影提速

状态：合了（2026-10-24）。主会话排：CI 上「一次请求的投影：开着记忆的大会话」最近常擦线（p95 5.0–7.0 ms，预算 5 ms，项目主人 10-19 定预算不放宽），要优化到慢跑机上也有余量（目标 EPYC 7763 上 p95 ≤ 4 ms）。主会话派的编号是 V-12，已被「读日志照字节分块」占了，改用 V-17。

### 查下来的（`perf` 采大会话说到一万条事件以后的核心）

这台机器只许采用户态：要 `perf record -e task-clock:u --user-callchains`；dwarf 展不开，另编一份带帧指针的（`-C force-frame-pointers=yes`，单独的目标目录）。照「包含这个函数的样本」算：

| 占比（改前） | 在哪 | 为什么 |
|---|---|---|
| 18.9% | `miyu_models::provider::provider`（解析模型的供应商） | 发请求那条路（`route::exchange`）、会话列表算上下文（`list::context::fill`）每次都调 |
| 8.6% / 6.6% | `miyu_config::key::split` / TOML 解析 | 列名字时配置里每个键都拆一遍，每个都当一份 TOML 文档解析 |
| 5.9% + 3.0% | `matching::address` / `squeezed` | 认供应商时每次把目录里上百家现规整一遍 |
| 8.5% | `Request::fingerprint` | 每条消息写成 JSON 再算 SHA-256，只为比出和上一次请求的第一处不同 |
| 16.9% | 会话列表（`list::one` 等） | 没人订阅也每次「变了」都重算那一项 |

- 是不是哪个提交突然慢了一截（记忆会话本机二分，定核 2-7、交替各 3 遍）：P-14（bf42635c5）、Z-1下（70c2fcbb4）、M-8（671b278ff）三点「开着记忆」那项 p95 中位 4.4 / 4.1 / 4.7 ms，差都在噪声里；「开着记忆比不开多出的那截」也没有 CI 上那种稳定的 +1 ms。是一直贴着预算、CI 机器更慢更吵，不是某个提交长出来的；上面这几处是每次请求都付的底账。

### 做了什么

1. 拆配置键的快路：全是裸段的直接照点拆，别的照旧交给 TOML（结果一样，对照测试守着）。
2. 模型目录建好、从整理好的那一份读回来时，每家规整过的编号和地址算一次存着，认供应商查现成的（照编号字节排取头一家的规矩不变）。
3. 指纹照结构算 64 位哈希（`Hash` 派生；`RawJson` 照原文算），不写 JSON、不用 SHA-256：只在内存里比上一次请求，不落盘、不跨重启。
4. 会话列表没人订阅时，「变了」不算那一项、只往上加号；之后订阅的先要一份列表，排在后面算，已经是最新的。

### 前后（本机，同一个起点 379f3a2dd，两轮交替，perf stat 记整趟所有进程的 CPU）

| 项 | 改前 | 改后 |
|---|---|---|
| 整趟 CPU | 38.3 / 42.5 s | 32.7 / 30.9 s |
| 一次请求的投影：开着记忆的大会话 p95 | 5.3 / 5.1 ms | 3.6 / 3.8 ms |
| 同上 p50 | 3.2 / 3.3 ms | 2.3 / 2.3 ms |
| 一次请求的投影：大会话 p95 | 4.1 / 4.5 ms | 3.4 / 3.9 ms |
| 从头投影：重启后头一次说 p50 | 5.4 / 4.8 ms | 3.5 / 3.2 ms |

照同样的比例推，7763 上开着记忆那一项约 4.4 ms，还没到 4 ms：剩下的大头是组装请求（整段历史重渲染），留给 V-17 下。

### 不做什么

- 不放宽预算。
- 不动请求的规范字节、日志里的请求哈希（照发出去的请求体算，没变）。

### 验收

- `miyu-config`：`key/tests.rs` 的 `the_fast_split_agrees_with_toml`（裸的、带引号的、带空格的、空段的、中文的……快路和 TOML 一样）。
- `miyu-models`：认供应商的老测试全过；`matching/tests.rs` 补一条目录那一家的地址带 `/v1` 也认得出。
- `miyu-kernel`：`request/tests.rs` 的 `the_fingerprint_still_sees_what_the_bytes_carried`（工具参数格式、驱动私有数据、结果出没出错都比得出来）；第一处不同的老测试全过。
- `miyu-endpoint`：会话列表、推送的测试全过。
- 手写变异：快路改宽、目录那一边不规整、读回来不建、`RawJson` 不算哈希，都红。
- `cargo xtask check`、Windows 版 clippy；推 step 分支过三台。

### 风险

- 指纹换成 64 位哈希：相邻两次请求同一位置的两条消息撞上的机会可以不计；撞上了只是少报一次「第一处不同」。
- 会话列表没人订阅时不算：之后订阅靠先要的那一份列表补齐；订阅着的头（终端、网页）照旧每次算。
