## 施工单 Q-2：旁路请求登记（核心这一侧）

状态：核心的分会话做。设计 `43-旁路请求和档位池.md` 第三节第 2、3、4 条，第五节第 2 条；做法六条 2026-10-26 主会话同意，另交代两条：会话的模型本身在池里时不再往下退要有测试守着；去掉 `memory.organizer` 前和记忆那条线打招呼（shorin-49 回：照做，撞得不大）。

### 为什么

起标题走会话的模型（会话是旗舰的，起一个标题也走旗舰），整理记忆单独一个键 `memory.organizer`。旁路请求没有统一的去处。

### 做了什么

1. 登记表 `miyu-models` 的 `side.rs`：档位 `Tier`（照三个固定池）、一条登记 `Side`（编号、档位）。出厂两条：`core/title` 是 `lite`，`memory/organize` 是 `normal`（抽取、合并、写关键词、整理会话都算它）。给人看的名字、说明在 `core/human` 的 `model/side/<编号>`、`model/side/<编号>/summary`。
2. 那条链：池有成员的照池的分法挑一个发；池是空的用会话的模型（不算退）；池里出字以前出了会冷却的错换下一个，挑到试过的、全冷却挑不出的退到会话的模型发一次，记 `INFO side fallback`；会话的模型本身就是这个池的不再退。
3. 起标题（会话端口，`route/side.rs`）：内核不替辅助请求重发，所以端口在派出去的任务里自己换人、退（`Route` 多一格指向自己的弱引用，好把整个路由带进任务）；发送层拆出「试一次」（`send::attempt`），出了会冷却的错交回回报好换下一个，`Switch` 多 `cooled`。不动会话钉着的成员、不粘。
4. `model.called` 多 `fell_back`（退过的写 `true`，没退的不写，旧日志字节不变）：沿 `Report::Sent` → `Input::AsideSent` → 内核的 `Aside` 带过去。内核的辅助请求还没收到增量就又报发出去了的，发给谁、请求哈希、退过没有照后一次（真发给的那一个），时刻照第一次。
5. 整理记忆走一次性入口的 `OneShot::call_side`、`call_side_watching`：池里换遍了还没答成（全在冷却、限速、可重试、认证失败，还没给出一个字）退到后备再发一次。后备：抽取是被抽的那个会话这一刻的引用（`Job` 多 `fallback`，actor 照端口的 `reference()` 交），合并、写关键词没有会话的照 `models.chat`。整理会话钉 `@normal`，池是空的照 `models.chat`（会话端口原来的规矩），全在冷却照主请求报。
6. `memory.organizer` 去掉（配置项、三语标签、样本、图纸），写了的照不认识的键警告；测试的帮手改成往 `normal` 池里放成员。
7. `model.list` 多 `side`：每条 `id`、`tier`、`name`、`summary`（照连接的语言）、`resolved`（池名或 `session`）。

### 不做的

- 扩展的登记（清单 `[[side]]`、`model.call` 的 `side`、`miyu check` 提没有的编号）：Q-3。
- 池的路由补齐（`ordered`、窗口剔除、`quota`、全冷却只探一个）：Q-4。

### 验收

1. `side/tests.rs`：档位对上固定池；池是空的落到会话的模型。
2. `route_side.rs`：起标题照 `lite` 池、主请求照会话的模型；池是空的用会话的模型、不算退；池里出错退回会话的模型、记 `fell_back`；会话钉在 `lite` 池上的不再往下退、没碰 `models.chat` 那一台。
3. `once_side.rs`：整理记忆照 `normal` 池；池是空的照后备（会话的、`models.chat`）；池里出错退一次、成员取不到 key 也退；后备就是这个池的照池的规矩报。
