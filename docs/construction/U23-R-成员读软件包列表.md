## U23-R：成员读软件包列表

状态：主会话做。网页接 U23 末上、末下（每个人把包对自己关掉）时碰到：成员调不了 `package.list`（只给管理员组），软件包页拿不到装了哪些包，没法照包画开关。项目主人 2026-10-24 要的是普通用户在软件包页照包开关。放开的写法主会话定（技术题）：放开 `package.list` 只读、删掉管理员才用得上的格，不在 `config.schema` 里另造一份包列表。

### 一、做了什么

1. 门禁：成员能调的名单（`connection/gate/members.rs`）加 `package.list`。软件包的流照旧不给成员：那里还推 MCP 服务（`mcp.changed`）。
2. 成员拿到的每一项只留 `package`、`layer`、`removed`、`kind`、`name`、`version`、`summary`、`icon`、`from`、`features`、`contents`、`status`、`enabled`、`page`、`code`、`missing`（`packages.rs` 的 `FOR_MEMBERS`）：这台机器上的路径、程序和参数、MCP 服务的写法（可能带环境变量、请求头）、读坏了的原话只给管理员。照连接的 `Peer::admin` 判。
3. 他对自己关没关一个包照他的配置读，列表里不另写；关、开照旧 `config.set` 写他那一份。
4. 蓝图 `protocol.md` 的 `package.list` 写上成员看到的样子。

### 二、怎么验

1. 端点 `package_list_member.rs`：成员拿得到、出厂的 `shell` 有名字和功能、每一项都没有那几格；机主照旧有 `state`；成员订软件包的流 `not_permitted`。
2. 手写变异 3 个全抓到：不删格、成员名单不放、留下路径。
3. 本机门禁。
