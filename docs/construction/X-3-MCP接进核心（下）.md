## 施工单 X-3 下：扩展包带的 MCP 服务、目录缓存

状态：合了（2026-10-11，90d4a8fd，run 1792；变基到一个只改文档的提交上）。接 X-3 上；图纸 `mcp.md`「怎么走」第一条第 4 条、第二条第 1 条、第三条第 1、2 条。

### 这一步做什么

1. 扩展包（`process`）带的 `[[mcp]]` 跟着扩展起停：扩展拉起了（开着、程序在、能力批了），它的服务跟着起；关掉、卸掉、升级时跟着停。服务的工具和扩展经 `provide` 登记的互不冲掉（X-3 上已把目录分开管）。扩展的状态照旧只看扩展进程；每个服务的状态随 X-4。
2. 目录缓存 `state/mcp/<服务名>.json`：每次列完写下起它的命令、环境变量的写法（引用照引用写，不取值）、认出来的时代、每件工具的原文；一样的不写。核心起来、开服务时，命令和环境变量的写法都没变的照缓存先登记（服务还没好时调到说暂时不可用），连的时候照记着的时代直接说（旧时代的直接握手、不再探）。缓存读不成、写不成的记一行 `WARN`，等服务自己列。
3. `ttlMs`：新时代的服务说目录多久内不用再问，过了以后下一次有人调它的工具时叫看管的任务再列一次（这一次照旧调），变了换掉、写缓存。
4. 卸包清干净：卸掉的包带的服务，缓存和工作目录（`state/mcp/<服务名>/`）一起删；它的工具和包自己的一样记成随包卸掉，用过的会话调到说已卸载。
5. 测试用的服务多两个参数：`ttl:<毫秒>`（列的结果带 `ttlMs`）、`exit-if:<路径>`（这个路径在就起来就退出）。

### 定了的（主会话，技术题照推荐）

- 扩展的 `extension.restart` 只重启扩展进程，不动它带的服务：两样是不同的进程，服务自己退出了自己会退避重启；手动重启服务随 X-4 的每服务状态一起做。
- 缓存认命令和环境变量的写法，不认取出来的值：密钥换了不会换时代，也不该让密钥落进缓存。
- 缓存、工作目录放在 `state/mcp/` 下（图纸原样），不挪进包的状态目录：那是包自己的地方，核心管的东西放进去会撞名。卸包时照清单的服务名另删。
- 过期了不当场列：先照旧调，同时叫任务列；列完的下一个回合换工具面（同「工具变了」）。
