## 施工单 V-25 上：模型资料查表

状态：已完成。2026-10-30 项目主人定这一轮性能优化「照推荐的做」；核心主会话同天定了切口，分上下两步：上只切开、定接口，下接进路由、存盘、目录不常驻。

### 目的

核心常驻整份 models.dev 目录（8341 个模型，约 3.3 MB），可一个核心真问到的只有配置里那几家、那几个模型。把每一轮路由读目录的地方收成两个纯函数和一个查表的接口，另做一份「照输入记下的答」，证明它和整份目录现算逐字一样。这一步对外行为一个字节都不变：目录照旧常驻，路由照旧拿整份目录现算。

### 查下来的

- 目录被每一轮路由读的地方最后只落到两处：
  - 合一家供应商（`provider.rs` 的 `provider`）：`matching::recognize` 认成目录里哪一家，再取那一家的 `npm`（换驱动）、`api`（没写地址时用）。
  - 合一个模型的资料（`facts.rs` 的 `facts`）：`matching::find` 四层对目录，再取对上的那一条，来源带目录的 `fetched`。
- 两处都是纯的：同一份目录、同样的输入（编号、字面地址、手写的 `catalog`；认出的那一家、模型名、手写的 `catalog`，加认原厂的表），答的一定一样。所以答可以照输入记下来。
- 要整份目录的另有几处：`model.list` 的发布日期、第一次接入（`onboard`）、搜目录、图标、`probe.rs` 推荐模型。这些照旧看 `Knowledge.catalog`，不在这一步。
- `Knowledge` 是 `Copy`，各处照字面造（路由的 `ModelData::with`、几处测试）；查的时候借 `&Knowledge`，要边查边记得有内部可变。

### 蓝图改哪几节

`models.md`：

- 状态那一行：加「V-25 上在做」。
- 「在哪」：`knowledge.rs` 一行加 `lookup`；新加 `catalog/lookup.rs`、`catalog/recall.rs` 两行。
- 「怎么走」第一条第 2 条：目录里那一家的 `api`、`npm` 经查目录的接口取。
- 「怎么走」第二条第 8 条：加两款——查目录只经一个接口（两个纯函数各收什么、交什么，为什么切在这里），`CatalogLookup` 的两种、负的答也记、记不记由调的一方说、认哪一份目录照 `of`、写成 JSON 带版本、为什么写成枚举不写成 trait。
- 「守着它的」：加 `catalog/recall/tests.rs` 一行。

施工时定的：

| 题 | 定的 | 为什么 |
|---|---|---|
| 接口写成 trait 还是枚举 | 枚举 `CatalogLookup<'a>`：`Full(&Loaded)`、`Recalled(Recalling)` | 只有这两种、都在 `miyu-models` 里；枚举 `Copy`，`Knowledge` 照旧整份拷着走，造的地方一句 `catalog.map(CatalogLookup::Full)`；这个 crate 里也没有别的 trait |
| `Knowledge` 怎么变 | 加一格 `lookup: Option<CatalogLookup>`，`catalog` 留着 | `provider`、`facts` 只看 `lookup`；要整份目录的几处照旧看 `catalog`。没有 `lookup` 的当没有目录，和以前目录还没读完一样 |
| 「不知道」怎么表达 | `Recalled` 自己的方法交 `Recall::{Known, Unknown}`；经 `CatalogLookup` 合资料时 `Unknown` 当没有目录（认不出、没对上） | 合资料的结果和以前目录没读完时一样；下一步要分辨的直接调 `Recalled` 的方法 |
| 记不记 | `Recalled` 的方法收 `remember`，`Recalling` 带一格 `remember` | 核心主会话要求能分「配置里写过、真问过」和临时问一句；这一步先给开关，谁记谁不记由下一步接的时候定 |
| 记下的放哪、怎么改 | `Recalled` 是纯数据（`&mut self` 记），合资料时借 `&Mutex<Recalled>` | `Knowledge` 借出去是共享的引用，边查边记要内部可变；锁坏了照样用（每一条查完才整条放进去） |
| JSON 的样子 | `{"v":1,"of":…,"source":…,"fetched":…,"providers":[[输入,答]…],"models":[[输入,答]…]}`；目录条目原样写（`serde` 开 `rc`） | 表的键不是字，写成一排；照 `digest.rs` 带写法的版本，读不懂、版本不对的报错，由调的一方处理（`of` 对不对得上也由它看） |

### 不做什么

- 不接进 `ModelData`、不存盘、目录照旧常驻：都是 V-25 下。
- `model.list`、第一次接入、搜目录、图标、推荐模型这些要整份目录的不改。
- 不管换了目录以后记下的答怎么作废：`of` 留给调的一方定，这一步只带着它。
- `facts()`、`provider()` 之后的合并顺序、来源、默认值、报错原话一行不动。

### 风险

- 合一个模型的资料现在拷一份目录条目（原来借着）：条目里的字、价格、思考强度都是 `Arc`，拷只是加引用计数；合一家供应商多拷三段字。每一轮几次，量不出来。
- `Recalled` 借进来的整份目录必须是记下时的那一份，这里不查；认原厂的表也不算进输入。下一步接的时候要把目录的指纹、认原厂的表一起算进 `of`，换了就换一份新的，不然会拿两份目录的答拼在一起。
- 只有一部分记下、又没有目录可借时，认不出的一家会拿「没认出」去问模型那一面，交的是没认出时的答（如果记过），和有目录时不一样。下一步要么保证配置里的都记全了再撤目录，要么说不出来时先把目录读回来。
