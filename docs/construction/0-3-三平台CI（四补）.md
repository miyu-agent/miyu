Windows 门禁那一步拆开：编 xtask 31 秒，格式 7 秒，clippy 1 分 54 秒，文档 45 秒，测试 18 分 23 秒。测试里编测试程序 8 分 53 秒，跑 133 个测试程序 9 分 19 秒（一个接一个跑：端点那个 710 个测试 2 分 46 秒，431 个的那个 2 分 28 秒，225 个的 1 分 04 秒）。

### 这一步做什么

1. **只改门禁不读的文档不跑**：`on.push.paths` 排除施工单、作者说明、评审、设计文档；门禁读的照跑（蓝图全部：样本块和提示词；设计 01、23、26；`docs/perf`）。
2. **main 上测过的不再跑**：先跑一项 `tested`，main 上的这个提交在别的分支上已经有一趟绿的 CI，就算测过。测过的：门禁、长跑、量尺在编译缓存正好命中时跳过；没命中的照跑（顺带存这一份缓存：只有 main 存，分支照它取，跳过了就再也存不上新的）。

### 施工时定的（主会话，技术题照推荐）

- 文档的排除用白名单式的 `paths`（后写的盖先写的），不用 `paths-ignore`：设计文档里有三份门禁要读。
- 判「测过」照 GitHub 的接口查同一个 sha 的成功的 CI，不另记。

### 没做的、待定

- Windows 跑测试程序一个接一个（9 分多钟）：换成并行跑测试程序的工具（`cargo nextest`）大概能省一半，但测试里有几处靠「一个进程只装一次」（自己装日志订阅者的那几个照旧各是各的程序），要先逐个确认，另起一步。
