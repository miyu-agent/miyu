## 施工单 M-4：给她看的字（说明、例子、输出字段）

状态：施工中（2026-10-21 项目主人拍板：三种都比、60 次；测完拿数问他定写在哪；MCP 的输出格式不转、PowerShell 的例子只在虚拟机里跑通，都照推荐）。设计 `39-脚本调工具.md` 第九节、第十节、第十一节 M-4；输出字段是项目主人 2026-10-20 加的（shellhook 转来，见「为什么多一件」）。图纸 `tools/shell.md`、`tools/interface.md`（说明文件）、`policy.md`（system 怎么拼）、`session/tools.md`（工具面）、`cli/call.md`（`--schema`）、`prompts.md`（登记）。

### 目的

M-1 到 M-3 合了，脚本里已经能 `miyu call`，但说明里没写，她不知道（第十一节末尾）。这一步把两段字接上：`shell` 说明的末尾讲怎么用，system 里一段讲什么时候用；合了才算对她开。

### 为什么多一件

项目主人 10-20 原话：「工具schema写上输出内容字段。可以不用所有工具都带上，让那些clicall true的带上就行。也许能提高clicall工具的使用效率？」「这就需要实际测试了。可以做简短的测试。不用太复杂。」

设计第九节本来就有 `{shapes}`：结果的样子写在 `shell` 说明那一段末尾，第二到六轮实测一直带着它，没单独比过带和不带。这一步比三种：不写、写在 `shell` 那一段、写在各工具自己的说明里，照数定写哪（「拍板的」第 1 条）。

### 做什么

1. **`shell` 说明的末尾一段**：字照设计第九节，放资源文件 `software/basesystem/shell/call/describe.txt`，模板留 `{tools}`、`{example}`、`{shapes}`。只在这个会话的工具面上有能调的工具时接上。
   - 在哪接：组工具面的那一处（`Agents::face`）。那里本来就照会话改 `shell` 的说明（只前台的会话换一份），工具面、哪几件 `clicall` 开着都在手上。
   - `{tools}`：照工具面上两道都过的（`clicall` 开着、类别准的），照名字排；一个 MCP 服务的几件并成 `mcp__<服务>__*`。
   - 工具面在一个会话里不变，这一段也不变，不碰前缀缓存；人改了预设、装了包，下一个回合工具面重算时一起换（`25-工具加载.md` 第五节的口径，现有的）。
2. **`{example}`**：核心起来时和 `{shell}` 一起定一次，会话里不变。PowerShell 的用 PowerShell 那行；bash、zsh 的 `PATH` 上有 `jq` 用 jq 那行，没有、有 `python3` 用 Python 那行，都没有不带 `Example:` 这一行（设计第九节第 2 条）。三行各一个资源文件。`shell` 那个包交出这一行（`Tool` 加一个钩子，同 `foreground_description`），组工具面时填进去。
3. **system 一段**：字照设计第九节，放 `core/clicall.txt`，接在「核心的几行」（权限、本机那两段）后面；工具面上有能调的工具才带。
4. **输出字段**：工具的说明文件加一格可选的 `result`，写结果的样子，紧凑写法（照原型那样）：
   - `web_search` `{"kind":"links","links":[{"title","url","snippet","site","date"}]}`
   - `memory_search` `{"memories":[{"id","class","date","text"}],"turns":[{"date","session","text"}]}`
   - `kb_search` `{"hits":[{"kb","path","heading","snippet","page"}]}`
   - `kb_read` `{"kb","path","page","pages","text"}`
   - 只给交结构化结果（`data`）的写。`web_fetch`、`history`、`sessions`、`session_usage`、`packages` 交的是字，不写，统一一句「别的打印文字」。`meme_search` 在表情包仓库，它交结构化结果的话照同样写（告诉那边）。
   - 写在哪照实测定（「拍板的」第 1 条）。
5. **`--schema` 加 `Result:` 一行**（M-3 拍板延到这一步）：有 `result` 的照它印，没有的不印。
6. **登记、量 token**：新的资源文件进设计 26 第十节，量 token（照开发端点量，同 M-3）；`cargo xtask prompts` 重生成 `prompts.md`。

### 实测（项目主人要的「简短的测试」）

- 照第十节那套（`~/.cache/miyu-remake/m0-eval/`，ClinePass 的 `deepseek-v4.1-flash`），但跑的是这一步真的代码，不用原型。实验期间在一个不合的提交里加环境变量 `MIYU_EXP_SHAPES` 切三种，测完删掉。
- 三种：
  - A 不写；
  - B 写在 `shell` 那一段末尾（设计第九节现在的写法）；
  - C 写在各工具自己的说明末尾（`miyu call prints: {…}`）。
- 题：A2、W2（重活，调很多次）、W1（搜了再抓，串起来）；对照题 C2 看会不会乱用。每格 5 次，一共 3 × 4 × 5 = 60 次。
- 量：请求次数；全部 token（没命中缓存的、命中的、输出）；正确率；`--schema` 调了几次；脚本因为字段名写错重跑了几次（shell 的退出码和标准错误里的 `KeyError`、jq 取到 `null`）。
- 每种多花的 token：B 每个能调的会话固定一份；C 分在各工具的说明里，开着这几件工具的会话都付。

### 拍板的（2026-10-21 项目主人定）

1. **输出字段写在哪：测完拿数问项目主人定**（他没选「照判法自定」）。下面是我会附上的推荐判法：
   - B 或 C 比 A 省（全部 token 中位数省 10% 以上，或者正确率高）：带。
   - B、C 差不多（相差 10% 以内）：选 B。只有能调的会话付这几个 token，写在一处；各工具的说明和指纹不动。
   - C 明显比 B 好：选 C。
   - A 不比 B、C 差：不写，`--schema` 的 `Result:` 照印，要的时候她自己查。
2. **规模**：三种都比，60 次（照推荐）。
3. **MCP 的输出格式第一版不转**（照推荐）：MCP 工具声明的 `outputSchema` 不转成 `result`，照原样交 `structuredContent`，统一归进「别的」那一句。转的话说明会跟着服务变长，要另测。
4. **PowerShell 的例子只在虚拟机里跑通那一行**（照推荐，经 SSH，不碰桌面）：确认它在 PowerShell 5.1 里取得出、数得对；不在 Windows 上跑模型实测（没有那里的实测环境，模型照着写一行管道的行为和 Linux 上一样）。

### 不做什么

- 两个头（M-5）。
- 说明翻成别的语言（给她看的字一律英文）。

### 验收

- 单元：
  - 没有能调的工具的会话不接这一段、system 不带那一句；有的接上。
  - 名单照名字排、MCP 的并成一项。
  - 有 `result` 的进 `{shapes}`，没有的归「别的」。
  - `{example}` 四种：PowerShell、有 jq、只有 python3、都没有。
  - `--schema` 的 `Result:`。
- 请求形状探针：没有能调的工具的会话逐字节不变。
- 登记簿指纹、`prompts.md` 重生成、说明的预算测试。
- 回归：用最后定的字照第十节的题再跑一遍（每格 4 次），和第五轮比，不变差。
- 门禁全过，三平台 CI 过；手写变异 10 个左右。

### 风险

- 说明的预算测试（`basesystem/tests/budget.rs`，11700 字节）量的是说明文件，接在后面的这一段不算在里面；它在会话里多出来的 token 记进登记簿。
- 测试里的模型偶尔交回垃圾搜索结果（第十节第 5 条），W1 噪声大，看中位数。
