## 施工单 X-42：远程 MCP 的 OAuth

状态：在分支 `step/X-42-远程MCP的OAuth` 上。主会话审过（2026-10-21）：九题照推荐，另补三点（见「主会话补的」）；拆上、下两步写代码；CIMD 等项目主人定网址，那一题留着。「MCP 服务挂在哪个包」照现在的写，F-17 合的时候主会话统一挪。

### 目的

Notion、Linear、Sentry 这类远程 MCP 服务只认浏览器授权（OAuth），发不了个人令牌，现在接不上。项目主人 2026-10-20 定推迟，2026-10-21 重开：「命令行先，头也做」。这一步照 MCP 规范 2026-07-28 的「Authorization」做核心和命令行，人打一条 `miyu mcp login <服务>`，浏览器里点同意，服务就连上了，令牌到期自己续。终端、网页的「登录」按钮由主会话和两个头另排。

### 主会话补的

1. 写回密钥文件照现有的写法：整份重写、0600、照读到的版本防并发改；续期和人手改密钥撞了不丢。
2. 授权地址拼好以后，命令行印的那一行只有地址，不带 `code_verifier` 之类。
3. 手贴回调（`mcp.login_finish`）同样校验 `state`、`iss`，和本机回调在同一处判。

### 要拍板的

1. 客户端元数据文档（CIMD，规范更推荐的注册办法）要一个固定的 https 网址放 Miyu 的客户端信息，这一步不做。**推荐**：等项目主人定了放哪（比如开项目的 GitHub Pages），再单开一步；现在先用动态注册和预先注册，主流服务都认。

### 不做什么

- 终端、网页的登录按钮（第 9 题）。
- CIMD（上面那条）。
- 本机起进程的服务：规范说标准输入输出的服务照环境变量拿凭据，不走 OAuth。
- 扩展自己的 OAuth：扩展的事。

### 验收（写代码那两步照这个写测试）

1. 测试用的假网址服务（`miyu-mcp` 的 testkit）多一套假授权服务器：受保护资源元数据（头里给的、只在 well-known 的两种）、授权服务器元数据（OAuth、OIDC 两种路径）、注册、授权（测试自己当浏览器去 GET 授权页，假服务器直接跳回调）、换令牌、续期；每一样都能配成错的。
2. 先写会红的测试，一题至少一条：回 401 的记成 `needs_login`、写了 `bearer` 的不走；`mcp.login` 回的授权页带 `code_challenge`（S256）、`state`、`resource`、`redirect_uri`；回调换来的令牌存进密钥文件（0600），服务连上、请求带 `Bearer`；`state`、`iss` 对不上的不认；不支持 S256 的拒；到期前续、续不成的 `needs_login`；403 `insufficient_scope` 的下次 `scope` 并上；`mcp.logout` 删掉；运行日志、事件、协议回应里搜不到令牌、授权码、`code_verifier`（照 `secrets_log.rs` 那个单独的测试程序验）。
3. 手写变异每步 15 个左右；`cargo xtask check` 全过；本机跑 Windows 的 clippy；碰网络、子进程、打开浏览器，推 `step/` 过三台 CI。
4. 真服务走一遍：挑一个只认 OAuth 的公开服务，项目主人在自己的终端里点同意；临时数据根，走完只删它。

### 风险

- 授权服务器千奇百怪：规范要求的两种发现路径、两种注册都做，不认的说清楚为什么（`oauth_unregistered`、元数据对不上），不猜。
- 令牌泄露：只进密钥文件，日志、事件、回应里由单独的测试程序守着。
- 回调端口被别人抢：只听 `127.0.0.1`、随机端口、`state` 一次一用、只收一次。
