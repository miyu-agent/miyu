## OV-1：同名覆盖工具说明和提示词

状态：主会话做，分上、中、下三步。项目主人 10-26 定（设计 00 第五节「可自定义」、`25-工具加载.md` W7、`26-提示词.md` J9）。

### 一、为什么

设计 00 第五节：出厂的只读，要改就在自己的家目录里写一份同名覆盖，只写改了的项。人格、预设早就这样做了；工具说明、提示词还没有，只能改出厂的文件，升级就丢。

### 二、项目主人定的

1. 同名覆盖：`system/tools/<工具>.toml`、`home/<账号>/tools/<工具>.toml` 这类，找的顺序是自己的、系统的、出厂的。
2. 写坏了退回出厂的，并且报出来。
3. 核心盯目录（文件变动通知）加版本号，回合开始只比号；下一轮生效。
4. 头的交互：下一次发送前弹「检测到文件变动：<文件>。继续对话会因缓存失效支付额外输入费用，是否继续。」三个选项：「压缩上下文并发送」「直接发送」「取消」。
   - 核心给会话状态「前缀要变」，发送带「先压缩」。
   - 场所会话、没有头的会话照旧下一轮换上。
5. 范围：人格、预设、技能目录等一切改文件会让前缀变的（主人未反对）。
6. `AGENTS.md` 加一句指向设计 00 第五节，随 OV-1 提交。

### 三、分步

- **上：工具说明的覆盖**。工具说明、每个参数的说明能改，工具名不能改（W7）。查英文和长度，写坏退回出厂并报。造会话时照属主找。显示名（给人看的）挪到下：执行器派调用时取显示名是另一条路，要跟着盯文件一起改。
- **中：提示词的覆盖**。核心随带的字（`resources/core/` 下给模型看的那些）照同一个找法：`system/prompts/<同样的路径>`、`home/<账号>/prompts/<同样的路径>`。
- **下：盯文件、换前缀、问一声**。
  - 盯覆盖、人格、预设、技能的目录，给每个账号一个版本号；会话记着造快照时的号，回合开始只比号，变了照新的重拼快照（`session.policy_changed`）。
  - 会话状态多「前缀要变」和变了哪些文件；`session.send` 多「先压缩」。
  - 两个头照它弹窗。

### 四、上：定下的（技术题，主会话定）

1. **文件的样子**：TOML，只写改了的项；只认 `description` 和 `[parameters.<名字>] description`，别的格算写坏。

   ```toml
   description = "Read a file. ..."
   [parameters.path]
   description = "Absolute path."
   ```

2. **找**：自己的（`home/<账号>/tools/<工具>.toml`）压着系统的（`system/tools/<工具>.toml`），一格一格地压，没写的照下一层，都没写的照出厂。管理员在管理员模式外改的就是他自己的那一层，同人格、预设。
3. **管哪些工具**：工具名在这个人的工具目录里的都管：内置的、脚本、MCP、扩展登记的。不在目录里的覆盖文件放着不报错（那个包可能以后才装）。
4. **查**：
   - `description`、参数的 `description` 照给模型看的字的规矩：一行或几行英文，CJK 不过半，`description` 最多 2000 字、参数的最多 500 字。
   - 参数名必须是这件工具参数格式里有的，写了没有的参数算写坏。
   - 写坏了整份不认，照下一层（最后是出厂的）。报到三处：运行日志一行；`check` 多一条「覆盖文件写坏了：<路径>：<原因>」；`config_errors` 照旧只数配置，不混进去。
5. **放哪改**：造会话、回合开始换快照拼工具面的时候（`Agents::face`），照属主的覆盖把说明、参数说明换掉。工具目录本身不动：别人的会话、脚本里调（`miyu call --schema`）照旧看出厂的，只有她的工具面照这个人改的。叠好的覆盖换不进的（参数格式里没有那个参数）这一件照出厂的、记一行运行日志。
6. **什么时候生效**：上这一步只在造会话、换快照时读，读了就照它。盯目录、回合开始比版本号、头弹窗都在下。上做完以后，改了覆盖文件的人开新会话就是新的，开着的会话要等下。
7. **缓存**：覆盖是人自己写的，工具面变了的那一次冷启动是他要的；没写覆盖的会话工具面字节不变。

### 五、上：做什么

1. `miyu-store`：读 `tools/<工具>.toml` 两层（`overrides` 模块）：读、合、查写法，交回每件工具一份 `Override { description?, display_name?, parameters: {名字: description} }` 和写坏了的那几份（路径和原因）。
2. `miyu-tool`：`Spec` 照一份 `Override` 换出新的（`Spec::overridden`），参数说明改进参数格式里那个参数的 `description`，参数不在的拒。
3. `miyu-session`：拼工具面时照属主的覆盖换；覆盖跟着 `PresetPlaces`（同 IM-6 的交了的功能，每次拼时取一次）。
4. `miyu-endpoint`：给会话取覆盖的那一头；`check` 报写坏了的；显示名照覆盖。
5. 测试：两层压、只写一格、写坏了退回出厂且 `check` 报、参数不在算写坏、中文说明算写坏、不写覆盖的工具面字节不变。
6. 蓝图 `tools/interface.md`、`kernel/tools.md`，作者说明。

### 六、上：做了什么

1. `miyu-policy` 的 `overrides.rs`：`ToolOverride::{parse, over, apply}`。只认两种格；给模型看的字非空、说明最多 2000 字、参数说明最多 500 字、除了换行没有控制字符、CJK 不过半；参数说明改进参数格式那一个参数，没有那个参数的整件不换；没写参数说明的不重写参数格式，字节照旧。
2. `miyu-store` 的 `overrides.rs`：`tools_in(dir)` 找一层里的 `<工具名>.toml`，照配置文件的规矩读。
3. `miyu-session`：`PresetPlaces.overrides`（`ToolOverrides`）；`Agents::face` 的 `Offers.overrides` 拼工具面时换。造会话、回合开始换快照（`actor/persona/face.rs`）两处都带。
4. `miyu-endpoint`：`presets/overrides.rs` 的 `of`（两层叠）、`problems`（写坏的、换不进的），`places` 交给会话；`check` 报 `override_bad`（`kind` 是 `override`，三种语言的话）。
5. `AGENTS.md`「代码的规矩」加一句指向设计 00 第五节。

### 七、上：怎么验

1. `miyu-policy` 单测：只盖写了的格；自己的说明压着系统的；没写参数说明的参数格式字节不变；参数不在的整件不换；写坏的几种（中文、空的、不认识的格、不是字、坏 TOML、太长）各说为什么。
2. `miyu-store` 单测：只认 `<工具名>.toml` 的普通文件，照名字排，没有目录的是空的。
3. 端点 `tool_override.rs`：扩展登记四件工具。
   - `echo` 说明照系统那一层的，参数说明照自己那一层的。
   - `broken`（中文说明）、`missing`（参数不在）照出厂的，`check` 报这两份。
   - 没写覆盖的 `plain` 参数格式字节和出厂的一样。
4. 手写变异 6 个全杀：叠的先后反了、不查中文、拼工具面不换、不读自己那一层、`check` 不报、换不进的不报。叠的先后那一个头一轮活了，补了「上一层的说明压着下一层」才杀掉。
5. 原有工具面、预设、`check` 测试照过。
6. 本机门禁全过。

### 八、中：定下的、做了什么（技术题，主会话定）

1. **范围**：随核心附带的给模型看的字，就是资源目录里经 `ResourceRoot` 读的 `.txt`、`.md`：`core/` 下的那些、子会话的场所说明、人设之外核心拼进 system 的几行。`.json` 不盖：工具说明有上一步的覆盖；给人看的字不是提示词。人格自己的字照人格的同名覆盖（已有）。
2. **路径**：`home/<账号>/prompts/<资源目录里同样的路径>` 压着 `system/prompts/<同样的路径>` 压着出厂的，例如 `system/prompts/core/agent-version.txt`。
3. **规矩**：
   - 出厂得有这一份，覆盖只改已有的字。
   - 不是空的，除了换行、制表没有控制字符，CJK 不过半。
   - `{名字}` 占位和出厂的一模一样：少了的换不进去，多了的会原样发给模型。
   - 不合的照下一层，最后是出厂的。
4. **做法**：`ResourceRoot` 多一列覆盖（`overlaid`），`read` 每读一份字照它找（`resources/overlay.rs`）。读法只有这一条路，不用一份份改调用的地方。端点照属主压上两层（`presets::overrides::resources`），造会话（`sessions/setup.rs`）、载入（`sessions/found.rs`）、派子代理（`sessions.rs`）、整理记忆（`sessions/dream.rs`）四处交给会话。
5. **报**：`check` 报 `prompt_override_bad`（不合规矩的、出厂没有这个路径的、不是 `.txt`、`.md` 的），三种语言的话。
6. 生效同上一步：造会话、载入、换快照拼字时读；开着的会话下一轮换上、头问一声在下。

### 九、中：怎么验

1. `miyu-store` 单测：自己的没写照系统的；自己的压着系统的；占位不对照下一层；都不合（中文）照出厂；报三种不合的（占位、出厂没有、`.json`）；`.json` 不盖。
2. 端点 `prompt_override.rs`：系统那一层改了版本那一行、自己那一层的占位不对 → 照系统的；自己那一层改了本地路径那一行、系统那一层也改了 → 照自己的，出厂的、系统的都不在；`check` 报自己那一层占位不对的那一份。
3. 手写变异：见结果。
4. 本机门禁全过。

### 十、下：定下的（技术题，主会话定；交互是项目主人 10-26 定的，协议和终端头 10-28 对过）

1. **盯哪些**：每个账号两层（系统区、他的家目录）的 `tools/`、`prompts/`、`personas/`、`presets/`、`skills/`，往下递归（`skills/` 施工 PT-2 上拿掉了：技能那一块钉在快照里、中途变了走尾巴注入，前缀不变，问人是误报）。还没有的目录登记时建空的：这几个本来就是给人放自定义的地方。新建、挪进来的子文件夹，里面已经有的文件都算改了（施工 OV-1 补：系统的递归监视报了新文件夹才去看它，建好就写进去的那一下原来漏了）。只盯这五样，不盯整个家目录（会话目录变动多，递归盯它浪费系统的监视名额）。
2. **版本号**：每个账号一个，盯着的文件一变就加一，记下这一下是哪个文件（照数据根写的相对路径，最近的 64 条）。系统区的一变，所有账号都加一。只在内存里：核心重启从零数，会话也从零记，不会误判。
3. **会话怎么用**：会话记着它最后一次拼快照时看到的号。回合开始只比号，变了就照现在的文件把工具面、system 重拼一遍（人格、预设本来每回合就照内容比，这一步补上工具说明、提示词的覆盖和技能目录），拼出来的字节和快照一样就不换，不一样就换（`session.policy_changed`），再记下这个号。
4. **问一声（反应式）**：
   - 握手 `caps.prefix_ask: true` 的头才问；没声明的照旧直接发、下一轮换上。
   - 开新一轮的入口：`session.send`、开轮的 `command.run`、`session.redo`。会话空着、是本机会话、有人确认、属主的号比会话记着的新、这一批没放行过的，不带 `prefix` 就拒 `prefix_changing`，`data.files` 是变了的文件（最多 20 个，多的带 `more`）。
   - 带 `"prefix": "keep"` 的放行这一批，照常说；带 `"prefix": "compact"` 的先压缩再说，压不了的回压缩自己的拒绝、这句不发。
   - 放行照会话记；之后有新的改动再问。正在跑一轮时说的话、跑着时排进去的那句、场所会话、子会话、定时和 `/loop` 自己起的轮都不问。
5. **显示名的覆盖**（从上挪过来）：留到以后单开一步，这一步不做。头上的显示名照出厂的。

### 十一、下：做了什么

1. `miyu-store` 的 `watch.rs`：`watch_tree` 往下递归盯一棵树，交回变了的那个文件（照调的一方给的根写，跳过点开头的）。
2. `miyu-endpoint` 的 `presets/edits.rs`：`Edits` 记每一层最后一下的号和最近 64 条改动；`version` 取属主那一层和系统区大的那个，`since` 交回号以后改了的文件和还有几个。`Core::watch_edits` 在 `places` 里照属主登记，系统区头一回一起盯，没有的目录建空的。
3. `miyu-session` 的 `prefix.rs`：`Prefix` 记会话照着拼过的号（`seen`）、人放行过的号（`allowed`），actor 和 `Handle` 共用一份；`PresetPlaces.edits` 取属主这时的号。回合开始（`actor/persona.rs`）号比 `seen` 新的照现在的文件重拼，换了、没换都记下这个号。回合开始不换快照的会话（整理记忆的、fork 子代理的，`follows_files`）`hold`：永远不问。
4. 握手 `caps.prefix_ask`；`sessions/prefix.rs` 的 `ask`：`session.send`、`session.redo`、模板命令、MCP 提示词、`/goal` 设定和继续开轮前调；`prefix` 参数 `keep`、`compact`；拒绝 `prefix_changing`（三种语言的话、`data.files`、`data.more`）。`compact` 照 `session.compact` 开一轮，开了才放行，这一句排在它后面。
5. 蓝图 `protocol.md` `session.send` 第 9 条、`caps`、三处参数表、拒绝表；参考 `connection`、`sessions`、`packages`、`errors` 中英两份。
