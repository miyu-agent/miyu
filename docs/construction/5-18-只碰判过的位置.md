## 施工单 5-18：只碰判过的位置

状态：开工（2026-10-22）。漏洞排查会话 2026-10-22 查出、复现测试是红的（补丁 `~/.cache/miyu-audit/core-audit-tests.patch`，高）；主会话排给 core2，同一天同意修法（不只守数据根，改成只碰判过的位置）。只有技术细节，直接做。

### 目的

权限策略判一次调用时把路径换成真实的位置判，文件工具执行时自己又换一次，打开前不再核对。两次之间路径上的链接被换掉（沙盒里的命令就换得了工作区里的链接），工具碰的就不是判过的那一个：读得到数据根里的本机令牌，或者工作区一级不问人写到工作区外（`~/.bashrc` 这类）、私密目录。做完以后，权限策略把判过的真实位置交给工具，工具换出来的不在里面就不碰。

### 蓝图改哪几节

- `tools/interface.md`：`Call` 多一格 `checked`；「二、一次调用」第 2 步判完交回判过的位置、第 3 步放进 `Call`；「三、要碰的路径」多第 4 条：工具照 `Call::real`、`Call::real_itself` 换，换出来的不是判过的不碰；`glob`、`grep` 只核搜的那个目录。
- `session/guard.md`「判一次调用」多第 11 条：换成的真实位置连同结论交回。
- `session/tools.md` 第 1 条第 3 款：执行器照调用编号记下、派的时候放进去，没记下的按空的算，回合结束扔掉没派出去的；「1g」第 2 条：嵌套调用的记在等着的那一份上。
- `fs.md` 第四节第 1 条：打开的是判过的那一个，两段各由谁挡。
- 设计 `11-权限与沙盒.md` 第七节「第一版怎么做」：补一条「判的和碰的是同一个」，记下未选的「只守数据根」。

### 不做什么

- 不在工具里另守数据根：数据根里本来就有能碰的（默认工作区 `home/<账号>/workspace/<会话>/`、技能文件夹、附件目录），工具单独拒会误伤；判过的位置已经管住了。
- `glob`、`grep` 往下走的子树不一层层核：走目录本来不跟链接，读文件逐层不跟链接地打开（`fs.md` 第四节）。
- 扩展、MCP 的工具在自己的进程里碰文件，核心管不到，不动。`package`、`packages` 看包文件夹由包管理那一头读，不在这一步。
- Windows 上「换完到打开之间」照旧挡不住（`fs.md`「还没有的」），不在这一步。

2. 会话层：`cargo test -p miyu-session --test all guard_checked`：报的几条照先后交到工具手里（相对的、外面的、还不存在的），不报路径的是空的；脚本里调的一样带；问人时把工作区里的链接换成指进数据根，人点了允许，`write` 不写、数据根里没多文件（Unix）。修之前最后一条写进了数据根。
3. 每件文件工具：`cargo test -p miyu-basesystem --test all checked`、`an_attachment_that_was_not_judged`：不在判过的就不碰，在的照常。

### 风险

- 漏了一条派工具的路，那条上的文件工具就全拒：核心里造 `Call` 跑工具的只有直接调用（`tools.rs`）、嵌套调用（`tools/nested.rs`），都先过权限策略；两条各有测试。扩展的工具经 `tool.call` 走的也是直接调用那条。
- 判和跑之间合法地建出了文件（大小写不分的平台上换了个大小写写），换出来的写法不一样会被拒：她再调一次就好，不放开。
- 回合结束扔掉没派出去的：调用都在回合里派，结束了的回合不会再派。
