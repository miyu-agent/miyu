## 施工单 X-12 下：`miyu check` 报跳过的脚本、技能；沙盒里读得到脚本自己

状态：合了（0638a960，三台 CI run 1920；2026-10-12 主会话）。图纸 `docs/blueprint/skills.md`「脚本」第 2 条、「定了的」第 3 条。

### 目的

脚本、技能写错了不登记，作者得知道是哪一个、为什么：跑 `miyu check` 一条条报出来，不用去翻运行日志。

### 做了什么

1. **`check` 不写文件的那一种多查一样**（`miyu-endpoint` 的 `check/skipped.rs`）：照这一刻装了的包和管理员家目录把脚本、技能再找一遍（`miyu_store::scripts::find`、`miyu_store::skills::find`，在阻塞线程里），排在包自己的检查后面，每一处一条警告：
   - `script_skipped`：脚本没登记（读不了、不是字、开头写错、同一个工具名前面已经有了）；
   - `script_clashed`：脚本读成了，撞了别的工具的名字（出厂的、扩展的、MCP 的），工具目录没登记；
   - `skill_skipped`：技能没列出来（开头写错、读不了、同名被压掉）。

   `kind` 是 `script`、`skill`，`file` 照数据根写相对路径，`message` 照连接的语言，带上为什么（英文一句，同读开头时说的）。
2. 给人看的三句（`resources/core/human/{zh,en,ja}.json` 的 `package-problems/script_skipped` 这几条）。
3. **进沙盒的脚本读得到它自己**（`miyu-basesystem` 的 `shell/script.rs`，真模型走一遍时查出来的）：家目录里放的、自己装的包带的脚本在数据根里，沙盒藏着那一片，解释器读不到脚本（Linux 上 `Permission denied`，她只好改用 `shell` 自己掷骰子）。经助手起时，规格的 `reveal` 加上脚本这一个文件，只读；旁边的照旧藏着。外部身份的会话（只准读名单）也照 `reveal` 放开（X-10 中的做法）。

### 定了的

- **脚本说明、参数多大都收，不按大小挡**（2026-10-12 项目主人改定）：原先图纸写的是单件超过 550 token 的不收、`miyu check` 报，撤掉了。
- **报的是警告，不是错**：没登记的那一个不影响别的，核心照常起来。

### 真模型走了一遍

沙箱数据根，管理员家目录 `scripts/` 里放掷骰子的 `dice.py`、旧版的 `reddit-search`（说明加参数 2208 字节，超过原先定的 2000 字节预算）、一个没写 `Description` 的 `broken.sh`，`skills/` 里一个没写 `description` 的技能。开发端点（magpie 网关的 `clinepass/cline-pass/deepseek-v4.1-flash`）：

| 做的 | 结果 |
|---|---|
| `miyu check` | 两条警告：「跳过了这个脚本：Description is missing or empty」、「跳过了这个技能：description is missing or empty」，文件照数据根的路径 |
| 「帮我掷三个六面的骰子」（修以前） | 调 `dice` 两次都是 `Permission denied`，改用 `shell` 掷 |
| 同一句（修以后） | 调 `dice`，交回 `{"faces": [1, 3, 2], "total": 6}`，照着答 |
| 「用 reddit 工具看看 r/rust 最新的 3 个帖子，只要标题」 | 调 `reddit-search`（`subreddit: rust, limit: 3, full: false`），沙盒里照样联网，答出三个标题 |

日志里没有密钥；沙箱核心停了。

### 验收

- 端点：管理员家目录放一个好脚本、一个没写 `Description` 的、一个撞了 `read` 的，一个没写 `description` 的技能；`check` 交回三条警告（种类、文件、代码、级别都对），说明里带着为什么、撞的名字。
- 会话层（Unix 上有收紧手段的）：alice 家目录里的脚本经真助手跑，读得到它自己、旁边的数据根读不到。修以前这一条报红（退出码 126，权限不够）。
- 变异 7 个全报红（不调、跳过的脚本不报、撞名判反、撞名比较不对、跳过的技能不报、理由不带、级别写成错）；规格不加脚本那一条就是上面修以前的红。
