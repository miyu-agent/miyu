拆成两半：上是名单（配置、出厂清单）和文件工具；下是沙盒里的命令（规格多一格 `readonly`、bubblewrap 挂只读、macOS 写拒绝规则、探测多验只读；Windows 等 5-9 改下量完 MXC 再接），要推 step 分支过三台。

### 上：做什么

1. 名单（`miyu-fs` 的 `readonly.rs`）：`Readonly { inside, paths }`。一项三种写法：`~/…`、绝对路径，照 `written` 拼；别的当相对路径，照 `/` 拆（Windows 上 `\` 也算），空的、`.` 跳过，带 `..` 的、什么都没写的不收（`readonly_entry`）。出厂的去掉人去掉的（照写法比），加上人加的；家目录本身和它的上级、写法不对的不算，重复的只留一个（`Readonly::with`）。
2. 出厂清单（`readonly/shipped.rs` 的 `SHIPPED_READONLY`）：前七个是工作区里的 `.git/hooks`、`.git/config`、`.miyu`、`.mcp.json`、`.vscode`、`.idea`、`.envrc`，三个平台一样；后面是家目录下的 shell 启动文件、git 的全局配置，Linux 加 systemd 的用户服务、桌面自启动，macOS 加 `Library/LaunchAgents`，Windows 是 git 的全局配置和 PowerShell 的配置文件。比对照报告多了 `.bash_login`、`.zshenv`、`.zlogin`、`~/.config/git/config`（同一类：shell 启动文件、git 的全局配置的另一处）。
3. 边界表（`boundary.rs`）：原来写死的 `runs_outside`（`.git` 下一层 `hooks`、`config`）换成照名单。只把能写的那几片（工作区、加进来的目录、临时目录）里落在名单上的降成只能读，读照旧，名单上的落在别的片里照那一片算。相对的那几项在工作区、加进来的目录里哪一层接得上都算（同原来，子仓库也算）；`~/…`、绝对路径的造表时照 `resolve` 换成真实的位置，还不存在的照最近的上级换，建它也要问。名单上有 `.git/config` 的，作为文件的 `.git`（worktree、子模块）也只能读。macOS、Windows 上不分大小写。
4. 配置项（`miyu-tool` 的 `readonly.rs`，挨着私密目录登记）：`sandbox.readonly.add`、`sandbox.readonly.remove`，文字的列表，系统、个人两层，下一轮生效，`privacy` 页新组 `readonly`（「受保护的路径」），排在私密目录后面，没有总开关（网页画好的形状）。
5. 每一轮照配置换（`Guard::readonly_of`、`Guard::set_readonly`，回合开始和私密目录一起换）；造权限策略时是出厂的。
6. `config.set` 多查一道（端点 `config/private.rs`）：`add` 写法不对 `bad_format`（问题 `Code::ReadonlyPath`，单给一句说该怎么写），家目录本身或它的上级 `readonly_too_broad`（新的问题码）；`remove` 只收出厂清单（`Code::ReadonlyNotShipped`，协议上 `not_an_option`）。`config.schema` 里 `remove` 交出厂清单当 `options`、带 `ticks: "unlisted"`，同私密目录。
7. 放行规则（第四条）：受保护的路径同私密目录，只认放行范围本身也受保护的规则（`Boundary::protected`、`guard/asking.rs` 的 `granted`），对整个工作区点了「此目录不再询问」照旧问；问它时提的规则，它是文件、上级不受保护的只放它本身（`Asked::alone`），上级也受保护的照旧放上级。
8. 字表中英日（两项、组名、三句）、生成的样本、蓝图 `config.md`、`fs.md`、`session/guard.md`、协议参考、设计 11 第四节和 A4。

### 上：不做什么

- 不跟环境变量走（`ZDOTDIR`、`XDG_CONFIG_HOME` 指到别处的）：以后要再加。
- 沙盒里的命令不动（下下）。
