## 施工单 M-2：脚本能调哪些工具、交回什么（字段和结果）

状态：施工中（2026-10-20 项目主人拍板：出厂开五件加 `meme_search`；按单个工具开关加进这一步；`data`、`detail` 分开，以前的会话不开）。设计 `39-脚本调工具.md` 第三节、第四节第 2、4、6、7 条、第六节第 3 条（MC2、MC7，2026-10-20），图纸 `tools/`（工具的规格、说明文件、`Done`）、`kernel/tools.md`、`kernel/session.md`「嵌套调用」、`policy.md`、`mcp.md`、`skills.md`（脚本工具的开头注释）、`extensions.md`（`provide`）、`config.md`、`protocol.md`（MCP 编辑原样保留）。

### 目的

M-1 让内核认得嵌套调用；这一步把两头补齐，但仍然不接通道：

1. **哪些工具脚本里能调**：工具多一个开关 `clicall`，从说明文件、扩展、MCP 配置、脚本工具的开头注释一路带到快照、内核；人在个人设置里能按单个工具、按 MCP 服务改。内核在访问类别之外再查它，不是 `true` 的当场拒。
2. **交回脚本什么**：`Done` 多一格 `data`（结构化结果，只给脚本，不进上下文、不进 `tool.result`）。出厂四件照现在给头的那一份填；MCP 的 `structuredContent` 留下来。
3. **真执行器那一头**：`miyu-session` 接上内核的嵌套动作（判、跑、掐、答），留一个口子给 M-3 的通道：交进去一次嵌套调用，拿回一个等回答的 `oneshot`。这一步只在测试里从这个口子驱动。

### 蓝图改哪几节

- `tools/`：
  - 规格 `Spec` 多 `clicall`（布尔）。
  - 内置和软件包的说明文件 `tools/<名字>.json` 认 `"clicall": true`，默认关。
  - `Done` 多 `data`：哪些工具填、什么样子，和 `detail`（给头的）的分别。
  - 嵌套调用里跑的 `Call`：没有任务、子代理、提问、目标的端口，不开通道。
  - 嵌套调用里报了 `effects`、`sent`、`end_turn` 的记一行 `ERROR`、丢掉，结果照常交回。
- `kernel/tools.md`：`ToolRule` 多 `clicall`；嵌套调用的检查在类别之后加这一道，拒绝照 `NotAllowed`。
- `policy.md`：快照的 `ToolEntry` 多 `clicall`，`false` 不写，以前的快照读进来写出去一字不差（以前的会话里一件都不开，照保守的来）。
- `mcp.md`、`config.md`：
  - `[[mcp]]` 和个人设置的服务表认 `clicall`（布尔，或 `yes`/`no`，同 `need_load`），缺省开，整个服务的工具都算。
  - 只改这一格也算改了、照旧重启那个服务。
  - 网页编辑 MCP 时原样保留它。
- `config.md`：个人设置加两项 `clicall.tools.<name>`、`clicall.mcp.<id>`（布尔），照 L-3 的 `loading.tools.<name>`、`loading.mcp.<id>`：一件工具先照它自己那一项，没写的是 MCP 的工具再照它的服务那一项，都没写的照来处；从下一个回合起生效；设置页不画（隐藏项）。
- `skills.md`：脚本工具的开头注释认 `# Clicall: yes|no`，缺省开。
- `extensions.md`：`provide` 的工具认 `clicall`（布尔），缺省关。
- 参考文档中英两份：`packages.md`（说明文件、脚本注释、MCP 配置）、`extensions.md`（`provide`）跟着改。配置的样本（`config.schema`、`reference.toml`、个人设置的 schema）加这一格。

### 拍板的（2026-10-20 项目主人定，都照推荐）

1. **出厂开的五件**：`web_search`、`web_fetch`、`memory_search`、`kb_search`、`kb_read` 的说明文件里加 `"clicall": true`（设计 39 第三节第 2 条已定）。
   - 这五个文件会变，登记簿（`26-提示词.md` 第十节）的指纹跟着换，token 不变：这一格不发给模型。
   - 推荐：照设计放在说明文件里，和工具写在一起。
2. **`data` 和 `detail` 分开两格**：`detail` 是给头画的，以后可能为了界面改；`data` 是给脚本的接口，要稳。推荐分开，出厂四件现在填一样的值。
   - `web_search` 交 `{"kind":"links","links":[…]}`，搜不到的也交，列表是空的。
   - `memory_search` 交 `{memories, turns}`。
   - `kb_search` 交 `{hits}`。
   - `kb_read` 交 `{kb, path, page, pages, text}`。
   - 出错的（`Done::error`）不填。
   - 2026-10-20 项目主人加开 `meme_search`（表情包包，扩展 `provide` 的，读类）：在 `miyu-memes` 仓库里给它的登记加 `"clicall": true`，这一步合了以后跟一个提交。
3. **以前造的会话**：快照里没有 `clicall`，读成关，那些会话里的脚本一件都调不成，要新开会话。推荐这样：M-4 之前她本来就不知道 `miyu call`；照「以前的快照读进来逐字节一样」的规矩，不去猜旧会话里哪件该开。

4. **按单个工具开关**：人在个人设置里写 `clicall.tools.<name>`、`clicall.mcp.<id>`，照 L-3 的办法。别家（2026-10-19 拉的源码）：Codex、opencode 只能按 MCP 服务或命名空间关，dsh 全有或全无，pi-mono 能按通配符关 MCP 的单件；这里内置、扩展、MCP、脚本的每一件都能单开单关，写法用确切的名字，不用通配符（同 `loading.tools.<name>`）。

### 不做什么

- 通道、`miyu call`、`--schema`（M-3）；给她看的字、`{shapes}`（M-4）；头（M-5）。
- 通配符（pi-mono 的 `toolExposure` 那样）：按一批关用按服务那一项。
- `mcp.list`、脚本列表回应里显示 `clicall`、网页上能开关（像 X-27 的 `tool.set_loading`）：等网页那边要的时候另开一步；这一步只保证编辑 MCP 时不丢，个人设置文件里写了就生效。

### 验收

- `clicall` 的来处各一条测试，默认值和改法照设计第三节的表：
  - 说明文件写了 `true` 的开，没写的关，写了不是布尔的整件拒（同 `need_load` 的报错）。
  - 扩展 `provide` 写了的开，没写的关。
  - MCP 缺省开，`clicall = false`、`"no"` 关，个人设置的服务表也认；只改这一格，那个服务重启。
  - 脚本工具缺省开，`# Clicall: no` 关，写错的照 `Need load` 一样报。
  - 个人设置：`clicall.tools.<name>` 盖过来处（开的能关、关的能开），`clicall.mcp.<id>` 管它的服务里没单写的工具；从下一个回合起生效；名字写法不对的照 `<name>`、`<id>` 的报错。开的工具类别不准（写的、`venue` 的），内核照样拒。
- 快照：`ToolEntry` 带上它，`false` 不写；以前的快照（`samples/` 里的）读进来写出去一字不差。出厂五件的 `clicall` 是 `true`，别的出厂工具都是 `false`（列一张表测）；`meme_search` 在 `miyu-memes` 那个提交里测。
- 内核：`clicall` 是 `false` 的读类工具，嵌套调用当场答 `NotAllowed`、什么都不记；是 `true` 的照 M-1 走。要先加载的工具不用先加载也能调。
- 内核那边预审时补的（2026-10-20）：一条快照往返测试钉住「没有 `clicall` 的旧快照读进来写出去字节不变」；随机长跑里一部分工具 `clicall = false`，看守断言调它们的一条 `tool.nested` 都没记。
- `Done.data`：出厂四件各一条，搜到、搜不到都交同一个样子；`tool.result` 里没有它，请求形状探针、`samples/requests` 逐字节不变。
- MCP：有文字又有 `structuredContent` 的，文字照旧进 `tool.result`，`structuredContent` 进 `data`；只有 `structuredContent` 的照旧把它当文字，也进 `data`。
- 执行器（`miyu-session`，替身工具）：从口子交进去一次嵌套调用，
  - 放行的：跑完、结果存了 blob、内核记了 `tool.nested` 落了盘，口子才拿到回答（状态、文字、`data`、有没有被丢掉的图片）。
  - 拒绝的、要问人的、`clicall` 关的、工具不认识的：口子拿到对应的回答，退出码要用的信息齐全。
  - 父调用先交回：在跑的被掐掉，口子拿到「已取消」。
  - 报了 `effects` 的：记一行 `ERROR`，效果没进日志，结果照常交回。
  - 跑的 `Call` 里没有任务、提问、目标端口。
- `cargo xtask check` 全过；三台 CI 过（碰了 MCP 子进程、配置读写）。
- 合进 main 之前，内核那几行（`ToolRule`、检查）交内核那边过。
- 手写变异 10 个左右，全抓住。

### 风险

- 改了五个说明文件，登记簿的指纹要换：门禁会拦，照它重新量、写原因。
- `SpecFile` 是 `deny_unknown_fields`：漏加这一格，写了 `clicall` 的说明文件整件读不进来。出厂五件的测试会拦。
- MCP 原样保留：X-27 补刚把编辑改成「照原来写的存回去」，加一格要跟着进 `written.rs`、`editing.rs`，漏了的话网页编辑一次就把 `clicall = false` 丢了。加一条「编辑别的格，`clicall` 留着」的测试。
- 嵌套调用里的 `Call` 少了几个端口：`Call` 的端口本来都是可选的，没有的工具自己答「这里用不了」；能调的五件本来就不用这几个。记忆、知识库的端口要留着（`memory_search`、`kb_*` 靠它们）。
