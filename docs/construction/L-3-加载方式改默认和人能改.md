## 施工单 L-3：加载方式改默认，人能改

状态：2026-10-20 合了（5dceae09）。同一天项目主人定（改设计 `25-工具加载.md` W9 的已定）。图纸 `kernel/tools.md`、`mcp.md`、`skills.md`。

### 起因

W9（10-15）定的是每件工具登记时自己说要不要先加载，没写的全量，设置页不改加载状态。项目主人 10-20 改了两条：一个 MCP 服务常有十几件工具，MCP 和脚本默认先加载；网页要加技能、脚本、MCP 三页，人能在那里改加载方式，随包来的也能改。

### 做了什么

1. 默认值照来处分：MCP 服务（`[[mcp]]`、个人设置的服务表）、脚本（开头注释）没写的先加载；要全量的写 `need_load = false`、`# Need load: no`，MCP 也收 `"yes"`、`"no"`（大小写不论）。内置工具的说明文件、扩展 `provide` 的没写的照旧全量。
2. 人改的一层：配置清单多两项 `loading.tools.<id>`（工具名）、`loading.mcp.<id>`（服务名），开关，系统配置、个人设置都能写，设置页不画（技能、脚本、MCP 几页另给写法）。一件工具先照它自己那一项，MCP 的工具再照服务那一项，都没写的照来处（`miyu-session/src/loading.rs`）。造工具面时照这一轮的配置算（`Offers`），改了下一个回合生效。
3. 个人设置里的 MCP 服务只改了 `need_load` 的也照「改了」处理、重起重列（原来比较时漏了这一格，X-26 报的）。
4. 技能不要这个开关：工具面上只有 `load_skill` 和目录，本来就是用到才读正文。
5. 出厂的包不带脚本、MCP 服务，出厂的会话照旧没有 `load_tools`，请求样本不变。

### 验收

- `loading::tests`：工具那一项先于服务那一项，都没写的照来处；别的键不算。
- `package::mcp::tests::need_load_takes_yes_and_no_and_defaults_to_on_demand`、`script::tests::need_load_is_yes_or_no`：新的默认、`yes`、`no`。
- `scripts::loading::a_script_loads_on_demand_unless_settings_say_otherwise`：没写的脚本先加载（外壳、多 `load_tools`），`config.set` 写 `loading.tools.weather = false` 以后的会话全量。拿掉覆盖、默认改回全量都红。
- 原来测 MCP、脚本别的事的测试，夹具写明全量（`need_load = false`、`# Need load: no`），照旧测原来的。
- 配置样本多这两项；三种语言的名字、说明、分组。
- 本地门禁八项。
