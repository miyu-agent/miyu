## 施工单 X-32 上：网址的服务接进来

状态：在分支 `step/X-32-远程MCP` 上，等主会话审过合进 main。X-32（`X-32-远程MCP.md`）拆成上、下：上是写法、转接、看管、缓存、列出来的样子；下是 `mcp.set` 收网址的服务、搜索来源改走同一个转接、真服务走一遍。

### 目的

个人设置、清单里写 `url` 的 MCP 服务，核心不起进程，经 Streamable HTTP 连上、列出工具、会话里调得到。令牌、请求头那一种；OAuth 推迟（2026-10-20 项目主人定）。

### 蓝图改哪几节

- `mcp.md`「对外的样子」多「网址的服务」一段：`command`、`url` 写一个，`bearer`、`headers` 跟着 `url`，写法同 `env` 的值。
- `mcp.md`「怎么走」第二条注明网址的没有进程，新加第五条「网址的服务怎么说话」：转接、对方回错、会话过期、不开 GET 长连接、`http://` 只给本机、状态没有进程号；第三条第 1 款缓存照什么认。
- `mcp.md`「在哪」「守着它的」「还没有的」跟着改。
- 作者文档 `mcp`（中英）、协议参考 `packages`（中英）：网址的写法；`mcp.list`、软件包列表带 `url`、没有 `pid`。

和 X-32 施工单原文不一样的几处，都是技术细节：

1. 转接放在 `miyu-mcp`（`src/http.rs`），不放 `miyu-net`：Session-Id、SSE、协议版本头都是 MCP 自己的事。`miyu-mcp` 和 `miyu-http` 同在第 3 层，同层依赖不违反分层。
2. 对方回错的原话不塞进停下的原因（那是一个枚举），写进这个服务现成的日志 `state/logs/mcp-<服务名>.stderr`：软件包列表「停下的带最后几行」照旧能用，界面一个字不改。日志里不写网址：有的服务把密钥放在查询串里。
3. 会话过期不在转接里重连，关掉管道交给看管的那一头重连，从认时代重来；跑起来以后的过期不算失败、不退避（主会话审时提：不然过期几次服务就被停了）。
4. 测试用的假网址服务另写一份（`miyu-mcp` 的 `testkit/http.rs`），没复用 `miyu-http` 的假服务器：那个照剧本回，答不了带客户端编号的请求。

### 不做什么

- OAuth；GET 的长连接、断点续传；旧的 HTTP+SSE 传输。
- `mcp.set` 收 `url`、搜索来源改走转接：X-32 下。现在网址的服务手改个人设置、写进包里。

### 验收

1. `miyu-config`：网址、令牌、请求头读成 `Reach::Url`；和命令混写、写法不对、`Authorization` 这类留给核心的头报 `bad_mcp`。
2. `miyu-mcp`：转接认时代（不认 `server/discover` 的退回握手）、列、调，JSON、SSE 两种回法都通；令牌、请求头每次都带，握手以后带会话编号和版本；401 连不上、日志里一行；会话过期连接断开。
3. 真核心：个人设置写 `url` 的服务连上，`mcp.list` 带 `url`、不带 `pid`，会话里调得到，假服务收到的每个请求都带令牌；`http://` 别的机器的停下 `cannot_start`、日志说清。
4. `cargo xtask check` 全过。

### 风险

- 令牌泄露：`http://` 只给本机地址；令牌只在转接发请求时用，日志不写值、不写网址。
- 状态里进程号改成可空，扩展的状态照旧带 `pid`（`Some`）。
