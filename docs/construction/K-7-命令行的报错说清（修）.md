## 施工单 K-7 修：命令行的报错说清

状态：已完成（2026-10-13 写、做；验收手册待定 1 到 4，项目主人 2026-10-13 照推荐定）。

### 目的

验收手册实测，命令行有四处只说「参数错误。」或者说错话：

1. `miyu kb read notes`、`miyu memory edit m5` 少了参数，印的是 `ask` 的「少了要说的话：miyu ask "…"」。
2. `miyu kb add notes report.docx`：核心只回「参数错误。」，文件还白传了一份。
3. `miyu kb new 日语`：「参数错误。」，不说编号该怎么写。
4. `miyu kb read world cat.pdf --page 99`：「参数错误。」，不说一共几页。

### 蓝图改哪几节

- `cli/main.md`「参数写错时」：嵌着的子命令缺了必写的那一行；「守着它的」。
- `cli/kb.md`：「怎么走」第 3、5 步，退出码，给人看的字，「守着它的」。

### 定了的

1. 嵌着的子命令少了必写的：照这个命令的帮助页（已经分中英文）上这个子命令那一行的写法说，「少了参数：miyu kb read <库> <文档>」，同 `ask` 那一句的样子；帮助页上没有那一行的说到命令为止。测试查着：有必写的子命令，帮助页上都得有它那一行。
2. `kb add`：传以前先看全部文件名，扩展名不在认的几种里的一个都不传，说「只收 .md、.markdown、.txt、.pdf、.html、.htm：<文件名>」，退出码 1。认的几种照核心那一张（`miyu_store::knowledge::EXTENSIONS`），测试查着和核心认的一样。
3. 库的编号（子命令的、`--kb` 的）发以前照核心的规矩看（`miyu_store::layers::valid`），不合的说清写法，退出码 2（参数不对）。
4. `kb read --page`：核心回 `bad_params` 的是页码出界，再读一次第一页看一共几页，说「没有第 9 页，一共 3 页。」；只在出错时多问一次，PDF 不白抽一遍。别的错照原话。

### 不做什么

- 核心、协议不动：命令行在自己这一头说清。网页的头要同样的话，另说。
- 待定 10（整理失败没说为什么）：项目主人这一轮没点。

### 验收

1. 先写测试，没实现时要红：参数写错的那一句（中英文、主程序那一层）；真的核心上 `kb add` 不认的格式一个不传、编号写错退出码 2、页码出界说几页、别的错照原话；扩展名那一张和核心认的一样。
2. 手写变异全被逮住；门禁全过；三台机器的 CI 全绿。

- 守着「少了要说的话」的那条测试只查了最外面一层的子命令，`kb read`、`memory edit` 这种嵌着的没查到：新加的测试照帮助页查到每一个有必写的子命令。
- 页码出界的测试原来用一页的文档，「一共几页」写死成 1 也过：换成两页的。
