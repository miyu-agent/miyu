## 施工单 X-21：软件包自己的几行

状态：待施工。设计 `34-表情包.md` 第五节第 6 条、`26-提示词.md` 第四节第 3 块（项目主人 2026-10-16 定一起做）。

### 起因

设计 26 第四节第 3 块「核心和软件包的几行」里软件包那一半一直没做：一个包要让她一直记着的规矩（表情包的「发完就是说完了」）只能塞进工具说明。先把口子做出来；哪个包真要加字，照「给模型的字非必要不加」实测再加。

### 这一步做什么

1. **清单**：`[prompt] system = "<包文件夹里的相对路径>"`，文件是英文短句，至多 2000 个字符；读不成、超长的照清单写错报（`package invalid`）。
2. **谁的会带**：装着、这个会话的工具面上有它的工具（预设关了它就没有，和 X-16 一个判法）。照包的编号排，接在核心的几行后面，每个包一块，外面套 `<package id="…">`。
3. **钉住**：造会话时钉进快照；装、卸、升级了包、预设开关了它的，下一轮 `refresh_persona` 换一份（工具面本来就这样换）。
4. **登记**：包的字由包自己登记（作者说明加一条）；核心的出厂包要用时进核心的登记簿。

### 验收

- 装一个带 `[prompt]` 的扩展：新会话 system 里有它那块；预设关了它的没有；卸了下一轮没有；两个包照编号排。
- 没有带 `[prompt]` 的包的会话五张脸不变（请求形状探针）。
- 写错的路径、超长的报 `package invalid`。
- 手写变异全抓住。
