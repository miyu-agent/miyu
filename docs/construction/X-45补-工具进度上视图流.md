## 施工单 X-45 补：工具进度上视图流

状态：施工中。经过：项目主人用抖音下载的脚本，卡了 70 秒界面上什么都看不到；X-45 让脚本印 `miyu-progress: ` 开头的行，这些行只推给头、不进结果，但只在事件流的 `tool.progress` 里，照视图流画的头（网页，终端也要换过去）收不到。核心主会话 2026-10-23 和两个头定了形状，网页已照形状做好在等，终端同意，交这一步做。图纸 `view.md`（`tool` 条目）、`protocol.md`（视图流），协议参考中英的视图那一篇。

### 目的

一步工具在跑的时候，视图流的那一条带上它最新的一行进度，头照它写「下好 3/10」。

### 形状（和两个头定死的）

1. **`tool` 条目多一格 `progress`**：字，没有的不写。
2. **只认进度行**：`tool.progress`（瞬时事件 `TransientBody::ToolProgress`）的字里，一整行以 `miyu-progress: ` 开头的（同 X-45：照字面、分大小写、后面带一个空格）。
   - 照调用编号攒半行：一段的末尾没有换行的留着等下一段。只留可能是进度行的：开头和前缀对不上的当场扔掉、丢到换行；留着的最多 1024 个字节，多的不收，内存不涨。
   - 一段里有几行进度的取最后一条。
   - 去掉前缀、去掉首尾空白（`\r\n` 的 `\r` 也去掉），空的不算；最长 200 个字（Unicode 字符），多的截掉。
   - 和这一格现在的值一样的不推；变了才出那一条的 `view.update`。
   - 任何工具的调用都认（`shell` 里她跑的命令印了也算）：投影不看是哪件工具。
3. **结果到了去掉**：那一步的结果到了，更新那一条时这一格去掉，攒着的半行、压着的值一起扔掉。
4. **不进 `view.page`、重新订阅不带**：瞬时的，同压缩的 `written`。翻页、订阅的回应都是照日志投影的，瞬时事件不在里面，本来就没有。
5. **合并**：同一个调用最多每 0.5 秒推一次，最新的那一条最迟 0.5 秒内到（尾巴不丢）。
   - 投影记每个调用上次推的时刻（照事件的 `at`）、压着的值。离上次不到 0.5 秒的压着；`Projector::due()` 交回最早到点的时刻，`Projector::tick(现在)` 把到点的推出去。
   - 端点视图流的转发循环（`subscriptions/view.rs` 的 `relay`）多一个分支：有压着的就等到最早那一刻，到点调 `tick`，写出来。没有压着的不等、不醒。
6. **不做**：后台任务那一条、嵌套调用不带进度；事件流的 `tool.progress` 推送照留（终端换视图流以前还要用）。

### 代码放哪

- `miyu-view`：`entry.rs` 的 `Tool` 多一格；新文件 `projector/progress.rs`（攒半行、取值、限速、`due`、`tick`）；`projector/tools.rs` 结果到了去掉；`projector.rs` 接上瞬时事件。`projector.rs` 496 行，先把 `Running`、`Block`、`Job` 三个小类型挪进 `projector/parts.rs`。
- `miyu-endpoint`：`subscriptions/view.rs` 的 `relay` 多一个到点的分支。
- `miyu-kernel` 的测具：`Stage::tool_progress` 送一段进度。
