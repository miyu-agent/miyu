## 施工单 5-15：命令也能「此目录不再询问」，私密目录人能加，数据根落在能写的里面照样藏

状态：上已合（2026-10-20，b1ded96e）；下合了（2026-10-21，f376259d）。2026-10-20 开工时拆成两半：私密目录可配要动设置页、协议给出厂的列表、权限策略和沙盒照每一轮的配置换，单独一半。2026-10-20 项目主人定；图纸 `docs/designs/11-权限与沙盒.md` 第二节「问人时的选项」、第四节「藏起来的落在能写的范围里」、A7 的 2026-10-20 补、A14。

### 做什么（上：第 2、4、5 条；下：第 1、3 条）

1. 「本会话都允许」改叫「此目录不再询问」：协议上 `decision` 照旧是 `session`，两个头换字；「这个工作区以后都允许」不做。
2. 命令被沙盒挡下、她带「这一次在沙盒外跑」重跑问人时，多给「此目录不再询问」：选了的，这一次照「允许这一次」在沙盒外跑，同时把工作目录加进这个会话能写的范围（记成事实，载入照旧），下一条起在沙盒里照新范围跑。家目录本身也照加。
3. 私密目录可配（设置页「隐私与安全」）：两项，「加了的」一串路径、「去掉的出厂项」一串；出厂的列表交给头画（带出厂标记），能删、能恢复默认。家目录本身和它的上级不收、说清原因（2026-10-20 项目主人定，措辞别太随意也别太像机器）。`permission.level` 挪到这一页、完全放开的说明加「不启用沙盒」（中英日三份）。合完告诉两个头画这一页。
4. Linux 助手：藏起来的落在能写的里面不再拒绝，照目录一级级绕开（同读那边的 `reads.rs`）：路上那几层不放增删改名，里面已有的文件单个放写，别的整个放写，链接跳过。执行器只把数据根放进这种情况：落在能写的里面的私密目录照 5-13 不写进 `hidden`（装了 bubblewrap 的在 5-16 写）。
5. 量：放开 `~` 时每条命令多多少（本机约 0.9 ms 估），记进 `sandbox/linux.md`。

### 验收

- 放开 `~` 以后：`~/Documents` 里随便写；`echo >> ~/.bashrc` 成；`mkdir ~/x`、`rm ~/a`、`sed -i ~/.bashrc` 被挡；数据根读写都不行、`mv ~/.miyu ~/x` 被挡；文件工具在 `~` 里建删不问。
- 原来 shellhook 撞见的 `cannot hide … inside a writable path` 不再出现。
- 私密目录设置：加了的命令读不到、文件工具问人；落在能写的范围里的命令读得到（只有 Landlock）。
- 变异约 15 处。

### 上：做了什么

1. 内核的 `RunTool` 多 `grants`（本会话放行过的规则，原样交）；执行器写沙盒的规格时，规则里放行写的目录也能写（`sandbox.rs` 的 `granted_writes`）。
2. 命令越过沙盒问人时提的规则是 `{"tool", "write": [工作目录的真实位置]}`（`guard/asking.rs` 的 `this_dir`），协议上就是带了规则的确认：头照它给「此目录不再询问」（`decision: "session"`）。越过沙盒的照样每次问。
3. 私密目录里的那一条只认放行范围本身也在私密目录里的规则：放行了家目录，文件工具写 `~/.ssh` 照旧问。
4. Linux 助手：藏起来的落在能写的里面不再拒绝，写也一级级绕开（`reads.rs` 的 `around`）。正式装机放开 `~` 每条命令约 1.3 ms（本机量）。

### 上：验收

- `crates/miyu-sandbox/tests/linux.rs` 的 `a_hidden_path_inside_a_writable_one_is_walked_around`（真 Landlock）：已有的文件改得了，旁边的目录写得了；那一层新建、删除、把藏起来的挪走都被挡；藏起来的读写都不行。`reads/tests.rs` 的 `a_writable_path_is_walked_around_what_it_hides`。
- `crates/miyu-session/tests/outside_sandbox.rs`：提的规则；选了此目录不再询问以后，命令照旧在沙盒里、放行的家目录能写，越过沙盒的照样问；放行了家目录的，文件工具写家目录别处不问、写私密目录照问。
- 变异 3 处（私密目录不挡、不提规则、沙盒不放放行的目录）各让测试红。

### 下：做了什么

1. 出厂清单挪进 `miyu-fs` 的 `private.rs`，写成 `~/…`（`SHIPPED_PRIVATE`，照系统不同）：同一份既拼路径，也是设置页能去掉的那几个。`private_dirs_with(家目录, 加的, 去掉的)`：去掉的照写法比，加的 `~/…` 照家目录拼、绝对路径照原样，别的写法、家目录和它的上级（`too_broad`）不算。
2. 两项配置 `sandbox.private.add`（文字的列表）、`sandbox.private.remove`（选项的列表，选项就是出厂清单），系统、个人两层，下一轮生效，`privacy` 页的 `private` 组（`miyu-tool` 的 `private.rs`；`settings!` 的选项只收写死的字，两项手写登记）。选项照原样给人看，资源里不写名字（核心的设置测试照这个放过）。
3. 照这一轮的配置换：回合开始拼一次（`Guard::private_of`），权限策略（`Guard::set_private`）、沙盒（`Sandbox::set_private`）都换上；往下走目录的工具照调用带的这一轮的配置拼。头浏览文件、读附件只看数据根，不受影响。
4. `config.set` 改几项时 `sandbox.private.add` 多查一道（`config/private.rs`）：写法不对 `bad_format`，家目录本身或它的上级 `private_too_broad`（新的问题码，`got` 是那一个，中英日三句说清原因）。整份换、手改文件写了的不拒，运行时照不写算。
5. `permission.level` 挪到 `privacy` 页的 `permission` 组；完全放开的选项名加「不启用沙盒」（中英日）。新页「隐私与安全」、两个组的名字三份。`guard.rs` 到了 500 行，级别的判法挪进 `guard/levels.rs`。

### 下补（2026-10-21，网页实测报的）

1. 只写 `~` 也认成家目录（`miyu_fs::written`），同 `~/` 拒 `private_too_broad`；原来走成写法不对。
2. 写法不对的单给一句（问题 `Code::PrivatePath`，协议上照旧 `bad_format`）：「relative/dir 写法不对：要写成 ~/… 或绝对路径」，中英日三份；原来套的是通用的类型提示，读不通、没说该怎么写。
3. 「去掉的出厂项」在清单里登记成文字的列表（原来是选项的列表）：选项照系统不同，写进生成的 Schema、参考文件，macOS、Windows 上和样本对不上（CI run 39485465283）。出厂清单改由端点给：`config.schema` 交成 `options`（`config/private.rs` 的 `options`），`config.set` 写了别的拒，问题 `Code::PrivateNotShipped`，协议上照旧 `not_an_option`，单给一句。
4. 验收：`miyu-fs`、端点 `config/private` 的单元测试多 `~`、多只收出厂的；`tests/config_set_private.rs` 多写法不对的那一条（`bad_format`、话里有写错的那个和 `~/`）。

### 下修（2026-10-22，clicall 报的）

私密目录里加了一个包住数据根的上级（比如 `~/.cache`），有 bubblewrap 的机器上所有沙盒命令都起不来，退出 125 前报 `bwrap: Can't create file …/.cache/miyu`：藏起来的一条条盖 tmpfs，先盖了里面的数据根、再盖外层，最后给里面那一条设只读时，它的挂载点已经不在了。

1. 造规格时藏起来的彼此不重叠（`miyu-session` 的 `sandbox.rs` 的 `outermost`）：落在已有的一条里面的（一样的也算）不加，已有的落在它里面的去掉，只留最外面那一层。各平台拿到的都不重叠，助手不动：盖了外层也就藏了里面。
2. 验收：`sandbox/tests.rs` 的 `a_hidden_dir_inside_another_is_left_to_the_outer_one`（数据根、`.config/gh` 让给外层，重复的只写一次，有挂载、没挂载一样）；Linux 上有能用的 bubblewrap 的，真经助手跑一次 `a_command_runs_when_a_private_dir_holds_the_data_root`（命令起得来，数据根里的读不到；修以前报的就是上面那一句）。变异 3 个全抓住（不看已有的外层、不去里面的、照旧只比一样的）。`cargo xtask check` 八项；先推 step 分支过三台。
