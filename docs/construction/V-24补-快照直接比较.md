## 施工单 V-24补：快照直接比较

状态：已完成。2026-10-30 这一轮性能优化排在 V-24 里的第三件；核心主会话等 AE-1 进了 main（16fbc45b1）以后同意开工。

### 目的

回合开始重拼快照时，判「和原来一样」直接比两份快照，不再各写一遍 JSON、各算一遍 SHA-256；换上新快照时存 blob 拿到的就是它的哈希，不再写一遍、算一遍。

### 查下来的

- `actor/persona.rs` 重拼快照以后 `new.hash() == old.hash()`：两份快照（system 加工具面，几十到几百 KB）各序列化一遍、各算一遍哈希，只为比一不一样。
- 换上新快照时 `blobs.put(&new.to_bytes())` 里已经算了内容哈希，接着 `new.hash()` 又序列化、又算一遍。
- `Snapshot` 本来就 `derive(PartialEq, Eq)`；没有序列化时跳过的字段、没有浮点、没有 JSON 值字段，serde_json 也没开保序：结构一样就是字节一样。

### 蓝图改哪几节

- 不改：蓝图写的是「拼出来和原来一样的什么都不记」（`providers.md`、`personas.md` 换人格那一段），没写怎么比。

### 不做什么

- 不动换快照的判法：一样的、程序升级而人格预设工具面都没变的，照旧什么都不记；步数照预设重算的（AE-1 的 `steps::restepped`）照样在比的里面。

### 验收

1. `snapshot/tests.rs`：直接比和比字节（哈希）说法一样：同样来源拼的、读回来的相等；改了字、步数上限、不是人开的回合的步数上限、续轮次数、有没有人看着、人格的，两样都不等。
2. 原有的快照、换人格、换预设、步数测试照旧全过。
3. `cargo xtask check` 全过、Windows 版 clippy。

### 风险

- 以后给 `Snapshot` 加了序列化时跳过的字段、浮点或 JSON 值字段，直接比和比字节可能说法不一：第 1 条测试在，加的人改了它会红。
