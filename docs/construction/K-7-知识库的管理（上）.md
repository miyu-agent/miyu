## 施工单 K-7 上：知识库的管理（协议）

状态：已完成（2026-10-13 写、合；同一天项目主人定：人能删整个库进系统回收站、挂进来的只拿掉登记；加文档照附件上传；建库、改名字说明也放进 K-7。项目主人 2026-10-12 定 K-7 先于 K-6）。

### 目的

现在建库、挂目录、加文档都得手动建目录、写 `kb.toml`、往数据根里拷文件，两个头做不了知识库页。这一步给人经协议加上管理的几个方法：建库、改名字和说明、删库、挂目录、加文档、删文档、重建索引。命令行 `miyu kb` 是 K-7 下。

  - 「怎么走」：多第八条「人管理」。

- `docs/construction/README.md` 的 K 线表：K-7 拆成上、下两行。

### 定了的

项目主人定的（2026-10-13）：

1. 人能删整个库：
   - 自己的库：整个目录挪进系统回收站，索引删掉。
   - 挂进来的库：只拿掉登记（库目录和索引），挂的那个目录一个字都不动。库目录照样挪进回收站（里面只有 `kb.toml`），两种一个做法。
   - 她照旧删不了整个库（19 N14）。
2. 加文档照附件上传：`kb.add` 收已经上传好的 blob（`blob.put`、分块上传，和聊天发附件同一套）。一份最多 20 MiB（附件的上限），更大的请挂目录。
3. 建库、改名字和说明也在这一步：`kb.create`、`kb.update`。

技术细节照推荐定：

4. 七个方法，都是命令，照管理员的账号（同 `kb.list`）：

   | 方法 | 参数 | 回应 |
   |---|---|---|
   | `kb.create` | `kb`；`name`、`description`（可以不写） | 一个库（同 `kb.list` 的一项） |
   | `kb.update` | `kb`；`name`、`description`（至少写一个，空字符串是拿掉） | 一个库 |
   | `kb.delete` | `kb` | `{"trash"}`：整个库目录在回收站里的位置 |
   | `kb.mount` | `kb`、`folder`（绝对路径或 `~/` 开头）；`name`、`description` | 一个库（照挂的目录补完的） |
   | `kb.add` | `kb`、`path`（库里的相对路径）、`blob`；`replace`（已经有了的换掉，不写是 `false`） | `{}` |
   | `kb.remove` | `kb`、`path` | `{"trash"}`：回收站里的位置 |
   | `kb.reindex` | `kb` | 一个库（重建完的） |

5. 拒绝：
   - 编号、路径不合写法、参数写错：`bad_params`。
   - 没有这个库：`unknown_kb`；没有这个文档：`unknown_document`；blob 不在：`unknown_attachment`（同 `session.send`）。
   - 新的：
     - `kb_exists`：要建的、要挂的编号已经有了。
     - `document_exists`：加的文档已经有了，没写 `replace`。
     - `kb_read_only`：往挂进来的库里加、删。
     - `folder_unavailable`：要挂的目录不在、读不了、不是绝对路径（`data.message` 是英文的一句为什么）。
     - `trash_failed`：挪不进回收站（`data.message`）。
6. 写都照 K-3 的那一套：
   - `kb.toml` 照 TOML 写，改名字、说明时留着 `mount`。
   - 文档照 `miyu_fs::replace`，先写临时文件再改名；删的照 `miyu_fs::trash`。
   - 人加的文档什么格式都行（PDF、网页也行），她写的照旧只有文字的。
7. 删库、重建前，先拿那个库的补的锁，再关上它的索引连接、删掉索引文件。
   - Windows 上开着的 SQLite 文件删不掉，会话在后台补向量拿着的那一份照「库用不了的不写」不碍事。
   - 重建是删掉以后照文件补一遍，向量下一次搜完再补。
8. 不认请求编号去重：建、挂的再发一次回 `kb_exists`，删的再发一次回 `unknown_kb`，加的再发一次回 `document_exists`（写了 `replace` 的照样换，结果一样）。

### 不做什么

- 命令行 `miyu kb`（K-7 下）。
- 推送知识库变了的通知：头改完自己再 `kb.list`。量出来要了再加。
- 成员只能挂自己工作区里的（19 第二节）：协议只照管理员的账号，多用户时再判。
- 留痕（账号日志）：文件就是真相，目录里看得到。

### 验收

1. 先写测试，没实现时要红：
   - 知识库那一层：建、改、删（自己的进回收站、挂进来的不碰目录）、挂、加（PDF 也行、已经有的拒、`replace` 换）、删文档、重建（数对上、向量没了）。
   - 真核心：七个方法的回应一格一格对，各种拒绝。
2. 手写变异全被逮住；门禁全过；三台机器的 CI 全绿。

### 做了以后

- `kb.toml` 照配置的那一套只改那一格（`miyu_config::edit`）：不用另加依赖，注释、`mount` 照留。
- `blob` 照 `session.send` 的附件读（`attach::read_blob` 改成 crate 里能用）。
- 手写变异 15 个全被逮住。头一回活着三个，都补了测试：
  - 「空字符串照写成空的」：列出来的说明一样是空的，补了查文件里没这一格。
  - 「删库不清登记」：补了同一个编号再建、再搜。
  - 「挪不进回收站当内部出错」：真核心上挪得进，碰不到这一路，补了照每一种错对拒绝的单元测试。

### 风险

- 删整个库进回收站：有的机器上临时目录那块盘没有回收站，测试照实报。
- 加的文档最多 20 MiB：更大的 PDF 只能挂目录（项目主人知道）。
