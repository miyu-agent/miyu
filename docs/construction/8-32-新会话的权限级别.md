## 施工单 8-32：新会话的权限级别

状态：已合（2026-10-13，4527293f，CI run 2019）。项目主人验收两个头的第一次引导时提的：旧版终端的引导里有「沙盒开不开」那一步，重制版没有。2026-10-13 定：引导里加这一步，默认开。图纸 `docs/blueprint/config.md`「M8 的配置项」。

### 为什么

新会话一律从「工作区」开局（执行命令在沙盒里跑），想一直完全放开的人只能每个会话手动切。引导里的「沙盒」一步要有地方写：核心没有这一项配置。

### 做了什么

1. 配置项 `permission.level`：`workspace`（默认）或 `full`，只写在系统配置、个人设置里，新会话生效。项目配置要收紧的照旧用 `permission.start_read_only`，这一项不让项目配置写，配置的收紧规则不用加一种。
2. 造会话时本机开的照它定开局的级别；场所会话照旧从工作区开局（外部身份另有限制，`session/guard.md` 第四条末）。会话里人切级别照旧。
3. 三种语言的名字、说明、两个选项；配置的样本（两份 Schema、参考文件）照生成的重写，蓝图里抄的那几段跟着改。

### 验收

- 测试：本机的新会话默认工作区、个人设置写了 `full` 的从完全放开开局；判级别的那一步认不出的、场所会话都从工作区开局；`config.schema` 里这一项是下拉、默认 `workspace`；`miyu config get` 列出它。
- 变异 4 处全抓住：不看场所、认不出的当放开、造会话时不用它、开局只读丢了。

### 留下的
