## 施工单 X-15 中：界面块的内容和推送

状态：已合（2026-10-15，7f52b649，CI run 38688243204）。设计 `33-界面扩展.md`，图纸 `widgets.md`「内容」「程序发给核心」「核心告诉程序」「头」。

### 做了什么

1. 内容的查法（`miyu-policy/src/widget.rs`，纯逻辑）：六种段、各自的格和上限，`call`、`open`、`copy` 三种动作，进度条的 `mark`，换掉的标题；字里不许有控制字符、改写方向的字符；语言表照连接的语言挑。底栏那一段按显示宽度算（`unicode-width` 进了纯逻辑层的白名单，设计 01）。
2. 程序推内容：`widget.set`、`widget.clear`，只在核心拉起的连接上；块不在清单里 `unknown_widget`，写法不对 `bad_widget_content`（`data.path`、`data.problem`），原来的不动；跟着会话的、没人在看的会话不留（`kept: false`）。
3. 谁在看：头订阅 `{"stream": "widgets", "session"?, "showing", "page"?}` 时记成在看，从没人看到有人看推给程序 `widget.watch`，最后一个人走了推 `widget.unwatch`；握了手先把这一刻在看的补一遍；掉了队照这一刻重对。
4. 推给头：回应列出装着、开着的扩展声明的块，屏上的带内容；之后 `widget.changed`（同一块最快每 250 毫秒，中间的只留最新的），包装卸、开关、程序起停整块推一遍，关掉、卸掉的推 `null`。程序停了它的内容全清。

- 内容的查法 8 条、登记表 3 条、真核心 7 条（看了才叫程序推、不看了扔掉跟着会话的、连推十次只到头两三次且最后一份不丢、写法不对的拒、关掉推 `null`、订阅的参数、程序停了清空且新程序握了手又被告诉一遍）。
