### 这一步做什么

1. `miyu-source` 的 `collect::rules`：读 `miyu-agent/packages` 仓库里的四份规则——`sources.toml`（`[[source]] kind = "official"`；社区的 `kind = "topic"` 读得懂、现在不收，记一笔）、`official.toml`（`repos`，`owner/repo`）、`names.toml`（`[names]` 编号到来源仓库）、`blocked.toml`（`[[blocked]]`，`id` 或 `origin` 加 `reason`）。没有的文件当空的，写错的说是哪个文件。
2. `miyu-source` 的 `collect`：照来源列仓库，读每个仓库最新的 Release，下它的 `.miyu`，算哈希、解开、照 Miyu 自己那一套读清单，写成索引的一条（名字、说明、带了哪几样、能力、依赖、文件）。
   - 一个 Release 里只能是同一个包的同一个版本；文件名要和清单对得上（`<编号>-<版本>[-<系统>].miyu`）。不对的整个仓库这一次不收。
   - 编号先到先得：没占的占上、写回 `names.toml`；被别的仓库占了的不收。拉黑的不收，`blocked` 随索引下发。来源仓库在 `official.toml` 里的标 `official`。
   - 网络走 `Fetch` 接口：小程序接 HTTP，测试接内存。
3. `miyu-index build <规则目录> <输出目录>`：收一趟，写 `index.json`（没签名，之后 `sign`），一行一件事印出收了什么、跳过了什么（给 Actions 的摘要）。GitHub 令牌照 `GITHUB_TOKEN`，只发给 API 的 `/repos/` 下面；API 地址 `MIYU_INDEX_API` 能换。

### 定了的（主会话）

- 一个编号只列最新的那一版（设计 37 第三节第 1 条）：只读最新的 Release。
- 拉黑的照样占住编号：拉黑的仓库换个编号再发也收不进来，编号也不会放给别人。
- `official` 现在只会是 `true`（只收官方来源），留着这一格给社区来源；变异「写死 `true`」因此活着，是等价的。
