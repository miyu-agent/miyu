## 施工单 S-7 上：核心的测试不再用 `miyu-embed`

状态：在做（2026-10-19 主会话；项目主人 2026-10-17 定 `miyu-embed` 拆成自己的仓库，10-19 定先 S-7 再 G-8；记忆的会话 10-19 回话：混合规则重调全合了，`meaning.rs` 随时能动）。

### 起因

拆出去以后核心仓库里没有 `miyu-embed`，可核心的测试（`miyu-session` 的 `embed`、`embed_replace`、`memory_recall`、`memory_search_floor`、`memory_vectors`，`miyu-endpoint` 的 `memory_meaning`）都拉起 cargo 编在旁边的真小程序和手造的小模型；量尺（`kb_eval`、`memory_eval`、`memory_vectors` 的真模型那一条）照仓库里的出厂清单拼包目录。

### 这一步做什么

1. **测试用的小程序 `miyu-test-embed`**（`miyu-session` 的 `src/bin/`，`test = false`，不随发行带出去）：说和 `miyu-embed` 一样的协议，只认手造的小模型（照模型文件的 SHA-256 认，别的照「载不了」说 `cannot load …`、退出码 1），小模型照手算：每个位置是词的嵌入加第 0 类的嵌入，第一格再加整句的和，归一化。分词照 `miyu-embed` 的 WordPiece 抄一份，Unicode 的类别不查表、照常见的几段认（测试里的句子切得一样就够）。
2. **小模型的文件拷进核心**：`crates/miyu-session/tests/fixtures/embed-tiny/`（模型、词表、清单、`expected.json`），造它的 `make.py` 留在 `miyu-embed`。
3. **测试照它**：`tests/support/package.rs`、`src/embed/tests.rs`、`miyu-endpoint` 的 `memory_meaning.rs` 换成新位置和 `miyu-test-embed`。
4. **量尺照一份真的包**：`MIYU_EMBED_MODEL_DIR`（Release 的文件，清单照仓库里的）换成 `MIYU_EMBED_PACKAGE`：装好的、或者解开的 `embed` 包，里面有 `model.toml`、它写的文件和 `bin/miyu-embed`；模型编号照包里的清单。

### 定了的（主会话）

- 核心不留真的 `miyu-embed`：编它要联网下 ONNX Runtime，拆仓库就是为了核心不带它。测试守的是核心这一头（核对、拉起、排队、闲了退出、起不来三次不再拉起、向量进库），换成手算的小程序守的一样；模型算得对不对是 `miyu-embed` 自己仓库的测试守。
- 手算的和 ONNX Runtime 算的照 `expected.json` 比：六组编号每格差不过 1e-6（本机手试过）。

### 留给 S-7 下

建 `miyu-agent/miyu-embed` 仓库（带着历史）、删掉核心的 `crates/miyu-embed` 和 `miyu-core/tests/embed_package.rs`、模型文件的 Release 搬过去、打包模板发进软件源。

### 验收

- `miyu-session` 的 `tests/test_embed.rs`：小程序照 `expected.json` 的六句每格差不过 1e-6（含截断、空句、`[UNK]`），`unaffable` 切成带 `##` 的三段，读不懂的回错。变异 10 处全杀。
- `miyu-session`、`miyu-endpoint` 原来的测试照旧过，测试只认 `miyu-test-embed`。
- 设了 `MIYU_EMBED_PACKAGE` 的量尺照真的 granite 包跑得通（本机 `measure_meaning_with_the_real_model`：两路 8/8）。
- `cargo xtask check` 八项；三台 CI。
