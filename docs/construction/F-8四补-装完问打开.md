## 施工单 F-8 四补：装完问「打开？」

状态：已合（2026-10-13，079e01f3，CI run 1996）。项目主人 2026-10-11 照推荐定（作者说明第九节第 1 条）；图纸 `docs/blueprint/cli/pkg.md`「怎么走」第 2½ 步。

### 为什么

命令行装好一个扩展以后，还得去终端界面或网页的「软件包」页里打开、批能力，命令行这一侧做不完。

### 做了什么

1. `miyu pkg install` 一律先看一眼（原来只有没写 `--yes` 的看）：要的能力在看一眼的回应里，打开时一并批。
2. 装好以后，装好的那一项有开关、程序在，并且关着的；或者开着却没在跑、看一眼时又列了要的能力的（清单写了一起来就拉起，能力还没批）：问「现在打开？[Y/n]」。答是发 `package.enable`，`approve` 是那几个能力，印「打开了：<编号>」；答不、标准输入关着的不打开，印「没有打开：以后在「软件包」页里打开」，照样算装好了（退出码 0）。`--yes` 当是。
3. 没有开关的（界面、小程序、只带技能脚本的）、程序不在的、已经在跑的不问。打开被拒的照原来的说法，退出码 1。
4. 作者说明第七节第 2 条照它改了，第九节第 1 条记成做了。

### 验收

- 单元：问不问（关着的问；开着没在跑、要能力的问；不要能力的停下了不问；在跑、在起、没有开关、程序不在的不问）；能力的编号从看一眼的回应里取；空的、`y`、`yes` 算是，别的、读不到的算不，`--yes` 不问。
- 真核心：带 MCP 服务的 `bundle` 答不、没得答的不打开、照样装好；答是的打开；已经开着的再装不问；从没装过的 `--yes` 装完直接打开；程序不在的扩展 `--yes` 装完不问也不开。Unix 上要能力的扩展（程序是一段脚本）：先列「需要：」，答是一并批、打得开。

- 变异 11 处全抓住：不取能力、关着的不问、程序不在的也问、在跑的也问、没开关的也问、`--yes` 不当是、空的不算是、不批能力、不打开不说、打开了不说、不打开。

### 留下的

- 卸掉一个打开过的包再装回来，开关还记着「开」（`system/extensions.json`），装上就起了，不问。卸载清干净（设计 31 第八节）要不要连开关、批过的能力一起清，另查。
