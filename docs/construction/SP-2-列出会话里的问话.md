## 施工单 SP-2：列出会话里的问话

状态：已完成（2026-11-03）。网页 W-1069 要的，core1 转主人的需求；方法的形状照派活时定的。编号原派 SP-1，和已有的「每一轮的出字速度」撞了，改成 SP-2。

### 为什么

网页右边的「问话跳转」要把一个会话里主人问过的话都列出来，没读进来的点了也能先往前读到那一页再跳。原来只有 `view.page` 按页往前翻：主人十万条的大会话，为了列问话得一页页翻到头，而 `view.page` 每翻一页都把整份日志读一遍。

### 照的图纸

- `docs/blueprint/protocol.md`「`view.page`」（只读日志、不载入会话、报错）、「`session.list`」（`preview` 的取法）。
- `docs/blueprint/venues.md`「判官看的群聊记录」第 3 条（施工 V-39 上、上补：边读边过有效历史、只解要的种类）。
- `docs/blueprint/kernel/history.md`（有效历史：撤销、恢复、撤回、留着一切的那一份）。

### 做什么

1. **协议** `session.prompts {session}` → `{prompts: [{seq, turn, at, text}]}`，照先后（`protocol.md`「`session.prompts`」第 1～7 条）：
   - 只列有效历史里主人本人说的 `message.user`：`by` 是主人（`person`），带不带 `via` 都算：桥代主人在私聊里转进来的也列（主人在 QQ 私聊里说的话都带 `via`）。子会话和父会话发来的、平台上别的人说的（`external`，群里的主人也是）、模块注入的（长期目标的续轮）、别的 harness 的、定时的、内核的都不列。
   - 有效历史照留着一切的那一份（`History::whole`，同判官）：撤销掉的不列，恢复的放回，重做（编辑上一句）照最后那一版，撤回的排着的话不列，压缩换出去的照样列。
   - `turn`：回合里排着的是那一轮；闲着时说的是它开的那一轮（有效历史里 `trigger` 是它的 `turn.started`）；都没有的不写。`at` 写法同事件。
   - `text` 和会话表的 `preview` 同一处代码：`miyu-store` 的 `index/row.rs` 原来私有的取法挪成公开的 `said(message, most)`，`Row::see` 照它取 50 个字，问话照它取 100 个字。
   - 分叉出来的会话只列它自己日志里的；底子里的话在父会话的日志里（`view.page` 在这个会话上也翻不到），父会话照列。
   - 权限、报错同 `view.page`：扩展要 `events.read`；编号不合写法、多写了格 `bad_params`，没有这个会话 `session_not_found`，日志读不了 `session_broken`（记 `WARN log not read`）。
2. **读法**（`crates/miyu-endpoint/src/asked.rs`）：只读日志、不载入、不落缓存、不常驻。照 `read_range_only` 只全解 `message.user`（有效历史照种类认的那几种它自己也全解，回复、请求只解 `seen` 那几格，别的种类只认外壳），一遍读下来，事件照先后交给真的 `History::whole`，谁都碰不到的那一截收下问话就放；撤销、撤回比放掉的还早的照骨架算的下界再读一遍，骨架认不得的整份读到头一遍读到的那一条。
3. **共用**：判官的「边读边过有效历史」（V-39 上的 `venues/records/pass.rs` 里放的那一套、`bones.rs`）挪到 `crates/miyu-endpoint/src/sweep.rs`、`sweep/bones.rs`，泛成 `Sweep<S: Settle>`：怎么放、骨架、再读一遍的计划都在那里，判官只留它收下的那几样（`Kept`），问话列表收它的（`Asked`）。判官的逻辑一行没改，只是挪了地方、换了字段的路径。
4. 文档：`protocol.md`（方法表、一节、文件表、`bad_params` 那一行），`docs/reference/sessions.md`、`sessions.en.md`（方法表、谁能调、一节），`methods-v1.txt` 登记，`venues.md` 判官那一行的文件。

### 不做什么

- 不改 `view.page`、不加索引、不落缓存文件、不常驻额外状态；不载入会话。
- 不碰 im、miyu-web；不碰 `miyu-store` 的 `root.rs`、`root/places.rs`、`config_file.rs`、`cache.rs`；不碰 V-39 下在改的 miyu-session open/fork、`memory/lane.rs`、`memory/turns.rs`、`forking.rs`。
- 不给模型看到新字（没有 resources/ 里的新字，不用台账）。

### 和派活时定的不一样的

- 编号 SP-1 → SP-2（撞号，协调方 11-03 同意）。
- 「只列 person」落成 `By::Person`，不论 `via`。头一版照「场所桥进来的不列」把带 `via` 的也排除了，复核时协调方指出「场所桥进来的」指群里别人、平台上别的人，不是主人本人：主人在 QQ 私聊里说的话全带 `via`，排除了那种会话的问话列表就是空的。改成都列（2026-11-03）。
- `turn` 闲着时说的照它开的那一轮写（事件自己的 `turn` 是空的）；一轮都没开的（被撤回、排着还没开）不写这一格。

### 验收

1. **先红后绿**：`crates/miyu-endpoint/tests/session_prompts.rs`（协议层，真核心）先写，没接方法时 6 个全红（`unknown_method`；扩展那一条是表里没有、当只给人的 `local_only`），接上以后全绿：
   - 普通问话（多行的取第一个不空的行）、斜杠命令模板（照人敲的 `/review src/a.rs`）、150 个字的截到 100 个；还没人说过话的是空的；`seq`、`at` 对得上日志，闲着时说的 `turn` 是它开的那一轮。
   - 撤销（最后一句不列）、恢复（放回）、重做带新字（只列新的那一版）。
   - 分叉：支线只列支线自己的，主线照列主线的。
   - 手写的日志：主人闲着时说的、回合里排着的、桥代主人在私聊里转进来的（带 `via`）列；平台上别的人、子会话、模块注入的、别的 harness、定时的、内核的不列，子会话回报不是人话；末尾半行不算。
   - 中间坏一行 `session_broken`、没有这个会话 `session_not_found`、编号不合写法、没写、多写了格 `bad_params`，前三种和 `view.page` 回的错一字不差。
   - 核心拉起的扩展没批 `events.read`：`session.prompts`、`view.page` 一样回 `needs_approval`、缺 `events.read`。另 `connection/tests.rs` 的表里加了这一条。
   每一个回应都和准绳比：整份 `read_events` → `History::whole` → 有效历史里主人本人的 `message.user` → `miyu_store::index::said` 取字（准绳抄在测试里）。
2. **新旧对照**（`asked/tests.rs`、`asked/tests/script.rs`）：照种子造 3,000 份本机会话（10～330 步：闲着说、排着说、命令模板、多行、长的、只有图的，1/6 是桥代主人在私聊里转进来的（带 `via`），六种别的来路，回复、请求、暂停着的请求、工具结果、注入的事实、不认识的种类，三种回报和照它们接着开的一轮，撤销最近一轮 / 最近几轮 / 很早的一轮、恢复、重做、撤回、压缩（撤销跨压缩），1/8 是分叉出来的、从 `upto + 1` 数起，偶尔撤一轮没有的、触发写成还没有的序号），写成 1～4 段、1/4 末尾带半行，放法多半调小（`flush_at` 1～24、`keep` 1～10，1/7 照出厂的），和准绳逐条比（序号、回合、时刻、字）。覆盖：头一遍放早了再读一遍的 1,981 份（每一份照下界再读的那一遍都收齐、不靠整份读兜底）、骨架认不得整份读的 11 份、有效历史和「全列出来」不一样的 2,860 份，一共列了 196,888 句。坏行（中间、最后一行、序号断、人话正文不合写法）报的错和整份读一样，只有半行的是空的、没有目录的是没有，同整份读；整份读的退路只读到头一遍读到的那一条。
3. **手写变异 10 个都逮住**：桥代主人在私聊里转进来的不列；撤销还能恢复时也放；放早了不再读一遍；认不得的不整份读；字截到 50 个；闲着时说的不记它开的那一轮；放的时候多放一条还碰得到的；再读一遍不照下界（原来被整份读兜住、逮不住，加了「再读的那一遍要收齐」才逮住）；命令模板不照人敲的那一行；整份读的退路不截到头一遍读到的。
4. 判官的对照测试（`venues/records/tests/`）照旧全过：挪了地方的那一套一行逻辑没改。
5. `cargo xtask check`（.91 门禁 11 项），Windows 版 clippy，三平台 CI。

### 实测

2026-11-03，本机（Ryzen 9 7940H），这一步的 release 核心，断网命名空间（`unshare -rn`），核心绑 12–15 号核、问的一头绑 2–7 号核。数据根是这一步的核心在空的数据根上（FH-3 以后的布局）照假模型造的：一个本机会话问了 9,200 句（每一轮假模型调两次 `shell` 再答），隔几轮撤销又恢复、撤销不恢复、重做、手动压缩（撤销 269 次、恢复 174 次、重做 151 次、压缩 23 次），日志 103,936 条、56.9 MB、一段。量法同 V-39 上补：每一次照原样拷一份新的数据根，起核心，等 3 秒再问；堆是 heaptrack `--record-only`（等它收完），匿名内存每 2 ms 读一次 `RssAnon`，指令只量那一下的用户态（`perf stat -e instructions:u`）；堆 3 次、匿名内存和指令 5 次、耗时 10 次，都是中位。「整段读一遍」是现在网页列问话唯一的法子：`view.page`（`turns: 50`，原始事件）从最新一页照 `first` 往前翻到头，收下页里的 `message.user`。

| | `view.page` 翻到头（188 页） | `session.prompts`（一次） |
|---|---|---|
| 堆峰值（核心闲着 3.5 MB） | 127.9 MB（127.9～128.2） | 17.6 MB（17.6～17.6） |
| 匿名内存多 | 137.9 MB | 22.5 MB |
| 用户态指令 | 4,304 亿 | 19.5 亿（约 1/220） |
| 耗时中位（最快～最慢） | 16.8 s（15.2～28.0 s） | 201 ms（141～365 ms） |
| 回应 | 57.6 MB（188 个） | 1.06 MB |
| 列出来的 | 9,351 条人话（翻页拿到的是日志里全部的，撤销、重做掉的还得头自己照有效历史算） | 9,105 句（9,351 − 撤销不恢复的 95 − 重做换掉的 151） |

`view.page` 每翻一页都把整份日志读成事件再切（一页一次 57 MB 的全解），所以指令是一次全解的两百来倍；`session.prompts` 读一遍、只全解人话，峰值里是读、解的一窗原文和几块解好的、有效历史留着的最后一截（出厂 `flush_at` 2,048 条）、九千多句问话和回应的 JSON 树。

### 风险

- 有效历史的规矩以后多认了别的种类、多看了别的格，`event/only.rs` 不跟着改的话，这里和判官一起算错（V-39 上补施工单「风险」第 1 条）；对照测试逮得到生成器造得出的那几种。
- 判断「主人本人」照 `By::Person`（不论 `via`）：以后主人在别处（别的头、别的入口）说的话换了记法，要跟着改。
- 分叉出来的会话不列底子：网页要是把底子和支线拼成一条时间线显示，得另向父会话要；现在 `view.page` 也只翻支线自己的。
