## 施工单 X-42 上：网址的服务登录

状态：在分支 `step/X-42-远程MCP的OAuth` 上（同设计那两个提交一起交），照 `X-42-远程MCP的OAuth.md` 的拆法，主会话看过（2026-10-21：代码放法、不加新 crate、回调照服务记住端口都同意）。

### 目的

只认浏览器授权的远程 MCP 服务接得上：服务回 401 的记成「要登录」，人打 `miyu mcp login <服务>`，浏览器里点同意，核心换到令牌、存进密钥文件、连上。设计照 `mcp.md`「待定（施工 X-42）」第 1、2（不含手贴）、3、4、7 题，审过的推荐和主会话补的三点照做。

### 蓝图改哪几节

- `mcp.md`：定了的几题挪进「怎么走」新的第八条「网址的服务登录」，「待定」里只留第 5、6、8 题和第 2 题的手贴（X-42 下）、CIMD；要登录的服务照扩展的 `needs_approval` 那一路停下：`state: "stopped"`、`reason: "needs_login"`，不另开新状态（主会话 2026-10-22 同意）；「出错」加 `oauth_unregistered`、`oauth_failed`（`mcp.login` 的原因码）。

- `cli` 蓝图：`miyu mcp login`。

### 代码放哪

- `miyu-mcp` 新 `oauth` 模块：照规范的纯逻辑（读 `WWW-Authenticate`、拼两种 well-known 网址、校验 `issuer`、PKCE、拼授权页、读回调、规范网址）和几次 HTTP（取元数据、动态注册、换令牌）；回调的监听只听 `127.0.0.1`（`tokio` 的 `net` 本来就在测试里用，挪进正式的依赖）。没有新的 crate：`sha2`、`base64`、`getrandom` 工作区里都有。
- `miyu-endpoint`：网址的转接把 401 和它的 `WWW-Authenticate` 交给看管的一头；`needs_login` 状态；`mcp.login`；令牌照密钥的现有写法存、连的时候当 `bearer`。
- `miyu-cli`：`miyu mcp login <服务>` 调 `mcp.login`，打开浏览器（打不开的只印地址，不带 `code_verifier` 之类），等服务连上。

- CIMD、头的按钮。

### 验收

照 `X-42-远程MCP的OAuth.md`「验收」里属于这一步的几条：假授权服务器两种发现路径、两种注册、`state`、`iss`、S256、令牌进密钥文件、日志和回应里搜不到令牌。手写变异 15 个左右；门禁全过；本机 Windows clippy；推 `step/` 过三台 CI。

### 风险

- 第一次连就要人点：`needs_login` 不算失败、不退避重连，人登录完立刻重连。
- 回调的端口：RFC 8252 第 7.3 节说回环地址的端口授权服务器不该限死，但有的照端口精确比（主会话提的）。授权服务器认为 `redirect_uri` 不对时照 OAuth 不跳回来、只在浏览器里报错，核心收不到回调，所以「报错了再重新注册」没法自动触发。改成：**照服务记住一个端口**。
  - 回调只听 `127.0.0.1`（字面的地址，不解析 `localhost`、不听 `0.0.0.0`），路径 `/callback`。
  - 动态注册时就用真端口：`redirect_uris` 写 `http://127.0.0.1:<端口>/callback`，端口跟着 `client_id` 存进密钥里的那一份。
  - 下一次登录先绑同一个端口：绑得上的照用，精确比的授权服务器也认；绑不上（被别的程序占了）的换一个随机端口，动态注册来的重新注册一次（只一次），预先注册的照旧用新端口，授权服务器不认的回 `oauth_failed` 带原话。
  - 预先注册的可以在表里写 `oauth.port`，照它绑，给要事先登记回调地址的服务。
  - 测试的假授权服务器加一个「端口要精确」的变体：同一个端口登第二次照过；端口被占、换了端口的，重新注册以后过。
  - 主会话 2026-10-21 同意这个做法，补两点：端口和 `client_id` 同进退，登出时一起清，重新注册成了才用新端口盖掉旧的、没成的不盖；`oauth_failed` 带的原话当不可信的字办（截长、不进给模型的说明），和别处的报错同一个口径。

### 做下来的

- 适配器（`miyu-mcp` 的 `oauth`）：纯逻辑（读 `WWW-Authenticate` 的 `Bearer` 那一段、规范网址、两种 well-known 的先后、查 `issuer` 和 S256、PKCE、拼授权页、读回调、`iss` 照 RFC 9207 那张表、范围怎么挑）；几次 HTTP（`flow.rs`：发现、动态注册、换令牌，授权服务器的说明截到 200 个字符）；回调的监听（`callback.rs`：只听 `127.0.0.1`，照记住的端口绑）。转接在 `401` 时记下挑战的原文（`Opened::challenged`）。假授权服务器（`testkit/oauth.rs`）带「端口要精确」的变体，测试服务能照令牌挡（`HttpServer::protect`）。
- 端点：看管的一头照 `needs_approval` 那一路停在 `stopped`、`needs_login`，不算失败、不退避；`mcp.login`（只给人）找服务、发现、注册（端口被占的、动态注册来的重新注册一次）、交回授权页的网址，回调到了换令牌，经 `secrets::store` 存进 `mcp-oauth-<服务名>`，照 X-32 补那一路重起服务；连的时候表里没写令牌的带上存的那个。个人设置里去掉的、卸包时缓存忘掉的服务，连同那一份密钥一起清（`secrets::discard`，记成核心改的）。等回调的登录记在每个核心自己身上（`Servers.logins`）。
- 命令行：`miyu mcp login <服务>` 调 `mcp.login`，打开浏览器（打不开的只印地址），等到服务连上或者停下。
- 看红：适配器先放空壳（类型、签名是真的，里面空的），9 条纯逻辑测试全红，换上实现全绿。端点、命令行的实现写在测试前面：4 条真核心的登录测试头一遍全红，两处是测试没搭对（没起跟着个人设置走的那一圈、没起扩展，照别的测试补上），一处是代码的毛病：等回调的登录原来记在全进程共用的一张表里，几个核心同时跑、服务名都叫 `notes`，互相把对方的等待取消了，改成每个核心各记各的。
- 手写变异 20 个：头一遍 18 个都抓住；另外 2 个（不认 S256 也用、`http` 的端点也用）`cargo fmt` 改了那几行、原文对不上没跑起来，照新格式重写补跑，也都抓住，20 个全抓住。
- 登记簿不加行：`mcp.login` 只给人，这一步没有给模型看的新字。
- `cargo xtask check` 全过（头一回 clippy 两处、英文帮助页一行超宽、`cli` 蓝图的帮助样例没跟上；测试的假授权服务器里丢掉 `Result` 的那一处，改成 `let _ =` 照样不认，最后写成 `if let` 连着判断，都改完过）；本机 Windows 的 clippy 过；推 `step/` 过三台 CI（见交接的消息）。
