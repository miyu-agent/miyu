## 施工单 X-42 上：网址的服务登录

状态：在分支 `step/X-42-远程MCP的OAuth` 上（同设计那两个提交一起交），照 `X-42-远程MCP的OAuth.md` 的拆法，等主会话看一眼。

### 目的

只认浏览器授权的远程 MCP 服务接得上：服务回 401 的记成「要登录」，人打 `miyu mcp login <服务>`，浏览器里点同意，核心换到令牌、存进密钥文件、连上。设计照 `mcp.md`「待定（施工 X-42）」第 1、2（不含手贴）、3、4、7 题，审过的推荐和主会话补的三点照做。

### 蓝图改哪几节

- `mcp.md`：定了的几题挪进「怎么走」新的第八条「网址的服务登录」，「待定」里只留第 5、6、8 题和第 2 题的手贴（X-42 下）、CIMD；「出错」加 `needs_login`（状态）、`oauth_unregistered`、`oauth_failed`（`mcp.login` 的原因码）。
- 协议参考 `packages`（中英）：`mcp.login {service}` → `{url}`；`mcp.list` 的 `state` 多 `needs_login`。
- 作者文档 `mcp`（中英）「最快：写进个人设置」：要浏览器登录的服务写完 `url` 打 `miyu mcp login <服务>`；能写 `oauth = { client_id, client_secret? }`。
- `cli` 蓝图：`miyu mcp login`。

### 代码放哪

- `miyu-mcp` 新 `oauth` 模块：照规范的纯逻辑（读 `WWW-Authenticate`、拼两种 well-known 网址、校验 `issuer`、PKCE、拼授权页、读回调、规范网址）和几次 HTTP（取元数据、动态注册、换令牌）；回调的监听只听 `127.0.0.1`（`tokio` 的 `net` 本来就在测试里用，挪进正式的依赖）。没有新的 crate：`sha2`、`base64`、`getrandom` 工作区里都有。
- `miyu-endpoint`：网址的转接把 401 和它的 `WWW-Authenticate` 交给看管的一头；`needs_login` 状态；`mcp.login`；令牌照密钥的现有写法存、连的时候当 `bearer`。
- `miyu-cli`：`miyu mcp login <服务>` 调 `mcp.login`，打开浏览器（打不开的只印地址，不带 `code_verifier` 之类），等服务连上。

### 不做什么

- X-42 下的：续期、权限不够、登出、手贴回调。
- CIMD、头的按钮。

### 验收

照 `X-42-远程MCP的OAuth.md`「验收」里属于这一步的几条：假授权服务器两种发现路径、两种注册、`state`、`iss`、S256、令牌进密钥文件、日志和回应里搜不到令牌。手写变异 15 个左右；门禁全过；本机 Windows clippy；推 `step/` 过三台 CI。

### 风险

- 第一次连就要人点：`needs_login` 不算失败、不退避重连，人登录完立刻重连。
- 回调网址固定 `/callback`、端口每次随机：动态注册时 `redirect_uris` 写 `http://127.0.0.1/callback`，授权时带上真端口（RFC 8252 第 7.3 节：回环地址的端口授权服务器不该限死）；有不认的授权服务器，`oauth_failed` 带它的原话。
