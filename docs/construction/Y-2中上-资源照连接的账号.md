## 施工单 Y-2 中上：人格、预设、技能、脚本、知识库照连接的账号

状态：已合（2026-10-23）。用户系统主线（设计 `06` 八又补「每人一个独立的 Miyu，共用的只有系统」、U2），核心主会话 2026-10-23 派给 clicall 会话；Y-2 上（会话只给属主）已在 main。核心主会话同一天审过下面的表。第二批（记忆、配置和密钥、附件 blob、场所、包、用量）核心主会话另排。

### 目的

`miyu-endpoint` 里这几样资源写死照 `core.admin` 走：`core.admin` 就是装 Miyu 的那个人自己的账号，成员现在被临时的闸挡着进不来。这一步把它们改成照「这个连接的账号」：写只写进调用者自己的家目录，读是自己的加系统层。成员进来以前，对主人零可见变化。

### 定的（2026-10-23，核心主会话审过）

1. **系统层是系统区，不是管理员的家目录**：`core.admin` 的家目录是主人自己的东西（他的人格、知识库、脚本），当系统层的话成员一进来就读得到主人私人的东西，违「共用的只有系统」。系统层是 `root.system()` 下的系统区：人格、预设原来就有这一层（`Layer::System`）；技能、脚本、知识库这一步给它留 `root.system()/skills`、`/scripts`、`/kb` 的位置，读的时候有就读、没有就空（设计 06 八又补第 6 条的「系统库」以后在管理员模式下建）。
2. **一处函数**：`miyu-endpoint/src/scope.rs`，`scope(core, caller) -> Scope { user }`；系统层是 `DataRoot::system()`，存储层各样资源照它叠（审表时的 `system_dir` 一格没人读，拿掉）；以后拆出独立的系统账号改这两处。写系统区的判断随 Y-2 下的管理员模式加（核心主会话 10-23：先不留没人用的函数）。
3. **同名的自己的盖过系统的**（同包的 U23）：人格、预设照原来的层序（出厂 < 包 < 系统区 < 家目录）；技能、脚本照原来的次序（家目录在最前，先到的赢），系统区排在家目录后面、包前面。
4. **脚本只改人看的那几个方法**：`scripts.list`、管理脚本的方法照调用者；登记进全核心共用的工具目录的照旧是主人那一份（成员进不来，零变化）。每个会话照属主叠自己的脚本单列一步（Y-2 中-脚本目录）。
5. **会话里用的照会话属主**：开会话、换人格预设时找人格、预设，照会话的属主，不照 `core.admin`。
6. **系统账号照它服务的人**（核心主会话 10-23 报的）：群、陌生人私聊的会话属主是桥的系统账号，系统账号没有自己的一层；`scope()` 里照 `memory_owner`（这一版是管理员，同人格的 keeper 一个口径），主人家目录里的人格群里照样找得到。以后每个带进程的包都有自己的账号（U16），判的是 `is_system`，不看包写没写 `system_account`。

### 每样怎么改

| 资源 | 读 | 写 |
|---|---|---|
| 知识库（先做） | 自己的 `home/<调用者>/kb`，加系统区的库（有就读） | 只写 `home/<调用者>/kb`：挂载、改名、建、删、重建索引、加文档（blob 进调用者的）、删文档 |
| 人格 | 出厂 < 包 < 系统区 < `home/<调用者>` | 写、删 `home/<调用者>/personas` |
| 预设 | 同人格 | 写、删 `home/<调用者>/presets` |
| 技能 | `home/<调用者>/skills` < 系统区 < 包 | 写、删只碰 `home/<调用者>/skills` |
| 脚本 | 同技能（人看的列表） | `home/<调用者>/scripts` |

### 验收

- 两个账号直接调底层函数：甲写的乙读不到；系统区两人都读得到；同名的甲自己的盖过系统区的。人格、预设、技能、脚本、知识库各一条。
- 端点照连接的账号：主人照旧读写原来那几处（零变化），现有测试照旧过。
- 系统账号的群会话用主人家目录里的人格（`tests/system_account_personas.rs`），改回照系统账号自己的家目录找就红。
- 手写变异，漏的补测试；`cargo xtask check` 全过。
