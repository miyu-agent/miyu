## 施工单 X-38：作者文档指向开发包

状态：主会话审过（2026-10-21），照审时的三条改了：只照 SDK 推上去的那一版写，Windows 照 `#!` 找解释器写成现状，Rust 的仓库依赖加一句锁版本写 `rev`。只改文档，不碰代码、路径、子进程，不用先推 `step/` 分支过三平台 CI（AGENTS.md「施工的规矩」第 2 条）。

### 目的

设计 `40-开发包.md` 第二节定了：「作者文档 `docs/authors/extensions.md` 加一节『用开发包写』，指过去；手写 JSON 的那个例子照旧留着：协议不挑语言」。开发包的仓库 `miyu-agent/miyu-sdk` 已经建好、推上去了（Python 一个文件、Rust 一个 crate，各带假核心和例子），核心这边的作者文档还一个字没提，作者照着文档只会手写 JSON-RPC：同时来的调用、取消、退出码 1、读到头就退，最容易漏的那几样正是开发包包好了的。

### 改哪几处

- `docs/authors/extensions.md`（中英）：「一个最小的扩展」后面加一节「用开发包写」：
  - 一句话说开发包包了什么（握手、一行一条的收发、几个调用同时来时照编号对着回、取消、配置推送、标准输入读到头就退、退出码 1），不多给本事，扩展能做什么照旧由协议定；MIT。
  - Python：把 `miyu_ext.py` 拷进包的 `bin/`、和程序放在一起，只用标准库，不用 pip；三个平台一份文件（Windows 上核心照 `#!` 找 `python`）。最短的例子照 SDK 推上去的那一版（`origin/main`，2026-10-20）的 README，同一个 `hello_greet`；用到的接口只有那一版里有的，本地领先的两个提交里才有的不写。
  - Rust：依赖 crate `miyu-ext`（`git = "https://github.com/miyu-agent/miyu-sdk"`，SDK 还没发版；要锁版本的写 `rev`，打了标签以后改成 `tag`），同步、只依赖 `serde_json`；编出来的程序放 `bin/`，Windows 上是 `.exe`。
  - 测：两份各带一个假核心，离开 Miyu 也能测，一行例子。
  - 完整的说明、例子在 SDK 仓库里，这一节不抄全：两份文档写同一件事容易走岔。
- `docs/authors/README.md`（中英）：「包能带什么」那张表下面一句：写扩展有 Python、Rust 的开发包。
- 设计 40 的「状态」补一句：作者文档指过去了（施工 X-38）。

### 不做什么

- 不把开发包拷进核心仓库、不加依赖（设计 40 第二节：核心仓库不依赖它）。
- 不改手写 JSON 的那个例子。
- SDK 仓库自己的 README 另提交（扩展线本地已有两个提交：`Reply` 的几格、Python 三个平台一份文件，等项目主人点头再推）。

### 验收

1. 文档里的例子照 SDK 推上去的那一版的接口写：拿那一版的例子包真装一次（`miyu pkg install`），照作者文档说的跑通（本机 Linux）。
2. 中英两份对得上；作者文档不写施工编号。
3. `cargo xtask check` 全过（文档那一项查链接、两份对得上）。

### 做下来的

- 照施工单。例子、接口只用 SDK 推上去的那一版（`origin/main` 3901df1）里有的：`Extension`、`@ext.tool`、`ext.config`、`ext.call`、`FakeCore`；扩展线本地领先的两个 README 提交里才有的（`Reply` 的几格、`data`）没写。
- 验收：拿那一版的例子包（`python/examples/hello`，`miyu_ext.py` 照作者文档拷进 `bin/`），在临时数据根里用这个分支编出来的 `miyu` 装上：`miyu pkg install … --yes` 装好、打开；扩展照 `#!` 起来（`python3 …/bin/miyu-hello serve`），标准错误日志是空的，登记缓存里有 `hello_greet`，`miyu check` 没有问题。验完只停了这个临时数据根起的核心和扩展，删了临时目录。
