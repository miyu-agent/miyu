## 施工单 R-17：整理留痕

状态：做好了（2026-10-19 写、施工、自己验收）。项目主人 2026-10-19 问整理（dream）有没有像压缩那样的进度，又说「不是说仿 Linux 吗？日志呢？一切皆文件呢？」「有内容吗？例如删掉了什么，记录了什么，更新了什么」，看过方案说「开工」。跟着照推荐定的：后台自己合的也写；作废的种类和留下的那一条也记进日志；一批之内不细分。剩下的是技术细节，照施工方案第一节第 1 条直接做。

### 原来缺什么

- 记忆日志里已经有内容：改的（`saved` 带 `replaces`）、删的（`retired` 带 `why`）、摘要、关键词、每一批的 `merged`。订阅 `memory` 流的头照它就能列出做了什么。
- 缺开头：头不知道开始整理了、一共几条，算不出进度；没合成的不连着三次不写，半路停了的什么都不写，头分不出「在合」和「停了」。
- 缺种类：R-16 起模型交 `kind`、`by`，核心核对过，日志里只写了 `why`。
- 运行日志每一批有开始、结束两行，一趟合（合到没有剩下的）的头尾要自己凑。

### 定了的

1. **开始合一批**：每一批发请求以前记 `ext.memory.merging`：`upto`（这一批新记的里最后那一条）、`fresh`（这一批几条新记的，不算带上的相关旧记忆）、`left`（连它在内还有几条新记的）、`manual`（`memory.dream`、`/dream` 是真，后台自己合的是假）。
2. **收尾**：同一个 `upto` 的 `ext.memory.merged`（合成了；连着三次没成跳过的 `failed`）或 `ext.memory.merge_failed`（`upto`、`why`、`tries`）。每一次没成都记一条 `merge_failed`，第三次后面另跟原来那条 `merged`（`failed`）。`why` 是英文的一句，同运行日志，再遮一遍 key。
3. **半路停了**：这一回第一次开这一间（`Keeper::log` 拿到 `Report` 那一下），底账里有开始合了、没收尾的那一批（`MemoryBook::merging`），补一条 `merge_failed`（`why: interrupted`，不写 `tries`）。开日志总在合以前，这一回还不会有在合的。
4. **作废的种类**：整理作废的 `ext.memory.retired` 另写 `kind`（`outdated`、`repeat`、`worthless`）、`kept`（核对过的 `by`：取代它的、和它重复的；`worthless` 没有）。人作废的、R-17 以前的不写，读的时候没有就是没有。种类挪进 `miyu_recall::memory::RetireKind`，`merge::Kind` 是它。
5. **头怎么用**（写进 `reference/memory.md`「`memory.dream`」）：头一批的 `left` 是总数，收了尾的各批 `fresh` 加起来是合了多少；`merging` 到它收尾之间 `by` 是记忆模块的改、删、摘要就是这一批做了什么；关键词跟在 `merged` 后面；没收尾的是正在合。
6. **运行日志**：一趟合开始 `INFO memory merging started left=… manual=…`，合完 `INFO memory merging ended batches=… given=… revised=… retired=… took_ms=…`；每一批开始那一行多 `fresh`。

### 不做什么

- 一批之内不细分：模型写的那一会儿不推字数。那不是一件事，不进日志；要的话照压缩另做不落盘的推送，那时再问。
- `memory.list` 不另给「正在整理」：头照日志算（`/proc` 只给现在的样子）。

### 验收

1. 测试先写：`miyu-recall` 的 `memory/tests/trace.rs`（作废的种类和留下的、开始合、没合成、半路停了的读写得回，种类写错的读不懂；底账同一个 `upto` 才收尾）；`miyu-session` 的 `memory_merge_trace.rs`（真整理：人叫的、后台的、连着三次没成、分两批、半路停了、收了尾的不补）。
2. 手写变异八个左右，全被逮住；`cargo xtask check` 八项；三台 CI。
