## 施工单 SEC-1：密钥写错类型不回显

状态：施工中（2026-11-10）。语音会话报、项目主人撞上。

### 为什么

类型是密钥的项（例如 `say.mimo.key`、`providers.<id>.key`）只收引用 `{ secret = … }`、`{ env = … }`。把 key 本身当成字写进去（设置页的输入框里贴、`miyu config set`、手改配置文件），回的 `config_invalid` / `wrong_type` 里 `got` 和整句的话都把原值照抄出来：「…要写 { secret = "…" } 或 { env = "…" }，写的是 "sk-…"」。头会把它显示出来、可能记进日志，密钥模块自己定的「值不进回应、报错的话」在这条路上漏了。

### 做什么

1. 记问题时就不抄原文（`miyu-config` 的 `problem/hidden.rs`）：类型是密钥、密钥的列表、带密钥字段的列表的一格，`got` 是空的，另记它是什么样的（`Shape`：几个字符的字、几项的列表、一张表、几个字符的值；照 JSON、TOML、人敲的几种认）。不在说话时才藏：原文进 `got` 前已经截到 80 个字符，到那时数不对、截出来的前半段已经在问题里了。
2. 说成话时照连接的语言说这个样子（新字 `config/got/text`、`list`、`table`、`value`，中、英、日三份），`got` 那一格和整句的话用同一句；`wire::problem` 的 `got` 改取说成话的那一份。
3. 走到的路：配置文件读进来（`config.get`、`check`、改了推送、`config.set` 整份换、`config.check` 都走它），`config.set` 照 `value`、`input` 逐项改，列表里的密钥字段。不认识的键、列表里不认识的字段、一组键写成的一个值（`providers.dev = "sk-…"`）没有类型，值可能就是拼错了键的密钥（`say.mimo.kye = "sk-…"`），同样只记什么样的，键和最近的键名照给（主会话定）。不是密钥、认识的项字节不变。
4. 蓝图 `config.md`「报错」`got` 那一行、报错的话那张表、测试表；参考文档 `config` 中英两份。

### 验收

- 单元（`problem/hidden/tests.rs`）：样子的几种认法；哪些类型、键算密钥；配置文件里密钥项、密钥字段写明文的，问题和话里都没有原文（超过 80 个字的也没有截出来的那段）；拼错的键、不认识的字段、一组键写成的值也没有；不是密钥的照旧照抄。
- 集成（`tests/config_secret_got.rs`、`package_records.rs`）：`config.set` 照 `value`、`input` 写明文，写成数组、对象，配置文件里手写的、拼错了键的、一组键写成值的经 `config.get`、`check`、`config.check` 报出来，把整条回应变成字查，没有那串字，说的是几个字符的字；列表里的密钥字段同样；不是密钥的照旧照抄。先红：没修时 `got` 是原文，报红。
- 本机门禁全过。回应的样子变了（密钥项的 `got`），合了告诉 UI 和 im。
