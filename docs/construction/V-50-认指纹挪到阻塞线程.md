## 施工单 V-50：认指纹挪到阻塞线程

状态：已完成（2026-11-05）。V-47 施工单「没做的」第 2 条、「代价」里记下的那一处：核心按规格缓存 Landlock 规则集以后，每条关起来的命令起之前要在核心里认一遍指纹，原来是在跑异步任务的线程上同步做的。core1 2026-11-05 定：挪到阻塞线程，编号 V-50。

### 为什么

`miyu_sandbox::command`（V-47）对能缓存的规格（Linux、只用 Landlock、有藏起来的、路径都是绝对的）每次都把从头建要看的东西重看一遍、和缓存的指纹逐字节比：列目录、逐条 `fstatat`、读挂载表，V-40 那份规格约 2 ms，要重建的那一次约 5 ms。调它的 `shell`（前台、后台）、脚本工具都在 tokio 的异步任务里同步调，这几毫秒占着一个工作线程。核心的运行时只有两个工作线程（`miyu-core` 的 `WORKERS`），这段时间别的会话、别的请求只剩一个线程可用。

### 做什么

1. **`miyu_sandbox::checks_files(&Sandboxed)`**（`wrap.rs`，新的公开函数）：`command` 会不会在调的线程里看文件系统。Linux 上照 `cache.rs` 的 `looks`：规格能缓存（`cacheable`），这台机器的 Landlock 能用（原来 `ruleset` 里那个只探一次的 `OnceLock`，提成 `usable()` 两处共用）；别的平台恒为假。它只决定在哪个线程造命令，说错了也只是多一次或少一次线程往返，造出来的命令不变。
2. **`shell`**（`shell/channel.rs` 的 `Shell::prepare` 改成 `async`）：开通道、挑环境变量、改规格照旧当场做；`checks_files` 为真的，把整个 `Program::command`（拼 shell 的参数、调 `miyu_sandbox::command`、设工作目录和环境变量）放进阻塞线程（`crate::blocking::blocking`，带着派活时的 span，panic 照样传回来），造好的 `Command` 拿回来；为假的照旧当场造，不多一次往返。前台、后台（`background` 跟着改成 `async`）都经它。
3. **脚本工具**（`shell/script.rs` 的 `Script::command` 改成 `async`）：规格照旧当场拼好（加 `reveal`、`write`），`checks_files` 为真的只把 `miyu_sandbox::command` 这一句放进阻塞线程，规格、程序、参数本来就是这里自己的一份，挪进去不多拷。`run` 里原来 `and_then` 的闭包拆成一段 `match`，先后不变。
4. **`fork` 照旧在原处**：阻塞线程只造 `Command`（认指纹、拿到缓存的规则集 `Arc<OwnedFd>`、装上 `pre_exec`），起进程（`process::start` → `spawn`，走 `fork`，子进程里 `pre_exec` 只调一次 `fcntl` 去掉 `O_CLOEXEC`）还是在原来跑这个异步任务的线程里，和改前一样。跨线程交的东西都安全：`Command` 是 `Send`（`pre_exec` 的闭包要求 `Send + Sync`，里面只拿着 `Arc<OwnedFd>`）；缓存的锁是标准库的 `Mutex`，只在 `ruleset` 里拿、不跨 `await`；规则集描述符带 `O_CLOEXEC`，在哪个线程拿到、核心别处同时起的子进程都漏不过去。
5. 后台命令原来写明「这里一个 `await` 都没有：交上了就一定交回结果」。现在唯一的 `await` 在造命令里，在起进程、交任务端口之前：这时被掐掉，命令还没起、通道丢掉时关，和造命令出错一样；起进程以后照旧一个 `await` 都没有。注释改成这样说。

### 行为差别

没有。起的程序、参数（含 `--ruleset <号码>` 的位置和号码怎么交）、工作目录、环境变量、出错报的字（规格写不成 JSON 照旧说起不来）、先后（没有任务端口的后台照旧先报 `shell/no-background`、工作目录不在的照旧先报）都不变。关起来的命令照旧拿到同一份缓存的规则集（strace 核对：改前改后 9 条命令都带 `--ruleset`）。不用缓存的（bwrap、关起来的会话、macOS、Windows、Landlock 用不了）一行都没变，也不多一次线程往返。

**多一次线程往返的代价**（`scratchpad/v50/hop/`：和核心一样的运行时，多线程、2 个工作线程；每次先睡 5 ms 让线程都停下，再做一次空的活，当场调和经 `spawn_blocking` 各 2000 次，`getrusage` 拿进程的 CPU，3 遍）：往返墙钟 p50 20～35 µs，CPU 每次多 21～26 µs。照实算：每条关起来的命令核心多花约 0.02～0.03 ms CPU，是认一遍指纹（约 2 ms）的 1% 左右，换来那 2～5 ms 不占着两个工作线程里的一个。不用缓存的规格不付这一份。

**内存**：不常驻、不落盘。阻塞线程用的是 tokio 本来就有的池（命令的等待本来就在那里），没有新的常驻线程；造命令多拷一份 shell 的路径和命令原文（几十到几千字节，造完就丢）。
