## 施工单 R-23：不经会话的整理也停得下

状态：待合（2026-10-20 写、施工、自己验收）。R-22 只让会话里人叫的整理停得下；项目主人 2026-10-20 看了说命令行的 `miyu memory dream` 停不下来「不合理」，要和核心对一下。和核心那边对过（方法名 `memory.dream_stop`、R-23 由记忆这边做、分派表晚合的 rebase 对一下）。网页记忆页的「整理」走的也是这一路，一起补上。剩下的是技术细节，照施工方案第一节第 1 条直接做。

### 定了的

1. **一间一份叫停的那一头**：放在 `Merges` 里（和一间一把锁一起），`Keeper::stop_dream` 叫停。人叫的整理不管是哪一路叫的（带 `persona`、`session` 的 `memory.dream`，会话里的 `/dream`），都同时听叫它的会话的（R-22）和这一间的，哪一头叫停都停；定时的不听。会话的 `/dream stop`、`/stop` 照旧只停这个会话叫的。
2. **协议 `memory.dream_stop`**：参数只有 `persona` 或 `session`（照 `find` 找那一间，同 `memory.*`）；叫停这一间这时人叫的那一趟，回 `{"stopped": true}`；没有的（定时的在合也算没有、整理回了以后）回 `not_dreaming`。照顺序答：`memory.dream` 在后台答，同一条连接上接着发就行。停的规矩同 R-22：合完的批留着，正在合的那一批放弃、记 `merge_failed`（`why: stopped`），被叫停的那条带 `"stopped": true`，下次接着合。
3. **命令行**：`miyu memory dream` 等的时候按一次 Ctrl+C 发 `memory.dream_stop`（同一间、同一条连接），标准错误印「正在停止整理……再按一次 Ctrl+C 直接退出。」，接着等原来那一条，印「整理已中断：…」（和 `/dream` 的同一句），退出码 3；再按一次不等、直接退，退出码 3。退出码用 3 不用 130：`miyu ask`、`miyu compact` 按了 Ctrl+C 都是 3（`exit::INTERRUPTED`），130 是贴 key 时取消的那一套。帮助页 `dream` 那一行多「按 Ctrl+C 停下，合完的留着」。
4. **网页**：记忆页整理进度那里的「停止」调 `memory.dream_stop`，归网页的头。

### 验收

1. 测试：`hush.rs` 多一条（会话的、这一间的哪一头叫停都停）；`miyu-endpoint` 新的 `memory_dream_stop.rs` 两条（叫之前 `not_dreaming`；照人格叫停同一条连接上在后台答的 `memory.dream`，两条回应都带 `stopped`，记忆流推 `stopped`；回了以后再叫 `not_dreaming`；下次接着合。会话里叫的那一趟照会话叫停也停得下）；`miyu-cli` 的 `memory.rs` 一条（按一次叫停、印中断了、退出码 3、提示在标准错误，下次接着合；按两次直接退）。R-22 端点那一条顺手改成等到记忆流的 `stopped` 为止（推送另走转发任务，可能晚于回应到；新的那一条头一回跑就这样挂过一次）。
2. 变异五个（不经会话的不听这一间、只等会话那一头、命令行 Ctrl+C 不发叫停、按两次不退、会话里叫的不听这一间）全被逮住；头一轮漏了最后一个，补了照会话叫停那一条。变异的脚本还原文件以后要碰一下修改时刻：还原的那一份时刻比上一次编译早，cargo 当它没变，接着用变异过的那一版（头一回查出来就是这样，三次挂看着像真毛病）。`cargo xtask check` 八项；三台 CI。
