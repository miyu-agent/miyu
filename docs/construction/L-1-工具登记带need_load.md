## 施工单 L-1：工具登记带 need_load

状态：待施工。设计 `25-工具加载.md` W9（2026-10-15 项目主人定），图纸 `kernel/tools.md`、`providers.md`、`skills.md`、`mcp.md`。

### 目的

每件工具登记时可以说「要先加载」：tools 数组里只有它的名字、说明和空的参数外壳，她用之前调 `load_tools` 拿完整格式。内置工具、脚本、扩展、MCP 四个来处一个写法。

### 蓝图改哪几节

- `kernel/tools.md`：工具规格多 `need_load`；快照的工具面每件记上它；拆成 tools 数组时要加载的那几件参数换成 `{"type": "object"}`；`load_tools` 由内核当场答，结果是这几件的完整说明和参数格式；没加载直接调出错的，结果后面附上这一件的完整格式。
- `skills.md` 脚本开头注释多 `# Need load: yes`；`providers.md` `provide` 的一件多 `need_load`（不是布尔的 `bad_tool`，`problem` 是 `need_load`）；`mcp.md` `[[mcp]]`、个人设置的服务多 `need_load`。
- `prompts.md`：`load_tools` 的说明、附上完整格式的那一句，进登记簿。
- 给作者的说明（中、英）：四个来处各一句。

### 不做什么

- 不按组加载，不做出厂的混合模式，设置页不改加载状态（W9 第 4 条）。
- 出厂的工具一件都不标：全量照旧。
- 吃不下空外壳的供应商在 L-2。

### 验收

- 没有要加载的工具时，请求形状探针五张脸逐字节不变；`load_tools` 不出现。
- 测试扩展登记一件带 `need_load` 的：tools 数组里它的参数是 `{"type": "object"}`、说明是整段，多了 `load_tools`；调 `load_tools` 结果是它的完整格式，第二轮前缀命中不掉。
- 脚本、MCP 服务各标一件，同上。
- 不加载直接调：参数对的照常执行；扩展回了出错的，结果后面附上完整格式。
- 以前的快照（没有这一格）读进来再写出去一字不差。
- 真模型（magpie 那组）：一件要加载的工具，她先 `load_tools` 再调成功。
- 手写变异全抓住。

### 风险

- 快照多一格：没标的不写，旧快照、旧指纹不动。
- 内核当场答 `load_tools`，结果的字节只看快照，不看这时的目录：包升级了也照会话开局时的格式交。
