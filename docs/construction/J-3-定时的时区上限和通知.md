## J-3：定时的时区、上限、命令行和通知

状态：上、中主会话做，下核心的分会话做（2026-10-27 派），都合了。设计 `45-定时和循环.md` 第五节第 3 条，项目主人 2026-10-27 定了时区和上限。

### 一、上：做了什么

1. **时区**（项目主人 10-27 定：建时自动记下，可以手写覆盖，内部存 UTC）：
   - `when.cron` 多一格可选的 `zone`（IANA 名，例如 `Asia/Tokyo`），存在唤醒表那一格 JSON 里，表结构不变。
   - 头、命令行建时交本地的；不交的，核心记这台机器那一刻的。以前建的没有，照本机的。
   - 算下一次照记下的那个时区读 cron，夏令时交给时区库；记下的认不出了也照本机。
   - 不认识的拒 `bad_params`（`problem: zone`），和 `at`、`every` 一起写的拒 `when`。
   - 她经 `cron_create` 建的记这台机器的，工具不加参数：加一个参数每次请求都要多带 token，先不加。
2. **每账号 200 个**（项目主人 10-27 定，熔断性质的安全上限）：
   - 人建、她建、包建合计，到了只拒新建，已有的照跑。
   - 协议回 `too_many_schedules`。
   - 她经工具建的回一句 `software/schedule/cron/account-full.txt`（叫她转告人删，她在这个会话里删不掉别处的），已登记进设计 26。
3. **每次新开的工作目录建时就查**（J-1 下审出的跟进）：
   - 照开会话的写法换成真实位置。
   - 不在的、不是目录的、落在数据根里又不在他自己工作区里的，拒 `bad_params`（`problem: cwd`）。
   - 原来要到点才在日志里记一句 `not_opened`。

### 二、上：怎么验

1. 端点 `schedule_limits.rs`：
   - 东京 7:30 的下一次是东京第二天 7:30，纽约照夏令时；不认识的时区、和 `every` 一起写的拒；
   - 一个账号满 200 个后协议拒、已有的还在，她经工具建的拿到满了的那一句；
   - 每次新开的工作目录不在的、在数据根里别人那里的拒，在的照建。
2. `schedule_methods.rs`：没交时区的记这台机器的。
3. 手写变异 9 个全抓到。
4. 本机门禁。

### 三、中：给人的通知（形状两个头 2026-10-27 都推荐）

1. **流**：账号级的 `notices`。`subscribe` 回 `{}`、不补以前的；成员也能订、只收自己账号的；扩展订不了；掉队推 `resync`。
2. **推送** `notice {"kind", "at", …}`：
   - `schedule.ran {schedule, session, ok}`：每次新开会话的定时，交进去之前先订阅那个会话，交进去的那句开的那一轮结束时推（`schedules/ran.rs`），`ok` 是答完了；跑在已有会话上的不推（头照会话状态弹）。
   - `schedules.reset {}`：唤醒表坏了改名留着、换了一份空的。
3. 不存盘（`schedules/notices.rs`，写法同知识库的进度）。为什么不靠头自己照会话状态弹：网页那一轮跑得快还没读进来就漏，终端只盯正在看的那棵会话树（两个头 10-27 说的现状）。

### 四、中：怎么验

1. 端点 `schedule_notices.rs`：跑在已有会话上的到点不推；每次新开的那一轮答完了推 `schedule.ran`（任务、新开的会话、`ok`）；唤醒表坏了换一份空的推 `schedules.reset`；订阅回应是空的。
2. 手写变异 5 个全抓到：新开的不订、已有会话也订、坏了不推、流接错、认错那一轮。
3. 本机门禁。

### 五、下：命令行（做完了）

形状和主会话对过（10-27）。照 `miyu kb` 的写法，只动命令行，核心不动；图纸 `docs/blueprint/cli/schedule.md`。

1. `miyu schedule [list|add|rm|pause|resume]`：连上核心（没在跑就拉起来），照子命令发 `schedule.list`、`schedule.add`、`schedule.cancel`、`schedule.pause`、`schedule.resume`。不写子命令是 `list`。成了退出码 0，核心拒的照原话印在标准错误、退出码 1，参数错的 2。
2. `add <话>...`：
   - 时间三选一：`--cron '<五段>'`（`--once` 只跑一次）、`--at <时刻>`、`--every <间隔>`；`--once`、`--zone` 只跟 `--cron`，clap 管。
   - `--cron` 不写 `--zone` 的交本机的 IANA 时区名（`jiff` 的 `TimeZone::try_system()`）；本机说不出名字的不交，照核心的默认。
   - `--at` 带偏移的 RFC 3339 照它，不带偏移的（`2026-10-28 08:00`）照本机时区读，换成核心认的 `…T…:00.000Z` 再交；已经过了的不另查，核心回 `past`。
   - `--every` 收秒数，或者 `90s`、`10m`、`2h`、`1d`；`--at`、`--every` 读不懂的不连核心就说，退出码 2。
   - 目标：`--session <编号>`，或者每次新开（`--persona`、`--no-persona`、`--preset`、`--cwd`，不写的照核心默认）；`--cwd` 相对的照当前目录接、在的换成真实的位置。
3. `list`：一项一行，编号、什么时候（带时区）、循环、停着、下一次、上一次和结果、跑在哪、那句话；时刻照本机时区印到分钟；`--format json` 原样印。
4. 核心拒 `bad_params` 带 `data.problem` 的，原话后面接上是哪一样（时刻已经过了、间隔至少 60 秒、不认识这个时区……），原来核心只回「参数错误。」。
5. 帮助页中英两份、`-h` 的列表加一行；`cli/main.md` 的几处列表和样本块跟上。
