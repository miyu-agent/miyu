## 施工单 X-42 下修：续期测试不靠一秒

状态：主会话 2026-10-22 排（main 的 run 39726454429、step/R-31 的 39728149033、step/5-14改中撤 的 39728217165 在 Windows 上都只红 `mcp_relogin::a_call_in_flight_outlives_a_refresh_and_a_person_s_change_still_restarts`，Linux、macOS 绿），排在 X-44 补后面。

### 为什么红

两条测试让假授权服务器发 61 秒过期的令牌（`expire_after(61)`），核心离到期不到 60 秒（`EARLY`）的先续，又照整秒比：令牌在发出的那一秒里才算新鲜，留给「登录完、服务连上、第一次调用」的只有零到一秒。Windows 的 CI 慢，过了这条线：

- run 39726454429：服务连的时候就先续了，续到的 `access-2` 假服务不认（它还只认 `access-1`），再续一次还是不认，服务停在 `needs_login`，测试在等 `running` 时超时（日志 `HTTP 401: bad credentials` 两行、`the login is no longer accepted` 一行）。
- run 39728149033：第一个会话的调用发出去时已经过了线，同上停下，两个会话都拿到「工具这时用不了」。

不是代码的竞态：续期、重发、关管道都照设计走了，是测试的时间线只给了一秒。

### 改哪几处

只改 `crates/miyu-endpoint/tests/mcp_relogin.rs`：

- 「续期期间在跑的调用不断」那一条不再靠时间：令牌照默认一小时，第一个会话的调用照旧慢慢答；然后假服务改认 `access-2`，第二个会话的调用回 `401`，续一次、写回密钥、照新令牌重发。要守的还是同一件事：续期写回不重起服务，在跑的那一次不断；人自己改了那一份的照旧重起。
- 「快到期的先续」那一条照旧靠时间（它测的就是时间那一路），新鲜的窗口从一秒放宽到四秒：`expire_after(64)`，登录完等 4.2 秒再调。整秒比的话，登录完三秒内连上的都还新鲜，4.2 秒以后一定过了线。

### 验收

1. 先看红：「在跑的调用不断」那一条登录完多等 1.1 秒再发第一次调用（模拟 Windows 慢），原来的写法红、改完的绿。「快到期的先续」那一条连的那一段测试里拖不慢，只放宽窗口；照旧守得住「不提前续」（`EARLY` 改成 0 的变异要红）。
2. `cargo xtask check` 全过；本机跑 Windows 的 clippy；推 `step/` 过三台 CI（红的就是 Windows）。
