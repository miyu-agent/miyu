## 施工单 X-29 补：核心的 miyu-wallpaper 跟上网页那一份

状态：已完成（2026-11-19）。

### 为什么

`crates/miyu-wallpaper`（找这台电脑现在用的壁纸，给界面「跟随壁纸」取色用）是施工 X-29 从网页仓库原样搬进核心的（网页 `2e68711`）。搬过来以后核心这一份一直没动；网页仓库里那一份还留着，又改了四次。终端经门面 `miyu-client` 用的是核心这一份，所以缺后面的修复。

项目主人定（审计 #092）：合成核心一份。这一步先把网页那一份的改动同步进核心；合了以后网页和它的桥改用核心这一份、删掉网页那一份（网页那边的会话做）。

### 同步了什么

以网页仓库 main（`d282cd6`）的 `crates/miyu-wallpaper` 为准，逐文件对。核心这一份搬来以后没有自己的改动，五个源文件直接照网页的换；`Cargo.toml` 只有开头的注释不一样（各说各的仓库怎么用它），留核心的。

| 网页的提交 | 改了什么 | 落在哪 |
|---|---|---|
| W-1016 | Windows 上找壁纸不再闪黑窗口：拉起 `reg.exe` 这类程序时带 `CREATE_NO_WINDOW`。界面在后台跑、自己没有控制台，不带它 Windows 11 每次都新开一个终端窗口 | `lib.rs` 的 `no_console` |
| W-1029 | macOS 上用系统自带的航拍壁纸也找得到：壁纸设置里没有 `file://` 的，照系统存的缩略图（`aerials/thumbnails/<assetID>.png`）；从设置文件里解出各处的 `assetID`，挑出现最多、缩略图在的那一个 | `probe.rs`、`parse.rs` 的 `macos_aerial_ids`、`pick_aerial`（自己解 base64、找 UUID，不加依赖） |
| W-980、W-1165 | 注释里包文件夹的名字跟着改名（`webui/matugen/…`） | `matugen.rs` |

测试跟着过来：`tests.rs` 多了航拍那几条（解编号、挑哪一个、写坏了的跳过）。

W-1016 另外两半（文件没变就交记着的回答、切窗口一秒内只问一次）在网页服务里，不在这个 crate，不归这一步。

### 验收

- 同步完和网页那一份逐文件比，只剩 `Cargo.toml` 的注释不一样。
- 这个 crate 的测试、门禁、Windows 目标的 clippy、三台 CI。

### 做下来的

- 逐文件比：`diff -rq` 只报 `Cargo.toml`。
- 这个 crate 15 条测试全过（Linux）；连同门面 `miyu-client` 开着全部开关的 clippy 过。
- 没实测的：两处修复一处只在 Windows、一处只在 macOS 起作用，这台机器是 Linux，跑不了；靠测试（解析那几条不分平台）和三台 CI 编得过。Linux 上找壁纸的那条路这次没有改动。
- Windows 目标的 clippy（这个 crate 连同门面，开着全部开关）本机过。

### 怎么实测验收

这一步的两处修复各只在一个系统上起作用，Linux 上看不出区别：

1. **Windows 11**（W-1016）：终端界面开着「跟随壁纸」（或者任何会去找壁纸的地方），切到别的窗口再切回来几次。不该有一闪而过的黑色控制台窗口。原来每找一次壁纸闪一次。
2. **macOS**（W-1029）：系统壁纸选一张自带的航拍（动态的那种），打开「跟随壁纸」。界面该照那张航拍的缩略图取出颜色；原来读不到壁纸、取不出颜色（或者弹出要不要允许控制 System Events 的询问）。换回一张普通图片壁纸，照旧取得出。
3. **Linux**：照旧。换一张壁纸，界面的颜色跟着变，和这一步以前一样。

终端经 `miyu-client` 用这一份，上面三条在终端界面里就能看；网页和它的桥要等网页那边改用核心这一份以后才走到这里。
