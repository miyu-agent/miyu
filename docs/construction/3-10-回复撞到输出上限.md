## 施工单 3-10：回复撞到输出上限

状态：待开工。2026-10-20 项目主人照借鉴调研同意做（调研报告在主会话本机 `~/Downloads/miyu-借鉴调研-2026-10-20/`，不进仓库）。

### 目的

回复写到一半撞上输出上限（openai-chat 的 `finish_reason: length`、anthropic 的 `stop_reason: max_tokens`、openai-responses 的 `incomplete` 原因 `max_output_tokens`），现在三个驱动都当正常说完：截在半截的工具调用照样派出去（参数是半截 JSON，拿到「参数不是对象」），只有正文的停在半句、这一轮就结束了。改成认得出截断：截断的回复里的工具调用一个都不派，告诉她拆小了接着做；只有正文的接着写；连着截断有上限。

### 怎么做（技术题，主会话照推荐定）

1. 驱动的收尾 `Ending` 多一格 `truncated`：上面三种原因，加上 anthropic 的 `model_context_window_exceeded`（输入加输出撑满了窗口，同样是没写完）。照旧算正常说完，不是错。经 `Outcome::Ended`、路由、`Input::ModelEnded` 交到内核。
2. `model.called` 多一格 `truncated`（只有截断的写 `true`，以前的日志读写一字不差），取证用。
3. 内核收到截断的、成功的那一次（`model_ended` 的成功分支）：
   - 回复里有工具调用：调用一个都不派（最后一个必是半截，前面几个是一个整体里的前半，单派前半同样会错）。记下的 `message.assistant` 去掉调用块、标 `interrupted`，照被打断的样子回放；接着记一条事实 `output_limit`（新文件 `resources/core/facts/output-limit.txt`，见下），马上再请求，不等。
   - 只有正文、思考：照「被打断的回复接着写」（设计 05 第七节，`reply_cut`）走，会接着写的供应商前缀续写，不会的带那一句。
   - 什么都没写出来（思考吃光了输出）：照有工具调用的那一种：记事实、再请求。
4. 上限：一轮里连着截断 3 次（照 Claude Code 的恢复次数），第 4 次照出错结束这一轮，错误类 `output_limit`（新），给人看的一句「回复超过了输出上限」。成功的一次（没截断）清零。和重试的 `turn.retries` 分开数：截断不是供应商的错，不退避。
5. 事实那一句照设计 26 第十节登记（量 token、写为什么加）。草稿：`<output-limit>Your reply hit the output limit, so none of its tool calls ran. Split the work into smaller steps, such as writing a long file in several edits, and continue.</output-limit>`，开工时实测：截断以后不加它，她是不是照原样再写一遍、再截断（加之前先证明不加不行）。

### 蓝图改哪几节

- `drivers/openai-chat.md`、`anthropic.md`、`openai-responses.md` 的「收尾」：截断照旧算正常说完，多报 `truncated`。
- `kernel/session.md`「回复怎么收」：截断的三种情形、上限。
- `kernel/events-bodies.md`：`model.called` 的 `truncated`，`context.injected` 的种类加 `output_limit`，错误类加 `output_limit`。
- `prompts.md` 跟着登记簿重写。
- 协议：错误类多一个，告诉两个头和接入QQ。

### 不做什么

- 截断以后调大 `max_tokens` 再试（Claude Code 第一次截断会把上限抬到 64k）：要看模型资料的最大输出、各家收不收，另开一张。
- 把截断前写完整的工具调用挑出来先派。

### 验收

- 三个驱动各一条：截断的原因交出 `truncated`，别的原因不交。
- 内核：截断、带调用的不派、记的回复没有调用块、事实一条、马上再请求；只有正文的照接着写；连着 3 次以后第 4 次出错结束、错误类对；中间成功一次清零；以前的日志载入一字不差。
- 真模型：开发端点把最大输出压小（例如 300），让她写一个长文件，看拆成几次写完。
