## 施工单 Q-3：扩展登记旁路请求

状态：核心的分会话做。设计 `43-旁路请求和档位池.md` 第三节第 2、3、4 条，第五节第 3 条；排在 Q-2 之后（主会话排期）。项目主人 2026-10-26 交代：做完以后通知各家会调模型的会话，照声明的档位改。

### 为什么

扩展在对话以外调模型（通讯平台判要不要回、顾问），只能写 `model.call` 的 `model` 或 `use`，不写的走 `models.chat`：每家扩展都得自己有一个配置项让人另配一遍，量大的判断也走主力模型。Q-2 给核心自己的旁路请求登了档位，扩展还没有路。

### 做了什么

1. 清单 `[[side]]`（`miyu-config` 的 `package/side.rs`）：一段一条，`id`（写法同命令名，包里不重）、`tier`（`lite`、`normal`、`flagship`，只认三个固定池名，`SIDE_TIERS`）、`name`、`summary`（照语言）。只有扩展包能写；`model.call` 谁都调得了，不另要能力。写错的报新代码 `bad_side`（三语提示），`miyu check` 查清单时照样报出来。清单格式认的表从 21 张变 22 张，中英作者文档 `manifest.md` 多一节。
2. 登记表（`miyu-models` 的 `side.rs`）：`Side` 的编号改成借字（`Side<'a>`），出厂的照旧是常量，扩展的借清单里的字，路由那一边不用另写；`Tier::parse` 照池名认回档位；测试守着清单那份档位名和 `pools::FIXED` 一样（`miyu-config` 在下层，用不上这边的）。
3. `model.call` 多 `side`、`session`（端点 `models/call.rs`）：`side` 只认这个扩展自己包里登记的编号（`models/side.rs` 照核心手里的清单找，包卸了跟着没了；人的连接没有包，一律不认），和 `model`、`use` 不能同写；`session` 只跟着 `side`，是用不上档位池时退到的那个会话（取它这一刻的引用），不写的照 `models.chat`；不是自己的会话在连接那一道当作没有（`session_not_found`，原来就有的那一道）。走 Q-2 的 `OneShot::call_side`：池有成员的照池挑，空的、全冷却、都出错的退。
4. `model.list` 的 `side` 带上扩展登记的：编号 `<包>/<编号>`，名字、说明照连接的语言从清单里取，和出厂的一起照编号排。
5. 文档：图纸 `models.md`（旁路请求第 7 条、`model.call` 参数和拒绝、`model.list`、在哪、测试表），`packages.md`（样本、种类能写的表、`bad_side`、在哪、测试表）；协议参考 `config.md`（中英）；作者文档 `manifest.md`、`extensions.md`（中英）。

「`miyu check` 提没有的编号」照这样做：编号只在运行时的 `model.call` 里出现，静态查不到；`miyu check` 查的是清单，`[[side]]` 写错的（编号、档位、名字、说明、重了）照清单的问题报。运行时写了没登记的编号回 `bad_params`，记一行 `DEBUG unknown side request`。

### 不做的

- 池的路由补齐（`ordered`、窗口剔除、`quota`、非 API 应答、全冷却只探一个）：Q-4。
- 通讯平台、顾问各自改成写 `side`：各自的会话做（合了以后通知）。

### 合了以后

通知会调模型的会话（项目主人 2026-10-26 交代）：通讯平台判要不要回登记 `lite`，别的照用途选档；写法见作者文档 `manifest.md` 的 `[[side]]`。

### 验收

1. `miyu-config` 的 `package/side/tests.rs`：读对编号、档位、名字、说明，三档都认；编号写错、少了、重了，档位不认识、少了，少了名字、说明报 `bad_side`、`detail` 对；不认识的格、写成一张表、不是扩展包的照各自的代码。
2. `miyu-models` 的 `side/tests.rs`：清单的档位名就是三个固定池，照池名认得回来，扩展的编号借字。
3. `miyu-endpoint/tests/model_call_side.rs`（扩展经真的路由调模型）：登记了的照档位从 `lite` 池取；没登记的、别的包登记的、和 `model`、`use` 同写的、`session` 不跟着 `side` 的、人的连接写 `side` 的都拒、都没发；池是空的，写了会话的照会话的模型、没写的照 `models.chat`；`model.list` 列出扩展的、照编号排、档位和落点对。修以前两条都红（写了 `side` 照旧走 `models.chat`）。
4. 手改 9 个都红：写了 `side` 照旧走 `model`、别的包的编号也认、不照会话退、`session` 不跟 `side` 也放、`side` 和 `model` 同写也放、列表不带扩展的、档位一律 `lite`、清单不查档位、编号重了不报。
5. `cargo xtask check` 全过、Windows 版 clippy、三平台 CI。
