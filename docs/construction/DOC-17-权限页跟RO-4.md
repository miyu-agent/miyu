## 施工单 DOC-17：权限页、安全页跟上「只有整个数据根才问」

状态：待验收（2026-11-18）。跟核心的 RO-4、RO-4补：挪走、扔进回收站整个数据根也先问；数据根里面的文件、目录不再问，同别处。

### 改了什么

中文页、英文页同一处一起改。

- `guide/permissions`：
  - 讲数据根的那一段：「只有删整个数据根先问你」写成「只有删、挪走、扔进回收站整个数据根先问你；数据根里面的文件、目录同别处，不问」。
  - 「递归删除」一行：原来写「删数据根、数据根里的东西、装着它的目录」都问。改成：删、挪走、扔进回收站整个数据根或者装着它的目录，不管用哪个命令（举 `rm -rf`、`mv`、`gio trash`、`trash-put`、带 `--remove-source-files` 的 `rsync`），AI 用 `trash` 工具删也算；数据根里面的不问。
  - 「Windows 上的写法」那张表「递归删除（先问）」一行：加上删、挪走整个数据根或者装着它的目录，挪走的认 `Move-Item`、`Rename-Item` 和它们的别名。
- `guide/security`「AI 删掉 Miyu 自己的数据」一行：同上改。

DOC-11 说的「核心排了 RO-4，合了以后手册再跟」就是这一步。

### 实测

当前 main（`69a42031e`）编的 `miyu`，沙箱数据根，Linux，命令行 `miyu ask`（没有人能确认），真模型，9 次提问。这一次用 `bwrap` 把真的家目录换成空的，只把编好的程序只读放回来，提示里一律写沙箱的绝对路径（DOC-11 那次的教训）；跑前跑后真的家目录里看得见的只有放回来的那一个目录。

| 命令 | 结果 |
|---|---|
| `rm <数据根>/etc/z.txt`（数据根里的一个文件） | 跑了，文件没了，不问 |
| `rm -rf <数据根>/tmp-doc`（数据根里的一个目录） | 跑了，目录没了，不问 |
| `mv <数据根>/tmp-doc2 <别处>`（把数据根里的一个目录挪出去） | 跑了，不问 |
| `mv <不相干的目录> <别处>` | 跑了，不问 |
| `mv <数据根> <别处>` | 「没做：需要确认，无人确认」，末尾「miyu: 警告：1 步需要确认，已跳过」，数据根还在 |
| `gio trash <数据根>` | 同上，数据根还在 |
| `rm -rf <数据根>` | 同上，数据根还在 |
| `mv <装着数据根的目录> <别处>` | 同上，都还在 |
| `mv <数据根> <别处>`（英文界面） | 「not done: Needs confirmation, no one to confirm」，数据根还在 |

没实测：

- 人点了允许以后真的挪走、删掉：`miyu ask` 里没有人能点。
- `trash-put`、`rsync --remove-source-files`、`gio move`、`kioclient` 这几个：照蓝图 `tools/shell.md` 和核心的测试写，没逐个跑。
- Windows 的 `Move-Item`、`Rename-Item`，macOS。
