## 施工单 T-9 补：扩展能改自己包的配置项

状态：2026-10-18 在做。接入QQ 的会话 2026-10-17 要的，项目主人定「只许写自己包的项」；图纸 `docs/blueprint/config.md` 的 `config.set`、`protocol.md`。

### 起因

T-9 起扩展进程调 `config.set` 一律 `local_only`。接入QQ 连自己的 `onebot.whitelist` 都写不了；项目主人要 AI 能用工具改私聊白名单、群白名单（只有终端管理员叫她时才动），以后的场所卡片也要写。

### 定了的

1. 核心拉起的扩展能逐项改系统配置里键以自己的包编号开头的项（`onebot.*`），留痕的 `by` 记成这个包（模块）。
2. 照旧 `local_only` 的：个人设置、别的键、整份换的。
3. 密钥类的项（密钥、密钥的列表）、写成引用的值（`{ secret = … }`、`{ env = … }`）也不收（主会话定）。扩展握手时拿到的自己的密钥是真值：要是能改引用，就能把自己的项指到别人的密钥、环境里的 API key，再读回去。
4. 密钥（`secret.set`、`secret.delete`）照旧不给扩展。

### 做了什么

- `miyu-endpoint`：
  - `config::set::set_from_package` 查上面几条，过了走原来的 `set_by`，记成这个包；
  - 分派照调用方是不是扩展走它（`methods.rs`）；
  - 门口那一关不再一刀切挡 `config.set`（`connection.rs` 的 `people_only`）。

### 测试

- `extension_config.rs` 的 `an_extension_sets_only_its_own_plain_settings`：测试扩展自己发七次 `config.set`。
  - 自己的 `echo.port` 改成了，留痕记成 `echo`；
  - 自己的密钥项、写成 `{secret}`/`{env}` 引用的（两种写法）、别的包的键、个人设置、整份换的都 `local_only`，引用一个都没写进去。
- 手写变异：不查直接放行的、门口照旧一刀切挡的，这一条都红。
