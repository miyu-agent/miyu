## 施工单 V-7：三家对比进仓库

状态：合了（2026-10-15，90a4d57c，CI run 38643158690）。性能五条的第五条（2026-10-14 项目主人定）：发版前和 jcode、codex 比一次。10-14 那一趟的测具是临时写在仓库外的脚本，端点、家目录、程序的位置都写死在里面，换台机器、换个人就跑不了。

### 这一步做什么

1. 测具进仓库 `bench/rivals/`（Python，`uv run` 直接跑，依赖只有 `pyte`）：每一家怎么配、怎么起、看到什么算首屏、长会话的编号怎么找、装好的是哪几个文件写在 `rivals.toml`，加一家只加一张表。
2. 端点、key、模型名只从环境变量来（`OPENAI_BASE_URL`、`OPENAI_API_KEY`、`MIYU_BENCH_MODEL`）：key 留在环境变量里交给各家，不写进任何文件、不打印；Miyu 配模型走 `miyu config set`，写成 `{ env = … }` 引用。结果只记模型名，不记地址。核心、终端界面、jcode、codex 照参数找，不写死路径。
3. 跟 10-14 那一趟比改了的，后四条是量的时候查出来的测具自己的偏差，改完从头跑：
   - 终端界面的包从终端仓库的 `tui/` 装，包名对了，`tui.*` 的设置生效（以前从一个改了名的目录装，包名错了）。
   - 做模板时等终端界面整个安静下来再存：CPU、页缓存、进程三样都不动了才算（codex 第一次开会在后台 clone 插件仓库，只看 CPU 会在半截存下）。
   - 到首屏照读到画出那几个字的那一块当场记：以前隔一段才看一次屏幕，最多多算 50 毫秒，三家的首屏都偏大（Miyu 冷启动 53 → 18 毫秒）。
   - 空闲、三个会话同时开都先等 `--settle`（13 秒）再量，多量每秒醒几次、终端每秒收到几个字节；首屏后每秒的 CPU 都记下。实测 Miyu 到第 11 秒还有每秒 20 毫秒的活，第 12 秒起是 0；只等 1 秒时每秒醒 4.5 到 6 次，等 13 秒是 0.1 次。
   - 还原家目录后先 `sync`：拷模板留下的脏页会被被测程序的 fsync 一起刷，一轮 Miyu 的写盘凭空多出 17 MiB。写分开报交给系统的（`wchar`）和落到盘上的（`write_bytes`）。
   - 量的条件记三家的版本、核心和终端的提交、终端是不是 `heads.toml` 钉的那一份。
   - 每个子命令跑完查一遍输出目录里有没有 key：codex 会把环境写进自己家目录的 `shell_snapshots`。
4. CI 的量尺那一项先跑 `test_rivals.py`：表写得对、占位都认识、key 只经 `OPENAI_API_KEY` 交出去、汇表。
5. 图纸：`perf.md` 加「三家对比」一节和测试表一行；设计 23 加 F6。
6. 用这一份测具照核心 d426dc68、终端 2d7b5f5 量了一趟，结果 `docs/perf/2026-10-15-rivals.md`、同名 `.json`。

### 定了的（主会话，技术题照推荐）

- 用 Python 写，不进 `miyu-perf`：要驱动别家的终端界面、在伪终端里回答它们问终端的几样、读 cgroup，Python 加 `pyte` 一千来行；用 Rust 重写进量尺，好处只是同一种语言，花的力气配不上。发版前人跑一次，不随产品发。
- 只在 Linux 上量：CPU、内存照 cgroup v2 和 `/proc` 读。
- 不进 CI：要真模型和别家的程序。CI 只跑不用别家就能查的几条。

### 不做什么

- 不出网页汇总页：表进 `docs/perf/`，要给人看的另外做。
- 不量终端界面的按键到上屏、一帧多久：那是终端自己的量尺。
