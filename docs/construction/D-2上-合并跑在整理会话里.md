状态：待合（2026-10-20 写、施工、自己验收；2026-10-21 照核心的 D-1 下改了端口）。设计 `41-整理会话.md` 第五节 D-2：核心的 D-1 上（cdeaf2a9）给了整理会话和端口 `DreamSessions`，D-1 下（55efda8d）给 `batch` 加了正文增量、加了 `close`，这一步让记忆的合并跑在里面。原来要另做的 D-2 补（边收边推、跑完收）一起做进来。方向项目主人 2026-10-20 定（经网页的会话转来）；接口和主会话对过。

### 改了什么

1. **合并跑在整理会话里**（`memory/merge/ask.rs`，从 `merge.rs` 拆出来）：接了会话表的，这一趟真有要合的批时才开会话（没东西可整理的不开空会话），一趟一个；一批一轮（`<会话>/dream/<n>`，遮过 key 的原文）。`DreamSpec`：那一间的主人、哪一间、人叫的、人在哪个会话里叫的（只有人叫的记，`MergeJob.from`）、`memory.organizer`。人叫的、后台的都走（DS6）。
2. **交回怎么办**：`Answered` 照旧读、核对、落；`Failed` 数一次失败、连着三次跳过这一批（同一次性入口失败）；`Stopped`（会话自己停了）同人叫停、放弃这一批、不数；`Err`（会话那一路断了）这一趟停、不记没合成、不数。放弃了一批的这一趟到此为止（原来人叫停照循环开头那一道停，会话自己停了的会马上重问同一批）。
3. **叫停就是打断**（DS4）：`Hushes` 照旧是登记，听见了调 `stop`（另用编号 `<会话>/dream/<n>/stop`：和这一批同一个的会当成重发），等那一轮收尾。
4. **`session`**：`ext.memory.merging` 多 `session`（`miyu-recall` 的 `Merging`，旧的没有照读），`Dreamed`、`memory.dream` 的回应多 `session`。`Dreamed` 不再是 `Copy`。
5. **她正在写什么**（R-21，DS8 照留）：`batch` 边流边交正文增量（D-1 下的 `watch`，同一次性入口的 `Watched`），接到同一个 `MergeJob::watcher`（`Watch`），写完一条推一条；换了一次请求的先交 `Restart`，之前那几段作废。
6. **跑完收这一趟**（DS9）：不管合完、叫停、出错，一趟跑完调 `close(会话, memory.dream_keep)`（出厂 20，`0` 是连这一趟一起删），收不成的记一行 `dream session not closed`，不影响回执。
7. **没接会话表的**照旧走一次性入口（测试里的核心）；合完补关键词（R-15 下）照旧走一次性入口；用量照会话记，合并这一路不再记 `usage.oneshot`。
