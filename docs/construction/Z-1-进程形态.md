### 目的

现在核心是按需运行：头连上时拉起，没有头、没有回合、没有后台任务，空闲 10 分钟就退（`12-进程形态与分发.md` 第二节 R1）。通讯平台的桥、定时任务、离线收件箱（地基排期第 7 条）要核心一直在；自己有服务器的人，那台机器上没人坐着、没有头，核心要开机就起。这一步把默认改成常驻，给各平台的服务管理器各一份托管核心的写法，重点是个人机器上的用户级服务。

### 蓝图改哪几节

设计 `12-进程形态与分发.md` 第二节（运行形态）、第四节（安装渠道那张表多一列「开机常驻」）：

1. **空闲不退是默认**：系统配置多一项 `core.idle_exit`（分钟，`0` 是不退，默认 `0`），只在系统那一层（管理员定，个人设置里没有）。配了的照现在的规矩退（没有连接、没有在跑的回合，连续这么久）。`miyu core --idle-seconds` 照旧盖过它（开发、测试用）。头连不上核心时照旧自己拉起，这一条不动。
2. **两种托管**，`packaging/` 里各放一份，写进设计 12：
   - **本人的**（个人电脑、自己的账号）：
     - Linux 用 systemd 用户服务 `packaging/systemd/user/miyu.service`（`ExecStart=… core`，`Restart=on-failure`，`Type=simple`），`systemctl --user enable --now miyu`；没人登录也要跑的加 `loginctl enable-linger <账号>`（设计 12 原来就这么写）。
     - 没有 systemd 用户会话的桌面用 XDG 自启动 `packaging/xdg/miyu.desktop`（放进 `~/.config/autostart/`）。
     - macOS 用 launchd 的用户代理 `packaging/macos/miyu.plist`（放进 `~/Library/LaunchAgents/`，`RunAtLoad`、退出码不是 0 的重起）。
     - Windows 用登录时启动的任务计划 `packaging/windows/miyu.xml`（当前用户、不要管理员；设计 12 原来写的注册表 Run 键改成这个，主会话 2026-10-22 说的）。
   - **服务器的**（样例，主会话 2026-10-22 同意；说明里写清是给自己有服务器的人用的，第一版的重点是上面本人的那一层）：systemd 系统服务 `packaging/systemd/system/miyu.service`，用一个专门的系统用户 `miyu` 跑（`User=miyu`、`Environment=MIYU_HOME=/var/lib/miyu`、`StateDirectory=miyu` 让 systemd 建好数据根、`Restart=on-failure`）。
     - 不用用户服务加 linger：服务器上的数据根不该挂在某个人的家目录下面，那个人的账号停了、搬了，核心跟着没了。
     - 网页软件也给一份 `packaging/systemd/system/miyu-web.service`（`After=`、`Requires=miyu.service`，同一个用户）：服务器上的人都从网页进（地基排期第 2 条）。
     - 说明里写清两件：在 Y-1 下的第二个本机入口（`run/public.sock`）做好以前，本机的命令行要以 `miyu` 这个用户跑才连得上（`sudo -u miyu miyu …`）；沙盒要用户命名空间，systemd 的加固项不能写 `RestrictNamespaces=`（拦了 bubblewrap 要的用户命名空间）；别的加固项（`PrivateUsers=`、`ProtectHome=` 这些）验收时在容器里逐个试过、能用的才写进样例。
   - OpenRC、runit、dinit：`packaging/init/` 下各一份系统级的样例（同上，专门的用户、`MIYU_HOME`），一份 README 说怎么装、日志在哪。
3. **两个核心撞上**：已经有一个核心在跑（头先拉起了）时，服务管理器起的这一个照现在的握手说 `running`、退出码 0 就走，`Restart=on-failure` 不重起它；头拉起的那一个退了以后，服务管理器下一次起它才接手。说明里写一句：装好服务以后要它马上接手的，先 `miyu` 退干净再 `systemctl --user restart miyu`。
4. **`miyu service`**（Z-1 下，主会话 2026-10-22 定拆出去）：`miyu service enable|disable|status`，只管本人这一层：
   - 有 systemd 用户会话的写 `~/.config/systemd/user/miyu.service`（`ExecStart` 照 `miyu` 的真实位置填，安装脚本装的在 `~/.local/lib/miyu/`）、`systemctl --user enable --now`；
   - macOS 写用户代理、`launchctl bootstrap`；Windows 建任务；没有 systemd 的桌面写 XDG 自启动。
   - 系统级的不经它：要 root、要建用户，照 `packaging/` 里的说明手做。
   - 设计 12 原来写的「开启这些功能时 Miyu 提议把核心登记为服务」就是它；头的「设置」页以后调它。
   - Z-1 上只放文件、改默认、写文档。

别的几处：作者文档 `README`（中英）「装好以后」加一段「让核心一直开着」，指到 `packaging/` 和设计 12；蓝图 `cli/` 里 `miyu core` 那一段写上 `core.idle_exit`。

### 代码放哪

- `miyu-core` 的 `serve.rs`：`idle` 交 `Option<Duration>`，没有的不看空闲；`main` 读系统配置的 `core.idle_exit`，`--idle-seconds` 盖过它。
- 系统配置的一项（端点的设置表，同 `log.level` 那一类）。
- `packaging/{systemd,xdg,macos,windows,init}/`：文件和 README，不进二进制。

### 不做什么

- 不动头拉起核心那一条；不改握手。
- 不做 Windows 服务（要管理员）、macOS 的 LaunchDaemon（系统级）：第一版服务器只给 Linux。
- 不接 `sd_notify`：`Type=simple`，头连不上本来就会重试。
- 不写打包脚本（PKGBUILD、deb、rpm）：写打包的那一步照这里装（用户服务装进 `/usr/lib/systemd/user/`，系统服务的样例装进文档，不默认启用）。
- 升级时有人在线（地基排期第 18 条）是 Z-2。
