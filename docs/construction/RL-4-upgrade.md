## RL-4 `miyu upgrade`

状态：施工完，待 core1 审（2026-11-05，sub1）。设计 `12-进程形态与分发.md` 第五节 R10、`59-发版.md` 第三节第 2 条、第四节、第六节第 4 条；
蓝图 `docs/blueprint/cli/upgrade.md`。四条做法 core1 11-05 照推荐定了，另补了几处（下面「定了的」）。

### 目的

发版以后，用安装脚本装的人敲 `miyu upgrade` 就换成新版：自己问 GitHub、下载、照编进来的发版公钥核对、替换；包管理器装的说用哪条
命令；手工解开的说去哪下。哪一步不对都停下，装着的不动。数据根一个字节都不碰。

### 定了的（core1 11-05）

1. **认谁装的看标记文件** `install.toml`（程序真实位置的旁边），`channel = "script" | "aur" | "brew"`：
   - `script` 自己升；
   - `aur`、`brew` 只印升整套的命令：`paru -Syu`、`brew upgrade`。分包以后标记跟着 `miyu-core` 那个包装，不猜装了哪几个包；
   - 没标记的只印下载地址。
   不照路径猜（猜错了会去改包管理器的文件）。
2. **看新版**：GitHub Releases，草稿、预发布不算，`--pre` 才算（演练用）；只升不降。连不上、限流（匿名每小时 60 次）分开说，退出码
   非 0。仓库地址写 `miyu-agent/miyu`（发版当天旧仓库转进来叫这个名字）。
3. **签名**：下 `SHA256SUMS`、`SHA256SUMS.sig`，照编进来的发版公钥验，再照清单对压缩包的 SHA-256。公钥表（`sign::RELEASE`）现在是
   空的：空的时候明确拒绝，不跳过。主人生成钥匙以后把公钥填进来（同 `OFFICIAL` 的写法，换钥匙新旧并列）。
4. **换**：整个安装目录（程序加 `resources/`）一起换。解到安装目录里的暂存，先查（五个程序、`resources/`、新的 `miyu --version`），
   再逐样对换（Windows 上跑着的 exe 改得了名、删不掉；整个目录改不了名，所以不整个改）。另外两条：
   - 新版查不过、换到一半出错：删暂存，留着旧的不动，退出码非 0；
   - 安装目录没有写权限（被人装进系统目录又没写标记）：直接说清楚，不提权、不 `sudo`。
   - 核心重启：设计 04 第八节的 `kernel.restart_when_idle` 现在没有（蓝图 `core.md`、`protocol.md` 记作还没有的），不在这一步造，
     只提示 `miyu core stop`，下次打开就是新版。

### 做什么

- `crates/miyu-cli/src/upgrade.rs` 和 `upgrade/`：
  - `plan.rs`：标记、版本号（semver：数字逐段比，预发布排在正式版前，预发布逐段数字照数字比）、挑发布、压缩包名、清单里那一行；
  - `flow.rs`：怎么走（蓝图「怎么走」1 到 10），经 `World`（程序位置、网络、公钥、系统、现在的版本、跑 `--version`、问一句、说进度、
    改名）干活，测试换替身；
  - `net.rs`：`miyu-http` 的 `get_full`，照环境变量走代理；没有状态码的是连不上，`403`/`429` 带 `x-ratelimit-remaining: 0` 的是限流
    （带 `x-ratelimit-reset`），别的照状态码；
  - `swap.rs`：解开 tar.gz、zip，查缺什么，逐样对换（出错照反方向挪回），收拾上次留下的 `.miyu-old-…`、`.miyu-upgrade/`。
- `crates/miyu-cli/src/language/upgrade.rs`：中英文；报错照设计 47 第三节（`miyu: <事>`、`提示：…`）。
- 帮助页 `help/{zh,en}/upgrade.txt`，总帮助的「系统」一栏加 `upgrade`；`miyu/src/main.rs` 加子命令。
- `miyu_source::sign`：`RELEASE`（空）、`release()`；测试查表里的都读得成、编号对得上、和软件源那把不重。
- miyu-cli 加依赖 `miyu-http`、`sha2`、`tar`、`flate2`、`zip`：版本、特性同工作区里已经用着的，不多拉新包。
- 蓝图 `cli/upgrade.md`（新）、`cli/main.md` 的命令表和「还没有的」、设计 59 第六节指过来。

### 怎么验

- 单元 25 个（`upgrade/plan`、`upgrade/swap`、`upgrade/tests`）：见蓝图「测试」那张表。走一趟的测试用真钥匙（`sign::generate`）、真
  打的 tar.gz、真的临时目录，网络是照地址交回的替身；每一种停下的都查装着的没动、暂存删了。
- 手写变异（下面「变异」）。
- 本机（编出来的 debug `miyu`，拷进临时目录）：`miyu upgrade --help` 印帮助页；没有标记的说不自动升级、给下载地址，退出码 0；
  `channel = "aur"` 的说用 `paru -Syu`，退出码 0；`channel = "script"` 的报「这一版没有内置发版公钥」，退出码 1，英文界面同样；
  都没上网，目录里没多东西。

### 变异

手写 20 个，都抓住：不查公钥表、允许降级、不问、不验签名、不查清单写法、不对哈希、新版缺东西照放、不认 `--version`、没写权限不
单说、不删暂存、不收拾上次的、包管理器装的也往下走、预发布标记不看、草稿也算、预发布排到正式版后面、预发布数字照字比、出错不把
旧的挪回、出错不把新的退回、标记跟着挪走、没用完的 403 也算限流。第一轮没抓住三个（不收拾上次的、预发布标记不看、出错不把新的
退回），补了测试：上次留下的 `.miyu-old-0.9.0` 不删这一次就建不了；标成预发布、标签不带 `-` 的；退回以后暂存里新版六样都在。

### 没验到

- **真的 GitHub、真的下载、真的替换**：发版公钥还没有，`script` 的走到第 3 步就停；整条要等主人生成钥匙、填进 `RELEASE`、发了带
  签名的预发布以后，拿 `--pre` 在临时目录里装一份旧版试（RL-2 的演练之后）。
- **Windows 上对换跑着的 `miyu.exe`**：逐样改名是照 Windows 的规矩写的，测试在三平台 CI 上跑的是挪普通文件；真的跑着的 exe 要在
  Windows 上实测。
- 限流的判断照 GitHub 文档的头写的，没在真的限流下跑过。
