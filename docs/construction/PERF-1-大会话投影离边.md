## 施工单 PERF-1：开着记忆的大会话，一次请求的投影离开 5 ms 的边

状态：核心的分会话做。perf 闸门「一次请求的投影：开着记忆的大会话」两趟红过：bd8d563fb（run 40339401801）p50 2.5 / p95 5.2 / p99 5.7 ms，588214cf5（run 40352584555）p95 5.08 ms，预算 p95 5 ms。主会话派（2026-10-27）：闸门不许放宽；量出投影里哪一段贴着边，找能省的真优化，前后数字写进施工单。

### 查下来的

1. 两趟红的原始数据（`perf-raw`）：尾巴 30 轮里冒了一两个 5.2 到 6.0 ms 的尖，p95 照 30 个数就是第二大的那个；同一趟关着记忆的 p95 2.6、4.1 ms。开着、关着的 p50 只差 0.2 到 0.7 ms。
2. 量尺的「投影」从 `session.send` 的回应到假模型读全请求头。回应要等这一批后台同步完才交（V-19），回合不等：本机 NVMe 同步约 2 ms，比回合开头还慢，请求先到，本机量出来几乎全是 0；CI 上同步快，量到的就是回合开头整条路。所以在核心里临时插桩（只在本地，没提交），量回合开始（`turn_start`）到假模型收到请求这整段，绑两个核（`taskset -c 5,6`）学 CI，尾巴说 200 轮。
3. 两核上开着记忆的这一段 p50 2.63、p99 5.14、最大 6.49 ms，冒尖复现了。拆开（p50）：

   | 段 | p50 ms | 说明 |
   |---|---|---|
   | 冻结配置、换模型、私密目录 | 0.28 | |
   | 刷新人格（阻塞线程一跳） | 0.40 | 线程里干活约 0.31 |
   | 再找一遍技能（阻塞线程一跳） | 0.29 | 线程里干活约 0.23 |
   | 项目指令（阻塞线程一跳） | 0.07 | |
   | 挂接点：记忆的摘要、卡、联想 | 0.03 以下 | 记忆本身不是它 |
   | 内核组装 | 0.33 | |
   | 取 blob（阻塞线程一跳） | 0.02 | p99 0.52、最大 1.36：一个 blob 也不用照样跳 |
   | 编码（22 万字节） | 0.45 | 已经是直接写结构体，不经 `Value` |
   | 发出到假模型读全请求头 | 0.51 | |

4. 冒尖和记忆的回合线程写回合库不重叠（最慢的几轮重叠 0）：不是记忆抢核，是两核上的调度抖动，落在回合开头那几跳阻塞线程上。要离开边线只能让整条路短、跳得少。

### 做了什么

- 取 blob：驱动列的清单是空的不跳阻塞线程（`route/exchange.rs`）。
- 技能、项目指令：读盘的那一件先交出来，和挂接点、扩展放进同一个 `join` 一起等，回来再把技能文件夹换上（`actor/skills.rs` 拆成 `skills_turn` 和 `skills_take`，`actor/model.rs`）。两样都不借 actor，挂接点也不看技能文件夹；技能照旧排在刷新人格后面（换了人格工具面跟着变）。注入的先后不变：挂接点、扩展、技能、项目指令。
- 图纸：`http.md` 第 2 条、`session/actor.md` 跑挂接点那一行补一句。

### 前后

本机，同一台机器、同两个核、背靠背各跑一趟量尺（尾巴 200 轮），回合开始到假模型收到请求（ms）：

| | p50 | p95 | p99 | 最大 |
|---|---|---|---|---|
| 开着记忆，改前 | 2.76 | 3.89 | 4.91 | 17.48 |
| 开着记忆，改后 | 2.26 | 3.15 | 3.56 | 4.21 |
| 关着记忆，改前 | 2.56 | 3.32 | 4.80 | 5.08 |
| 关着记忆，改后 | 2.45 | 3.35 | 3.79 | 10.03 |

改后拆开：技能、项目指令那 0.36 ms 不再排在前面，并进了挂接点那一段；取 blob 那一跳没了。

CI 上改前就是开头那两趟红的（开着记忆 p95 5.24、5.08 ms）；改后照分支和合进去以后的 perf 摘要、`perf-raw` 看，数报给主会话。

### 验收

1. 改前改后照上面量，数写在这里。
2. `miyu-session` 整套（技能换文件夹、项目指令、挂接点、带图的请求取 blob 那几组）照过；`cargo xtask check` 全过、Windows 版 clippy、三平台 CI，perf 闸门过。
