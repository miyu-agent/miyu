### 已定

1. 是基础系统里的一个功能，预设能开关：名字 `project-docs`，界面上叫「项目指令」。通讯平台的场所会话一律不读。

### 同一天拍板的

2. **放在哪**：不放 system，因为文件一变整段要重算，缓存就断了。照 Codex 的做法，在会话开头作为一条事实注入。文件中途改了，原来那条不动，追加一句替换声明（Codex `core/src/context/world_state/agents_md.rs:11-13、44-69`）。压缩以后从磁盘重读、放回去，接进压缩后的重建（同 X-10 下的技能）。
3. **找哪些文件**：
   - 从工作目录往上找到仓库根（有 `.git` 的那一层）。从根到工作目录逐层收集：每层先找 `AGENTS.md`，没有再找 `CLAUDE.md`。离工作目录越近的放得越后。
   - 所有层共用一个总大小上限（Codex 默认 32 KiB）。超出的截断，并告警。
   - 工作目录不在仓库里的（例如 `~`），一份都不读。
   - shellhook 的终端会话每一轮都会换工作目录：同一个会话里每个仓库只注入一次，第一次走进那个仓库时追加。在同一个仓库里换子目录不重复注入。
4. **信任**：不设门，照 Codex、opencode。原来推荐复用 `.miyu/config.toml` 的信任，但那道门绑在项目配置那份文件的内容上，大多数仓库没有这个文件，复用了几乎都读不到。内容作为事实进对话、不当 system 的规则；她读 README 一样会读到仓库里的字，兜底的是权限和沙盒。

5. **出厂预设**：「基础功能」「全部功能」两个都开。
