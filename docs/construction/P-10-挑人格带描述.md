## 施工单 P-10：派子代理挑人格带上名字和简单描述

状态：2026-10-17 合了（2c5b2996）。2026-10-17 项目主人定；图纸 `docs/blueprint/tools/subagent.md` 的 `persona`、`personas.md` 的 `[persona]` 那一条、登记簿 `26-提示词.md` 的 `subagent`。

### 为什么

`subagent` 的 `persona` 只列编号。新建的人格由核心起编号 `persona-<n>`，她看不出该派哪个。项目主人定：人格的「简单描述」就是 `persona.toml` 现有的 `summary`，不另加字段，详细的写在人设里；派子代理时把名字和简单描述一起给她。

### 做了什么

1. `miyu-session` 的 `agents::persona_choices`：照编号列这台机器上的人格，每个叠好以后取 `name`、`summary`。
2. `persona_choice` 拼那一行：`<名字> — <简单描述>`；缺一样给另一样，都没有的只有编号；挑英文的（语言表没有英文的挑别的），换行并成空格；叠不成的人格照样列，只有编号。
3. 开会话（`open.rs`）、换预设重拼工具面（`actor/persona.rs`）都照它；进快照，整个会话不变。

### 代价

没建人格的一个字节不变（出厂不带人格）。每个人格多它自己写的名字和简单描述，样本的软件工程师多 14 个 token（o200k 数的）。

### 测试

- `agents/tests.rs` 的 `a_persona_choice_carries_its_name_and_summary`：两样都有、只有名字（中文）、只有简单描述、空的简单描述、都没有、叠不成。
- `tests/spawn/pool.rs`：工具面上 `persona` 的说明从 `engineer` 变成 `engineer: Software Engineer — Writes code and tracks down problems, no role-play`。

### 留下的

两个头：人格编辑里两样改叫「简单描述」「具体人格提示词」，网页那一段描述接 `summary`。
