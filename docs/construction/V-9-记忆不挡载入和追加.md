## 施工单 V-9：开着记忆的会话也在预算里（载入、追加不等回合索引）

状态：2026-10-20 合了（0d1d50c7）。2026-10-17 项目主人定，排在 P-12 后面。图纸 `docs/blueprint/perf.md`「怎么走」第 5 条、`memory.md`。

### 起因

P-12 起无人格的会话也有记忆，量尺的会话就是无人格的，main 上 perf 那台红了。本机同一台机器、同一套量尺对比：

| 项 | P-12 以前（7423fbd1） | P-12（67818084） | 预算 |
|---|---|---|---|
| 重启以后打开大会话（连上、握手、订阅） | p95 24.4 ms | p95 114.3 ms | p95 50 ms |
| 追加一条事件并同步 | p99 10.5 ms | p99 77.7 ms | p99 20 ms |

多出来的是回合索引：
- 载入时开回合库、把整份事件过一遍 `TurnFeed`（`miyu-session` 的 `memory.rs`，`Turns::connect`）。
- 追加时写回合库（`Turns::advance`）。

带人格的会话一直付着这一笔，以前量尺的会话不接记忆，没量到。

项目主人定：量尺原来那一组照旧量不开记忆的会话（造会话写 `memory: off`，和 P-12 以前量的一样）；另开这一张，把记忆挪出关键路径，再给量尺加一组开记忆的，用同样的预算卡。

### 打算

1. 先量清楚慢在哪：开库、读照到哪、`TurnFeed::primed_on` 过一万条、追加时写库，各占多少。
2. 载入不等回合索引：接上记忆交到后台线程，头订阅、能提交第一轮不等它；它没好之前落盘的批次排着，好了照先后补。
3. 追加不等回合库：写回合库挪出会话的落盘回调，和检索库一样在后台按批写；会话停下、崩了，下次载入照「照到哪」补上（本来就有这一套）。
4. 量尺加一组：同样的几项，会话开着记忆，同样的预算。

开工前照这一节量出的数字再定第 2、3 条的做法，有要拍板的另问。

### 量出来的（第 1 条）

本机同一套量尺，大会话开着记忆（无人格，`memory: persona`），载入时接上回合索引那一段拆开量（5 次）：

| 段 | 用时 |
|---|---|
| 开回合库（`RecallIndex::open`：`quick_check`、补表） | 26–32 ms |
| 读照到哪 | 0.1 ms 以内 |
| `TurnFeed::primed_on` 过一万条 | 5–6 ms |
| `UseFeed::prime` | 0.2–0.3 ms |
| 写库（照到的位置已经在最后，没有要写的） | 0 |

大头是开库时的 `quick_check`：跟它的库一样大，跟着人格的那一间攒着这个人格所有会话的回合，越用越大。追加那一项量尺在进程里直接写日志、不经回合索引，开不开记忆都量不到；会话里每一批落盘以后写回合库原来也在落盘回调里同步做。

### 做了什么

1. 回合索引在后台写（`miyu-session/src/memory/lane.rs`）：核心一个线程（`memory-turns`），照交来的先后做三样：接上（开库、对照到哪、读日志铺回、补上落下的）、往前写一批、放下。会话载入、新造、换人格时交一件接上，落盘以后交一批，都不等。同一个会话的几件照交的先后，一批不会赶在接上前面。
2. 载入时后台自己再读一遍日志铺：载入读到的那一份交给会话重放，不拷一份。后台读到的可能已经有载入以后又落盘的几条，后来交来的一批里照铺到的那一条以后看，已经铺过的不再看（不然同一个 `turn.started` 看两次，这一轮就丢了）。
3. 换人格时照旧在阻塞线程里读回日志认换的那一条（抽取从它以后抽），读回的整份交给后台铺，不再读一遍。
4. 搜以前的对话（她的 `memory_search`、协议的 `memory.turns`）、读用到几次、删会话以前先等后台把这时交过的写完：搜到的是落了盘的全部，删掉的不会再被一批写回来。交了还没做完的有个数，没有的不等。出处活不活不等：回合开始的摘要要用它，等的话打开会话后头一轮又要等接上。
5. 回合库本来就照照到的位置认落后的一批不写；会话停了、核心退了后台还没写的，下次载入照日志补上，和原来更新失败一样。
6. 量尺加一组（施工单第 4 条）：大会话再造一个开着记忆的，重启打开、投影、从头投影三行照同样的预算比，过不了一样拦；原始数据记在 `large_memory`，以前的原始数据没有这一组照样读得回。

### 验收

本机量尺（同一台机器，改之前、改之后都开着记忆）：

| 项 | 改之前 | 改之后 | 预算 |
|---|---|---|---|
| 重启以后打开大会话 p95 | 114–129 ms | 27.7 ms | 50 ms |
| 载入时接上记忆（`memory_ms`） | 37–113 ms | 0.1 ms | — |
| 一次请求的投影 p95 | 8.8 ms | 2.9 ms | 5 ms |
| 从头投影 p95 | 19.2 ms | 10.5 ms | 50 ms |

关着记忆的那一组照旧（重启打开 p95 23.5 ms）。一间新建的人格回合库第一次说话会多等建库的那一下（本机 40 ms 一次，建库占着登记的锁），一间只有一次，不在预算的几行里。

- `memory::lane::tests::what_was_laid_from_the_log_is_not_seen_again`：日志里已经有这一轮的开头、交来的一批里又有一遍，这一轮照样记上；拿掉「已经铺过的不再看」就红。
- 原来直接读回合库的测试先等后台写完（`Memory::settle`）；`memory::each_turn_goes_in_and_undo_and_restore_follow` 不等就红。
- 量尺的表测试：开着记忆的三行出在表里、超了照名字拦、原始数据读回一样。
- 本地门禁八项。
