## 施工单 ipc 补：Windows 上管道忙多等一会

状态：施工中（2026-10-12 主会话）。图纸 `docs/designs/04-核心协议.md` 第二节「各平台的坑」，施工 3-8 补的那一段。

### 为什么

F-10 下上的 CI（run 1938）Windows 那一台偶发红：`ask::a_core_without_a_model_says_so` 里 `miyu ask` 报「All pipe instances are busy (os error 231)」。命名管道一次只开一个等着的实例，核心接走一个连接以后才开下一个；头碰上「管道忙」歇 50 毫秒再连，最多 100 次、5 秒。CI 的 Windows 机器负载重时，核心 5 秒内没轮到开下一个实例，头就放弃了。重跑同一份提交是绿的。

### 做了什么

1. 头连管道碰上「管道忙」最多等 30 秒（`miyu-ipc` 的 `windows.rs`，`BUSY_TRIES` 100 → 600），歇的间隔照旧 50 毫秒。别的错照旧当场交回。
2. 测试（`tests/pipe.rs`，只在 Windows 上编）：第一个头占着等着的那个实例，核心 6 秒后才去接；第二个头一直碰「管道忙」，核心接走第一个、开了下一个实例以后连得上。

### 先红

只带测试、不带修的那一份推上去跑（run 1953）：Windows 上这一条报红，第二个头 5 秒就放弃了，报的正是 `Os { code: 231, message: "All pipe instances are busy." }`；带上修以后转绿。

### 定了的（主会话）

- **只加长等的时间，不换 `WaitNamedPipe`**：头本来就在退避重试，问题只是窗口太短；30 秒内核心总会开下一个实例，核心真没了的照旧马上报「没在跑」（`NotFound`）。
