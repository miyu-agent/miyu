## 施工单 R-15 下：记忆的关键词（谁来写）

状态：做好了（2026-10-19 写、施工、自己验收）。项目主人 2026-10-19 定：记录时写关键词，旧的整理（dream）时顺带慢慢补，模型照「整理记忆的模型」（`memory.organizer`，不写的照默认文本模型 `models.chat`，项目主人同一天问过、照推荐不改）。上一步（R-15 上）做了数据和协议。剩下的是技术细节，照施工方案第一节第 1 条直接做。

### 量下来的（2026-10-19，开发端点 `group/auto-deepseek-v4-1-flash`，主人旧版的真对话、真记忆，仓库外）

写关键词不能塞进抽取、整理原来那一次请求：

| | 不加关键词 | 加了关键词 |
|---|---|---|
| 抽取：25 段对话抽出几条 | 14、20、19（三轮） | 27、26、34；换一种写法 29、23 |
| 整理：200 条里改了几条 | 23、25 | 7、12 |
| 整理：200 条里作废几条 | 13、9 | 4、6 |

抽取多记五六成（多出来的有「系统快照显示负载 18.86」这种很快就过时的）；整理改、作废的少了一半，合掉矛盾、剔除过时的正是整理的本分。所以另发一次只写关键词的请求：同样 200 条每 20 条一批，200 条都写上，一条约 270 个 token（这个模型的思考占大半），关键词中位 116 个字。

### 定了的

1. **一次只写关键词的请求**（`resources/software/memory/tag/instruction.txt`，登记簿）：几条记忆，一条一行（照 `memory_search/memory.txt`），交回 `{"keywords": [{"id", "keywords"}]}`；照 `memory.organizer` 发、用途 `memory` 记账、遮 key 同抽取。只收交进去的编号，关键词照 `miyu_recall::keywords_of` 整理（太长的截断）。
2. **记下的时候**：抽取记下了几条，接着给这几条写（抽取记完的那一个后台里，不挡下一次抽取）。
3. **整理的时候顺带补旧的**：整理落完以后，挑这一间现在算数、还没有关键词的最多 20 条写：这一次交进去的在前，再照新的在前补满。她当场记没写关键词的、以前的都这样慢慢补上（项目主人定「旧记忆就在 dream 的时候整理」）。
4. **只写还没有的**：落的时候（追加 `ext.memory.tagged`）那一条还算数、听众合、还没有关键词的才写：人改过的、她当场给了的不盖。写完照新的字补向量。
5. **出错**：发不出去、交回读不成的记一行 `WARN memory tagging failed`，不重试；整理时没写上的下次整理照样挑得到。成了记一行 `INFO memory tagged count=… took_ms=…`。

### 不做什么

- 抽取、整理原来那一次请求一个字都不改。
- 一次性补全旧的：项目主人定慢慢补。

### 验收

1. 测试先写，没实现时红：抽取记下以后写上这几条的关键词、只收交进去的编号；整理以后补没有的、交进去的在前、最多 20 条；有了的、作废的不写；写不成的不碍抽取、整理。
2. 手写变异五个左右，全被逮住；`cargo xtask check` 八项；三台 CI。
3. 登记簿：`tag/instruction.txt` 照开发端点量，写上为什么加。

### 施工结果（2026-10-19）

1. **测试**：`memory_tagging.rs` 四条、`miyu-recall` 的 `tag/tests.rs` 三条。七个手写变异逮住五个、两个等价的照改：「作废的也挑」——作废的、改掉的、清掉的本来就被 `shown` 挡住，挑和落的时候各多查的一道 `current()` 去掉；「不限条数」——最后照 `limit` 截断，循环里提前停只是省事。头一回「落的时候盖掉有的」漏了，另加一条：假服务器晚 0.8 秒回，这期间替人改上关键词，回来以后不盖。
2. **测试场地**：写关键词的字做成可选（`Extraction::tag`，核心总交）：场地照旧只交抽取、合并的字，原来按先后备回答的十七条测试不用重排；`organizer_tagging` 另交。
3. **挑哪几条**：合并时「交进去的在前」原来照编号从小到大，第一次合并（还没有摘要，以前记的都算新的）先挑了最旧的；改成交进去的也照新的在前。
4. **登记簿**：`tag/instruction.txt` 照开发端点量 91 个 token，一行记忆约 27 个。
5. 抽取的 `record_extraction` 交回记下的编号（原来交条数），接着给这几条写。
6. **真核心的两条**：端点的 `memory_dream.rs` 用真核心（总交写关键词的字），合并以后、`/dream` 抽完以后各多一次请求：备的回答照先后插上，数的请求数改了，写明为什么多。
7. **拆文件**：`merge.rs` 超过 500 行，合并以后补关键词那一段挪进 `memory/tag.rs`。
