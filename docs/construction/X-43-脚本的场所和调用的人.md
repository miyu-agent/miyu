## 施工单 X-43：脚本的场所和调用的人

状态：在分支 `step/X-43-脚本的场所和调用的人` 上，等主会话审。安全的一步，排在 X-42 上之后、X-44 之前（主会话 2026-10-22 排）。

### 目的

shorin-ac 会话把旧 Miyu 的 16 个脚本移植成包时撞见的：B 站直播的脚本登录态全机共用，群里有人叫 AI「改直播标题」，用的是主人的账号，脚本自己挡不住。这一步给脚本两样：开头注释写 `Venues` 限定在哪种会话里有；跑的时候拿到调用的事实（哪种场所、开口的是不是主人），照它调整行为。

### 蓝图改哪几节

`skills.md`「脚本」：

1. **开头注释多一格 `Venues`**（中文 `场所`）：写法同扩展工具清单的 `venues`，`local`、`private`、`group` 几种，逗号或空格分开；不写的照现在哪种会话都有。写错的（不认识的词、空的）整个脚本跳过，`miyu check` 照 `script_skipped` 报。写了的，工具照它给哪种会话：不在里面的会话，工具面上没有它（同扩展、MCP 工具照 `venues` 筛，`Tool::venues`）。**这才是门**。
2. **调用的事实**（宿主产生）：核心当工具跑脚本时，先去掉继承来的 `MIYU_CALLER_*`，再设这一次的：
   - `MIYU_CALLER_VENUE`：本机的会话是 `local`，场所会话是场所编号（`qq:group:123` 这样）。
   - `MIYU_CALLER_OWNER`：这一轮开口的人是不是机器主人，`1` 或 `0`。本机的会话是 `1`；场所会话照 E-0 的 `speakers`（回合开始照这一轮的消息算一次，记在这一轮上，派工具时交给执行器）：有开口的人、每个都是主人才是 `1`，别的（陌生人、群里几个人、不是人开的一轮）是 `0`。
   - shell 跑命令时同样去掉 `MIYU_CALLER_*`：核心自己的环境里有残留的不带进去。
3. **只是事实，不是门**：AI 在命令里自己写 `MIYU_CALLER_OWNER=1 ./脚本` 挡不了。要挡场所写 `Venues`；群聊、陌生人私聊的会话里 shell 本来就拒、只碰得到自己的工作区，伪造不进脚本工具。环境变量只用来调整行为（比如群里只读、不改东西）。作者文档写明这一句（主会话 2026-10-22 定）。

别的几处（中英）：作者文档 `scripts-skills` 开头注释的表加 `Venues`，「跑起来」加两个环境变量和上面那一句；顺手改一处：开头注释写完要空一行再写别的注释，不然说明里一句「Timeout: …」会被当成开头读（shorin-ac 撞见的）。

### 不做什么

- 不按人放行、不做白名单：门只有 `Venues`，人是不是主人只交事实。
- 扩展的工具、MCP 工具不加这两个环境变量：扩展拿 `tool.call` 的参数，MCP 不归核心管。

### 验收

1. 先写会红的测试：
   - `miyu-policy`：`Venues` 读成几种，中英文的键名都认，写错的报 `BadVenues`；不写的没有。
   - 真核心：写了 `Venues: local` 的脚本，本机会话的工具面上有、群聊会话的没有；不写的两边都有。
   - 跑起来：本机会话里脚本拿到 `MIYU_CALLER_VENUE=local`、`MIYU_CALLER_OWNER=1`；群里陌生人开口的一轮拿到场所编号和 `0`；主人在群里开口的是 `1`；核心的环境里先放一个 `MIYU_CALLER_OWNER=1`，脚本、shell 命令里都看不到这个残留。
2. 手写变异 12 个左右。
3. `cargo xtask check` 全过；本机跑 Windows 的 clippy；碰子进程的环境，推 `step/` 过三台 CI。

### 风险

- `speakers` 里一轮几个人：只要有一个不是主人就是 `0`，宁严。
- 子代理的会话：照它自己的场所（继承父会话的场所）算，没有人开口的一轮是 `0`（场所会话）或 `1`（本机）。
