## 施工单 W-7 四补：B 站视频先调接口

状态：合了（2026-10-22）。终端会话报（项目主人问的）：B 站视频链接没有卡片，YouTube 的有。图纸 `docs/blueprint/net.md`「怎么走」第 12 条第 1 款、「起草时定的」第 14 条。

### 根因（实测，2026-10-22）

- 项目主人的核心日志：`link preview failed host=www.bilibili.com why=unreachable`，之后两次 `why=no_preview`。
- 视频页 `/video/BV…` 对谁（像浏览器的 `User-Agent`、curl 的）都只回一页 4.6 KB 的拦截页：没有 `__INITIAL_STATE__`，也没有 og。
- 接口 `api.bilibili.com/x/web-interface/view`：像浏览器的 `User-Agent`（核心用的就是）回 HTTP 412；`Miyu`、`curl/…`、不带 `User-Agent` 都回 `code: 0`，标题、封面、UP 主、时长、简介都在。10-03、10-14 那两次「接口回 412」都是带着像浏览器的 `User-Agent` 试的。

### 做了什么

- B 站视频页先调接口：协议、端口照视频页，主机、路径、`User-Agent` 照 `link_preview.json` 的 `api_host`、`api_path`、`api_user_agent`（`Miyu`）；`bvid`、`aid` 照路径。`code: 0` 的照接口做卡片，不读页面；封面的 `http:`（没写端口的）换成 `https:`；图标照视频页的 `/favicon.ico`。风控拦下的（HTTP 412，`code` 是 `-412`、`-352`）当过会儿再试（`unreachable`），不读页面；别的退回读页面（原来那一套），记 `link site fallback`。
- 终端会话转来项目主人的建议：照旧 Miyu 直播脚本的那套请求头（像浏览器的 UA、`sec-ch-ua`、`sec-fetch-*`、`origin`，再加 `referer`）。本机实测这一套整套带上照样 412，`Miyu` 连着五次 200，所以用不像浏览器的 `User-Agent`。
- `Fetcher::json` 多一个可以不写的 `User-Agent`。
- 测试：单元测试接口地址和封面；`tests/sites_api.rs`（`tests/sites.rs` 过了 500 行，拆出来）先调接口（`User-Agent`、主机、不读页面）、风控拦下的 HTTP 412、`-352` 是 `unreachable` 且不读页面、别的 `code`（`-404`）退回读页面、原来读页面的那条照样过（多查每张卡先调了一回接口）。变异 8 条全杀。
