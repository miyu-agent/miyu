## 施工单 X-34：包里的程序可以是脚本，Windows 上照 `#!` 找解释器

状态：主会话审过（2026-10-20）；项目主人定做 Python 开发包，这一步是它的前提。M-3 改了 `basesystem/shell.rs` 的几行模块声明，没碰 `shell/script.rs`，等它合了再动最省事。

### 目的

现在包里的程序在 Windows 上只找 `bin/<名字>.exe`，Python 写的扩展得用 PyInstaller 打成 exe。改成：一个带 `#!/usr/bin/env python3` 的 `bin/<名字>`，三个平台都能直接跑，Windows 上照脚本工具那一套找解释器。Miyu 本体不带解释器，用的是系统里装的（同脚本工具，`skills.md`「脚本」第 3 条）。

### 蓝图改哪几节

- `packages.md`「转交」、`extensions.md`「怎么走」第 1 条（找程序）：先找 `bin/<名字><可执行文件后缀>`、`miyu` 旁边的，照现在；Windows 上都没有的，再找 `bin/<名字>`（没有后缀的文件），照它第一行的 `#!` 起（`python3` 换成 `python`，同脚本工具），没有 `#!` 的当没找到。Linux、macOS 上照旧直接起（系统认 `#!`），文件要有可执行权限。
- 找解释器的函数从 `miyu-basesystem/src/shell/script.rs` 的 `launcher` 挪到扩展、转交、小程序都用得到的地方（`miyu-store` 的 `packages::locate` 旁边），脚本工具照用它，一份代码。
- 扩展、`miyu <命令>` 转交、小程序三处拉起照它：交回「程序加前面的参数」，不再只是一个路径。
- 解释器没装的（Windows 上找不到 `python`）：扩展记成停下 `cannot_start`，原话写「找不到 python」；转交照「程序未安装」的退出码 1。
- 作者文档 `README`「三个平台」、`extensions`（中英）：去掉「Windows 上 `bin/` 里要放 `.exe`、用 PyInstaller」，改成一个带 `#!` 的文件三个平台都行，要求装了解释器的写进包的说明。

### 不做什么

- 不替人装 Python、Node（同 MCP：别人的活不揽）。
- 不认 `.py` 这类后缀当程序名：清单的 `program` 照旧是名字，文件名就是它，三个平台一份清单。

### 验收

1. 先写会红的测试：包里只有 `bin/<名字>`（`#!` 指向测试用的一个小程序）的扩展，Windows 上照它拉起、握手；Linux、macOS 照旧；没有 `#!` 的报没找到；脚本工具的测试照旧全过（挪过去的 `launcher`）。
2. 碰子进程、Windows：推 `step/` 分支过三平台 CI（AGENTS.md「施工的规矩」第 2 条）。
3. `cargo xtask check` 全过。

### 风险

- Windows 上 `python` 是应用商店的占位程序：照脚本工具现在的做法，起不来的照实报，不猜别的路径。
