## 施工单 B-5：用量相加不溢出

状态：做完，等合。漏洞排查会话 2026-10-22 的鲁棒性测试复现。

### 根因

用量是供应商报的任意 `u64`，十来处直接相加：算金额（`miyu-models` 的 `price.rs`）、索引一行的 token 和上下文、会话的累计、用量汇总、一次性入口的日志、视图的收尾和状态、`miyu ask` 的汇总。报得离谱就溢出：debug 下 panic，release 下绕回去、挑错价格档。

### 做了什么

- 内核的 `Usage` 多三个方法：`input()`（三种输入加起来）、`total()`（再加输出）、`plus()`（两份各项相加，思考两份都没报的照旧没有），都封顶不溢出（`saturating_add`，同内核 `estimate.rs`）。
- 上面那些地方都改用它们；`miyu ask` 的汇总是自己的结构，照样封顶。
- 补丁里的 `robust_methods.rs`（148 个方法各喂十几组怪参数，现在是绿的）留下，装了全进程的 panic 钩子，照规矩单独一个测试程序（`Cargo.toml` 另列 `[[test]]`）。

### 验收

1. `price::tests::a_huge_usage_report_does_not_overflow`（补丁里的，修前 panic）。
2. 变异（`input()` 改回直接相加）报红。
3. `cargo test -p miyu-endpoint --test robust_methods` 过。
4. `cargo xtask check` 八道全过。
