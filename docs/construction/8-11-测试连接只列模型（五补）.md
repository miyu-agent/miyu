## 施工单 8-11 五补：测试连接只列模型

状态：已合（2026-10-13，c17e9f54，CI run 2017）。项目主人验收第一次引导时卡住以后定的（2026-10-13）：测试连接列得出模型就算通，不再拿一个模型真发一句；列不出模型时填模型名、拿它发一句短话验证；测不通时给「仍然保存」，可以接着走。图纸 `docs/blueprint/models.md`「协议」`provider.test`、「怎么走」第七条第 4 条，`docs/blueprint/cli/setup.md`「怎么走」第 7、8 条。

### 为什么

- 原来 `provider.test` 列完模型还要挑一个真发一句。没写模型的挑「能调工具、窗口够大、发布最晚」的那个；中转（magpie）上这个正好是 OpenCode Zen 的免费档，回 403，于是命令行 setup 说认证失败、退回去重贴 key，终端、网页的引导停在「测试连接」过不去。
- 列模型本身就验过了地址和 key；真发一句只多验一个模型，还花额度。
- 测不通就过不去：密钥框写着可以空，可本机服务列不出模型时没有出路。
- 网页的引导上看到的报错是一句内部用的英文（`provider "deepseek" has no usable key`）：配置里引用的密钥早就不在了，`miyu check` 能说清，测试连接说不清。

### 做了什么

1. `provider.test`（`miyu-session` 的 `route/probe.rs`）：
   - 列到了：写了模型、在列表里的就是它，没写的照推荐挑，挑得出就算通（`checked: list`），不发请求。列表是空的：`need_model`。写的模型不在列表里：拿它发一句。
   - 列不到：认证错停在 `list`，写没写模型都不发请求；别的（这一家不给列、地址不对）写了模型的拿它发一句（`checked: request`，带 `first_token_ms`，模型照目录列），没写的 `need_model`。
2. 回应多两格：`checked`（`list`、`request`）、`need_model`；只列了模型的没有 `first_token_ms`。
3. `config` 那一步：配置里引用的密钥、环境变量取不到的，`message` 照连接的语言说，和 `miyu check` 同一句（`reach` 带上缺的那一样 `Missing`；远程 embedding 照旧取英文的一句）。
4. 命令行 `miyu setup`：通了照「列出 <n> 个模型」说；核心回 `need_model` 才问模型名；测不通在终端里问「仍然保存？[y/N]」，是的话没有模型先问模型名，贴的 key 照样存、配置照填的写，不是的回上一步。不在终端里的不问。
5. 蓝图 `models.md`、`cli/setup.md`、`protocol.md` 照上面改。终端、网页的引导照新形状改（「仍然保存」按钮、`need_model` 时问模型名），由两个头做，合了以后发给它们。

### 验收

- 测试：列到了只发一个 GET（配好的、候选的、写了在列表里的）；写的不在列表里的发一句，带温度、只有一条 user；列不出、没写模型的 `need_model`、不发请求，写了的发一句、模型照目录列；列模型 401 停在 `list`、给了模型也不发；列表是空的 `need_model`；`config` 那一步缺密钥、缺环境变量（key 的、地址的）各照中文说。命令行：环境变量的 key、贴的 key（先 401 不保存、回去再贴）、自定义的一家都只列了模型；仍然保存（先问模型名、存 key、写配置）；不在终端里不问。
- 变异 16 处全抓住：列到了也发请求、认证错当成别的、认证错也要模型名、空列表不要模型名、发了一句却不交毫秒数、缺的那一项写成别的两处、密钥说成环境变量、不交 `need_model`、`checked` 说反、缺了引用也照英文说；命令行照 `stage` 认要不要模型名、只认 `yes`、不在终端里也问仍然保存、只列了模型也说试的哪个、仍然保存时空的模型名也收（这一处起初没抓住，补了一条测试）。
- 编出来的 release 对真的中转（magpie）：不写 `--model` 的 `miyu setup` 自定义一家，「· 通了：列出 91 个模型。」，敲模型名选了要的那个，接着 `miyu ask` 回了话。原来这一步试最新的模型、403、退回去贴 key。

### 留下的

- 终端、网页的引导等两个头改；改之前它们照旧读 `first_token_ms`，只列了模型的没有这一格，要照 `checked` 认。
