## 施工单 SB-3：越过沙盒的放行规则按命令前缀记

状态：核心的分会话做。终端第 23 条，项目主人 2026-10-27 定，照 Claude Code：命令要越过沙盒、人选了「此目录不再询问」以后，同一类命令（例如 `docker ps`、`npm run`）在这个目录别再每次问。主会话派（2026-10-27），形状和三处收紧（路径不去、开头赋值不报、包一层的不报）和主会话对过。

### 原来

越过沙盒问人时提的规则是 `{"tool", "write": [工作目录]}`（施工 5-15）：选了的只放开这个目录的写，越过沙盒的命令照样每次问，规则只管路径。修前的测试（`outside_prefix.rs` 第一条，去掉规则那一句断言）：选了此目录不再询问以后，同一前缀的下一条又停下来问，这一轮等满六十秒结束不了。

### 做了什么

1. 前缀怎么取（`miyu_policy::hazard::prefix`，用高危那一套拆命令）：第一个词照原样；「程序 + 子命令」那二十个带上紧跟着的子命令（紧跟着的是选项的不报）；`|`、`&&`、`||`、`;`、`&`、换行连起来的每段一样才报。不报：开头有变量赋值、第一个词是包一层的（`env`、`sudo`、`sh`、`timeout` 这十九个）、引号外有子 shell、花括号（`${名字}` 不算）、命令替换、前缀的词里有变量。宁可窄：取不清就照旧每次问。
2. 工具报前缀：`Tool::prefix`（默认没有），`shell` 只认 bash、zsh（同高危）；测试的假工具照参数里的 `prefix`。
3. 权限策略（`guard.rs`、`guard/asking.rs`）：越过沙盒问人时规则另写 `prefix`（`{"prefix", "tool", "write"}`，键照字母排）；判越过沙盒之前先看本会话放行过的规则，工具一样、前缀一字不差、这一次工作目录的真实位置是规则放行写的目录本身或者下面的，工作区这一级放行、照样在沙盒外跑。高危、只碰得到自己工作区的、报的路径判了拒绝的都在这之前拦下；只读照拒；管理员放行表那条路不动。
4. 内核、协议的方法都不动：`rule` 本来就是原样记、原样交给头的 JSON。协议图纸 `session.answer` 第 3 条、参考文档 `sessions.md` 中英两份写明 `rule` 的几格和头怎么显示 `prefix`。
5. 图纸：`session/guard.md` 第四条、测试表、还没有的；`tools/shell.md` 新一节「命令前缀」；`kernel/asking.md` 第 7 条。

### 定下的

- 前缀照写的原样比，一字不差：`docker ps` 的规则放行 `docker ps -a`，不放行 `docker run`，也不放行 `./docker ps`。
- 「这个目录下」照路径的段比，和放行写的规则同一个比法：`/a/b` 不放行 `/a/bc`。
- 第一版不管沙盒里跑的命令（本来不问）、不管 PowerShell。

### 验收

1. 修前：同前缀的下一条照样问（见上）。修后 `outside_prefix.rs` 四条：同前缀同目录不问、提的规则带前缀；不同前缀、没报前缀照问；工作目录换到下面不问、换到外面照问；真经 `shell` 两段都是 `echo` 的不问、包了 `env` 的照问。`hazard/prefix/tests.rs` 七条。
2. 手改六个都红：规则不比前缀、不比目录（`outside_prefix.rs`）；去掉路径、放过开头赋值、包一层的照报、各段不一致也报（`prefix/tests.rs`）。
3. `cargo xtask check` 全过、Windows 版 clippy、三平台 CI。
