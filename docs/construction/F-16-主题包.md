## 施工单 F-16：主题包

状态：合了（2026-10-21，8b84d7dd）。项目主人 2026-10-21 定，终端界面的会话转来（终端图纸 `tui.md`「主题」，终端分支 `theme-packs`）。

### 目的

终端照网页的「皮肤」做一层变量化，叫「主题」（框线、记号、修饰、留白、动效一张表），主题做成一种软件包，默认主题也是一个包。核心照吉祥物包（F-7）认 `kind = "theme"`：只认文件在哪，内容整份由终端解析。

### 做了什么

1. `miyu-config`：`PackageKind::Theme`、`Manifest.theme`（`Theme { file }`）、`[theme]` 的读法（同 `[mascot] model`）、问题码 `bad_theme_file`；主题包只能写 `[package]`、`[theme]`（另可写依赖），不说协议。
2. 端点：`package.list` 带 `theme: {"file"}`；`package.file` 只给那一份；`miyu check` 查在不在、不超过 256 KiB、是 JSON 对象（`theme_missing`、`theme_too_big`、`theme_not_json`，和吉祥物共用 `data_problem`）；没有开关、不是扩展；装之前的看一眼多 `theme: true`，命令行照它说「主题」。
3. 三份字表：四句问题的说法，不认识的表那一句加 `[theme]`。
4. 蓝图 `packages.md`「主题包」、`protocol.md`，协议参考 `packages` 中英。

### 和终端说的不一样的

- 另可写依赖（`[depends]`、`[recommends]`），同吉祥物包；别的表照旧 `wrong_kind`。

### 验收

1. `crates/miyu-endpoint/tests/package_theme.rs`（照 `package_mascot.rs`）：列出来带 `theme`、没有协议；`package.file` 只给主题文件；关不了；`check` 报不在、不是对象、太大，好了不报；写了协议、`[command]`、`[mascot]` 的 `wrong_kind`，路径写出包目录的 `bad_theme_file`，没写 `file` 的 `missing_key`。
2. 变异 6 个抓住 5 个；没抓住的「主题包也收 `[mascot]`」等价：两张都写的先认成吉祥物包，吉祥物包不收 `[theme]`，照样 `wrong_kind`。
3. `cargo xtask check` 八项；读包里的文件，先推 step 分支过三台。
