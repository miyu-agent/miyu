## 施工单 X-13 上：只带技能、脚本的包

状态：施工中（2026-10-12 主会话）。图纸 `docs/blueprint/skills.md`「施工拆分」X-13 上、`packages.md`「格式」「MCP 服务」第 3、4 条、`package-pages.md`「状态」「开关」。

### 目的

作者把几个技能、脚本放进一个包文件夹，清单只写一张 `[package]` 就能装（X-11 下查出来以前报 `missing_key`）；装之前看得到包里带了哪些技能、脚本。

### 做了什么

1. **清单**（`miyu-config` 的 `package/kinds.rs`）：没有程序表、没有 MCP 服务、没有吉祥物的也是 `bundle`，带的是包文件夹里的 `skills/`、`scripts/`。写了 `[command]` 或协议版本、却没有程序表的照旧报 `missing_key`（漏了程序表，不报成「这种包不能写 protocol」）。
2. **开关**（`miyu-endpoint` 的 `packages/status.rs` 的 `runs`）：开关只给起得来停得下的：扩展、带了 MCP 服务的 `bundle`。只带技能、脚本的 `bundle` 没有 `enabled`，状态是 `ready`，`package.enable`、`package.disable` 报 `not_switchable`，`package.restart` 报 `not_restartable`。技能、脚本照预设开关（X-11、X-12 中）。
3. **装之前看一眼**（`packages/preview.rs`）：`package.install` 带 `preview: true` 的多两格 `skills`（技能名）、`scripts`（工具名），照包文件夹找，开头读得成的才列（`miyu_store::skills::carried`、`miyu_store::scripts::carried`；读开头的那一段和 `find` 共用）。装回出厂的包也列。
4. **命令行**（`miyu-cli` 的 `pkg/confirm.rs`）：「包含」那一行印「技能 <名字>」「脚本 <名字>」。

### 定了的（主会话，技术题照推荐）

- **只带技能、脚本的包没有开关**：开关管的是起停（扩展的进程、MCP 服务）；技能、脚本每个都是功能，预设里开关，再加一层包的开关是两处管一件事。
- **什么都没带的包不另报**：装之前的预览里「包含」那一行是空的，人看得出来；只写依赖的那种包以后要有（照 pacman 的元包），不拦。
- **预览只列开头读得成的**：写错的装上以后 `miyu check` 报（X-12 下）。

### 验收

- 清单：只写 `[package]` 的读成 `bundle`、不说协议；不带程序的包写配置项报 `wrong_kind`；写了 `[command]`、协议版本却没有程序表的报 `missing_key`。
- 仓库：包文件夹带的技能、脚本照名字排，写错的、没有 `SKILL.md` 的、子文件夹、点开头的不列；没有这个文件夹的是空的。
- 端点：只带技能、脚本的包，预览列出 `skills`、`scripts`、没有 `program`；装得上；`package.list` 里状态 `ready`、没有 `enabled`；开、关报 `not_switchable`，重启报 `not_restartable`；新会话的 system 里有它的技能，工具面里有它的脚本。
- 命令行：「包含：技能 take-notes、脚本 dice」，英文的同样。
- 真二进制（沙箱数据根）：`miyu pkg install ./notes` 印「包含：技能 take-notes、脚本 dice」，答 n 不装、答 y 装好；`miyu pkg info notes` 有名称、大小；`miyu check` 没有问题。
- 变异 11 个全报红（空清单照旧报少了、说协议的不算漏程序表、bundle 一律有开关、开关和重启和状态不看带没带服务各一、预览不列技能、不列脚本、写错的技能和脚本也列、命令行不印技能）。
