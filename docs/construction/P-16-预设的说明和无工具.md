## 施工单 P-16：预设的说明和无工具

状态：项目主人 2026-10-23 定，主会话委派、审过拆法。分两段：**P-16 上**出厂预设写说明、加「极简开发」（做完了，2026-10-23）；**P-16 下**「无工具」能选（没开工）。

### 目的

开会话、换预设时，头照 `preset.list` 列出几种预设给人挑，现在只有名字没有说明，人不知道差在哪；项目主人列了四种：极简开发、常规开发、全部功能、无工具。

### P-16 上：出厂预设的说明、极简开发

1. `dev`、`full` 的 `[preset]` 多 `summary`（三语，同 `name`）。原来不写说明（施工 P-4 下，2026-10-08 项目主人：「描述可以不要」），这次项目主人改了：
   - 常规开发：「在极简开发的基础上增加记忆、网络搜索、子代理、Agent间交流等开发常用工具。」
   - 全部功能：「开放全部工具。」
2. 新出厂预设 `minimal`「极简开发」（en `Minimal`、ja `ミニマル開発`），图标 `square-terminal`。说明「只提供Shell和读写文件的工具，最小化工具集以最大程度发挥 AI 原有的能力。」写法：
   - `unlisted = "off"`，不写 `[software] basesystem`，只写 `[features] files = true`、`commands = true`，再 `[tools] glob = false`、`grep = false`、`trash = false`：留 `shell`、`read`、`write`、`edit` 四件。
   - 为什么不写「开 basesystem、其余逐件关」：功能一级写了的照写的算，没写的落到 `unlisted`（`presets.md` 第 4 条的先后）。基础系统以后新加的功能在这里默认关着，不用回头补；只有往 `files`、`commands` 这两个功能里加新工具才会冒出来，那时照这份单子再看。
3. 说明是给人看的，不发给模型，不进登记簿。

### 做下来的（P-16 上）

- `resources/presets/dev.toml`、`full.toml` 加 `summary`（中文照项目主人的原话，英、日照意思写短句）；新的 `minimal.toml`，日文名「ミニマル開発」，图标 `square-terminal`。
- 蓝图 `presets.md`「出厂的三个」照它改。
- 测试：`miyu-store` 的 `the_shipped_presets_read_cleanly` 改成三份都有三语的名字、说明，中文照原话，极简开发只写 `[features]` 两个、关三件；端点新加 `preset_minimal`，基础系统照清单的 18 件全登记，极简开发的会话发出去的工具正好是 `edit`、`read`、`shell`、`write`。没加资源时两条都红。`presets`、`persona_avatar` 里列出厂预设的两条跟着改期望。
- 手写变异 10 个全抓住（不开运行命令、文件读写关、少关一件、开整个基础系统、没写的照开、缺日文说明、缺说明、说明写错、换图标）。

### P-16 下：无工具

主会话 2026-10-23 同意的形状：

1. `preset.list` 末尾固定一项 `{"preset": null, "name": "无工具", "summary": "不提供任何工具。", "icon": "circle-off"}`，名字、说明照连接的语言（三语放在核心给人看的字里）。编号用 `null` 不用 `"none"`：预设编号是文件名，`none` 会和人自己写的 `none.toml` 撞。
2. `session.create`、`session.configure` 的 `preset` 收 `null`：这个会话一件工具都不给，system 里也不提工具。和人格的 `null`（不用人格）同一个读法。`preset.default` 第一版不收 `null`。
3. 快照、内核事件记 `no_tools`：布尔，默认 `false`，`false` 的不写，以前的日志照旧读得进。`true` 时 `preset` 是空的。以前那种没记预设的（测试里造的、以前的快照）照旧不筛：`preset` 空、`no_tools` 是 `false`。主会话给模型的那一块事实里写 `none`。
4. 要动的文件开工前列给主会话看（它在动 facts、`session/limits.rs`、`session/input.rs`、`actor/model.rs` 的 hand，不碰这几处）。
