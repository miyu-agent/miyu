## 施工单 R-19：整理时轮着重看旧记忆

状态：做好了（2026-10-19 写、施工、自己验收）。项目主人 2026-10-19 问「这个不是 dream 的事情吗？」，照推荐定「每次整理顺带最久没检查过的 20 条，不一次性全量重整」，量过成本再做。剩下的是技术细节，照施工方案第一节第 1 条直接做。

### 原来缺什么

整理（dream）只交新记的和每条照关键词、照意思搜出来的相关旧记忆（最多 3 条）。和新记的不沾边的旧记忆永远不会再被看一眼：R-16 以前记下的过时的、重复的、没价值的，一直留着。

### 定了的

1. **挑**：一趟整理（合到没有剩下的）开头照底账挑一次：上次重看到的那一条（`MemoryBook::swept`）后面、现在算数、听众合的，照编号最多 20 条，不够的从头接；从头合的（还没合并过、摘要不算了的）全是新记的，不挑。
2. **放**：头一个放得下的批带上，接在相关的旧记忆后面，标题 `merge/sweep.txt`「Other older memories to look over again:」；新记的塞满了的照挑好的那一份往后一批挪，不重挑（重挑会把这一趟刚合完的算成旧的）；已经当相关的交进去的不重复列、也算看过；只重看的一批至少交一条。指令开头一句多说这一块，规矩照旧。
3. **记**：合成了在 `merged` 后面记 `ext.memory.swept`（`upto` 重看的里最后那一条、`count` 几条）；没合成的不往前走。
4. **谁叫**：人叫的（`memory.dream`、`/dream`、`miyu memory dream`）没有新记的也照样重看（那一批 `merging` 的 `fresh`、`left` 是 0，`upto` 是上次合到的那一条）；一条记忆都没有的照旧不发。后台的只在有新记的时候合，顺带重看。

### 验收

1. 数据先行：量尺 `memory_dream_eval` 加「轮转」场景，同一刻在 main 和这一步上各跑 3 轮（开发端点 `group/auto-deepseek-v4-1-flash`）：不轮转的旧库一条都清不掉；轮转矛盾 15/15、日期 10/12、没价值 18/18、重复 12/12、误删 0、摘要 24/24；原来两种场景照旧（`memory/eval.md`「整理」）。成本一趟多 550 个输入 token 上下。
2. 测试：`memory_sweep.rs` 五条（每趟 20 条、接着、从头接；没合成的不往前走；新记的在前、塞满了往后挪、一趟只看一次；当相关的交过的不重复、照样往前走；后台没有新记的不合）；`memory_dream.rs`、`miyu-endpoint` 的 `memory_dream.rs`、`miyu-cli` 的 `memory.rs` 里「再叫一次是零」改成重看留下的那一条。
3. 手写变异、`cargo xtask check` 八项、三台 CI。

### 施工结果（2026-10-19）

1. **量尺**：见验收第 1 条；数据和对照写进 `memory/eval.md`「整理」。
2. **测试**：`memory_sweep.rs` 五条，加上三处「再叫一次是零」改的；写的时候查出两处要改的设计：头一批让新记的塞满了的白轮（改成头一个放得下的批带上），往后挪的时候重挑会把这一趟刚合完的算成旧的（改成开头挑一次、照它往后带）。
3. **变异**：十一个（不从头接、不分前后、条数改了、后台没有新记的也合、只看新记的、不记 `swept`、塞满了不往后挪、往后挪的重挑、当相关的交过的不往前走、只重看的一批合到哪写错、底账不跟 `swept`），头一回漏了两个（后台那条让间隔挡住了、重挑那条列出来的一样），改了测试以后全被逮住。
