# Writing themes and appearance

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Give the terminal or the web UI a look of your own and release it as a package: terminal themes, web themes and color schemes, and mascots. You need to be able to write JSON; for the web part you also need a little JavaScript and CSS. Chinese version: [themes.md](themes.md).

## What you can make

| What | What it controls | Which head | Manifest | Where people pick it |
|---|---|---|---|---|
| A terminal theme | Frame lines, marks, text styling, how the selection looks | Terminal | `[theme.tui]` | Settings page, "Appearance" → "Theme"; config key `tui.look` |
| A web color scheme | The colors of the whole page, one set for light and one for dark | Web UI | `[theme.web]` | Settings page, "General" → "Color scheme" |
| A web theme | Corner radius, shadows, borders, blur, fonts, icons | Web UI | `[theme.web]` | Settings page, "General" → "Theme" |
| A terminal mascot | The looks and motions of the figure on the home screen and in the sidebar | Terminal | `[mascot]` | Settings page, "Appearance" → "Figure" → "Mascot"; config key `tui.mascot` |

Terminal colors are not up to packages: under "Appearance" → "Color scheme" on the settings page, "Colors" only offers "Auto", "Follow the avatar", "Follow the wallpaper", "Tokyo Night" and "Terminal colors", and `/theme` picks from the same list.

A package with `[theme]` is an appearance package, and one with `[mascot]` is a mascot package. An appearance package can carry only the terminal part, only the web part, or both.

## The manifest of an appearance package

```toml
[package]
version = "0.1.0"
name = { zh = "薄荷", en = "Mint" }

[theme.tui]
file = "theme.json"     # the terminal theme: a relative path inside the package folder

[theme.web]
dir = "web"             # the web part: a relative directory inside the package folder
```

- Write at least one of `[theme.tui]` and `[theme.web]`. `file` and `dir` are required, and may not contain `..` or start with `/`.
- An appearance package may only have `[package]`, `[theme]`, `[depends]` and `[recommends]`; other tables such as `protocol` or `[command]` get `wrong_kind`. It has no program, switches or config items.
- `miyu check` checks the terminal theme file (it must exist, be a JSON object, and be at most 256 KiB) and that the web directory exists.

Every field is in [The manifest](../authors/manifest.en.md#theme).

## Terminal themes

One JSON file where you write only the fields you want to change. The terminal lays it over the default theme: where both sides are objects it merges level by level, and anything else (text, lists) is replaced whole. Keys starting with `_` are notes and the terminal doesn't read them.

The default theme is `packages/tui-theme-default/theme.json` in the terminal repository, with a note on every field, and editing a copy of it is the fastest way. These are the sections you can write:

| Section | What it controls | What you can write |
|---|---|---|
| `frame` | Frame lines: `input` the input box, `boxes` the boxes opened above the input box (the command list, the session list, `/model` and so on), `toast` small pop-up notices, `code` the lines of code blocks in answers, `table` tables in answers | `rounded` rounded corners, `plain` square corners, `double` double lines, `thick` thick lines, `ascii` (`+-\|`), `none` keeps the space but draws no line |
| `marks` | Small symbols in the interface: `pointer` before the selected row, `on`, `off`, `now`, `ok`, `fail`, `ellipsis`, `caret`, `gap`, `next`, `sep`, `dash`, `rule`, `quote`, `bar`, `side`, `secret`, `enter`, `swatch`, `heat`, `minus`, `task` (`todo`, `done`), `chart` (eight cells), `block`, `fill` (eight cells), `ring` (five cells) | Text. Marks at the start of a line such as `pointer`, `heat` and `task` must be two cells wide |
| `text` | Text styling: `heading`, `title`, `strong`, `emphasis`, `link`, `quote`, `table_head`, `picked` (the chosen row in a list), `level` (the permission level), `model` (the model name in the footer), `selected` (a selection) | A list whose elements are `bold`, `italic`, `underline`, `dim`, `reversed`; an empty list adds nothing |
| `pick` | How the selected row in a list looks | `bar` fills the whole row with a background color; `mark` doesn't fill and relies only on the mark and the accent color |
| `layout` | The marks in the timeline, sidebar, to-do list, memory cleanup and similar places | Keys as in this section of the default theme; write only the ones you want to change |
| `timeline` | The spinner frames `spinner`, the vertical line `line`, queued `queued`, omitted `omitted` | Text; `spinner` is a list |

An unknown key in `frame`, `marks` or `text` makes the whole file unreadable. When it is unreadable or the package is gone, the terminal draws the default theme and shows "Theme package unreadable, using the default theme".

The terminal also has a built-in `ascii` theme (frame lines and marks all turned into ASCII, selection with no background fill): setting `tui.look` to `ascii` selects it. If `tui.look` has never been set, it is the default in the Linux console (`TERM` is `linux`).

### Example: a square-frame theme

A theme package that makes the input box and pop-up boxes square, turns the selected row into an arrow, and doesn't fill the background.

1. Create the directory `tui-theme-square/` and write `package.toml`:

   ```toml
   [package]
   version = "0.1.0"
   name = { zh = "方框", en = "Square" }
   summary = { zh = "直角框线，选中不铺底", en = "Square frames, no highlight bar" }

   [theme.tui]
   file = "theme.json"
   ```

2. In the same directory write `theme.json`:

   ```json
   {
     "frame": { "input": "plain", "boxes": "plain", "toast": "plain" },
     "marks": { "pointer": "▶ " },
     "pick": "mark"
   }
   ```

3. Install: `miyu pkg install ./tui-theme-square`.
4. Pick: in the terminal type `/settings`, and in the "Theme" group of the "Appearance" page pick "Square"; or run `miyu config set tui.look tui-theme-square`. It switches on the spot.

After you change `theme.json`, run `miyu pkg install ./tui-theme-square` again to switch to the new version.

## Web themes and color schemes

On the web UI, the "Color scheme" controls colors and the "Theme" controls shapes and materials. Both are brought in by the directory that `[theme.web]` of an appearance package points to.

That directory is a web package:

```text
web/
├── manifest.json     # the package's manifest
├── index.js          # exports apply(ctx)
└── …                 # styles, fonts, icons, fetched by relative address
```

- `manifest.json`: `name` (`{"zh": …, "en": …}`) and `inject` (the services it uses; to mount things you must write `slots`). `id` is worked out from the core's package id, so whatever you write makes no difference; a package always counts as optional, and people can turn it off on the settings page under "Packages".
- `index.js`: exports `apply(ctx)`. Inside it, use `ctx.slots.mount(<position>, <item>)` to mount the color scheme and the theme. Fetch other files with `new URL('<file>', import.meta.url)`.
- The script runs in the web page as usual, with no extra restrictions, the same as shipped packages.
- Installing and removing take effect on the spot; for an upgrade, or for a package this page has already loaded, a notice above the input box says it takes effect after you refresh the page. If one can't start (a broken manifest, no `apply`, `apply` throws), the reason is shown on its row in the "Packages" page of the settings.

### Color schemes: mount into `theme.palettes`

```js
ctx.slots.mount('theme.palettes', { id, name, render });
```

- `render(scheme)`: `scheme` is `'light'` or `'dark'`, and it returns `{page, tui}`, two sets of colors; return `null` for one it can't supply, and the web UI uses another scheme.
- Each key in `page` is written as a CSS variable of the page, `--<key>` (with `_` changed to `-`), and the ones in `tui` as `--t-<key>` (used where the web UI draws terminal-style content). You can't leave out any color variable of the whole page: one you don't give does not exist. For the keys of the shipped "Default" scheme, see `web-demo/packages/theme-default/manifest.json` in the web repository (the settings `light_…` and `dark_…`; the ones starting with `t_` are the `tui` set).
- The easiest way is to change a few things in the shipped "Default" scheme: it is mounted at the same position with the id `default`; find it with `ctx.slots.list('theme.palettes')` and call its `render`.
- The thumbnail on the settings page's card draws `sidebar_bg`, `surface`, `accent`, `text` and `gold`.

### Themes: mount into `skin.packs`

```js
ctx.slots.mount('skin.packs', { id, name, tokens, css, icons, palette });
```

| Field | Description |
|---|---|
| `id` | Starts with a lowercase letter, and contains only lowercase letters, digits and `-` |
| `name` | The name in the settings page's dropdown |
| `tokens` | Variable names to values. A value is a string, or one for light and one for dark, `{"light", "dark"}`. Names may only be ones the web UI recognizes (below), or your own helper variables starting with `--skin-` |
| `css` | Optional: the address of a style file (rules below) |
| `icons` | Optional: the address of an icon table, written like the web UI's `resources/lucide.json`; only the shapes `path`, `circle`, `rect`, `line`, `polyline`, `polygon`, `ellipse` and `g` and drawing attributes are accepted |
| `palette` | Optional: the id of a recommended color scheme. When a person picks this theme it is switched on along with it, and they can still pick another later |

The variables the web UI recognizes are in `web-demo/styles/tokens.css` in the web repository, in two layers:

- The master switches for shape: `--round` (multiplier for corner radius, 1 is as shipped, 0 is all square corners), `--blur` (multiplier for frosted-glass blur, 0 is no blur), `--text-scale` (multiplier for font size), `--space` (multiplier for spacing), `--motion-scale` (multiplier for animation duration, 0 is no motion), `--font-ui` (the font of the interface), `--font-read` (the font for reading), `--font-mono` (monospace) and `--font-code` (code in answers).
- One group per material, not defined as shipped; whichever you write replaces that kind: large areas, answers, the timeline, motion, icons, the input box, the send button, your messages, cards, code blocks, small floating boxes, dialogs, the layer under a dialog, a selectable row, a transparent icon button, buttons, the primary button, text fields, small tags, the track of a switch, the knob of a switch, the track of a segmented control, the selected segment of a segmented control, the left column. Every variable name in each group and its description are in the comment at the top of that file.

For colors, write only the color variables of the color scheme (things like `var(--accent)`) and `color-mix(…)`, and no colors like `#rrggbb`. That way, when a person picks "Follow persona" or "Follow wallpaper", your theme changes color with it.

**Style files** (`css`) are for what variables can't do:

- Every rule starts with `:root[data-skin="<your id>"]`.
- Pick elements only by part name, `[data-part="<name>"]`, with names from `web-demo/resources/parts.json` in the web repository; write states as `[data-state="<state>"]`. Don't write class names or `#id`s.
- It may carry `@font-face`, `@media` and `@supports`; your own animation names start with `skin-<your id>-`.
- A style sheet with even one rule that breaks the rules is not used at all; a rule whose part name isn't recognized has no effect. The reason something isn't accepted is written to the browser's developer tools console (a warning that the skin with that id was not recognized, followed by the reason).

A complete example to copy from: `web-demo/packages/skin-pixel/` in the web repository (the "Pixel" theme, with styles, a pixel font and icons).

### Example: Mint

An appearance package that only changes the accent color and halves the corner radius.

1. Create the directory:

   ```text
   webui-theme-mint/
   ├── package.toml
   └── web/
       ├── manifest.json
       └── index.js
   ```

2. `package.toml`:

   ```toml
   [package]
   version = "0.1.0"
   name = { zh = "薄荷", en = "Mint" }
   summary = { zh = "绿色的强调色，圆角小一半", en = "Green accent, half-size corners" }

   [theme.web]
   dir = "web"
   ```

3. `web/manifest.json`:

   ```json
   {
     "id": "webui-theme-mint",
     "name": { "zh": "薄荷", "en": "Mint" },
     "inject": ["slots"]
   }
   ```

4. `web/index.js`:

   ```js
   // Accent color: one for light, one for dark
   const ACCENT = { light: '#1f7a5c', dark: '#6fd3ae' };

   export function apply(ctx) {
     // Color scheme: take the shipped "Default" one and change only the accent color
     ctx.slots.mount('theme.palettes', {
       id: 'mint',
       name: 'Mint',
       render: (scheme) => {
         const base = ctx.slots.list('theme.palettes').find((p) => p.id === 'default')?.render(scheme);
         return base ? { page: { ...base.page, accent: ACCENT[scheme] }, tui: base.tui } : null;
       },
     });
     // Theme: half the corner radius; picking it also switches on the color scheme above
     ctx.slots.mount('skin.packs', { id: 'mint', name: 'Mint', tokens: { '--round': '0.5' }, palette: 'mint' });
   }
   ```

5. Install: `miyu pkg install ./webui-theme-mint`. A web page that is open loads it on the spot.
6. Pick: in the web UI type `/settings`; at the top of the "General" page, in the "Theme" group, pick "Mint" in the "Theme" dropdown; the "Color scheme" group has gained a "Mint" card, which is selected along with it.
7. Look: type `/gallery` to open the gallery, a session set up with all kinds of answer and timeline entries (you can't send anything in it), and see how it looks with your theme on.

## Mascots

**Terminal**: a mascot package may only have `[package]` and `[mascot]` (and, optionally, `[depends]` and `[recommends]`):

```toml
[package]
name = { zh = "布丁", en = "Pudding" }

[mascot]
model = "mascot.json"
```

- `model` is a JSON object of at most 256 KiB, laid over the one built into the terminal: `resources/mascot.json` in the terminal repository. Every field may be left out. The fields you can write are `cols`, `rows`, `radius`, `center_row`, `ramp`, `light`, `ambient`, `shapes`, `face`, `mouth`, `idle`, `gaze` and `colors`; `face`, `mouth`, `idle` and `gaze` are laid over field by field, and the others are replaced whole. A file with any other field, or over a limit (`cols` 1 to 36, `rows` 1 to 18, `shapes` 1 to 32 entries), is not used at all, and the terminal shows "Mascot package unreadable, using the built-in mascot".
- After installing, pick it on the settings page under "Appearance" → "Figure" → "Mascot", or run `miyu config set tui.mascot <package id>`.
- Whether the home screen and the sidebar draw a mascot is controlled by two other switches, both off as shipped: "Show the figure on the home screen" and "Show the figure in the sidebar" in the same group. If the session's persona has an avatar, the avatar is what gets drawn.
- Miyu ships no mascot packages.

**Web UI**: pick the web UI's mascot on the settings page under "General" → the "Theme" group → "Mascot"; "Deniro" is there as shipped. An appearance package can also mount a mascot into the web UI (position `mascot.characters`); the interface it has to implement hasn't been written up yet.

## Naming and releasing

- The rules for ids are the same as for other packages ([Writing a package](../authors/README.en.md)). The web appearance packages already in the package source are all named `webui-theme-<name>`, and the terminal's shipped default theme package is named `tui-theme-default`; name yours in the same pattern, and it is clear at a glance which head it is for.
- For packing and publishing to a package source see [Writing a package](../authors/README.en.md#publishing-to-the-package-source).

## Check before you release

Terminal:

- Both dark and light: switch "Light or dark" under "Appearance" → "Color scheme" to dark and to light, and look at each.
- Color depth: open the terminal interface once each with `MIYU_COLOR=256`, `MIYU_COLOR=16` and `NO_COLOR=1`, and see whether the frame lines and the selection are still recognizable. `MIYU_COLOR` also accepts `truecolor` and `none`.
- Icons: `/icons` switches between "Nerd Font icons" and "Plain characters"; look at both.
- If you changed marks: whether the width is right (two cells at the start of a line), and whether anything is misaligned in the few terminals you use most.

Web UI:

- Switch "Mode" under "Color scheme" to light and to dark and look at each; when the color scheme is "Follow persona" or "Follow wallpaper", your theme's colors change along with it.
- Look in both Firefox and Chromium: the web UI has a few places tuned separately for the differences between the two browsers.
- Open the browser's developer tools: the console has no warning that your skin was not recognized, and your package shows no fault on the settings page under "Packages".
