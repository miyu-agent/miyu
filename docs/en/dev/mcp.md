# MCP servers

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Existing MCP (Model Context Protocol) servers can be connected to Miyu directly: the core starts the server process and talks MCP with it over stdin and stdout; for a server that only gives a URL (Streamable HTTP), the core connects to that URL directly. The server's tools are registered for the AI to use. There are two ways to connect a server: write it in your configuration (just for you, and the quickest), or make it a package (so you can share it).

## Quickest: your configuration

Open `~/.miyu/etc/config.toml` (or run `miyu config edit`) and write one table per server:

```toml
[mcp.files]
command = ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/home/me/notes"]
```

If a server only gives a URL (GitHub and the like), write `url`, and put the token in `bearer`:

```toml
[mcp.github]
url = "https://api.githubcopilot.com/mcp/"
bearer = { secret = "github" }       # store the token with miyu provider login or the settings page; it is sent as Authorization: Bearer …
```

The change takes effect as soon as you save it, without a restart. The `Packages` page of the terminal UI or the web UI shows whether the server is running, and `miyu check` checks your configuration for mistakes.

Some servers only accept browser authorization and can't issue a personal token (Notion, Linear and the like). For these, write only `url` and no `bearer`. The server then waits as "needs login" (`needs_login`); run `miyu mcp login <server>` and agree in the browser, and the server connects. The token goes into the secrets file, so you never handle it, and the core renews it before it expires. If the browser is on another machine, paste the whole address the browser lands on back into the terminal after you authorize. Run `miyu mcp logout <server>` when you no longer need it.

## As a package

A package that only brings MCP servers needs nothing in its folder but a `package.toml`:

```text
notes-mcp/
└── package.toml
```

```toml
[package]
name = { en = "Notes", zh = "笔记" }

[[mcp]]
name = "notes"                                    # the server name: a lowercase letter first, then only lowercase letters, digits and -, 1 to 32 characters
command = ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/srv/notes"]
env = { TOKEN = { secret = "notes" } }            # optional; a value can be text, or refer to a secret { secret = … } or an environment variable { env = … }
venues = ["local"]                                # optional: which sessions get the server; when left out, only local sessions
timeout_ms = 600000                               # optional: how long one call may take, from 1000 to 3600000
clicall = false                                   # optional: false means the AI cannot call this server's tools with miyu call inside a command
```

A package that brings only servers and no program doesn't need `protocol`, `[command]` or `[process]`. A package can bring several servers; extension packages can bring servers too, and those servers start and stop together with the extension.

To install it, run `miyu pkg install ./notes-mcp`. A package that brings only servers is **switched off** after it is installed; turn it on in the `Packages` page.

## Fields

The table below explains each field you can write for an MCP server:

| Field | Notes |
|---|---|
| `name` | The server name (in the configuration it is the table name). It starts with a lowercase letter and contains only lowercase letters, digits and `-`, 1 to 32 characters; it must be globally unique. |
| `command` | The command and its arguments. The first item is looked up in the package's `bin/` first, then on `PATH` (`npx`, `uvx`, `docker` and the like). Write either `command` or `url`. |
| `url` | The server's address, starting with `https://`. `http://` is only allowed for servers on this machine (`localhost`, `127.0.0.1`); servers on other machines aren't connected over it, so that the token isn't sent in the clear. Write either `url` or `command`. |
| `bearer` | Goes with `url`: the token, sent as `Authorization: Bearer <value>`. It is written like an `env` value; please write the token as `{ secret = … }`. |
| `headers` | Goes with `url`: other request headers, such as `{ X-Api-Key = { secret = "key" } }`, written like `env`. |
| `env` | Environment variables for the server. Write secrets as `{ secret = "<name>" }` (store them with `miyu provider login` or the settings screen); don't put the values in the manifest. |
| `venues` | One or more of `local`, `private` and `group`, meaning local sessions, private chats on chat platforms, and groups. When it isn't written, only local sessions get the server. |
| `timeout_ms` | How long one call may take, in milliseconds, from 1000 to 3600000. When it isn't written, it is 600000. |
| `clicall` | Whether the AI can call this server's tools with `miyu call` from a script it runs in a command. When it isn't written, the AI can. If the server writes or sends things, write `false`. |

## What the AI sees

- Tools are named `mcp__<server>__<tool>`, and their descriptions and parameters are used as the server gives them (a description over 2048 characters is cut).
- In presets each server counts as one feature (`mcp-<server>`), which you can switch off as a whole or tool by tool.
- **Whether people are asked**: tools whose annotations say `readOnlyHint: true` are never asked about, at any permission level. The rest are treated like network access: under full access (the default) nobody is asked, and once read-only is on, a person confirms every call. If you write servers yourself, please mark the read-only tools this way.

## Server instructions, prompts and resources

- **Instructions** (`instructions`): the text your server gives goes at the end of the AI's system prompt, one section per server with the server's name, up to 4000 characters. Only servers whose tools are in that session get a section. In the instructions, say when your tools should be used and how they work together. If a server's instructions change mid-session, the new ones take effect on the next turn where the tools change (so that the cache isn't broken on every turn).
- **Prompts** (`prompts`): each prompt becomes a slash command `/<server>:<prompt>`, shown in the command menu. The words a person types after the name are split on whitespace (a value with spaces goes in English double quotes, e.g. `/weather:forecast "San Francisco" CA`) and matched to your declared arguments in order, with the last argument taking the rest. The text and images that come back are sent to the AI as that person's message. Characters outside `[A-Za-z0-9_-]` in a name become `_`; a prompt whose name clashes after that isn't registered, and `miyu check` reports it. Prompts can only be used in local sessions.
- **Resources** (`resources`): material your server makes available (files, documents, table schemas…), one URI each, or URI templates such as `file:///logs/{day}.txt`. A server that declares `resources` gives the AI two more tools: `mcp__<server>__list_resources` lists resources and templates a page at a time, and `mcp__<server>__read_resource` reads one resource by its URI. Text comes back to the AI as is, images are taken the same way as images from tools, and other binary content is reduced to one line with its type and size. These two tools follow the server's switch, venues and `clicall`; if your server has its own tool with the same name, your tool is used. A server with only resources and no tools can be connected too.

## While running

- The server's working directory is `~/.miyu/var/lib/mcp/<server>/`, which is also given to it as `MIYU_STATE_DIR`; the server runs outside the sandbox. Its stderr goes to `~/.miyu/var/log/mcp/<server>.stderr`; when the server won't start, look there first.
- A server that fails to start or crashes is retried with backoff, and stopped after 5 failures in a row. The `Packages` page shows the reason and the last lines of stderr, and restarting the server there tries again.
- Both the old and the new MCP versions are understood, so a server can speak either one. Miyu uses the server's tools, instructions, prompts and resources; `sampling` and the like aren't used.
- Miyu doesn't install Node or Python for people: if your server is started with `npx` or `uvx`, say in its description what must be installed first.

## Same name in the configuration and a package

If the configuration and a package both have a server with the same name, the one in the configuration wins and covers the package's (the `Packages` page shows this).
