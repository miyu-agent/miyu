# Writing themes and appearance

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

The terminal interface and the web interface are both "heads" (interface programs that connect to the core). This page explains how to give these heads a look of your own and release it as a package: terminal themes, web themes and color schemes, and mascots. To follow this page you need to be able to write JSON; for the web part you also need a little JavaScript and CSS.

## What you can make

There are four kinds of appearance you can make:

| What | What it controls | Which head | Manifest | Where to pick it |
|---|---|---|---|---|
| A terminal theme | Frame lines, marks, text styling and how the selected row looks | Terminal | `[theme.tui]` | Settings page, `Appearance` → `Theme`; the config key is `tui.look` |
| A web color scheme | The colors of the whole page, one set for light and one for dark | Web UI | `[theme.web]` | Settings page, `General` → `Color scheme` |
| A web theme | Corner radius, shadows, borders, blur, fonts and icons | Web UI | `[theme.web]` | Settings page, `General` → `Theme` |
| A terminal mascot | The looks and motions of the mascot on the home screen and in the sidebar | Terminal | `[mascot]` | Settings page, `Appearance` → `Figure` → `Mascot`; the config key is `tui.mascot` |

Terminal colors are not decided by packages: under `Appearance` → `Color scheme` on the settings page, `Colors` only offers `Auto`, `Follow the avatar`, `Follow the wallpaper`, `Tokyo Night` and `Terminal colors`, and `/theme` picks the same setting.

A package with `[theme]` is an appearance package, and one with `[mascot]` is a mascot package. An appearance package can carry only the terminal part, only the web part, or both.

## The manifest of an appearance package

The `package.toml` of an appearance package looks like this:

```toml
[package]
version = "0.1.0"
name = { zh = "薄荷", en = "Mint" }

[theme.tui]
file = "theme.json"     # the terminal theme: a relative path inside the package folder

[theme.web]
dir = "web"             # the web part: a relative directory inside the package folder
```

- Write at least one of `[theme.tui]` and `[theme.web]`. `file` and `dir` are required; they must not contain `..` or start with `/`.
- An appearance package may only have `[package]`, `[theme]`, `[depends]` and `[recommends]`; if you write other tables such as `protocol` or `[command]`, you get `wrong_kind`. An appearance package has no program, switches or config items.
- `miyu check` checks the terminal theme file (it must exist, be a JSON object, and be at most 256 KiB) and whether the web directory exists.

For details on every field, see [The manifest](../../authors/manifest.en.md#theme).

## Terminal themes

A terminal theme is one JSON file in which you only write the fields you want to change. The terminal lays it over the default theme: where both sides are objects it merges level by level, and anything else (text, lists) is replaced whole. Keys starting with `_` are notes, and the terminal doesn't read them.

The default theme is `packages/tui-theme-default/theme.json` in the terminal repository, with a note on every field; editing a copy of it is the fastest way. These are the sections you can write:

| Section | What it controls | What you can write |
|---|---|---|
| `frame` | Frame lines: `input` is the input box, `boxes` are the boxes opened above the input box (the command list, the session list, `/model` and so on), `toast` is a small pop-up notice, `code` is the lines of code blocks in answers, `table` is tables in answers | `rounded` rounded corners, `plain` square corners, `double` double lines, `thick` thick lines, `ascii` (`+-\|`), `none` keeps the space but draws no line |
| `marks` | Small symbols in the interface: `pointer` is the symbol before the selected row, and there are also `on`, `off`, `now`, `ok`, `fail`, `ellipsis`, `caret`, `gap`, `next`, `sep`, `dash`, `rule`, `quote`, `bar`, `side`, `secret`, `enter`, `swatch`, `heat`, `minus`, `task` (`todo`, `done`), `chart` (eight cells), `block`, `fill` (eight cells), `ring` (five cells) | Text. Marks that appear at the start of a line, such as `pointer`, `heat` and `task`, must be two cells wide |
| `text` | Text styling: `heading`, `title`, `strong`, `emphasis`, `link`, `quote`, `table_head`, `picked` (the chosen row in a list), `level` (the permission level), `model` (the model name in the footer), `selected` (a selection) | A list whose elements can be `bold`, `italic`, `underline`, `dim`, `reversed`; an empty list adds no styling |
| `pick` | How the selected row in a list looks | `bar` fills the whole row with a background color; `mark` doesn't fill and relies only on the mark and the accent color |
| `layout` | The marks in the timeline, the sidebar, the to-do list, memory cleanup and similar places | The keys are the same as in this section of the default theme; write only the ones you want to change |
| `timeline` | The spinner animation frames `spinner`, the vertical line `line`, queued `queued`, omitted `omitted` | Text; `spinner` is a list |

If you write an unknown key in `frame`, `marks` or `text`, the whole file can't be read. When the file can't be read or the package is gone, the terminal draws with the default theme and shows `Theme package unreadable, using the default theme`.

The terminal also has a built-in `ascii` theme (frame lines and marks all turned into ASCII characters, and the selected row has no background fill): setting `tui.look` to `ascii` selects it. If `tui.look` has never been set, it is the default in the Linux console (`TERM` is `linux`).

### Example: a square-frame theme

The following builds a theme package that makes the input box and pop-up boxes square, turns the mark before the selected row into an arrow, and doesn't fill the background.

1. Create the directory `tui-theme-square/` and write `package.toml` in it:

   ```toml
   [package]
   version = "0.1.0"
   name = { zh = "方框", en = "Square" }
   summary = { zh = "直角框线，选中不铺底", en = "Square frames, no highlight bar" }

   [theme.tui]
   file = "theme.json"
   ```

2. In the same directory write `theme.json`:

   ```json
   {
     "frame": { "input": "plain", "boxes": "plain", "toast": "plain" },
     "marks": { "pointer": "▶ " },
     "pick": "mark"
   }
   ```

3. Install: `miyu pkg install ./tui-theme-square`.
4. Pick: in the terminal type `/settings`, and in the `Theme` group of the `Appearance` page pick `Square`; or run `miyu config set tui.look tui-theme-square`. It takes effect on the spot.

After you change `theme.json`, run `miyu pkg install ./tui-theme-square` once more to switch to the new version.

## Web themes and color schemes

On the web UI, the `Color scheme` decides the colors and the `Theme` decides shapes and materials. Both are brought in by the directory that `[theme.web]` of an appearance package points to.

That directory is a web package, laid out like this:

```text
web/
├── manifest.json     # the package's manifest
├── index.js          # exports apply(ctx)
└── …                 # styles, fonts, icons, fetched by relative address
```

- `manifest.json`: write `name` (`{"zh": …, "en": …}`) and `inject` (the services it uses; to mount things you must write `slots`). `id` is worked out from the core's package id, so whatever you write makes no difference; a web package always counts as optional, and people can turn it off on the settings page under `Packages`.
- `index.js`: exports `apply(ctx)`. Inside it, use `ctx.slots.mount(<position>, <item>)` to mount the color scheme and the theme. Fetch other files with `new URL('<file>', import.meta.url)`.
- The script runs in the web page as usual, with no extra restrictions, the same as the shipped packages.
- Installing and removing take effect on the spot; for an upgrade, or for a package this page has already loaded, a notice above the input box says it takes effect after you refresh the page. If a package can't start (a broken manifest, no `apply`, or `apply` throws), its row on the `Packages` page of the settings shows the reason.

### Color schemes: mount into `theme.palettes`

Mount the color scheme into the position `theme.palettes`:

```js
ctx.slots.mount('theme.palettes', { id, name, render });
```

- `render(scheme)`: `scheme` is `'light'` or `'dark'`, and the function returns `{page, tui}`, two sets of colors; if it can't supply one of them, it returns `null`, and the web UI uses another scheme instead.
- Each key in `page` is written as a CSS variable of the page, `--<key>` (with `_` changed to `-`), and the keys in `tui` as `--t-<key>` (used where the web UI draws terminal-style content). You can't leave out any color variable of the whole page: a variable you don't give does not exist. For the keys of the shipped `Default` scheme, see `web-demo/packages/theme-default/manifest.json` in the web repository (the settings `light_…` and `dark_…`; the ones starting with `t_` are the `tui` set).
- The easiest way is to change a few colors of the shipped `Default` scheme: it is mounted at the same position with the id `default`; find it with `ctx.slots.list('theme.palettes')` and call its `render`.
- The thumbnail on the settings page's card draws the colors `sidebar_bg`, `surface`, `accent`, `text` and `gold`.

### Themes: mount into `skin.packs`

Mount the theme into the position `skin.packs`:

```js
ctx.slots.mount('skin.packs', { id, name, tokens, css, icons, palette });
```

| Field | Description |
|---|---|
| `id` | Starts with a lowercase letter, and contains only lowercase letters, digits and `-`. |
| `name` | The name shown in the settings page's dropdown. |
| `tokens` | A table from variable names to values. A value is a string, or one for light and one for dark, `{"light", "dark"}`. Names may only be ones the web UI recognizes (see below), or your own helper variables starting with `--skin-`. |
| `css` | Optional: the address of a style file (rules below). |
| `icons` | Optional: the address of an icon table, written like the web UI's `resources/lucide.json`; only the shapes `path`, `circle`, `rect`, `line`, `polyline`, `polygon`, `ellipse` and `g` and drawing attributes are accepted. |
| `palette` | Optional: the id of a recommended color scheme. When a person picks this theme, that scheme is switched on along with it, and they can still pick another one later. |

The variables the web UI recognizes are in `web-demo/styles/tokens.css` in the web repository, in two layers:

- The master switches for shape: `--round` (multiplier for corner radius; 1 is the shipped value, 0 makes all corners square), `--blur` (multiplier for frosted-glass blur; 0 means no blur), `--text-scale` (multiplier for font size), `--space` (multiplier for spacing), `--motion-scale` (multiplier for animation duration; 0 means no motion), `--font-ui` (the font of the interface), `--font-read` (the font for reading), `--font-mono` (the monospace font) and `--font-code` (the font of code in answers).
- One group of variables per material, not defined as shipped; whichever group you write, that kind of element changes its look. The materials are: large areas, answers, the timeline, motion, icons, the input box, the send button, your messages, cards, code blocks, small floating boxes, dialogs, the layer under a dialog, a selectable row, a transparent icon button, buttons, the primary button, text fields, small tags, the track of a switch, the knob of a switch, the track of a segmented control, the selected segment of a segmented control, the left column. Every variable name in each group and its description are in the comment at the top of that file.

For colors, write only the color variables of the color scheme (for example `var(--accent)`) and `color-mix(…)`, and don't write color values like `#rrggbb`. That way, when a person picks `Follow persona` or `Follow wallpaper`, your theme changes color with it.

**Style files** (`css`) are for what variables can't do, and follow these rules:

- Every rule starts with `:root[data-skin="<your id>"]`.
- Pick elements only by part name, `[data-part="<name>"]`, with names from `web-demo/resources/parts.json` in the web repository; write states as `[data-state="<state>"]`. Don't write class names or `#id`s.
- It may carry `@font-face`, `@media` and `@supports`; your own animation names start with `skin-<your id>-`.
- If even one rule breaks these rules, the whole style sheet is not used; a rule whose part name isn't recognized has no effect. The reason something isn't accepted is written to the console of the browser's developer tools (a warning that the skin with that id was not recognized, followed by the reason).

A complete example to copy from is `web-demo/packages/skin-pixel/` in the web repository (the `Pixel` theme, with styles, a pixel font and icons).

### Example: Mint

The following builds an appearance package that only changes the accent color and halves the corner radius.

1. Create the directory:

   ```text
   webui-theme-mint/
   ├── package.toml
   └── web/
       ├── manifest.json
       └── index.js
   ```

2. Write `package.toml`:

   ```toml
   [package]
   version = "0.1.0"
   name = { zh = "薄荷", en = "Mint" }
   summary = { zh = "绿色的强调色，圆角小一半", en = "Green accent, half-size corners" }

   [theme.web]
   dir = "web"
   ```

3. Write `web/manifest.json`:

   ```json
   {
     "id": "webui-theme-mint",
     "name": { "zh": "薄荷", "en": "Mint" },
     "inject": ["slots"]
   }
   ```

4. Write `web/index.js`:

   ```js
   // Accent color: one for light, one for dark
   const ACCENT = { light: '#1f7a5c', dark: '#6fd3ae' };

   export function apply(ctx) {
     // Color scheme: take the shipped "Default" one and change only the accent color
     ctx.slots.mount('theme.palettes', {
       id: 'mint',
       name: 'Mint',
       render: (scheme) => {
         const base = ctx.slots.list('theme.palettes').find((p) => p.id === 'default')?.render(scheme);
         return base ? { page: { ...base.page, accent: ACCENT[scheme] }, tui: base.tui } : null;
       },
     });
     // Theme: half the corner radius; picking it also switches on the color scheme above
     ctx.slots.mount('skin.packs', { id: 'mint', name: 'Mint', tokens: { '--round': '0.5' }, palette: 'mint' });
   }
   ```

5. Install: `miyu pkg install ./webui-theme-mint`. A web page that is already open loads it on the spot.
6. Pick: in the web UI type `/settings`; at the top of the `General` page, in the `Theme` group, pick `Mint` in the `Theme` dropdown; the `Color scheme` group gains a `Mint` card, which is selected along with it.
7. Look at the result: type `/gallery` to open the gallery. The gallery is a session set up with all kinds of answer and timeline entries (you can't send anything in it), for seeing how things look with your theme on.

## Mascots

**Terminal**: a mascot package may only have `[package]` and `[mascot]` (and, optionally, `[depends]` and `[recommends]`), for example:

```toml
[package]
name = { zh = "布丁", en = "Pudding" }

[mascot]
model = "mascot.json"
```

- `model` is a JSON object of at most 256 KiB, laid over the mascot built into the terminal, which is defined in `resources/mascot.json` in the terminal repository. Every field may be left out. The fields you can write are `cols`, `rows`, `radius`, `center_row`, `ramp`, `light`, `ambient`, `shapes`, `face`, `mouth`, `idle`, `gaze` and `colors`; `face`, `mouth`, `idle` and `gaze` are laid over field by field, and the others are replaced whole. If the file has any other field, or goes over a limit (`cols` 1 to 36, `rows` 1 to 18, `shapes` 1 to 32 entries), it is not used at all, and the terminal shows `Mascot package unreadable, using the built-in mascot`.
- After installing, pick it on the settings page under `Appearance` → `Figure` → `Mascot`, or run `miyu config set tui.mascot <package id>`.
- Whether the home screen and the sidebar draw a mascot is decided by two other switches, both off as shipped: "Show the figure on the home screen" and "Show the figure in the sidebar" in the same group. If the session's persona has an avatar, the avatar is what gets drawn.
- Miyu ships no mascot packages.

**Web UI**: pick the web UI's mascot on the settings page under `General` → the `Theme` group → `Mascot`; `Deniro` is there as shipped. An appearance package can also mount a mascot into the web UI (at the position `mascot.characters`), but the interface it has to implement hasn't been documented yet.

## Naming and releasing

Name and release your package as follows:

- The rules for ids are the same as for other packages (see [Writing a package](../../authors/README.en.md)). The web appearance packages already in the package source are all named `webui-theme-<name>`, and the terminal's shipped default theme package is named `tui-theme-default`; name yours in the same pattern, so that it is clear at a glance which head it is for.
- For packing and publishing to a package source, see [Writing a package](../../authors/README.en.md#publishing-to-the-package-source).

## Checking before release

Before you release, check the following in the terminal and in the web UI.

Terminal:

- Both dark and light: switch `Color mode` under `Appearance` → `Color scheme` to dark and then to light, and look at each.
- Color depth: open the terminal interface once each with `MIYU_COLOR=256`, `MIYU_COLOR=16` and `NO_COLOR=1`, and see whether the frame lines and the selected row are still recognizable. `MIYU_COLOR` also accepts `truecolor` and `none`.
- Icons: `/icons` switches between `Nerd Font icons` and `Plain characters`; look at both.
- If you changed marks: check that the widths are right (two cells for marks at the start of a line), and that nothing is misaligned in the few terminals you use most.

Web UI:

- Switch `Mode` under `Color scheme` to light and then to dark, and look at each; when the color scheme is `Follow persona` or `Follow wallpaper`, your theme's colors must change along with it.
- Look in both Firefox and Chromium: the web UI has a few places tuned separately for the differences between the two browsers.
- Open the browser's developer tools and make sure the console has no warning that your skin was not recognized, and that your package shows no fault on the settings page under `Packages`.
