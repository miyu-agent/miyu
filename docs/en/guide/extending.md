# Extending Miyu

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

You can add four kinds of things to your own Miyu without writing a resident program: skills, scripts, slash command templates and MCP servers. For the first three, you only need to put files in the right folders; MCP servers need to be written into the config file.

| | What it is | Where it goes |
|---|---|---|
| Skill | A `SKILL.md` that teaches the AI a way of doing something. | `~/.miyu/root/skills/<name>/SKILL.md` |
| Script | One file is one tool for the AI. | `~/.miyu/root/scripts/<file>` |
| Slash command template | A `.md` file; when you type `/<name>`, its body is sent to the AI as something you said. | `~/.miyu/root/commands/<name>.md` |
| MCP server | Hooks up an existing MCP server and gives its tools to the AI. | A `[mcp.<name>]` table in `~/.miyu/etc/config.toml` |

In the paths below, `~/.miyu` means the data root: by default it is `~/.miyu`, and on Windows it is `%USERPROFILE%\.miyu`; if you set `MIYU_HOME`, the data root is the folder it points to. If the three folders above do not exist, you need to create them yourself.

In presets, each of the four is a feature that can be switched on its own: a skill is `skill-<name>`, a script is `script-<tool name>`, a template is `command-<name>`, and an MCP server is `mcp-<server name>`. For details, see [Personas and presets](personas-presets.md).

Anything that is written wrongly, or has the same name as something else, does not appear, and `miyu check` tells you which one and why.

## Skills

A skill is a folder with a `SKILL.md` in it. Its format is the public Agent Skills format, so skills that tools such as Claude Code and Codex recognize work here as soon as you put them in.

### Writing a skill

For example, create `~/.miyu/root/skills/weekly-report/SKILL.md`:

```markdown
---
name: weekly-report
description: "Write the weekly report from this week's git log and notes/. Use when the user asks for a weekly report, 周报."
metadata:
  display_name: Weekly report
  display_name_zh: 写周报
  summary: Weekly report from git log and notes
  summary_zh: 照 git 记录和笔记写周报
---

# Weekly report

1. Run `git log --since="1 week ago" --oneline` in the workspace.
2. Read every file under `notes/` changed this week.
3. Write `reports/YYYY-WW.md` with three sections: Done, In progress, Blocked.
```

The part between the two `---` lines at the top of the file is YAML, and what follows is the body.

| Field | Notes |
|---|---|
| `name` | 1 to 64 characters, using only lowercase letters, digits and `-`; `-` cannot be at the start or the end, and cannot appear twice in a row. It must be the same as the folder name. If it is different, the name as written is used; if it is missing or invalid, the folder name is used, and in both cases `miyu check` gives a warning; if neither name follows the rules, the skill is not taken. |
| `description` | Written for the AI: say clearly what the skill is and when to use it. It is required. Anything over 1024 characters is cut. Put it in double quotes: a value that has a "colon and space" in it and no quotes is not valid YAML; Miyu can re-read it as one whole sentence, but gives a warning. |
| `display_name`, `summary` under `metadata` | The name and one line of description written for you. Chinese and Japanese go in `display_name_zh`, `summary_zh`, `display_name_ja` and `summary_ja`. |
| `disable-model-invocation` | With `true`, the AI does not use the skill on its own; only you can name it. |
| `user-invocable` | With `false`, you cannot name the skill; it is only for the AI itself. |

Other fields (`license`, `compatibility`, `allowed-tools` and so on) are recognized by Miyu but not used. Other files kept in the folder (reference material, bundled scripts) can be read by the AI but not changed; a bundled script is not a tool, so you need to say clearly in the body how to run it.

### When the AI reads a skill

Normally the AI sees only each skill's name, its `description` and the path of its `SKILL.md`, and it reads the body itself only when it thinks the skill is useful. So `description` must say clearly when to use the skill. Also, the AI must have a tool for reading files (the shipped "Read files") for skills to be listed for it.

You can also name a skill yourself: type `$` in the input box of the terminal interface or the web interface, and a list of skills pops up; pick one from it, or type `$weekly-report` directly. You can name several skills in one message. The bodies of the skills you named go ahead of that message, and all of it goes to the AI together. If the session's preset has the skill turned off, naming it reports `Preset "<preset>" has the skill $<name> off.`

### After you add one

- Once the skill is in the folder, open sessions see it from the next turn too.
- The `Skills` page of the web interface settings page (`/settings`) lists all skills, marked `Your own`, `From packages` or `Shared`, each with a switch; clicking `Open folder` opens `~/.miyu/root/skills/`.
- Type `$` in the input box to see whether it is in the list.

If skills have the same name, the one in `~/.miyu/root/skills/` takes priority, then the one a package brings, and last the ones in other folders.

### Reading skills in other folders

Other apps (Codex, opencode and the like) often install skills in `~/.agents/skills`. Once you turn on the following setting, Miyu recognizes those skills too:

```sh
miyu config set skills.external.enabled true
```

You can also turn on `Read Skills from other folders` at the top of the `Skills` page in the web interface. Which folders are read is decided by `skills.external.dirs`, which is `["~/.agents/skills"]` when shipped; you can write `~/…` or absolute paths, they are read in order, and for the same name the one listed first takes priority. On Windows you can also write `~\…`:

```bash
miyu config set skills.external.dirs '["~/.agents/skills", "~/src/team-skills"]'
```

In PowerShell, use double quotes outside and TOML single-quoted strings inside; it can be copied as is in both Windows PowerShell 5.1 and PowerShell 7:

```powershell
miyu config set skills.external.dirs "['~/.agents/skills', '~/src/team-skills']"
```

Both settings take effect from the next turn. Miyu does not delete skills in these folders; if you want to delete one, you need to delete it in that folder.

### Checking for mistakes

`miyu check` reports the skills that were skipped, and explains why: the top has no section wrapped in two `---` lines, the YAML cannot be parsed, there is no `description`, or neither the name nor the folder name follows the rules. Skills that were taken but are not in the proper format get a separate warning:

| Warning | What it means |
|---|---|
| The name does not match the folder; the skill goes by the written name <name> | Make the two the same. |
| The name is missing or not 1 to 64 lowercase letters, digits and single hyphens; the skill goes by its folder name <name> | Add `name`. |
| The front matter is not valid YAML | Put quotes around values that contain a colon. |
| The description is longer than 1024 characters; the rest was cut | Make the description shorter. |
| `compatibility` should be text of at most 500 characters | Make it shorter. |
| `metadata` should map text keys to text values | Values cannot be numbers, lists or nested tables. |
| Same name as <other>, which covers it; this one is not used | Pick another name. |

## Scripts

One script file is one tool. Write the description and the parameters in the comments at the top of the file, and the AI can call it just as it calls any other tool.

### Writing a script

A shell script with no parameters, `~/.miyu/root/scripts/disk-free.sh`:

```sh
#!/bin/sh
# Description: Show used and free space of every mounted disk.
# 描述：看每块盘用了多少、还剩多少
# Display name: Disk free
# 显示名称：磁盘空间
# Timeout: 10

df -h
```

This script is started by `#!/bin/sh`, so on Windows `sh` must be found on `PATH` for it to run. On Windows, you can write the same thing as a PowerShell script, `~/.miyu/root/scripts/disk-free.ps1`, which is used on Windows only:

```powershell
# Description: Show used and free space of every mounted disk.
# 描述：看每块盘用了多少、还剩多少
# Display name: Disk free
# 显示名称：磁盘空间
# Timeout: 10

Get-PSDrive -PSProvider FileSystem
```

A Python script with parameters, `~/.miyu/root/scripts/c_to_f.py`:

```python
#!/usr/bin/env python3
# Description: Convert a temperature between Celsius and Fahrenheit.
# 描述：摄氏度和华氏度互换
# 显示名称：温度换算
# Clicall: yes
# Parameters:
# {"type": "object",
#  "properties": {"value": {"type": "number"}, "to": {"type": "string", "enum": ["C", "F"]}},
#  "required": ["value", "to"]}

import json
import sys

args = json.load(sys.stdin)
v = float(args["value"])
if args["to"] == "F":
    print(f"{v} °C = {v * 9 / 5 + 32:.1f} °F")
else:
    print(f"{v} °F = {(v - 32) * 5 / 9:.1f} °C")
```

The tool name is decided by the file name: the last extension is removed, characters that are not letters, digits, `_` or `-` become `_`, and it is at most 64 characters. The tool names of the scripts above are `disk-free` (the `.sh` and `.ps1` files have the same name, so keep only one of them) and `c_to_f`. Subfolders and files starting with a dot do not count as scripts.

### The header comments

The header is the run of `#` or `//` comment lines starting at the first line of the file, with the `#!` line counted in it; it ends at the first line that is not a comment. After the header, leave a blank line before writing any other comment; otherwise something like `Timeout: …` in a later comment is read in too. Each line has the format `Key: value`, and the colon can be either the full-width Chinese colon or the ordinary one.

| Key | Notes |
|---|---|
| `Description` | One line written for the AI. It is required. |
| `描述` | One line of description written for you. |
| `Display name`, `显示名称` | The name written for you, in English and in Chinese. |
| `Parameters` | The JSON Schema of the parameters; the top level must be `"type": "object"`. It can be written on the same line, or across several lines starting from the next line, until it makes one complete JSON. Leaving it out means the script has no parameters. |
| `Timeout` | The most seconds the script may run; it must be a positive integer, and the default is `60`. When the time is up, the whole group of processes is killed. |
| `Clicall` | With `yes` (or `true`), when the AI writes a script inside a command, it can also call this script with `miyu call`, and the result goes to that command and does not go into the conversation. Leaving it out means `no`. It suits scripts that only read or look things up; do not set it on scripts that change things, send things or cost money. |
| `Venues` | Which kinds of session can use it: pick some of `local` (the terminal interface and the web interface on this machine), `private` (private chats on a chat platform) and `group` (groups), separated by commas, for example `Venues: local, private`. Leaving it out means every kind of session can use it. |
| `Scope` | Narrows it further within `Venues`: `any` (the default), `local` (sessions on this machine), `local_main` (the main session on this machine, not given to subagents), `local_main_attended` (the main session on this machine, and someone is watching), `spawn` (sessions on this machine, and the subagent depth has not reached the limit). |
| `Role` | Only `read_file` can be written, and it means this tool is for reading text files. |

If `Description` is missing, or the value of `Parameters`, `Timeout`, `Clicall`, `Venues`, `Scope` or `Role` is wrong, the whole script is not taken. A key name for `Role` or `Scope` that is one letter off, such as `role` or `Scpoe`, also counts as wrong. Other keys are recognized by Miyu but not used.

### How it runs

- How a script is started depends on whether its first line has `#!`:

  | | With `#!` | Without `#!` |
  |---|---|---|
  | Linux, macOS | Started as written: the interpreter, the arguments after it, and then the script. | The file is run directly, and it needs the executable permission: `chmod +x ~/.miyu/root/scripts/<file>` |
  | Windows | If the interpreter is written as an absolute path that exists on this computer, that one is used; otherwise the interpreter's name is looked up on `PATH`: with `env`, the name after `env` is taken, and `python3` is turned into `python`. For example, `#!/usr/bin/env python3` looks for `python`, and `#!/bin/sh` looks for `sh`. | Decided by the extension: `.py` uses `python`, `.ps1` uses Windows PowerShell (`powershell`, which reads no profile and is not limited by the execution policy), `.js` uses `node`, and `.cmd` and `.bat` use `cmd /C`; any other extension is run directly. |

  Miyu does not bring interpreters, so you need to install the ones you use yourself. On Windows, once Python and Node are installed, `python` and `node` must be found on `PATH`.
- Arguments: the arguments the AI gives are one JSON object, which can be read in full from standard input; when it is at most 30 KiB, a copy is also in the environment variable `MIYU_ARGS_JSON`. Long arguments are only on standard input, so reading standard input is the safest.
- Result: standard output and standard error go to the AI in the order they were written, at most 30000 characters; if there is more, half is kept from the start and half from the end. An exit code other than `0` counts as failure, and the reason should be written in the output.
- Progress: print a whole line starting with `miyu-progress: `, and you see it in the interface while the AI does not. Write this line to standard error and flush it at once, for example in Python `print("miyu-progress: 3/10", file=sys.stderr, flush=True)`.
- The working directory is the session's working directory. Python reads and writes standard input and standard output as UTF-8 (`PYTHONUTF8=1`).
- A script cannot call `miyu call`.

Miyu gives scripts several folders through the following environment variables:

| Environment variable | What it is |
|---|---|
| `MIYU_CACHE_DIR` | A writable cache folder under `~/.miyu/var/cache/scripts/`, one per script. Content not used for 30 days is cleared, so keep only things here that can be made again if lost. |
| `MIYU_STATE_DIR` | A state folder that is kept (for a login, where the last run stopped and so on), one per script. After you delete the script, the state folder is still there, and `miyu check` reminds you where it is. |
| `MIYU_IMAGES_DIR` | An empty folder for handing over images, a new one for every call. |
| `MIYU_PICTURES_DIR`, `MIYU_VIDEOS_DIR`, `MIYU_DOCUMENTS_DIR`, `MIYU_DOWNLOADS_DIR` | `pictures`, `videos`, `documents` and `downloads` under `~/.miyu/root/`; put files meant for you here. Only sessions on this machine have these variables, so check that they exist before using them. |
| `MIYU_CALLER_VENUE` | The kind of session the script was called in: `local` for sessions on this machine, and the venue id for sessions on a chat platform. |
| `MIYU_CALLER_OWNER` | Whether the person speaking this turn is you yourself: `1` or `0`. It only tells the script and does not stop anyone; to limit who can use the script, you need to use `Venues`. |
| `MIYU_MODEL`, `MIYU_EFFORT` | The model and reasoning effort of this turn. When no model has been settled yet, these two variables are absent. |

### Handing images to the AI

If you want the AI to see an image directly, copy the image into `MIYU_IMAGES_DIR`:

```python
import os, shutil
shutil.copy("chart.png", os.environ["MIYU_IMAGES_DIR"])
print("Drew 1 chart.")
```

- Images are taken in file-name order, at most 4; PNG, JPEG, GIF and WebP are supported, recognized by file content and not by extension.
- An image over 5 MiB, or with a side over 8000 pixels, is scaled down first; one that cannot be scaled down is not handed to the AI.
- Only regular files directly in this folder count, and links are not followed.
- The AI does not know about an image that was not handed over; the run log has a `script image dropped` line.
- If this call was killed because it timed out, no images are handed over; if the exit code is other than `0`, they are still handed over.

### Permissions a script runs with

Scripts follow the same rules as commands the AI runs (see [Permissions and sandbox](permissions.md)):

- Full access: the script does not run in the sandbox, and it has all the permissions of your system user.
- Read-only: the script runs in the sandbox, and it can write only to its own cache, state and image folders and the four folders above, and nowhere else.
- Groups and private chats with strangers on chat platforms: the script runs in the sandbox, and it can write only to that session's workspace and its own cache, state and image folders. On Windows, scripts do not run in these two kinds of session; on Linux, if the sandbox cannot confine Unix sockets, scripts do not run either; for details, see [Permissions and sandbox](permissions.md#sessions-on-chat-platforms).

The script file itself is in the data root, so it can still be read inside the sandbox. Scripts that need to touch hardware or need `sudo` do not work in the sandbox. On Windows, scripts that use WMI (`Get-CimInstance`, `Get-WmiObject`, `wmic` and the like) cannot connect to WMI inside the sandbox either; to use such scripts, you need to switch to full access. For the other differences between the sandboxes of each system, see [Permissions and sandbox](permissions.md#the-three-platforms).

### After you add one

- When a script is added, changed or deleted, the core knows at once, and the tools change from the next turn, with no restart needed.
- In the terminal interface, type `/tool-list` to see which tools this session has. The `Scripts` page of the web interface settings page lists all scripts, each with a switch; clicking `Open folder` opens `~/.miyu/root/scripts/`.
- If the tool names are the same, the script in `~/.miyu/root/scripts/` takes priority over one a package brings. A script with the same name as another tool is not registered.

A script can also be a link pointing to a file you keep elsewhere, and in that case the file it points to is what counts; a broken link is skipped. A link pointing elsewhere in the data root is not recognized.

### Checking for mistakes

`miyu check` reports the following problems:

| What you see | How to fix it |
|---|---|
| `This script was skipped`: `Description is missing or empty` | Add `Description`. |
| `This script was skipped`: `Parameters is not valid JSON: …` | The JSON is unfinished or wrong. |
| `This script was skipped`: `Parameters must be a JSON object schema` | Write `"type": "object"` at the top level. |
| `This script was skipped`: `Timeout "…" is not a positive number of seconds` | Write a positive integer. |
| `This script was skipped`: `Clicall "…" is not yes or no` | Write `yes` or `no`. |
| `This script was skipped`: `Venues "…" must list some of local, private, group, each once` | Write only these three, with no repeats. |
| `This script was skipped`: `Role …`, `Scope …` | Write the key names and values as in the table above. |
| `Script <name> has the same name as another tool and was not registered` | Rename the file. |
| `The core has not picked up script <name> yet` | You have just added the script, so check again in a while; if it stays like this, restart the core. |
| `There is a state folder for the script …, but no such script now` | If you no longer need it, delete that folder. |

## Slash command templates

A slash command template is a Markdown file, and its file name is the command name. When you type `/<name> arguments`, the body is expanded with the arguments and sent to the AI as something you said, and the timeline shows the line you typed.

### Writing a template

For example, create `~/.miyu/root/commands/commit-msg.md`:

```markdown
---
description: Draft a commit message for the staged changes
argument-hint: "[style]"
metadata:
  summary_zh: 给暂存的改动写提交说明
---

Read `git diff --cached` and draft a one-line commit message.
Style: $ARGUMENTS
```

When you type `/commit-msg short`, what the AI receives is the body, with `$ARGUMENTS` replaced by `short`.

- Name: it starts with a lowercase letter, uses only lowercase letters, digits and `-`, and is at most 32 characters. Subfolders, files starting with a dot and files that are not `.md` do not count as templates.
- The top section can be left out, and then the whole file is the body.

| Field | Notes |
|---|---|
| `description` | The line of description shown in the command list. |
| `argument-hint` | A hint for what should follow the name. |
| `summary_zh`, `summary_ja` under `metadata` | The line of description in Chinese and in Japanese. |

Other fields (`allowed-tools`, `model` and so on) are recognized by Miyu but not used.

### Arguments

- `$ARGUMENTS` is replaced by all the text after the name, with leading and trailing whitespace removed.
- `$ARGUMENTS[0]` is the first word and `$ARGUMENTS[1]` the second, split on whitespace. Put a value that contains spaces in English double quotes: for `/commit-msg "very short"`, `$ARGUMENTS[0]` is `very short`. If there is no such word, it is replaced by nothing.
- If the body has no `$ARGUMENTS` at all and you added text after the command, that text is appended to the end of the body after a blank line.

### After you add one

- The template is looked up again every time you type the command, so a change needs no restart.
- Type `/` in the terminal interface or the web interface to see whether it is in the command list.
- If names are the same, your template takes priority over one a package brings; if it has the same name as a command that comes with Miyu, your template does not count, and the built-in command takes priority.
- Who can use a template is the same as for the commands that come with Miyu; for details, see [Slash commands](commands.md).

`miyu check` reports `This slash command was skipped: …` (the YAML at the top cannot be parsed, or is not a table), `Covered by <other>, which has the same name; this one is not used` and `Same name as Miyu's built-in /<name>; this one is not used`.

## MCP servers

An MCP (Model Context Protocol) server can be connected in two ways: Miyu starts a program on this machine and talks to it over standard input and output; or Miyu connects to an address (Streamable HTTP).

### Adding it to the config file

Each server is written as one `[mcp.<name>]` table in `~/.miyu/etc/config.toml`. You can open the config file with `miyu config edit`, which checks it automatically before saving; `miyu config set` cannot change these tables. Once you save, it takes effect, with no restart needed.

A server that starts a program on this machine is written like this:

```toml
[mcp.notes]
command = ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/home/me/notes"]
env = { LOG_LEVEL = "warn" }
```

On Windows, write paths in the Windows format, as TOML single-quoted strings, with each `\` left as it is:

```toml
[mcp.notes]
command = ["npx", "-y", "@modelcontextprotocol/server-filesystem", 'C:\Users\me\notes']
env = { LOG_LEVEL = "warn" }
```

A server that connects to an address is written like this:

```toml
[mcp.acme-docs]
url = "https://mcp.example.com/mcp"
bearer = { secret = "acme-docs" }
headers = { X-Workspace = "team-a" }
venues = ["local", "private"]
timeout_ms = 120000
clicall = false
```

The secret that `bearer` refers to must first be stored in the secrets file. Run:

```sh
miyu provider login acme-docs
```

What you paste is not shown on the screen.

| Field | Notes |
|---|---|
| Table name `<name>` | The server name: it starts with a lowercase letter, uses only lowercase letters, digits and `-`, and is at most 32 characters. |
| `command` | The command and its arguments, one word per item, not run through a shell. The first item can be an absolute path, `~/…` (on Windows `~\…` is accepted too), or just a name to be looked up on `PATH` (`npx`, `uvx`, `docker` and the like). On Windows, a bare name is looked up on `PATH` as `.exe`, `.cmd` and `.bat`; `npx` and `uvx` are `.cmd` and are found all the same. `~` is replaced only in the first item; the arguments after it are given to the program as written. Write only one of `command` and `url`. |
| `env` | Used together with `command`: environment variables for the server. |
| `url` | The server's address, starting with `https://`; `http://` can only connect to servers on this machine. Write only one of `url` and `command`. |
| `bearer` | Used together with `url`: the token, sent as `Authorization: Bearer <value>`. |
| `headers` | Used together with `url`: other request headers. Names can use only letters, digits and `-`; `Authorization`, `Mcp-Session-Id`, `MCP-Protocol-Version`, `Mcp-Method` and `Mcp-Name` cannot be written. |
| `venues` | Which kinds of session can use it: pick some of `local`, `private` and `group`. The default is `["local"]`, which gives it only to sessions on this machine. |
| `timeout_ms` | The longest to wait for one call, in milliseconds, from `1000` to `3600000`; the default is `600000`. |
| `clicall` | Whether the AI can call this server's tools with `miyu call` inside a command. The default is yes; you can write `true`, `false`, or `"yes"`, `"no"`. For servers that write things or send things, write `false`. |

The values of `env`, `bearer` and `headers` can be written directly as text, or as a reference: `{ secret = "<secret name>" }` takes the value from the secrets file, and `{ env = "<variable name>" }` takes it from the core's environment variables. Write the token as a reference; do not put the token's value in the config file.

You can also click `Add server` on the `MCP` page of the web interface settings page (`/settings`), choose `Local` or `URL`, and then fill in the form.

If a server in the config file has the same name as one a package brings, the one in the config file takes priority, and the one in the package does not start.

### Servers that need a browser login

Some servers accept only browser authorization and cannot give you a personal token. For such a server, write only `url` and no `bearer`. Once connected, it stays at `Sign-in required`; then sign in with these steps:

1. Run `miyu mcp login <server name>`.
2. The command prints an address and opens it in the browser automatically; click agree on that page. If the browser did not open by itself, open the printed address yourself.
3. When you see `logged in, <server name> connected`, you are done.

If the browser is on another computer: after authorizing, paste the whole address from the browser's address bar back into the command line and press Enter. The command waits at most 10 minutes. The token is stored in the secrets file, and the core renews it automatically when it is about to expire. When you no longer need it, run `miyu mcp logout <server name>`.

The `MCP` page of the web interface and the `MCP` page of the terminal interface settings page also have `Sign in`. A server with `bearer` written does not go through sign-in.

### What the AI sees

| What the server gives | What it becomes in Miyu |
|---|---|
| Tools | Tools of the AI, named `mcp__<server name>__<tool name>`. Characters that are not letters, digits, `_` or `-` become `_`, and the name is at most 64 characters; a description is at most 2048 characters. |
| Resources | Two more tools: `mcp__<server name>__list_resources` lists the resources page by page, and `mcp__<server name>__read_resource` reads one resource by its address. If the server has a tool of the same name itself, the server's own tool is used. |
| Prompts | A slash command `/<server name>:<prompt name>`, shown in the command list. The text after the command is split on whitespace and matched in order to the arguments the prompt declares, with the last argument taking all the remaining text; put a value that contains spaces in English double quotes. What comes back is sent to the AI as something you said. It works only in sessions on this machine. |
| Instructions (`instructions`) | Put at the end of the AI's system prompt, one passage per server, at most 4000 characters. |

The read-only mark: if the server marks a tool `readOnlyHint: true`, you are not asked under any permission level; a tool that is not marked is treated like the network kind, so under full access you are not asked, and under read-only you are asked every time. For details, see [Permissions and sandbox](permissions.md).

### After you add one

- The `MCP` page of the terminal interface settings page lists the current state of each server, `Off`, `Starting`, `Running`, `Reconnecting`, `Stopped` or `Sign-in needed`, and how many tools it has. The `MCP` page of the web interface lists the servers too, and you can `Restart`, `Edit` and `Remove` them there.
- In the terminal interface, type `/tool-list` to see whether the tools are there.
- If a server lists some tools and prompts but they were not registered, the web interface shows `The server lists these, but Miyu didn't register them`, and `miyu check` reports them too.

### Config mistakes and start failures

- `miyu check` reports `Invalid MCP server: …`, with the line number. The server that is written wrongly does not start, and the other servers work as usual.
- The working directory of a program on this machine is `~/.miyu/var/lib/mcp/<server name>/` (also in the environment variable `MIYU_STATE_DIR`), and it does not run in the sandbox. Its standard error is in `~/.miyu/var/log/mcp/<server name>.stderr`; if it fails to start, look at this file first.
- A server that fails to start or crashes is retried after a while, and stops after 5 failures in a row. After you fix it, click `Restart` on the `MCP` page.
- For a server started with `npx` or `uvx`, you need to install Node, Python and the like yourself first.

## Doing more

If you need a program that keeps running, an interface or dashboard page of your own, or you want to give these things to other people, make them into a package: see [Writing a Miyu package](../dev/packages.md) and [Writing an extension](../dev/extensions.md). Put skills, scripts and templates in the package folder's `skills/`, `scripts/` and `commands/` respectively; the format is the same as described on this page.

You can also have the AI help you write them. The shipped "Authoring" package brings two skills:

- `skill-creator` (writes skills): writes a skill in the structure of a package, checks it and installs it.
- `package-creator` (writes scripts and packages): makes a script into a tool and puts it in a package, checks it and installs it.

In the input box, type `$skill-creator` or `$package-creator` followed by what you want; or just say "write a skill" or "write a tool", and the AI reads the two skills by itself. What both skills write are packages; once installed, you manage them on the Packages page; for details, see [Packages](packages.md).
