# Installing, upgrading and uninstalling

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page explains how to install, upgrade and uninstall Miyu, and what ends up on your computer after you install it. If you want the core to keep running, or want to deploy it on a server, see [Keeping it running, and servers](service.md).

## Choosing how to install

The ways you can install Miyu depend on your system:

| System | Architecture | Install script | AUR | Homebrew | Tray installer |
|---|---|---|---|---|---|
| Linux | x86_64 | `install.sh` | Yes | No | deb, rpm |
| Linux | aarch64 | `install.sh` | Yes | No | None |
| macOS | Apple silicon | `install.sh` | No | Yes | dmg |
| Windows | x86_64 | `install.ps1` | No | No | msi |

There is currently no release archive for Intel Macs, or for 32-bit Windows and Windows on ARM.

macOS needs version 12 or later. If you run the install script on an older macOS, it prints `needs macOS 12 or later; …` and installs nothing.

Each way of installing also installs different things:

| Way of installing | Core and command line | Terminal UI | Web UI | System tray |
|---|---|---|---|---|
| Install script | Yes | Yes | Yes | No |
| `miyu-agent` on the AUR, `miyu-agent` plus the cask on Homebrew | Yes | Yes | Yes | Yes |
| Tray installer | Yes | No | Yes | Yes |

Use only one way of installing on a computer; mixing them makes them conflict with each other.

## Using the install script

The install script downloads the archive for your system from the GitHub releases page, and installs it only after it passes verification. You do not need administrator rights, and you do not need `sudo`.

### Linux, macOS

Run:

```sh
curl -fsSL https://raw.githubusercontent.com/miyu-agent/miyu/main/packaging/install.sh | sh
```

> Your system needs `curl` and `tar`.

You can add arguments after `sh -s --`:

| Argument | What it does |
|---|---|
| `--version <version>` | Installs the given version, for example `--version 2026.11.0` |
| `--prerelease` | Counts pre-releases too, and installs the latest of them |
| `--uninstall` | Uninstalls |

Without `--version` or `--prerelease`, the script installs the latest stable release. If there is no stable release yet, the script stops and says `no stable release yet; add --prerelease to install a pre-release`, and installs nothing.

For example, to install version 2026.11.0:

```sh
curl -fsSL https://raw.githubusercontent.com/miyu-agent/miyu/main/packaging/install.sh | sh -s -- --version 2026.11.0
```

After installing:

- The whole directory from the archive is placed in `~/.local/lib/miyu/`, and the `install.toml` next to it records how Miyu was installed; it contains `channel = "script"`.
- `~/.local/bin/miyu` is a link to `~/.local/lib/miyu/miyu`.
- On Linux, the script also writes `~/.local/share/mime/packages/miyu.xml` (under `XDG_DATA_HOME` if you have set it), so that the system recognizes `.miyu` package files.
- The script does not change your shell config. If `~/.local/bin` is not in `PATH`, the script ends with the note `Note: … isn't on PATH; add this line to your shell's config: …`; add `export PATH="$HOME/.local/bin:$PATH"` to your shell's config file and you are done. If the first `miyu` found on `PATH` is one somewhere else, the script tells you that too.

If Miyu is already installed, the script says `… is already installed (…); use miyu upgrade to upgrade` and changes nothing.

### Windows

Run this in PowerShell (both Windows PowerShell 5.1 and PowerShell 7 work):

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/miyu-agent/miyu/main/packaging/install.ps1)))
```

Arguments go at the end of the command: `-Version <version>`, `-Prerelease`, `-Uninstall`, with the same meanings as in the table above. For example:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/miyu-agent/miyu/main/packaging/install.ps1))) -Version 2026.11.0
```

After installing:

- The whole directory from the archive is placed in `%LOCALAPPDATA%\Programs\Miyu\`, and the `install.toml` next to it contains `channel = "script"`.
- The script adds this directory to the current user's `PATH`, changing only your own environment variables. Terminals you open afterwards can run `miyu` directly, and so can the window you ran the install script in, right away.

### What the script verifies

Before installing, the install script runs three checks in order:

1. It downloads this version's `SHA256SUMS` and its signature `SHA256SUMS.sig`, and verifies the signature with the release public key written into the script.
2. It downloads the archive and checks its SHA-256.
3. It unpacks the archive and runs the new `miyu --version` once to confirm the version is right.

If any step fails, the script stops and installs nothing. Verifying the signature needs an `openssl` that supports Ed25519 (OpenSSL 3 or later; on Windows, the one that comes with Git for Windows works). The one that comes with macOS is LibreSSL, which cannot verify it, and the tools that come with Windows do not support Ed25519 either. When the signature cannot be verified, the script checks only the SHA-256, carries on installing, and tells you so:

| Situation | What the script says |
|---|---|
| `openssl` does not support Ed25519 (this is the case with the one that comes with macOS) | `This machine's openssl doesn't support Ed25519, so the signature wasn't checked (it isn't broken); checking SHA-256 only. …` |
| No `openssl` on Linux or macOS | `No openssl here, so the signature can't be checked; checking SHA-256 only. …` |
| No `openssl` on Windows | `No openssl here (Windows' own tools don't support Ed25519), so the signature wasn't checked (it isn't broken); checking SHA-256 only. …` |

If you want to verify the signature yourself, use the `gh attestation verify <file> -R miyu-agent/miyu` that the note suggests.

If `GITHUB_TOKEN` is set, the script sends it when it calls the GitHub API (but not when downloading files). Because anonymous access is limited to 60 requests an hour, networks where several people share one exit can easily hit the limit, and the script then says `GitHub rate limit reached`.

## Installing from the AUR (Arch Linux)

On Arch Linux you can install Miyu from the AUR. Use the AUR helper you are used to (for example `paru`) and run:

```sh
paru -S miyu-agent
```

These are the packages on the AUR:

| Package | Contents | Install location |
|---|---|---|
| `miyu-agent` | The bundle; it has no files of its own and depends on the four packages below | |
| `miyu-core` | Core and command line | `/usr/lib/miyu/`, with `/usr/bin/miyu` as a link to it, plus `/usr/share/mime/packages/miyu.xml` |
| `miyu-tui` | Terminal UI | `/usr/share/miyu/packages/tui/` |
| `miyu-webui` | Web UI | `/usr/share/miyu/packages/webui/` |
| `miyu-applet` | System tray; needs system libraries such as `gtk3` | `/usr/bin/miyu-applet`, plus the application menu entry and icons |
| `miyu-agent-git` | Core, terminal UI and web UI built from the latest source, in one package, without the system tray | Same as `miyu-core`, `miyu-tui`, `miyu-webui` |
| `miyu` | A transition package for users of the old 0.7 version; it has no files of its own and depends on `miyu-agent` | |

- If you do not need the system tray, you can install the three packages `miyu-core miyu-tui miyu-webui`, or only the ones you need. The terminal UI and the web UI both depend on `miyu-core`.
- `miyu-agent-git` conflicts with `miyu-core`, `miyu-tui`, `miyu-webui` and `miyu-agent`. Building it needs `git`, `rustup` and `python`, and the build goes online to fetch dependencies. If you want the system tray, install `miyu-applet` separately.
- `miyu-core` conflicts with `miyu`, the old package from the 0.7 generation; when you install, pacman asks you to confirm replacing the old package.
- `install.toml` is written in `/usr/lib/miyu/` and contains `channel = "aur"`.

## Installing with Homebrew (macOS)

On macOS you can install Miyu with Homebrew. Miyu's tap (a third-party Homebrew repository) is `miyu-agent/miyu`; run these in order:

```sh
brew tap miyu-agent/miyu
brew install miyu-agent
brew install --cask miyu-applet
```

What these commands install:

| Name | Kind | Contents |
|---|---|---|
| `miyu-agent` | formula | The bundle; it depends on the three formulae below; the system tray is a cask that you install separately |
| `miyu-core` | formula | Core and command line, placed in the formula's `libexec/`, with `miyu` linked into Homebrew's `bin/`; `install.toml` contains `channel = "brew"` |
| `miyu-tui` | formula | Terminal UI, installed into `share/miyu/packages/tui/` under the Homebrew prefix |
| `miyu-webui` | formula | Web UI, installed into `share/miyu/packages/webui/` |
| `miyu-applet` | cask | The system tray `Miyu.app`; depends on `miyu-core` and `miyu-webui` |

All of these packages install only on Macs with Apple silicon.

## System tray installers

The system tray installer bundles the core, the web UI and the system tray together. After installing, open `Miyu` from the application menu and it is ready to use, with no terminal needed; the terminal UI is not included. Download it from the system tray's releases page <https://github.com/miyu-agent/miyu-applet/releases>:

| System | File |
|---|---|
| Linux x86_64 | `.deb`, `.rpm`; needs GTK 3 |
| macOS Apple silicon | `.dmg`; drag `Miyu.app` into `Applications` |
| Windows x86_64 | `.msi`; comes with a copy of PowerShell 7 |

> These installers are not signed, and their releases are all marked as pre-releases.

`miyu-core` from the system repositories conflicts with the core these installers put in place, so do not mix them with the AUR or Homebrew ways of installing.

For how to use the system tray, see [System tray](heads/applet.md).

## Confirming the installation

Run:

```sh
miyu --version
```

If it prints a line like `miyu 2026.11.0`, the installation succeeded. The version number has the form "year.month.release number within that month".

Run `miyu` in a terminal to open the interface. The first time you open it, an onboarding guide walks you through setting up a model provider and choosing a theme and a persona; for details, see [Quick start](quickstart.md).

## What gets installed

The install script installs a one-piece bundle, a single directory that contains:

- Five programs: `miyu` (core and command line; the core is simply `miyu` running in the background), `miyu-sandbox`, `miyu-extract`, `miyu-tui` (the terminal UI) and `miyu-web` (the web UI). Linux and macOS have a sixth program, `miyu-watchdog`: if the core exits unexpectedly, it ends the commands and extensions that the core started; Windows does this with the system's job objects, so it has no such program. On Windows these programs all have the `.exe` suffix, for example `miyu.exe` and `miyu-sandbox.exe`.
- `resources/`: the core's shipped resources, plus the two packages for the terminal UI and the web UI (`resources/packages/tui/`, `resources/packages/webui/`).
- `LICENSE`, `THIRD-PARTY-LICENSES.txt`, `README.txt`. `README.txt` explains how to use the archive if you unpack it yourself: on Linux and macOS it says `Add this folder to PATH, or link miyu into ~/.local/bin`, and on Windows `Add this folder to PATH (or call miyu.exe by its full path)`.
- The `install.toml` written by the install script.

The terminal UI and the web UI are two packages, each with its own version number, and every version of Miyu comes with the copy that matches it. You can see them in `miyu pkg list`, with the ids `tui` and `webui`. The AUR and Homebrew split them into separate packages and install them into `share/miyu/packages/` under the system directory, and the core finds them there as well. The core looks in these places:

| System | Where packages installed by the system package manager are looked for |
|---|---|
| Linux | `miyu/packages/` under each directory in `XDG_DATA_DIRS`; if it is not set, `/usr/local/share:/usr/share` is used. Packages installed by Linuxbrew are not found automatically; you need to add Linuxbrew's `share` directory to `XDG_DATA_DIRS` yourself |
| macOS | `share/miyu/packages/` under the Homebrew prefix, where the prefix is the parent of the directory `miyu` is in |
| Windows | There is no such place; only packages in the install directory and the data root are looked for |

Because `resources/` is replaced as a whole on every upgrade, do not put your own things in the install directory.

Your sessions, settings and keys are not in the install directory but in the data root (the directory where Miyu keeps your data): `~/.miyu` by default, `%USERPROFILE%\.miyu` on Windows, or the directory the environment variable `MIYU_HOME` points to if you have set it. Installing, upgrading and uninstalling never change the data root.

## Upgrading

To upgrade Miyu, run:

```sh
miyu upgrade
```

Arguments you can add:

| Argument | What it does |
|---|---|
| `--prerelease` | Counts pre-releases too (versions whose tag contains `-`, such as `-rc.5`) |
| `--yes` | Upgrades directly, without asking `Upgrade Miyu … → …? [Y/n]` |
| `-h`, `--help` | Shows help |

`miyu upgrade` reads the `install.toml` next to the `miyu` program to tell how Miyu was installed:

| `channel` | How it was installed | What `miyu upgrade` does |
|---|---|---|
| `script` | Install script | Upgrades itself; the steps are below |
| `aur` | AUR | Says `this Miyu was installed with AUR; upgrade it with the package manager`, and the next line is `paru -Syu` |
| `brew` | Homebrew | Says `this Miyu was installed with Homebrew; upgrade it with the package manager`, and the next line is `brew upgrade` |
| No `install.toml` | Tray installer, or an archive unpacked by hand | Says `this Miyu was not installed by the install script or a package manager, so it does not upgrade itself`, and gives the download address |

If Miyu was installed with the install script, `miyu upgrade` upgrades it like this:

1. It reads the feed of the GitHub release page, `https://github.com/miyu-agent/miyu/releases.atom`, and picks the newest release that is newer than the current version. The feed is an ordinary web page, so it does not count against the GitHub API limit of 60 anonymous requests an hour, and an upgrade does not fail because several people share one network exit. A version whose tag contains `-` (for example `v2026.11.0-rc.5`) is a pre-release, and it counts only when you add `--prerelease`. If a release has no archives uploaded, `miyu upgrade` skips it and looks at the next older one, but it never picks a version older than the current one. If there is no newer version to upgrade to, it says `already up to date (…)`.
2. It downloads this version's `SHA256SUMS` and `SHA256SUMS.sig`, verifies the signature with the release public key built into the program, and then asks whether you want to upgrade. Pressing Enter or typing `y` means yes. If it is not running in a terminal and cannot read an answer, it says `cancelled: no confirmation`; in that case you need to add `--yes`.
3. It downloads this version's archive, checks the SHA-256, unpacks the archive and runs the new `miyu --version` once.
4. It replaces the files in the install directory that belong to Miyu and does not change `install.toml`. Anything that is not Miyu's is left as it was, with the note `… item(s) in the install folder are not Miyu's and were left as they were`. The old files are first moved into `.miyu-old-<old version>/` in the install directory and deleted once the replacement is done; on Windows, the running `miyu.exe` cannot be deleted, so it is left until the start of the next `miyu upgrade`.
5. It says `upgraded Miyu … → …`.

The terminal UI and the web UI are in the same archive, so they are upgraded along with it. If any step fails, the upgrade stops and the installed version stays as it is.

After the upgrade, the core that is already running is still the old version. Run:

```sh
miyu core stop
```

The next time you open the terminal UI or the web UI, the version that starts is the new one. If you have the start-at-boot service installed and want the service to keep managing the core, also run `miyu service enable`: with Linux's systemd user service and on macOS the new version starts right away; with Linux's desktop autostart and on Windows it starts at your next login. For details, see [Keeping it running, and servers](service.md#making-the-service-take-over-now).

If you installed with the tray installer, download the new installer and install it over the old one.

### Switching installation methods

`channel` is decided by how Miyu was installed, so do not edit `install.toml` by hand. To switch from one way of installing to another:

1. Uninstall the current Miyu as described in "Uninstalling" below.
2. Install it the new way.

The data root is not affected, so your sessions and settings are still there after the switch.

If you want to use pre-releases: when you installed with the install script, add `--prerelease` when upgrading; when you installed from the system repositories, follow the package manager's own way.

## Uninstalling

Every way of installing removes only the programs when you uninstall, and keeps the data root.

| Way of installing | How to uninstall |
|---|---|
| Install script (Linux, macOS) | `curl -fsSL https://raw.githubusercontent.com/miyu-agent/miyu/main/packaging/install.sh \| sh -s -- --uninstall` |
| Install script (Windows) | `& ([scriptblock]::Create((irm https://raw.githubusercontent.com/miyu-agent/miyu/main/packaging/install.ps1))) -Uninstall` |
| AUR | `sudo pacman -Rns miyu-agent miyu-core miyu-tui miyu-webui miyu-applet`; if you installed the transition package, add `miyu` as well |
| Homebrew | `brew uninstall --cask miyu-applet`, then run `brew uninstall miyu-agent miyu-tui miyu-webui miyu-core` |
| Tray installer | Use the system's way of removing software: `apt remove`, `dnf remove`; on Windows, uninstall it in `Settings → Apps`; on macOS, drag `Miyu.app` into the Trash |

The uninstall script first stops the start-at-boot service (`miyu service disable`) and the core (`miyu core stop`), then deletes the install directory, the `~/.local/bin/miyu` link and the `.miyu` file type; on Windows it also removes the install directory from your `PATH`. If a directory was not installed by the install script, the uninstall script leaves it alone. At the end the script says `Miyu is uninstalled. Your data is still in …; delete it yourself if you don't need it.`

On Windows, if a Miyu program is still open, the install directory cannot be deleted; the script then reports `can't remove … (…): close any running Miyu program and try again` and stops, and `PATH` is not changed either. Close Miyu programs such as the terminal UI and the web UI, then uninstall again.

For the other ways of installing, stop the service and the core yourself before uninstalling:

```sh
miyu service disable
miyu core stop
```

### Deleting the data

If you do not want the data either, delete these places after uninstalling the programs:

| What | Linux | macOS | Windows |
|---|---|---|---|
| Data root | `~/.miyu` | `~/.miyu` | `%USERPROFILE%\.miyu` |
| Cache | `~/.cache/miyu` (under `XDG_CACHE_HOME` if you have set it) | `~/Library/Caches/Miyu` | `%LOCALAPPDATA%\Miyu\cache` |

If `MIYU_HOME` is set, the data root is the directory it points to. **The data root holds all your sessions, memory, settings and stored keys, and once deleted they cannot be recovered**, so back up anything you want to keep first.

## Migrating from the old 0.7 version

The old version's data is not migrated automatically. Because the old version's data directory is also `~/.miyu`, and this version's core does not recognize it and will fail to start, you need to move it aside first. On Linux and macOS, run:

```bash
mv ~/.miyu ~/.miyu-0.7
```

On Windows, run this in PowerShell:

```powershell
Rename-Item $HOME\.miyu .miyu-0.7
```

If you upgraded from the old `miyu` package on the AUR, pacman prints `Run "miyu migrate" to bring your data over from the old Miyu`. `miyu migrate` is a command that comes with the migration package, so you need to install that package first:

```sh
miyu pkg install migrate
```

Then follow [Migrating from the old 0.7 version](migrate.md) step by step.
