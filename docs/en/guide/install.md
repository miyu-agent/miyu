# Installing, upgrading and uninstalling

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Installing Miyu on your own machine, seeing what was installed, upgrading and removing it completely are all on this page. After it is installed, for how to keep the core running and put it on a server, see [Keeping it running, and servers](service.md). Chinese version: [中文](../../zh/guide/install.md).

## Which systems it installs on

| System | Architecture | Install script | AUR | Homebrew | Tray installer |
|---|---|---|---|---|---|
| Linux | x86_64 | `install.sh` | Yes | No | deb, rpm |
| Linux | aarch64 | `install.sh` | Yes | No | None |
| macOS | Apple silicon | `install.sh` | No | Yes | dmg |
| Windows | x86_64 | `install.ps1` | No | No | msi |

There is no release archive for Intel Macs, 32-bit Windows or Windows on ARM.

The ways of installing do not install the same things:

| Way of installing | Core and command line | Terminal | Web UI | Tray |
|---|---|---|---|---|
| Install script | Yes | Yes | Yes | No |
| `miyu-agent` on the AUR, `miyu-agent` plus the cask on Homebrew | Yes | Yes | Yes | Yes |
| Tray installer | Yes | No | Yes | Yes |

Pick one way for one machine.

## Installing with the install script

The install script downloads the archive for your system from Miyu's releases on GitHub, and installs only after checking it. It needs no administrator rights and no `sudo`.

### Linux, macOS

```sh
curl -fsSL https://raw.githubusercontent.com/miyu-agent/miyu/main/packaging/install.sh | sh
```

It needs `curl` and `tar`. Put arguments after `sh -s --`:

| Argument | What it does |
|---|---|
| `--version <version>` | Installs this version, for example `--version 2026.11.0` |
| `--prerelease` | Counts pre-releases too, and installs the latest one |
| `--uninstall` | Uninstalls |

```sh
curl -fsSL https://raw.githubusercontent.com/miyu-agent/miyu/main/packaging/install.sh | sh -s -- --version 2026.11.0
```

When it is done:

- The whole directory from the archive goes into `~/.local/lib/miyu/`, with an `install.toml` written next to it that contains `channel = "script"`.
- `~/.local/bin/miyu` links to `~/.local/lib/miyu/miyu`.
- On Linux it also writes `~/.local/share/mime/packages/miyu.xml` (under `XDG_DATA_HOME` if that is set), so the system recognizes `.miyu` package files.
- It does not change your shell config. If `~/.local/bin` is not in `PATH`, the script prints a line at the end, "Note: … isn't on PATH; add this line to your shell's config: …", and you add `export PATH="$HOME/.local/bin:$PATH"` to your shell config as it says. If the first `miyu` found on `PATH` is one somewhere else, it prints a note about that too.

If it is already installed, the script says "… is already installed (…); use miyu upgrade to upgrade" and changes nothing.

### Windows

In PowerShell (Windows PowerShell 5.1 and PowerShell 7 both work), run:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/miyu-agent/miyu/main/packaging/install.ps1)))
```

Arguments go at the end: `-Version <version>`, `-Prerelease`, `-Uninstall`, with the same meaning as in the table above.

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/miyu-agent/miyu/main/packaging/install.ps1))) -Version 2026.11.0
```

When it is done:

- The whole directory from the archive goes into `%LOCALAPPDATA%\Programs\Miyu\`, with `install.toml` (`channel = "script"`) written next to it.
- This directory is added to the current user's `PATH`; only your own environment variables are changed. `miyu` is found in terminals opened afterwards, and in the window you installed from right away.

### What the script checks

1. It downloads this version's `SHA256SUMS` and its signature `SHA256SUMS.sig`, and verifies the signature with the release public key written in the script.
2. It downloads the archive and checks the SHA-256.
3. It unpacks it and runs the new `miyu --version` once; the version must match.

If any step fails, it stops and installs nothing. Checking the signature needs an `openssl` that supports Ed25519 (OpenSSL 3 and later; on Windows, the one that comes with Git for Windows works). The one that comes with macOS is LibreSSL and cannot check it; the tools that come with Windows do not support Ed25519 either. When the signature cannot be checked, the script checks only the SHA-256, continues installing, and says so:

| Situation | What the script says |
|---|---|
| `openssl` does not support Ed25519 (this is the case with the one that comes with macOS) | "This machine's openssl doesn't support Ed25519, so the signature wasn't checked (it isn't broken); checking SHA-256 only. …" |
| No `openssl` on Linux or macOS | "No openssl here, so the signature can't be checked; checking SHA-256 only. …" |
| No `openssl` on Windows | "No openssl here (Windows' own tools don't support Ed25519), so the signature wasn't checked (it isn't broken); checking SHA-256 only. …" |

To check the signature yourself, use the `gh attestation verify <file> -R miyu-agent/miyu` it suggests.

If `GITHUB_TOKEN` is set, the script sends it when it asks the GitHub API (not for downloads). Networks where several people share one exit often hit the anonymous limit of 60 requests an hour, and the script then says "GitHub rate limit reached".

## Installing from the AUR (Arch Linux)

Use the AUR helper you like, for example `paru`:

```sh
paru -S miyu-agent
```

The packages on the AUR:

| Package | What it installs | Where it goes |
|---|---|---|
| `miyu-agent` | The bundle; it has no files itself and depends on the four below | |
| `miyu-core` | Core and command line | `/usr/lib/miyu/`, with `/usr/bin/miyu` linked to it, and `/usr/share/mime/packages/miyu.xml` |
| `miyu-tui` | Terminal | `/usr/share/miyu/packages/tui/` |
| `miyu-webui` | Web UI | `/usr/share/miyu/packages/webui/` |
| `miyu-applet` | Tray; needs system libraries such as `gtk3` | `/usr/bin/miyu-applet`, plus the application menu entry and icons |
| `miyu-agent-git` | Core, terminal and web UI built from the latest source, as one package, without the tray | Same as `miyu-core`, `miyu-tui`, `miyu-webui` |
| `miyu` | A transition package for users of the old 0.7 version; it has no files itself and depends on `miyu-agent` | |

- If you do not want the tray, install the three `miyu-core miyu-tui miyu-webui`, or only the ones you need. The terminal and the web UI both depend on `miyu-core`.
- `miyu-agent-git` conflicts with `miyu-core`, `miyu-tui`, `miyu-webui` and `miyu-agent`. Building it needs `git`, `rustup` and `python`, and it goes online to fetch dependencies while building. If you want the tray, install `miyu-applet` separately.
- `miyu-core` conflicts with the old 0.7-generation package `miyu`; when you install, pacman asks you to confirm replacing it.
- `install.toml` is written in `/usr/lib/miyu/` and says `channel = "aur"`.

## Installing with Homebrew (macOS)

Miyu's tap is `miyu-agent/miyu`:

```sh
brew tap miyu-agent/miyu
brew install miyu-agent
brew install --cask miyu-applet
```

| Name | Kind | What it installs |
|---|---|---|
| `miyu-agent` | formula | The bundle; it depends on the three formulae below; the tray is a cask you install separately |
| `miyu-core` | formula | Core and command line, placed in the formula's `libexec/`, with `miyu` linked into Homebrew's `bin/`; `install.toml` says `channel = "brew"` |
| `miyu-tui` | formula | Terminal, installed into `share/miyu/packages/tui/` under the Homebrew prefix |
| `miyu-webui` | formula | Web UI, installed into `share/miyu/packages/webui/` |
| `miyu-applet` | cask | The tray `Miyu.app`; depends on `miyu-core` and `miyu-webui` |

All of them install only on Macs with Apple silicon.

## Tray installers

The tray's installer bundles the core, the web UI and the tray; after installing, open "Miyu" from the application menu and it works, with no terminal needed. The terminal is not included. Download from the tray's releases page <https://github.com/miyu-agent/miyu-applet/releases>:

| System | File |
|---|---|
| Linux x86_64 | `.deb`, `.rpm`; needs GTK 3 |
| macOS Apple silicon | `.dmg`; drag `Miyu.app` into the Applications folder |
| Windows x86_64 | `.msi`; comes with a copy of PowerShell 7 |

These installers are not signed, and the releases are all marked as pre-releases. `miyu-core` in the system repositories clashes with the core they install, so do not mix them with the AUR or Homebrew ways of installing.

For how to use the tray, see [Tray](heads/applet.md).

## Checking that it installed

```sh
miyu --version
```

If it prints a line like `miyu 2026.11.0`, it is installed. The version number is "year.month.release number within that month".

Type `miyu` in a terminal to open the interface. The first time you open it, it walks you through setting up a model provider, choosing a theme and a persona, see [Quick start](quickstart.md).

## What gets installed

The install script installs a one-piece bundle, with this in one directory:

- Five programs: `miyu` (core and command line; the core is what `miyu` looks like when it runs in the background), `miyu-sandbox`, `miyu-extract`, `miyu-tui` (the terminal) and `miyu-web` (the web UI). On Windows they all have `.exe`: `miyu.exe`, `miyu-sandbox.exe` and so on.
- `resources/`: the core's shipped resources, plus the two packages for the terminal and the web UI (`resources/packages/tui/`, `resources/packages/webui/`).
- `LICENSE`, `THIRD-PARTY-LICENSES.txt`, `README.txt`. `README.txt` says how to use the archive if you unpacked it yourself: on Linux and macOS, "Add this folder to PATH, or link miyu into ~/.local/bin", and on Windows, "Add this folder to PATH (or call miyu.exe by its full path)".
- The `install.toml` the install script writes.

The terminal and the web UI are two packages, each with its own version number; every version of Miyu comes with the copy matched to it. You can see them in `miyu pkg list`, with the ids `tui` and `webui`. The AUR and Homebrew split them into separate packages and install them into `share/miyu/packages/` under the system directory, and the core still finds them. The core looks in these places:

| System | Where packages installed by the system package manager are looked for |
|---|---|
| Linux | `miyu/packages/` in each entry of `XDG_DATA_DIRS`; if it is not set, `/usr/local/share:/usr/share`. Ones installed by Linuxbrew are not found automatically; you have to add Linuxbrew's `share` directory to `XDG_DATA_DIRS` yourself |
| macOS | `share/miyu/packages/` under the Homebrew prefix, where the prefix is the parent of the directory `miyu` is in |
| Windows | There is no such place; only the install directory and the data root are used |

`resources/` is replaced as a whole on every upgrade, so do not put your own things in the install directory.

Your sessions, settings and keys are not in the install directory; they are in the data root (`~/.miyu` by default, `%USERPROFILE%\.miyu` on Windows, or the directory the environment variable `MIYU_HOME` points to if set). Installing, upgrading and uninstalling never touch the data root.

## Upgrading

```sh
miyu upgrade
```

| Argument | What it does |
|---|---|
| `--prerelease` | Counts pre-releases too |
| `--yes` | Upgrades without asking "Upgrade Miyu … → …? [Y/n]" |
| `-h`, `--help` | Shows help |

`miyu upgrade` reads the `install.toml` next to the `miyu` program to see how it was installed:

| `channel` | How it was installed | What `miyu upgrade` does |
|---|---|---|
| `script` | Install script | Upgrades itself, see below |
| `aur` | AUR | Says "this Miyu was installed with AUR; upgrade it with the package manager", and the next line is `paru -Syu` |
| `brew` | Homebrew | Says "this Miyu was installed with Homebrew; upgrade it with the package manager", and the next line is `brew upgrade` |
| No `install.toml` | Tray installer, or an archive unpacked by hand | Says "this Miyu was not installed by the install script or a package manager, so it does not upgrade itself", and gives the download address |

For one installed by the install script, `miyu upgrade` upgrades like this:

1. It asks GitHub for the latest releases and picks the newest one that is newer than the current one. If there is none, it says "already up to date (…)".
2. It asks whether to upgrade. Pressing Enter or typing `y` means yes. If it is not running in a terminal and cannot read an answer, it says "cancelled: no confirmation", and you need `--yes`.
3. It downloads this version's archive, `SHA256SUMS` and `SHA256SUMS.sig`, verifies the signature with the release public key built into the program, checks the SHA-256, unpacks it and runs the new `miyu --version` once.
4. It replaces the files in the install directory that belong to Miyu and leaves `install.toml` alone. Things that are not Miyu's are left as they were, with a line saying "… item(s) in the install folder are not Miyu's and were left as they were". The old files are first moved into `.miyu-old-<old version>/` in the install directory and deleted once the new ones are in place; on Windows, the running `miyu.exe` cannot be deleted, so it is left until the start of the next `miyu upgrade`.
5. It says "upgraded Miyu … → …".

The terminal and the web UI are in the same archive and are upgraded with it. If any step fails, it stops and the installed version is untouched.

After upgrading, the core that is already running is still the old version. Run:

```sh
miyu core stop
```

The next time you open the terminal or the web UI, what it starts is the new version. If you have the start-at-boot service installed and want the service to manage it again, run `miyu service enable` too: on Linux's systemd user service and on macOS the new version starts right away; on Linux's desktop autostart and on Windows it starts at the next login. See [Keeping it running, and servers](service.md#making-the-service-take-over-now).

For one installed by the tray installer, download the new installer and install it over the old one.

### Switching installation method

`channel` is decided by how it was installed; do not edit `install.toml` by hand. To switch from one way of installing to another:

1. Uninstall the current one as in "Uninstalling" below.
2. Install with the new way.

The data root is not affected, so your sessions and settings are still there after the switch.

To use a pre-release, add `--prerelease` when upgrading one installed by the script; for one installed from the system repositories, use the package manager's own way.

## Uninstalling

Every way of installing deletes only the programs and leaves the data root.

| Way of installing | How to uninstall |
|---|---|
| Install script (Linux, macOS) | `curl -fsSL https://raw.githubusercontent.com/miyu-agent/miyu/main/packaging/install.sh \| sh -s -- --uninstall` |
| Install script (Windows) | `& ([scriptblock]::Create((irm https://raw.githubusercontent.com/miyu-agent/miyu/main/packaging/install.ps1))) -Uninstall` |
| AUR | `sudo pacman -Rns miyu-agent miyu-core miyu-tui miyu-webui miyu-applet`; if you installed the transition package, add `miyu` as well |
| Homebrew | `brew uninstall --cask miyu-applet`, then `brew uninstall miyu-agent miyu-tui miyu-webui miyu-core` |
| Tray installer | The system's way of removing software: `apt remove`, `dnf remove`; on Windows "Settings → Apps"; on macOS drag `Miyu.app` into the Trash |

The uninstall script first stops the start-at-boot service (`miyu service disable`) and the core (`miyu core stop`), then deletes the install directory, the `~/.local/bin/miyu` link and the `.miyu` file type; on Windows it removes the install directory from your `PATH`. It does not touch a directory that was not installed by the install script. The last line it prints is "Miyu is uninstalled. Your data is still in …; delete it yourself if you don't need it."

On Windows, if a Miyu program is still open, the install directory cannot be deleted; the script reports "can't remove … (…): close any running Miyu program and try again", stops, and does not change `PATH` either. Close Miyu programs such as the terminal and the web UI, and uninstall again.

For the other ways of installing, stop them yourself first:

```sh
miyu service disable
miyu core stop
```

### Deleting the data too

After uninstalling the programs, delete these places:

| What | Linux | macOS | Windows |
|---|---|---|---|
| Data root | `~/.miyu` | `~/.miyu` | `%USERPROFILE%\.miyu` |
| Cache | `~/.cache/miyu` (under `XDG_CACHE_HOME` if that is set) | `~/Library/Caches/Miyu` | `%LOCALAPPDATA%\Miyu\cache` |

If `MIYU_HOME` is set, the data root is the directory it points to. The data root holds all your sessions, memory, settings and stored keys; once deleted they cannot be recovered, so back up what you want to keep first.

## Coming from the old 0.7 version

The old version's data does not move over by itself. The old version's data directory is also `~/.miyu`, and this version's core does not recognize it and will not start, so move it aside first:

```bash
mv ~/.miyu ~/.miyu-0.7
```

```powershell
Rename-Item $HOME\.miyu .miyu-0.7
```

When upgrading from the old `miyu` package on the AUR, pacman prints `Run "miyu migrate" to bring your data over from the old Miyu`: `miyu migrate` is a command that comes with the migration package, which you have to install first:

```sh
miyu pkg install migrate
```

Then follow [Migrating from the old 0.7 version](migrate.md) step by step.
