# Knowledge base

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

A knowledge base is a set of documents you hand to the AI to look things up in, such as notes, manuals, setting books and PDFs. This page explains how to create a knowledge base, when the AI looks things up in it, and how to update and delete it.

A knowledge base is different from memory: a knowledge base is material you provide, kept as it is, and the AI reads the original text when it looks things up; [Memory](memory.md) is the individual notes the AI writes down by itself during conversations.

The tools the AI uses to search knowledge bases come from the shipped package `base-knowledge`, which is called `Knowledge base` in the interface. The files in a knowledge base belong to you: even if this package is not installed, you can still manage them with `miyu kb`.

## Creating a knowledge base

To create a knowledge base and try a search, follow these three steps:

1. Create an empty base, or mount an existing directory:

   ```bash
   miyu kb new notes --name "Study notes" --description "Japanese grammar and vocabulary"
   miyu kb mount handbook ~/Documents/handbook --name "Team handbook"
   ```

   ```powershell
   miyu kb new notes --name "Study notes" --description "Japanese grammar and vocabulary"
   miyu kb mount handbook $HOME\Documents\handbook --name "Team handbook"
   ```

2. Add files to the base you created:

   ```bash
   miyu kb add notes ~/Downloads/grammar.md ~/Downloads/kanji.pdf
   ```

   ```powershell
   miyu kb add notes $HOME\Downloads\grammar.md $HOME\Downloads\kanji.pdf
   ```

3. Try a search:

   ```sh
   miyu kb search te-form
   ```

A base id must start with a lowercase letter, can contain only lowercase letters, digits, `-` and `_`, is at most 64 characters long, and cannot be a Windows reserved name such as `con`, `nul` or `com1`. If the id is wrong, it is reported as `invalid knowledge base id`.

## Supported files

A knowledge base takes the following kinds of files:

| File | Extensions | How it is cut into passages | Largest |
|---|---|---|---|
| Markdown | `.md`, `.markdown` | By heading | 4 MiB |
| Plain text | `.txt` | By paragraph | 4 MiB |
| PDF | `.pdf` | By page | 64 MiB |
| Web page | `.html`, `.htm` | Converted to text, then cut by heading | 64 MiB |

- Text files must be encoded in UTF-8.
- PDFs and web pages need `miyu-extract` to extract their text, which sits in the same directory as `miyu` (on Windows, `miyu-extract.exe` next to `miyu.exe`); without `miyu-extract`, these files are skipped. Scanned PDFs, or PDFs with only images, contain no text and are skipped too.
- Files in subdirectories are taken as well. Files and directories whose names start with a dot, and links, are not taken. Files with other extensions are not taken either.
- When you add files with `miyu kb add`, each file can be at most 20 MiB.

A file that cannot be taken does not affect the other files. `miyu kb list <kb>` writes the reason after that document, for example `(unreadable: too large)`.

## Adding versus mounting

Adding files to a knowledge base and mounting a directory as a knowledge base differ in the following ways:

| | `miyu kb new` + `add` | `miyu kb mount` |
|---|---|---|
| Where the files are | Copied into `~/.miyu/root/kb/<id>/` (the data root is `~/.miyu` by default, `%USERPROFILE%\.miyu` on Windows) | They stay in the original directory; the base only records which directory is mounted |
| After the original file changes | The copy in the base does not follow; you need to run `add --replace` again | It follows the next time you search or list |
| Adding and deleting documents | Possible, with `add` and `remove`; the AI can write too | Not possible; the base is read-only, and neither you nor the AI can change it |
| `delete` | Moves the whole base directory to the system trash | Only unmounts it; the directory itself stays unchanged |

Write the mounted directory as an absolute path, or as a path starting with `~/`; on Windows, a path starting with `~\` is accepted too.

You can also put files straight into `~/.miyu/root/kb/<id>/` and change them there; creating a directory under `~/.miyu/root/kb/` whose name follows the id rules is the same as creating a base. The next time you search or list, Miyu updates the index from the files: new and changed files are read again, deleted files are taken out of the index, and unchanged files are left as they are.

## miyu kb

`miyu kb` is the command for managing knowledge bases:

```text
miyu kb [<command>] [<options>]
```

With no command, it runs `list`. Options can go before or after the command.

| Command | What it does | Prints on success |
|---|---|---|
| `list` | Lists the knowledge bases, one per line: id, name, how many documents; for a base that comes from a package it writes `from <package>`, for one with auto recall on it writes `auto recall`, and the description comes last | |
| `list <kb>` | Lists the documents in a base | |
| `search <words>…` | Searches all bases and lists at most 10 passages | |
| `read <kb> <document>` | Reads one page of a document. A page is 32 KiB; a PDF is split by its own pages | |
| `new <kb>` | Creates an empty base | created … |
| `edit <kb>` | Changes the name and description, and turns auto recall on or off | updated … |
| `add <kb> <file>…` | Copies files into the base | added <kb>/<document> |
| `remove <kb> <document>` | Removes a document by moving it to the system trash | moved to trash: … |
| `mount <kb> <folder>` | Mounts an existing directory as a read-only base | mounted …: N documents |
| `delete <kb>` | Deletes a whole base | deleted …, moved to trash: … |
| `reindex <kb>` | Deletes the index and builds it again from the files | reindexed …: N documents |

| Option | What it does |
|---|---|
| `--kb <kb>` | `search` searches only this base |
| `--page <page>` | `read`: which page to read, page 1 if not written |
| `--name <name>` | For `new`, `edit`, `mount`: the displayed name; the id is used if not written |
| `--description <description>` | For `new`, `edit`, `mount`: one sentence saying what this base is |
| `--auto` | For `new`, `edit`, `mount`: turns auto recall on |
| `--no-auto` | For `edit`: turns auto recall off |
| `--to <dir>` | For `add`: puts the files into this subdirectory of the base |
| `--replace` | For `add`: replaces an existing document of the same name |
| `--format <text\|json>` | Output format of `list` and `search` |

Write `<document>` as the relative path inside the base, the same way `list <kb>` prints it. For example:

```bash
miyu kb read notes grammar.md --page 2
miyu kb add notes --to grammar --replace ~/Downloads/grammar.md
miyu kb edit notes --auto
miyu kb search --kb handbook expenses
```

```powershell
miyu kb read notes grammar.md --page 2
miyu kb add notes --to grammar --replace $HOME\Downloads\grammar.md
miyu kb edit notes --auto
miyu kb search --kb handbook expenses
```

## When the AI looks things up in knowledge bases

In a session with knowledge bases turned on:

- The system prompt lists the bases the AI can search: id, name and description. Because the AI relies on the name and description to decide when to look things up, write them clearly.
- The AI searches by itself with `kb_search`, and reads the original text page by page with `kb_read`.
- For a base with auto recall on, there is no need to wait for the AI to look: whichever passage your words mention is brought in.

If a session cannot search any base at all, the AI does not get `kb_search`, `kb_read`, `kb_edit` or `kb_delete`; it gets only `kb_save`, so that it can still create the first base.

### Auto recall

On every turn you start, Miyu looks in the bases with auto recall on, based on what you said in this turn:

- If your words contain the last level of a section's title (for example "te-form" when the title is "Grammar › te-form"), that section is brought in.
- If your words are close in meaning to a passage, that passage is brought in. This needs a semantic model; see "Semantic search" below.

At most 3 passages are brought in per turn. Each passage consists of where it is (base, document, heading) plus its first 120 characters, in a block of at most 600 bytes; if the full text is needed, the AI reads it with `kb_read` itself. A passage already brought in during one stretch of context is not brought in again; counted together with the associative recall of memory, at most 40 passages are brought in per stretch of context (counted again after compaction).

Auto recall is off by default. You can turn it on or off with `miyu kb edit <kb> --auto` or `--no-auto`, or with the `Auto-suggest` switch on the card on the Knowledge page of the web interface.

### Giving a section an alias

Write keywords on the first line under a Markdown section heading, and the section gets a few more names that trigger auto recall. For example:

```markdown
## The lamp keeper

keys: the lighthouse girl, Eileen, the one who tends the lamp

The lamp keeper lives in the lighthouse on the headland…
```

- The line must start with `关键词`, `keys` or `キーワード` (case does not matter), followed by `：` or `:`.
- Keywords are separated by `、`, `，`, `,`, `；` or `;`.
- A heading or keyword counts only if it has at least 2 characters.
- This line is not given to the AI.

## The AI writing to knowledge bases

The AI can write to knowledge bases with these three tools:

| Tool | What it does |
|---|---|
| `kb_save` | Creates a document, or appends to the end of one. If the base does not exist yet, it creates the base |
| `kb_edit` | Replaces a piece of text in a document; the original text being replaced must occur only once in the document |
| `kb_delete` | Moves a document to the trash |

- The AI can write only Markdown and plain text, and after writing, the file must not exceed 4 MiB.
- The AI cannot write to mounted bases or to bases that come with a package.
- The AI cannot delete a whole base.
- Under full access, the AI can also read and change the documents in `~/.miyu/root/kb/` with the tools that read and write files, and changed documents have their index updated from the file's content; under read-only, the AI can only read these documents.

To stop the AI from writing to knowledge bases, pick either of these:

- Turn off these three tools in the preset's `[tools]`:

  ```toml
  [tools]
  kb_save = false
  kb_edit = false
  kb_delete = false
  ```

- In a read-only session, these three tools do not run; see [Permissions and sandbox](permissions.md).

## Which sessions can search which bases

You can control which knowledge bases a session can search at the following scopes:

| Scope | How to write it |
|---|---|
| All sessions | By default every base can be searched: the ones you created, the ones you mounted, and the ones that come with installed packages |
| Sessions using a given persona | In `[knowledge]` of the persona file `persona.toml`, write `bases = ["notes"]`, and only the listed bases can be searched; write `[]` and none can be searched, and no base can be created either |
| Sessions using a given preset | Write `knowledge = false` under `[features]`; all five tools are gone, and there is no auto recall |

For example:

```toml
# ~/.miyu/root/personas/captain/persona.toml
[knowledge]
bases = ["sea-charts", "handbook"]
```

After you create a base or change a persona, the new settings apply from the next time. For how to write personas and presets, see [Personas and presets](personas-presets.md).

## Semantic search

Searching a knowledge base looks things up in two ways at once, by keywords and by meaning, and ranks the results together. Looking up by meaning needs a semantic model, that is `models.embedding`, which by default uses the local `embed` package (`miyu pkg install embed`, see [Add-ons](addons.md) and [Models](models.md#the-three-uses)).

- If it is not installed, or is set to `off`: search goes only by keywords, and auto recall recognizes only titles and keywords.
- If it is set to a remote model: search looks both ways, and the text used to compute vectors is sent to that provider; auto recall does not bring things in by meaning, and recognizes only titles and keywords.

The indexes are built at the following times:

- The keyword index: on search, list, mounting a directory, rebuilding the index, and when the AI uses the knowledge base tools, the index of the base is brought up to date from the files.
- Vectors: they are filled in in the background after a search; for a base with auto recall on, they are also filled in in the background when it is used. Passages without vectors yet can be found only by keywords.

At the end of its output, `miyu check` prints the index progress; for example, `Knowledge bases: handbook 30/42` means that 30 of the 42 passages of this base have vectors. For how to read this output, see [Troubleshooting](troubleshooting.md#run-miyu-check-first).

## Knowledge bases that come with packages

A package can also bring a knowledge base, which can be searched once the package is installed, and the list shows `from <package>` for it. Such a base is read-only: you can only turn its auto recall on or off (recorded in `~/.miyu/etc/kb.toml`) and rebuild its index. When you remove the package, the knowledge base it brought is removed with it. If you have a base of your own with the same id, yours is used.

One ready-made knowledge base in the package source is `kb-shorinwiki`. Run the following command to install it:

```sh
miyu pkg install kb-shorinwiki
```

To make one yourself, see [Things that work as files](../../authors/scripts-skills.en.md#knowledge-bases).

## Interface

You can manage knowledge bases in the web interface; in the terminal interface you can only use the command:

- Web interface: the `Knowledge` page in the settings. You can search at the top of the page; each base is a card, with an `Auto-suggest` switch on it; click into a card to list the documents and read the original text; for a base you created, you can `Add files`, `Add a folder`, drag files in, and delete documents; the page also has `Empty base`, `Mount a folder`, `Rebuild index` and `Delete`.
- The terminal interface has no knowledge base page; you need to use `miyu kb`.

## Storage location

Files related to knowledge bases are stored in these places:

| Location | What it is |
|---|---|
| `~/.miyu/root/kb/<id>/` | One base: the documents in it, and a `kb.toml` |
| `~/.miyu/var/cache/index/kb/` | The index, computed from the files; `reindex` rebuilds it |
| `~/.miyu/etc/kb.toml` | For bases that come with packages, records the auto recall switches you changed |

`kb.toml` can be written by hand, and all four fields can be left out:

```toml
name = "Study notes"                       # name, the id if not written
description = "Japanese grammar and vocabulary"  # one-sentence description
auto = true                                # auto recall, off if not written
mount = "~/Documents/notes"                # mounted directory; if written, the documents are there
```

On Windows, write a Windows path in `mount`, as a TOML single-quoted string, and leave the `\` inside as it is, for example `mount = 'D:\notes'`.

If the file has other fields, or is written wrongly, the base is used as if it had no `kb.toml`, and `miyu kb list` shows the error for it.

For backing up knowledge bases and moving them to another computer, see [Data and backups](data.md).

## Troubleshooting

| What you see | What to do |
|---|---|
| `cannot add X: unsupported format` | A knowledge base takes only the kinds of files in the table above |
| `A mounted knowledge base is read-only.` | You cannot add documents to or delete documents from a mounted base; change them in the original directory |
| `A knowledge base from a package is read-only; only auto recall can be switched.` | A base that comes with a package only allows turning auto recall on or off and rebuilding the index |
| `Folder cannot be mounted.` | The directory does not exist, or cannot be read |
| A document shows `miyu-extract is missing` after it | Text cannot be extracted from PDFs and web pages; `miyu-extract` must be in the same directory as `miyu` |
| The AI does not look things up | Try a search with `miyu kb search`; check the persona's `[knowledge]` and whether the preset has knowledge bases on; give the base a clear name and description |
