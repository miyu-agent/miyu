# Migrating from the old 0.7 version

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

If you used the old Miyu (0.7.x) and have installed this version, you can follow this page to bring over your earlier personas, sessions, memories, settings and files.

`~/.miyu` in the paths on this page means the data root (by default `~/.miyu`, and `%USERPROFILE%\.miyu` on Windows; if you set `MIYU_HOME`, it is the folder that points to).

## Before you start

Before migrating, be aware of the following:

- This version does not read the old version's data folder, and does not move it by itself. Moving the data is done with the command `miyu migrate`, which comes with the package `migrate`, so you need to install that package first.
- The old version's data folder is also at `~/.miyu` by default, the same place as this version's data root. As long as the old folder is still there, this version's core cannot start. So the first step is to move the old folder somewhere else.
- Migration does not change or delete the old folder. It first packs the whole old folder into one archive, `miyu-0.7.tar.zst`, checks it file by file, and from then on reads only from the unpacked copy. The archive is kept in `~/.miyu/root/documents/Old Miyu migration/<time>/`, and is not deleted when you uninstall `migrate`.
- Migration has no "look first, change nothing" mode. Before it changes anything, it checks whether the old version has stopped and whether there is enough disk space; if either is not met, it writes nothing.
- Migration can be run again. What was already migrated is not duplicated; for details, see "Running again and failures part-way" below.

Migration is supported on Linux x86_64, macOS (M series) and Windows x86_64. There is no such package for Linux aarch64, and running `miyu pkg install migrate` there reports `Not supported on this system.`

## Steps

1. Close the old version: quit its windows and background processes. If the old version is still running, migration refuses to start.

2. Move the old folder somewhere else:

   ```bash
   mv ~/.miyu ~/.miyu-0.7
   ```

   ```powershell
   Rename-Item $HOME\.miyu .miyu-0.7
   ```

3. Install this version; see [Installing, upgrading and uninstalling](install.md). If you upgraded from the old `miyu` package on the AUR, this version is already installed.

4. Set up a model:

   ```sh
   miyu setup
   ```

   You can also migrate without setting up a model: the providers, keys and default model configured in the old version are added. But the memory step asks the AI to consolidate memories once, and consolidating needs a model; if there is no model at that point, the step is skipped and the report says `consolidation failed (…); it will run again at the usual interval`. In that case, run `miyu memory dream` after the migration is done. For how to set up a model, see [Models](models.md).

5. If you want the following to be migrated along with the rest, install the matching packages first (if you do not install them now, you can still add them later; see the table below):

   ```sh
   miyu pkg install im          # QQ message records
   miyu pkg install memes       # stickers
   miyu pkg install im-sponsor  # sponsorship records
   miyu pkg install goofish     # Goofish (Xianyu) login state
   ```

6. Install the migration package:

   ```sh
   miyu pkg install migrate
   ```

7. Start the migration:

   ```bash
   miyu migrate ~/.miyu-0.7
   ```

   ```powershell
   miyu migrate $HOME\.miyu-0.7
   ```

   If the core is not running, migration starts it first. On success it prints two lines:

   ```text
   Report: /home/me/.miyu/root/documents/Old Miyu migration/20261114T083000Z/report.md
   For the agent: /home/me/.miyu/root/documents/Old Miyu migration/20261114T083000Z/for-agent.json
   ```

   It prints full paths, and the above is what they look like on Linux; on macOS and Windows, it prints the full path of the data root on that system.

8. Read `report.md` and check it as described in "Reading the report" below.

`miyu migrate` takes exactly one argument:

| Form | What it does |
|---|---|
| `miyu migrate <old folder>` | Migrates `<old folder>` into this version's data root |
| `miyu migrate -h`, `--help` | Prints usage |

If the number of arguments is wrong, it prints usage and exits with code `2`. Which data root it migrates into is decided by `MIYU_HOME`; if that is not set, it is `~/.miyu`.

## What is migrated

The following table lists what is migrated, and what each item becomes in this version:

| Item | Where it comes from in the old version | What it becomes in this version | Package to install first |
|---|---|---|---|
| Personas | The built-in Miyu, developer mode, and the characters you wrote in `prompts/` | The built-in Miyu becomes a new persona named `Miyu`, which uses the old version's character text, with the role-play prompt and example dialogues you edited laid on top; developer mode maps to the shipped `Software Engineer` (`software-engineer`); each character you wrote becomes a new persona. If this version already has a persona with the same name, no new one is created, and the existing one is used | |
| Sessions | The session database `conversation.db` | Each session becomes one read-only archive: you can read and search it, but you cannot continue the conversation; it is in the `Archived` group of the session list (see [Sessions](sessions.md)). Text, tool calls and results, attachments, questions the AI asked you and things you said mid-turn are all kept; subagent sessions are imported along as child sessions; turns pushed out by the old version's compaction are put back into their original session, and if the original session no longer exists, they go into `旧版被挤出的对话` (conversations pushed out in the old version) | |
| QQ sessions | Sessions in the session database that are bound to a QQ group or private chat | They become a read-only archive of that group or private chat. A turn in a group is split into what each person said, by the number at the start of each line | |
| QQ message records | `history.sqlite3` | Converted to `qq-records.jsonl` in this run's folder, then handed to `miyu im records import` to be imported into im's chat records | `im`: if it is not installed, the report says which line to run after installing it |
| Memories | The facts in each persona's `memory.db` | Imported into the matching new persona, keeping the time each was originally recorded. Facts about someone else are recorded as that person's, and facts about you as yours. After importing, memories are consolidated once, merging anything that duplicates memories already recorded | |
| Configuration and keys | `config.jsonc`, and the profile about you | What is migrated: providers (address, key, model context window, temperature, price), the default model (`models.chat`), the vision model (`models.vision`), a remote semantic model (`models.embedding`), the models of the three tiers, which go into the `lite`, `normal` and `flagship` pools respectively, Tavily and Exa keys and the SearXNG address, the description about you (`profile.about`), and the old version's admin QQ number, which is taken as you. Only what this version does not have yet is added; anything already configured stays unchanged. Keys are stored in the secrets file | |
| Stickers | Your own sticker libraries, one folder per library | Each library is made into a sticker package `legacy-memes-<library>` and installed | `memes`: if it is not installed, the sticker package stays in this run's folder, and the report says which line to run after installing it |
| Skills | Skills you wrote | Copied into `~/.miyu/root/skills/<name>/`. If there is a skill with the same name but different content, the copy is renamed `<name>-legacy`. Skills that were disabled in the old version are enabled in this version | |
| Knowledge base | Documents you put into the knowledge base yourself | Copied into a new knowledge base `Old Miyu knowledge base` (`旧版知识库` when the interface language is Chinese; `~/.miyu/root/kb/legacy/`), and this version builds the index itself. If there is a document with the same name but different content, the copy is renamed `<name>-legacy.<ext>` | |
| Files | Pictures, documents, tool output, working directories | Pictures go into `~/.miyu/root/pictures/`; documents into `~/.miyu/root/documents/`; output, sorted by session, into `~/.miyu/root/documents/旧版产物/`; working directories into `~/.miyu/root/workspace/旧版/`. If there is a file with the same name but different content, the copy is renamed `<name> (旧版 N).<ext>` | |
| Goofish login state | The login file of Goofish search | Copied into the state folder of the `goofish` package. It is not guaranteed that the new package reads the old format; if it does not, log in again as the new package's instructions describe | `goofish`: if it is not installed, nothing is copied |
| Sponsorship records | The sponsorship records in the session database | Imported into the ledger of the `Sponsorships` plugin, keeping the original times, amounts and exchange rates | `im-sponsor`: if it is not installed, install it and run the migration again |

Every copied file is checked one by one against its SHA-256.

## What is not migrated

The following items are not migrated. All of them stay in the archive, and the report lists, item by item, where each one is in the archive and what format it is in. When you need something, you can have the AI read `for-agent.json` in the same folder and continue the migration.

| Item | Reason, and what to do |
|---|---|
| Scripts you wrote | This version's script format is different. The report lists each of these scripts; if the official package source has a new package with the same name, the report says which one to install |
| Skills and scripts installed by the old package manager | They are not copied. The report names the matching new package in the package source, and you can install it with `miyu pkg install` |
| Persona subsystems and plugin switches, developer mode's prompt, and the system prompt used when no persona was chosen | This version has nothing matching. For how personas and presets work, see [Personas and presets](personas-presets.md) |
| CLI relay providers in the configuration (`claude-code`, `codex`, `antigravity`, `codebuddy`) | The core in this version has no matching driver. For `antigravity` there is a community package `antigravity` that brings a driver (Linux and macOS only); after installing it, write this provider by hand. The other three need to be replaced with providers connected by API. See [Models](models.md#writing-a-provider-by-hand) |
| The `context`, `tools`, `cache`, `display`, `notifications`, `voice` and `skills` sections of the configuration, and plugin settings other than vision and search | This version has no matching settings |
| The `mcp` section of the configuration | You need to add MCP servers again in this version, see [Extending Miyu](extending.md#mcp-servers) |
| QQ connection settings (other than the admin number) | You need to connect QQ again in im, see [Chat platforms](heads/im.md#connecting-qq) |
| Usage records | This version's usage ledger cannot take these records in yet |
| The terminal's up-arrow history | |
| Pictures, files and avatars received on QQ | This version's im records only placeholders and does not store the content |
| QQ plugin data such as affection and mood | This has to be rebuilt in this version's im |
| Diaries, turn-by-turn experiences, change records and old vectors in memory | Only facts are imported. This version computes vectors itself |
| The AI's own memories, memories not in use, and memories longer than 120 characters | Overlong memories are written into `for-agent.json`; once shortened, they can still be imported |
| One-off `ask` sessions, members' sessions, and sessions on platforms other than QQ | |
| Members' home folders | This version is for one person only |
| Scheduled reminders | If you need them, set them up again from what the report says, see [Schedules](automation.md#schedules) |
| The old web UI's login password and custom styles | This version's web interface has its own login and appearance settings |
| Login state for Zhihu, Xiaohongshu and Bilibili search | This version has no matching package yet. For Bilibili live streaming, you can install `bilibili-live-stream` and log in again there |
| The old version's built-in default knowledge base and default stickers | Not migrated |
| Things you shared with others before | Not migrated |
| Logs, caches, indexes | This version rebuilds them itself |

Things the old version installed outside the data root are not put into the archive. Migration checks only the places below, and the report's `Outside the data root` section lists the ones that exist:

- Six places under your home folder: `~/.local/bin/miyu`, `~/.config/fish/conf.d/miyu.fish` (if `XDG_CONFIG_HOME` is set, the `fish/conf.d/miyu.fish` under it is checked instead), `~/.gemini/config/agents/miyu`, `~/.gemini/antigravity-cli`, `~/.cache/miyu/voice-models`, `~/.local/state/miyu`.
- The block the old terminal integration wrote into shell startup files: `~/.bashrc`, `~/.bash_profile`, `~/.bash_login`, `~/.profile` and `~/.zshrc` are checked (if `ZDOTDIR` is set, the `.zshrc` under it is checked as well). The report says which lines the block is on, for example ``Lines 3-5, 7-9 were written by the old terminal integration. Migration leaves them alone; running `miyu shellhook install --shell bash` in the new version backs the file up and removes them. If you do not use the terminal integration, you can delete these lines yourself.``

Migration only reads these files and does not change them; for what to do about the old terminal integration, see "After migrating" below. On macOS and Windows it also checks only these places; things the old version installed elsewhere are not listed in the report, and you need to find and clean them up yourself.

## Reading the report

Each run of the migration creates a new folder `~/.miyu/root/documents/Old Miyu migration/<time>/`; the time is in UTC, written as `20261114T083000Z`. When the interface language is Chinese, the folder is called `旧版 Miyu 迁移`, the two files are called `报告.md` and `给agent.json`, and the report is in Chinese. The folder contains these files:

| File | What it is |
|---|---|
| `report.md` | The report for you to read |
| `for-agent.json` | The JSON version of the same report, for the AI to read and continue migrating what was not migrated |
| `miyu-0.7.tar.zst` | The archive of the whole old folder |
| `miyu-0.7.manifest.json` | The SHA-256 of every file in the archive |
| `qq-records.jsonl` | Present only if there are QQ message records |
| `legacy-memes-<library>/` | Present only if you have your own sticker libraries |

`report.md` contains, from top to bottom:

- The start: the time of the migration, where the old folder is, and where the archive is.
- `Personas`: a table that lists which persona in this version each old persona maps to, with the result `created`, `a persona with this name already existed`, `built-in software engineer` or `not mapped`.
- `By category`: one section per category, named with the category's English name (such as `sessions`, `memories`, `config`). Each section first gives the result, `Migrated`, `Partly migrated`, `Not migrated, kept in the archive` or `Nothing to migrate`, then how many entries were migrated and how many skipped and where they went, and finally one more sentence of notes. If the matching package is not installed, the note says which line to run after installing it.
- `Outside the data root`: what the old version installed outside the data root.
- `Not migrated`: a table that lists each item's path in the archive and its old format.
- `Old data root`: the archive's size and SHA-256, and when you can delete the old folder.

The report contains only names and counts, and never keys, cookies or chat content.

## Confirming the migration succeeded

After the migration is done, you can confirm that things came over in these places:

- Personas: the persona list on the settings page has `Miyu` and your own personas.
- Sessions: the `Archived` group in the session list.
- Memories: run `miyu memory list --persona <id>`.
- Knowledge base: run `miyu kb list legacy`.
- Settings: run `miyu config get` and `miyu provider list`.
- Skills: look in `~/.miyu/root/skills/`.

## Running again and failures part-way

Running `miyu migrate ~/.miyu-0.7` again is safe, and is useful for migrating the rest after you install a package you missed:

- Sessions: the ids of the new sessions are derived from the old ids, so sessions already imported are not imported again.
- Memories: each memory records which old entry it came from; ones already imported, and ones you deleted afterwards, are not imported again.
- Configuration: only settings that are still missing are added.
- Personas: if a persona with the same name exists, it is reused and not created again.
- Skills, knowledge base, files: identical content counts as already migrated; something with the same name but different content is renamed and kept side by side with the original.
- QQ message records, sponsorship records, stickers: the receiving side recognizes what it already has, so nothing is duplicated.

Every run packs a new archive and adds a new folder, which takes twice the old folder's size in disk space. If you run it twice within the same second, the second run reports `… already exists; wait a second and run again`.

If the migration fails part-way, it prints `miyu migrate: <reason>` on standard error and exits with code `1`. What was written before the failure stays; fix the cause and run it again, and what was already migrated is skipped. A failed run leaves behind:

- `~/.miyu/root/documents/Old Miyu migration/<time>/`: it holds the archive but no report. You can delete it once you have checked it.
- `~/.miyu/var/lib/migrate/<time>/`: the unpacked copy used for checking, which holds the plain-text keys from the old config. Whether the migration succeeds or fails, this copy is deleted on the spot, so normally nothing is left; if it cannot be deleted, migration prints `cannot remove the unpacked copy of the old data <path> (<reason>); it holds plain-text keys from the old config, delete it by hand`, and you need to delete it yourself as the message says.

## After migrating

After the migration is done, a few things are left to take care of:

- The old program: after upgrading, the old `miyu` package on the AUR becomes the transitional package `miyu`, which ships no files of its own and only depends on `miyu-agent`; the old program is gone. The new `miyu-core` conflicts with the 0.7-era `miyu`, see [Installing, upgrading and uninstalling](install.md#installing-from-the-aur-arch-linux). If you installed it some other way, go by the report's `Outside the data root` section, and delete things only after confirming they belong to the old version. If `~/.local/bin/miyu` belongs to this version (the link the install script puts there, or an earlier wrapper script), the report says `This is the new miyu, not the old one. Do not delete it.`; in that case, do not delete it.
- The old terminal integration: migration does not change it, and the report's `Outside the data root` section lists which file and which lines it is in. If you want to use the terminal integration in this version, run `miyu shellhook install --shell <shell>`; installing backs up and cleans up the old version's copy first, see [Terminal UI](heads/tui.md#cleaning-up-the-old-versions-integration). If you do not use the terminal integration, you can delete those lines yourself using the line numbers in the report; the fish copy is `conf.d/miyu.fish`, which you can simply delete.
- The old folder `~/.miyu-0.7`: migration does not delete it. Once you have confirmed that everything came over and have used this version for a while without problems, delete it yourself.
- The archive: keep it. If you later want the AI to continue migrating what was not migrated, it needs the archive and `for-agent.json`. When you no longer need them, delete the whole `<time>/` folder.
- The `migrate` package: when you are done with it, you can run `miyu pkg remove migrate` to uninstall it. The migration folders are in `~/.miyu/root/documents/`, and uninstalling the package does not delete them.

## Troubleshooting

| What you see | What to do |
|---|---|
| This version does not start, and shows `… isn't a Miyu data root …` or `… is an old Miyu data root, which this version doesn't read …` | The old folder is still at `~/.miyu`. Move it away as in step 2 above |
| `old Miyu is still running (pid <pid>); stop it first` | The old version is still running. Close the old version, or run `kill <pid>` (Linux, macOS) |
| `old Miyu is still running; stop it first` | The old version is still running, but migration cannot find its process id. On Windows this is always the message. Close the old Miyu's windows and background programs, then migrate; on Windows, you can find it in Task Manager and end it |
| `<path> is not an old Miyu data folder` | This folder is not the old version's data folder. Check whether the path is written wrongly |
| `old Miyu did not finish moving its files (…); start the old version once to let it recover` | The old version did not finish moving its own files last time. Start the old version once to let it finish, close it, then migrate |
| `not enough disk space for the archive and its check under <folder>: need <N> MiB, have <M> MiB` | There is not enough disk space: the place where the archive goes needs twice the old folder's size. Free up space and run again |
| `cannot reach the core: …` | Migration cannot connect to this version's core. See [Troubleshooting](troubleshooting.md) |
| ``run this as `miyu migrate <old folder>`: MIYU_STATE_DIR is not set`` | You ran the program inside the package directly. Use `miyu migrate` instead |
| The report says `consolidation failed (…)` | There was no usable model when memories were migrated. After setting up a model, run `miyu memory dream --persona <id>` |
| In the report, some category is `Not migrated, kept in the archive`, and the note says a package is not installed | Install that package, then run the line given in the note, or run the migration again |
| The report says ``N link(s) in the skill `<name>` were not copied …`` | Migration does not follow links in a skill folder (they may point outside the skill), so these links stay in the archive. If you need them, copy them out of the archive yourself |
| The report says ``The SKILL.md of `<path>` is a link that leads outside the skill folder … the whole skill was not copied`` | That skill's `SKILL.md` is a link; migration did not follow it, so the whole skill was not copied and stays in the archive. If you need it, copy it out of the archive yourself |
| The report says `Cannot read the knowledge base list kb_meta.db (…); the documents were not migrated` | The old knowledge base list cannot be read, so the documents stay in the archive. If you need them, take them out yourself and add them to a knowledge base with `miyu kb add` |
| The report says `Cannot read the session database (…); the sponsor records were not migrated` | The old session database cannot be read, so the sponsor records stay in the archive |
| The report says `N sponsor record(s) have an unreadable time and were not migrated` | The time of those sponsor records cannot be read; migration skips only them and imports the rest as usual; the skipped ones stay in the archive |
