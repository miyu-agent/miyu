# Tools the AI can use

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

The AI reads files, runs commands and goes online by calling tools. This page lists every tool that ships with Miyu: what it does, whether it still works under read-only, what its limits are, and how to turn one of them off.

## Where tools come from

The tools the AI can use come from the following places:

- Tools from the shipped packages: see the full tables below.
- Tools from packages and extensions you install: see their own descriptions. For `qq_*` and `tg_*` on chat platforms, see [Connecting chat platforms](heads/im.md); for the stickers' `meme_*`, and tools such as `render_image` and `ocr`, see [Add-ons](addons.md).
- Scripts: in `~/.miyu/root/scripts/` under the data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`), each file is one tool, and the tool is named after the file. For how to write a script, see [Things that work as files](../../authors/scripts-skills.en.md).
- MCP servers: the tool name is `mcp__<server name>__<tool name>`; characters other than letters, digits, `_` and `-` in the tool name are replaced with `_`, and the whole name is at most 64 characters long. A server that declares resources gets two more tools, `mcp__<server name>__list_resources` and `mcp__<server name>__read_resource`, which list and read its resources. For how to connect an MCP server, see [Extending Miyu](extending.md).

Which tools a session has is decided by the session's preset (see [Personas and presets](personas-presets.md)). On top of that, a few more filters apply:

- The three memory tools exist only in sessions that have memory turned on; the knowledge base's search, read, edit and delete tools exist only when at least one knowledge base can be found, while `kb_save` is always there so that you can create the first knowledge base.
- `subagent` is only given to sessions on this machine, and subagents dispatched by a subagent no longer have it; `ask_user` is only given to main sessions on this machine with someone watching; `sessions` is only given to main sessions on this machine; `send_message`, `todowrite` and `session_usage` are only given to sessions on this machine.
- Sessions on chat platforms have further limits, see [Connecting chat platforms](heads/im.md).

To see which tools this session has right now, you can use:

- Terminal interface: type `/tool-list`, which lists the tool names grouped as built-in, package, MCP and script. Press `c` to copy and `Esc` to close.
- Web interface: click the session title at the top left of the conversation area, then click the pencil (`Edit this preset`) at the right of the `Preset` row to open the preset, where you can see which features and tools are on.

## shell

The `shell` tool behaves as follows:

- Which shell is used: this is decided by the system and looked up once when the core starts, and no config can change it. Your shell startup files are not read (`.bashrc`, `.zshrc` and PowerShell's `$PROFILE` are all skipped). The tool description tells the AI which kind of shell it is, and the AI writes commands in that shell's syntax:

  | | Which one | How it is found | Name given to the AI |
  |---|---|---|---|
  | Linux | bash | It uses `bash` on `PATH`, or `/bin/bash` if none is found. | `bash` |
  | macOS | zsh | It always uses `/bin/zsh` and does not look it up through `PATH`. | `zsh` |
  | Windows | PowerShell 7, or Windows PowerShell 5.1 if there is none | It first uses the copy that comes with the tray installer (`.msi`), then looks for `pwsh.exe` on `PATH`, and if neither exists, it uses `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`. | `PowerShell 7` or `Windows PowerShell 5.1` |
- Where it runs: commands run in this session's working directory. Each call starts a new shell in the working directory, so the previous `cd` and variables are not carried over. If the working directory was deleted or moved, no command can run, and the tool answers `working directory no longer exists`; switch to another working directory and it works again (see [Sessions](sessions.md)).
- Environment variables: the core's whole environment is passed on, except variables whose names contain `KEY`, `SECRET`, `TOKEN`, `PASSWORD`, `PASSWD` or `CREDENTIAL` (case-insensitive), and variables that start with `MIYU_`. It also sets `GIT_TERMINAL_PROMPT=0`, `PAGER=cat`, `GIT_PAGER=cat`, `NO_COLOR=1` and `TERM=dumb`: this way git fails at once when it wants a password, and output is not paged or colored.
- Timeout: if the AI does not specify one, the tool waits 120 seconds, and the AI can specify up to 600 seconds. If a command has not finished by then and the preset has `Background` on, the command moves to the background and keeps running, and the timeline records `timed out, moved to the background as …`; if `Background` is off, or the command starts with `sleep` (`Start-Sleep` on Windows), the whole group is stopped, and the timeline records `stopped after … s`.
- Stopping a command: when a command is stopped on timeout or when you stop it, on Linux and macOS the command's whole process group is killed, and on Windows `taskkill /T /F` kills the whole process tree. After a command exits by itself, on Linux and macOS any child processes it left in the group that have not exited are killed too; on Windows they are not killed, and the leftover processes keep running.
- Running in the background: when the preset has `Background` on, the AI can put a command in the background from the start and immediately gets a job id (for example `j1`), and the result is reported automatically when the command finishes. A background command runs at most `jobs.max_running` (default `30m`, and it can be set from `1m` to `2h`), and it is stopped when that time is up. The AI can also have each line of a background command's output passed to it right away, to keep an eye on a log.
- Idle waiting: a foreground `sleep` (on Windows `Start-Sleep`) of two seconds or more is not run, and the tool answers `foreground sleep isn't allowed`: a background task reports by itself when it is done, so there is no need to wait idly.
- Output that is too long: at most 30000 characters of output are shown to the AI; beyond that, half is kept from the start and half from the end, with a note in the middle saying how much was left out. If you need to see all of it, have the AI write the output to a file and then read the file.
- Dangerous commands: under full access, some kinds of commands ask you first and some are refused outright, see [Permissions and sandbox](permissions.md#commands-that-need-confirmation). On Windows they are recognized by PowerShell and cmd syntax, see [How it is written on Windows](permissions.md#how-it-is-written-on-windows).

## trash

What `trash` deletes goes into the system trash: on Linux the freedesktop trash, on macOS the Trash, and on Windows the Recycle Bin. To get something back, restore it from the system trash. Using `/undo` to undo that turn does not put it back.

## show

With `show`, the AI can show you images, web pages, documents, audio and video that it made or found, directly. If the same path is shown again, it replaces the earlier one.

- Terminal interface: a card or an image appears on the timeline, and clicking it opens it with the system's program; HTML and PDF files are opened automatically once when they arrive. If no program can open the file, it shows `No program can open it:` and the path; on Windows the terminal interface hands the file to the system to open and cannot tell whether any program can open it, so handing it over counts as opened. If the file is changed later, it shows `File changed`, and if it is deleted, it shows `File no longer exists`.
- Web interface: the file is put in the `Preview panel` on the right, with the most recently shown first; audio and video play right in the timeline; a file it does not recognize can only be downloaded.

While `show.system_hint` (default `true`) is on, the system prompt has a sentence reminding the AI to use `Show` to show you these things. Turning it off takes effect for new sessions; to turn it off, run:

```sh
miyu config set show.system_hint false
```

## ask_user

When the AI asks you something, both the terminal interface and the web interface show `… is asking`, with the questions and options below it. Press `↑` and `↓` to select, `Space` to check an option in a multiple-choice question, and `Enter` to submit; every question lets you choose `Type another answer`, and `n` (`N` in the web interface) adds a note; when there are several questions, `←` and `→` switch between them; press `Esc` twice to cancel. When another session is asking you, the terminal interface shows `"…" is asking you · /resume to switch`.

The AI waits for your answer for as long as it takes; the confirmation box's timeout `permission.confirm.timeout` does not apply. Sessions where nobody can answer (subagents, `miyu ask`, chat platforms) do not have this tool.

## advisor

When the AI is stuck, it can use `advisor` to hand the question to a model in the flagship pool (`flagship`), wait for the answer and then carry on. The flagship model only sees the question the AI wrote for it, not this session. The AI can continue from its previous question. The flagship pool is empty by default; for how to add models to it, see [Models](models.md).

## subagent

With `subagent`, the AI opens another session and dispatches a subagent, which works in the background and sends a report back when it is done. The AI can choose a model pool and a persona for the subagent (only personas with `subagent = true` are listed), have it continue from this session's conversation (fork), or allow it to read only and not change anything. The subagent uses the preset and permissions of the session that dispatched it, and it does not save memories. For details, see [Letting the AI keep working on its own](automation.md).

## Turning off a tool

You can turn off tools in the following ways:

- Turn it off in the preset: turn that feature or tool off in the preset on the settings page, or write `[features]` and `[tools]` in the preset file. For details, see [Personas and presets](personas-presets.md).
- Turn off a whole package: under `Packages` on the settings page, turn off the package's `Enabled` switch, and all the tools it brings are gone. From the command line, you can run:

  ```sh
  miyu config set packages.base-net.enabled false
  ```

- Skills, scripts and MCP servers also have a master switch `features.<feature id>` (for example `features.mcp-github`); the master switch only affects presets that have everything on by default, and if a preset sets the switch itself, the preset's setting wins.

All of these changes take effect from the next turn.

## Tools under read-only

After you switch to read-only:

- `write`, `edit`, `trash`, `kb_save`, `kb_edit` and `kb_delete` do not run, and the timeline records `Read-only mode, not run`.
- `shell` and scripts run in the sandbox, where nothing can be written anywhere. For how the sandbox differs on the three platforms, see [Permissions and sandbox](permissions.md#the-three-platforms).
- Tools of MCP servers that are not marked read-only ask you first every time before they are used.
- All other tools work as usual.
