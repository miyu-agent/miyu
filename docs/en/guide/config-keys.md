# Config key reference

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page lists every config key the core registers, along with the keys of the terminal interface and web interface that ship with the core. To learn how to change them, where to change them, and why a change did not take effect, see [Configuration](config.md).

All of these keys are written in the system config `~/.miyu/etc/config.toml` (the data root is `~/.miyu` by default, and `%USERPROFILE%\.miyu` on Windows). Only `permission.start_read_only` can also be written in the project config.

## Reading the tables

The "Type" column is written as follows:

| Type | How to write it |
|---|---|
| Switch | `true`, `false` |
| Integer, decimal | Write a number. Where a decimal is expected, you can also write an integer |
| Option | One of the values in the "Allowed values" column, in quotes |
| Multi-choice | Several of the values in the "Allowed values" column, written as an array |
| Text | One line of quoted text, which cannot be empty; the "Allowed values" column gives the maximum number of characters |
| Multiline text | Text that can span several lines |
| English text | One line of text, in which Chinese, Japanese and Korean characters cannot make up more than half |
| Duration | A quoted positive integer followed by `s`, `m` or `h`; without a unit it means seconds, for example `"30m"` |
| Name | Starts with a lowercase letter and contains only lowercase letters, digits, `-` and `_`, at most 64 characters |
| URL | Starts with `http://` or `https://`; it can also be written as `{ env = "VARIABLE" }` |
| Model reference | `"provider/model"` or `"@pool"` |
| Secret reference | `{ secret = "name" }` or `{ env = "VARIABLE" }`, see [Configuration](config.md#secrets) |
| List | An array, where each item has the type given in parentheses |

A "—" in the "Default" column means there is no default: if you do not write the key, it is not set, and the description says what happens in that case.

The "Takes effect" column means the following:

| Written | Meaning |
|---|---|
| Immediately | The new value is used as soon as you change it |
| Next turn | Sessions that are already open use the new value from the next turn |
| New sessions | Sessions you open from now on use the new value; sessions that are already open do not change |
| After interface restart | The terminal interface and web interface read the new value only the next time they start |
| After core restart | The core reads the new value only the next time it starts |

The part of a key in angle brackets is a name you choose yourself: `<id>` starts with a lowercase letter and contains only lowercase letters, digits, `-` and `_`, at most 32 characters; `<model>` uses the provider's own name for the model and is 1 to 128 bytes long; `<tool name>` and `<feature id>` are 1 to 128 characters long and cannot contain `.`. If a name contains `.`, `:` or `/`, put that part in double quotes, for example `[providers.ollama.models."qwen3:8b"]`.

| Key | Type | Default | Allowed values | Description | Takes effect | Project config |
|---|---|---|---|---|---|---|
| `permission.confirm.git` | Switch | `true` | | A destructive git operation asks you first. | Next turn | No |
| `permission.confirm.delete` | Switch | `true` | | A recursive delete asks you first. | Next turn | No |
| `permission.confirm.power` | Switch | `true` | | A shutdown or reboot asks you first. | Next turn | No |

## MCP servers

`mcp.<server name>.*` configures the MCP servers you connect, with one table per server. These keys are not in the registered list, so you cannot change them with `miyu config set`; you need to edit the config file by hand, and the change takes effect as soon as you save. A server name starts with a lowercase letter and contains only lowercase letters, digits and `-`, 1 to 32 characters. For the details of each field, see [Connecting MCP servers](../dev/mcp.md).

| Key | Type | Default | Allowed values | Description | Project config |
|---|---|---|---|---|---|
| `mcp.<server name>.command` | List (text) | — | | The command and arguments that start the server. Write either `command` or `url`, not both. | No |

The last four keys are not on the settings page, so you need to edit the config file by hand or use `miyu config set`. Each key holds at most 100 parts, and each part is written as an inline table:

| Field | Type | Default | Description |
|---|---|---|---|
| `part` | Text, at most 100 characters | Required | The part name. |
| `shown` | Switch | `true` | Whether to show the part; `false` hides it. |
| `rows` | Integer, `0` to `200` | `0` | The most lines the part can take; `0` means no limit. |

The shipped part names are listed below, in the shipped order:

| Key | Parts |
|---|---|
| `tui.side` | `avatar`, `session`, `cwd`, `context`, `usage`, `loops`, `jump`, `files`, `recent`. Interface blocks from packages are appended after them automatically, so you do not need to write them |
| `tui.footer` | The left section is `level`, `model`; the right section is `usage` |
| `tui.above` | `todo` |
| `tui.top` | `prompt` |

The parts you write go in the order you write them, and the parts you do not mention follow in the shipped order. A part that is not recognized is not drawn, and you are told about it once.

```toml
[tui]
side = [{ part = "recent", rows = 5 }, { part = "avatar", shown = false }]
```
