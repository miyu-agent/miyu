# Security

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

When you put an AI that can run commands on your own computer, you need to know what Miyu blocks for you, what it does not block, and what gets sent out. This page covers that, and how to set up a few common uses.

## Trust model

Miyu runs as your system user. Under full access, the AI can do almost everything you can do in a terminal: read and write your files, run commands and go online.

The protections below guard against two things: first, the AI making a mistake in a moment of confusion; second, the AI being led astray by words in the web pages, files and group messages it reads. These protections are not meant to confine a program that is deliberately looking for loopholes. If you do not want the AI to touch something, keep it out of the AI's reach: use read-only, or do not put the thing anywhere the AI can read.

## What Miyu blocks

Miyu blocks the following:

| Risk | How it is blocked | Where it is explained in full |
|---|---|---|
| The AI changes your files | Switch to read-only: file tools do not write, and commands run in the system's sandbox, where nothing can be written anywhere. On Windows the sandbox only works in a logged-in desktop session, and outside a desktop session every command is refused. | [Permissions and sandbox](permissions.md#two-permission-levels) |
| Dangerous commands | Under full access, destructive git operations, recursive deletes, shutdown and restart, running a download directly, and containers using host devices ask you first; deleting the root and home directories, formatting disks, writing directly to disk devices, and letting a container take over the whole computer are refused outright. On Windows the rules recognize PowerShell and cmd syntax, but not the kind that writes directly to disk devices. | [Permissions and sandbox](permissions.md#commands-that-need-confirmation) |
| The AI deletes Miyu's own data | Deleting the whole data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`) or a folder that contains it, moving it away or putting it in the trash asks you first; this belongs to the `Recursive deletes` kind. Files and folders inside the data root are not asked about, and other reads and writes are not blocked either, see the next table. | [Permissions and sandbox](permissions.md#commands-that-need-confirmation) |
| Other people telling the AI what to do on chat platforms | Groups and private chats with someone other than you are locked down: files can only be reached in that session's workspace, commands run in a sandbox that confines reading too (commands cannot run on Windows), packages cannot be installed, and anything that needs confirmation is not done; by default these sessions are not given MCP servers. | [Permissions and sandbox](permissions.md#sessions-on-chat-platforms), [Connecting chat platforms](heads/im.md#what-the-ai-can-do-in-groups) |
| Words in a web page tricking the AI into connecting to this machine or the internal network | `web_fetch` and link cards do not visit addresses such as localhost, the internal network and link-local addresses, and every redirect hop is checked again. | [Web search and fetching pages](web-search.md#addresses-it-cannot-reach) |
| Installing a package of unknown origin | Before installing, the capabilities the package needs are listed, and they are granted only after you approve; the package source's index has its signature verified, and package files are checked against SHA-256; packages from the community and packages installed from a local file are marked. | [Packages](packages.md#package-sources) |
| A tampered Miyu program | The install script and `miyu upgrade` check the signature and SHA-256, and do not install anything that does not match. | [Installing, upgrading and uninstalling](install.md#what-the-script-verifies) |
| Keys ending up in files, logs and commands | The config only holds references, and keys live in the secrets file (on Linux and macOS its permissions are `0600`, so only you can read and write it; on Windows it uses the access control inherited from the data root); commands the AI runs do not get environment variables whose names contain `KEY`, `SECRET`, `TOKEN`, `PASSWORD`, `PASSWD` or `CREDENTIAL`; the core's log does not record keys or conversation content. | [Configuration](config.md#secrets), [Tools the AI can use](tools.md#shell), [Keeping it running, and servers](service.md#logs) |
| Other devices connecting to your web interface | By default it only listens on this machine; other devices need the access password to connect (it is stored as an argon2id hash, and after 5 wrong tries from the same source within 60 seconds, that source is refused first); only requests whose `Host` is a local address or this computer's IP are accepted, not domain names; the conversation connection checks `Origin`. | [Web UI](heads/web.md#access-and-security), [Keeping it running, and servers](service.md#opening-the-web-ui-from-other-computers-and-phones) |
| Other users on this machine connecting to your core | On Linux and macOS the socket sits in a folder only you can enter; on Windows it is a named pipe open only to you, and after connecting the core also checks that the process at the other end belongs to you. An interface that connects to the core must also present the local token. | [Troubleshooting](troubleshooting.md#the-core-will-not-start-or-cannot-connect) |
| Someone else's repository loosening permissions through project config | Project config can only tighten permissions, and for now only `permission.start_read_only = true` is recognized; a project config you have not trusted has no effect, and once its content changes you have to trust it again. | [Configuration](config.md#setting-things-for-a-single-repository) |
| Someone connecting to the QQ interface and impersonating | A OneBot implementation that connects must bring a token, and one without a token is refused. | [Connecting chat platforms](heads/im.md#connecting-qq) |

## What Miyu does not block, or cannot block completely

Miyu does not block the following, or cannot block them completely, so you need to watch out for them yourself:

| Risk | What actually happens | What you can do |
|---|---|---|
| Dangerous commands written another way | Protected commands are recognized only by their literal text, and a command written on purpose to get around the check is not recognized. | Use read-only for work you are not sure about. |
| Dangerous commands Windows does not recognize | Commands encoded in `-EncodedCommand`, writing directly to disk devices, `Set-ExecutionPolicy` and deleting from the registry are not recognized by the rules on Windows: under full access they neither ask you first nor get refused. | Use read-only for anything you are not sure about, see [Permissions and sandbox](permissions.md#how-it-is-written-on-windows). |
| Commands and file tools under full access | Commands do not run in the sandbox. Miyu does not give the data root any extra protection: commands and file tools can read and write `~/.miyu`, including the secrets file `~/.miyu/etc/private/secrets.toml`, the config and the sessions. | The same as the row above. |
| The secrets file | None of the three platforms uses the system keychain; keys are written in plain text in `~/.miyu/etc/private/secrets.toml`. On Linux and macOS, Miyu sets its permissions to `0600` every time it writes it; on Windows no separate permissions are set, and it uses the access control inherited from the data root. Any program that runs as you can read it. So can the AI: at both permission levels, file tools and commands can read the data root, this file included, and a key the AI reads goes into the context and is sent to the model provider. | Do not have the AI read it; do not run programs of unknown origin as yourself; do not put the data root in a folder other users can read. |
| Prompt injection | Web pages, files, a repository's `AGENTS.md`, group messages and MCP server replies that the AI reads all go into the context, and what they say may lead the AI astray. Miyu does not recognize such words; the only things that can stop it are the rules in the table above, which do not look at what the AI says. | Use read-only when reading things you do not know; do not casually click through important confirmations. |
| Your files sent to the model provider | Under both full access and read-only, the AI can read any file your system user can read, including `~/.ssh`, browser data, other programs' logins and Miyu's own data root; whatever it reads goes into the context and is sent to the model provider. Read-only only stops writing; it does not hide files for you. | Do not let the AI rummage through a folder that holds private files; if you do not want the AI to read something, you need to put Miyu inside another sandbox yourself, or run it as a different system user. |
| Network access under read-only | Commands under read-only can still go online, and any file they can read can be sent out. | The same as the row above. |
| Environment variables | Removing variables with `KEY` and the like in their names only keeps keys from being carried out by accident; it is not a wall: commands and the core both run as your system user, the system does not defend programs of the same user against each other in the first place, and the core process's environment can still be read (for example `/proc/<pid>/environ` on Linux), which is where a key referenced by `{ env = "…" }` lives. | Store keys in the secrets file with `miyu provider login`. |
| LAN access | It uses plain HTTP: people on the same network can see the access password, login tokens and conversations. | Turn it on only on a network you trust; when you are away, connect through an encrypted tunnel such as Tailscale or WireGuard first. |
| Connections coming in through SSH port forwarding | The web interface treats forwarding that adds no forwarding headers, such as `ssh -L`, as this machine: no password is required, and the access password can be changed. | Keep this route for yourself only. |
| Extensions | Extensions run as you, outside the sandbox. Miyu does not audit what an extension does with the capabilities you grant it. An extension granted `Use a model provider's key` gets that provider's key in plain text, and after you change the key, it gets the new one too. | Do not install extensions of unknown origin, see "Before installing a community package" below. |
| Scripts and MCP servers | Scripts under full access and all MCP servers run as you, outside the sandbox. | Only connect scripts and MCP servers whose code you have read and that you trust. |
| People in a group using memory and the knowledge base | The AI in a group still has `remember`, `forget`, `memory_search` and the tools that write to the knowledge base, and it uses the same memory as you and your knowledge base. | Give the group a preset that turns these tools off, see [Connecting chat platforms](heads/im.md#memory-and-the-knowledge-base). |
| Platform accounts bound as you | Private chats from such an account follow your permission level and are not locked down. If someone else gets hold of the account, they can act on this computer with your permissions. | Only bind accounts that you use yourself and keep safe. |
| Pages that cannot be fetched | The URL is handed to Exa, Firecrawl or Parallel to fetch; a host name that only your internal network knows is handed out the same way when it cannot be reached. If the web provider is DeepSeek, the URL to fetch goes to DeepSeek first. | See [Web search and fetching pages](web-search.md#privacy). |
| Undo | Undo only rolls back the conversation; files the AI changed and commands it ran are not rolled back. | Use version control such as git, or back up first, see [Sessions](sessions.md#undo-restore-redo). |
| Cost | There is no automatic spending cap. | Keep an eye on usage and set a limit on the number of requests, see [Letting the AI keep working on its own](automation.md#when-nobody-is-watching). |

## What leaves this machine

Data leaves your computer in the following cases:

| Sent to | What is sent | When it is sent | If you do not want it sent |
|---|---|---|---|
| Model provider | The system prompt, persona, conversation, attachments, tool results, recalled memories and knowledge base snippets brought in. | Every time the model is requested. | Use a model service running on this machine, see [Models](models.md). |
| OpenCode Go's quota endpoint (`https://opencode.ai/inference/go/v1/usage`, or the changed address if you changed `providers.<id>.quota.url`) | One GET request with this provider's key and no conversation content. | When the session uses OpenCode Go, it is queried once in the background at the end of each turn. The same provider is not queried again within 60 seconds, and a failed query does not report an error. | Do not use OpenCode Go. |
| A model in the everyday pool (if none is configured, the session's model) | The part of the conversation to be processed and related memories; the plain text of secrets referenced in the config and common key formats are masked first. | When memories are saved automatically or tidied. | Turn off persona memory in the preset, see [Memory](memory.md#turning-off-and-clearing-memory). |
| A remote semantic model | The text of memories, conversations and the knowledge base. | When `models.embedding` is set to a remote model. | Use the local `embed`, see [Add-ons](addons.md#built-in-semantic-model-embed). |
| Web provider (the one you chose, and the ones tried automatically when it is unavailable) | The search terms. | When the AI searches the web. | Turn off `Web search`, see [Web search and fetching pages](web-search.md#turning-it-off). |
| Fetching services (Exa, Firecrawl, Parallel; also DeepSeek if the web provider is DeepSeek) | URLs. | For pages Miyu cannot fetch itself; if DeepSeek is chosen, every page fetch by the AI goes to it first. | Turn off `Fetch web pages`. |
| The site a page is on | An ordinary visit. | When the AI fetches a page, and when a link in the timeline is shown as a card. | The same as the row above. |
| Remote MCP servers | The arguments the AI passes when it calls their tools. | When a tool is called. | Do not connect them, or turn them off in the preset. |
| Package source `https://miyu-agent.github.io/packages/` | Fetching the index and downloading package files. | When you run `miyu pkg update`, and when searching, installing or upgrading while the local index is more than 24 hours old. | Do not use the package source. |
| models.dev | Fetching the model catalog and each provider's icon. | When the core is running in the background and the copy it has is older than `models.catalog.every` (default `24h`). | Run `miyu config set models.catalog.update false`. |
| Exchange rate service (Frankfurter, with open.er-api.com as backup) | Currencies and dates, without usage. | When a usage amount needs to be converted to another currency. | Do not look at converted amounts. |
| GitHub | Asking for the latest release, and downloading it. | When you run `miyu upgrade` or the install script. | Do not run them. |
| Chat platforms | The AI's replies and the files it sends. | When chat platforms are connected. | Do not install `im`. |
| Places an extension connects to by itself | It depends on the extension. | Extensions that were granted the `Network` capability. | Do not grant the capability, or do not install the extension. |

Miyu has no telemetry: it does not report your usage, conversations or errors anywhere, and it sends no crash reports. When the terminal interface crashes, the call stack it leaves is written only to the cache folder on this machine.

## Setting up for common uses

Below are the recommended settings for a few common uses.

### Reviewing an unfamiliar repository

When you have the AI look at a repository you do not know, the recommended steps are:

1. Start the session in read-only:

   ```bash
   miyu ask -C ~/src/unknown-repo --permission read-only "tell me what this repository is for"
   ```

   ```powershell
   miyu ask -C $HOME\src\unknown-repo --permission read-only "tell me what this repository is for"
   ```

   In the terminal interface or web interface, you can press `Shift+Tab` after opening the session to switch to read-only.
2. The repository's `AGENTS.md` is handed to the AI every turn, so the AI reads whatever it says. Under read-only the AI cannot change files, but it can still read your disk and go online.
3. If the repository has a `.miyu/config.toml`, `miyu ask` shows `project config … is not trusted; not used this time`. Project config can only tighten permissions, so whether you trust it or not, it never loosens them.
4. Before the AI starts changing things, run `git status` to make sure the working tree is clean, and read the diff after the changes are done.

See [Permissions and sandbox](permissions.md) and [Sessions](sessions.md).

### Running unattended for a long time

When you let the AI work for a long time with nobody watching, the recommended settings are:

1. A session that a schedule opens each time has nobody watching it: anything that needs confirmation is not done, and the AI cannot ask you either. For that reason, the kinds of protected commands do not run.
2. Give it a preset that turns on only the features it needs, and choose it with `--preset`.
3. In that preset, limit how many times one turn may request the model:

   ```toml
   [limits]
   unattended_steps = 100
   ```

4. If you only want it to read and not to change anything, set `permission.start_read_only true`, so that new sessions start in read-only.
5. Check usage every so often: type `/usage` in the terminal interface, or open the `Usage` page in the web interface settings.

See [Letting the AI keep working on its own](automation.md#when-nobody-is-watching) and [Personas and presets](personas-presets.md).

### Connecting to group chats

When you connect the AI to group chats on a chat platform, the recommended settings are:

1. Sessions in a group are already locked down, so you do not need to set permissions separately.
2. Give the group a tightened preset and choose it under `Group defaults` on the im backstage page: turn off persona memory, turn off `kb_save`, `kb_edit` and `kb_delete`, and keep only the tools the group needs.
3. In `Who you are`, enter only your own account.
4. By default, groups and people not on the lists are only recorded and not replied to; do not casually turn on `Reply` for `Other groups` or `Other private chats`.
5. If NapCat and im are on the same computer, change the connection's listen address to `127.0.0.1`. The default is `0.0.0.0`, where only the token keeps others out.
6. If you have internal domain names, put them in `net.internal_domains`, so that the AI does not visit them when someone has it fetch a page.
7. Set usage limits and rate limits for the people in the group, see [Connecting chat platforms](heads/im.md#limits-and-usage).

### Deploying to a server

When you run the core on a server, the recommended settings are:

1. Run the core as a dedicated system user, put the data root in `/var/lib/miyu`, and do not use any person's home directory. The system service examples in the repository are for Linux only (systemd, OpenRC, runit, dinit).
2. Have the web interface listen only on `127.0.0.1` (this is the default), and connect to it from your own computer through `ssh -L`, Tailscale or WireGuard.
3. If other devices need to open the web interface directly, set a long access password first, then turn on LAN access. Do not expose the web interface's port directly to the public internet.
4. If you go through a reverse proxy, the proxy must add forwarding headers such as `X-Forwarded-For`; requests without them are treated as coming from the server itself and need no password.

See [Keeping it running, and servers](service.md#deploying-to-a-server).

### Before installing a community package

Before you install a package from the community, it is a good idea to check it with the following steps:

1. See what it is:

   ```sh
   miyu pkg info weather
   ```

   In the output, look at `Origin` (official, community, local file), the `Upstream` repository and `Capabilities`.
2. If it asks for more capabilities than its stated purpose needs, do not install it. For example, a weather package that asks for `Read sessions` and `Write files`.
3. Nobody has reviewed community packages. Before installing, take a look at the code in the `Upstream` repository and see whether anyone uses it.
4. A folder or `.miyu` file that someone sends you directly has no signature, so it has one less layer of checking than a community package.
5. After installing, run `miyu pkg check <id>` to see whether the files in the package have been changed.

See [Packages](packages.md#capabilities).

## Reporting a security issue

Do not post details of how to exploit an issue anywhere public. Report it privately with **Report a vulnerability** on the core repository's Security tab ([open it directly](https://github.com/miyu-agent/miyu/security/advisories/new); you need to be signed in to GitHub), and only you and the maintainers can see the report. Issues in the other repositories are reported there too. For what to include in the report, see [SECURITY.md](../../../SECURITY.md#reporting-a-security-issue).
