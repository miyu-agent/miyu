# Packages

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page explains how to find and install packages, see the capabilities they need, turn them on and off, upgrade and remove them, add other package sources, and which packages ship with Miyu. If you want to write a package yourself, see [Writing a Miyu package](../dev/packages.md).

In the paths below, `~/.miyu` means the data root: by default it is `~/.miyu`, and on Windows it is `%USERPROFILE%\.miyu`; if you set `MIYU_HOME`, the data root is the folder it points to.

## What a package can bring

A package is a folder, and the folder's name is the package's id. A package can bring any one of the following things, or a mix of several:

| What it brings | What you get after installing |
|---|---|
| Tools | The AI has a few more tools it can call. |
| Skills | The AI has another way of doing things, and you can also name the skill in the input box with `$skill-name`. |
| Scripts | Each script is one tool. |
| Slash commands | You get a few more `/command`s. |
| Subcommands | You get one more `miyu <name>` command. |
| Interfaces | A place to talk to the AI, such as the terminal or the web UI. |
| Appearance | Themes and mascots for the terminal or the web UI. |
| Personas, presets | The persona list and the preset list get a few more entries. |
| Knowledge bases | A set of material the AI can look things up in. |
| MCP servers | An existing MCP server is hooked up. |
| Resident programs (extensions) | Programs that connect to chat platforms or do things for you; the core starts them and keeps them running. |
| Dashboard pages | The package's own web page, where you manage it in the browser. |

Once installed, a package is in one of the following three situations:

- It runs automatically after installing: this is an extension whose manifest says to start it together with the core. Once it is installed and you have approved the capabilities it needs, it runs in the background.
- You need to turn it on yourself: these are other extensions, and packages that bring only MCP servers. They are off after installing; the install asks `Enable '<id>' now? [Y/n]`, and you can also turn them on later on the Packages page.
- It only adds things: these are packages that bring only skills, scripts, slash commands, personas or knowledge bases. They are on once installed, and you can turn off the whole package; each skill, script and command in it can also be switched separately in presets (see [Personas and presets](personas-presets.md)).

## Finding and installing

You can find and install packages on the command line, or do it in the terminal interface and the web interface.

### Using the command line

To install a package on the command line, follow these steps:

1. Search for the package:

   ```sh
   miyu pkg search ocr
   ```

   The results show one package per line, in the format `<id>  <name>  <description>`. An installed package is followed by `(installed)`, one that is not official by `(community)`, and a blocked one by `(blocked: <reason>)`. If you write several words, the results must match all of them; with no words, every package is listed. If nothing matches, the command prints nothing and the exit code is `1`.

2. See a package's details:

   ```sh
   miyu pkg info ocr
   ```

   If the package is installed, it shows the information of the copy on this machine; if it is not installed, it looks in the package source. Each line has the format `Key : value`: packages from the package source have the extra lines `Repository`, `Origin` and `Download Size`, and installed ones have the extra lines `Required By` and `Install Date`. The other lines are `Name`, `Title`, `Version`, `Description`, `Depends On`, `Recommends`, `Provides`, `Capabilities`, `Author`, `Upstream`, `License` and `Installed Size`. A line with no value is not shown, and `Depends On` and `Recommends` say `None` when they have nothing. To look only at installed packages, run `miyu pkg -Qi <id>`; to look only at the package source, run `miyu pkg -Si <id>`.

3. Install the package:

   ```sh
   miyu pkg install ocr
   ```

4. Read the confirmation screen, then type `y` or just press Enter to install; any other input does not install and shows `cancelled`.

5. When the install finishes, it prints `installed <id> <version>`, followed by the line `approved capabilities for <id>: …`. If the package has a switch and it is still off, it asks `Enable '<id>' now? [Y/n]`: if you answer yes, it is turned on; if you answer no, it prints `left <id> disabled`, and you can turn it on later on the Packages page.

`miyu pkg install` can also install packages from this machine:

```sh
miyu pkg install ./hello            # a folder that contains a package.toml
miyu pkg install ./hello-0.1.0.miyu # a .miyu package file
```

If what you write contains `/` or `\`, is `.` or `..`, or ends in `.toml` or `.miyu`, it is taken as a path; anything else is taken as an id. So a folder in the current directory must be written as `./hello`; if you write only `hello`, it looks in the package source. If you only want to have a look without installing, run `miyu pkg info ./hello`: it checks the manifest by the same rules as an install, and reports the line number of any mistake right at this step.

With `--yes` (the same as `--noconfirm`), nothing is asked: install, upgrade and remove all go ahead as if you had answered "yes", the capabilities they need are approved along with them, recommended packages are not installed, and installed packages are turned on at once. If standard input is closed (for example when running in a script) and `--yes` is not given, the command reports `cancelled: no confirmation` and hints that you add `--yes`.

### The confirmation screen

When installing from the package source, the command first prints `resolving dependencies...` and `looking for conflicting packages...` on standard error, and then shows the confirmation screen:

```text
Packages (1)  weather-0.3.0

Download Size   : 1.2 MiB
Installed Size  : 3.4 MiB
Origin          : community, signature verified (github.com/ann/weather)
Capabilities    : Network: Access the network and open ports
                  Provide tools: Add tools the AI can call

Note: This is a community package. It has not been reviewed and may be risky.
Install 'weather' and approve the capabilities it needs? [Y/n]
```

- `Packages (N)`: the packages this install will install, with missing dependencies listed first and installed together. If there are recommended packages, there is another line, `Recommended (N)`; after the main package is answered, it asks `Also install N recommended packages? [Y/n]`; if a recommended package needs capabilities, it first lists `Recommended Capabilities`.
- `Origin`: an official package says `official, signature verified`; a community package in the official package source says `community, signature verified`, followed by its source repository; a package source you added yourself is shown by its own name. If you install several packages at once and their origins differ, each package gets a line of its own, starting with its id.
- `Capabilities`: one capability per line, in the format `name: description`. A capability you approved before and that is kept this time is followed by `(approved)`. If there is nothing to approve, the last line is `Install '<id>'? [Y/n]`.
- `Note`: this line appears only for community packages and packages installed from a local file.

When you install a folder or package file from this machine, the confirmation screen looks different:

```text
Will install hello 0.1.0
Includes: extension, skill take-notes, script dice
Needs: Network: Access the network and open ports
From: local file
Size: 12.0 KiB, 5 files

Note: This package comes from a local file. It has not been reviewed and may be risky.
Install 'hello' and approve the capabilities it needs? [Y/n]
```

The `Includes: ` line lists what the package brings; the possible entries are `interface`, `extension`, `worker program`, `built-in feature`, `command miyu <name>`, `admin page`, `mascot`, `theme`, `<platform> connection`, `MCP server <name>`, `model driver <name>`, `skill <name>`, `script <name>`, `slash command /<name>`, `persona <id>`, `preset <id>`, `knowledge base <id>` and `N settings`. Skills and scripts that cannot be read, and so would not work even if installed, are listed after `Unreadable: `, together with the reason. If a copy with the same id is already installed, the first line is followed by `(replaces <old version>)`.

If a model driver in the package states in its manifest which tools it has the model provider run on its own, each such driver gets one more line under `Includes`, for example `model driver antigravity has the provider run on its own: search_web`; `miyu pkg info` shows this line too. When the AI installs a package for you in the web interface, the confirmation there, and the details of an installed package on the `Get software` page, carry the same sentence under `Includes`.

### Capabilities

A capability is a permission that an extension, the resident kind of program, needs. The capabilities are listed when you install, and they are granted only after you agree. If you do not approve an item, the program cannot use the features that go with it. Shipped packages count as having approved every capability they declare, except `Sign in pages on this machine` and `Use a model provider's key`: even shipped packages need you to approve these two.

| Name on the confirmation screen | In the manifest | Description |
|---|---|---|
| `Provide tools` | `tools` | Adds tools the AI can call. |
| `Tools that run commands` | `tools.commands` | The tools it provides run commands, and those commands can call the AI's tools as the current session. |
| `Provide commands` | `commands` | Adds slash commands. |
| `Show things in the interface` | `widgets` | Shows its content on the home screen, the sidebar, the status bar and its own full pages. |
| `Add to context` | `context.inject` | Adds content to what the AI sees at the start of each turn. |
| `Add to the system prompt` | `context.system` | Puts a passage at the end of the system prompt the AI sees every turn. |
| `Intercept tool calls` | `tool.guard` | Allows or denies a tool before it runs, or asks you first. |
| `Modify tool results` | `tool.rewrite` | Rewrites a tool's result after it runs. |
| `Read sessions` | `events.read` | Reads everything recorded in sessions. |
| `Write session records` | `events.write` | Appends its own records to sessions. |
| `Drive sessions` | `sessions.drive` | Sends messages in sessions and starts new sessions. |
| `Call other packages` | `packages.call` | Calls the methods that other packages offer. |
| `Be a web provider` | `search` | It appears in the list of web providers; if you choose it, your search terms are handed to it. |
| `Provide a model driver` | `model.driver` | When its models are used, the whole conversation sent to the model goes through it. |
| `Use a model provider's key` | `provider.key` | It gets the key of one model provider you set up in the model settings. The package states which provider, and the confirmation screen shows a sentence like `This package gets your DeepSeek key`. Which of your providers counts as that provider is decided the same way as in [web providers borrowing DeepSeek's key](web-search.md#using-deepseek); no other provider's key is given to it. |
| `Speak for platform users` | `act_for_external` | Sends messages and commands on behalf of people on a chat platform. |
| `Sign in pages on this machine` | `login.page` | It can let pages opened on this machine sign in without the password. |
| `Network` | `network` | Accesses the network and opens ports. |
| `Read files` | `fs.read` | Reads the specified files and folders. |
| `Write files` | `fs.write` | Writes to the specified files and folders. |
| `Use the microphone` | `audio.record` | Records sound from this computer's microphone. |
| `Play sound` | `audio.play` | Plays sound through this computer's speakers or headphones. |
| `Write memories and knowledge bases` | `memory.write` | Remembers, changes and forgets memories for the AI, and adds, changes and removes knowledge bases and their content. |

This layer of permissions governs what the program can do through the core. The extension's program itself runs on this computer as you, and it is not in the sandbox. Do not install packages from unknown sources; for details, see [Security](security.md).

### Using the terminal and web interfaces

Besides the command line, you can find and install packages in the terminal interface and the web interface:

- Web interface: type `/market` to open the `Get software` page of the settings page. At the top of the page are the search box, `N upgradable` and `Refresh the source`; below them are two rows of filters (`All`, `Installed`, `Upgradable`, `Official`, `Community`, and filters by kind), and you can sort by `Default`, `Newest`, `Downloads` and `Trending`. Click a card to see the details (source, license, what it includes, what it provides, permissions it needs), and then click `Install`. Community packages are marked `Community packages may be risky; avoid installing them casually`.
- Terminal interface: type `/settings` and go into `Packages`; the first page is `Download`. Press `/` to search, `Space` to pick, `Enter` to install, `s` to change the sort, `r` to refresh the package source, `,` and `.` to change the page, and `Esc` to go back. Before installing, it lists the origin and capabilities in the same way, and asks `Install and approve the capabilities? [Y/n]`.

The AI can also look in the package source and install packages for you; this comes from the shipped "Packages" feature. Under full access the AI asks you first every time, and under read-only it does not do it; for details, see [Permissions and sandbox](permissions.md).

## Turning packages on and off

Every package has one `Enabled` switch. Packages that bring only skills, scripts or content have it too, and so do appearance, interfaces, workers and mascots. When it is off, the tools, skills, scripts, commands, presets, knowledge bases, content and appearance it brings are gone, and an extension and the services it brings stop; when you turn it back on, they return. Open sessions follow the change from the next turn.

| Where | How |
|---|---|
| Web interface | Type `/pkg` to open the `Packages` page of the settings page; each row has a switch on the right. Groups such as `Base system` are folded into one row; click in to see the packages in the group. |
| Terminal interface | Type `/settings` and go into `Packages` → `Installed`, select a package and press `Space`. |
| Command line | Run `miyu config set packages.<id>.enabled false`; to turn it back on, write `true`. |
| System tray | The tray has no switch. If a package has a dashboard page and its manifest gives a tray entry, it gets one row in the tray menu while it is on, and clicking that row opens its dashboard page. |

When you turn on an extension that still has unapproved capabilities, they are listed and you are asked first: the web interface shows `Approve these permissions before enabling:`, and you click `Approve and enable`; the terminal interface asks `Turning on <name> needs:`.

Shipped built-in feature packages are a special case: turning one off removes it, and turning it on installs it back; for details, see "Three layers" below.

### Switching from the command line

`packages.<id>.enabled` is the package's switch, the same one as on the Packages page, and `true` means on:

```sh
miyu config set packages.base-jobs.enabled false
```

The command replies `set packages.base-jobs.enabled = false (takes effect immediately)`. This item is not written to the config file, and if you write it into `config.toml` by hand, it is not recognized. Turning off a shipped built-in feature package removes it; `miyu pkg list` then shows it followed by `(removed)`, and writing `true` installs it back.

### Switching each thing in a package separately

Every skill, script, slash command template and MCP server a package brings is a feature in presets. You can switch each one on its own, and you can also turn off its tools one by one. For details, see [Personas and presets](personas-presets.md).

### Package settings

A package can declare its own settings in its manifest. These settings are stored in `~/.miyu/etc/config.toml`, with keys in the format `<prefix>.<name>`. There are three ways to change them: in the web interface, click a package on the `Packages` page to go to its page and change them there; in the terminal interface, select the package under `Installed` and press `Enter`; or use `miyu config set`. For details, see [Configuration](config.md#package-settings).

### Dashboard pages

If a package has a dashboard page, you can open it in the browser with this command:

```sh
miyu pkg page im
miyu pkg page im --print   # print the address only
```

The command always prints the address, so you can copy it even when the browser did not open. A dashboard page is served by the package's own program, so if the program is not running, it reports `<id> is not running; enable it, then open it again`. The `Dashboards` page of the web interface settings, and `Backstage`, the third page of `Packages` in the terminal interface, list every package that has a dashboard page.

## Inspecting installed packages

The following commands show installed packages and their files:

| Command | What it prints |
|---|---|
| `miyu pkg list` (the same as `miyu pkg`) | Installed packages, one per line, in the format `<id>  <name>`. One that is off is followed by `(off)`, a removed shipped package by `(removed)`, and one whose manifest is wrong by `(invalid: <what is wrong>)`. |
| `miyu pkg files <id>` | Lists the files it installed, one per line, in the format `<id> <absolute path>`. |
| `miyu pkg owns <path>` | Prints `<path> is owned by <id>`; if the path is inside the package's directory but the file was not there at install time, it says `<path> is in the directory of <id> but was not installed with it`; if no package has the path, it reports `no package owns <path>`, and the exit code is `1`. |
| `miyu pkg check [<id>]` | Checks whether installed files were changed: a package with no problem gets one line, `<id>: OK`; a package with problems gets one line per file, `modified`, `missing` or `extra`. If a file was changed or is missing, the exit code is `1`; `extra` is only a notice, and files the package writes itself while running count as extra too. Shipped packages are not checked; for packages installed by the system package manager, only whether the manifest can be read and whether the program is there are checked. |

All of these commands accept `--format json`, which prints one line of JSON.

The logs are in these places:

- An extension's standard error: `~/.miyu/var/log/<id>/stderr`. On the Packages page of the web interface, an extension that has stopped has a `Show output` button.
- The standard error of the MCP servers a package brings: `~/.miyu/var/log/mcp/<server name>.stderr`.
- The core's runtime log: `~/.miyu/var/log/core.log`.

## Upgrading and cleaning up

The following three commands fetch the new index, upgrade packages and clear the cache:

```sh
miyu pkg update    # fetch the new index
miyu pkg upgrade   # upgrade
miyu pkg clean     # clear the cache
```

- `update`: prints one line per package source, `updated <source>: N packages (<time>)`. You do not have to run it by hand: when you search, install or upgrade and the index on this machine is more than 24 hours old, it is fetched automatically. If the package source cannot be reached, the copy on this machine keeps being used, and searching shows `cannot reach the package source, using the local index (<time>)`.
- `upgrade`: upgrades only packages installed from the package source. Packages installed from a folder or package file on this machine are not upgraded; shipped packages are upgraded together with Miyu itself (`miyu upgrade`); packages installed with the system package manager (for example `pacman` or Homebrew) are upgraded by the system package manager, and `miyu pkg upgrade` leaves them alone. A package is upgraded whenever the version in the package source differs from the installed one, so if the author withdraws a new version, the package goes back too. The confirmation screen shows one line per package, `Will upgrade <id> <old version> → <new version>`; capabilities the new version needs in addition are listed below it under `New: `, and then it asks `Upgrade '<id>' and approve the new capabilities? [Y/n]`. Settings, state, switches and capabilities you approved before are all kept. If you do not approve the extra capabilities of the new version, you are asked again when you turn the package on.
- `clean`: deletes package files in the cache that are not the installed version, and prints `removed N package files, freed <size>`.

In the following five cases the package is not upgraded; the command prints one sentence about each on standard error, the installed version keeps being used, and the other packages are upgraded as usual:

| Message | Reason |
|---|---|
| `skipping held package <id>` | The package is in `packages.hold`. |
| `<id> is no longer in the package source, keeping the installed version` | The package is gone from the package source, or the package source it was installed from has been removed from the config. |
| `<id> is blocked: <reason>` | The package source blocked it. Whether to remove it is up to you, and the hint explains how. |
| `<id> now comes from <repository>, not upgraded` | The id changed its source repository. A new source means a different person you have to trust, so it is not upgraded automatically. |
| `skipping <id> <version>: needs Miyu <version>` | The new version in the package source needs a newer Miyu. Update Miyu first, then run `miyu pkg upgrade` again. |

If you want to pin a package so that it is not upgraded, run:

```bash
miyu config set packages.hold '["im"]'
```

```powershell
miyu config set packages.hold "['im']"
```

What you write is the whole list. In PowerShell, write it as above, with double quotes outside and TOML single-quoted strings inside; it can be copied as is in both Windows PowerShell 5.1 and PowerShell 7.

At the top of the `Get software` page in the web interface there are `N upgradable` and `Upgrade all`; in the terminal interface under `Installed`, press `u` to upgrade the selected package and `U` to upgrade all.

## Removing packages

To remove a package, use `miyu pkg remove`:

```sh
miyu pkg remove ocr
miyu pkg remove --purge ocr   # delete the config too
```

After you run it, the confirmation screen is shown:

```text
Will remove ocr 0.2.0
Will delete /home/me/.miyu/var/lib/ocr (3.1 MiB)
Config kept in /home/me/.miyu/etc/ocr, plus 2 settings
Size: 18.4 MiB, 12 files

Remove 'ocr'? [Y/n]
```

The two lines in the middle show full paths. The above is how it looks on Linux; on macOS the paths look like `/Users/me/.miyu/var/lib/ocr`, and on Windows like `C:\Users\me\.miyu\var\lib\ocr`.

- Deleted: the package folder `~/.miyu/opt/<id>/`; its `<id>/` under `var/lib/`, `var/cache/`, `var/log/`, `tmp/` and `run/` in `~/.miyu/`; the state folders of the scripts it brings.
- Kept: the config folder `~/.miyu/etc/<id>/`, and its settings in `~/.miyu/etc/config.toml`. If you install the same id again, they are used as before. They are deleted too only if you add `--purge` (the same as `-n`).
- If other installed packages depend on it, it cannot be removed, and the command reports `Other packages depend on it, so it cannot be uninstalled`.

In the web interface, a package's page has `Uninstall` and `Uninstall and delete config`; in the terminal interface, select the package under `Installed` and press `d`.

## Three layers

A package with the same id can have a copy in each of three places:

| Layer | Location | `Origin` in `miyu pkg info` |
|---|---|---|
| Shipped | `packages/<id>/` in the resource directory installed together with Miyu. | shipped |
| Installed by the system package manager | Linux: `miyu/packages/<id>/` under each directory in `$XDG_DATA_DIRS`, or `/usr/local/share/miyu/packages/` and `/usr/share/miyu/packages/` when it is not set, with earlier ones taking priority; Linuxbrew installs are not recognized automatically, so you need to write Linuxbrew's `share` directory into `XDG_DATA_DIRS` yourself. macOS: `share/miyu/packages/<id>/` under the Homebrew prefix, which is the parent of the directory `miyu` is in. Windows has no such layer, only shipped packages and packages you install. | system |
| Installed by you | `~/.miyu/opt/<id>/` | official, community, local |

If the same id is in several layers, the one you installed takes priority, then the one the system package manager installed, and last the shipped one; the copies that are covered are not loaded. If the system package manager's copy is newer than yours, `miyu check` mentions it and explains how to switch back.

- A package with the same id as a shipped package cannot be installed, and the command reports `Id conflicts with a built-in package`.
- When you remove a shipped package or one installed by the system package manager, the files are not deleted; only a note is made in `~/.miyu/etc/removed/<id>`, and the package is no longer loaded. To delete the files of a package installed by the system package manager, you need to use the system's package manager.
- To install it back, run `miyu pkg install <id>`. The switch in the web interface and `Space` under `Installed` in the terminal interface also put it back.
- For a whole group: `miyu pkg remove tasks` removes the whole `Tasks and schedules` group, and `miyu pkg install tasks` installs back the packages removed from the group. At the group level, the web interface has `Uninstall all` and `Reinstall all`.

To act on a whole group with `miyu pkg install` or `remove`, write the group's id: Base system is `basesystem`, Tasks and schedules is `tasks`, Injected environment is `environment`, Persona is `persona`, and Research is `research`.

`base-authoring` and `base-persona-engineer` have no switch; to take them away, you need to run `miyu pkg remove`. Deleting the persona "Software Engineer" also removes `base-persona-engineer`.

The Miyu archive downloaded from GitHub Releases also brings two interface packages, `tui` (the terminal interface) and `webui` (the web interface), and they also belong to the shipped layer. If you install through the system package manager, they are two system packages, `miyu-tui` and `miyu-webui`, and they belong to the system package manager's layer.

## Package sources

The default package source is `https://miyu-agent.github.io/packages/`, and it is what `miyu pkg search` and `miyu pkg install <id>` use.

- The index file is `index.json`, and its signature is the `index.json.sig` next to it, using Ed25519. The official public key is built into the `miyu` program, and an index whose signature does not verify is rejected as a whole. The copy of the index stored on this machine is verified again every time it is read.
- Package files are checked against the SHA-256 written in the index, and a package that does not match is not installed.
- The package source has official packages and community packages. Community packages get in when authors put the `miyu-package` topic on their own GitHub repository, and the package source collects them once a day; nobody has reviewed them. You can tell them apart like this: a result line of `search` ends with `(community)`, `Origin` in `info` says `community, not officially reviewed`, there is a `Note` before installing, and the card in the web interface is marked `Community`.
- A package that is in no package source (for example a folder or a `.miyu` file someone sent you) has no signature and has not been reviewed by anyone; before installing, the confirmation screen says `This package comes from a local file. It has not been reviewed and may be risky.` For details, see [Security](security.md).

The package source settings are all written in `~/.miyu/etc/config.toml`, and they take effect as soon as you change them:

| Key | Default | What it does |
|---|---|---|
| `packages.source` | `"https://miyu-agent.github.io/packages/"` | The address of the official package source. If you change the address, the index there must also be signed by the official key. |
| `packages.mirrors` | `[]` | Mirrors of the official package source, tried in order; if none of them works, `packages.source` is tried. A mirror cannot change the content, because signatures are still verified and hashes still compared. |
| `packages.hold` | None | The ids of packages to skip when upgrading. |
| `packages.sources.<name>.url` | None | The directory where another package source keeps its index. |
| `packages.sources.<name>.key` | None | The Ed25519 public key that signs that source's index, in base64, at most 64 characters. |

For example, to add a friend's package source:

```toml
[packages.sources.friends]
url = "https://friends.example.com/miyu/"
key = "bWl5dS1leGFtcGxlLWtleS1ub3QtcmVhbC0wMDAwMDA="
```

- A package source counts only when both `url` and `key` are written; adding a package source means you trust it, and its index is verified with that public key.
- The package source cannot be named `official`.
- When installing, Miyu looks in the official package source first, and then in the ones you added, in the order of their names. A package is upgraded only from the package source it was installed from.
- `Origin` on the confirmation screen shows the name of this package source, for example `friends, signature verified`.

On the settings page of the web interface, these settings are on the `Advanced` page, in the `Package source` group.

## pacman syntax

If you are used to pacman, you can also use these forms:

| pacman form | Same as |
|---|---|
| `miyu pkg -S <id>…` | Install these packages from the package source |
| `miyu pkg -Sy` | `update` |
| `miyu pkg -Sy <id>…` | `update` first, then install |
| `miyu pkg -Ss [<word>…]` | `search` |
| `miyu pkg -Si <id>` | `info`, looking only at the package source |
| `miyu pkg -Su` | `upgrade` |
| `miyu pkg -Syu` | `update` first, then `upgrade` |
| `miyu pkg -Sc` | `clean` |
| `miyu pkg -U <path or id>` | `install` |
| `miyu pkg -R <id>` | `remove`; `-Rn` is the same as `remove --purge` |
| `miyu pkg -Q` | `list` |
| `miyu pkg -Qi <id>` | `info`, looking only at installed packages |
| `miyu pkg -Ql <id>` | `files` |
| `miyu pkg -Qo <path>` | `owns` |
| `miyu pkg -Qk [<id>]` | `check` |
| `--noconfirm` | `--yes` |

`-S` with nothing after it reports `no targets specified`, and the exit code is `2`. `-Qi` and `-Si` accept only ids, and giving them a path reports an error; to look at a folder or package file, use `miyu pkg info <path>`.

For all arguments, see the [command line reference](cli.md#miyu-pkg).

## Troubleshooting

Errors are printed on standard error, and they start with `miyu: `.

| The error you see | How to fix it |
|---|---|
| `package '<id>' not found`, `Package not found` | The id is wrong, or the index is too old: run `miyu pkg update` and search again. To install a folder in the current directory, write `./<folder>`. |
| `Package source unreachable` | The network is down or the address is wrong. Check `packages.source`; if the official package source cannot be reached, you can add `packages.mirrors`. |
| `Package download failed` | The download failed from every address, or the hash of the downloaded file does not match. Try again in a while, or switch to another mirror. |
| `Not supported on this system.` | This package has no build for your system. |
| `cannot install <what you wrote>: package.toml:<line>: …` | The manifest is wrong; fix the line the error names. If you did not write the package, you need to contact the author. |
| `cannot install <what you wrote>: <kind> <name> exists in <package>` | A tool, skill, command, MCP server or the like that it brings has the same name as one in another installed package, with one line per clash. Remove that other package, or ask the author to rename. |
| `Id conflicts with a built-in package` | A package on this machine uses the id of a shipped package; you need to rename the folder. |
| `Required packages are missing` | A package it depends on is not in the package source, or its version is too old. |
| `cannot install <what you wrote>: …This package needs Miyu <version> or newer: update Miyu first` | Run `miyu upgrade`. |
| `Other packages depend on it, so it cannot be uninstalled` | Remove the packages that depend on it first. |
| `Program not installed` | The package's program is missing; you need to install the package again. |
| `Extension permissions not approved` | Approve the capabilities it needs when you turn it on. |
| `cancelled: no confirmation` | When running in a script, add `--yes`. |
| On the Packages page of the web interface, an extension shows `Stopped` or `Failed 5 times in a row, stopped` | Click in and use `Show output`, or look at `~/.miyu/var/log/<id>/stderr`. |
| The Packages page shows `Missing dependencies: <id>` | Install the packages that are missing. |
