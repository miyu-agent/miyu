# Packages

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Find a package, install it, see what it asks for, turn it on and off, upgrade it, remove it, add other package sources, and see which packages ship with Miyu. To write a package, see [Writing a Miyu package](../../authors/README.en.md). Chinese version: [中文](../../zh/guide/packages.md).

In paths, `~/.miyu` is the data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`; if `MIYU_HOME` is set, that one).

## What a package can bring

A package is a folder, and the folder name is its id. A package can bring any of the following, in any mix:

| It brings | What you notice |
|---|---|
| Tools | The AI has a few more tools it can call |
| Skills | The AI has another way of doing things, and you can name it in the input box with `$skill-name` |
| Scripts | A script is a tool |
| Slash commands | A few more `/command`s |
| Subcommands | One more `miyu <name>` |
| Interfaces | A place to talk to the AI, such as the terminal or the web UI |
| Appearance | Themes and mascots for the terminal or the web UI |
| Personas, presets | A few more entries in the persona list and the preset list |
| Knowledge bases | A set of material for the AI to look things up in |
| MCP servers | Hooks up an existing MCP server |
| Resident programs (extensions) | Programs that connect to chat platforms or do things for you; the core starts them and keeps them running |
| Dashboard pages | A web page of the package's own, to manage it in the browser |

Once installed, a package comes in one of three kinds:

- Runs as soon as it is installed: an extension whose manifest says to start it together with the core. Once installed and the capabilities it asks for are approved, it runs in the background.
- Needs you to turn it on: other extensions, and packages that bring only MCP servers. They are off after installing. The install asks "Enable '<id>' now? [Y/n]", and later you turn them on on the Packages page.
- Only adds things: packages that bring only skills, scripts, slash commands, personas or knowledge bases. They are on once installed, and the whole package can be turned off; each skill, script and command is also switched separately in presets (see [Personas and presets](personas-presets.md)).

## Finding and installing

### On the command line

1. Search:

   ```sh
   miyu pkg search ocr
   ```

   One line per package, `<id>  <name>  <description>`. An installed one is followed by " (installed)", one that is not official by " (community)", and a blocked one by " (blocked: <reason>)". With several words, all of them must match; with no words, everything is listed. If nothing matches, nothing is printed and the exit code is `1`.

2. See a package's details:

   ```sh
   miyu pkg info ocr
   ```

   For an installed package it describes the copy on this machine; for one that is not installed it looks in the package source. Each line is "Key : value". Ones from the package source have "Repository", "Origin" and "Download Size" in addition; installed ones have "Required By" and "Install Date". The other lines are "Name", "Title", "Version", "Description", "Depends On", "Recommends", "Provides", "Capabilities", "Author", "Upstream", "License" and "Installed Size". A line with no value is not printed; "Depends On" and "Recommends" say "None" when there is nothing. To look only at installed packages, write `miyu pkg -Qi <id>`; to look only at the package source, write `miyu pkg -Si <id>`.

3. Install:

   ```sh
   miyu pkg install ocr
   ```

4. Read the confirmation screen, then type `y` or press Enter to install; any other text means do not install ("cancelled").

5. When it is installed, it prints "installed <id> <version>", followed by a line "approved capabilities for <id>: …". If the package has a switch and is still off, it asks "Enable '<id>' now? [Y/n]": answer yes and it is turned on; answer no and it prints "left <id> disabled", and you turn it on later on the Packages page.

`miyu pkg install` also installs things from this machine:

```sh
miyu pkg install ./hello            # a folder that has a package.toml
miyu pkg install ./hello-0.1.0.miyu # a .miyu package file
```

Anything with `/` or `\` in it, anything that is `.` or `..`, and anything ending in `.toml` or `.miyu` is taken as a path; anything else is taken as an id. So a folder in the current directory must be written `./hello`; writing `hello` alone looks in the package source. To only have a look without installing, write `miyu pkg info ./hello`: it checks the manifest the same way an install does, and reports the line number of any mistake right there.

`--yes` (`--noconfirm` is the same) does not ask: install, upgrade and remove all go ahead as if you had answered yes, the capabilities they need are approved with them, recommended packages are not installed, and what was installed is turned on at once. When standard input is closed (running in a script) and `--yes` is not given, it reports "cancelled: no confirmation" and hints to add `--yes`.

### The confirmation screen

When installing from the package source, it first prints "resolving dependencies..." and "looking for conflicting packages..." on standard error, then prints:

```text
Packages (1)  weather-0.3.0

Download Size   : 1.2 MiB
Installed Size  : 3.4 MiB
Origin          : community, signature verified (github.com/ann/weather)
Capabilities    : Network: Access the network and open ports
                  Provide tools: Add tools the AI can call

Note: This is a community package. It has not been reviewed and may be risky.
Install 'weather' and approve the capabilities it needs? [Y/n]
```

- "Packages (N)": what this install will install, with missing dependencies listed first and installed together. If there are recommended packages, there is another line, "Recommended (N)"; after the main package is answered, it asks "Also install N recommended packages? [Y/n]"; if a recommended package needs capabilities, it first lists "Recommended Capabilities".
- "Origin": an official package says "official, signature verified"; a community package in the official package source says "community, signature verified" followed by its source repository; a package source you added is named by its own name. When several packages are installed at once and their origins differ, each package gets a line, starting with its id.
- "Capabilities": one per line, "name: description". One you approved before and that stays as it was this time is followed by " (approved)". If there is nothing to approve, the last line is "Install '<id>'? [Y/n]".
- "Note": only for community packages and packages installed from a local file.

For a folder or package file on this machine, the confirmation screen is different:

```text
Will install hello 0.1.0
Includes: extension, skill take-notes, script dice
Needs: Network: Access the network and open ports
From: local file
Size: 12.0 KiB, 5 files

Note: This package comes from a local file. It has not been reviewed and may be risky.
Install 'hello' and approve the capabilities it needs? [Y/n]
```

The "Includes: " line lists what the package brings: "interface", "extension", "worker program", "built-in feature", "command miyu <name>", "admin page", "mascot", "theme", "<platform> connection", "MCP server <name>", "model driver <name>", "skill <name>", "script <name>", "slash command /<name>", "persona <id>", "preset <id>", "knowledge base <id>" and "N settings". Skills and scripts that cannot be read, and so would not work even if installed, are listed after "Unreadable: ", with the reason. If a copy with the same id is already installed, the first line is followed by " (replaces <old version>)".

If a model driver in the package says in its manifest which tools it has the provider run on its own, each such driver gets one more line under "Includes", for example "model driver antigravity has the provider run on its own: search_web"; `miyu pkg info` prints this line too. When the AI installs a package for you in the web UI, the confirmation there, and the details of an installed package under "Get software", carry the same sentence under "Includes".

### Capabilities

A capability is a permission an extension, the resident kind of program, asks for. It is listed when you install, and given only when you agree. For an item you do not approve, the program cannot use the things that go with it. Shipped packages count as having approved everything they declare, except "Sign in pages on this machine" and "Use a model provider's key", which shipped packages need you to approve too.

| Name on the confirmation screen | In the manifest | Description |
|---|---|---|
| Provide tools | `tools` | Add tools the AI can call |
| Tools that run commands | `tools.commands` | Its tools run commands, and those commands can call the AI's tools as the current session |
| Provide commands | `commands` | Add slash commands |
| Show things in the interface | `widgets` | Show its own content on the home screen, the sidebar, the status bar and its own pages |
| Add to context | `context.inject` | Add content to what the AI sees at the start of each turn |
| Add to the system prompt | `context.system` | Put a passage at the end of the system prompt the AI sees every turn |
| Intercept tool calls | `tool.guard` | Allow, deny or ask you before a tool runs |
| Modify tool results | `tool.rewrite` | Change a tool's result after it runs |
| Read sessions | `events.read` | Read everything recorded in sessions |
| Write session records | `events.write` | Append its own records to sessions |
| Drive sessions | `sessions.drive` | Send messages and start sessions |
| Call other packages | `packages.call` | Call the methods other packages offer |
| Be a web provider | `search` | Listed under Web provider; when chosen, it receives the search terms |
| Provide a model driver | `model.driver` | When its models are used, everything sent to the model goes through it |
| Use a model provider's key | `provider.key` | Gets the key of one model provider you set up. The package says which one, and the confirmation screen says something like "This package gets your DeepSeek key". Which of yours counts as that provider is decided the same way as in [web providers borrowing DeepSeek's key](web-search.md#using-deepseek); no other provider's key is given |
| Speak for platform users | `act_for_external` | Send messages and commands for people on a chat platform |
| Sign in pages on this machine | `login.page` | Lets pages opened on this machine sign in without the password |
| Network | `network` | Access the network and open ports |
| Read files | `fs.read` | Read specified files and folders |
| Write files | `fs.write` | Write to specified files and folders |
| Use the microphone | `audio.record` | Record sound from this computer's microphone |
| Play sound | `audio.play` | Play sound through this computer's speakers or headphones |
| Write memories and knowledge bases | `memory.write` | Remember, change and forget memories; add, change and remove knowledge bases |

This layer of permission governs what the program can do through the core. The extension's program itself runs on this machine as you and is not in the sandbox. Do not install packages from unknown sources; see [Security](security.md).

### In the terminal and the web UI

- Web UI: type `/market` to open "Get software" on the settings page. At the top are the search, "N upgradable" and "Refresh the source"; below are two rows of filters ("All", "Installed", "Upgradable", "Official", "Community", and by kind), and sorting by "Default", "Newest", "Downloads" and "Trending". Click a card for the details (source, license, what it includes, what it provides, permissions it needs) and press "Install". Community packages are marked "Community packages may be risky; avoid installing them casually".
- Terminal: type `/settings`, go into "Packages", first page "Download". `/` searches, `Space` picks, `Enter` installs, `s` changes the sort, `r` refreshes the package source, `,` `.` change the page, `Esc` goes back. Before installing it lists the origin and capabilities the same way, and asks "Install and approve the capabilities? [Y/n]".

The AI can also look in the package source and install packages for you (the shipped "Packages" feature). Under full access it asks you first every time, and under read-only it does not do it; see [Permissions and sandbox](permissions.md).

## Turning on and off

Every package has one "Enabled" switch, including packages that bring only skills, scripts or content, and appearance, interfaces, workers and mascots. When it is off, the tools, skills, scripts, commands, presets, knowledge bases, content and appearance it brings are gone, and an extension and the services it brings stop; turn it back on and they return. Open sessions follow from the next turn.

| Where | How |
|---|---|
| Web UI | Type `/pkg` to open "Packages" on the settings page; each row has a switch on the right. Groups such as "Base system" are folded into one row; click in to see the packages in the group |
| Terminal | `/settings` → "Packages" → "Installed", select one and press `Space` |
| Command line | `miyu config set packages.<id>.enabled false`; write `true` to turn it back on |
| Tray | No switch. A package that has a dashboard page and whose manifest gives a tray entry gets one row in the tray menu while it is on; click it to open its dashboard page |

When you turn on an extension that still has unapproved capabilities, it lists them and asks first: the web UI writes "Approve these permissions before enabling:" and you press "Approve and enable"; the terminal asks "Turning on <name> needs:".

For a shipped built-in feature package, turning off means removing and turning on means installing it back; see "Three layers" below.

### Switching from the command line

`packages.<id>.enabled` is this package's switch, the same one as on the Packages page; `true` is on:

```sh
miyu config set packages.base-jobs.enabled false
```

It replies "set packages.base-jobs.enabled = false (takes effect immediately)". This item is not written to the config file, and one written into `config.toml` by hand is not recognized. Turning off a shipped built-in feature package removes it: `miyu pkg list` shows it with " (removed)", and writing `true` installs it back.

### Each thing in a package has its own switch

Every skill, script, slash command template and MCP server a package brings is a feature in presets that can be switched on its own, and its tools can be turned off one by one. See [Personas and presets](personas-presets.md).

### Package settings

A package can declare its own settings in its manifest. They are stored in `~/.miyu/etc/config.toml`, with the key `<prefix>.<name>`. In the web UI, click a package under "Packages" to go to its page and change them; in the terminal, select it under "Installed" and press `Enter`; or use `miyu config set`. See [Configuration](config.md#package-settings).

### Dashboard pages

For a package that has a dashboard page, open it in the browser:

```sh
miyu pkg page im
miyu pkg page im --print   # print the address only
```

The address is always printed, so you can copy it even when the browser did not open. A dashboard page is served by the package's own program, so when the program is not running it reports "<id> is not running; enable it, then open it again". "Dashboards" on the web UI settings page, and the third page of "Packages" in the terminal, "Backstage", list every package that has a dashboard page.

## Inspecting

| Command | What it prints |
|---|---|
| `miyu pkg list` (same as `miyu pkg`) | Installed packages, one per line, `<id>  <name>`. One that is off is followed by " (off)", a removed shipped package by " (removed)", and one whose manifest is wrong by " (invalid: <what is wrong>)" |
| `miyu pkg files <id>` | The files it installed, one per line, `<id> <absolute path>` |
| `miyu pkg owns <path>` | "<path> is owned by <id>"; for a path inside the package's directory that was not there at install time, "<path> is in the directory of <id> but was not installed with it"; for a path no package has, it reports "no package owns <path>", exit code `1` |
| `miyu pkg check [<id>]` | Whether installed files were changed: for a package with no problem, one line "<id>: OK"; for one with problems, one line per file, "modified", "missing" or "extra". Exit code `1` if something was changed or is missing; extra files are only a notice, and what the package writes itself while running counts too. Shipped packages are not checked; for ones installed by the system package manager, only whether the manifest can be read and the program is there is checked |

All of them take `--format json`, which prints one line of JSON.

Logs:

- An extension's standard error: `~/.miyu/var/log/<id>/stderr`. On the web UI Packages page, an extension that has stopped has "Show output".
- Standard error of the MCP servers a package brings: `~/.miyu/var/log/mcp/<server name>.stderr`.
- The core's runtime log: `~/.miyu/var/log/core.log`.

## Upgrading and cleaning up

```sh
miyu pkg update    # fetch the new index
miyu pkg upgrade   # upgrade
miyu pkg clean     # clear the cache
```

- `update`: one line per package source, "updated <source>: N packages (<time>)". You do not have to fetch by hand: when you search, install or upgrade and the index on this machine is more than 24 hours old, it fetches by itself. When it cannot connect, it keeps using the copy on this machine, and says "cannot reach the package source, using the local index (<time>)" when you search.
- `upgrade`: upgrades only packages installed from the package source. Ones installed from a folder or package file on this machine are not touched; shipped ones follow Miyu's own upgrade (`miyu upgrade`). It upgrades when the version in the package source differs from the installed one, and goes back too when the author withdrew a new version. The confirmation screen has one line per package, "Will upgrade <id> <old version> → <new version>"; capabilities the new version asks for in addition are listed below under "New: ", and it asks "Upgrade '<id>' and approve the new capabilities? [Y/n]". Settings, state, switches and capabilities approved before are all kept. If you do not approve the extra capabilities of the new version, it asks again when you turn it on.
- `clean`: deletes package files in the cache that are not the installed version, and prints "removed N package files, freed <size>".

The next four kinds are not upgraded; each gets one sentence on standard error, and the installed one is used as before:

| It says | Why |
|---|---|
| "skipping held package <id>" | It is in `packages.hold` |
| "<id> is no longer in the package source, keeping the installed version" | It is gone from the package source, or the package source it was installed from was removed from the config |
| "<id> is blocked: <reason>" | The package source blocked it. Whether to remove it is up to you; the hint says how |
| "<id> now comes from <repository>, not upgraded" | The id changed its source repository. A new source means a different person to trust, so it is not upgraded automatically |

To pin a package so that it is not upgraded:

```bash
miyu config set packages.hold '["im"]'
```

```powershell
miyu config set packages.hold "['im']"
```

What you write is the whole list. In PowerShell, use double quotes outside and TOML single-quoted strings inside, as above; it can be copied as is in both Windows PowerShell 5.1 and PowerShell 7.

At the top of "Get software" in the web UI there are "N upgradable" and "Upgrade all"; in the terminal under "Installed", `u` upgrades the selected one and `U` upgrades all.

## Removing

```sh
miyu pkg remove ocr
miyu pkg remove --purge ocr   # delete the config too
```

The confirmation screen:

```text
Will remove ocr 0.2.0
Will delete /home/me/.miyu/var/lib/ocr (3.1 MiB)
Config kept in /home/me/.miyu/etc/ocr, plus 2 settings
Size: 18.4 MiB, 12 files

Remove 'ocr'? [Y/n]
```

The two lines with paths print the full path. The above is how it looks on Linux; on macOS it is like `/Users/me/.miyu/var/lib/ocr`, and on Windows like `C:\Users\me\.miyu\var\lib\ocr`.

- Deleted: the package folder `~/.miyu/opt/<id>/`; its `<id>/` under `var/lib/`, `var/cache/`, `var/log/`, `tmp/` and `run/` in `~/.miyu/`; the state folders of the scripts it brings.
- Kept: the config folder `~/.miyu/etc/<id>/`, and its settings in `~/.miyu/etc/config.toml`. Installing the same id again uses them as before. They are deleted too only if you write `--purge` (`-n` is the same).
- A package that other installed packages depend on cannot be removed; it reports "Other packages depend on it".

In the web UI, a package's page has "Uninstall" and "Uninstall and delete config"; in the terminal, select it under "Installed" and press `d`.

## Three layers

One id can have a copy in all three places:

| Layer | Where | "Origin" in `miyu pkg info` |
|---|---|---|
| Shipped | `packages/<id>/` in the resource directory installed with Miyu | shipped |
| Installed by the system package manager | Linux: `miyu/packages/<id>/` in each place in `$XDG_DATA_DIRS`, or `/usr/local/share/miyu/packages/` and `/usr/share/miyu/packages/` when it is not set, earlier ones first; Linuxbrew installs are not recognized by themselves, so write Linuxbrew's `share` directory into `XDG_DATA_DIRS` yourself. macOS: `share/miyu/packages/<id>/` under the Homebrew prefix, which is the parent of the directory `miyu` is in. Windows has no such layer, only shipped ones and ones you install | system |
| Installed by you | `~/.miyu/opt/<id>/` | official, community, local |

When the same id is in several layers, the one you installed wins, then the one the system package manager installed, and last the shipped one; the copies that are covered are not loaded. When the system package manager's copy is newer than yours, `miyu check` mentions it and says how to switch back.

- One with the same id as a shipped package cannot be installed; it reports "Id conflicts with a built-in package".
- Removing a shipped package or one installed by the system package manager: the files stay, and only a note is made in `~/.miyu/etc/removed/<id>`, so it is no longer loaded. To delete the files of one installed by the system package manager, use the system's package manager.
- To put it back: `miyu pkg install <id>`. The switch in the web UI and `Space` under "Installed" in the terminal put it back too.
- A whole group: `miyu pkg remove tasks` removes the whole "Tasks and schedules" group, and `miyu pkg install tasks` installs back the ones removed from the group. At the group level in the web UI there are "Uninstall all" and "Reinstall all".

## Package sources

The default package source is `https://miyu-agent.github.io/packages/`. It is what `miyu pkg search` and `miyu pkg install <id>` use.

- The index is `index.json`, and the signature is the `index.json.sig` next to it, Ed25519. The official public key is built into `miyu`, and an index whose signature does not verify is rejected as a whole. The copy stored on this machine is verified again on every read.
- Package files are checked against the SHA-256 written in the index, and a package that does not match is not installed.
- The package source has official packages and community packages. Community packages are collected once a day by the package source from authors who put the `miyu-package` topic on their own GitHub repository, and nobody has reviewed them. You can tell them apart: a line of `search` ends with " (community)", "Origin" in `info` says "community, not officially reviewed", there is a "Note" before installing, and the web UI card is marked "Community".
- A package that is in no package source (a folder or a `.miyu` file someone sent you) has no signature and has not been reviewed, and before installing, the confirmation screen says "This package comes from a local file. It has not been reviewed and may be risky." See [Security](security.md).

The settings are all written in `~/.miyu/etc/config.toml` and take effect as soon as you change them:

| Key | Default | What it does |
|---|---|---|
| `packages.source` | `"https://miyu-agent.github.io/packages/"` | The address of the official package source. If you change the address, the index there must be signed by the official key too |
| `packages.mirrors` | `[]` | Mirrors of the official package source, tried in order, and if none works, `packages.source` is tried. A mirror cannot change the content: signatures are still verified and hashes compared |
| `packages.hold` | None | Ids of packages to skip when upgrading |
| `packages.sources.<name>.url` | None | The directory that holds the index of another package source |
| `packages.sources.<name>.key` | None | The Ed25519 public key that signs that source's index, base64, at most 64 characters |

Add a friend's package source:

```toml
[packages.sources.friends]
url = "https://friends.example.com/miyu/"
key = "bWl5dS1leGFtcGxlLWtleS1ub3QtcmVhbC0wMDAwMDA="
```

- A source counts only when both `url` and `key` are written; adding one means trusting it, and its index is verified with that public key.
- The name cannot be `official`.
- When installing, the official source is looked in first, then the ones you added, in the order of their names. An upgrade uses only the source a package was installed from.
- "Origin" on the confirmation screen says this source's name, for example "friends, signature verified".

On the web UI settings page, these items are under the "Advanced" page, in the "Package source" group.

## pacman syntax

If you are used to pacman, these forms are understood too:

| pacman form | Same as |
|---|---|
| `miyu pkg -S <id>…` | Install these from the package source |
| `miyu pkg -Sy` | `update` |
| `miyu pkg -Sy <id>…` | `update` first, then install |
| `miyu pkg -Ss [<word>…]` | `search` |
| `miyu pkg -Si <id>` | `info`, looking only at the package source |
| `miyu pkg -Su` | `upgrade` |
| `miyu pkg -Syu` | `update` first, then `upgrade` |
| `miyu pkg -Sc` | `clean` |
| `miyu pkg -U <path or id>` | `install` |
| `miyu pkg -R <id>` | `remove`; `-Rn` is the same as `remove --purge` |
| `miyu pkg -Q` | `list` |
| `miyu pkg -Qi <id>` | `info`, looking only at installed ones |
| `miyu pkg -Ql <id>` | `files` |
| `miyu pkg -Qo <path>` | `owns` |
| `miyu pkg -Qk [<id>]` | `check` |
| `--noconfirm` | `--yes` |

`-S` with nothing after it reports "no targets specified", exit code `2`. `-Qi` and `-Si` take only ids, and a path reports an error; to look at a folder or package file, use `miyu pkg info <path>`.

For all arguments, see the [command line reference](cli.md#miyu-pkg).

## When something goes wrong

Errors are printed on standard error, starting with `miyu: `.

| What you see | What to do |
|---|---|
| `package '<id>' not found`, `Package not found` | The id is wrong, or the index is old: run `miyu pkg update` and search again. To install a folder in the current directory, write `./<folder>` |
| `Package source unreachable` | The network is down or the address is wrong. Check `packages.source`; if the official one cannot be reached, you can add `packages.mirrors` |
| `Package download failed` | Every place failed, or the hash of what was downloaded does not match. Try again in a while, or switch mirrors |
| `Not available for this system` | This package has no build for your system |
| `cannot install <what you wrote>: package.toml:<line>: …` | The manifest is wrong; fix the line it names. If you did not write the package, contact the author |
| `cannot install <what you wrote>: <kind> <name> exists in <package>` | A tool, skill, command or MCP server it brings has the same name as one in another installed package, one line per clash. Remove that one, or ask the author to rename |
| `Id conflicts with a built-in package` | A package on this machine uses the id of a shipped package; rename the folder |
| `Required packages are missing` | A package it depends on is not in the package source, or its version is too old |
| `cannot install <what you wrote>: This package needs Miyu <version> or newer: update Miyu first` | `miyu upgrade` |
| `Other packages depend on it` | Remove the ones that depend on it first |
| `Program not installed` | The package's program is missing; install the package again |
| `Extension permissions not approved` | Approve the capabilities it asks for when you turn it on |
| `cancelled: no confirmation` | Running in a script; add `--yes` |
| An extension on the web UI Packages page says "Stopped" or "Failed 5 times in a row, stopped" | Click in and use "Show output", or look at `~/.miyu/var/log/<id>/stderr` |
| The Packages page says "Missing dependencies: <id>" | Install the ones that are missing |
