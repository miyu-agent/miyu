# Terminal UI

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page is the full guide to using Miyu in a terminal: what each part of the screen is, what each key does, how to set the interface up the way you like it, and how to talk to the AI straight from your shell prompt.

## Opening the terminal UI

Run `miyu` or `miyu tui` in a terminal to open the terminal UI. Plain `miyu` opens the interface set in `Default interface` (`ui.head`) in the settings, and the shipped setting is the terminal UI. If the core is not running, it is started first.

```text
miyu tui [--resume <id> | --page <page> | config]
```

| Form | What it does |
|---|---|
| No arguments | Opens a new session or continues the most recent one, depending on the `On start, open` (`ui.startup`) setting |
| `--resume <id>` | Opens this session; you must write the full id. If the session cannot be opened, it reports an error and exits |
| `--page config`, `config` | Opens only the settings page, without entering a session; press `Esc` on the settings menu to exit |
| `--page oobe` | Goes through first-run setup again |
| `-h`, `--help` | Prints the help |

If the page name is not recognized, the home page opens as usual. The terminal UI is provided by the package `tui`; if you uninstalled it, you can install it again with `miyu pkg install tui`.

You can adjust the terminal UI with these environment variables:

| Variable | What it does |
|---|---|
| `MIYU_COLOR` | Forces the color depth: `truecolor` (or `24bit`), `256`, `16`, `none` |
| `NO_COLOR` | Set it to any non-empty value to turn colors off, keeping only styling such as bold and italics |
| `MIYU_TUI_IME=0` | Stops Miyu from switching the input method for you (see "Input method" below) |

To set an environment variable for just this one launch, run:

```bash
MIYU_COLOR=truecolor miyu
```

```powershell
$env:MIYU_COLOR = 'truecolor'
miyu
```

An environment variable set this way in PowerShell stays in effect for the rest of that window.

## What it needs from the terminal

Some features of the terminal UI work only if the terminal supports them. The table below shows how Miyu detects support, and what happens without it:

| Needed | How it is detected | What happens without it |
|---|---|---|
| True color | `COLORTERM` is `truecolor` or `24bit`; `TERM` contains `kitty`, `wezterm`, `alacritty`, `ghostty` or `foot`; `TERM_PROGRAM` is `iTerm.app`, `WezTerm`, `ghostty` or `vscode`. On Windows, an unset `TERM` also counts as support | If `TERM` contains `256color`, it switches to the nearest 256 colors, otherwise to 16 colors; if `TERM` is empty or `dumb`, no colors are shown |
| Nerd Font | Not detected automatically; first-run setup asks whether you see icons or boxes | Icons show as boxes or question marks. You can switch to plain characters: run `/icons`, or change it in `Appearance → Icons` on the settings page |
| Mouse | The program takes over the mouse | The terminal's own selection does not work, so Miyu does dragging to select and copying itself (see "Mouse") |
| Images | Asks the terminal once at startup, waiting at most 2 seconds; it recognizes the kitty, sixel and iTerm2 protocols | Images, formulas and Mermaid diagrams all show as source |
| Keyboard protocol | Terminals that support the kitty keyboard protocol can report `Shift+Enter` and `Ctrl+Enter` | For a new line you have to use `Alt+Enter` or `Ctrl+J`; `Shift+Enter` does not work |
| Foreground and background | The terminal reports when the window gains and loses focus | In terminals that cannot report focus, no notification is shown when a reply finishes (except kitty) |

In the Linux console (`TERM=linux`), if you have not set the icons, plain characters are used by default; if you have not set the theme, the plain ASCII theme is used by default. If the interface language is Chinese or Japanese, it shows once: `The Linux console can't show Chinese or Japanese: you can switch the interface language to English in settings`.

In Windows Terminal (detected by the environment variable `WT_SESSION`; running WSL inside Windows Terminal also counts), the rotating hints in the empty input box are not shown, and neither is the hint line on the home page.

### tmux, SSH, herdr

When you use Miyu inside tmux or herdr, or on another machine over SSH, a few things work differently:

- Copying goes through the terminal's OSC 52, so it reaches the clipboard on your local machine even over SSH. If the terminal does not support OSC 52, nothing is copied, and no error is shown.
- `Ctrl+V` reads the clipboard of the machine that runs Miyu. When you are connected over SSH, use your terminal's own paste to paste from your local clipboard (in kitty, `Ctrl+Shift+V`).
- In tmux and herdr, notifications are handed to the system to show (the terminal's own notifications cannot get through).
- In tmux, the terminal's colors cannot be queried, so when the colors follow the terminal, only the terminal's 16 colors are used. If you want the true-color set, turn on tmux passthrough.
- If you sometimes view the same interface in a terminal that can show images and sometimes in one that cannot (for example when you connect from a phone inside herdr), run `/images off` to stop showing images for this run, and `/images on` to show them again. These two commands do not change the config.

## First-run setup

The first time you open the terminal UI, after it connects to the core, the whole screen is first-run setup. When you finish, it writes `ui.welcomed`, and setup does not appear again. If you press `Ctrl+C` part-way, the program quits without recording setup as finished, so it starts over next time. To go through it again, run `miyu tui --page oobe`.

The welcome page says `Welcome to Miyu` and `Take a minute to set up a model and a persona`; press `Enter` to start. The top line shows your progress: language, controls, icons, model, currency, persona, color scheme, about you, preset. In every step, you can press `Esc` to go back one step.

1. Interface language: the first line is `Follow the system (…)`, followed by 中文, English and 日本語. The interface switches as soon as you choose.
2. How you like to move around: choose `Arrow keys` (↑↓ to move, type to search) or `Vim` (j/k to move, / to search); your choice is written to `tui.keys`.
3. Icons: this step asks `Do you see icons, or boxes and garbled text?`. Choose `Icons` to use Nerd Font icons, or `Boxes or garbage` to use plain characters; your choice is written to `tui.icons`.
4. Choose a model provider: pick a provider, enter its key, and click `Test connection` (it sends one test request, which uses a little of your quota); once connected, pick a model. The list also has `More providers…` and `Custom…` (where you enter an address and an API type: OpenAI compatible, Anthropic, OpenAI Responses). If a model is already set up, it asks whether to `Use it` or `Choose another`. This step cannot be skipped. For details on providers, keys and models, see [Models](../models.md).
5. Which currency amounts should be shown in: the list has twenty common currencies, and on the last line, `Other…`, you can enter a three-letter currency code. Your choice is written to `usage.currency`, and costs are converted into that currency at recent exchange rates.
6. Create a persona: you can fill in a name (required), a short description, an avatar, a detailed persona prompt, example dialogs and a roleplay reminder. For the longer fields, press `Enter` to open an editing window, or `Ctrl+G` to write in an external editor; on Windows there is no external editor option, so write in the editing window or paste into it. Choosing `Next` creates the persona and makes it the default persona; choosing `Skip` creates no persona. For details, see [Personas and presets](../personas-presets.md).
7. Color scheme: choose the mode (auto, dark, light) and the colors (auto, follow the avatar, follow the wallpaper, terminal colors); whichever one you move the cursor to, the interface changes to it at once. If the persona has no avatar, there is an extra field, `Figure`, where you choose whether to show the mascot (`Uses more CPU and slows startup when on`). With follow the avatar or follow the wallpaper there is an extra field, `Accent`. There is also a field `Background`. If you skipped the persona in the previous step, this step is skipped too.
8. How the AI knows you: this step has three fields, `What language should the AI reply in`, `What should the AI call you` and `More about you (optional)`. All of them are optional, and you can also choose `Skip`.
9. Choose a preset: each preset is shown as a block; press Space to see its details, and `Enter` to pick it and make it the default preset. The last block is `Custom`, where you name the preset and tick features yourself.
10. Turn on the built-in semantic model?: this step appears only if the package source has a semantic model package. Choosing `Yes` downloads and installs it right away; choosing `No` uses keyword search only. For details, see [Memory](../memory.md).
11. Done: the page shows `Model … · Persona … · Preset …`; press `Enter` to start chatting. The new session that opens right after uses the persona and preset you chose here.

If you want to change any of these settings later, you can do it on the settings page (`/settings`).

## Screen layout

An empty session shows the home page: the input box is in the middle of the screen, with the home page items above it (and an avatar or the mascot if `Show the figure on the home screen` is on). After you send your first message, the screen looks like this:

```text
┌──────────────────── Main column ────────────────────┐│┌── Sidebar ──┐
 Top of the conversation (pins your message on scroll) ││ Avatar
                                                       ││ Session name, #short id
 Timeline                                              ││ Workspace
                                                       ││ Context
 Above the input box (todos, run status, queued)       ││ Usage
 ╭ Input box ──────────────────────╮                   ││ …
 ╰─────────────────────────────────╯                   ││
 Footer: permission level · model           usage      ││
```

| Part | What it shows |
|---|---|
| Timeline | What you said, the AI's replies, and each step the AI took (see "Reading the timeline") |
| Top of the conversation | When you have scrolled up and your message has scrolled off the screen, a line with that message is pinned at the top; click it to jump back |
| Above the input box | Todos; the run status line while the AI is replying (`Thinking`, `Replying` and the elapsed time); queued messages; the reason, in red, when the core cannot be reached; temporary hints |
| Input box | What you type. The input box grows to at most 8 lines; anything beyond that scrolls inside the box |
| Footer | On the left, the permission level (`⏵⏵ Full access`, `⏸ Read-only`), the model and provider, and the thinking effort; on the right, the speed and usage cell (for example `◔ 128.4k · ¥0.42`). When background commands are running, a `Background: N` button appears in the middle. When the window gets narrow, the cells on the right are dropped first, then the permission level shrinks to its icon and the model shows only the last part of its name, and finally the provider name is dropped |
| Sidebar | The sidebar appears on the right, 38 columns wide, when the window is at least 120 columns wide and you are not on the home page. You can scroll it and drag to select text in it |

### Sidebar parts

The sidebar is made of the parts below, in this order as shipped:

| Part name | What it shows | What clicking does |
|---|---|---|
| `avatar` | The persona's avatar, or the mascot if the persona has none. This part is controlled by `Show the figure in the sidebar` (`tui.mascot_sidebar`, off as shipped); when it is off, a persona's avatar is still shown if it has one | |
| `session` | The session name, below it `#short id`, and below that the persona and preset | Clicking the short id copies the full session id |
| `cwd` | `Workspace`: this session's working directory | |
| `context` | `Context`: how much is used / how big the window is · percent | |
| `usage` | `Usage`: total tokens, input and output tokens each, cache hit rate, number of compactions, number of cache breaks, and cost | |
| `loops` | The loops attached to this session (`/loop`) | |
| `jump` | `Jump to`: your latest messages in this session, newest at the bottom, with an arrow in front of the one you are viewing. The number shown is set by `tui.sidebar_jumps` (shipped `8`) | Clicking a message jumps to it |
| `files` | `Changed files`: the files this session changed, one per line, followed by the number of lines added and removed, at most 8. Not shown if no files were changed | Clicking a line opens the `/files` page with that file selected |
| `recent` | `Recent sessions`: one session per line. A yellow `?` at the start of a line means it is waiting for your approval or answer, a spinner means it is running, a dot means it has finished and you have not looked yet, and an arrow marks the current session. The number shown is set by `tui.sidebar_sessions` (shipped `8`) | Clicking a line switches to that session |

If you install packages that bring interface blocks, their blocks come after these parts.

### Choosing which parts to show

The sidebar, the footer, the area above the input box and the top of the conversation each have a list of parts. These lists are not on the settings page, so you edit the system config `~/.miyu/etc/config.toml` by hand with `miyu config edit` (the data root is `~/.miyu` by default, and `%USERPROFILE%\.miyu` on Windows):

| Key | Shipped parts |
|---|---|
| `tui.side` | The nine parts in the table above |
| `tui.footer` | Left section `level`, `model`; right section `usage` |
| `tui.above` | `todo` |
| `tui.top` | `prompt` |

Each part is written as an inline table: `part` is the part name; `shown = false` hides it (shipped `true`, which means shown); `rows` is the maximum number of rows (`0` means no limit; the footer has only one row and ignores it). The parts you list come in the order you wrote them, and the parts you did not list follow in the shipped order. If a part name is not recognized, that part is not drawn, and it shows once: `Unknown parts in a slot: …`.

```toml
[tui]
# Recent sessions at the top, at most 5 rows; no avatar
side = [{ part = "recent", rows = 5 }, { part = "avatar", shown = false }]
# No model in the footer
footer = [{ part = "model", shown = false }]
```

Once you save, the interface is redrawn with the new config at once. If you only want fewer sessions or messages listed, changing `tui.sidebar_sessions` or `tui.sidebar_jumps` is enough; setting it to `0` hides that block.

## Keys

The keys are listed below by situation. Whenever a list or box is open, it gets the keys first; you can run `/help` at any time to see the keys and all commands.

### In the input box

While you type in the input box, you can use these keys:

| Key | What it does |
|---|---|
| `Enter` | Sends the message; if what you typed is a command, runs it. Nothing is sent if the box holds only whitespace |
| `Shift+Enter`, `Alt+Enter`, `Ctrl+J` | Starts a new line |
| `↑`, `↓` | Moves up and down in the input box; pressing `↑` again on the first line or `↓` again on the last line goes through the input history. If the box already had text, only history entries starting with that text are shown |
| `Ctrl+R` | Opens the input history list |
| `←`, `→`, `Home`, `End` | Moves the cursor; `Home` and `End` go to the start and end of the line. Holding `Shift` selects text |
| `Ctrl+←`, `Ctrl+→` | Moves the cursor by word; holding `Shift` selects text |
| `Ctrl+A` | Goes back to the start of the input box |
| `Ctrl+W`, `Alt+Backspace`, `Ctrl+Backspace` | Deletes the previous word |
| `Backspace`, `Delete` | Deletes one character |
| `Ctrl+C` | With text selected, copies it; with nothing selected but text in the box, clears the input box and shows `Cleared · ↑ to bring it back`. Pressing `↑` while the box is empty gets the text back |
| `Ctrl+S` | Stash: saves the text in the box and clears the input box; press it again to get the text back. If both the stash and the input box have text, they are swapped |
| `Ctrl+V`, `Alt+V` | Reads the clipboard and pastes; images and copied files in the clipboard become attachments (see "Ways to write in the input box"). In Windows Terminal, paste images with `Alt+V` |
| `Ctrl+Shift+V` | The terminal's own paste; everything pasted comes in as text |
| `Ctrl+G` | Writes this message in an external editor: `$VISUAL`, or `$EDITOR` if that is not set, or `vi` if neither is set. Once you save and quit the editor, the text returns to the input box. This is not available on Windows, and pressing it does nothing; write long messages straight in the input box (start new lines with `Shift+Enter`, `Alt+Enter`, `Ctrl+J`), or paste them in |
| `Esc` | Cancels the selection; while you are editing the last message with `/edit`, cancels editing. `Esc` does not clear the input box |
| `Ctrl+D` | Quits the program when the input box is empty |

### Timeline

While you read the timeline, you can use these keys:

| Key | What it does |
|---|---|
| `PgUp`, `PgDn` | Scrolls up or down half a screen. After you scroll up, new text does not push away what you are reading |
| `Ctrl+End` | Goes back to the bottom and follows the newest content. While you are scrolled up, `Jump to bottom (Ctrl+End) ↓` is shown at the bottom right, and it brightens when there is new content |
| `Ctrl+L` | Clears the screen: pushes the content off the top, and you can still see it by scrolling up. You cannot clear the screen while the AI is replying |
| `/jump` | Lists what you have said in this session; press `Enter` to jump there, and that message appears on the top line of the screen |
| `Ctrl+C` | When you have dragged to select text in the conversation, copies the selected text. Press `Esc` to cancel the selection |

To expand or collapse a step in the timeline, click it with the mouse.

### While the AI is replying

While the AI is replying, these keys work differently from usual:

| Key | What it does |
|---|---|
| `Enter` | Sends as usual. The message is queued and sent after this turn ends. Queued messages are shown above the input box, and clicking one takes it back into the input box |
| `Esc` `Esc` | One press shows `Press Esc again to interrupt`; a second press within 1.5 seconds interrupts this turn, and the queued messages are sent next. If the AI has not started doing anything yet and nothing is queued, the interrupted turn is withdrawn and your message goes back into the input box |
| `Ctrl+C` (input box empty) | Interrupts this turn; the queued messages are not sent and go back to the input box |
| `Ctrl+Enter` | If the input box has text, queues it first; then interrupts the turn at once, and the queued messages are sent right away. When the AI is not replying, it does the same as `Enter` |
| `Ctrl+L` | Cannot clear the screen, and shows `Can't clear the screen while a reply is running` |

While the AI is consolidating memories, pressing `Esc` twice stops the consolidation. When you are viewing a subagent, or when the main session is idle but subagents are still running, pressing `Esc` twice with the input box empty stops the subagents, and pressing `Ctrl+C` stops them too.

### Approval and question boxes

When the AI needs your approval for a step or asks you a question, a box takes the place of the input box, and all keys go to that box:

| Key | What it does |
|---|---|
| `↑`, `↓` (`j`, `k`) | Choose |
| `1` to `9` | Choose that item directly |
| `Enter` | Confirm, submit |
| Space | Ticks or unticks an option in multiple-choice questions |
| `←`, `→` (`h`, `l`), `Tab`, `Shift+Tab` | Switch between questions |
| `n` | In a question, lets you write extra notes; in an approval, moves the cursor to `Don't allow` so you can write a reason |
| `Ctrl+J`, `Ctrl+K`, `Ctrl+↑`, `Ctrl+↓` | Scroll through the command about to run, or the preview |
| `Ctrl+V` | Pastes an image: in a question, the image goes with the current question; in an approval, an image is accepted only on `Don't allow` |
| `Backspace` | When you are not writing, deletes the last image on this page |
| `Esc` `Esc` | Cancel |

While you are writing, `Enter` saves, `Shift+Enter`, `Alt+Enter` and `Ctrl+J` start a new line, and `Esc` leaves editing. For the three choices in the approval box and how long it waits before refusing automatically, see [Permissions and sandbox](../permissions.md#the-confirmation-box).

### Lists and pop-up boxes

In the `/` command list, the `@` file list, the `$` skill list, input history, `/sessions`, `/model` and similar lists and boxes, you can use these keys:

| Key | What it does |
|---|---|
| `↑`, `↓`, `Ctrl+K`, `Ctrl+J` | Choose |
| `Enter` | Run, choose |
| `Esc` | Close |
| Typing | In the command list and the `@` and `$` lists, keep typing to filter; in input history, the session list and the model list, typing searches |
| `Tab` | In the command list, completes the command name; in the `@` list, enters this folder |

In boxes where you cannot type (`/help`, `/theme`, `/language`, `/effort`, `/usage`, `/status`, `/tool-list`, `/context`, `/export`, the background panel, the persona and preset picker), `j` and `k` also move up and down. The boxes below have keys of their own:

| Box | Keys |
|---|---|
| `/sessions` session list | Space ticks, `Ctrl+A` selects all, `Ctrl+P` pins or unpins, `Ctrl+D` deletes (you need to press it twice) |
| `/status`, `/tool-list` | `c` copies everything |
| `/context` context details | `Enter` expands, `c` copies |
| `/usage` | `Tab`, `←`, `→` switch pages, `t` switches between tokens and cost |
| Background panel | `Enter` expands or collapses a command's output, `x` stops that command |
| Persona and preset picker for a new session | `e` edits the selected persona or preset; while this box is open, `Ctrl+C` and `Ctrl+D` quit the program |
| The `/files` page | `↑`, `↓` (`j`, `k`) switch files, `PgUp`, `PgDn`, Space scroll the diff, `Home`, `End` go to the start and end, `Esc` or `q` go back |

### Global

You can use these keys at any time:

| Key | What it does |
|---|---|
| `Tab`, `Shift+Tab` | Switches between full access and read-only. While the command list or the `@` or `$` list is open, `Tab` goes to the list, and `Shift+Tab` still switches. For permission levels, see [Permissions and sandbox](../permissions.md) |
| `↓` (input box empty) | Moves the focus to the background button in the footer and the subagent status lines. Then move with `↑`, `↓`, `←`, `→`; press `Enter` to open the background panel or switch into that subagent's session, `x` to stop the selected subagent, and `Esc` to go back to the input box |
| `Ctrl+Z` | Suspends the program to the background; run `fg` to resume it. Not available on Windows |
| `Ctrl+D` | Quits the program when the input box is empty; you can also run `/exit` to quit |

When you are viewing a subagent's session and that subagent has stopped or finished reporting, pressing `Esc` with the input box empty takes you back to the main session.

### Vim key mode

After you set `tui.keys` to `vim` (in `General → Interaction → Key mode` on the settings page, or by choosing `Vim` in step 2 of first-run setup), these places use a different set of keys:

| Where | Arrow keys (`arrows`, shipped) | Vim (`vim`) |
|---|---|---|
| Session list, model list, input history list, `/jump` | Type to search, `↑`, `↓` to choose | `j`, `k` to choose; `/` starts a search, and while searching `Ctrl+J`, `Ctrl+K` choose, `Enter` closes the search box (the filter stays), and `Esc` cancels the search; when you are not searching, `Esc` first clears the remaining filter, and pressing it again closes |
| `@` file list, `$` skill list | `Esc` closes the list | `Esc` enters `pick in list`: `j`, `k` choose, `h`, `l` move the cursor in the input box, `/` filters, `Enter` inserts, and `Esc` again closes |

Keys everywhere else are the same in both modes.

### Input method

On Linux with the fcitx5 input method, when you press keys in a list that are not for typing, such as `j` and `k`, Miyu first switches the input method to English, and switches it back when you return to typing; it does not switch while the terminal is not in the foreground. If you do not want this, set `MIYU_TUI_IME=0` when you open the terminal UI. This only works with fcitx5 (it takes effect only when fcitx appears in the environment variable `XMODIFIERS`, `GTK_IM_MODULE` or `QT_IM_MODULE`, and it switches with `fcitx5-remote`); input methods on macOS and Windows are not switched for you.

## Mouse

The terminal UI takes over the mouse. In different places, you can use the mouse to do the following:

| Where | What you can do |
|---|---|
| Timeline | Click a section or a step to expand or collapse it; drag to select text, which is copied when you release the button (the selection stays, and `Ctrl+C` copies it again); click links and paths to open them with the system's program; click a Mermaid diagram to open the large image in a program; each notch of the scroll wheel moves three lines |
| The column to the right of the timeline | Hovering over it shows the scroll bar, which you can drag or click |
| Input box | Click to place the cursor, drag to select text, double-click to select a word; click an attachment block or file block to open that file with the system's program |
| Queued messages | Click one to take it back into the input box |
| The message pinned at the top of the conversation | Click it to jump back to that message |
| Footer | Click the usage cell to open `/context`; when the session is stuck, clicking `Compact` does the same as running `/compact`; click the background button to open the background panel |
| Sidebar | Scroll with the wheel; drag to select text, then press `Ctrl+C` to copy; for what clicking the short id, recent sessions, jump-to messages and changed files does, see the parts table above |
| Lists and boxes | Hover to select, click to run, scroll with the wheel |
| Approval and question boxes | Hover to select; a click does the same as pressing `Enter` |

When you click a link, a path or an attachment block, Miyu hands it to the system to open: `xdg-open` on Linux, `open` on macOS, `rundll32.exe url.dll,FileProtocolHandler` on Windows. Only `http`, `https` and `file` links and local files that already exist are opened.

Files the AI shows you with `show`, and large Mermaid images, are handed first to the default program for that type of file, and to the browser if there is no default program:

| System | Default program | Browser |
|---|---|---|
| Linux | Asks `xdg-mime` for the default program for that type of file and starts it with `gio launch`; without `gio`, uses `gtk-launch`; failing that, uses `xdg-open` | Uses `$BROWSER`; if it is not set, tries `firefox`, `chromium`, `chromium-browser`, `google-chrome`, `google-chrome-stable`, `brave-browser`, `microsoft-edge` in that order |
| macOS | `open` | `$BROWSER` first, then `open -a Safari` |
| Windows | Handed to the system (`rundll32.exe`); because it cannot tell whether any program can open the file, handing it over counts as opened | `$BROWSER` |

If nothing can open it, the card shows `No program can open it: …` and the file's path.

## Ways to write in the input box

Besides plain typing, the input box supports the following forms:

| Form | What it does |
|---|---|
| `/command` | Typing `/` brings up the command list, which is filtered as you type |
| `@` | Refers to a file or folder: typing `@` and a few characters brings up the file list; press `Tab` to enter a folder, and `Enter` to turn the entry into a block. Type `/` to browse by folder |
| `$` | Names a skill to use: typing `$` and a name brings up the skill list; you can name several skills in one message |
| `!` | Typing `!` as the first character enters command mode, and the box shows `Type a command to run`; when you press Enter, the core runs that command directly, without going through the AI, for at most 120 seconds. Attachments are not allowed in this mode. With the box empty, press `Backspace` or `Esc` to go back to normal mode |
| Dragging files into the terminal | If everything you drag in is an existing local file or folder, images, PDFs, audio and video become attachments (`[image 1]`), anything else becomes a file block (`[name]`, `[folder/]`), and they are replaced with paths when sent |
| Pasting images | Press `Ctrl+V` (`Alt+V` in Windows Terminal) to turn an image in the clipboard into an attachment; files copied in a file manager are handled the same way as dragged-in files (not on macOS, see below) |
| Pasting long text | Text of more than 10 lines or 800 characters becomes a block `[pasted N line(s)]`, which is replaced with the original text when sent |

Attachments can be at most 20 MiB. If the current model does not accept that kind of attachment, it is sent as a file path instead, with the hint `This model doesn't take …, sent as file paths`. A message over 1 MB is sent as a text attachment.

`Ctrl+V` uses these commands to read the clipboard:

| System | Text | Images | Copied files |
|---|---|---|---|
| Linux | Under Wayland, tries `wl-paste` first, then `xclip`, `xsel` | Under Wayland, reads with `wl-paste` if it is installed, otherwise with `xclip` | Same as images |
| macOS | The built-in `pbpaste` | The built-in `osascript` | Not accepted: files copied in Finder cannot be pasted in |
| Windows | Windows PowerShell (`powershell`) | Same as text | Same as text |

Each command waits at most 1 second; on Windows, where starting PowerShell is slow, it waits at most 3 seconds. If none of them can read the clipboard, it shows `Can't read the clipboard: use your terminal's own paste (Ctrl+Shift+V in kitty)`.

## Reading the timeline

The timeline records everything that happens in the session:

- Each step the AI takes in a turn is one line, showing an icon, the tool name and short arguments. Commands, thoughts and edits come with a few preview lines: while a thought is in progress, the latest `tui.timeline_thought_rows` (shipped `15`) lines scroll by, and command previews show `tui.timeline_preview_rows` (shipped `10`) lines. If you turn on `tui.timeline_expand_thought`, `tui.timeline_expand_command` or `tui.timeline_expand_edit`, that kind of step shows its full text by default.
- Clicking a step expands it, so you can see its output or the edit's diff; memory and knowledge base results open as individual entries. Click again to collapse it.
- When a turn ends, its steps fold into one line, for example `Ran 2 commands · 3 thoughts · 48s`, followed by the number of lines added and removed if files were edited. Click the line to expand it. If you do not want folding, turn off `tui.timeline_fold`.
- At the end of a turn there is a closing line showing time · provider/model · elapsed, followed by the speed, this turn's usage and the cache hit rate.
- Diffs: running `/files` opens the `Changed files` page; one side lists the changed files (on the right in a wide window, at the top in a narrow one), and the other side shows the full diff of the selected file.
- Local paths and URLs in replies are clickable, and open with the program the system assigns to that type of file. Files the AI shows you with `show` are labeled with their kind and `Click to open`.
- Images, block formulas and Mermaid diagrams are drawn as images in terminals that support an image protocol, and clicking a Mermaid diagram opens the large image in a program; where the terminal cannot show them, the source is shown. Run `/images off` to stop drawing them for this run.
- Subagents: above the footer, each subagent has one line showing its status; press `↓` to select one and `Enter` to switch into its session.
- Background commands: the middle of the footer shows `Background: N`; click it, or select it and press `Enter`, to open the background panel, where you can see output and stop commands. When a command finishes, the timeline records a line `Background command done · …`.
- Usage: the usage cell on the right of the footer shows the context ring, cumulative tokens (including subagents) and cost; the sidebar's `Context` and `Usage` sections give more detail. Run `/usage` to see the usage on this machine by day and by model.
- Messages from elsewhere (other sessions, subagents, or what you sent from another interface) are recorded as a line `Message from …`.

## Appearance

### Colors

Run `/theme` to open the colors box; whichever color scheme you move the cursor to, the interface changes to it at once. Press `Enter` to write your choice to `tui.theme`, or `Esc` to change back to the original.

| Option | Value | Where the colors come from |
|---|---|---|
| Auto | `auto` (shipped) | Checked in order: if the persona has an avatar or a theme color, it follows the avatar; if a desktop wallpaper can be found, it follows the wallpaper; if the terminal's colors can be queried, it uses terminal colors; if none of these work, it uses Tokyo Night |
| Follow the avatar | `persona` | Takes the main color from the avatar of the persona you are viewing and generates a color set from it; if the persona has its own main color set, that color is used. Not listed if the persona provides no color |
| Follow the wallpaper | `wallpaper` | First looks for the colors generated by matugen; if there are none, takes the main color from the desktop wallpaper image. When you change the wallpaper, the colors follow automatically. Not listed if no wallpaper can be found |
| Terminal colors | `terminal` | Follows the terminal's own colors. If the terminal supports true color and its colors can be queried, it picks a main color from the terminal's 16 colors to generate a set; otherwise it uses the terminal's 16 colors directly. This scheme does not paint the background |

Tokyo Night is only the fallback when `Auto` finds nothing. It is not listed in the colors box, but writing `tui.theme = "tokyonight"` by hand is also recognized. The program comes with four color files: `tokyonight-night`, `tokyonight-day` (with their own colors), `terminal`, `terminal-light` (using the terminal's colors).

When follow the avatar, follow the wallpaper or terminal colors has several candidate main colors, you can pick one in `Appearance → Color scheme → Main color` on the settings page. A pick for follow the wallpaper or terminal colors is written to `tui.theme_seed`; a pick for follow the avatar is written back to that persona.

Light or dark (`tui.theme_mode`): auto follows the terminal's background, and counts as dark if the background cannot be queried; you can also choose to always use dark or light.

Paint the background (`tui.theme_background`, on as shipped): the whole interface is painted in the scheme's background color. Terminal colors do not paint the background, and the settings page does not list this item for them.

### Icons, theme, language

- `/icons` switches between Nerd Font icons and plain characters, for this run only. If you want to keep it, set `tui.icons` (`Appearance → Icons` on the settings page).
- The theme (`tui.look`) controls borders, marks and text styling: when unset, the default theme is used; `ascii` uses the built-in plain ASCII theme, which replaces the symbols and icons on screen with ASCII characters (Chinese characters and letters are unchanged), and the icons chosen with `tui.icons` or `/icons` are used again only after you switch back to another theme; if you installed another terminal theme package, write its id. For how to install theme packages, see [Packages](../packages.md).
- `/language`: the first line is `Auto (system: …)`, followed by 中文, English and 日本語. Your choice is written to `ui.language`. After you switch, newly drawn text uses the new language, and what is already in the timeline does not change.

## Shell integration

Once shell integration is installed, you type a sentence after the shell prompt and press Enter, and you are talking to the AI. The reply is printed in the shell in the style of the timeline, without switching to the full-screen interface.

### Installing and uninstalling

You can use these commands:

```sh
miyu shellhook install            # install for the shell you are using
miyu shellhook install --shell zsh
miyu shellhook status             # see which shells it is installed in
miyu shellhook doctor             # check the install, the connection to the core, terminal colors and the clipboard
miyu shellhook uninstall          # turn it off: remove it from the shell
```

`--shell` can be `fish`, `bash`, `zsh`, `pwsh` (PowerShell 7) or `powershell` (the 5.1 that comes with Windows). Without `--shell`, the shell is detected on each system as follows:

| System | How it is detected without `--shell` |
|---|---|
| Linux | From the parent process; if that is not recognized, from `SHELL` |
| macOS | From `SHELL` only |
| Windows | From `SHELL` if it is set; otherwise from the user module folders PowerShell adds to `PSModulePath`, which tell 5.1 and 7 apart |

If it cannot tell, it reports `Can't tell which shell this is: pass --shell fish, bash, zsh, pwsh or powershell`. `--program <path>` sets the program the shell calls; without it, the `miyu` next to this program is used.

Where it is installed:

| Shell | Written into |
|---|---|
| fish | `~/.config/fish/conf.d/miyu-shellhook.fish` (under `XDG_CONFIG_HOME` if that is set); it writes the whole file |
| bash | A marked section in `~/.bashrc` |
| zsh | A marked section in `~/.zshrc` (under `ZDOTDIR` if that is set) |
| pwsh, powershell | Asks PowerShell for its own `$PROFILE.CurrentUserCurrentHost` and writes a marked section into that file. PSReadLine is required |

Only one line is installed, and the script is printed fresh each time the shell starts, so after you upgrade Miyu, new shells use the new script automatically. Shells that are already open show `This terminal still has the old hook; reopen the terminal to use the new one`. Installing again only replaces the existing section. If a fish file was not written by shellhook, installing does not touch it.

If PowerShell's execution policy is `Restricted` or `AllSigned`, PowerShell does not load the profile, and installing prints `PowerShell's execution policy is Restricted, so it won't load the profile and the hook has no effect: run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned in PowerShell, then open a new window` (the message names the actual policy). Run what it says:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### Using it

1. Open a new shell.
2. Type a sentence and press Enter. If the first word is an ordinary word and not any command, the line goes to the AI; if it is a command, it runs as usual. For multiple lines, it first checks whether the first command exists, and when it cannot tell, Miyu decides. When a command is not found, the line also goes to the AI.
3. Read the reply. When your approval or an answer is needed, the same box as in the full-screen interface pops up below the prompt. Press `Ctrl+C` to interrupt.

| Key | What it does |
|---|---|
| `Ctrl+J` | Starts a new line on the command line, for multi-line messages |
| `Ctrl+V` | Reads the clipboard: images and copied files become blocks (`[image 1]`), and long text becomes `[pasted 14 line(s)]`. In PowerShell, `Alt+V` works too |

You can also type slash commands in the shell, or write them as `miyu shellhook <name>` (for example `miyu shellhook model`). `/model`, `/theme`, `/effort`, `/sessions`, `/persona` and `/preset` open a box below the prompt for you to choose from, and after `/model`, `/theme` and `/effort` you can also write the name directly. `/settings` opens the full-screen settings page. `/tui` opens this terminal's session in the full-screen interface. `/exit` and `/language` do nothing in the shell.

When background tasks the AI started finish, they are printed when you return to the prompt. If a task finishes while the prompt is waiting for your input: fish and zsh print it at once; bash waits until you next press Enter, and PowerShell waits until the prompt is next drawn (when you press Enter or `Ctrl+C`).

### Shell integration sessions

Each terminal window has its own session, called a shell integration session, which is marked `Shell` in the session list. Just opening a terminal does not create a session; it is created only when you actually say something. `General → Shell integration session` on the settings page has three settings:

| Key | Default | What it controls |
|---|---|---|
| `terminal.persona` | Follows `persona.default` | Which persona a new shell integration session uses |
| `terminal.preset` | Follows `preset.default` | Which preset a new shell integration session uses |
| `terminal.idle_new_after` | `180` | If you have been idle for more than this many minutes since you last spoke, the next message starts a new session, with the hint `The last message was … ago: started a new session so an expired cache doesn't cost extra`. Set it to `0` to never start a new session |

Running `/persona` or `/preset` in the shell also changes these two settings.

## Notifications

When the terminal is not in the foreground and a reply finishes, an error occurs, or Miyu is waiting for your approval or answer, Miyu shows a notification and plays a sound. The notification title is the name of the session's persona, and if the persona has an avatar, the notification shows it. When another session finishes, or another session is asking you something, the notification is shown even with the terminal in the foreground, but without a sound.

| Where | How it notifies |
|---|---|
| kitty | Uses kitty's own notification, and clicking it jumps back to the window; kitty does not show it while the window is in the foreground |
| iTerm2, WezTerm, ghostty (detected by `TERM_PROGRAM` being `iTerm.app`, `WezTerm`, `ghostty`) | Uses the terminal's own notification |
| Other terminals, and inside tmux or herdr | Uses a system notification, see the table below |

For system notifications and sounds, each platform uses:

| System | System notification | Sound |
|---|---|---|
| Linux | `notify-send` | Tries `pw-play`, `paplay`, `canberra-gtk-play`, `aplay` in that order |
| macOS | `osascript` | `afplay` |
| Windows | None: when it falls through to system notifications, nothing is shown | There is no player program for Windows, so no sound is played |

On Windows, notifications can be shown only by terminals like those in the first two rows of the table above, which understand notification sequences themselves (for example WezTerm). Windows Terminal is not on that list, and Miyu does not send it notifications.

In herdr, herdr plays the sound. Notifications and sounds have no switch you can set.

## Multiple sessions

When you work with several sessions:

- Whether opening the terminal UI starts a new session or continues the most recent one depends on `On start, open` (`ui.startup`); for details, see [Sessions](../sessions.md).
- A new session starts by choosing a persona and then a preset, and you can type only after choosing. If you do not want to choose every time, turn on `tui.auto_pick`.
- Run `/sessions` to open the session list, where sessions are grouped into `Recent`, `Past 7 days`, `Past 30 days`, `Older` and `Archived`. Clicking a line in the sidebar's `Recent sessions` also switches sessions.
- When another session is waiting for your approval or answer, no box pops up in the current session; instead it shows the hint `"<title>" is asking you · /resume to switch`, that entry in the session list is marked `asking`, and its line in the sidebar starts with a yellow `?`. The box pops up once you switch over.
- When another session finishes a turn, a dot appears on its line in the sidebar, and it disappears once you switch over.

## Using it with herdr

When the terminal UI is open in a herdr pane:

- Miyu reports its state, working, waiting for you or idle, to herdr, which shows it in its sidebar.
- When you switch sessions, Miyu automatically reports the resume command `miyu tui --resume <id>`. After herdr restarts, each pane reconnects to its own session. Running `/new` clears the old resume command. If you only close the herdr client, Miyu keeps running.
- The resume command requires the command name you typed to be found on PATH; if it cannot be found, nothing is reported. Temporary environment variables written before the command (for example `MIYU_HOME=… miyu` in bash) are not saved by herdr; if you need them, write a launch script that fixes these variables and put it on PATH.

## Files in the cache

The terminal UI keeps its crash records, the drafts it hands to the editor, and similar files in the cache folder. The cache folder is shared by the whole machine and does not change with `MIYU_HOME`:

| System | Cache folder |
|---|---|
| Linux | `$XDG_CACHE_HOME/miyu` (`~/.cache/miyu` if `XDG_CACHE_HOME` is not set or is not an absolute path) |
| macOS | `~/Library/Caches/Miyu` |
| Windows | `%LOCALAPPDATA%\Miyu\cache` |

The files the terminal UI uses in the cache folder:

| Where | What it is |
|---|---|
| `tui/crash.log` | Crash records: time, version, error and stack trace, with each crash appended after the last |
| `tui/edit/` | Temporary files handed to the editor by `Ctrl+G` and when you edit prompts |
| `tui/pasted/<pid>/` | Images pasted from the clipboard. They are deleted when the interface exits; files left behind by a crash are cleaned up the next time you open the terminal UI on Linux and macOS, but not on Windows, where you delete them by hand if you want |
| `tui/sounds/` | Notification sounds |

## Troubleshooting

| What you see | What to do |
|---|---|
| Icons are boxes or question marks | The font has no Nerd Font icons. Install a Nerd Font, or run `miyu config set tui.icons plain` |
| Borders and spinners are garbled | Run `miyu config set tui.look ascii` to switch to the plain ASCII theme |
| Colors look gray or wrong | Check whether `COLORTERM` and `TERM` identify true color; if they do not, set `MIYU_COLOR=truecolor`; or change the colors and light or dark in `Appearance → Color scheme` on the settings page |
| Images and formulas show as source | The terminal does not support the kitty, sixel or iTerm2 image protocol, so you need to switch to one that does; or you ran `/images off` earlier, so run `/images on` |
| Pressing `Shift+Enter` sent the message | The terminal cannot report `Shift+Enter`, so use `Alt+Enter` or `Ctrl+J` for a new line |
| `Can't read the clipboard: use your terminal's own paste (Ctrl+Shift+V in kitty)` | Linux: install one of `wl-paste` (under Wayland), `xclip`, `xsel`; pasting images and copied files needs `wl-paste` or `xclip`. macOS: the clipboard is read with the built-in `pbpaste`; if that fails, use the terminal's own paste. Windows: reading the clipboard has to start Windows PowerShell (`powershell`), and if reading does not finish within 3 seconds it counts as failed; in that case, use the terminal's own paste |
| It shows `Copied … character(s)`, but the clipboard is empty | The terminal does not support OSC 52, so nothing was copied. You need to switch to a terminal that supports OSC 52 |
| `The core isn't running: set MIYU_CORE_BIN to the remake's miyu when starting`, `Can't connect to the core: …` | Open it with `miyu` or `miyu tui`; do not run `miyu-tui` directly. If that does not help, see [Troubleshooting](../troubleshooting.md#the-core-will-not-start-or-cannot-connect) |
| A sentence typed in the shell was sent twice | Run `miyu shellhook status`; it will tell you the old `conf.d/miyu.fish` is still there. Delete that file |
| The terminal UI crashed, showing `Stack trace saved to …` | The crash record is `tui/crash.log` in the cache folder; see "Files in the cache" above |

If you installed shell integration, run `miyu shellhook doctor` first; it tells you, item by item, what is wrong and how to fix it.
