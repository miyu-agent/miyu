# Terminal

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

The full guide to using Miyu in a terminal: what each part of the screen is, what each key does, how to set it up the way you like, and how to talk to the AI straight from the shell prompt. Chinese version: [中文](../../../zh/guide/heads/tui.md).

## Opening it

Type `miyu` or `miyu tui` in a terminal. Plain `miyu` opens the interface set in "Default interface" (`ui.head`) in settings, which is the terminal as shipped. If the core is not running, it is started first.

```text
miyu tui [--resume <id> | --page <page> | config]
```

| Form | What it does |
|---|---|
| No arguments | Opens a new session or continues the most recent one, as set in "On start, open" (`ui.startup`) |
| `--resume <id>` | Opens this session; the full id is required. If it cannot be opened, it reports an error and exits |
| `--page config`, `config` | Opens only the settings page, without entering a session; press `Esc` on the settings menu to exit |
| `--page oobe` | Goes through first-run setup again |
| `-h`, `--help` | Prints help |

An unknown page name opens the home page as usual. The terminal interface is the package `tui`; if you uninstalled it, install it again with `miyu pkg install tui`.

Environment variables:

| Variable | What it does |
|---|---|
| `MIYU_COLOR` | Forces the color depth: `truecolor` (or `24bit`), `256`, `16`, `none` |
| `NO_COLOR` | Set to any non-empty value to turn colors off, keeping only bold, italics and the like |
| `MIYU_TUI_IME=0` | Does not switch the input method for you (see "Input method" below) |

To open it once with an environment variable set:

```bash
MIYU_COLOR=truecolor miyu
```

```powershell
$env:MIYU_COLOR = 'truecolor'
miyu
```

Set this way in PowerShell, it stays in effect for that window.

## What it needs from the terminal

| Needed | How it is detected | What happens without it |
|---|---|---|
| True color | `COLORTERM` is `truecolor` or `24bit`; `TERM` contains `kitty`, `wezterm`, `alacritty`, `ghostty` or `foot`; `TERM_PROGRAM` is `iTerm.app`, `WezTerm`, `ghostty` or `vscode`. On Windows, an unset `TERM` also counts | With `256color` in `TERM` it switches to the nearest 256 colors, otherwise to 16 colors; with `TERM` empty or `dumb` there are no colors |
| Nerd Font | Not detected automatically; first-run setup asks whether you see icons or boxes | Icons show as boxes or question marks. Switch to plain characters: `/icons`, or "Appearance → Icons" on the settings page |
| Mouse | The program takes over the mouse | The terminal's own selection does not work; dragging to select and copying are done by Miyu itself (see "Mouse") |
| Images | Asks the terminal once at startup, waiting at most 2 seconds; recognizes kitty, sixel and iTerm2 | Images, formulas and Mermaid diagrams all show as source |
| Keyboard protocol | Terminals that support the kitty keyboard protocol can report `Shift+Enter` and `Ctrl+Enter` | For a new line, use `Alt+Enter` or `Ctrl+J` instead of `Shift+Enter` |
| Foreground and background | The terminal reports when the window gains and loses focus | In terminals that cannot report it, no notification is shown when a reply finishes (except kitty) |

In the Linux console (`TERM=linux`), icons default to plain characters if you have not set them, and the theme defaults to the plain ASCII one if you have not set it. If the interface is in Chinese or Japanese, it shows once: "The Linux console can't show Chinese or Japanese: you can switch the interface language to English in settings".

In Windows Terminal (detected by the environment variable `WT_SESSION`, which also covers WSL running inside it), the rotating hints in the empty input box and the hint line on the home page are not shown.

### tmux, SSH, herdr

- Copying goes through the terminal's OSC 52, so it reaches the clipboard on your side even over SSH. If the terminal does not support OSC 52, nothing is copied, and no error is shown.
- `Ctrl+V` reads the clipboard of the machine running Miyu. When connected over SSH, use your terminal's own paste to paste from your side (in kitty, `Ctrl+Shift+V`).
- In tmux and herdr, notifications are shown by the system (the terminal's own notifications do not get through).
- In tmux, the terminal's colors cannot be queried: when the colors follow the terminal, only the terminal's 16 colors are used. For the true-color set, turn on tmux passthrough.
- If you sometimes view the same interface in a terminal that can show images and sometimes in one that cannot (for example connecting from a phone inside herdr), type `/images off` to stop showing images for this run, and `/images on` to restore them. The config is not changed.

## First-run setup

The first time you open the terminal, after it connects to the core, the whole screen is setup. When you finish, it writes `ui.welcomed`, and setup does not appear again. Pressing `Ctrl+C` part-way quits the program without recording it as finished, so it starts over next time. To go through it again: `miyu tui --page oobe`.

The welcome page says "Welcome to Miyu" and "Take a minute to set up a model and a persona"; press `Enter` to start. The line at the top shows progress: language, controls, icons, model, currency, persona, color scheme, about you, preset. In every step, `Esc` goes back one step.

1. Interface language: the first line is "Follow the system (…)", followed by 中文, English and 日本語. Your choice applies at once.
2. How you like to move around: "Arrow keys" (↑↓ to move, type to search) or "Vim" (j/k to move, / to search); written to `tui.keys`.
3. Icons: "Do you see icons, or boxes and garbled text?" Choose "Icons" for Nerd Font icons, or "Boxes or garbage" for plain characters; written to `tui.icons`.
4. Choose a model provider: pick one, enter its key, "Test connection" (it sends one test request, which costs a little), and once connected, pick a model. The list has "More providers…" and "Custom…" (enter an address and an API: OpenAI compatible, Anthropic, OpenAI Responses). If a model is already set up, it asks whether to "Use it" or "Choose another". This step cannot be skipped. Details on providers, keys and models: [Models](../models.md).
5. Which currency amounts should be shown in: twenty common ones are listed, and the last line, "Other…", takes a three-letter code. Written to `usage.currency`; costs are converted into it at recent exchange rates.
6. Create a persona: name (required), short description, avatar, detailed persona prompt, example dialogs, roleplay reminder. For the long fields, `Enter` opens an editing window and `Ctrl+G` writes in an external editor; on Windows there is no external editor option, so write in the editing window or paste into it. "Next" creates it and makes it the default persona; "Skip" creates none. See [Personas and presets](../personas-presets.md).
7. Color scheme: mode (auto, dark, light) and colors (auto, follow the avatar, follow the wallpaper, terminal colors); the interface changes to whichever one you move to. If the persona has no avatar, there is an extra field, "Figure": show or hide the mascot ("Uses more CPU and slows startup when on"). With follow the avatar or follow the wallpaper there is an extra field, "Accent". There is also a field "Background". If you skipped the persona in the previous step, this step is skipped too.
8. How the AI knows you: "What language should the AI reply in", "What should the AI call you", "More about you (optional)". All are optional, and you can "Skip".
9. Choose a preset: one block per preset; Space shows details, `Enter` picks it as the default preset; the last block, "Custom", lets you name it and tick features yourself.
10. Turn on the built-in semantic model?: appears only if the package source has a semantic model package. "Yes" downloads and installs it right away; "No" uses keyword search only. See [Memory](../memory.md).
11. Done: shows "Model … · Persona … · Preset …"; press `Enter` to start chatting. The new session that follows uses the persona and preset chosen here.

To change any of this later, use the settings page (`/settings`).

## What is on the screen

An empty session is the home page: the input box is in the middle of the screen, with the home page items above it (an avatar or the mascot if "Show the figure on the home screen" is on). After you send the first message, it looks like this:

```text
┌──────────────────── Main column ────────────────────┐│┌── Sidebar ──┐
 Top of the conversation (pins your message on scroll) ││ Avatar
                                                       ││ Session name, #short id
 Timeline                                              ││ Workspace
                                                       ││ Context
 Above the input box (todos, run status, queued)       ││ Usage
 ╭ Input box ──────────────────────╮                   ││ …
 ╰─────────────────────────────────╯                   ││
 Footer: permission level · model           usage      ││
```

| Part | What it shows |
|---|---|
| Timeline | What you said, the AI's replies, and each step the AI took (see "Reading the timeline") |
| Top of the conversation | When you have scrolled up and your message has scrolled out of view, a line with that message is pinned at the top; click it to jump back |
| Above the input box | Todos; the run status line while the AI is replying ("Thinking", "Replying", elapsed time); queued messages; the reason in red when the core cannot be reached; temporary hints |
| Input box | What you type. It grows to at most 8 lines; beyond that it scrolls inside the box |
| Footer | On the left, the permission level ("⏵⏵ Full access", "⏸ Read-only"), the model and provider, and the thinking effort; on the right, the speed and usage cell (for example `◔ 128.4k · ¥0.42`). With background commands running, a "Background: N" button appears in the middle. When the window is narrow, the cells on the right go first, then the permission level shrinks to its icon only and the model shows only its last part, and finally the provider name is dropped |
| Sidebar | Appears on the right, 38 columns wide, when the window is at least 120 columns wide and you are not on the home page. It scrolls, and you can drag to select text |

### Sidebar parts

In shipped order:

| Part name | What it shows | What you can click |
|---|---|---|
| `avatar` | The persona's avatar, or the mascot if it has none. Governed by "Show the figure in the sidebar" (`tui.mascot_sidebar`, off as shipped); when off, a persona's avatar is still shown if it has one | |
| `session` | The session name, below it `#short id`, below that the persona and preset | Click the short id to copy the full session id |
| `cwd` | "Workspace": this session's working directory | |
| `context` | "Context": used / window size · percent | |
| `usage` | "Usage": total tokens, input and output each, cache hit rate, number of compactions, number of cache breaks, cost | |
| `loops` | The loops attached to this session (`/loop`) | |
| `jump` | "Jump to": your latest messages in this session, newest at the bottom, with an arrow in front of the one you are viewing. The count follows `tui.sidebar_jumps` (shipped `8`) | Click a message to jump to it |
| `files` | "Changed files": files this session changed, one per line, followed by lines added and removed, at most 8. Not shown if no files were changed | Click a line to open the `/files` page with that file selected |
| `recent` | "Recent sessions": one per line. A yellow `?` at the start means it is waiting for your approval or answer, a spinner means it is running, a dot means it finished and you have not looked yet, an arrow means the current one. The count follows `tui.sidebar_sessions` (shipped `8`) | Click a line to switch to it |

Packages that bring interface blocks add their blocks after these.

### Choosing which parts to show

The sidebar, the footer, the area above the input box and the top of the conversation each have a list. They are not on the settings page; edit the system config `~/.miyu/etc/config.toml` by hand with `miyu config edit` (the data root is `~/.miyu` by default, `%USERPROFILE%\.miyu` on Windows):

| Key | Shipped parts |
|---|---|
| `tui.side` | The nine in the table above |
| `tui.footer` | Left section `level`, `model`; right section `usage` |
| `tui.above` | `todo` |
| `tui.top` | `prompt` |

Each part is an inline table: `part` is the part name, `hidden = true` hides it, `rows` is the maximum number of rows (`0` for no limit; the footer has only one row and ignores it). The parts you list come in the order you wrote them; the ones you did not list follow in shipped order. An unknown part name is not drawn, and it shows once: "Unknown parts in a slot: …".

```toml
[tui]
# Recent sessions at the top, at most 5 rows; no avatar
side = [{ part = "recent", rows = 5 }, { part = "avatar", hidden = true }]
# No model in the footer
footer = [{ part = "model", hidden = true }]
```

Once saved, it is redrawn at once. If you only want fewer sessions or messages listed, change `tui.sidebar_sessions` or `tui.sidebar_jumps`; `0` hides that block.

## Keys

Grouped by situation below. Whichever list or box is open gets the keys first; `/help` shows the keys and all commands at any time.

### In the input box

| Key | What it does |
|---|---|
| `Enter` | Sends; for a command, runs it. Nothing is sent if the box holds only whitespace |
| `Shift+Enter`, `Alt+Enter`, `Ctrl+J` | New line |
| `↑`, `↓` | Move up and down in the box; pressing `↑` on the first line or `↓` on the last line goes through input history. If the box already had text, only entries starting with it are shown |
| `Ctrl+R` | Input history list |
| `←`, `→`, `Home`, `End` | Move the cursor; `Home` and `End` go to the start and end of the line; hold `Shift` to select |
| `Ctrl+←`, `Ctrl+→` | Move by word; hold `Shift` to select |
| `Ctrl+A` | Go to the start of the input box |
| `Ctrl+W`, `Alt+Backspace`, `Ctrl+Backspace` | Delete the previous word |
| `Backspace`, `Delete` | Delete one character |
| `Ctrl+C` | With text selected, copies it; with nothing selected and text in the box, clears the input box and shows "Cleared · ↑ to bring it back"; press `↑` while the box is empty to get it back |
| `Ctrl+S` | Stash: saves the text in the box and clears it; press again to get it back. If both have text, they are swapped |
| `Ctrl+V`, `Alt+V` | Pastes from the clipboard; images and copied files in the clipboard become attachments (see "Ways to write in the input box"). In Windows Terminal, paste images with `Alt+V` |
| `Ctrl+Shift+V` | The terminal's own paste; everything pasted comes in as text |
| `Ctrl+G` | Writes this message in an external editor: `$VISUAL`, or `$EDITOR` if that is not set, or `vi` if neither is. Save and quit, and the text returns to the input box. Not available on Windows: pressing it does nothing; write long messages straight in the input box (new line with `Shift+Enter`, `Alt+Enter`, `Ctrl+J`), or paste them in |
| `Esc` | Cancels the selection; while editing the last message with `/edit`, cancels editing. Does not clear the input box |
| `Ctrl+D` | Quits when the input box is empty |

### Timeline

| Key | What it does |
|---|---|
| `PgUp`, `PgDn` | Scroll up or down half a screen. After you scroll up, new text does not push away what you are reading |
| `Ctrl+End` | Back to the bottom, following the newest. While scrolled up, "Jump to bottom (Ctrl+End) ↓" is shown at the bottom right, and it brightens when there is new content |
| `Ctrl+L` | Clears the screen: pushes everything off the top; scrolling up still shows the content. Not possible while the AI is replying |
| `/jump` | Lists what you have said in this session; `Enter` jumps there, with that message at the top line of the screen |
| `Ctrl+C` | When you have dragged to select text in the conversation, copies the selection. `Esc` cancels the selection |

Expanding and collapsing a step in the timeline is done by clicking with the mouse.

### While the AI is replying

| Key | What it does |
|---|---|
| `Enter` | Sends as usual. The message is queued and sent after this turn ends. Queued messages are shown above the input box; click one to take it back into the input box |
| `Esc` `Esc` | One press shows "Press Esc again to interrupt"; a second press within 1.5 seconds interrupts this turn, and queued messages are sent next. If the AI has not started doing anything yet and nothing is queued, the interrupted turn is withdrawn and your message goes back into the input box |
| `Ctrl+C` (input box empty) | Interrupts this turn; queued messages are not sent and go back to the input box |
| `Ctrl+Enter` | If the input box has text, it is queued first; then the turn is interrupted at once and the queued messages are sent right away. When no reply is running, same as `Enter` |
| `Ctrl+L` | Cannot clear the screen; shows "Can't clear the screen while a reply is running" |

While the AI is consolidating memories, pressing `Esc` twice stops the consolidation. When viewing a subagent, or when the main session is idle but subagents are still running, pressing `Esc` twice with the input box empty stops the subagents; `Ctrl+C` stops them too.

### Approval and question boxes

When the AI needs your approval for a step or asks you a question, a box takes the place of the input box. All keys go to it:

| Key | What it does |
|---|---|
| `↑`, `↓` (`j`, `k`) | Choose |
| `1` to `9` | Choose that item directly |
| `Enter` | Confirm, submit |
| Space | Tick or untick in multiple-choice questions |
| `←`, `→` (`h`, `l`), `Tab`, `Shift+Tab` | Switch between questions |
| `n` | In a question, write extra notes; in an approval, moves the cursor to "Don't allow" to write a reason |
| `Ctrl+J`, `Ctrl+K`, `Ctrl+↑`, `Ctrl+↓` | Scroll the command to be run, or the preview |
| `Ctrl+V` | Paste an image: in a question it goes with the current question; in an approval it is only accepted on "Don't allow" |
| `Backspace` | When not writing, deletes the last image on this page |
| `Esc` `Esc` | Cancel |

While writing, `Enter` saves, `Shift+Enter`, `Alt+Enter`, `Ctrl+J` start a new line, and `Esc` leaves editing. For the three choices in the approval box and how long it waits before refusing automatically, see [Permissions and sandbox](../permissions.md#the-confirmation-box).

The `/` command list, the `@` file list, the `$` skill list, input history, `/sessions`, `/model` and the like:

| Key | What it does |

| `Tab` | In the command list, completes the command name; in the `@` list, enters this folder |

In boxes where you cannot type (`/help`, `/theme`, `/language`, `/effort`, `/usage`, `/status`, `/tool-list`, `/context`, `/export`, the background panel, the persona and preset picker), `j` and `k` also move up and down. Keys of particular boxes:

| Box | Keys |
|---|---|

| `/status`, `/tool-list` | `c` copies everything |
| `/context` context details | `Enter` expands, `c` copies |
| `/usage` | `Tab`, `←`, `→` switch pages, `t` switches between tokens and cost |
| Background panel | `Enter` expands or collapses a command's output, `x` stops it |
| Persona and preset picker for a new session | `e` edits the selected persona or preset; while this box is open, `Ctrl+C` and `Ctrl+D` quit the program |
| The `/files` page | `↑`, `↓` (`j`, `k`) switch files, `PgUp`, `PgDn`, Space scroll the diff, `Home`, `End` go to the start and end, `Esc` or `q` go back |

### Global

| Key | What it does |
|---|---|
| `Tab`, `Shift+Tab` | Switch between full access and read-only. While the command list or the `@` or `$` list is open, `Tab` goes to the list and `Shift+Tab` still switches. For permission levels, see [Permissions and sandbox](../permissions.md) |
| `↓` (input box empty) | Moves focus to the background button in the footer and the subagent status lines. Then move with `↑`, `↓`, `←`, `→`; `Enter` opens the background panel or switches into that subagent's session, `x` stops the selected subagent, `Esc` goes back to the input box |

### Vim key mode

After setting `tui.keys` to `vim` ("General → Interaction → Key mode" on the settings page, or choosing "Vim" in step 2 of first-run setup), these places use different keys:

| Where | Arrow keys (`arrows`, shipped) | Vim (`vim`) |
|---|---|---|
| Session list, model list, input history list, `/jump` | Type to search, `↑`, `↓` to choose | `j`, `k` to choose; `/` starts a search, and while searching `Ctrl+J`, `Ctrl+K` choose, `Enter` closes the search (the filter stays), `Esc` stops searching; when not searching, `Esc` first clears the remaining filter, and the next press closes |
| `@` file list, `$` skill list | `Esc` closes the list | `Esc` enters "pick in list": `j`, `k` choose, `h`, `l` move the cursor in the input box, `/` filters, `Enter` inserts, `Esc` again closes |

Keys elsewhere are the same in both modes.

### Input method

On Linux with fcitx5, when you press keys in a list that are not typing, such as `j` and `k`, Miyu first switches the input method to English and switches it back when you return to typing; it does not switch while the terminal is not in the foreground. If you do not want this, set `MIYU_TUI_IME=0` when opening it. Only fcitx5 is supported (fcitx in the environment variable `XMODIFIERS`, `GTK_IM_MODULE` or `QT_IM_MODULE`, switched with `fcitx5-remote`); input methods on macOS and Windows are not switched for you.

| Where | What you can do |
|---|---|
| Timeline | Click a section or step to expand or collapse it; drag to select text, which is copied when you release (the selection stays, and `Ctrl+C` copies it again); click links and paths to open them with the system's program; click a Mermaid diagram to open the large image in a program; the scroll wheel moves three lines per notch |
| The column to the right of the timeline | Hovering shows the scroll bar, which you can drag or click |
| Input box | Click to place the cursor, drag to select, double-click to select a word; click an attachment block or file block to open that file with the system's program |
| Queued messages | Click one to take it back into the input box |
| The message pinned at the top of the conversation | Click to jump back to that message |
| Footer | Click the usage cell to open `/context`; when the session is stuck, clicking "Compact" is the same as `/compact`; click the background button to open the background panel |
| Sidebar | Scroll with the wheel; drag to select text, `Ctrl+C` copies; for clicking the short id, recent sessions, jump-to messages and changed files, see the parts table above |
| Lists and boxes | Hover to select, click to run, scroll with the wheel |
| Approval and question boxes | Hover to select; a click is the same as `Enter` |

Links, paths and attachment blocks you click are handed to the system to open: `xdg-open` on Linux, `open` on macOS, `rundll32.exe url.dll,FileProtocolHandler` on Windows. Only `http`, `https`, `file` and existing local files are opened.

Files the AI shows you with `show`, and large Mermaid images, go first to the default program for that type of file, and to the browser if there is none:

| System | Default program | Browser |
|---|---|---|
| Linux | Asks `xdg-mime` for the default program for that type of file and starts it with `gio launch`; without `gio`, uses `gtk-launch`; failing that, `xdg-open` | `$BROWSER`; if not set, tries `firefox`, `chromium`, `chromium-browser`, `google-chrome`, `google-chrome-stable`, `brave-browser`, `microsoft-edge` in that order |
| macOS | `open` | `$BROWSER`, then `open -a Safari` |
| Windows | Handed to the system (`rundll32.exe`); it cannot tell whether a program can open it, so handing it over counts as opened | `$BROWSER` |

If nothing can open it, the card shows "No program can open it: …" and the file's path.

## Ways to write in the input box

| Form | What it does |
|---|---|
| `/command` | Typing `/` brings up the command list, filtered as you type |
| `@` | Refers to a file or folder: type `@` and a few characters to bring up the file list, `Tab` enters a folder, `Enter` turns it into a block. Type `/` to browse by folder |
| `$` | Names a skill: `$` plus a name brings up the skill list; you can name several in one message |
| `!` | Typing `!` as the first character enters command mode; the box says "Type a command to run", and Enter makes the core run that command directly, without going through the AI, for at most 120 seconds. Attachments are not allowed. With the box empty, `Backspace` or `Esc` goes back to normal |
| Dragging files into the terminal | If they are all existing local files and folders, images, PDFs, audio and video become attachments (`[image 1]`), anything else becomes a file block (`[name]`, `[folder/]`), and they are replaced with paths when sent |
| Pasting images | `Ctrl+V` (`Alt+V` in Windows Terminal) turns an image in the clipboard into an attachment; files copied in a file manager are treated like dragged-in files (not on macOS, see below) |
| Pasting long text | More than 10 lines or 800 characters becomes a block `[pasted N line(s)]`, replaced with the original text when sent |

Attachments are at most 20 MiB. If the current model cannot take that kind of attachment, it is sent as a path instead, with the hint "This model doesn't take …, sent as file paths". A message over 1 MB is sent as a text attachment.

Commands `Ctrl+V` uses to read the clipboard:

| System | Text | Images | Copied files |
|---|---|---|---|
| Linux | Under Wayland tries `wl-paste` first, then `xclip`, `xsel` | Under Wayland asks `wl-paste` if installed, otherwise `xclip` | Same as images |
| macOS | The built-in `pbpaste` | The built-in `osascript` | Not accepted: files copied in Finder cannot be taken in |
| Windows | Windows PowerShell (`powershell`) | Same as text | Same as text |

Each command waits at most 1 second; on Windows, where starting PowerShell is slow, at most 3 seconds. If none can read it, it shows "Can't read the clipboard: use your terminal's own paste (Ctrl+Shift+V in kitty)".

## Reading the timeline

- Each thing the AI does in a turn is one line: an icon, the tool name, short arguments. Commands, thoughts and edits have a few preview lines: while a thought is in progress, the latest `tui.timeline_thought_rows` (shipped `15`) lines scroll by, and command previews show `tui.timeline_preview_rows` (shipped `10`) lines. The kinds turned on in `tui.timeline_expand_thought`, `tui.timeline_expand_command` and `tui.timeline_expand_edit` show their full text by default.
- Click a step to expand it and see its output or the edit's diff; memory and knowledge base results open as individual entries. Click again to collapse.
- When a turn ends, its steps fold into one line, for example "Ran 2 commands · 3 thoughts · 48s", followed by lines added and removed if there were edits. Click it to expand. If you do not want folding, turn off `tui.timeline_fold`.
- At the end of a turn there is a closing line: time · provider/model · elapsed, followed by the speed, this turn's usage and the cache hit rate.
- Diffs: `/files` opens the "Changed files" page; one side lists the changed files (on the right in a wide window, at the top in a narrow one), and the other shows the full diff of the selected file.
- Local paths and URLs in replies are clickable and open with the program the system assigns to that type of file. Files the AI shows you with `show` are labeled with their kind and "Click to open".
- Images, block formulas and Mermaid diagrams are drawn as images in terminals that support an image protocol; click a Mermaid diagram to open the large image in a program; where the terminal cannot show them, the source is shown. `/images off` stops drawing them for this run.
- Subagents: one status line per subagent above the footer; `↓` selects one, `Enter` switches into its session.
- Background commands: "Background: N" in the middle of the footer; click it, or select it and press `Enter`, to open the background panel, where you see output and stop commands. When a command finishes, the timeline records a line "Background command done · …".
- Usage: the usage cell on the right of the footer shows the context ring, cumulative tokens (including subagents) and cost; the sidebar's "Context" and "Usage" give more detail. `/usage` shows usage on this machine by day and by model.
- Messages from elsewhere (other sessions, subagents, what you sent from another interface) are recorded as a line "Message from …".

## Appearance

### Colors

`/theme` opens the colors box; the interface changes to whichever one you move to, `Enter` writes it to `tui.theme`, and `Esc` changes back to the original.

| Option | Value | Where the colors come from |
|---|---|---|
| Auto | `auto` (shipped) | Checked in order: if the persona has an avatar or a theme color, follow the avatar; if a desktop wallpaper can be found, follow the wallpaper; if the terminal's colors can be queried, terminal colors; if none, Tokyo Night |
| Follow the avatar | `persona` | Generates a set from the main color of the avatar of the persona you are viewing; if the persona set its own main color, that is used. Not listed if the persona provides no color |
| Follow the wallpaper | `wallpaper` | First looks for the one generated by matugen; if there is none, takes the main color from the desktop wallpaper image. Follows automatically when you change the wallpaper. Not listed if no wallpaper can be found |
| Terminal colors | `terminal` | Follows the terminal's own colors. With true color and queryable terminal colors, picks a main color from the terminal's 16 colors to generate a set; otherwise uses the terminal's 16 colors directly. Does not paint the background |

Tokyo Night is only the fallback when "Auto" finds nothing; it is not listed in the colors box, but writing `tui.theme = "tokyonight"` by hand also works. The program comes with four color files: `tokyonight-night`, `tokyonight-day` (with their own colors), `terminal`, `terminal-light` (using the terminal's colors).

When follow the avatar, follow the wallpaper or terminal colors has several candidate main colors, pick one in "Appearance → Color scheme → Main color" on the settings page. A pick for follow the wallpaper or terminal colors is written to `tui.theme_seed`; a pick for follow the avatar is written back to that persona.

Light or dark (`tui.theme_mode`): auto follows the terminal's background, and counts as dark if it cannot be queried; or always dark, or always light.

Paint the background (`tui.theme_background`, on as shipped): the whole interface is painted in the scheme's background color. Terminal colors do not paint it, and the settings page does not list this item for them.

### Icons, theme, language

- `/icons` switches between Nerd Font icons and plain characters, for this run only. To keep it, set `tui.icons` ("Appearance → Icons" on the settings page).
- The theme (`tui.look`) controls borders, marks and text styling: unset is the default theme; `ascii` is the built-in plain ASCII one, which replaces the symbols and icons on screen with ASCII characters (Chinese characters and letters are unchanged), and the icons chosen with `tui.icons` or `/icons` are used again only after switching back to another theme; for another installed terminal theme package, write its id. How to install theme packages: [Packages](../packages.md).
- `/language`: the first line is "Auto (system: …)", followed by 中文, English and 日本語. Your choice is written to `ui.language`. After switching, newly drawn text uses the new language; what is already in the timeline does not change.

### Keys for appearance and behavior

All `tui.*` keys are in [Config key reference](../config-keys.md#terminal).

| Key | Default | Settings page | What it controls |
|---|---|---|---|
| `tui.theme` | `auto` | Appearance → Color scheme → Colors | Colors |
| `tui.theme_mode` | `auto` | Appearance → Color scheme → Light or dark | Light or dark |
| `tui.theme_background` | `true` | Appearance → Color scheme → Paint the background | Whether the background is painted |
| `tui.theme_seed` | — | Appearance → Color scheme → Main color | Main color for follow the wallpaper and terminal colors, `#rrggbb` |
| `tui.look` | — | Appearance → Theme | Theme package |
| `tui.icons` | `nerd` | Appearance → Icons | `nerd` or `plain` |
| `tui.mascot` | — | Appearance → Figure | Which mascot to use; unset is the built-in one |
| `tui.mascot_home` | `false` | Appearance → Figure | Shows the avatar or mascot above the input box in an empty session |
| `tui.mascot_sidebar` | `false` | Appearance → Figure | Shows the avatar or mascot at the top of the sidebar |
| `tui.keys` | `arrows` | General → Interaction | Key mode |
| `tui.skip_pick` | `false` | General → New sessions | New sessions use the default persona and preset without showing the picker |

| `tui.timeline_limit_live` | `true` | General → Timeline | Steps in progress show only their latest lines |

```sh
miyu config set tui.theme terminal
miyu config set tui.icons plain
```

Changes take effect at once.

## Settings page

`/settings` (`/config` is the same command) opens the full-screen settings page; `Esc` goes back one level at a time, and `Esc` on the main menu returns to the conversation. To open it directly without entering a session: `miyu tui config`.

| Page | What it controls |
|---|---|
| General | Display (Interface language, On start, open), New sessions (Default persona, Default preset, Start new sessions read-only, Don't ask for persona and preset in new sessions), Sessions, Shell integration session; the terminal's own timeline, interaction, sidebar counts and history list |
| Appearance | Theme, Color scheme, Figure, Icons |
| Providers & models | Three pages: Providers, Default models, Pools; see [Models](../models.md) |
| User | Profile: preferred name, reply language, additional details |
| Privacy & security | Permissions and protected commands; see [Permissions and sandbox](../permissions.md) |
| Personas | Create, edit and delete personas; see [Personas and presets](../personas-presets.md) |
| Presets | Create, edit and delete presets |
| MCP | Status of MCP servers, logging in and out. Listed only when there are servers |
| Packages | Three pages: Download, Installed, Backstage; press `Enter` on an installed package to open its own settings; see [Packages](../packages.md) |
| Advanced | Compaction, Core, Runtime log, and settings packages put on this page, such as skills and platform accounts |

On a page, `↑`, `↓` choose, `Enter` changes, `d` resets to default, `D` resets this group, `Esc` goes back. For long fields such as the persona prompt, `Enter` opens an editing window and `Ctrl+G` writes in an external editor (found the same way as `Ctrl+G` in the input box); on Windows there is no external editor option, so write in the editing window or paste into it.

## Shell integration

Once installed, you type a sentence after the shell prompt and press Enter, and that is talking to the AI. The reply is printed in the shell in the style of the timeline, without going full-screen.

### Installing and uninstalling

```sh
miyu shellhook install            # install for the shell you are using
miyu shellhook install --shell zsh
miyu shellhook status             # see which shells it is installed in
miyu shellhook doctor             # check the install, the connection to the core, terminal colors and the clipboard
miyu shellhook uninstall          # turn it off: remove it from the shell
```

`--shell` can be `fish`, `bash`, `zsh`, `pwsh` (PowerShell 7) or `powershell` (Windows' built-in 5.1). Without it, the shell is detected as follows on each system:

| System | How it is detected without `--shell` |
|---|---|
| Linux | From the parent process; if that is not recognized, from `SHELL` |
| macOS | From `SHELL` only |
| Windows | From `SHELL` if it is set; otherwise from the user module folders PowerShell adds to `PSModulePath`, which tell 5.1 and 7 apart |

If it cannot tell, it reports "Can't tell which shell this is: pass --shell fish, bash, zsh, pwsh or powershell". `--program <path>` is the program the shell calls; without it, the `miyu` next to this program is used.

Where it is installed:

| Shell | Written into |
|---|---|
| fish | `~/.config/fish/conf.d/miyu-shellhook.fish` (under `XDG_CONFIG_HOME` if that is set), the whole file |
| bash | A marked section in `~/.bashrc` |
| zsh | A marked section in `~/.zshrc` (under `ZDOTDIR` if that is set) |
| pwsh, powershell | Asks PowerShell for its own `$PROFILE.CurrentUserCurrentHost` and writes a marked section into that file. Requires PSReadLine |

Only one line is installed; the script is printed fresh each time the shell starts, so new shells use the new version automatically after you upgrade Miyu. Shells that are already open show "This terminal still has the old hook; reopen the terminal to use the new one". Installing again only replaces the existing section. A fish file not written by shellhook is left alone.

If PowerShell's execution policy is `Restricted` or `AllSigned`, PowerShell does not load the profile, and installing prints "PowerShell's execution policy is Restricted, so it won't load the profile and the hook has no effect: run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned in PowerShell, then open a new window" (with the actual policy). Run what it says:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### Using it

1. Open a new shell.
2. Type a sentence and press Enter. If the first word is an ordinary word and not any command, the line goes to the AI; if it is a command, it runs as usual. For multiple lines, it first checks whether the first command exists, and when it cannot tell, Miyu decides. When a command is not found, the line also goes to the AI.
3. Read the reply. When approval or an answer is needed, the same box as in full-screen pops up below the prompt. Press `Ctrl+C` to interrupt.

| Key | What it does |
|---|---|
| `Ctrl+J` | New line on the command line, for multi-line messages |
| `Ctrl+V` | Reads the clipboard: images and copied files become blocks (`[image 1]`), long text becomes `[pasted 14 line(s)]`. In PowerShell, `Alt+V` works too |

Slash commands can also be typed in the shell, or written as `miyu shellhook <name>` (for example `miyu shellhook model`). `/model`, `/theme`, `/effort`, `/sessions`, `/persona` and `/preset` open a box below the prompt to choose from; after `/model`, `/theme` and `/effort` you can also write the name directly. `/settings` opens the full-screen settings page. `/tui` opens this terminal's session in the full-screen interface. `/exit` and `/language` do nothing in the shell.

When background tasks the AI started finish, they are printed when you return to the prompt. If one finishes while the prompt is waiting for you to type: fish and zsh print it at once; bash waits for your next Enter, and PowerShell waits until the prompt is next drawn (Enter or `Ctrl+C`).

### Shell integration sessions

Each terminal window has its own session, called a shell integration session, marked "Shell" in the session list. Opening a terminal does not count; the session is created only when you actually say something. "General → Shell integration session" on the settings page has three items:

| Key | Default | What it controls |
|---|---|---|
| `terminal.persona` | Follows `persona.default` | Which persona a new shell integration session uses |
| `terminal.preset` | Follows `preset.default` | Which preset a new shell integration session uses |
| `terminal.idle_new_after` | `180` | After this many idle minutes since you last spoke, the next message starts a new session, with the hint "The last message was … ago: started a new session so an expired cache doesn't cost extra". `0` never starts a new one |

Typing `/persona` or `/preset` in the shell also changes these two items.

## Notifications

When the terminal is not in the foreground and a reply finishes, an error occurs, or it is waiting for your approval or answer, Miyu shows a notification and plays a sound. The notification title is the name of the session's persona, with its avatar if it has one. When another session finishes or another session is asking you something, it notifies even with the terminal in the foreground, without a sound.

| Where | How it notifies |
|---|---|
| kitty | kitty's own notification; clicking it jumps back to the window; kitty does not show it while the window is in the foreground |
| iTerm2, WezTerm, ghostty (detected by `TERM_PROGRAM` being `iTerm.app`, `WezTerm`, `ghostty`) | The terminal's own notification |
| Other terminals, inside tmux or herdr | System notification, see the table below |

System notifications and sounds use, on each platform:

| System | System notification | Sound |
|---|---|---|
| Linux | `notify-send` | Tries `pw-play`, `paplay`, `canberra-gtk-play`, `aplay` in that order |
| macOS | `osascript` | `afplay` |
| Windows | None: nothing is shown when it falls through to system notifications | There is no player program for Windows, so no sound |

On Windows, notifications can only be shown by terminals of the kind in the first two rows of the table above, which understand notification sequences themselves (for example WezTerm). Windows Terminal is not on that list, and Miyu sends it no notifications.

In herdr, herdr plays the sound. Notifications and sounds have no switch you can set.

## Multiple sessions

- Whether opening it starts a new session or continues the most recent one depends on "On start, open" (`ui.startup`); see [Sessions](../sessions.md).
- A new session starts by choosing a persona, then a preset; you can type only after choosing. If you do not want to choose each time, turn on `tui.skip_pick`.
- `/sessions` opens the session list, grouped into "Recent", "Past 7 days", "Past 30 days", "Older" and "Archived". Clicking a line in the sidebar's "Recent sessions" also switches.
- When another session is waiting for your approval or answer, no box pops up here; it shows the hint `"<title>" is asking you · /resume to switch`, that entry in the session list is marked "asking", and its sidebar line starts with a yellow `?`. The box pops up when you switch over.
- When a turn finishes in another session, a dot appears on its sidebar line and disappears when you switch over.

## Using it with herdr

When the terminal is open in a herdr pane:

- Miyu reports working, waiting for you and idle to herdr, which shows them in its sidebar.
- When you switch sessions, it automatically reports the resume command `miyu tui --resume <id>`. After herdr restarts, each pane reconnects to its own session. `/new` clears the old one. If you only close the herdr client, Miyu keeps running.
- The resume command requires the command name you typed to be found on PATH; if it is not, nothing is reported. Temporary environment variables written before the command (`MIYU_HOME=… miyu` in bash) are not saved by herdr; if you need them, write a launch script that fixes these variables and put it on PATH.

## Files in the cache

The terminal's crash records, drafts handed to the editor and the like are kept in the cache folder. The cache folder is shared by the whole machine and does not change with `MIYU_HOME`:

| System | Cache folder |
|---|---|
| Linux | `$XDG_CACHE_HOME/miyu` (`~/.cache/miyu` if `XDG_CACHE_HOME` is not set or not an absolute path) |
| macOS | `~/Library/Caches/Miyu` |
| Windows | `%LOCALAPPDATA%\Miyu\cache` |

What the terminal uses in it:

| Where | What it is |
|---|---|
| `tui/crash.log` | Crash records: time, version, error and stack trace, appended one after another |
| `tui/edit/` | Temporary files handed to the editor by `Ctrl+G` and when editing prompts |
| `tui/pasted/<pid>/` | Images pasted from the clipboard. Deleted when the interface exits; ones left by a crash are cleaned up the next time you open the terminal on Linux and macOS, but not on Windows, where you delete them by hand if you want |
| `tui/sounds/` | Notification sounds |

## When something goes wrong

| What you see | What to do |
|---|---|
| Icons are boxes or question marks | The font has no Nerd Font icons. Install a Nerd Font, or `miyu config set tui.icons plain` |
| Borders and spinners are garbled | `miyu config set tui.look ascii` switches to the plain ASCII theme |
| Colors look gray or wrong | Check whether `COLORTERM` and `TERM` identify true color; if not, set `MIYU_COLOR=truecolor`; or change colors and light or dark in "Appearance → Color scheme" on the settings page |
| Images and formulas show as source | The terminal does not support the kitty, sixel or iTerm2 image protocol; switch to one that does. Or you typed `/images off`; type `/images on` |
| `Shift+Enter` sent the message | The terminal cannot report `Shift+Enter`; use `Alt+Enter` or `Ctrl+J` for a new line |
| "Can't read the clipboard: use your terminal's own paste (Ctrl+Shift+V in kitty)" | Linux: install one of `wl-paste` (under Wayland), `xclip`, `xsel`; pasting images and copied files needs `wl-paste` or `xclip`. macOS: it reads with the built-in `pbpaste`; if that fails, use the terminal's own paste. Windows: it has to start Windows PowerShell (`powershell`); if reading takes more than 3 seconds it counts as failed; use the terminal's own paste |
| It shows "Copied … character(s)", but the clipboard is empty | The terminal does not support OSC 52, so nothing was copied. Switch to a terminal that supports OSC 52 |
| "The core isn't running: set MIYU_CORE_BIN to the remake's miyu when starting", "Can't connect to the core: …" | Open it with `miyu` or `miyu tui`, not by running `miyu-tui` directly; if that does not help, see [Troubleshooting](../troubleshooting.md#the-core-will-not-start-or-cannot-connect) |
| A sentence in the shell is sent twice | `miyu shellhook status` will say the old `conf.d/miyu.fish` is also there; delete it |
| The terminal crashed, showing "Stack trace saved to …" | The crash record is `tui/crash.log` in the cache folder; see "Files in the cache" above |

If you installed shell integration, run `miyu shellhook doctor` first; it tells you, item by item, what is wrong and how to fix it.
