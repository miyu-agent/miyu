# Web interface

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page explains how to use Miyu in a browser: what each part of the page is and what you can do with it. To deploy the web interface on a server or put it behind a reverse proxy, see [Keeping it running, and servers](../service.md).

## Opening the web interface

Run this in a terminal:

```sh
miyu web
```

The web interface is served by the program `miyu-web`, called the "web app" below. If the web app is not running, `miyu web` first starts it in the background (and starts the core too if the core is not running), then hands the page to the system browser. The terminal prints one line, `opened in browser: <url>`, and the command returns right away, so it does not hold the terminal. The web app keeps running after you close the browser, so a bookmarked address opens directly. The default address is `http://127.0.0.1:8300`.

The command used to hand the page to the browser is `xdg-open` on Linux, `open` on macOS, and `cmd /C start "" <url>` on Windows. If that command cannot start, or fails and exits within 3 seconds, the hand-off counts as failed, and the terminal prints `miyu: cannot open a browser; open the address above`. The address is still printed on the line above it.

`miyu web` accepts the following options:

| Option | What it does |
|---|---|
| `--port <port>` | The port to listen on this time. It only takes effect when the web app is not running. The shipped value is `8300`. |
| `--print` | Prints the address without opening a browser. |
| `--format <text\|json>` | The output format; `json` also does not open a browser. |
| `--reset` | Opens the web interface with a one-time code so you can reset the access password. |
| `--logout` | Makes every browser sign in again. |
| `--package <id>` | Opens this package's page under `Dashboards` directly. |
| `--session <id>` | Opens this session directly. |
| `--settings [<page>]` | Opens the settings page directly; `access` opens `Access` under `General`. |
| `-h`, `--help` | Prints help. |

There are a few other ways to open the web interface:

- If the system tray is installed, click `Open Web Interface` in the tray menu. On Linux and Windows, a left click on the tray icon also opens it. For details, see [System tray](applet.md).
- If the browser's address bar offers `Install`, you can install the web interface as its own window, named Miyu.

Ports work like this:

- If you have never set a port and 8300 is taken, the web app tries 8301 to 8309 in turn and uses the first free one. If all of them are taken, or the port you set is taken, it reports `port 8300 is in use`; in that case, pick another port with `--port`.
- To fix the port, set `web.port`; to change the listen address, set `web.listen`. For details, see "Access and security" below.

Once started, the web app keeps running and does not exit when nobody uses it. If you want to save resources, you can set `web.idle_seconds`: when no browser is connected and it is not serving files such as images or videos for that many seconds in a row, the web app exits on its own, and the next `miyu web` starts it again. The shipped value is `0`, which means it never exits; it also does not exit while LAN access is on. The settings page does not show this item, so you need to change it with a command, for example:

```sh
miyu config set web.idle_seconds 600
```

If you want to close only the web interface and keep the core running, run `miyu web stop`. To see whether the web interface is running and at which address, run `miyu web status`. Neither command connects to the core; for details, see [command line reference](../cli.md#miyu-web). If the web app runs in the foreground (for example `miyu-web serve` started on a server as described in [Keeping it running, and servers](../service.md)), press `Ctrl+C` to stop it; on Linux and macOS it also stops when it receives `SIGTERM`.

### Using it on phones and other devices

After you turn on LAN access (see "Access and security"), a phone or tablet can open the web interface at this computer's address; sign in with the access password and you are in. When the window is narrower than 836 pixels, the page switches to its narrow layout:

- The left column folds away, and a menu button `Expand sidebar` sits in the top left corner. Tap it and the column slides in from the left; swipe left to fold it again.
- The right sidebar covers the conversation, with a close button at the top; swipe right to fold it.
- Buttons that normally appear only on hover (copy and edit under your messages, copy and redo at the end of a turn, multi-select in the left column) are always visible.
- On a page opened over plain `http` on the LAN, the browser gives no clipboard access, and a failed copy shows `Can’t copy here. Select the text and copy it manually.`

## First run

The first time you open the web interface, first-run setup covers the whole page, one step per screen. The row of small boxes at the top is the step bar. Press `Enter` to go to the next step, click `Back` to go back, and use the top right corner to switch between light and dark.

1. Welcome: the page shows `Miyu`. Click `Start`.
2. Interface language: choose 中文, English, 日本語, or `Follow system`.
3. Model: in `Select a model provider`, pick a provider, fill in the key, click `Test connection`, then pick the default model. For how to fill these in, see [Models](../models.md).
4. Persona: in `Create persona`, fill in the name, avatar and detailed prompt. You can click `Skip` here; if you skip, no persona is used.
5. Appearance: in `Appearance`, choose light or dark, the main color, the color scheme and the theme. If you skipped the persona in the previous step, this step is skipped too.
6. About you: in `How the AI knows you`, fill in `Preferred name` and `Additional details (optional)`; above them is a `Reply language (optional)` row. If both are empty, the button reads `Skip`.
7. Preset: in `Select preset`, click a preset; choose `Custom` to tick the features yourself.
8. Semantic model: in `Turn on the built-in semantic model?`, choosing `Yes (recommended)` downloads and installs the semantic model, and choosing `No` uses keyword search only. If the package source does not have this package and it is not installed, this step is absent.
9. Other devices: in `Use on other devices`, choosing `Open` first asks you to set an access password; once it is set, the page shows the address and QR code for other devices. Choosing `Don't open` means only this computer can open the web interface. If the page was not opened through `miyu web`, this step is absent.
10. Done: the page lists the chosen model, persona and preset. Click `▶ Start chatting` to enter a new session.

If you sign in from another device and are setting the access password for the first time, the first step is `Password`, and setup then continues from the interface language.

When you finish setup, it writes `ui.welcomed = true`, and neither the terminal interface nor the web interface shows first-run setup again. Changing the interface language reloads the page and continues from that step; if you close the page midway, setup starts over next time. To go through it again, run:

```sh
miyu config set ui.welcomed false
```

Then reload the page. You can change the persona, preset and appearance later on the settings page.

## Page layout

On a wide screen the page has three columns: the left column, the conversation area and the right column.

### Left column

From top to bottom, the left column holds:

- Avatar and name: the persona of the session you are viewing, with `Online`, `Connecting` or `Offline` under the name. Click the avatar to open this persona's edit card.
- Three rows: `New session`, `All sessions`, `Projects`. If a package adds an entry, a `More` row appears below them; click it for a pop-up menu.
- Three sections: `Pinned`, `Projects`, `Sessions`. Click a section header to fold or unfold it. `Sessions` is grouped by time: Recent, Past 7 days, Past 30 days, Older. Sessions opened by shell integration form their own group, `Terminal integration`, and imported archives form their own group, `Archived`. The section lists at most 20 sessions; click `View all` below it to go to the all-sessions page.
- The bottom row: the gear opens Settings, and the button next to it switches between light and dark.

Each session takes one row, and the mark on the left shows its current state: a running session shows a spinner; there are also two states, `Waiting for you` and `Interrupted, waiting for input`; and a session with unread content shows a dot. Subagent sessions hang under the session that dispatched them, and finished subagent sessions fold into `N done`.

When you hover over a row, `⋮` appears on the right. Its menu has: Pin (or Unpin), Move to project, Remove from project (only for sessions in a project), Copy session ID, Rename, Export…, Delete. Clicking Delete deletes the session at once, without asking again.

- Multi-select: hover over the `Sessions` header to reveal the multi-select button. Click it and each row gets a checkbox in front; `Shift`-click selects a range, and the header changes to `N selected` with select all, delete and exit buttons. Press `Esc` to leave multi-select.
- Drag: drag a session onto the `Pinned` section to pin it, drag it back down to unpin it, or drag it onto a project to move it in. Press `Esc` while dragging to cancel.
- Width: drag the right edge of the left column to change its width, and double-click to restore the shipped width. This device remembers the width.
- Fold: the button in the top left corner folds and unfolds the left column. Once it is folded, move the pointer to the left edge of the window and the column floats out.

### Conversation area

- The top left shows the session title; for a session in a project, the project name comes in front of it. Click the title for a card listing the session ID (click to copy), persona, preset and workspace. Click the persona or preset row to switch; it asks you first, and compacts the context before switching. The pen on the persona row opens the persona's edit card, and clicking the workspace row changes the working directory.
- For a subagent session, the levels above it are listed in front of the title; click one to go to that level. Right above the input box, `Back to “…”` takes you back to the session that dispatched it.
- The middle holds the timeline; for details, see "Timeline" below. After you scroll up, `Jump to bottom` appears at the bottom.
- A jump bar runs along the right side of the conversation area, with a short dash for each message you sent. Move the pointer close to it to list every message, and click one to scroll to it.
- The top right corner holds the right column's toggle, `Expand right sidebar`.
- Both side edges of the conversation column can be dragged to change its width; double-click to restore the shipped width.

In an empty session (before you send the first message), three buttons sit above the input box: `Select persona`, `Select preset` and `Set workspace`. If you do not click them, the defaults are used. If the default preset or persona cannot be used, the input box is locked and says `Select a preset` or `Select a persona`, and you can type only after choosing one.

When you choose a working directory (for example `Set workspace`, or a project's `Workspace folder`), the web interface opens the system's folder picker on this computer, one at a time:

| System | The picker it uses |
|---|---|
| Linux | It tries `zenity`, then `kdialog`; if neither is installed, or neither can reach the display, it falls back to a folder browser drawn by the page. |
| macOS | The folder picker of `osascript`; if that fails, it falls back to a folder browser drawn by the page. |
| Windows | The PowerShell folder picker, which shows on top of other windows. |

### Right column

Click the toggle in the top right corner to open the right sidebar, which is a stack of cards:

| Card | What it lists | Clicking does |
|---|---|---|
| To-do | The AI's to-do items, with the finished ones folded into `N done`. | |
| Background tasks | This session's background commands and subagents, with the subagents they dispatch nested below; it has `Stop` and `Stop all` buttons. | For background commands, `View output`; for subagents, it opens their session in the main area. |
| File changes | The files this session changed; you can search them. | Shows the diff of this change; switch with `Previous file` and `Next file`, and enlarge it with `Open large view`. |
| Shown files | Files the AI showed you with `show`. | Opens the file in the right column (the preview panel). |
| Scheduled tasks | The scheduled tasks attached to this session. | |

When the window is not wide enough, the right column covers the conversation; click outside it or press `Esc` to fold it. You set the order of the cards, whether each one is on, and how many rows each shows at most on the settings page, under `Packages`, in the `Web` section, in `Right sidebar`. The left edge of the right column can be dragged to change its width.

The preview panel is where the right column shows files. Its top row has:

- A `Preview` / `Source` switch (shown only when the file has both).
- The title; click it to list every file shown so far.
- Copy, download, maximize and close buttons. If you came in from the right sidebar, the top left corner is a back button.

Markdown is laid out the same way as answers; code gets line numbers and syntax highlighting; HTML runs directly in an isolated frame without network access; images can be zoomed with the scroll wheel and dragged; PDFs use the browser's own viewer. If an extension with UI blocks is installed, two tabs appear at the top, `Workspace` and `Panel`, and the panel holds what extensions put there.

After you turn off the right sidebar under `Packages` on the settings page, the top right corner shows a toggle for the `Preview panel` instead, and the button gets a dot when a new shown file arrives.

## Input box

You can use the following keys in the input box:

| Key | What it does |
|---|---|
| `Enter` | Sends the message. It also works while the AI is answering: the message queues, and you can `Withdraw` it from the status line. |
| `Shift+Enter`, `Ctrl+J` | Starts a new line. |
| `Esc` twice (within 1.5 seconds) | Interrupts the AI while it is answering. When idle, it clears the input box, and pressing `↑` while the box is empty brings the text back. In a memory-tidying session it stops the tidying. |
| `↑`, `↓` | Browses the messages you sent. |
| `Ctrl+R` | Opens the input history list, which you can search; in the list, `Tab` shows the full text and `Enter` puts it in the input box. |
| `Ctrl+S` | Stashes the message in the box; press it again with the box empty to take it back. On a Mac it is also `Ctrl+S`, and `⌘S` does not work. |
| `Tab`, `Shift+Tab` | Switches the permission level. While the command, `@` or `$` list is open, `Tab` goes to the list. |
| `/` | When focus is not in any input box, puts focus back in the input box. |
| `Backspace` | With the cursor at the very start, removes the last attachment. |
| `Ctrl+,` (`⌘,` on a Mac) | Opens Settings. |

The command, file, skill, session and history lists all work the same way: press `↑` `↓` to move, `Enter` to choose and `Esc` to close.

Whether `Ctrl+,` or `⌘,` applies depends on the device that opened the web interface: browsers on a Mac, iPhone or iPad use `⌘,`, and other devices use `Ctrl+,`. In forms on a package's full page, both `Ctrl+S` and `⌘S` save.

### Slash commands

Type `/` in the input box to pop up the command list. The list filters as you type; press `Tab` to complete and `Enter` to run. The most used commands are:

| Command | What it does |
|---|---|
| `/new` | Creates a new session. |
| `/sessions` | Opens the session list, optionally with a search term. |
| `/stop` | Interrupts this turn and stops this session's background commands, subagents and loop. |
| `/undo` | Undoes the last turn. |
| `/redo` | Drops the last turn and runs the same message again. |
| `/compact` | Compacts the context now. |
| `/model` | Changes this session's model. |
| `/persona`, `/preset` | Changes the persona or preset. |
| `/workspace` | Changes the working directory. |
| `/settings` | Opens the settings page. |
| `/help` | Shows the keys and all commands. |

For all commands, see [Slash commands](../commands.md).

### @ files and $ skills

In the input box you can refer to files with `@` and pick skills with `$`:

- Type `@` to pop up a file list, searched from the session's working directory. Press `Tab` to enter a folder and `Enter` to choose. Images and the like become attachments; other files become a `[file name]` block in the box, which is replaced by the path when you send. Backspace deletes the whole block.
- Type `$` to pop up the skill list. The skills you choose go to the AI together with this message, and one message can pick several.

### Attachments

- You can drag files into the window, paste into the input box, or choose them with `@`. On touch devices, the input box has a paper-clip button, `Add attachment`.
- You can add at most 10 attachments at a time; each can be at most 20 MiB, and images at most 5 MiB and no more than 8000 pixels per side.
- If a file is over the limits, the web interface looks for the original file on this computer. If it finds it, it hands only the path to the AI, and the card in the box is marked `Path`; if not, the card is marked `Not found`, and you can click it to fill in the full path.
- The original file is identified by name, size and modification time. The search goes first through the session's workspace, then through Downloads, Desktop, Documents, Videos, Pictures and Music under your home folder, and finally through the whole home folder. It skips folders starting with a dot, `node_modules`, `target`, the macOS Library and the Windows `AppData`, and searches until the time limit. On Linux with `plocate` installed, and on macOS, it first asks the system's existing index (`plocate`, Spotlight), which answers at once and also finds files on external drives. Windows has no index to ask, so it can only search folder by folder; a file it cannot find is `Not found`.
- Files inside the data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`) cannot be attachments.

For details, see [Sessions](../sessions.md#giving-the-ai-files-and-images).

### The row under the input box

The row under the input box holds the following:

| Position | What it is | Clicking does |
|---|---|---|
| Left | The permission level, shown as `⏵⏵ Full access` or `⏸ Read-only`. | Switches to the other level; for details, see [Permissions and sandbox](../permissions.md). |
| Left | The model name. | Opens the model menu, which has two pages, `Models` and `Model pools`; press `Tab` to switch pages. For a model with thinking levels, pointing at it expands `Thinking effort` to the right. |
| Middle | `Background tasks: N`, shown only while something is running. | Lists the background commands and subagents, which you can stop. |
| Right | A ring, the total tokens (cache hit rate in brackets) and the cost. | Opens a popover in three parts: context, total usage and cost. |

The ring shows how much of the window the context fills. While compacting, after a failed compaction, or when the context is over the window, this cell turns red and says `Compacting context`, `Context compaction failed` or `Context exceeds the window`. Extensions' UI blocks may also sit on the right.

There is also a row above the input box: on the left is the run status line (what the AI is doing, how long it has taken, and retries), and on the right are the goal and the next loop time. To-dos sit above this row.

## Timeline

The timeline is the part in the middle of the conversation area that shows the conversation. Your messages are right-aligned bubbles. Each AI turn is one block: the persona's avatar and name at the top, then the process, the answer and the closing line, in that order.

- Process: one line per step. Thinking shows `Thinking` or `Thought`, and each tool gets a line with an icon. The turn in progress stays expanded; when it is done it folds into a one-line summary, which you can click to see each step.
- Click a step to expand its details: the arguments and the result. Commands show the command itself and its output; file edits show the diff, with additions and deletions in different colors. For a file that is too large or not text, it shows `File too large, diff not shown` or `Not a text file, diff not shown`.
- When a script called tools, that step shows `Tools called by the script · N` below it; click it to see each call.
- Subagents: the step that dispatched one has a robot icon. When the subagent hands back its report, the timeline records a line `Subagent submitted its report · <title>`; click it to read the report. A finished background command also records a line; click it to see the command and its output.
- Compacting and clearing the context each record a line: `Context compacted` and `Context cleared`.

How answers are shown:

- Markdown layout: headings, lists, tables, formulas and footnotes. Code blocks get syntax highlighting, with `Copy code` in the top right corner.
- mermaid code is drawn as a diagram.
- Image, video and audio addresses on a line of their own in an answer are shown as cards. Click an image to enlarge it; below it are download, copy image, open in the right column (only for images the AI has shown) and open in a new tab.
- Web links on a line of their own are shown as link cards, at most three per answer.

Buttons on the timeline:

- Your messages: when you hover, `Copy` and `Edit` appear below. Edit lets you change the text right in the bubble; `Enter` sends and `Esc` cancels, and the turn runs again with the new text.
- An AI turn: the closing line shows the time, endpoint/model, duration, usage and output speed, followed by `Copy` and `Redo`.
- Edit and redo exist only on the latest turn, and not while the AI is answering.

### Confirmations and questions

When the AI needs you to confirm something or asks you a question, the whole input box turns into a drawer. What you have already typed in the box is kept and comes back once you answer.

Confirmation: the first line says what the AI wants to do (for example `Run command`, `Write N file(s)`, `Install or remove a package`), and protected commands are marked `Dangerous command`. Below are two choices:

1. `Allow once`
2. `Don't allow`: you can write a sentence under `Reason (optional)`, and the AI sees it.

Press `↑` `↓` to choose and `Enter` to confirm. If there is a timeout, it shows `Auto-deny in …`.

Questions: the title is `… is asking`, with one question per page; press `←` `→` to switch questions. A single-choice question is answered as soon as you choose; for a question that allows several choices, press `Space` to tick. Choose `Type another answer` to write your own, and press `N` to add `Notes`. The last page is `Review`, where pressing `Enter` does `Submit`.

Pressing `Esc` twice or clicking `Cancel` closes the drawer and interrupts this turn. What you have already answered stays on the timeline.

## Projects

A project groups sessions together and gives the new sessions in the group a preset working directory, persona, preset and a piece of extra prompt. Only the web interface has projects.

### Creating a project

1. Click the `+` on the `Projects` header in the left column (or click the last card, `New project`, on the `Projects` page of all sessions).
2. In `New project`, fill in the following:

   | Field | Notes |
   |---|---|
   | Name | Required, at most 40 characters. |
   | Description | At most 80 characters, shown on the project card. |
   | Color | Pick one of twelve colors, or click `+` to choose your own. |
   | Workspace folder | Sessions created in the project work in this folder; if you do not choose one, it is `Default workspace`. |
   | Persona, Preset | Choosing `Default` uses the default from Settings. |
   | Extra instructions | Every session in this project gets these instructions, at most 8000 characters. |
   | Messages | The switch `Can message sessions outside the project`, off by default. |

3. Click `Create`.

### Sessions in a project

- New: hover over the project row to reveal `⋯`, then click `New session in project`; or open the project page and click `New in project`. The new session uses the project's workspace, persona and preset, and the top left reads `<project name> / New session`.
- Putting an existing session in: drag it onto the project in the left column, or click `⋮` → `Move to project`. Taking it out: click `⋮` → `Remove from project`, or drag it back down among the sessions. Only main sessions you opened on this computer can go into a project; subagent sessions and chat-platform sessions cannot.
- A session moved into a project keeps its persona, preset and working directory. The extra instructions follow whichever project the session is in now and are added at the start of each turn; once the session is moved out, they are no longer added.
- Typing `/persona` or `/preset` in a session in a project shows `This session is in a project; the project sets its persona and preset`.
- While messages are off, sessions in a project can only see and message sessions in the same project. Once it is on, they can also message sessions outside the project.

In the left column each project takes one row; click it to expand all its sessions in place. While a project is folded and has running sessions inside, it shows `(N)` in front of its name.

### Changing and deleting

- Change: click `⋯` on the project row → `Project settings`, or click `Project settings` in the top right corner of the project page. The form is the same as when creating; click `Save` when you are done.
- Delete: click `⋯` → `Delete project`, then click `Delete`; or click `Delete project` twice in the bottom left of `Project settings`. The sessions in the project are deleted with it and cannot be recovered.

Project page (click `Projects` in the left column, then a project card): `‹ All projects` at the top takes you back; below it are the title and description, then a block `Defaults for new sessions in this project` listing the workspace folder, persona, preset, extra instructions and messages, and below that the sessions in the project.

## All sessions

Click `All sessions` or `View all` in the left column to open the all-sessions page, which takes the place of the conversation area. If the core supports projects, the top has two pages, `Sessions` and `Projects`.

The `Sessions` page has:

- At the top: search, `Select`, `New session` and `Import session…`.
- Filters: `All`, `Running`, `Unread`. On the right is `Recent activity`; click it to switch to `Date created`.
- The list is grouped by time. Sessions in projects are not listed here; open the project page to see them.
- Multi-select works the same way as in the left column: tick, `Shift` for a range, select all and delete.
- Click `Import session…` to choose an exported `.zip`; imported sessions go into the last group, `Archived`. Archives are read-only, and opening one shows `This is an archive. You can read it but not continue it`. For how to export, see [Sessions](../sessions.md).

Press `Esc` to close this page.

You can open it with the gear at the bottom of the left column, with `/settings`, or with `Ctrl+,`. `/config` goes straight to `Models`, `/pkg` to `Packages`, and `/market` to `Get software`. You can search the settings at the top. Each change is saved as soon as you make it.

| Page | What it covers |
|---|---|
| General | Appearance (theme and color scheme; see "Appearance" below); Display, New sessions, Sessions, Commands, Shell integration session; `Access`. |
| User | Avatar; `Profile`: preferred name and additional details. |
| Privacy & security | Permissions and protected commands; for details, see [Permissions and sandbox](../permissions.md). |
| Models | Three tabs, `Providers`, `Default models` and `Model pools`; for details, see [Models](../models.md). |
| Usage | Usage and cost, by day, by model, by session or by use, for today, 7 days, 30 days, all time or a custom range. |
| Presets, Personas | Create, change and delete presets and personas; for details, see [Personas and presets](../personas-presets.md). |
| Memory | View, change and tidy what the AI remembers; for details, see [Memory](../memory.md). |
| Knowledge | Search, read the original, add documents and attach folders; for details, see [Knowledge base](../knowledge.md). |
| Scheduled tasks | View, create, stop and delete scheduled tasks; for details, see [Letting the AI keep working on its own](../automation.md). |
| Skills, Scripts, MCP | Lists the installed skills, scripts and MCP servers; on the MCP page you can `Add server`. `Open folder` on the skill and script pages opens that folder in this computer's file manager: Linux uses `xdg-open`, macOS uses `open -R` (selecting it in Finder), and Windows uses `explorer`; if the folder cannot be opened, the path is copied instead. |
| Get software | Packages in the package source, which you can search, install and upgrade; for details, see [Packages](../packages.md). |
| Packages | Installed packages, one switch per row; the last section, `Web`, holds the web interface's own components. |
| Dashboards | Software with its own page; click one to open that page. |
| Advanced | Compaction, core, runtime log, model catalog, cooldown, package source and the like, one group per row; click in to change them. |

The last section of `Packages` on the settings page, `Web`, lists the web interface's own components, for example `Right sidebar`, `Notifications`, `Jump bar on the right` and `mermaid diagrams`. Each has a switch, and those with settings can be clicked into. These switches are remembered only in this browser on this device.

## Appearance

The appearance settings sit at the top of `General` on the settings page, in two groups:

- Theme: the `Mascot` row picks `None`, `Deniro`, or a mascot that comes with an appearance package. When other themes are installed, an extra `Theme` row appears, a drop-down for shapes and materials (rounded corners, shadows, borders, fonts); the shipped one is `Default theme`. When another timeline or answer style is turned on, an extra `Output style` row appears.
- Color scheme: `Mode` picks `Follow system`, `Light` or `Dark`; below it, each card is one color scheme; `Main color` picks from candidate colors.

The shipped color schemes are:

| Color scheme | Where the colors come from |
|---|---|
| Automatic (shipped) | If the session's persona has a main color, that color is used; if not, the desktop wallpaper; if neither, the default colors. |
| Follow persona | The persona's chosen main color; if it has none, colors picked from its avatar. |
| Follow wallpaper | This computer's desktop wallpaper, changing on the spot when you change the wallpaper. It is not available when the page is opened on another device. |

The button at the bottom of the left column also switches between light and dark.

`Follow wallpaper` first looks for the colors generated by matugen (on Linux `$XDG_CACHE_HOME/miyu/matugen.json`, or `~/.cache/miyu/matugen.json` if that variable is not set; on macOS `~/Library/Caches/miyu/matugen.json`; on Windows `%LOCALAPPDATA%\miyu\matugen.json`). If there are none, it looks for the wallpaper image on this computer's desktop:

| System | Where it reads the wallpaper |
|---|---|
| Linux | The desktop settings of KDE, GNOME, XFCE, Cinnamon and MATE (recognized by `XDG_CURRENT_DESKTOP`; Unity, Budgie and Pantheon are read the GNOME way); awww, swww, hyprpaper (under Hyprland), swaybg, wpaperd and waypaper; under X11, also feh and nitrogen. |
| macOS | The file where the system stores the wallpaper setting. If that cannot be read, it asks System Events, which pops up a dialog the first time asking whether to allow it; if you do not allow it, the wallpaper cannot be read. HEIC wallpapers are converted to JPEG with the system's `sips`. |
| Windows | `WallPaper` under the registry key `HKCU\Control Panel\Desktop`. If that cannot be read (for example with a slideshow), the copy Windows converted, `%APPDATA%\Microsoft\Windows\Themes\TranscodedWallpaper`, is used. |

Video wallpapers cannot be read. To keep up with wallpaper changes, follow wallpaper watches the wallpaper image and the settings files and picks colors again on any change (Linux uses inotify, macOS FSEvents, Windows ReadDirectoryChangesW). Programs such as hyprpaper and swaybg that change the wallpaper only through commands and write no file cannot be watched, and neither can a switch to another wallpaper program; in both cases it looks again when the browser window regains focus.

The background image can follow the persona: choose an image under `Background` in the persona's edit card, and the conversation area of sessions using this persona shows it.

The only shipped theme is `Default theme`. A `Pixel` theme also comes along, off by default; turn it on in the `Web` section of `Packages` on the settings page, then choose it under `Theme`. The package source has community-made web appearance packages (their names start with `webui-theme-`); once installed, they appear under `Theme` and `Color scheme`. For how to install them, see [Packages](../packages.md). After you install or remove an appearance package, the page says `Appearance "…" changed. Reload the page to apply it.`

`/gallery` opens the skin gallery: a session that exists only on this page, with every kind of element laid out, so you can check against it when you change themes.

## Access and security

Pages opened on this computer with `miyu web`, or by opening `http://127.0.0.1:<port>` directly, need no password. Access from another device needs the access password.

The access settings are in the `Access` card at the very bottom of `General` on the settings page (`miyu web --settings access` goes straight there):

- The `Local network access` switch, with `On` or `This computer only` next to it. If you turn it on before setting an access password, `Set an access password` pops up first; set the password and click `Set and turn on`.
- While the switch is on, there are a few more rows below it:
  - `Listen address and port`: `0.0.0.0` means every address of this computer, and you can also enter just one of them. The port is used both on this computer and on the LAN. When you change it, the web interface moves over on the spot; when the port changes, it says `The port is now …; this page stays connected`.
  - `Access password`: click `Set` or `Change`. Changing it from another device first asks for the `Current access password`.
  - `On another device, open`: a QR code and address, with a `Copy` button; if other network cards have addresses too, click `More addresses`. Scan the code with a phone and enter the access password to get in. If other devices cannot connect on macOS, follow the hint and allow incoming connections for `miyu-web` in `System Settings → Network → Firewall → Options`.

LAN access is plain HTTP; turn it on only on networks you trust. If you turn off LAN access from another device, that device disconnects at once.

The sign-in page on other devices is `Sign in to Miyu`: enter the access password. If you tick `Stay signed in`, this browser does not need the password again for 30 days; if you do not, you need to enter it again after closing the tab. If you forget the access password, run `miyu web --reset` on the computer where Miyu is installed; to make every browser sign in again, run `miyu web --logout`.

The following work only on the computer where Miyu is installed, and are not available on other devices:

- Choosing files with `@`, and choosing a working directory for a session or project.
- Buttons that open a folder, which copy the path instead on other devices.
- The `Follow wallpaper` color scheme.
- Files over the attachment limits that are handed over as paths only.
- Attaching folders to the knowledge base, and adding MCP servers that run local commands.

`LAN Access` and `Open on Your Phone…` in the system tray menu do the same thing; for details, see [System tray](applet.md). For the config keys for the listen address and port, and the limits of SSH port forwarding and reverse proxies, see [Keeping it running, and servers](../service.md#opening-the-web-ui-from-other-computers-and-phones).

## Notifications

When the AI finishes a turn, a question is waiting for your answer, or something needs your confirmation, the browser shows a system notification:

- For the session you are viewing, a notification appears only when this tab is not in the foreground; for other sessions it also appears in the foreground, but silently.
- The title is the name of the session's persona, or `Miyu` if there is no persona; the body is `<session title> · Done`, `… · Waiting for your answer` or `… · Waiting for your approval`. Click the notification to go back to that session.
- When a scheduled task that opens a new session each time finishes, it shows `Scheduled task finished` or `Scheduled task didn't finish`.
- Subagent sessions and one-off sessions do not show notifications.
- While the system tray is running, the tray shows notifications for sessions not open in the web interface, and the web interface shows them only for sessions open in this tab.

The first time you send a message in the input box, the browser asks once whether to allow notifications. If you do not want notifications, deny them in the browser, or turn off `Notifications` in the `Web` section of `Packages` on the settings page. After the tab is closed, the web interface no longer shows notifications; to keep receiving them, install the system tray.

## What packages add to the web interface

Packages can add a few things to the web interface. They appear once the package is installed and enabled, and go away when it is disabled:

- Dashboard pages: a full page of the package's own, listed under `Dashboards` on the settings page; click it to open it. A narrow bar runs along the top of the page with `Back` on the left. The address carries `#package=<id>`, so you can bookmark it or open it in a new tab. Running `miyu web --package <id>` opens it directly.
- UI blocks: a small piece of text and buttons placed by an extension (for example weather or build status), shown on the start page of a new session, in the right column's `Panel`, on the right of the row under the input box, or as a page of its own. When the extension's program is not running, it shows `Not running`.
- Appearance: themes, color schemes and mascots; for details, see "Appearance" above.

For how to make these, see [Putting things on the interface](../../dev/ui-surfaces.md).

## Troubleshooting

| What you see | What to do |
|---|---|
| `port 8300 is in use` | Pick another port with `miyu web --port <port>`, or change `web.port`. |
| `miyu: cannot open a browser; open the address above` | Open the printed address yourself; on a machine without a desktop, use `miyu web --print`. On Linux the hand-off to the browser relies on `xdg-open`; if it is missing, install it. |
| `Can't reach the web app`, `The web app isn't running.` | The web app is not running (it was stopped with `miyu web stop` or the tray's `Stop`, the computer restarted, or `web.idle_seconds` is set and it exited after idling). Run `miyu web` in a terminal. |
| `Still connecting. …` | If this device uses a proxy or VPN, turn it off, or let this address connect directly. |
| `Core is outdated` | Upgrade the core, then reload the page. |
| `Wrong access password` | Enter it again; if you forgot it, run `miyu web --reset` on the computer where Miyu is installed. |
| `Too many attempts. Try again in N s` | Wait the number of seconds it says, then try again. |
| `No access password yet` | Set it with `miyu web --settings access` on the computer where Miyu is installed, then sign in here. |
| `This link was already used or has expired: run miyu web in the terminal again` | Do what it says; a link with a ticket is valid for 60 seconds and works only once. |
| `Your sign-in expired. Enter the access password again` | Enter the access password again. |
| `No password is needed on this computer, but the core couldn't be reached this time…` | Run `miyu web` in a terminal to see why. |
| `Appearance "…" changed. Reload the page to apply it.` | Reload the page. |
| `Can’t copy here. Select the text and copy it manually.` | Pages opened over plain `http` on the LAN get no clipboard; long-press to select the text, then copy it. |

The web interface's log is at `~/.miyu/var/log/webui/web.log`. For other problems, see [Troubleshooting](../troubleshooting.md#the-web-ui-will-not-open).
