# System tray

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

The system tray is a Miyu icon shown in your system's tray area (in the menu bar on macOS); the program is called `miyu-applet`. It shows whether the core is running, starts and stops the core, and opens the web interface in your browser; even when the browser is closed, it shows notifications such as `Done` and `Waiting for your approval`. The system tray has no window of its own, and all chatting happens in the web interface; for details, see [Web interface](web.md).

## Installing and opening

The system tray comes in two kinds of package: the full installer bundles the core, the web interface and the system tray (without the terminal interface) and works as soon as it is installed; the tray-only package needs the core and the web interface installed separately. The packages available on each system are:

| System | Full installer | Tray only |
|---|---|---|
| Linux x86_64 | `.deb`, `.rpm` | `miyu-applet` on the AUR; `miyu-applet-<version>-linux-x86_64.tar.gz` on the system tray's releases page |
| Linux aarch64 | None | `miyu-applet` on the AUR; `miyu-applet-<version>-linux-aarch64.tar.gz` |
| macOS Apple silicon | `.dmg` | The Homebrew cask `miyu-applet` |
| Windows x86_64 | `.msi` | None |

For how to install, see [Installing, upgrading and uninstalling](../install.md).

Open `Miyu` from the application menu. Once the system tray is up, it does two things:

- It opens the web interface's home page in your browser, starting the web interface and the core too if they are not running.
- It stays in the tray as an icon, connected to the core, and shows the core's status.

If a system tray is already running and you open `Miyu` again, no second one starts; the running one just opens the web interface once more. There is one system tray per data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`); a system tray started with `MIYU_HOME` set uses the data root it points to, and each one runs on its own.

When the system tray connects to the core to show its status, it does not start the core; it only connects to a core that is already running. The core is started only when the web interface is opened or when you click `Start`. If the core was started elsewhere (the terminal, `miyu web`, a service), the system tray still shows `Running`.

## Clicking the icon

Left and right clicks on the icon do the following:

| | Linux | macOS | Windows |
|---|---|---|---|
| Left click | Opens the web interface | Shows the menu | Opens the web interface |
| Right click | Shows the menu | Shows the menu | Shows the menu |

Double click and middle click have no action of their own.

## Menu

The menu items are listed below from top to bottom, with a separator between groups:

| Menu item | What clicking it does |
|---|---|
| Status line (not clickable) | See "Status" below. |
| `Stop` or `Start` | Stop: stops the web interface first, then the core (`miyu web stop`, then `miyu core stop`). Start: starts the core without opening a browser. |
| `Restart` | Stops the core and starts it again; the web interface keeps running, and open pages connect to the new core. |
| `Open Web Interface` | Runs `miyu web`, which opens the home page in your browser. |
| `Settings…` | Runs `miyu web --settings`, which opens the web interface's settings page in your browser. On macOS you can press `⌘,`. |
| Package lines | One line per package that has a background page and declares `[tray]` in its manifest; clicking one runs `miyu pkg page <id>`, which opens its background page. If there are no such packages, this group is not shown. |
| `LAN Access` (checkbox) | Turns on or off opening the web interface from other devices over the LAN; for details, see "LAN" below. |
| `Open on Your Phone…` | Shown only while LAN access is on. Runs `miyu web --settings access`, which opens `Access` in the web interface's settings, where the address and a QR code are. |
| `Start at Login` (checkbox) | Starts the system tray when you log in; for details, see "Start at login" below. |
| `Open Log Folder` | Opens `~/.miyu/var/log/` in the file manager. |
| `About Miyu` | Opens a dialog showing the versions of the system tray, the core and the web interface. |
| `Quit Miyu` | Stops the web interface and the core first, then the system tray quits. On macOS you can press `⌘Q`. |

If the web interface is too old to understand arguments such as `--settings`, the system tray opens the web interface's home page instead.

### Status

The status line shows the core's status, with a small dot in front:

| Text shown | Dot | When it appears |
|---|---|---|
| `Running` | Green | Connected to the core. |
| `Running · LAN` | Green | Connected to the core, with LAN access on. |
| `Starting…`, `Stopping…` | Yellow | The system tray is starting or stopping the core. |
| `Not Responding` | Yellow | It can connect to the core, but requests get no answer for a long time. |
| `Stopped` | Gray | The core is not running. |
| `Something Went Wrong` | Red | Starting failed, or the connection was refused; the line below gives the reason. |

The tray icon itself does not change with the status; hovering over it shows `Miyu`.

Which menu items can be clicked in each state:

- While starting, that line is a grayed-out `Stop`; while stopping, it is a grayed-out `Start`.
- `Restart` can be clicked when the status is running, not responding or something went wrong.
- `LAN Access` can only be clicked while running.

### LAN

`LAN Access` changes the web interface's `web.listen`: turning it on writes `0.0.0.0`, and turning it off goes back to the shipped `127.0.0.1`. The web interface switches over at once, with no restart.

- If you turn it on before an access password is set, the system tray does not change the configuration; instead it first opens `Access` in the web interface's settings in your browser, where you need to set the password and turn LAN access on.
- If the web interface is not installed, or the system tray has never connected to the core yet, this group is not shown.

LAN access is plain HTTP; turn it on only on networks you trust. For how to open the web interface from other devices and how to set the access password, see [Web interface](web.md#access-and-security).

## Whether the core keeps running after you quit

When you close the system tray, whether the core keeps running depends on how you close it:

- `Quit Miyu`: the web interface and the core stop together, then the system tray quits. Even if stopping fails, the system tray quits anyway and writes a line in the log. Stopping the core waits at most 70 seconds, and the icon disappears right after you click.
- `Stop`: the web interface and the core stop; the system tray stays and shows `Stopped`.
- If the system tray did not quit from its menu (for example it crashed or was killed), the core keeps running as usual.

## Notifications

While the system tray is connected to the core, it takes over background notifications: for sessions not open in the web interface, the system tray shows a system notification; the web interface only notifies for sessions open in its own tabs, so the two do not duplicate.

| Notification | When it appears |
|---|---|
| `Done` | A turn has finished. |
| `Waiting for your answer` | The AI is asking you a question. |
| `Waiting for your approval` | Something the AI wants to do needs your approval. |
| `Scheduled task finished`, `Scheduled task didn't finish` | When a turn of a schedule that opens a new session each time has finished or failed. |
| `The scheduled task records were damaged and replaced with a new set; the old scheduled tasks are gone` | The schedule records could not be read. |

- The title is the name of the session's persona, with its avatar if the persona has one; with no persona it shows `Miyu`. The body looks like `<session title> · Done`; if the session has no title, the first sentence is used, and if there is none, only the reason is shown.
- Subagent sessions, one-off sessions and memory consolidation sessions do not show notifications.
- Clicking the notification or its `Open` button opens that session in your browser; the notification about damaged schedule records opens the web interface's home page. On Windows, clicking a notification in the notification center after the system tray has quit still starts the system tray and opens that session.
- On Linux and Windows, a new notification of the same kind for the same session replaces the old one; on macOS they all stay.

The system tray menu has no switch to turn notifications off.

## Start at login

Check `Start at Login`, and the system tray starts when you log in. A system tray started at login only stays in the tray; it does not open a browser or start the core. The setting is written in the following places:

| System | Where it is written |
|---|---|
| Linux | `~/.config/autostart/miyu-applet.desktop` (under `XDG_CONFIG_HOME` if that is set) |
| macOS | `~/Library/LaunchAgents/io.github.miyu-agent.miyu-applet.plist` |
| Windows | `Miyu` in the current user's `Run` registry key |

The system tray is started for the data root given by `MIYU_HOME` or `--home`, and at login it starts with the same data root. If you turn it off in the Linux desktop's autostart settings, the system tray treats it as off.

It differs from `miyu service enable` as follows:

| | `Start at Login` | `miyu service enable` |
|---|---|---|
| What starts at login | The system tray | The core |
| The core | Not started; it starts when you open the web interface or the terminal | Starts at login, so chat platforms and schedules do not have to wait |

With both on: at login the service starts the core, and the system tray starts, connects to it and shows `Running`. If you then click `Quit Miyu` or `Stop` in the system tray, the core exits normally, and the service manager does not start it again until the next login. If you only use the interfaces on the computer and no chat platforms, turning on `Start at Login` is enough; if you want the core always running in the background, you need to install the service, see [Keeping it running, and servers](../service.md#starting-the-core-at-boot-or-login).

## Three platforms

Where the system tray appears and what it needs on each platform:

| System | Where it appears | What it needs |
|---|---|---|
| Linux | System tray | GTK 3; the desktop's tray must support StatusNotifierItem. KDE, waybar and the like support it out of the box; GNOME needs the AppIndicator extension to show it. |
| macOS | Menu bar; the icon is drawn in the menu bar's color | Apple silicon, macOS 12 or later. It does not take a place in the Dock. |
| Windows | Notification area | Notifications must come from the program installed by the installer to carry Miyu's name and icon. |

The system tray menu text follows the system language: Chinese, Japanese, and English for every other language.

## Logs and the tray's own folder

The system tray writes a log and uses a folder of its own:

- Log: `~/.miyu/var/log/miyu-applet.log`, next to the core's and the web interface's logs; at 1 MiB it is renamed to `miyu-applet.log.1`. If the core has never started, `var/log/` does not exist yet, and no log file is written.
- The system tray's own folder holds the single-instance lock and the avatars used in notifications:

  | System | Location |
  |---|---|
  | Linux | `~/.local/state/miyu-applet` (under `XDG_STATE_HOME` if that is set) |
  | macOS | `~/Library/Application Support/miyu-applet` |
  | Windows | `%LOCALAPPDATA%\miyu-applet` |

The system tray has no other settings.

## Common problems

| What you see | What to do |
|---|---|
| No tray icon (Linux) | The desktop's tray does not support StatusNotifierItem. On GNOME, install the AppIndicator extension; if the desktop only supports the old-style tray, switch to another tray. |
| `Can't find the Miyu program. Try installing Miyu again.` | The system tray looks for `miyu` in this order: next to the system tray program, then `PATH`; on Linux and macOS also `~/.local/lib/miyu/` and `~/.local/bin/`; on macOS also `/opt/homebrew/bin` and `/usr/local/bin`; on Windows only next to the system tray program and in `PATH`. If Miyu is installed elsewhere, set the environment variable `MIYU_PROGRAM` to point there. |
| `Can't open the web interface.`, followed by what `miyu` said | Act on what it said; running `miyu web` in a terminal shows more. For problems on the web interface side, see [Web interface](web.md#troubleshooting). |
| `No answer for too long.` | Opening the web interface waits at most 90 seconds, and stopping the core at most 70 seconds. Click again; if it still fails, check the log. |
| The status line shows `Something Went Wrong`, with a line below about the data root not being recognized or the like | Do what that line says; for details, see [Troubleshooting](../troubleshooting.md#the-core-will-not-start-or-cannot-connect). |
| `Miyu didn't start.`, `Miyu didn't stop.` | Read the reason on the line below and the log. |
| `Couldn't change LAN access.` | The core is not running or did not accept the change; wait until the status is `Running` and click again. |
| `Couldn't change Start at Login.` | The autostart file or registry entry could not be written; read the reason on the line below. |
| `No logs yet: they appear after Miyu has run once.` | Click `Start` or `Open Web Interface` first. |
| Clicking the menu seems to do nothing | While starting or stopping, other start and stop requests are not accepted; wait for the status line to change before clicking again. |
