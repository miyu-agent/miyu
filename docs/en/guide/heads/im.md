# Connecting chat platforms

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page explains how to connect Miyu to QQ or Telegram and talk to the AI in private chats and groups: from installing the package and connecting accounts, to managing who can call the AI and what the AI can do in groups, plus chat records and usage.

## What is Connect Messaging?

The package `im` is called `Connect Messaging` in the interface. It is an extension that keeps running in the background, and it has its own dashboard page (a web page). The `miyu im` command exists only after this package is installed. It can be installed on `linux-x86_64`, `macos-aarch64` and `windows-x86_64`; there is no build for Linux aarch64, and running `miyu pkg install im` there reports `Not available for this system.`.

| Platform | How it connects | What you need to prepare |
|---|---|---|
| QQ | Through OneBot v11 reverse WebSocket: im opens a port, and the OneBot implementation connects to it. | Install a OneBot v11 implementation separately, for example NapCat or SnowLuma, and sign in to the QQ account the AI will use. |
| Telegram | Through the official bot interface (Bot API): im connects out and does not open a port. | Create a bot in BotFather and get its token. |

One im can connect several QQ accounts and several Telegram bots at the same time; each account is one "connection".

## Installing and opening

1. Install the package. Run:

   ```sh
   miyu pkg install im
   ```

   The confirmation screen lists the following under `Capabilities`; answer `Y` to approve them all at once: Provide tools, Drive sessions, Speak for platform users, Read sessions, Write session records, Network, Call other packages, Add to the system prompt, Show things in the interface, Sign in pages on this machine. For what capabilities are, see [Packages](../packages.md#capabilities).

2. When the installer asks `Enable 'im' now? [Y/n]`, answer `Y`. If you answered no at that point, you can run this later:

   ```sh
   miyu im start
   ```

   Once it is enabled, the core starts im every time the core starts. Run `miyu im stop` to turn it off; after that the core no longer starts it.

3. Open the dashboard page. There are three ways; use any one of them:

   ```sh
   miyu im web        # open in a browser; starts im first if it is not running
   miyu pkg page im   # same as above; add --print to print only the URL
   ```

   Or type `/im` in the web interface, and the dashboard page opens in a new tab.

The default address of the dashboard page is `http://127.0.0.1:8302/`. The link that `miyu im web` gives is valid for 1 minute. When you open the dashboard page on this computer, or jump over to it from the web interface or the terminal, you do not need to sign in.

The column on the left of the dashboard page contains, in order: `Home`, `Chat settings`, `Chat records`, `Statistics`, `Usage limits`; under `AI`, `Personas`, `Presets`, `Models` (the same data you change on the settings page); under `Software`, `Installed`, `Dashboards`, `Get software`; and at the bottom, `Settings`.

## Connecting QQ

First install a OneBot v11 implementation (for example NapCat or SnowLuma) and sign in to the QQ account the AI will use. The implementation must be able to create a `WebSocket client`, that is, a reverse WebSocket: it connects to im, and im does not connect to it.

1. On the Home page of the dashboard, click `New connection`, choose `QQ` (labelled `OneBot (NapCat and others)` below it), and click `Next`.
2. `Create a reverse WebSocket in your OneBot app`: the page gives you an address, for example `ws://127.0.0.1:8301/ws`. Click `Copy`, create a WebSocket client in NapCat's network panel, enter this address, and then click `Done, next`.
   - If NapCat is on another machine or in Docker, replace `127.0.0.1` with this machine's address.
   - Change the port directly in the address. It must be between `1024` and `65535`, and it must not clash with the port of another connection or of the dashboard page. The first connection uses `8301` by default, and connections you create later count up from there.
   - The path can be either `/ws` or `/onebot/v11/ws`.
3. `Get the reverse WebSocket token`: NapCat most likely generated a token automatically when it created the reverse WebSocket. Paste it here and click `Save and connect`. If a connection has no token, NapCat is refused when it connects.
4. `Your QQ number`: enter your own QQ number so that the AI can recognize you in private chats and groups (see "Binding your own accounts" below). If you do not want to enter it, click `Skip`.
5. `Waiting for it to connect`: after you save on the NapCat side, it connects within a few seconds. Once connected, the page shows `Connected`, and the line below gives the bot's number and the connected implementation, for example `Bot 10001 · connected through NapCat 4.8.0`.

Once connected, the `Connections` column on the Home page has one card per bot, showing the avatar, the name, `QQ · <implementation> <version>` and `<number> · connected N min`. The card of a disconnected connection stays and shows `disconnected N min, reconnecting`. If a token is set but no account has connected yet, the card shows `Waiting for NapCat`, along with the port. To check the connection state from the command line, run:

```sh
miyu im status
```

If it is connected, it prints `NapCat connected: <implementation> <version>, bot <number>`; if not, it prints `NapCat is not connected` and `NapCat address: ws://127.0.0.1:<port>/ws`.

The gear button on a card is `Connection settings`, which contains the following fields:

| Field | Notes |
|---|---|
| Listen address | The default is `0.0.0.0`, so programs on other machines and in Docker can connect too, and strangers are kept out by the token. With `127.0.0.1`, only connections from this machine are accepted. This field must be an IP address. |
| Reverse WebSocket port | The port NapCat connects to. |
| Reverse WebSocket token | Leave it empty to keep it unchanged. |
| Address to enter in the OneBot app | The address built from the fields above, which you can copy directly. |

Changes need no restart; NapCat is checked against the new settings the next time it connects. If there is more than one connection, a `Remove this connection` button appears below, and you have to click it twice to remove the connection.

If you want to connect several QQ accounts, each account needs its own OneBot implementation and its own connection, each with its own port and token. Go through `New connection` again with the steps above for each account.

## Connecting Telegram

1. In Telegram, find `@BotFather`, send `/newbot`, follow the prompts to set a name and username, and note down the token it gives you.
2. On the Home page of the dashboard, click `New connection`, choose `Telegram` (labelled `Bot API` below it), and click `Next`.
3. `Create a bot in BotFather`: paste the token into `Token`. `Proxy` has three options; choose one of them:
   - `Follow network settings`: uses a proxy according to the core's environment variables `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY` and so on; see [Web search and fetching pages](../web-search.md#proxy).
   - `Direct`: does not use a proxy.
   - `Custom`: enter `http://host:port` or `socks5://host:port`; `https://` is accepted too.

   If your network in mainland China cannot reach Telegram, choose a proxy that works. Then click `Check and connect`.
4. `Check results`: the page shows whether the token works (with the bot's name, username and number), whether Telegram is reachable, and whether privacy mode is on. Click `Next`.
5. `Your Telegram ID`: enter your numeric ID on Telegram, or click `Skip`.
6. The page shows `Connected`, and the connection is done.

The token is stored in the secrets file `~/.miyu/etc/private/secrets.toml` (the data root defaults to `~/.miyu`, and on Windows to `%USERPROFILE%\.miyu`); the config file holds only a reference to it. In the gear on the connection card you can replace the token (the hint reads `Set; leave empty to keep. Paste the new one if you changed it in BotFather`), change the proxy, and see the privacy mode.

### Privacy mode

Bots created with BotFather have privacy mode on by default. While privacy mode is on, the bot receives in groups only replies to the AI and commands sent to it; it does not even receive messages that `@` it. If you only use it in private chats, you do not need to deal with this. To call it in groups, turn privacy mode off with the steps below:

1. In Telegram, send `/setprivacy` to `@BotFather`.
2. Choose this bot, then choose `Disable`.
3. If the bot is already in a group, you need to remove it from the group and add it back before the setting takes effect.

You can also make the bot a group admin, since admins receive every message. After the change, click `Check again` in the connection settings. Groups where privacy mode is on are marked `Privacy mode` on their session card.

### Other notes on Telegram

- Only one program can receive messages for a token. If the connection card shows `Receiving elsewhere too`, another program is also using this token.
- Typing `/` in a private chat lists Miyu's commands. The `-` in command names is replaced by `_`, for example `/clear_memory`.
- In a group with topics turned on (marked `Topics` on the session card), the whole group is one session, and the AI replies in the original topic.
- If you run your own Bot API server, put its address in `im.tg.api`.

## Binding your own accounts

This step tells Miyu which account on a platform is you. The setting is kept in the core's config, and the three places below change the same data:

- The `Your QQ number` and `Your Telegram ID` step when you create a connection.
- On the dashboard page, `Settings → Bind → Your platform IDs`: click `New binding`, choose a platform first, then enter the number; click `Unbind` to remove a binding. QQ numbers can only be digits; IDs on other platforms cannot contain spaces or colons, and are at most 48 characters.
- On the settings page (type `/settings` in the terminal interface or the web interface), `Advanced → Platform accounts`, or edit `~/.miyu/etc/config.toml` by hand:

  ```toml
  [external.bindings]
  "qq:10001" = "owner"
  "tg:20002" = "owner"
  ```

Once it is set, this account is treated as follows:

- Its private chats are not locked down; like sessions you open in the terminal, they follow the permission level. Things that need confirmation are not done, because chat platforms have no confirmation box. See [Permissions and sandbox](../permissions.md#sessions-on-chat-platforms).
- When it calls the AI in a group, the message skips the reply judgement and the AI replies directly.
- It is not subject to rate limits, sleep hours or usage limits.
- It can use commands whose `access` is `admin`, as well as `/model`, `/persona`, `/preset` and `/loop` in groups.
- Its friend requests to the AI are accepted automatically.
- It can have the AI send messages to other groups and private chats, and have the AI search the chat records of all sessions.

After a change, im recognizes the new setting within 60 seconds at most.

## How sessions are divided

Under one connection, each group is one session, and each private chat is also one session. When several people in a group call the AI at the same time, the session opens a few extra branches to reply in parallel; the card's `Concurrent replies` decides how many at most.

Each session has a card, on the `Chat settings` page of the dashboard. If there is more than one connection, first choose the connection in the drop-down next to the title. The wall of cards has four sections:

| Section | Cards | What they cover |
|---|---|---|
| Defaults | `Group defaults`, `Private defaults` | Fields that are not changed on group cards and private cards use the settings of these two cards. |
| Not on the lists | `Other groups`, `Other private chats` | Groups and people not on the lists. Shipped, neither gets replies; messages are only recorded. |
| Group list | One card per group | Shipped, it replies. |
| Private allowlist | One card per person | Shipped, it replies. |

Click `New` to add a group or a person: first choose `Group` or `Private`, then search the groups the AI is in or the AI's contacts, or type the number directly, and click `Add and set up`. On QQ, when people added to the private allowlist send the AI a friend request, it is accepted automatically.

If a field is not filled in, the setting of the next level is used: group cards use `Group defaults`, private cards use `Private defaults`, and the default cards use the core's settings (default persona `persona.default`, default preset `preset.default`, default model `models.chat`). If a field shows text like `Same as group defaults (…)`, the value in brackets is the one it actually uses right now.

Groups and private chats have different shipped settings:

| | Group | Private |
|---|---|---|
| When it replies | Decided by the reply judgement (see the next section). | Every message with text gets a reply; messages with only images or stickers are only recorded. |
| Rate limit | 30 turns per 60 seconds; `Other groups` 5 turns per 300 seconds | 5 turns per 300 seconds; people on the private allowlist are not rate limited, shipped |
| Concurrent replies | 3 | Handled one at a time |
| Group messages included when replying | 30 | — |
| Final message only | On | Off |
| Show numbers to the AI | On | On |

### Session card pages

Click a card to open it. A card has the following pages:

| Page | What is on it |
|---|---|
| Overview | The `Reply` switch (when it is off, messages are only recorded and get no reply); this session's statistics for today, 7 days and 30 days; `Recent decisions` (groups) and `Recent messages` (private): whether each message got a reply and why; the last and next time of the autonomous loop; and at the bottom of listed cards, `Remove from group list` or `Remove from allowlist`. |
| Persona and models | `AI persona`, `Preset`, `Extra prompt` (applies only to this session), `Chat model`, `Context window`, `Vision model`, `Reply judgement model`, `Group messages included when replying`, and whether the AI sees the sender's number. |
| Triggers | Sets when it speaks, the reply judgement and permissions; see the next two sections. |
| Scheduled tasks | Creates scheduled and repeating tasks for this session; see "Scheduled tasks" below. |
| Rate and concurrency | `Rate limit` (messages / seconds), `Sleep hours`, three usage-limit fields, and `Concurrent replies`. |
| Outgoing messages | How it talks, how it sends, and how long text is handled; see "How messages are displayed". |
| Plugins | Sets which plugins are on in this session. |
| Pages added by plugins | Pages that enabled plugins add to this session, for example `Group admin panel`. |
| Live log | What the AI does in this session, one line per event: what it received, how it judged, what it thought, which tools it called, and what it sent. |
| View session | This page exists only when the web interface is installed: it opens this session's timeline in a new tab, read-only. |

When you change the persona, preset or model, existing sessions switch too: the model switches at once; the persona and preset first compact the context once and take effect from the next turn. If you clear the persona or preset on a card, existing sessions stay as they are; to switch back, pick one again on the card.

If you want the AI to start fresh in a group: on the `Chat records` page of the dashboard, click into the group, then click `Delete AI session` in the top right corner (you need to click it twice). This deletes only the AI's context; the chat records are kept.

You can also switch from within the chat: you and the people in the card's `Users allowed to run admin commands` can send `/model`, `/persona` and `/preset`:

| Form | What it does |
|---|---|
| `/model` | Says which one is in use, followed by how to use the command. |
| `/model search [<keyword>]` | Lists the choices, numbered. |
| `/model <number>`, `/model <name>` | Switches, and writes the choice to this session's card. |
| `/model default` | Goes back to following the default setting. |

`/persona` and `/preset` work the same way. When anyone else sends these commands, they go to the AI as ordinary messages.

## When the AI speaks

### Private chats

For people on the private allowlist and for you, the AI replies to every message with text. The shipped setting for other private chats is no reply.

### Calling the AI in a group

In a group, the following two cases count as calling the AI:

- The message `@`s the AI.
- A message starts with one of the words in `Extra trigger words`. The words are case-sensitive. If you want calling its name to work, you need to put the name in too; the persona's name is not added automatically.

A message that only replies to the AI's message without an `@` of the AI does not count as calling it.

In groups where `Reply judgement` is off, the AI replies when called and does not reply otherwise; if `Reply at random` is on, messages picked at random also go to the AI.

### Reply judgement

While the reply judgement is on (this is the shipped setting for groups), a message that meets any one of the conditions below goes to a judge model for a score, and the AI replies only if the score passes the threshold; a message that meets none of them is only recorded:

| Condition | When it counts |
|---|---|
| Called the AI | See the previous section. |
| Follow-up | Within 30 seconds after the AI replied to someone, that person speaks again. |
| Right after the AI spoke | Within 30 seconds after the AI sent a message, a message from anyone counts. |
| Added while replying | While the AI is replying to someone, that person sends more; if it passes, it joins this turn. |
| Picked at random | Messages that meet no other condition are picked by chance. Off when shipped; when turned on, 5% by default. |
| Possible violation | When the message contains a flagged word, the judge model checks it, and the AI replies when the severity reaches 7 (on a scale of 0 to 10). |

- When you, members of the allowlist, or people in the card's `Users who skip the judgement` call the AI, the AI replies directly without scoring.
- If you turn off `Judge even when called` (on when shipped), anyone who calls the AI gets a direct reply.
- The judge model is a model from the lite pool; if the lite pool is empty, it uses this session's chat model. To choose the judge model yourself, set `Reply judgement model` on the card.
- The shipped threshold is `0.8`. It rises in these cases: the AI has just spoken, the same person calls too often, or the AI has replied a lot in this group lately; the card's `Restraint` controls the first of these.
- The threshold, the five weights, the follow-up and observation windows in seconds, and the violation severity threshold are all under `Advanced` on the `Triggers` page.
- Flagged words are edited on the dashboard page under `Installed → Group admin → Settings`; messages from you are not checked.

The AI can also decide on its own to stay quiet this turn (with the tools `qq_skip_reply` and `tg_skip_reply`).

### Autonomous loop

With the autonomous loop on, the AI glances at the group chat every so often and decides on its own what to say or do. This feature is off when shipped, and only listed group cards and private cards have it:

- Turn on `Autonomous loop` on the `Triggers` page.
- `Glance every`: how often it glances when the AI has not set the next time itself; 7 minutes when shipped. If the AI sets the time with `qq_glance` or `tg_glance`, the time the AI set is used.
- `Messages per glance` (groups): at most how many messages not yet replied to since the last glance are passed to the AI; 50 when shipped.
- `Extra prompt for the autonomous loop`: what to do when glancing, for example what to watch for or what to collect.

If no new messages arrived in the group since the last glance, it does not call the model and schedules the next glance by the interval. In a private chat, it does not check for new messages when the time comes; as long as the private chat is idle, it lets the AI decide whether to speak. A glance that falls in sleep hours is postponed until the sleep hours end.

When glancing in a group, one hint is appended at the end of that turn's request (it is not kept in the session history). The hint says: nobody called the AI; it is looking back through the chat like a group member who mostly reads and rarely speaks; it speaks up only for something new: a question nobody answered (quoting that message when it speaks), following up with someone, or a real addition to the topic; it does not repeat what was already said here; staying silent is normal. In a private chat, the hint for that turn only says that nobody called the AI and that it is looking on its own; it does not urge the AI to say less. If the card has an `Extra prompt for the autonomous loop`, it is included in both groups and private chats.

In a group, you and the people in `Users allowed to run admin commands` can send:

| Form | What it does |
|---|---|
| `/loop` | Turns on the autonomous loop for this group, and replies `The autonomous loop is on for this group`. |
| `/loop off` | Turns off the autonomous loop for this group. |

In groups, `/loop` has only these two forms; with an interval or other text, it replies with a line of usage. It switches the card's `Autonomous loop` and is not passed to the core. In private chats, `/loop` goes to the core and is the core's loop, with the same forms as in the terminal: a bare `/loop` turns on the core's autonomous loop, which runs with this private chat's session. That is a different thing from `Autonomous loop` on the private card, and turning it on does not turn on that field on the card. For the core's loops, see [Letting the AI keep working on its own](../automation.md#loops-loop).

### Scheduled tasks

Listed group cards and private cards have a `Scheduled tasks` page: click `New task` and fill in what to do and when (`Every day at`, `Every`, `Once at`, `Cron (advanced)`). When the time comes, the AI carries out the task in this session, also during sleep hours; it is skipped while `Reply` is off. Tasks can be paused, resumed, edited and deleted. For other ways to use scheduled tasks, see [Letting the AI keep working on its own](../automation.md#schedules).

### Keeping the AI quiet in a group

- Just not speaking: turn off `Reply` on the card. The AI keeps recording messages but does not speak.
- Speaking less: turn off the reply judgement so that the AI replies only when called, or lower the `Rate limit`.
- Quiet for part of the day: set `Sleep hours` to something like `23:00-07:00`, in this computer's local time. During that time the AI replies only to you and members of the allowlist.
- Ignoring the group entirely: click `Remove from group list`. The group then uses the settings of the `Other groups` card, which does not reply when shipped.

### Other cases where messages are only recorded

You can see the reason in the card's `Recent decisions` and in the live log:

- `Rate limit reached, recorded only`, `Usage limit reached, recorded only`: you and members of the allowlist are not subject to these two.
- `Sleep hours, recorded only`.
- `The AI is muted, recorded only`, or `The AI is muted, will reply when unmuted`.
- `Several people repeating the same line, recorded only`: someone else said exactly the same thing within the last 2 minutes.
- The message that called the AI was recalled, so this turn stops.

## Setting who can use the AI

| List | Where to change it | What it controls |
|---|---|---|
| Group list | Create a group chat in `Chat settings`; `miyu im access group add <group number>` | In listed groups, the AI replies, shipped. |
| Private allowlist | Create a private chat in `Chat settings`; `miyu im whitelist add <number>`; config key `im.whitelist` | Can chat with the AI privately; friend requests to the AI are accepted automatically; not subject to rate limits or sleep hours; gets a direct reply when calling the AI in groups. |
| Users who skip the judgement | `Triggers` on the group card; `miyu im access skip <group number> add <number>` | Gets a direct reply when calling the AI in this group. |
| Users allowed to run admin commands | `Triggers → Permissions` on the group card | Counts as an admin in this group; see below. |

After you turn on `Reply` on the `Other groups` and `Other private chats` cards, the AI also replies to groups and people not on the lists.

`whitelist` and `access` on the command line change only the QQ lists, and numbers are written as plain digits.

### Handling requests

- Friend requests: requests from members of the allowlist and from you are accepted automatically. Requests from others are left alone, and you need to handle them yourself in QQ.
- Invitations for the AI to join a group: left alone; you need to handle them yourself in QQ.
- Someone asking to join a group: if the AI is an admin of that group, the group admin plugin is on, and `Rule to pass` is filled in on that group's `Group admin panel`, the AI reviews the request against the rule: approve, reject, or leave it for a human. Anything uncertain or failed is always left for a human. Without a rule, it does nothing.

### Group admins

People in `Users allowed to run admin commands` on the group card have the following in that group:

- They count as admins for commands whose `access` is `admin`. QQ group owners and group admins do not count; they need to be put in this field to count.
- They can use `/model`, `/persona`, `/preset` and `/loop`.
- When their command is refused, they get the line saying it was refused; when anyone else's command is refused, there is no reply at all.
- They can have the AI delete group files.

When a message starting with `/` is sent on a chat platform, it first goes to the core to be recognized as a command; anything the core does not recognize goes to the AI as an ordinary message. Who can use which command is set by `commands.<command name>.access`; see [Slash commands](../commands.md#setting-who-can-use-commands).

In groups, the reply to a successful command is recalled after 3 seconds for the commands in `im.recall_receipts`, which are `clear` and `clear-memory` when shipped; replies to refused commands are always recalled; replies in private chats are not recalled. You can change this on the dashboard page under `Settings → General → Commands whose receipts are recalled`.

## What the AI can do in groups

Group sessions, and private chats that are not with you, are locked-down sessions, whatever the permission level:

- File tools can reach only this session's workspace, and skill folders are read-only.
- Commands run in a sandbox that also confines reads to the workspace. Commands cannot run on Windows; on Linux, they cannot run either if the sandbox cannot confine Unix sockets.
- It cannot install or remove packages.
- Anything that needs confirmation is never done.

For details, see [Permissions and sandbox](../permissions.md#sessions-on-chat-platforms). There are also the following points:

- There are no subagents or goals, and it cannot ask people questions; see [Letting the AI keep working on its own](../automation.md).
- MCP servers are given only to local sessions when shipped; they are given to these sessions only after you add `private` or `group` to `mcp.<server name>.venues`; see [Config key reference](../config-keys.md). Scripts and skills are given according to their `Venues`; see [Extending Miyu](../extending.md).
- There are extra limits when other people ask the AI to fetch web pages; see [Web search and fetching pages](../web-search.md#when-someone-else-asks-the-ai-to-fetch-on-a-chat-platform).
- What you wrote about yourself in Settings (`profile.about`) is not included in group chats.

### Memory and the knowledge base

The AI in groups still has the memory and knowledge base tools: `remember`, `forget` and `memory_search` use this persona's memory, the same one you use in the terminal; `kb_save`, `kb_edit` and `kb_delete` write to your knowledge base. A single sentence from someone in the group may get the AI to remember, change or dig something up.

If you do not want people in groups to reach these tools, give those groups a preset that turns them off, and choose that preset in `Group defaults` or on the group card:

```toml
# add to ~/.miyu/root/presets/group.toml
[features]
memory = false

[tools]
kb_save = false
kb_edit = false
kb_delete = false
```

For how to write presets, see [Personas and presets](../personas-presets.md); for memory, see [Memory](../memory.md); for the knowledge base, see [Knowledge base](../knowledge.md).

| | `qq_contacts` | | Lists friends and the groups the AI is in. | ✓ |
| | `qq_members` | | Lists group members. | ✓ |
| | `qq_notices` | | Reads group announcements. | ✓ |
| Usage and ranking | `qq_activity_ranking` | `tg_activity_ranking` | Shows who talked most in this group lately. | ✓ |
| | `qq_token_usage` | `tg_token_usage` | Shows how many tokens and how much money this group or a person used lately. | ✓ |
| Group admin | `qq_mute` | | Mutes and unmutes, at most 32 people at a time. | |
| | `qq_kick` | | Kicks someone, optionally rejecting their future join requests. | |
| | `qq_moderation_log` | | Looks up this group's mute and kick records and ranking. | ✓ |

Muting, kicking and looking up moderation records need the group admin plugin to be on, and the AI must be the owner or an admin of that QQ group. Nobody can act on the group owner; admins can be acted on only when the AI is the owner. Whoever asks the AI to mute or kick, the AI decides for itself, with no extra confirmation. If you do not want the AI to act, turn off `Mute tool` and `Kick tool` under `Installed → Group admin → Settings`, or turn off group admin under `Plugins` on that group's card.

### Built-in plugins

QQ comes with three plugins. You can turn them on and off and change their settings under `Installed` on the dashboard page, and turn them on and off per session under `Plugins` on the session card:

| Plugin | What it does |
|---|---|
| Identity | When someone borrows the name of you, the AI or someone in `People and numbers` but the number does not match, it reminds the AI that this is not that person. |
| Lookups | Provides the tools for searching chat records, fetching images and files, avatars, group members, group announcements, group files, contacts, activity ranking and token usage. |
| Group admin | Provides muting, kicking, moderation records, flood handling, join approval and flagged words. It works only in groups. |

The group admin plugin adds a `Group admin panel` page to the session card. It contains: `Handle floods` (when the same person sends the same thing three times in a row, it recalls the repeats and mutes the person; `Within seconds` is 60 when shipped, and `Mute minutes` is 10), `Rule to pass` for `Join requests`, and recent moderation records and a ranking.

## How messages are displayed

The `Outgoing messages` page has the following fields:

| Field | Shipped | What it does |
|---|---|---|
| Drop the final period | On | Removes one `。` at the end of a reply. |
| Smart quoting | On | When 2 or more other messages followed the original, it quotes the original. |
| Smart mentions | On (groups) | Adds an `@` when quoting someone; with smart quoting off, it adds the `@` only when the reply comes more than 20 seconds later. |
| React when it decides to reply | | After deciding to reply, it first reacts to that message with an emoji, and removes the emoji after replying (groups). |
| Send in several messages | On | Splits at full stops like a person chatting, and sometimes at commas; messages that are too long or contain line breaks are still sent as one. |
| Pause between messages | On | Pauses between messages according to the typing speed. |
| Typing speed | 120 characters/minute | `20` to `600` |
| Send in order | On | Sends the next message only after the previous one went out. |
| Final message only | On for groups, off for private chats | Does not send the in-between text the AI says while calling tools. |
| Long text | Turn into an image | Long text over the threshold is drawn as an image; on QQ you can also choose `Forward as a bundle`. |
| Long text threshold | 300 characters | |
| How this chat talks | | Describe how people here usually talk; the AI sees it every turn (groups). |

Drawing images needs the `render` package; without it, long text is sent in several parts; see [Add-ons](../addons.md). Sending stickers needs the `memes` package; it is on once installed, and you can turn it off per session under `Plugins` on the session card.

What the AI can see:

- Quotes: the quoted message.
- Images: the images in the message that called the AI and in the message it quotes, at most 4 from each, each no larger than 20 MB. Other images, videos and files the AI fetches with `qq_fetch_media`. If the chat model cannot see images, they go to the `Vision model` (`models.vision` when the card does not set one).
- Forwarded bundles (QQ): at most 4 expanded per message, nested at most 3 levels, at most 20 messages each, and at most 500 characters per message.

## Limits and usage

Usage is limited by tokens, on three windows: the last 5 hours, 7 days and 30 days. Once a limit is reached, messages are only recorded and get no reply; you and members of the allowlist are not limited.

- Per-session limits: set them on the card's `Rate and concurrency` page in `5-hour token limit`, `Weekly token limit` and `Monthly token limit`. If a field is empty, there is no limit.
- Per-person limits: set them on the `Usage limits` page of the dashboard. The three fields under `Everyone` apply to everyone, and one person's use is added up across all groups and private chats; people under `Set per person` use their own three fields, which replace the `Everyone` settings as a whole set. Below, `Last 30 days` lists the people who have used it, and people shown in red have reached a limit. Numbers can be written as `200k` or `1.5m`. These settings are stored in `~/.miyu/etc/im/limits.toml`:

  ```toml
  [default]
  limit_5h = 2000000

  [[person]]
  id = "qq:10002"
  limit_month = 50000000
  ```

The `Statistics` page of the dashboard shows data for today, 7 days and 30 days: tokens and cost, request breakdown, statistics by session, by person and by model, the daily trend, messages by hour, and im's own CPU, memory and uptime. CPU and memory are measured with `ps`; Windows cannot measure them, so those two cells stay empty. With more than one connection, you can view the data by connection.

## Chat records

im stores messages from groups and private chats, group events (mutes, kicks, joins, leaves, recalls), and whether each message got a reply and why, in `~/.miyu/var/lib/im/records.db`. Images and files are recorded only as placeholders and platform IDs, and their contents are not stored. Records are never deleted automatically; they stay until you clean them up.

On the `Chat records` page of the dashboard, each connection is one group of entries, listing the groups and private chats that have records, with message counts and sizes. Click one to view its records; at the top you can search by keyword, number or name, and date.

To clean up records: click `Clean up records`, choose the venues and the range (`Keep last 7 days`, `Keep last 30 days`, `Keep last 90 days`, `Clear all`, `Custom`: which period and which sender), then click `Clean up` twice. Cleaned records cannot be restored; the AI's sessions and memory are not affected. The AI cannot delete records itself.

To import QQ records migrated out of the old Miyu, run:

```bash
miyu im records import ~/qq-records.jsonl
```

```powershell
miyu im records import "$HOME\qq-records.jsonl"
```

Records already present are not imported twice; if any line is wrong, nothing from the file is imported, and it prints which lines. For migration, see [Migrating from the old 0.7 version](../migrate.md).

## Plugins

im can install its own plugins, which you manage in these places on the dashboard page:

- `Installed`: installed plugins; you can turn them on and off, approve capabilities, change settings, and see `Where`.
- `Get software`: im plugins in the package source, which you can search and install.
- `Dashboards`: dashboard pages brought by enabled plugins.

### Sponsorships

`im-sponsor` (`Sponsorships`) is an im plugin: you or a group's admins can have the AI record a sponsorship, and anyone can ask the AI how much someone has given in total, or ask for the ranking. To install it, run:

```sh
miyu pkg install im-sponsor
```

It runs as soon as it is installed, appears under `Installed` on the dashboard page, and can be turned on and off per session. Records are changed and deleted on its dashboard page. Other currencies are converted to the default currency at the exchange rate on the day of recording; the default currency is set by the config key `im-sponsor.currency`, and is `CNY` when shipped.

| Command | What it does |

| `miyu im start` | Starts im; after this the core starts it every time the core starts. |

## Opening the dashboard page from other devices

Turn on `Open to the local network` under `Settings → Access` on the dashboard page, and phones and computers on the same LAN can open the dashboard page; the URL and a QR code are shown below the switch. To open it from another device, you need to sign in with the access password set in the web interface; see [Web interface](web.md). Do not put im behind a reverse proxy; to use it from the LAN, turn on this switch. On macOS, if other devices cannot open the dashboard page, allow incoming connections for `miyu-im` in `System Settings → Network → Firewall → Options`.

## Troubleshooting

| What you see | What to do |
|---|---|
| `miyu im status` prints `NapCat is not connected` | Check that the address entered in NapCat matches the one `miyu im status` prints, and that the path is `/ws` or `/onebot/v11/ws`; if NapCat is on another machine, replace `127.0.0.1` with this machine's address, and the listen address must be `0.0.0.0`. |
| `no token set, NapCat connections will be refused` | Run `miyu im web` and paste NapCat's token in the connection settings. |
| The Home page log shows `Blocked repeated wrong NapCat tokens (…)` | The tokens on the two sides differ; change it to match the token on the NapCat side. |
| `port … is in use`, `That port is already in use` | Pick another port in the connection settings, and change the address entered in NapCat to match. |
| The connection card shows `Token rejected, replace it in the connection settings` or `Wrong token` | Get a new token from BotFather and enter it in the connection settings. |
| `Can't reach Telegram, reconnecting`, `Can't reach Telegram, check the proxy` | Change the proxy in the connection settings; if you chose `Follow network settings`, check the core's `HTTPS_PROXY`. |
| `Proxy address is wrong, fix it in the connection settings` | Write it as `http://host:port` or `socks5://host:port`. |
| `Receiving elsewhere too` | Stop the other program that uses this token. |
| `Privacy mode on: @ in groups won't arrive` | Turn privacy mode off as described in "Privacy mode" above. |
| The AI does not reply in a group | Open that group's card and look at `Overview → Recent decisions`, or run `miyu im logs watch qq:<group number>`: `not called` means the message neither `@`s the AI nor starts with a trigger word; `Off, recorded only` means this group is not on the list or `Reply` is off; `… below the threshold …` means the judge model decided not to reply; there are also rate limit, usage, sleep and muted cases. |
| `model request failed` appears in the live log | Check that the chat model on the session card and the core's default model work; see [Models](../models.md). |
| The card names a persona or preset that does not exist, and this session does not reply | Pick one again on the card. |
| `miyu im web` prints `Connect Messaging is not running` | Run `miyu im start`; if that does not help, look at the output of `miyu im status` and `miyu im logs`. |
| `management page port … is in use, the page is unavailable` | Run `miyu config set im.web.port 8312` to pick another port. |
| `miyu im status` prints `Connect Messaging stopped and will not be restarted: …` | Fix the cause it gives, then run `miyu im restart`. |
| The dashboard page shows `Can't reach Connect Messaging` | im has stopped; run `miyu im start`. |
