# Sessions

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Each conversation you have with the AI is a session. This page explains how to start a new session, how to continue an earlier one, how to choose the directory the AI works in, how to go back one turn, what happens when the context is full, and how to rename, export, import and delete sessions.

Session data is stored in the data root (`~/.miyu` by default, and `%USERPROFILE%\.miyu` on Windows). Each session has an id written as a UUID, that is, hexadecimal digits in groups of 8-4-4-4-12, like `0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90`. The terminal interface and the web interface often show only the last 8 digits of the id, which is called the short id.

## Starting a new session

You can start a new session in the terminal interface, in the web interface, or on the command line.

Terminal interface:

1. Run `miyu`. Running plain `miyu` opens the interface named by `Default interface` (`ui.head`) in settings, which is the terminal interface as shipped. If standard input or standard output is not a terminal (for example in a script or a pipe), it only prints the help, and the exit code is `2`.
2. In the box, first choose a persona, then choose a preset; you can type only after you have chosen them. For what personas and presets are, see [Personas and presets](personas-presets.md).
3. Type your first message and press Enter.

Whether opening the interface starts a new session or continues the most recent one is decided by `General → Display → On start, open` (`ui.startup`) on the settings page: you can choose `A new session` (`new`, as shipped) or `The most recent session` (`recent`). If you are already in the interface, type `/new` to start a new session.

Web interface:

1. Click `New session` in the left column.
2. Above the input box there are three buttons, `Select persona`, `Select preset` and `Set workspace`; for the buttons you do not click, the defaults are used.
3. Type your first message. The session is created only when the first message is sent.

Command line: `miyu ask "<message>"` starts a new session, sends this one message, prints the answer and exits. For example:

```bash
miyu ask "What is this project for?"
cat error.log | miyu ask "Why did it fail?" -
miyu ask -C ~/src/app --preset full "Run the tests and fix the failures"
```

```powershell
miyu ask "What is this project for?"
miyu ask --file error.log "Why did it fail?"
miyu ask -C $HOME\src\app --preset full "Run the tests and fix the failures"
```

If you give no message, the whole message is read from standard input; if a word in the message is exactly `-`, standard input is read and put after the message. All the arguments of `miyu ask` are listed below:

| Argument | What it does | Can it be written with `-c`, `-s` |
|---|---|---|
| `-c`, `--continue` | Continues the session that the last `miyu ask` started | Not with `-s` |
| `-s`, `--session <id>` | Continues this session | Not with `-c` |
| `-C`, `--cd <directory>` | Works in this directory, which must already exist. If it is not given, the directory you ran the command in is used | No |
| `--add-dir <directory>` | Also counts another directory as part of this session's workspace; it can be written several times | Yes. If you write it when continuing a session, the directories added before are replaced as a whole by the ones written this time |
| `--persona <persona>` | Uses this persona | No; and not with `--no-persona` either |
| `--no-persona` | Uses no persona | No |
| `--preset <preset>` | Uses this preset | No |
| `--permission <read-only\|full>` | The permission level the session starts with: read-only or full access, see [Permissions and sandbox](permissions.md) | No |
| `--model <model>` | Uses this model or `@pool`. A session you continue switches to this model from then on, see [Models](models.md) | Yes |
| `--no-memory` | This session neither recalls nor saves memories, see [Memory](memory.md) | No |
| `--file <file>` | Attaches a file; it can be written several times, see "Giving the AI files and images" below | Yes |
| `--format <text\|json\|jsonl>` | The output format. `text` (shipped) prints the answer as it arrives; `json` prints one JSON on the last line; `jsonl` prints one event per line | Yes |
| `--timeout <duration>` | The longest to wait, for example `30s`, `10m`, `1h`; without a unit it is seconds. When the time is up, the turn is interrupted, and the exit code is `3` | Yes |
| `--from <name>` | When another agent calls it, the agent reports its own name, for example `claude-code`, and this message is recorded as coming from it | Yes |

If the AI sent out subagents, `miyu ask` waits until they have all reported back and the answer is finished before it exits. The exit codes mean the following:

| Exit code | Meaning |
|---|---|
| `0` | The turn ended normally |
| `1` | An error, for example the core cannot be reached, a refusal, or a model error |
| `2` | Wrong arguments |
| `3` | Interrupted (`Ctrl+C`), or the `--timeout` was reached |
| `4` | The turn ended, but some steps needed your confirmation, so they were not done |
| `5` | No model is available |

## Continuing an earlier session

You can find an earlier session and carry on the conversation in the terminal interface, in the web interface, or on the command line.

Terminal interface:

- Type `/sessions` (alias `/resume`) to open the session list, which you can search; press `Enter` to switch to the selected session. In the list, press `Ctrl+P` to pin, the space bar to tick several sessions, and `Ctrl+D` to delete.
- `/jump` lists what you have said in this session; pick a message to jump to it.
- The first line of `/status`, `Session ID`, is the full id; the sidebar shows the short id `#…`.
- To open a given session straight from the shell, run `miyu tui --resume <id>`; if the session cannot be opened, it reports an error and exits.

Web interface:

- The left column lists sessions grouped by time. Click `View all sessions` to go to the all-sessions page, where you can filter and search.
- Type `/sessions <word>` to open the session list above the input box, searched with that word.
- The `⋮` (Session actions) menu on the right of each session has `Copy session ID`.
- To open a given session straight from the shell, run `miyu web --session <id>`.

Command line:

```sh
miyu ask -c "How do I run the tests?"                           # continue the one the last miyu ask started
miyu ask -s 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90 "Keep going"    # continue the given one
```

`-c` recognizes only sessions that `miyu ask` started; for sessions started in the terminal interface or the web interface, use `-s` with the full id. If you have never used `miyu ask`, `-c` reports `no session from 'miyu ask' to continue`. To get the session id in a script, add `--format json`; the `session` in the last line of the output is the id.

`miyu undo`, `restore`, `redo`, `compact`, `recap`, `rename` and `session export` also accept `-s <id>`; if you leave it out, they use the session that the last `miyu ask` started.

## Setting a session's working directory

Each session remembers one working directory, and when the AI runs commands or writes relative paths, they are counted from that directory. Once the session is created, it keeps using this directory, and the directory changes only when you change it explicitly; when you change it in one interface, the other interfaces follow.

The working directory of a new session depends on where you start it:

| Where it starts | Working directory |
|---|---|
| Terminal | The directory the terminal was opened in; if you changed the directory with `/workspace <path>` before starting the session, the changed directory is used |
| Web UI | If you did not click `Set workspace`, it is the session's own default workspace `~/.miyu/root/workspace/<session id>/`, shown in the interface as `Default workspace` |
| `miyu ask` | The directory you ran the command in; if you wrote `-C`, the directory given with `-C` is used |

To change the working directory:

- Terminal interface: type `/workspace <path>`; a relative path is counted from the directory the terminal is in.
- Web interface: type `/workspace <path>`; without a path, it opens a menu for choosing a directory. Before a new session is created, click `Set workspace`.
- Command line: `-C` applies only to newly started sessions; a session you continue uses the directory it remembers, and if that directory differs from the one you are in, a line `· Session working directory: …` is printed at the start.

In the web interface, the path must be absolute or start with `~`: on Linux and macOS write `/…` or `~/…`; on Windows write `C:\…` or `C:/…`, and `~/…` and `~\…` are recognized too. Inside the data root, only directories under `~/.miyu/root/workspace/` can be a working directory, and any other directory is reported as unusable; if you run `miyu ask` inside the data root, the session's default workspace is used instead, with the message `working directory … is too broad; using …`.

A working directory that is too broad can still be used as usual, and commands start running from there; when you switch to it with `/workspace`, the reply says `Workspace switched to … (broad directory).`. The root directory (`/` on Linux and macOS, and a drive root such as `C:\` on Windows) counts as too broad on all three platforms; on Windows, the home directory itself and the directory that contains the data root count as well. On Windows the terminal usually opens in the home directory, so to have the AI work in a project: `cd` into the project directory before running `miyu`; write `-C <directory>` for `miyu ask`; for a session that is already open, type `/workspace <path>` to switch to it.

A directory added with `--add-dir` cannot be `~` itself, the home directory, the root directory, or a directory that contains the data root, and it cannot be inside the data root either; if you write such a directory, the whole command is not accepted.

## Undo, restore, redo

Undo goes back only in the conversation; it does not change files back. Files the AI changed and commands it ran in the undone turn stay on disk as they are. To get files back, you need to use version control such as git, or your own backup; Miyu has no command that changes files back. Type `/files` in the terminal interface, or look at the file changes block in the web interface's right column, to see which files this session changed and the diff of each step, and then change the files back by hand following the diffs.

| | Terminal, web UI | Command line |
|---|---|---|
| Undo the last turn | `/undo` (alias `/rewind`) | `miyu undo` (alias `miyu rewind`) |
| Restore what you just undid | `/restore` | `miyu restore` |
| Undo the last turn and run it again with the same message | `/redo`; in the web interface, click `Redo` at the end of the AI's turn | `miyu redo` |
| Undo the last turn and run it again with a different message | `/edit`; in the web interface, click `Edit` below your message | `miyu redo <new message>` |

Undo works as follows:

- What is undone is the last turn, that is, your message and the AI's answer, and the AI can no longer see them from then on. Things that came from elsewhere are kept, such as a subagent's report, a schedule firing, or a message from another session; what is undone is only the AI's response to them.
- The background commands and subagents that the turn sent out and that are still running are stopped together, and the reply says how many were stopped.
- If the context was compacted or cleared in the undone turns, the context goes back to how it was before the compaction or clear.
- In the terminal interface and the web interface, the message you undid is put back in the input box. If the AI is answering and you have a queued message that has not been sent yet, `/undo` first takes back the queued message.

Restore has to be done before you send the next message. If you undid several times in a row, you can restore them one at a time. After a redo, you can no longer restore.

Redo and edit work only on the last turn, and only if that turn was started by your message; you cannot redo or edit while the AI is answering.

## When the context is full

Each time the AI sends a request to the model, it carries the session's context. When the context reaches a certain fraction of the model's window, Miyu automatically compacts the older part into a summary, keeps the most recent part as it is, and then carries on working.

To see how much of the context is used:

- The terminal interface's sidebar shows `Context`: used / window size · percentage. `/context` opens the details, showing how much each block takes.
- In the web interface, below the input box there is a cell that shows the context, and `/context` opens the same details.
- `/status` shows it too.

To compact by hand, you can use:

```sh
/compact                         # in the terminal or the web UI
/compact keep the details of the database migration   # what follows is your request for the summary
miyu compact -s <id> keep only the conclusions      # on the command line
```

There are two settings for automatic compaction. They are on the settings page under `Advanced → Compaction`, and you can also change them with `miyu config set`:

| Key | On the settings page | Shipped value | What it does |
|---|---|---|---|
| `compaction.line` | Compaction line | `85` | The percentage of the window the context must reach before it is compacted automatically; it can be `20` to `95`. A model with a small window needs to leave room for the answer, so it actually compacts earlier: with a 200,000-token window, setting it above 85 has no effect, and only a million-token window can reach 95 |
| `compaction.prepare` | Pre-compaction | `true` | When the context gets close to the line, the older part is compacted in the background ahead of time, and the result is swapped in when the line is reached, so there is no need to stop and wait. When it is turned off, compaction happens only when the line is reached |

Both settings take effect from the next turn. To change them only for the current session:

- `/compact-line 70`: this session compacts when it reaches 70%, and the value can be `20` to `95`; `/compact-line off` goes back to following the settings; typing just `/compact-line` shows the current value and where it comes from.
- `/context 128k`: sets a context limit for this session; the number can be followed by `k` (thousand) or `m` (million); `/context off` or `/context unset` removes the limit, and the model's window is used instead. A limit so small that a compaction line cannot be worked out is not accepted, and the web interface shows `The context cap must be at least …`.

If you no longer want the earlier content:

- `/clear` (alias `/reset`) clears the context; the session stays the same, and the reply is `Context cleared.`. If you type `/undo` after clearing, it undoes the last turn from before the clear, and the clear is undone along with it.
- Or use `/new` to start a new session.

## Recap

`/recap` or `miyu recap` has the AI write a recap: what is being worked on, what has been finished, and what is left. Writing the recap makes one request to the model, but it does not start a new turn. On the command line it prints only this recap to standard output, so you can pipe it.

## Stopping

While the AI is answering, you can stop it in the following ways:

- Terminal interface: while the AI is answering, press `Esc` twice to interrupt it, and the queued messages are sent afterwards; press `Ctrl+C` to interrupt it, and the queued messages go back to the input box.
- Web interface: while the AI is answering, press `Esc` twice to interrupt it.
- Command line: press `Ctrl+C`, and the exit code is `3`.
- `/stop`: interrupts this turn, keeps the queued messages without sending them, and then stops the background commands and subagents this session sent out; this session's loop stops along with them. The reply is `All stopped.`.

## Renaming a session

By default, the AI gives a session its title based on the conversation.

- Terminal interface, web interface: `/rename <title>` changes the title to the one you write; typing just `/rename` has the AI pick a new one based on the last few turns; `/rename -` removes the title you gave.
- Web interface: choose `Rename` in the `⋮` menu on the right of the session, and edit the title right in the list.
- Command line: `miyu rename <title>`, where several words are joined with spaces; without a title, the AI picks a new one. When the rename is done, nothing is printed.

## Export and import

An exported session can be in one of two formats:

- Raw bundle (ZIP): it contains the original session log, the subagents' sessions, the fork source and the attachments, and it is used to move a session to another computer or another data root. The bundle also has a `transcript.md` that you can read directly. The exported content is not masked, so you need to keep it safe yourself.
- Markdown: for people to read, or to paste to another AI. Keys you have configured are replaced in it.

Markdown has three uses:

| The command line's `--for` | In the interface | What it looks like |
|---|---|---|
| `read` (shipped) | Conversation only, as Markdown | It has a title, time span, model and usage, and thinking and long output are folded |
| `agent` | For another agent to continue | It opens with a note that this is a session transcript, tools are written with their real names and raw arguments, it starts from the last compaction by default, it has no thinking, and it is all in English |
| `chat` | For a web chat | It opens with a token estimate, each tool takes one line, subagents show only their reports, and there is no thinking |

On the command line:

```bash
miyu session export                                   # the session of the last miyu ask, written to ./miyu-session-<first 8 characters of the id>.zip
miyu session export 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90 -o ~/backup/app.zip
miyu session export --md --for agent --last 20 -o -    # the Markdown of the last 20 turns, to standard output
miyu session import ~/backup/app.zip                     # prints the id of the newly imported session
miyu session import old-session.zip --archive               # import as a read-only archive
```

```powershell
miyu session export
miyu session export 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90 -o $HOME\backup\app.zip
miyu session export --md --for agent --last 20 -o -
miyu session import $HOME\backup\app.zip
miyu session import old-session.zip --archive
```

| Argument | What it does |
|---|---|
| `export [<id>]` | Exports a session; if you give no id, the session of the last `miyu ask` is exported. When it is done, it prints where the file was written |
| `-o`, `--output <file>` | Writes to this file. If it is not given, the file is `miyu-session-<first 8 characters of the id>.zip` in the current directory, or `.md` for Markdown. When exporting Markdown, `-` writes to standard output |
| `--md` | Exports as Markdown |
| `--for <read\|agent\|chat>` | The use of the Markdown; it can only be written together with `--md` |
| `--last <turns>` | Exports only the last few turns as Markdown; it can only be written together with `--md` |
| `import <file>` | Imports a raw bundle and prints the id of the newly imported session; a session that already exists with the same content is not imported again |
| `--archive` | Imports as a read-only archive: you can view and search it, but you cannot continue the conversation |

An exported file cannot be written into the data root, and an existing file with the same name is not overwritten.

Terminal interface: type `/export`, first choose the use (`Full archive` or one of the three Markdown uses), then choose `Copy to clipboard` or `Save as a file`. An archive can only be saved as a file; Markdown over 512 KiB can also only be saved as a file. The file is written in the directory the terminal is in. Copying goes through the terminal's OSC 52; if the terminal does not support OSC 52, the content does not reach the clipboard, and no error is reported, see [Terminal](heads/tui.md).

Web interface: choose `Export…` in the `⋮` menu on the right of the session. When exporting Markdown you can choose the range (All, Current context, Last turns), whether to include thinking, and how tools are written, and then choose `Copy` or `Download`; `Full archive` can only be downloaded. Import is `Import session…` at the top of the `All sessions` page; choose a `.zip` file and you are done.

Archives form their own group in the session list, called `Archived`.

## Giving the AI files and images

You can give the AI images, PDFs, text and other files. The AI sees images directly; if the model cannot read a kind of file, the interface tells you. One attachment is at most 20 MiB; an image is at most 5 MiB and no more than 8000 pixels on each side.

Terminal interface:

- Drag the file into the terminal window, or type `@` and choose from the list. Images, PDFs, audio and video become attachments; other files and directories are written into the message as paths, and the AI reads them itself when it needs to see them.
- Press `Ctrl+V` to paste an image from the clipboard as an attachment. In Windows Terminal, use `Alt+V` to paste an image.
- A message over 1 MB is automatically turned into a text attachment and sent.
- For a file over the size limit, only the path is given to the AI.

Web interface:

- Drag files into the window, paste them in the input box, or type `@` and choose from the list. On devices you tap with a finger, there is a paperclip button below the input box.
- You can attach at most 10 files at a time.
- For a file over the limit, the web interface finds the original file on this computer and gives only its path to the AI; if it cannot find the file, click it and fill in the full path. If the web interface is open on another device, a file over the limit cannot be sent.

Command line: use `--file <file>`, which can be written several times. For example:

```sh
miyu ask --file screenshot.png --file log.txt "Does this error match the screenshot?"
```

Files inside the data root cannot be used as attachments.

## Todos

When the AI does a multi-step job, it makes a todo list. You can see it in the right column of the web interface; `/todo` lists the current todos and the state of each one (pending, in progress, completed), and `/todo clear` empties the list.

## Deleting a session

You can delete sessions in the terminal interface and in the web interface:

- Terminal interface: `/delete` deletes the current session and switches to a new one. You cannot delete while the AI is answering, so interrupt it first. In the `/sessions` list, press `Ctrl+D` twice to delete the selected session, and tick several sessions with the space bar to delete them together.
- Web interface: choose `Delete` in the `⋮` menu on the right of the session; you can also click `Select` in the left column and tick several sessions to delete them together.

When you delete a session, the sessions of the subagents it sent out are deleted with it, and any subagents that are still running are stopped first. A deleted session is moved to `~/.miyu/root/trash/sessions/<session id>/` and kept for 7 days, and the next time the core starts, it clears the sessions that have been there for 7 days. Miyu has no command that brings a deleted session back into the session list.

## Troubleshooting

These are common problems when using sessions, and how to fix them:

| What you see | What to do |
|---|---|
| `no session from 'miyu ask' to continue` | `-c` recognizes only sessions that `miyu ask` started. For sessions started in the terminal interface or the web interface, use `-s <id>` |
| `working directory … is too broad; using …` | You ran `miyu ask` inside the data root. Run it outside the data root, or give a directory with `-C` |
| `Nothing to restore` | After the undo, a new message was already sent, or a redo was already done, so it cannot be restored |
| `Can't redo` | The last turn was not started by your message, or this session has no turn yet |
| `This is an archive and can't be continued` | A session imported with `--archive` can only be viewed. To continue the conversation, import the raw bundle again without `--archive` |
| `The context cap must be at least …` | The limit set with `/context` is too small; raise it according to the number in the hint |
