# Using Miyu in an editor

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page explains how to use Miyu as the AI assistant of an editor such as Zed. The editor and Miyu talk over ACP (Agent Client Protocol, a common protocol between editors and AI assistants): the editor starts `miyu acp`, and `miyu acp` connects to the core on this machine. Because sessions in the editor are Miyu sessions, a conversation you start in the editor also shows up in the terminal and web interfaces, and you can continue it there.

## Before you start

1. Install Miyu

   Install Miyu as described in [Installing, upgrading and uninstalling](install.md), and make sure that running `miyu --version` in a terminal prints a version.

2. Connect a model

   If you have not connected a model yet, run:

   ```bash
   miyu setup
   ```

   The model, persona and preset used in the editor are Miyu's own settings; they have nothing to do with the models configured in the editor.

## Add Miyu to Zed

1. Open the settings file

   In Zed, open `Agent Settings`, go to the `External Agents` page, click `Add Agent` and choose `Add Custom Agent`; Zed opens your settings file with an `agent_servers` entry. You can also edit the settings file directly: it is `~/.config/zed/settings.json` on Linux and macOS, and `%APPDATA%\Zed\settings.json` on Windows.

2. Add Miyu

   Write the `agent_servers` entry like this and save the file:

   ```json
   {
     "agent_servers": {
       "Miyu": {
         "type": "custom",
         "command": "miyu",
         "args": ["acp"],
         "env": {}
       }
     }
   }
   ```

   - `command`: the Miyu program. If Zed cannot find `miyu` (for example, Zed started from the Dock on macOS does not always see the `PATH` you set in your shell), write the absolute path; running `command -v miyu` in a terminal (`(Get-Command miyu).Source` in PowerShell) shows where it is.
   - `args`: always `["acp"]`.
   - `env`: usually empty. If your data root is not the default `~/.miyu`, add `"MIYU_HOME": "<absolute path of the data root>"` here, so that `miyu acp` connects to the core of that data root.

3. Start a conversation

   Open the Agent Panel and choose `Miyu` in the new-thread menu to start a conversation. If the core is not running, `miyu acp` starts it first, so the first message may take a second or two longer.

> For other editors that speak ACP (for example JetBrains IDEs), see their own documentation: add a custom agent whose command is `miyu` and whose argument is `acp`.

## What you can do in the editor

| What | How |
|---|---|
| Send a message | Type in the input box and press Enter. You can mention files with `@` and paste images: mentioned files are given to the AI as attachments, and images are handled like images pasted in the terminal interface. |
| See what the AI is doing | The AI's thinking and reply appear as they are written; each tool it uses shows up as a card whose title is the same line as in the terminal interface. Cards for tools that changed files show the before and after, and clicking a file name takes you there. |
| Approve | When the AI wants to run a command that needs approval, the editor shows a confirmation with the full command and the options `Allow once` and `Deny`, and sometimes `Allow for this session`. When the AI asks you questions, the choices also appear in a confirmation; if the editor supports forms, it shows a form where you can pick a choice or write your own answer. |
| Interrupt | Click the editor's stop button to interrupt the turn; if your message is still queued, it is withdrawn. |
| Switch permission | The editor's mode selector has `Full access` and `Read-only`, Miyu's two permission levels; new sessions start with full access. See [Permissions and sandbox](permissions.md). |
| Change the model or thinking effort | The editor's option selector lists the models you can use and the model pools (providers that need a key must have one set up first). Models from a newly installed package appear by themselves once Miyu has fetched their model list. When the current model has thinking levels, you can switch the thinking effort too. |
| Slash commands | Typing `/` lists Miyu's slash commands, such as `/clear` and `/todo`, plus `/compact` to compact the context by hand. See [Slash commands](commands.md). |
| The AI going on by itself | When a background job reports back and wakes the AI, the editor first shows a line such as `Background job "run tests" finished`, then the AI's reply. |
| To-dos and usage | The AI's to-do list appears as the editor's plan; how much of the context is used and how much has been spent are shown too (the amount is left out when it cannot be computed exactly). |
| Open an earlier session | Pick a session in the editor's thread history and Miyu shows its earlier conversation again, so you can go on. The list shows the Miyu sessions whose working directory is the current project. |

## Things to know

- The AI reads and writes the files on disk. It cannot see changes you have not saved in the editor, so save before asking the AI to read a file.
- MCP servers configured in the editor are not passed to Miyu. To let the AI use an MCP server, add it to Miyu; see [Extending Miyu](extending.md).
- If the core stops or restarts, the turn in progress in the editor ends with an error such as `the core stopped before this turn finished`, and everything after that works as usual: Miyu connects to the core again and starts it first if it is not running.
- The core uses the environment of the program that started it, including `PATH`, `HOME` and other environment variables. If the core is not running and `miyu acp` in the editor starts it, the core uses the editor's environment, and the terminal and web interfaces then connect to that same core. An editor opened from the Dock, the Start menu or the desktop often has a shorter `PATH` than your terminal and lacks the variables set in your shell configuration files. The AI may then fail to find programs you installed in your shell (for example `npx`), and the core cannot read keys kept in environment variables. So it is best to start the core in a terminal with `miyu core start` before opening the editor. If the editor has already started the core, run `miyu core stop`, then run `miyu core start` in a terminal.
- After you install the service with `miyu service enable`, the core starts when you log in, so the editor no longer starts it. A core started by the service cannot see the variables set in your shell either; see [The service and environment variables](service.md#the-service-and-environment-variables). Variables you put in `env` in the editor settings are also passed to a core that `miyu acp` starts.
- Closing the editor does not stop a turn in progress: Miyu finishes it in the background, and you can see the result in the terminal or web interface. If the AI is waiting for your approval at that moment, the request is denied automatically after `permission.confirm.timeout`, 5 minutes by default.

## When something goes wrong

- If the editor says Miyu could not start, first run `miyu acp` in a terminal and read the error on standard error (press `Ctrl+D` to quit). The most common cause is that the editor cannot find `miyu`; change `command` to the absolute path as described in step 2 above.
- If the AI cannot find programs when it runs commands in the editor, or an extension driver says you need to log in first, while everything works in a terminal, the core was most likely started by the editor and uses the editor's environment. Start the core in a terminal instead, as described in [Things to know](#things-to-know).
- Run `dev: open acp logs` from Zed's command palette to see every message between the editor and Miyu; you can attach it when you report a problem.
- For other problems, see [Troubleshooting](troubleshooting.md).
