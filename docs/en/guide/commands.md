# Slash commands

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page lists every command you can use after typing `/` in the input box: what each command does, what arguments it takes, and where it works among the terminal UI, the web UI and chat platforms. The commands that concern sessions (undo, compact, export and so on) are explained in detail in [Sessions](sessions.md).

## Typing commands

- Type `/` in the input box, and a command list pops up above the box. The list narrows as you type, and commands whose name or alias starts with what you typed come first. Use `↑` `↓` to select, `Tab` to complete and `Enter` to run.
- Write arguments after the command name, separated by one space, for example `/compact keep the interface changes`.
- If the name you type is not in the list, it is handed to the core to recognize. If the core does not recognize the name either: the terminal UI tells you why it cannot run; in the web UI, if there is text after the name, the whole line is sent to the AI as an ordinary message. If what follows `/` does not look like a command name (a command name starts with a Latin letter and contains only Latin letters, digits, `-` and `_`), such as `/hello!` or `/home/me`, it is treated as an ordinary message from the start.
- `/help` lists the keys and all commands.

Commands come in two kinds:

- Core commands: the commands the core registers, the commands packages provide and the commands you add yourself. They work in the terminal UI, the web UI and on chat platforms, and the command lists of both the terminal UI and the web UI show them.
- Interface commands: they exist only in one particular interface; see "Terminal UI commands" and "Web UI commands" below.

When the two kinds share a name (for example `/clear`, `/stop`, `/context` and `/workspace`), the interface carries the command out in its own way, and the command's description is the core's.

## Core commands

The core registers the following commands:

| Command | Alias | Arguments | What it does | Details |
|---|---|---|---|---|
| `/clear` | `/reset` | | Clears the context; the session itself stays as it is | [Sessions](sessions.md) |
| `/stop` | | | Interrupts the current turn, keeps queued messages without sending them, and also stops this session's background commands, subagents and loop | [Sessions](sessions.md) |
| `/workspace` | | `<path>` | Changes this session's working directory. Without a path, it shows the current working directory. Only you can use it | [Sessions](sessions.md) |
| `/context` | | `[<value> \| unset]` | With a value, sets this session's context limit, for example `128k` or `1m`; `unset` or `off` removes the limit; without arguments, it shows the current limit and the compaction line | [Sessions](sessions.md) |
| `/todo` | | `[clear]` | Lists the todos; with `clear`, empties them | [Sessions](sessions.md) |
| `/remember` | | `<text>` | Records a memory | [Memory](memory.md) |
| `/dream` | | `[stop]` | Organizes memory right away; with `stop`, stops the organizing | [Memory](memory.md) |
| `/clear-memory` | `/reset-memory` | | Clears the memories recorded in this session | [Memory](memory.md) |
| `/goal` | | `[[--rounds <rounds>] <goal> \| pause \| resume \| clear]` | Without arguments, shows progress; with a goal, sets a long-term goal, or changes it if one already exists, and `--rounds` sets the maximum number of rounds; `pause` pauses, `resume` continues, `clear` removes it | [Letting the AI keep working on its own](automation.md) |
| `/loop` | | `[[<interval>] <text> \| off]` | Says the text once every interval, written like `5m` or `2h`; without an interval, the AI decides when the next time is; with nothing at all, the AI decides on its own what to do and when; `off` stops this session's loop. If you give an interval but no text, it replies with the command's usage | [Letting the AI keep working on its own](automation.md) |

`/todo`, `/remember`, `/dream`, `/clear-memory`, `/goal` and `/loop` belong to their own packages: if the package is not installed, or the session's preset does not turn on that feature, the command list does not show the command.

In the web UI, if a new session has not started yet, typing a core command does not start the session; instead it replies with a hint on the spot. `/goal <goal>` and `/loop <text>` are the exceptions: like a first message, they start the session first. Typing just `/loop` does not start a session and shows the hint `Type what to say on each loop`; to start an autonomous loop, you need to send a first message to start the session, and then type the command.

## Commands from packages and ones you add yourself

The following kinds of commands also count as core commands, and appear in the command list together with the ones above:

| Where it comes from | How to write it | What happens when you type it |
|---|---|---|
| Command template: `root/commands/<name>.md` under the data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`), that is `~/.miyu/root/commands/<name>.md`, or in a package's `commands/` directory | `/<name> arguments` | The template body is sent to the AI as a message from you |
| A command declared by an extension (`[[slash]]` in the manifest) | `/<name> arguments` | The extension's program handles it and replies with a piece of text for you to read |
| An MCP server's prompt | `/<server>:<prompt> arguments`, for example `/github:review-pr 123` | The fetched content is sent to the AI as a message from you. It works only in sessions on this machine |
| A full page that an extension provides | `/<name>` | Opens that page |

If a template in `~/.miyu/root/commands/` has the same name as a template in a package, your template is used; if it has the same name as a core command registered above, the core's command is used. Each template and each MCP server is switched on or off separately in a preset; if the preset has it off, typing it shows `Preset "…" has /… off.` (with the preset name and the command filled in). For how to write templates and extension commands, see [Extending Miyu](extending.md).

## Setting who can use commands

On chat platforms, who can use a core command is set by `commands.<command name>.access`. The settings page has no entry for it, so you need to change it with `miyu config set`:

| Value | Who can use it |
|---|---|
| `admin` | You, and the people you put under `Users allowed to run admin commands` on the group card in the chat platform's backstage page. The platform's own group owners and group admins do not count; see [Chat platforms](heads/im.md) |
| `anyone` | Everyone can use it |
| `off` | Turned off, so nobody can use it; typing it shows `/<name> is turned off.` |

If this key is not set, the command's own setting is used (the setting an extension writes in `[[slash]]`); if the command has no setting of its own either, the value is `admin`. In the terminal UI and the web UI, the person talking is always you, so only `off` has any effect.

For example:

```sh
miyu config set commands.clear.access anyone       # anyone in the group can /clear
miyu config set commands.remember.access off       # turn off /remember
```

A change takes effect immediately. This key applies only to core commands; interface commands are not affected by it.

## Using commands on chat platforms

When you send the AI a message that starts with `/` on a chat platform, the core first tries to recognize it as a command, and a message the core does not recognize is sent to the AI as an ordinary message. On chat platforms you can use only core commands (the ones under "Core commands" above, plus template and extension commands; MCP prompts cannot be used), and who can use them is set by `commands.<command name>.access`. The terminal UI's and the web UI's own commands (for example `/undo`, `/compact` and `/new`) do not exist on chat platforms. For platform details, see [Chat platforms](heads/im.md).

## Other things you can write in the input box

Besides commands that start with `/`, you can write the following in the input box:

| What you write | Where it works | What it does |
|---|---|---|
| `$<skill name>` | Terminal UI, web UI | Names a skill: typing `$` pops up the skill list, and the body of the skill you pick is handed to the AI along with this message. One message can name several skills |
| `@<path>` | Terminal UI, web UI | Pops up a file list for you to pick a file from. Images and the like become attachments; other files and directories are written into the message as paths, see [Sessions](sessions.md) |
| `!<command>` | Terminal UI | Typing `!` as the first character in the input box enters command mode; pressing Enter runs the command directly in the session's working directory, without a permission prompt and outside the sandbox; the command and its output are handed to the AI together. Each command runs for at most 120 seconds and cannot take attachments. With the input box empty, press `Backspace` or `Esc` to go back to normal mode |
