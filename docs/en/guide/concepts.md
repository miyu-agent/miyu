# How Miyu fits together

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page is a map for people new to Miyu: what the words that come up across this guide mean, and how they relate to each other. For how to use each one, follow the links after it.

You talk in an interface, and the interface hands what you say to the core. The core sends requests to the model provider within a session, calls tools as the model's answers direct, and pushes the results back to every interface that has this session open.

```text
You
 │
 ├─ Terminal ────────┐
 ├─ Web UI ──────────┤
 ├─ Tray ────────────┼──→ Core (miyu in the background) ──→ Model provider
 └─ Chat platforms ──┘        │
                              ├─ Sessions
                              ├─ Tools
                              └─ Packages
```

## Core

The core is the `miyu` that runs in the background. Sessions, tools, model requests, schedules and installed packages all live in the core. When an interface opens and cannot reach the core, it starts the core; after all interfaces are closed, the core keeps running. Only one core runs per data root at a time. For details, see [Keeping it running, and servers](service.md).

## Interface

An interface is a program that talks to the core: the terminal interface, the web interface, the system tray, and, if you have connected chat platforms, QQ and Telegram. Several interfaces can be open at once and show the same session; a change made in one interface shows up in the others too. For details, see [Terminal](heads/tui.md), [Web UI](heads/web.md), [Tray](heads/applet.md), [Connecting chat platforms](heads/im.md).

## Session

A session is a back-and-forth conversation with its own id, timeline and working directory. Each session has one persona and one preset open, and runs at one permission level. Closing the interface does not end the session, and you can continue it next time. For details, see [Sessions](sessions.md).

## Persona

A persona decides who the AI is and how it talks: its character description and example dialogues are put into the system prompt sent to the model. A session can also run without a persona. Memory belongs to the persona. For details, see [Personas and presets](personas-presets.md).

## Preset

A preset decides which features this session has on: which tools, skills, scripts, MCP servers and slash command templates it can use. Every session always has a preset. For details, see [Personas and presets](personas-presets.md).

## Permission level

Each session uses one of `Full access` and `Read-only`. Under full access, the AI can read and write files and run commands, and dangerous commands ask you first; under read-only, the AI cannot change anything, and commands run in the sandbox. For details, see [Permissions and sandbox](permissions.md).

## Tools

Tools are the means by which the AI gets things done: reading files, running commands, searching the web, remembering things and dispatching subagents are each a tool. Tools come from packages, scripts and MCP servers. For details, see [Tools the AI can use](tools.md).

## Packages

Miyu's features are installed package by package: tools, skills, personas and interfaces can all come in packages. The features that ship with Miyu are packages too (their ids start with `base-`), and so are the terminal interface and the web interface. You install, uninstall and upgrade packages from package sources. For details, see [Packages](packages.md).

## Extensions, skills, scripts, slash command templates, MCP servers

These are several ways to add features to Miyu. They differ in who runs them and where they live:

- Extension: a long-running program in a package. The core starts it, and it can add tools, connect chat platforms and put things in the interface. For details, see [Packages](packages.md).
- Skill: a `SKILL.md` that teaches the AI a way of doing something. The AI only reads it when it needs it.
- Script: one file is one tool. Each time the AI calls it, it runs once.
- Slash command template: a `.md` file. When you type `/<name>`, its body is sent to the AI as if you had said it.
- MCP server: you connect an existing MCP server, and its tools are handed to the AI to use.

The last four work as soon as you put the file in place or write the config; they do not need to be made into a package. For details, see [Extending Miyu](extending.md), [Slash commands](commands.md).

## Models, providers, pools

A provider is a party that offers models (for example DeepSeek, Anthropic, or a model server on your machine), and a model is written in the form `provider/model`. A pool is a group of models, written as `@poolname`; when one of them fails, the next one is used. The three pools `lite`, `normal` and `flagship` always exist, and they handle work such as writing titles, tidying memory and giving the AI advice. For details, see [Models](models.md).

## Memory and knowledge base

Memory is the short notes the AI writes down by itself during conversations, so that it can recall them next time. A knowledge base is documents you hand the AI to look things up in; they are kept as they are, and the AI reads the original text when it looks something up. For details, see [Memory](memory.md), [Knowledge base](knowledge.md).

## Data root

The data root is the folder where Miyu keeps your sessions, settings, keys, memory and installed packages. By default it is `~/.miyu`, and on Windows `%USERPROFILE%\.miyu`; if you set `MIYU_HOME`, the data root is the folder it points to. If you back up this folder, you have backed up Miyu. For details, see [Data and backups](data.md).

## Venue

A venue is the kind of place a session was opened in: this machine (terminal interface, web interface, command line), a private chat on a chat platform, or a group. The venue decides whether a tool is given (`Venues` for scripts, `venues` for MCP servers), and groups and private chats with someone other than you are additionally locked down. For details, see [Permissions and sandbox](permissions.md#sessions-on-chat-platforms), [Extending Miyu](extending.md).

## Subagent

A subagent is another session the AI opens to do one job for it in the background, and when the job is done, it sends a report back. Several subagents can work at the same time. For details, see [Letting the AI keep working on its own](automation.md#subagents).
