# How Miyu fits together

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

A map for people new to Miyu: what the words that come up across this guide mean, and how they relate to each other. For how to use each one, follow the links after it. Chinese version: [中文](../../zh/guide/concepts.md).

You talk in a head, and the head hands what you say to the core. The core sends requests to the model provider within a session, calls tools as the answers direct, and pushes the results back to the heads that have this session open.

```text
You
 │
 ├─ Terminal ────────┐
 ├─ Web UI ──────────┤
 ├─ Tray ────────────┼──→ Core (miyu in the background) ──→ Model provider
 └─ Chat platforms ──┘        │
                              ├─ Sessions
                              ├─ Tools
                              └─ Packages
```

## Core

The `miyu` that runs in the background. Sessions, tools, model requests, schedules and installed packages all live in it. When a head opens and cannot reach it, the head starts it; when all heads are closed, it keeps running. Only one core runs per data root at a time. See [Keeping it running, and servers](service.md).

## Head

An interface that talks to the core: the terminal, the web UI, the tray, and, if you connected chat platforms, QQ and Telegram. Several heads can be open at once and show the same session; what changes in one head changes in the others too. See [Terminal](heads/tui.md), [Web UI](heads/web.md), [Tray](heads/applet.md), [Connecting chat platforms](heads/im.md).

## Session

A conversation going back and forth, with its own id, timeline and working directory. Each session has one persona and one preset open, under one permission level. Closing the head does not end the session; you can continue it next time. See [Sessions](sessions.md).

## Persona

Who the AI is and how it talks: a character description and example dialogues, put into the system prompt sent to the model. A session can also run without a persona. Memory belongs to the persona. See [Personas and presets](personas-presets.md).

## Preset

Which features this session has on: which tools, skills, scripts, MCP servers and slash command templates it can use. A session always has a preset. See [Personas and presets](personas-presets.md).

## Permission level

Each session runs at one of "Full access" and "Read-only". Under full access the AI can read and write files and run commands, and dangerous commands ask you first. Under read-only it cannot change anything, and commands run in the sandbox. See [Permissions and sandbox](permissions.md).

## Tools

The means by which the AI gets things done: reading files, running commands, searching the web, remembering things, sending out subagents. Each of these is a tool. Tools come from packages, scripts and MCP servers. See [Tools the AI can use](tools.md).

## Packages

Miyu's features are installed package by package: tools, skills, personas and interfaces can all come in packages. What ships with Miyu is packages too (ids starting with `base-`), and so are the terminal and the web UI. You install, uninstall and upgrade them from package sources. See [Packages](packages.md).

## Extensions, skills, scripts, slash command templates, MCP servers

Several ways to add things to Miyu. They differ in who runs them and where they live:

- Extension: a long-running program in a package. The core starts it, and it can add tools, connect chat platforms and put things in the interface. See [Packages](packages.md).
- Skill: a `SKILL.md` that teaches the AI a way of doing something. The AI reads it only when it needs it.
- Script: one file is one tool. Each time the AI calls it, it runs once.
- Slash command template: a `.md` file. When you type `/<name>`, its body is sent to the AI as if you had said it.
- MCP server: connects an existing MCP server and hands its tools to the AI.

The last four work once you put the file in place or write the config; they do not need to be made into a package. See [Extending Miyu](extending.md), [Slash commands](commands.md).

## Models, providers, pools

A provider is a company or service that offers models (DeepSeek, Anthropic, a model server on your machine, and so on). A model is written as `provider/model`. A pool is a group of models, written as `@poolname`; when one fails, the next one is used. The three pools `lite`, `normal` and `flagship` always exist and handle titles, memory tidying and giving the AI advice. See [Models](models.md).

## Memory and knowledge base

Memory is the short notes the AI writes down by itself during conversations, so it can recall them next time. A knowledge base is documents you hand the AI to look things up in; they are kept as they are, and the AI reads the original text when it looks something up. See [Memory](memory.md), [Knowledge base](knowledge.md).

## Data root

The folder where Miyu keeps your sessions, settings, keys, memory and installed packages. By default it is `~/.miyu`, on Windows `%USERPROFILE%\.miyu`; if `MIYU_HOME` is set, it is the folder that points to. Back it up and you have backed up Miyu. See [Data and backups](data.md).

## Venue

The kind of place a session was opened in: this machine (terminal, web UI, command line), a private chat on a chat platform, or a group. The venue decides whether a tool is given (`Venues` for scripts, `venues` for MCP servers), and groups and private chats with someone other than you are additionally locked down. See [Permissions and sandbox](permissions.md#sessions-on-chat-platforms), [Extending Miyu](extending.md).

## Subagent

Another session the AI opens to do one job for it in the background; when done, it sends a report back. Several subagents can work at the same time. See [Letting the AI keep working on its own](automation.md#subagents).
