## Without a subcommand

Typing just `miyu` in a terminal opens the interface that "Default interface" (`ui.head`) in the settings points to; the shipped default is the terminal. If the core is not running, it is started first. If standard input or standard output is not a terminal (in a script or a pipe), it prints only the help, with exit code `2`.

When the interface `ui.head` points to is not installed, it reports "user interface 'tui' is not installed" and gives hints: "install it with 'miyu pkg install tui'" to put it back, or "or switch to an installed one (web, gui): miyu config set ui.head <id>" to switch to one that is installed.

## Commands added by packages

When `miyu <name>` is not a built-in subcommand, Miyu looks among the installed packages for one that provides that command, hands it the remaining arguments unchanged, and uses its exit code. On Linux and macOS, `miyu` is replaced by that program; on Windows, `miyu` starts it and waits for it to exit, and during that time `Ctrl+C` is handled by that program, while `miyu` itself ignores it. If the name clashes with a built-in one, the built-in wins. `miyu -h` gets an extra section, "Commands from packages:", that lists the installed ones. `miyu help <name>` prints that program's own help. If you type only `miyu <name> --version` (or `-V`), `miyu` itself prints "miyu <name> <the package's version>" and does not hand it to that program; with other arguments after it, it is handed over as before. That program's environment has `MIYU_HOME` (this data root) and `MIYU_PROGRAM`.

Typing a command that is not installed reports "unknown command '<name>'". If a package that provides it is in the package source index stored on this machine, the hint is "package <id> provides it; install it with 'miyu pkg install <id>'".

## Common to all commands

### Help and version

| Form | What it does |
|---|---|
| `miyu -h`, `miyu --help` | Prints the overall help |
| `miyu <command> -h`, `miyu help <command>` | Prints the help for this command. For a command with subcommands, the help is one full page with all the subcommands in it |
| `miyu -V`, `miyu --version` | Prints the version, for example `miyu 2026.11.0` |

Help and version go to standard output, with exit code `0`.

### Output format

Most commands that show something have `--format <text|json>`: `text` (the default) is for people, and `json` prints one line of JSON for scripts. These are `bus`, `check`, `config get`, `config explain`, `kb`, `memory`, `pkg`, `provider list`, `schedule`, `service`. `ask` has one more, `jsonl`, see [`miyu ask`](#miyu-ask).

Output is colored only when standard output is a terminal and the environment variable `NO_COLOR` is not set.

### Interface language

The command line has only Chinese and English. Before it connects to the core, it follows the first of the environment variables `LC_ALL`, `LC_MESSAGES` and `LANG` that is set; if none is set, it follows the system setting (the preferred language on macOS, the display language on Windows). A value starting with `zh` uses Chinese, anything else uses English. The help pages and the errors for wrong arguments follow this.

After it connects to the core, it follows "General → Display → Interface language" (`ui.language`) on the settings page: `zh` uses Chinese, `en` and `ja` use English; `auto` (the default) follows the system language as above.

### Errors

Errors go to standard error and start with `miyu: `; anything you can act on goes on a separate line starting with "hint: ":

```text
miyu: unknown command 'ls' for 'miyu kb'
hint: see 'miyu kb --help'
```

### Exit codes

| Exit code | Meaning | Which commands can give it |
|---|---|---|
| `0` | Done | All |
| `1` | Error: cannot reach the core, the core refused, the model or a tool failed | All |
| `2` | Bad arguments, nothing was done | All |
| `3` | Interrupted (`Ctrl+C`), or `--timeout` expired | `ask`, `redo`, `compact`, `memory dream`, `call` |
| `4` | The turn ended, but some steps needed confirmation, nobody could confirm, and they were not done | `ask`, `redo`, `call` |
| `5` | No usable model: none configured, or all are cooling down | `ask`, `redo`, `compact`, `recap` |
| `130` | Cancelled while pasting a key: you pressed `Ctrl+C`; on Linux and macOS, `Ctrl+D` before typing anything counts too | `setup`, `provider login` |

In `miyu ask` nobody can confirm on the spot, so steps that need confirmation are never done, with exit code `4`. Do that kind of work in the terminal or the web UI, see [Permissions and sandbox](permissions.md).

### What reads standard input

| Command | What it reads |
|---|---|
| `miyu ask` | With no message, the whole input is the message; if a word in the message is exactly `-`, the input is read and appended after it |
| `miyu setup --provider <id>` | When not in a terminal, reads the key from a pipe |
| `miyu provider login` | Reads the key from a pipe |
| `miyu call <tool> --json -` | Reads the JSON arguments from a pipe |
| `miyu pkg`, `miyu upgrade` | When confirmation is needed, reads one line of answer. If standard input is closed, nothing is done; add `--yes` |

## miyu ask

```text
miyu ask [<options>] [<message>]
```

Sends a message and prints the reply. Without `-c` or `-s`, it opens a new session. If the AI started subagents, it exits only after they have all reported and the reply is finished.

| Argument | What it does |
|---|---|
| `-c`, `--continue` | Continues the session the last `miyu ask` opened. Cannot be combined with `-s` |
| `-s`, `--session <id>` | Continues this session |
| `-C`, `--cd <dir>` | Works in this directory, which must already exist. New sessions only |
| `--persona <persona>` | Uses this persona. New sessions only; cannot be combined with `--no-persona` |
| `--no-persona` | Uses no persona. New sessions only |
| `--preset <preset>` | Uses this preset. New sessions only |
| `--permission <read-only\|full>` | Permission level at the start: read-only or full access. New sessions only |
| `--format <text\|json\|jsonl>` | `text` (the default) prints as it arrives; `json` prints one JSON on the last line; `jsonl` prints one event per line |
| `--add-dir <dir>` | Adds another directory to the workspace, readable and writable; can be given several times |
| `--file <file>` | Attaches a file (image, PDF, text); can be given several times |
| `--timeout <time>` | The longest to wait, for example `30s`, `10m`, `1h`; without a unit it is seconds |
| `--from <name>` | When another agent calls it, reports its own name, for example `claude-code` |
| `--model <model>` | Uses this model or `@pool`. A session you continue switches to it from then on |
| `--no-memory` | Neither recalls nor saves memories. New sessions only |

The ones marked "new sessions only" cannot be combined with `-c` or `-s`.

```bash
git diff | miyu ask --format jsonl "Review these changes" -
```

```powershell
git diff --output=changes.diff
miyu ask --format jsonl --file changes.diff "Review these changes"
```

Exit codes: `0` to `5` can all occur, see the exit code table above. For more, see [Sessions](sessions.md).

## miyu undo

```text
miyu undo [-s <id>]
```

Undoes the last turn of a session; rolls back only the conversation, not the files. Can also be written `miyu rewind`.

| Argument | What it does |
|---|---|
| `-s`, `--session <id>` | Which session. Without it, the one the last `miyu ask` opened |

```sh
miyu undo
```

When refused (for example "nothing to undo"), the exit code is `1`. See [Sessions](sessions.md#undo-restore-redo).

## miyu restore

```text
miyu restore [-s <id>]
```

Restores the turn you just undid, before you send the next message. Arguments are the same as `miyu undo`.

```sh
miyu restore
```

When there is nothing to restore, it reports "nothing to restore" with exit code `1`.

## miyu redo

```text
miyu redo [-s <id>] [<message>]
```

Undoes the last turn and sends your message again; if you write a message, the new one is used instead. Arguments are the same as `miyu undo`, and the reply is printed as in `miyu ask`.

```sh
miyu redo Only change the README, leave the code alone
```

Exit codes are the same as `miyu ask`. If the last turn was not opened by your message, it reports "cannot redo" with exit code `1`.

## miyu compact

```text
miyu compact [-s <id>] [<instructions>]
```

Compacts the session's context into a summary; the most recent part stays as it is. What you write after it goes to the summary, saying what to keep. Arguments are the same as `miyu undo`.

```sh
miyu compact Keep the details of the database migration
```

Exit codes: `0` compacted; `1` refused or the compaction failed (with nothing to compress it reports "nothing to compact"); `3` interrupted; `5` no usable model. See [Sessions](sessions.md#when-the-context-is-full).

## miyu recap

```text
miyu recap [-s <id>]
```

Has the AI write a recap: what is being done, what is finished, where it is stuck. Only this text is printed to standard output, so it can go into a pipe. Arguments are the same as `miyu undo`.

```sh
miyu recap -s 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90
```

Exit codes: `0` written; `1` refused (nothing to recap, the recap was not written, no such session); `5` no usable model.

## miyu rename

```text
miyu rename [-s <id>] [<title>]
```

Renames a session. Several words are joined with spaces; without a title, the AI makes up a new one from the conversation. Prints nothing when done. Arguments are the same as `miyu undo`.

```sh
miyu rename Migrate the database
```

When refused (the title is blank or too long, no such session), the exit code is `1`.

## miyu session

```text
miyu session export [<id>] [-o <file>] [--md [--for <use>] [--last <turns>]]
miyu session import <file> [--archive]
```

| Subcommand, argument | What it does |
|---|---|
| `export [<id>]` | Exports the session's raw bundle (ZIP). Without an id, the session of the last `miyu ask`. Prints where it was written |
| `-o`, `--output <file>` | Writes to this file. Without it, `miyu-session-<first 8 characters of the id>.zip` in the current directory, or `.md` for Markdown. For Markdown, `-` prints to standard output |
| `--md` | Exports as Markdown |
| `--for <read\|agent\|chat>` | Who the Markdown is for: `read` for yourself (the default), `agent` for another AI, `chat` to paste into a web chat. Must be given with `--md` |
| `--last <turns>` | Markdown with only the latest turns, at least 1. Must be given with `--md` |
| `import <file>` | Imports a raw bundle, printing the ids of the newly imported sessions, one per line; sessions this data root already has are not printed |
| `--archive` | Imports as a read-only archive: it can be viewed and searched, but not continued |

```sh
miyu session export --md --for agent --last 20 -o -
```

When refused (the file already exists, it would be written into the data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`), it is not a session bundle), the exit code is `1`. See [Sessions](sessions.md#export-and-import).

## miyu setup

```text
miyu setup [--provider <id>] [--env <var>] [--model <model>]
```

Sets up the first model: pick a provider, paste the key, test the connection, pick the model, and write it to the system config.

| Argument | What it does |
|---|---|
| `--provider <id>` | Uses this provider from the model catalog, without picking |
| `--env <var>` | Takes the key from this variable in the core's environment, without pasting |
| `--model <model>` | Uses this model, without picking |

When not in a terminal, `--provider` is required, and the key is read from a pipe:

```bash
echo "$KEY" | miyu setup --provider deepseek
```

```powershell
$key | miyu setup --provider deepseek
```

In a terminal, the key is not shown as you paste it; press `Ctrl+C` to cancel. On Linux and macOS, `Ctrl+D` before typing anything also cancels.

Exit codes: `0` written; `1` nothing picked, no key received, the test failed, the core refused; `2` bad arguments, or not in a terminal and no `--provider`; `130` cancelled while pasting the key. See [Models](models.md#fastest-miyu-setup).

## miyu provider

```text
miyu provider login [<name>]
miyu provider list [--format <text|json>]
miyu provider logout [<name>]
```

| Subcommand | What it does |
|---|---|
| `login [<name>]` | Stores a key. Without a name, in a terminal you pick from the ones the config uses and the ones already stored. The key is not shown as you paste it, and can also be read from a pipe |
| `list` | Lists the stored ones, and the ones the config uses but are not stored yet (in gray). Keys are not shown |
| `logout [<name>]` | Removes one. Without a name, in a terminal you pick from the stored ones |

```bash
echo "$KEY" | miyu provider login acme
```

```powershell
$key | miyu provider login acme
```

Cancelling while pasting a key works as in `miyu setup`.

Exit codes: `0` done; `1` the core refused, no key received, nothing picked, the one to remove was never stored; `2` the name is not in the allowed form, or no name and not in a terminal; `130` cancelled while pasting the key. See [Models](models.md#where-keys-go).

## miyu config

```text
miyu config <subcommand> [<options>]
```

| Subcommand, argument | What it does |
|---|---|
| `get [<key>…] [--format <text\|json>]` | Prints the values in effect. Without a key, prints all of them; with exactly one key, prints only the value |
| `set <key> <value>` | Changes one item and writes it to the system config `~/.miyu/etc/config.toml`. `--project` is not accepted: a project config can only be edited by hand |
| `unset <key>` | Removes one item from the system config, back to the default |
| `edit [--project]` | Opens the system config in an editor (with `--project`, the project config of the current directory), checking it before saving. The editor follows `VISUAL` and `EDITOR`; if neither is set, it is `vi` on Linux and macOS and `notepad` on Windows |
| `explain <key> [--format <text\|json>]` | Prints what each layer says for this item and which layer is in effect |
| `path [--project]` | Prints the path of the system config; with `--project`, the path of the project config of the current directory |
| `trust [--yes \| --no]` | Shows what the project config in the current directory would change, and lets you decide whether to trust it. `--yes` trusts it and `--no` does not, both without asking |

Typing just `miyu config` in a terminal opens the settings page of the default interface; if the interface has no settings page, or you are not in a terminal, it prints the help, with exit code `2`.

```sh
miyu config explain models.chat
```

Write list values as a TOML array. In bash, wrap the whole thing in single quotes; in PowerShell, use double quotes outside and TOML single-quoted strings inside (Windows PowerShell 5.1 strips the double quotes in arguments):

```bash
miyu config set skills.external.dirs '["~/.agents/skills", "~/my-skills"]'
```

```powershell
miyu config set skills.external.dirs "['~/.agents/skills', '~/my-skills']"
```

Exit codes: `0` done; `1` the core refused (no such key, wrong value, the file has errors); `2` bad arguments, or `edit` typed outside a terminal, or `trust` without `--yes` or `--no`. See [Configuration](config.md).

## miyu pkg

```text
miyu pkg [<subcommand>] [<options>]
```

Without a subcommand, it runs `list`.

| Subcommand | pacman form | What it does |
|---|---|---|
| `list` | `-Q` | Lists the installed packages |
| `install <package>` | `-U` | Installs. `<package>` is a directory with a `package.toml`, a `.miyu` package file, or an id (installs from the package source, or puts back a removed shipped package) |
| `remove <id>` | `-R` | Removes it along with its settings and state, keeping its config |
| `info <package>` | | Shows a package's information. For one that is not installed, it looks in the package source; a directory or `.miyu` file is only shown, not installed |
| | `-Qi <id>` | Looks only at installed ones |
| | `-Si <id>` | Looks only at the package source |
| `files <id>` | `-Ql` | Lists the files it installed |
| `owns <path>` | `-Qo` | Finds which package a file belongs to |
| `check [<id>]` | `-Qk` | Checks whether installed files were changed or are missing |
| `page <id>` | | Opens its dashboard page in the browser |
| `pack <dir>` | | Packs a package directory into a `.miyu` file, without connecting to the core |
| `update` | `-Sy` | Fetches the new index from the package source |
| `search [<words>…]` | `-Ss` | Searches the package source; all the words must match; without words, lists everything |
| `upgrade` | `-Su` | Upgrades the installed packages from the package source. `-Syu` fetches the index first and then upgrades |
| `clean` | `-Sc` | Removes package files from the cache that are not the installed version |
| | `-S <id>…` | Installs these from the package source |

| Option | What it does |
|---|---|
| `--format <text\|json>` | Output format |
| `--yes`, `--noconfirm` | Does not ask before installing, upgrading or removing, and approves the capabilities they need |
| `-n`, `--purge` | With `remove`, deletes the config directory too |
| `--target <system>` | Which system `pack` builds for; a manifest that has `targets` must have one picked |
| `-o`, `--out <dir>` | Which directory `pack` writes to; without it, the current directory |
| `--print` | `page` only prints the address, without opening a browser |

```sh
miyu pkg search ocr
miyu pkg install ocr
```

Exit codes: `0` done; `1` the core refused, or `search` found nothing, or `owns` does not recognize the file in any package, or `check` found changed or missing files; `2` bad arguments. See [Packages](packages.md).

## miyu mcp

```text
miyu mcp login <server>
miyu mcp logout <server>
```

| Subcommand | What it does |
|---|---|
| `login <server>` | Logs in to a URL MCP server that accepts only browser authorization. Prints the authorization page address and tries to open a browser; once you agree, the token is stored in the secrets file and the server connects by itself. If the browser is on another machine, paste back the full address from the address bar after authorizing and press Enter. Waits up to 10 minutes |
| `logout <server>` | Deletes the stored login |

`<server>` is the name of the MCP server in the config or in a package.

```sh
miyu mcp login acme-docs
```

Exit codes: `0` connected, logged out; `1` the core refused, still not connected when the wait ran out, cannot reach the core. See [Extending Miyu](extending.md).

## miyu bus

```text
miyu bus [list [<name>]] [--format <text|json>]
```

Without a subcommand, it runs `list`. Packages provide features on the bus by name and do not hard-code each other's package names; `list` shows who provides each name and whether it can be used, and with a name, only that one.

```sh
miyu bus list render
```

See [Packages](packages.md).

## miyu dev

```text
miyu dev driver-check <id>
```

For people who write packages: checks whether the model driver encoding that this package provides is steady. It restarts the package's extension, and does not check while a session is using it. Exit code `0` when all pass, `1` when some do not. See [Writing a Miyu package](../../authors/README.en.md).

## miyu memory

```text
miyu memory [<subcommand>] [<options>]
```

Without a subcommand, it runs `list`. Options can go before or after the subcommand.

| Subcommand | What it does |
|---|---|
| `list` | Lists memories, newest first |
| `search <words>…` | Searches memories |
| `add <text>…` | Adds one |
| `edit <m-number> [<text>…]` | Edits one and prints the new number; when you change only `--keywords` or `--who`, leave out the text |
| `forget <m-number>` | Voids one |
| `clear session [<id>]` | Clears what a session recorded. Without an id, it follows `-s`, and if that is absent too, it is the session of the last `miyu ask` |
| `clear me` | Clears this whole memory: all classes, the cards of people you know, what is known about you. It does not ask first, and it cannot be recovered |
| `dream` | Organizes memories now. `Ctrl+C` stops it, and what is organized is kept |
| `cards` | Lists person cards |

A memory is written as `m` plus a number, for example `m12`, as printed by `list`.

| Option | What it does |
|---|---|
| `--persona <id>` | Uses this persona's memories; without it, the default persona's. Cannot be combined with `-s` |
| `-s`, `--session <id>` | Uses the memory that this session uses |
| `--forgotten` | `list` and `search` also list the voided ones |
| `--class <user\|feedback\|episode\|reference\|person>` | `list` lists only this class; `add` records it as this class, `user` if omitted |
| `--why <reason>` | `forget` writes why it is forgotten |
| `--keywords <words>` | `add`, `edit`: keywords for retrieval, separated by commas; for `edit`, an empty value removes them |
| `--who <who>` | `add`, `edit`: who a person memory is about, a platform id or a name. Required for `add --class person` |
| `--format <text\|json>` | Output format of `list` and `search` |

```bash
miyu memory add --keywords editor,vim The user writes code in Neovim
```

```powershell
miyu memory add --keywords 'editor,vim' The user writes code in Neovim
```

Exit codes: `0` done; `1` the core refused; `2` bad arguments; `3` `dream` was stopped by `Ctrl+C`. See [Memory](memory.md).

## miyu kb

```text
miyu kb [<subcommand>] [<options>]
```

Without a subcommand, it runs `list`. Removed documents and deleted knowledge bases go to the system trash. Options can go before or after the subcommand.

| Subcommand | What it does |
|---|---|
| `list [<kb>]` | Lists knowledge bases; with a kb, lists the documents in it |
| `search <words>…` | Searches knowledge bases |
| `read <kb> <document>` | Reads one page of a document |
| `new <kb>` | Creates a knowledge base |
| `edit <kb>` | Changes the name and description, and turns auto recall on or off |
| `add <kb> <file>…` | Adds files to the kb, 20 MiB each at most |
| `remove <kb> <document>` | Removes one document |
| `mount <kb> <dir>` | Mounts an existing directory as a read-only knowledge base |
| `delete <kb>` | Deletes the whole kb; for a mounted one, it is only unregistered and the directory is untouched |
| `reindex <kb>` | Rebuilds the index |

| Option | What it does |
|---|---|
| `--kb <kb>` | `search` searches only this knowledge base |
| `--page <page>` | Which page `read` reads; without it, page 1 |
| `--name <name>` | `new`, `edit`, `mount`: the display name |
| `--description <description>` | `new`, `edit`, `mount`: a one-sentence description |
| `--auto` | `new`, `edit`, `mount`: turns on auto recall, which brings in the opening of a section when the conversation mentions it |
| `--no-auto` | `edit`: turns auto recall off |
| `--to <dir>` | `add` puts it in this directory of the kb |
| `--replace` | `add` replaces an existing document of the same name |
| `--format <text\|json>` | Output format of `list` and `search` |

```sh
miyu kb mount handbook ~/Documents/handbook --name "Team handbook" --auto
```

`<kb>` is a knowledge base's id: it starts with a lowercase letter, contains only lowercase letters, digits, `-` and `_`, is at most 64 characters, and cannot be a Windows reserved name such as `con`, `nul` or `com1`. A wrong form reports "invalid knowledge base id: <id>".

Exit codes: `0` done; `1` the core refused; `2` bad arguments. See [Knowledge base](knowledge.md).

## miyu schedule

```text
miyu schedule [<subcommand>] [<options>]
```

Without a subcommand, it runs `list`. At the set time, a message is handed to a session to run one turn; times missed while the core is stopped are not made up.

| Subcommand | What it does |
|---|---|
| `list [--session <id>]` | Lists schedules; with a session, lists only those that run on it |
| `add <message>…` | Adds one. The time is given with one of `--cron`, `--at`, `--every` |
| `rm <id>` | Removes it |
| `pause <id>` | Pauses it |
| `resume <id>` | Resumes it, counting the next run from now |

A schedule's id is the first column of each line of `list`, for example `t1`.

Options of `add`:

| Option | What it does |
|---|---|
| `--cron <fields>` | Runs on a cron expression, for example `'0 8 * * *'` |
| `--once` | Runs the cron only once |
| `--zone <zone>` | The time zone the cron uses, for example `Asia/Tokyo`; without it, this machine's time zone |
| `--at <time>` | Runs once at this time: `'2026-10-28 08:00'` (this machine's time zone) or `2026-10-28T08:00:00+09:00` |
| `--every <interval>` | Runs repeatedly at this interval: a number of seconds, or `90s`, `10m`, `2h`, `1d`, at least 60 seconds |
| `--session <id>` | Runs on this existing session. Cannot be combined with the four below |
| `--persona <persona>` | Opens a new session each time, with this persona |
| `--no-persona` | Opens a new session with no persona each time |
| `--preset <preset>` | The new session uses this preset |
| `--cwd <dir>` | The new session's working directory; without it, each new session's own default workspace `~/.miyu/root/workspace/<session id>/` |

`--once` and `--zone` go only with `--cron`. `list` also accepts `--format <text|json>`.

```sh
miyu schedule add --cron '0 8 * * *' --zone Asia/Shanghai Check last night's CI run and list any failures
```

Exit codes: `0` done; `1` the core refused; `2` bad arguments. See [Letting the AI keep working on its own](automation.md).

## miyu service

```text
miyu service <enable|disable|status> [--format <text|json>]
```

| Subcommand | What it does |
|---|---|
| `enable` | Writes the service file, hands it to the system's service manager, and starts the core at boot or login |
| `disable` | Stops it, removes it from the service manager, and deletes the service file |
| `status` | Shows whether it is installed and turned on |

Linux uses a systemd user service, or desktop autostart where there is none; macOS uses launchd; Windows uses a scheduled task at logon. It covers only your own user. On Windows it cannot be installed when `MIYU_HOME` is set, and reports "cannot install the service: a Windows scheduled task cannot carry MIYU_HOME".

```sh
miyu service enable
```

Exit codes: `0` done, and also `0` when it was not installed to begin with and for `status`; anything else is `1`. See [Keeping it running, and servers](service.md).

## miyu upgrade

```text
miyu upgrade [--prerelease] [--yes]
```

| Argument | What it does |
|---|---|
| `--prerelease` | Counts pre-releases too |
| `--yes` | Upgrades without asking |

If it was installed by the install script, it downloads the new version, verifies the signature and checksum, and replaces it; if it was installed from AUR or Homebrew, it says which package manager command to use; if the archive was unpacked by hand, it says the download address. After upgrading, the core already running is still the old version; type `miyu core stop`, and the next time you open it, it is the new version. On Windows, a running `miyu.exe` cannot be deleted, so it stays in `.miyu-old-<old version>/` in the install directory and is deleted at the start of the next `miyu upgrade`. For a system with no release archive (a Mac with an Intel chip, Windows on ARM and the like), it reports "cannot upgrade: no release is built for this system", with a hint saying which systems have release archives and that on other systems you build from the source on the release page.

```sh
miyu upgrade --yes
```

Exit codes: `0` upgraded, already the latest, should use the package manager, only gave the download address; anything else is `1`. See [Installing, upgrading and uninstalling](install.md#upgrading).

## miyu core

```text
miyu core start
miyu core status [--format <text|json>]
miyu core stop
```

Manages the core running in the background. Interfaces and commands start the core by themselves when they need it, so it rarely has to be managed by hand; use these three to bring it up ahead of time, see whether it is there, or stop it.

- `start`: starts the core if it is not running, waits until it is ready and then returns, printing nothing when it works; does nothing if it is already running. It only starts the core, with no interface and no browser. If the core cannot start, it says why and the exit code is `1`.
- `status`: only looks, never starts it. When the core is running it prints three lines: the state, the version (the one the core reports: after an upgrade and before a restart it differs from `miyu --version`) and the data root; when it is not, it prints the state, the data root and a one-line hint.
- `stop`: tells the running core to stop, waits until it has exited and then returns, printing nothing when it works. If the core is not running, it does nothing and the exit code is `0`. If it is refused, cannot connect, or the core has not exited within 60 seconds, the exit code is `1`.

```sh
miyu core start
miyu core status
```

```text
The core is running
version: 2026.11.0
data root: /home/alice/.miyu
```

Exit codes of `status`: `0` running, `3` not running, `1` an error (for example the core is running but cannot be reached). `--format json` prints one line for scripts, with the same exit codes:

| Field | What it is |
|---|---|
| `running` | Whether it is running |
| `version` | The core's version; `null` when it is not running |
| `data_root` | The absolute path of the data root |

## miyu check

```text
miyu check [<file>] [--format <text|json>]
```

Checks the hand-written files that Miyu reads for mistakes. Without a file, it checks all of them; with one, only that file.

```sh
miyu check ~/.miyu/root/personas/miyu/prompts/examples.md
```

What it checks and how to read the result: see [Troubleshooting](troubleshooting.md#run-miyu-check-first). Exit code `1` when there are errors, `0` when there are only warnings.

## miyu rescue

```text
miyu rescue [<args>…]
```

When the core has a problem, fixes it with LiteMiyu's rescue mode. It does not connect to the core: it fills in the `LITEMIYU_RESCUE_*` environment variables from `models.chat`, runs `litemiyu --rescue`, and hands it the remaining arguments unchanged; variables that are already set are left alone. It looks for `litemiyu` in the directory `miyu` is in, in the directory `miyu` actually lives in, and in `PATH`, in that order. How it hands over to `litemiyu` is the same as in [Commands added by packages](#commands-added-by-packages).

```sh
miyu rescue
```

LiteMiyu exists only for Linux. On macOS and Windows it cannot be found, and the command prints "litemiyu not found" with the hint "only Linux is supported for now".

The exit code follows `litemiyu`'s; `1` when `litemiyu` cannot be found. See [Rescue](rescue.md).

## miyu call

```text
miyu call <tool> --<param> <value>…
miyu call <tool> --json '<object>'
miyu call <tool> --json -
miyu call --schema <tool>…
```

Calls this session's tools from a command the AI runs, for scripts the AI writes. It works only inside a command that Miyu runs, in a session with "Call tools from the command line" on; typed in your own shell, the exit code is `2`.

- `--<param> <value>`: the value is sent as text and converted to numbers or booleans according to the tool's parameter format; giving the same parameter several times makes a list.
- `--json`: passes a JSON object; write `-` to read it from standard input. Named parameters override keys of the same name in the object. Windows PowerShell 5.1 strips the double quotes in arguments, so use a pipe instead.
- `--schema <tool>…`: prints the parameters of these tools.

A tool with a structured result prints one line of JSON; others print text. The commands the AI runs use bash on Linux, zsh on macOS and PowerShell on Windows (see [Tools the AI can use](tools.md#shell)), and the script is written for that shell:

```bash
miyu call web_search --query niri | jq -r '.links[].site' | sort | uniq -c
```

```powershell
(miyu call web_search --query niri | ConvertFrom-Json).links.site
'{"query": "niri"}' | miyu call web_search --json -
```

Exit codes: `0` done; `1` the tool failed or was denied; `2` wrong usage, or not inside a command Miyu runs; `3` interrupted, or the command it belongs to has already ended; `4` needs confirmation, so call this tool directly instead.

## miyu tui

```text
miyu tui [--resume <id> | --page <page> | config]
```

Opens the terminal interface.

| Argument | What it does |
|---|---|
| None | Opens a new session or continues the most recent one, following "On start, open" (`ui.startup`) |
| `--resume <id>` | Opens this session; give the full id; if it cannot be opened, it reports an error and exits |
| `--page config`, `config` | Opens only the settings page, without entering a session; on the settings menu, press `Esc` to exit |
| `--page oobe` | Goes through the first-run guide again |
| `-h`, `--help` | Prints the help |

An unrecognized page name opens the home page as usual. The environment variable `MIYU_TUI_IME=0` makes the terminal not switch input methods (it switches only when you use the fcitx5 input method).

```sh
miyu tui --resume 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90
```

See [Terminal](heads/tui.md).

## miyu shellhook

```text
miyu shellhook <subcommand> [<options>]
```

Once installed in a shell, a message typed after the prompt and sent with Enter is talking to the AI.

| Subcommand | What it does |
|---|---|
| `install [--shell <fish\|bash\|zsh\|pwsh\|powershell>] [--program <path>]` | Installs into a shell. `pwsh` is PowerShell 7, and `powershell` is the Windows PowerShell 5.1 that comes with Windows. Without `--shell`, it works it out: on Linux it looks at the parent process, and for one it cannot recognize, at `SHELL`; on macOS it looks at `SHELL`; on Windows it looks at `SHELL`, and if that is absent, at `PSModulePath` to tell PowerShell 7 from 5.1 |
| `uninstall [--shell <fish\|bash\|zsh\|pwsh\|powershell>]` | Removes it from a shell |
| `status` | Shows which shells it is installed in |
| `doctor` | Checks whether it is installed, whether it can reach the core, the terminal's colors, the clipboard |

`--program <path>` is the program the shell calls; without it, it is the `miyu` next to this program.

```sh
miyu shellhook install --shell zsh
```

Exit codes: `2` for bad arguments; `1` when `doctor` finds one thing wrong. See [Terminal](heads/tui.md).

## miyu web

```text
miyu web [<options>]
miyu web stop
miyu web status
```

Opens the web interface: if the web UI is not running, it is started in the background first, and then the browser is handed the address. It returns right away and does not hold the terminal. The web UI keeps running after the browser is closed.

| Argument | What it does |
|---|---|
| `--port <port>` | Which port to listen on this time (counts only when the web UI is not running), `8300` by default |
| `--print` | Does not open a browser; prints the address |
| `--format <text|json>` | Format of what is printed; `json` does not open a browser either |
| `--reset` | Opens with a one-time code, to reset the access password |
| `--logout` | Makes every browser log in again |
| `--package <id>` | Opens this package's page in "Dashboards" directly |
| `--session <id>` | Opens this session directly |
| `--settings [<page>]` | Opens the settings directly; write `access` to open "Access" in "General" |
| `-h`, `--help` | Prints the help |

- `stop`: stops the web UI, and the core keeps running. It prints to standard error: "stopped the web interface" when it stopped it, "the web interface is not running" when it was not running, both with exit code `0`; "miyu: cannot stop the web interface: <reason>" when it could not stop it, with exit code `1`.
- `status`: shows whether the web UI is running, printed to standard output: "the web interface is running: <address>" with exit code `0` when it is running; "the web interface is not running" with exit code `3` when it is not (the same codes as `miyu core status`).

Neither of these connects to the core, so they do not start it when it is not running; nothing else may follow them.

```sh
miyu web --settings access
miyu web status
```

Bad arguments give exit code `2`. See [Web UI](heads/web.md), [Keeping it running, and servers](service.md#opening-the-web-ui-from-other-machines-and-phones).
