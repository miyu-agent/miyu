## Running without a subcommand

Running just `miyu` in a terminal opens the interface that `Default interface` (`ui.head`) in the settings points to; the shipped default is the terminal UI. If the core is not running, it is started first. If either standard input or standard output is not a terminal (for example when it runs in a script or a pipe), it prints only the help, with exit code `2`.

If the interface `ui.head` points to is not installed, it reports `user interface 'tui' is not installed` and gives the hints `install it with 'miyu pkg install tui'` to put it back, or `or switch to an installed one (<ids>): miyu config set ui.head <id>` to switch to an interface that is installed.

## Commands added by packages

If `miyu <name>` is not a built-in subcommand, Miyu looks among the installed packages for one that provides that command, hands the remaining arguments to its program unchanged, and uses that program's exit code. On Linux and macOS, `miyu` is replaced by that program; on Windows, `miyu` starts the program and waits for it to exit, and during that time `Ctrl+C` is handled by that program while `miyu` itself ignores it. If the name clashes with a built-in command, the built-in one wins. `miyu -h` gets an extra section, `Commands from packages:`, that lists the installed commands of this kind. `miyu help <name>` prints that program's own help. If you run only `miyu <name> --version` (or `-V`), `miyu` itself prints `miyu <name> <the package's version>` and does not hand it to that program; if other arguments follow, it is handed to the program as usual. That program's environment has `MIYU_HOME` (the current data root) and `MIYU_PROGRAM`.

If you run a command that is not installed, it reports `unknown command '<name>'`. If a package that provides the command is in the package source index stored on this machine, the hint is `package <id> provides it; install it with 'miyu pkg install <id>'`.

## Conventions common to all commands

The following conventions apply to every command.

### Help and version

| Form | What it does |
|---|---|
| `miyu -h`, `miyu --help` | Prints the overall help |
| `miyu <command> -h`, `miyu help <command>` | Prints the help for this command. If the command has subcommands, the help is one full page with all the subcommands in it |
| `miyu -V`, `miyu --version` | Prints the version, for example `miyu 2026.11.0` |

Help and version are printed to standard output, with exit code `0`.

### Output format

Most commands that show information have a `--format <text|json>` option: `text`, the default, is meant for people, and `json` prints one line of JSON for scripts. The commands with this option are `bus`, `check`, `config get`, `config explain`, `kb`, `memory`, `pkg`, `provider list`, `schedule` and `service`. `ask` has one more format, `jsonl`; see [`miyu ask`](#miyu-ask).

Output is colored only when standard output is a terminal and the environment variable `NO_COLOR` is not set.

### Interface language

The command line has only two languages, Chinese and English. Before it connects to the core, the command line uses the first of the environment variables `LC_ALL`, `LC_MESSAGES` and `LANG` that is set; if none is set, it uses the system setting (the preferred language on macOS, the display language on Windows). A value starting with `zh` means Chinese, and anything else means English. The help pages and the errors for wrong arguments use the language decided here.

After it connects to the core, the command line uses the setting `General → Display → Interface language` (`ui.language`) on the settings page: `zh` means Chinese, and `en` or `ja` means English; `auto` (the default) follows the system language as described above.

### Error messages

Errors are printed to standard error and start with `miyu: `; if there is something you can do about it, it goes on a separate line starting with `hint: `:

```text
miyu: unknown command 'ls' for 'miyu kb'
hint: see 'miyu kb --help'
```

### Exit codes

`miyu` uses the following exit codes:

| Exit code | Meaning | Which commands can give it |
|---|---|---|
| `0` | Done successfully | All |
| `1` | Error: the core cannot be reached, the core refused the request, or the model or a tool failed | All |
| `2` | Bad arguments; nothing was done | All |
| `3` | Interrupted (`Ctrl+C`), or the time set by `--timeout` ran out | `ask`, `redo`, `compact`, `memory dream`, `call` |
| `4` | The turn ended, but some steps needed a person to confirm them; since nobody could confirm, those steps were not done | `ask`, `redo`, `call` |
| `5` | No usable model: no model is configured, or all models are cooling down | `ask`, `redo`, `compact`, `recap` |
| `130` | Cancelled while pasting a key: you pressed `Ctrl+C`; on Linux and macOS, pressing `Ctrl+D` before typing anything also counts as cancelling | `setup`, `provider login` |

Because nobody can confirm anything on the spot in `miyu ask`, steps that need confirmation are never done there, and the exit code is `4`. You need to do that kind of work in the terminal UI or the web UI; see [Permissions and sandbox](permissions.md).

### Commands that read standard input

The following commands read from standard input:

| Command | What it reads |
|---|---|
| `miyu ask` | If you did not write a message, the whole input is used as the message; if a word in the message is exactly `-`, the input is read and appended after it |
| `miyu setup --provider <id>` | When not run in a terminal, reads the key from a pipe |
| `miyu provider login` | Reads the key from a pipe |
| `miyu call <tool> --json -` | Reads the JSON arguments from a pipe |
| `miyu pkg`, `miyu upgrade` | When confirmation is needed, reads one line as the answer. If standard input is closed, nothing is done, and you need to add `--yes` |

## miyu ask

```text
miyu ask [<options>] [<message>]
```

`miyu ask` sends a message and prints the AI's reply. If you do not give `-c` or `-s`, it opens a new session. If the AI started subagents, the command exits only after they have all reported back and the reply is finished.

| Argument | What it does |
|---|---|
| `-c`, `--continue` | Continues the session that the last `miyu ask` opened. Cannot be used together with `-s` |
| `-s`, `--session <id>` | Continues this session |
| `-C`, `--cd <dir>` | Works in this directory, which must already exist. Applies to new sessions only |
| `--persona <persona>` | Uses this persona. Applies to new sessions only; cannot be used together with `--no-persona` |
| `--no-persona` | Uses no persona. Applies to new sessions only |
| `--preset <preset>` | Uses this preset. Applies to new sessions only |
| `--permission <read-only\|full>` | The permission level at the start: read-only or full access. Applies to new sessions only |
| `--format <text\|json\|jsonl>` | `text` (the default) prints the reply as it arrives; `json` prints one JSON object on the last line; `jsonl` prints one event per line |
| `--add-dir <dir>` | Adds another directory to the workspace, which can be both read and written; you can give this argument several times |
| `--file <file>` | Attaches a file (image, PDF, text); you can give this argument several times |
| `--timeout <time>` | The longest time to wait, for example `30s`, `10m` or `1h`; without a unit the number is in seconds |
| `--from <name>` | When another agent calls it, the caller reports its own name with this, for example `claude-code` |
| `--model <model>` | Uses this model or `@pool`. If you are continuing a session, that session switches to this model from then on |
| `--no-memory` | Neither recalls nor saves memories. Applies to new sessions only |

The arguments marked "applies to new sessions only" cannot be used together with `-c` or `-s`.

For example, to have the AI review your current changes:

```bash
git diff | miyu ask --format jsonl "Review these changes" -
```

```powershell
git diff --output=changes.diff
miyu ask --format jsonl --file changes.diff "Review these changes"
```

Exit codes: any of `0` to `5` can occur; see the exit code table above. For more on how to use it, see [Sessions](sessions.md).

## miyu undo

```text
miyu undo [-s <id>]
```

`miyu undo` undoes the last turn of a session; it rolls back only the conversation and does not change the files back. The command can also be written as `miyu rewind`.

| Argument | What it does |
|---|---|
| `-s`, `--session <id>` | Which session. Without it, the session the last `miyu ask` opened is used |

For example:

```sh
miyu undo
```

If the request is refused (for example with `nothing to undo`), the exit code is `1`. See [Sessions](sessions.md#undo-restore-redo).

## miyu restore

```text
miyu restore [-s <id>]
```

`miyu restore` restores the turn you just undid; you need to use it before you send the next message. Its arguments are the same as those of `miyu undo`.

For example:

```sh
miyu restore
```

If there is nothing to restore, it reports `nothing to restore`, with exit code `1`.

## miyu redo

```text
miyu redo [-s <id>] [<message>]
```

`miyu redo` undoes the last turn and sends your message again; if you write a new message, the new one is used instead. Its arguments are the same as those of `miyu undo`, and the reply is printed in the same way as in `miyu ask`.

For example:

```sh
miyu redo Only change the README, leave the code alone
```

The exit codes are the same as those of `miyu ask`. If the last turn was not started by your message, it reports `cannot redo`, with exit code `1`.

## miyu compact

```text
miyu compact [-s <id>] [<instructions>]
```

`miyu compact` compacts the session's context into a summary, keeping the most recent part as it is. What you write after the command is passed to the summarizing step, to say what should be kept. Its arguments are the same as those of `miyu undo`.

For example:

```sh
miyu compact Keep the details of the database migration
```

Exit codes: `0` means the context was compacted; `1` means the request was refused or the compaction failed (when there is nothing to compact, it reports `nothing to compact`); `3` means it was interrupted; `5` means there is no usable model. See [Sessions](sessions.md#when-the-context-is-full).

## miyu recap

```text
miyu recap [-s <id>]
```

`miyu recap` has the AI write a recap: what is being done, what is finished, and where it is stuck. The command prints only this recap to standard output, so you can pipe it into something else. Its arguments are the same as those of `miyu undo`.

For example:

```sh
miyu recap -s 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90
```

Exit codes: `0` means the recap was written; `1` means the request was refused (there is nothing to recap, the recap could not be written, or there is no such session); `5` means there is no usable model.

## miyu rename

```text
miyu rename [-s <id>] [<title>]
```

`miyu rename` renames a session. Several words in the title are joined with spaces; if you do not give a title, the AI makes up a new one from the conversation. It prints nothing when the rename succeeds. Its arguments are the same as those of `miyu undo`.

For example:

```sh
miyu rename Migrate the database
```

If the request is refused (the title is blank or too long, or there is no such session), the exit code is `1`.

## miyu session

```text
miyu session export [<id>] [-o <file>] [--md [--for <use>] [--last <turns>]]
miyu session import <file> [--archive]
```

`miyu session` exports and imports sessions:

| Subcommand, argument | What it does |
|---|---|
| `export [<id>]` | Exports the session's raw bundle (ZIP). Without an id, it exports the session of the last `miyu ask`. When it is done, it prints where the file was written |
| `-o`, `--output <file>` | Writes to this file. Without it, the file is `miyu-session-<first 8 characters of the id>.zip` in the current directory, with the extension `.md` for Markdown. For Markdown, `-` prints to standard output |
| `--md` | Exports as Markdown |
| `--for <read\|agent\|chat>` | Who the Markdown is for: `read` for yourself (the default), `agent` for another AI, `chat` for pasting into a web chat. Must be given together with `--md` |
| `--last <turns>` | The Markdown contains only the latest turns, at least 1. Must be given together with `--md` |
| `import <file>` | Imports a raw bundle, printing the id of each newly imported session on its own line; sessions this data root already has are not printed |
| `--archive` | Imports as a read-only archive: it can be viewed and searched, but the conversation cannot be continued |

For example:

```sh
miyu session export --md --for agent --last 20 -o -
```

If the request is refused (the file already exists, the file would be written into the data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`), or the file is not a session bundle), the exit code is `1`. See [Sessions](sessions.md#export-and-import).

## miyu setup

```text
miyu setup [--provider <id>] [--env <var>] [--model <model>]
```

`miyu setup` sets up the first model: you pick a provider, paste the key, test the connection and pick the model, and it is then written to the system config.

| Argument | What it does |
|---|---|
| `--provider <id>` | Uses this provider from the model catalog, without asking you to pick one |
| `--env <var>` | Reads the key from this variable in the core's environment, without asking you to paste it |
| `--model <model>` | Uses this model, without asking you to pick one |

When not run in a terminal, `--provider` is required, and the key is read from a pipe:

```bash
echo "$KEY" | miyu setup --provider deepseek
```

```powershell
$key | miyu setup --provider deepseek
```

In a terminal, the key is not shown while you paste it, and you can press `Ctrl+C` to cancel; on Linux and macOS, pressing `Ctrl+D` before typing anything also cancels.

Exit codes: `0` means the config was written; `1` means nothing was picked, no key was received, the connection test failed, or the core refused the request; `2` means bad arguments, or that it was not run in a terminal and `--provider` was not given; `130` means you cancelled while pasting the key. See [Models](models.md#quick-setup-miyu-setup).

## miyu provider

```text
miyu provider login [<name>]
miyu provider list [--format <text|json>]
miyu provider logout [<name>]
```

`miyu provider` stores, lists and removes keys:

| Subcommand | What it does |
|---|---|
| `login [<name>]` | Stores a key. Without a name, in a terminal you pick from the names the config uses and the ones already stored. The key is not shown while you paste it, and it can also be read from a pipe |
| `list` | Lists the stored keys, and the ones the config uses but that are not stored yet (shown in gray). The keys themselves are not shown |
| `logout [<name>]` | Removes a key. Without a name, in a terminal you pick from the stored ones |

For example:

```bash
echo "$KEY" | miyu provider login acme
```

```powershell
$key | miyu provider login acme
```

You cancel while pasting a key in the same way as in `miyu setup`.

Exit codes: `0` means success; `1` means the core refused the request, no key was received, nothing was picked, or the key to remove was never stored; `2` means the name is not in the allowed form, or that no name was given and it was not run in a terminal; `130` means you cancelled while pasting the key. See [Models](models.md#storing-keys).

## miyu config

```text
miyu config <subcommand> [<options>]
```

`miyu config` views and changes the config, and trusts project configs:

| Subcommand, argument | What it does |
|---|---|
| `get [<key>…] [--format <text\|json>]` | Prints the values in effect. Without a key, it prints all of them; with exactly one key, it prints only the value |
| `set <key> <value>` | Changes one setting and writes it to the system config `~/.miyu/etc/config.toml`. It does not accept `--project`, because a project config can only be edited by hand |
| `unset <key>` | Removes one item from the system config, so that it goes back to the default |
| `edit [--project]` | Opens the system config in an editor (with `--project`, the project config of the current directory), and checks it before saving. The editor is chosen from `VISUAL` and `EDITOR`; if neither is set, it is `vi` on Linux and macOS and `notepad` on Windows |
| `explain <key> [--format <text\|json>]` | Prints what each layer says for this item, and which layer is in effect |
| `path [--project]` | Prints the path of the system config; with `--project`, it prints the path of the project config of the current directory |
| `trust [--yes \| --no]` | Shows what the project config in the current directory would change, and then lets you decide whether to trust it. `--yes` trusts it and `--no` does not, and neither asks |

Running just `miyu config` in a terminal opens the settings page of the default interface; if the interface has no settings page, or it is not run in a terminal, it prints the help, with exit code `2`.

For example, to see the value of `models.chat` in each layer:

```sh
miyu config explain models.chat
```

Write list values as a TOML array. In bash, wrap the whole value in single quotes; in PowerShell, use double quotes outside and TOML single-quoted strings inside (because Windows PowerShell 5.1 strips the double quotes in arguments):

```bash
miyu config set skills.external.dirs '["~/.agents/skills", "~/my-skills"]'
```

```powershell
miyu config set skills.external.dirs "['~/.agents/skills', '~/my-skills']"
```

Exit codes: `0` means success; `1` means the core refused the request (no such key, a wrong value, or the file has errors); `2` means bad arguments, or that `edit` was run outside a terminal, or that `trust` was run without `--yes` or `--no`. See [Configuration](config.md).

## miyu pkg

```text
miyu pkg [<subcommand>] [<options>]
```

`miyu pkg` installs, removes and inspects packages. Without a subcommand, it runs `list`.

| Subcommand | pacman form | What it does |
|---|---|---|
| `list` | `-Q` | Lists the installed packages |
| `install <package>` | `-U` | Installs a package. `<package>` can be a directory with a `package.toml`, a `.miyu` package file, or an id (to install from the package source, or to put back a removed shipped package) |
| `remove <id>` | `-R` | Removes a package along with its state; its config directory and its settings in the config file are kept |
| `info <package>` | | Shows a package's information. For a package that is not installed, it looks in the package source; if you give a directory or a `.miyu` file, it only shows the information and does not install anything |
| | `-Qi <id>` | Looks only at installed packages |
| | `-Si <id>` | Looks only at the package source |
| `files <id>` | `-Ql` | Lists the files it installed |
| `owns <path>` | `-Qo` | Finds which package a file belongs to |
| `check [<id>]` | `-Qk` | Checks whether installed files were changed or are missing |
| `page <id>` | | Opens its dashboard page in the browser |
| `pack <dir>` | | Packs a package directory into a `.miyu` file, without connecting to the core |
| `update` | `-Sy` | Fetches the new index from the package source |
| `search [<words>…]` | `-Ss` | Searches the package source, and results must match all the words; without words, it lists everything |
| `upgrade` | `-Su` | Upgrades the installed packages from the package source. `-Syu` fetches the index first and then upgrades |
| `clean` | `-Sc` | Removes package files from the cache that are not the installed version |
| | `-S <id>…` | Installs these packages from the package source |

| Option | What it does |
|---|---|
| `--format <text\|json>` | The output format |
| `--yes`, `--noconfirm` | Does not ask before installing, upgrading or removing, and approves the capabilities the packages need |
| `-n`, `--purge` | With `remove`, deletes the config directory and its settings in the config file as well |
| `--target <system>` | Which system `pack` builds for; if the manifest has `targets`, you must pick one of them |
| `-o`, `--out <dir>` | Which directory `pack` writes to; without it, the current directory |
| `--print` | With `page`, only prints the address and does not open a browser |

For example, to search for and install the OCR package:

```sh
miyu pkg search ocr
miyu pkg install ocr
```

Exit codes: `0` means success; `1` means the core refused the request, or `search` found nothing, or `owns` found no package the file belongs to, or `check` found changed or missing files; `2` means bad arguments. See [Packages](packages.md).

## miyu mcp

```text
miyu mcp login <server>
miyu mcp logout <server>
```

`miyu mcp` logs in to and out of MCP servers that need browser authorization:

| Subcommand | What it does |
|---|---|
| `login <server>` | Logs in to a URL-based MCP server that accepts only browser authorization. The command prints the address of the authorization page and tries to open a browser; once you agree, the token is stored in the secrets file and the server connects automatically. If the browser is on another computer, after authorizing, paste the full address from the browser's address bar back and press Enter. It waits up to 10 minutes |
| `logout <server>` | Deletes the stored login |

`<server>` is the name of the MCP server in the config or in a package.

For example:

```sh
miyu mcp login acme-docs
```

Exit codes: `0` means it connected or logged out; `1` means the core refused the request, the server was still not connected when the wait ran out, or the core cannot be reached. See [Extending Miyu](extending.md).

## miyu bus

```text
miyu bus [list [<name>]] [--format <text|json>]
```

`miyu bus` shows which package provides what on the bus. Without a subcommand, it runs `list`. Packages provide features on the bus by name and do not hard-code each other's package names; `list` shows who provides each name and whether it can be used, and with a name, it lists only that name.

For example:

```sh
miyu bus list render
```

For details, see [Packages](packages.md).

## miyu dev

```text
miyu dev driver-check <id>
```

`miyu dev` is for people who write packages: `driver-check` checks whether the model driver encoding that this package provides is steady. The check restarts the package's extension, so it does not run while a session is using it. The exit code is `0` when all checks pass, and `1` when some do not. See [Writing a Miyu package](../dev/packages.md).

## miyu memory

```text
miyu memory [<subcommand>] [<options>]
```

`miyu memory` manages memories. Without a subcommand, it runs `list`. Options can go either before or after the subcommand.

| Subcommand | What it does |
|---|---|
| `list` | Lists memories, newest first |
| `search <words>…` | Searches memories |
| `add <text>…` | Records a memory |
| `edit <m-number> [<text>…]` | Edits a memory and prints its new number; if you change only `--keywords` or `--who`, you do not need to write the text |
| `forget <m-number>` | Voids a memory |
| `clear session [<id>]` | Clears the memories a session recorded. Without an id, the session given by `-s` is used, and if there is no `-s` either, it is the session of the last `miyu ask` |
| `clear me` | Clears this whole memory: all classes, the cards of people you know, and what is known about you. The command does not ask first, and what it clears cannot be recovered |
| `dream` | Organizes memories right away. You can press `Ctrl+C` to stop it, and what is already organized is kept |
| `cards` | Lists person cards |

A memory is written as `m` plus a number, for example `m12`; use the number as `list` prints it.

| Option | What it does |
|---|---|
| `--persona <id>` | Uses this persona's memories; without it, the default persona's memories are used. Cannot be used together with `-s` |
| `-s`, `--session <id>` | Uses the memory that this session uses |
| `--forgotten` | With `list` and `search`, also lists the voided memories |
| `--class <user\|feedback\|episode\|reference\|person>` | With `list`, lists only this class; with `add`, records the memory as this class, which is `user` if omitted |
| `--why <reason>` | With `forget`, writes down why the memory is forgotten |
| `--keywords <words>` | For `add` and `edit`: keywords for retrieval, separated by commas; with `edit`, an empty value removes them |
| `--who <who>` | For `add` and `edit`: who a person memory is about, written as a platform id or a name. Required for `add --class person` |
| `--format <text\|json>` | The output format of `list` and `search` |

For example, to record a memory with keywords:

```bash
miyu memory add --keywords editor,vim The user writes code in Neovim
```

```powershell
miyu memory add --keywords 'editor,vim' The user writes code in Neovim
```

Exit codes: `0` means success; `1` means the core refused the request; `2` means bad arguments; `3` means `dream` was stopped by `Ctrl+C`. See [Memory](memory.md).

## miyu kb

```text
miyu kb [<subcommand>] [<options>]
```

`miyu kb` manages knowledge bases. Without a subcommand, it runs `list`. Removed documents and deleted knowledge bases are moved to the system trash. Options can go either before or after the subcommand.

| Subcommand | What it does |
|---|---|
| `list [<kb>]` | Lists knowledge bases; with a kb, lists the documents in it |
| `search <words>…` | Searches knowledge bases |
| `read <kb> <document>` | Reads one page of a document |
| `new <kb>` | Creates a knowledge base |
| `edit <kb>` | Changes the name and description, and turns auto recall on or off |
| `add <kb> <file>…` | Adds files to the knowledge base, at most 20 MiB each |
| `remove <kb> <document>` | Removes a document |
| `mount <kb> <dir>` | Mounts an existing directory as a read-only knowledge base |
| `delete <kb>` | Deletes the whole knowledge base; a mounted one is only unregistered, and its directory is left untouched |
| `reindex <kb>` | Rebuilds the index |

| Option | What it does |
|---|---|
| `--kb <kb>` | With `search`, searches only this knowledge base |
| `--page <page>` | With `read`, which page to read; without it, page 1 |
| `--name <name>` | For `new`, `edit` and `mount`: the display name |
| `--description <description>` | For `new`, `edit` and `mount`: a one-sentence description |
| `--auto` | For `new`, `edit` and `mount`: turns on auto recall, which brings in the opening of a section whenever the conversation mentions that section |
| `--no-auto` | For `edit`: turns auto recall off |
| `--to <dir>` | With `add`, puts the files in this directory of the knowledge base |
| `--replace` | With `add`, replaces an existing document of the same name |
| `--format <text\|json>` | The output format of `list` and `search` |

For example, to mount an existing directory as a knowledge base:

```sh
miyu kb mount handbook ~/Documents/handbook --name "Team handbook" --auto
```

`<kb>` is a knowledge base's id: it starts with a lowercase letter, contains only lowercase letters, digits, `-` and `_`, is at most 64 characters long, and cannot be a Windows reserved name such as `con`, `nul` or `com1`. If the id is in the wrong form, it reports `invalid knowledge base id: <id>`.

Exit codes: `0` means success; `1` means the core refused the request; `2` means bad arguments. See [Knowledge base](knowledge.md).

## miyu schedule

```text
miyu schedule [<subcommand>] [<options>]
```

`miyu schedule` manages schedules. Without a subcommand, it runs `list`. At the set time, a schedule hands a message to a session to run one turn; runs missed while the core is stopped are not made up.

| Subcommand | What it does |
|---|---|
| `list [--session <id>]` | Lists schedules; with a session, lists only the schedules that run on it |
| `add <message>…` | Adds a schedule. The time is given with one of `--cron`, `--at` and `--every` |
| `rm <id>` | Removes a schedule |
| `pause <id>` | Pauses a schedule |
| `resume <id>` | Resumes a schedule, counting the next run from now |

A schedule's id is the first column of each line that `list` prints, for example `t1`.

The options of `add` are:

| Option | What it does |
|---|---|
| `--cron <fields>` | Runs on a cron expression, for example `'0 8 * * *'` |
| `--once` | Runs the cron only once |
| `--zone <zone>` | The time zone the cron uses, for example `Asia/Tokyo`; without it, this machine's time zone is used |
| `--at <time>` | Runs once at this time: `'2026-10-28 08:00'` (this machine's time zone) or `2026-10-28T08:00:00+09:00` |
| `--every <interval>` | Runs repeatedly at this interval: a number of seconds, or `90s`, `10m`, `2h`, `1d`; the interval is at least 60 seconds |
| `--session <id>` | Runs on this existing session. Cannot be used together with the four options below |
| `--persona <persona>` | Opens a new session each time, with this persona |
| `--no-persona` | Opens a new session with no persona each time |
| `--preset <preset>` | The new session uses this preset |
| `--cwd <dir>` | The new session's working directory; without it, each new session uses its own default workspace `~/.miyu/root/workspace/<session id>/` |

`--once` and `--zone` can be used only with `--cron`. `list` also accepts `--format <text|json>`.

For example, to have the AI check CI every morning at 8:

```sh
miyu schedule add --cron '0 8 * * *' --zone Asia/Shanghai Check last night's CI run and list any failures
```

Exit codes: `0` means success; `1` means the core refused the request; `2` means bad arguments. See [Letting the AI keep working on its own](automation.md).

## miyu service

```text
miyu service <enable|disable|status> [--format <text|json>]
```

`miyu service` makes the core start automatically at boot or login:

| Subcommand | What it does |
|---|---|
| `enable` | Writes the service file and hands it to the system's service manager, so that the core starts at boot or login from then on |
| `disable` | Stops the service, removes it from the service manager, and deletes the service file |
| `status` | Shows whether the service is installed and whether it is turned on |

Linux uses a systemd user service, or desktop autostart where there is none; macOS uses launchd; Windows uses a scheduled task that runs at logon. The service covers only your own user. On Windows, the service cannot be installed when `MIYU_HOME` is set, and it reports `cannot install the service: a Windows scheduled task cannot carry MIYU_HOME`.

For example:

```sh
miyu service enable
```

Exit codes: `0` on success, and also `0` when the service was not installed to begin with and for `status`; anything else is `1`. See [Keeping it running, and servers](service.md).

## miyu upgrade

```text
miyu upgrade [--prerelease] [--yes]
```

`miyu upgrade` upgrades Miyu:

| Argument | What it does |
|---|---|
| `--prerelease` | Counts pre-releases too |
| `--yes` | Upgrades directly, without asking |

If Miyu was installed by the install script, the command downloads the new version, verifies the signature and checksum, and then replaces the old version; if it was installed from the AUR or Homebrew, the command tells you which package manager command to use; if the archive was unpacked by hand, the command tells you the download address. After the upgrade, the core that is already running is still the old version; you need to run `miyu core stop`, and the next time it is opened it is the new version. On Windows, a running `miyu.exe` cannot be deleted, so it stays in `.miyu-old-<old version>/` in the install directory and is deleted at the start of the next `miyu upgrade`. If your system has no release archive (for example a Mac with an Intel chip, or Windows on ARM), it reports `cannot upgrade: no release is built for this system`, with a hint saying which systems have release archives and that on other systems you need to download the source from the release page and build it yourself.

For example:

```sh
miyu upgrade --yes
```

Exit codes: `0` when the upgrade finished, when Miyu is already the latest version, when you should upgrade with the package manager, or when it only gave the download address; anything else is `1`. See [Installing, upgrading and uninstalling](install.md#upgrading).

## miyu core

```text
miyu core start
miyu core status [--format <text|json>]
miyu core stop
```

`miyu core` manages the core running in the background. Interfaces and commands start the core by themselves when they need it, so you do not need to manage it by hand; if you want to start the core ahead of time, see whether it is running, or stop it, use these three commands.

- `start`: if the core is not running, starts it, waits until it is ready and then returns, printing nothing on success; if the core is already running, it does nothing. This command only starts the core, and opens neither an interface nor a browser. If the core fails to start, it says why, and the exit code is `1`.
- `status`: only looks, and never starts the core. When the core is running, it prints three lines: the state, the version (the one the core itself reports; after an upgrade and before a restart, it differs from `miyu --version`) and the data root; when the core is not running, it prints the state, the data root and a one-line hint.
- `stop`: tells the running core to stop, waits until it has exited and then returns, printing nothing on success. If the core is not running, it does nothing, and the exit code is `0`. If the request is refused, the core cannot be reached, or the core has not exited within 60 seconds, the exit code is `1`.

For example, to start the core and check its status:

```sh
miyu core start
miyu core status
```

When the core is running, the output of `status` looks like this:

```text
The core is running
version: 2026.11.0
data root: /home/alice/.miyu
```

Exit codes of `status`: `0` means running, `3` means not running, and `1` means an error (for example the core is still running but cannot be reached). Adding `--format json` prints one line of JSON for scripts, with the same exit codes and these fields:

| Field | What it is |
|---|---|
| `running` | Whether it is running |
| `version` | The core's version; `null` when it is not running |
| `data_root` | The absolute path of the data root |

## miyu check

```text
miyu check [<file>] [--format <text|json>]
```

`miyu check` checks the files you write by hand that Miyu reads, looking for mistakes. Without a file, it checks all of them; with a file, it checks only that file.

For example:

```sh
miyu check ~/.miyu/root/personas/miyu/prompts/examples.md
```

For which files it checks and how to read the result, see [Troubleshooting](troubleshooting.md#run-miyu-check-first). The exit code is `1` when there are errors, and `0` when there are only warnings.

## miyu rescue

```text
miyu rescue [<args>…]
```

`miyu rescue` fixes the core with LiteMiyu's rescue mode when the core has a problem. It does not connect to the core; instead it fills in the `LITEMIYU_RESCUE_*` environment variables from `models.chat`, runs `litemiyu --rescue`, and hands it the remaining arguments unchanged; variables that are already set are left alone. It looks for `litemiyu` in the directory `miyu` is in, then in the directory `miyu` actually lives in, and then in `PATH`. It hands over to `litemiyu` in the same way as described in [Commands added by packages](#commands-added-by-packages).

For example:

```sh
miyu rescue
```

LiteMiyu exists only for Linux. On macOS and Windows it cannot be found, and the command prints `litemiyu not found` with the hint `only Linux is supported for now`.

The exit code is `litemiyu`'s exit code; it is `1` when `litemiyu` cannot be found. See [Rescue](rescue.md).

## miyu call

```text
miyu call <tool> --<param> <value>…
miyu call <tool> --json '<object>'
miyu call <tool> --json -
miyu call --schema <tool>…
```

`miyu call` calls this session's tools from a command the AI runs, for use in scripts the AI writes. It works only inside a command that Miyu runs, in a session with `Call tools from the command line` turned on; if you run it in your own shell, the exit code is `2`.

- `--<param> <value>`: the value is sent as text and then converted to a number or a boolean according to the tool's parameter format; giving the same parameter several times makes a list.
- `--json`: passes a JSON object; write `-` to read it from standard input. Named parameters override keys of the same name in the object. Windows PowerShell 5.1 strips the double quotes in arguments, so you need to use a pipe instead.
- `--schema <tool>…`: prints the parameters of these tools.

A tool with a structured result prints one line of JSON, and other tools print text. The commands the AI runs use bash on Linux, zsh on macOS and PowerShell on Windows (see [Tools the AI can use](tools.md#shell)), so write the script for that shell:

```bash
miyu call web_search --query niri | jq -r '.links[].site' | sort | uniq -c
```

```powershell
(miyu call web_search --query niri | ConvertFrom-Json).links.site
'{"query": "niri"}' | miyu call web_search --json -
```

Exit codes: `0` means success; `1` means the tool failed or was denied; `2` means wrong usage, or that it is not running inside a command Miyu runs; `3` means it was interrupted, or the command it belongs to has already ended; `4` means confirmation is needed, in which case you need to call this tool directly instead.

## miyu tui

```text
miyu tui [--resume <id> | --page <page> | config]
```

`miyu tui` opens the terminal UI.

| Argument | What it does |
|---|---|
| No arguments | Starts a new session or continues the most recent one, following the `On start, open` (`ui.startup`) setting |
| `--resume <id>` | Opens this session; you must give the full id; if it cannot be opened, it reports an error and exits |
| `--page config`, `config` | Opens only the settings page, without entering a session; on the settings menu, press `Esc` to exit |
| `--page oobe` | Goes through the first-run guide again |
| `-h`, `--help` | Prints the help |

If you give a page name it does not recognize, it opens the home page as usual. Setting the environment variable `MIYU_TUI_IME=0` makes the terminal UI not switch input methods (the terminal UI switches them only when you use the fcitx5 input method).

For example:

```sh
miyu tui --resume 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90
```

For details, see [Terminal UI](heads/tui.md).

## miyu shellhook

```text
miyu shellhook <subcommand> [<options>]
```

`miyu shellhook` installs Miyu into a shell. Once it is installed, typing a message after the prompt and pressing Enter talks to the AI.

| Subcommand | What it does |
|---|---|
| `install [--shell <fish\|bash\|zsh\|pwsh\|powershell>] [--program <path>]` | Installs into a shell. `pwsh` is PowerShell 7, and `powershell` is the Windows PowerShell 5.1 that comes with Windows. Without `--shell`, it works the shell out by itself: on Linux it looks at the parent process, and at `SHELL` if it cannot recognize that; on macOS it looks at `SHELL`; on Windows it looks at `SHELL`, and if that is absent, it uses `PSModulePath` to tell PowerShell 7 from 5.1. If the old version (0.7.x) left a shell integration in that shell, it is backed up and cleaned up first; see [Terminal UI](heads/tui.md#cleaning-up-the-old-versions-integration) |
| `uninstall [--shell <fish\|bash\|zsh\|pwsh\|powershell>]` | Removes it from a shell |
| `status` | Shows which shells it is installed in, and whether the old version's integration is still there |
| `doctor` | Checks whether it is installed properly, whether it can reach the core, the terminal's colors and the clipboard |

`--program <path>` is the program the shell calls; without it, it is the `miyu` next to this program.

For example:

```sh
miyu shellhook install --shell zsh
```

Exit codes: `2` for bad arguments; `1` when one of the `doctor` checks fails. See [Terminal UI](heads/tui.md).

## miyu web

```text
miyu web [<options>]
miyu web stop
miyu web status
```

`miyu web` opens the web UI: if the web UI is not running, it is started in the background first, and then handed to the browser to open; the command returns right away and does not hold the terminal. The web UI keeps running after you close the browser.

| Argument | What it does |
|---|---|
| `--port <port>` | Which port to listen on this time (it takes effect only when the web UI is not running); `8300` by default |
| `--print` | Does not open a browser, and only prints the address |
| `--format <text\|json>` | The format of what is printed; `json` does not open a browser either |
| `--reset` | Opens with a one-time code, to reset the access password |
| `--logout` | Makes every browser log in again |
| `--package <id>` | Opens this package's page in `Dashboards` directly |
| `--session <id>` | Opens this session directly |
| `--settings [<page>]` | Opens the settings directly; write `access` to open `Access` in `General` |
| `-h`, `--help` | Prints the help |

- `stop`: stops the web UI, while the core keeps running. The text goes to standard error: it prints `stopped the web interface` when it stopped the web UI, and `the web interface is not running` when it was not running, both with exit code `0`; it prints `miyu: cannot stop the web interface: <reason>` when it could not stop it, with exit code `1`.
- `status`: shows whether the web UI is running, with the text going to standard output: when it is running, it prints `the web interface is running: <address>`, with exit code `0`; when it is not running, it prints `the web interface is not running`, with exit code `3` (the same set of codes as `miyu core status`).

Neither of these commands connects to the core, so they do not start the core when it is not running; no other arguments may follow them.

For example:

```sh
miyu web --settings access
miyu web status
```

Bad arguments give exit code `2`. See [Web UI](heads/web.md) and [Keeping it running, and servers](service.md#opening-the-web-ui-from-other-computers-and-phones).
