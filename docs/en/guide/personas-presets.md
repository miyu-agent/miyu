# Personas and presets

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Every session has one persona and one preset open. This page covers what each one controls, how to choose, switch and set defaults, and how to write your own. Chinese version: [中文](../../zh/guide/personas-presets.md).

## What each one controls

- A **persona** controls who the AI is and how it speaks: the persona prompt, example dialogs and persona reminders are all put together into the system prompt sent to the model. You can also use no persona, in which case the AI carries only Miyu's own system prompt.
- A **preset** controls which features are on in this session: which tools, skills, scripts, MCP servers and slash command templates can be used, and what environment information is injected into the conversation. A session always has a preset.

The two are chosen independently, so mix them as you like. Persona memory follows the persona: sessions with the same persona share one memory, and sessions with no persona share another; see [Memory](memory.md). A session whose preset does not have "Persona memory" on does not record or recall anything.

## Shipped presets

| Called in the interface | Id | What is on | When to use it |
|---|---|---|---|
| Everything | `full` | Everything installed, and anything installed later | It is the default |
| Development | `dev` | The three groups Base system, Injected environment, and Tasks and schedules; web search, persona memory, and the two skills for writing skills and packages. Nothing else, and nothing installed later | Writing code, without extras such as extensions and MCP servers |
| Minimal | `minimal` | Only four tools, for reading files, creating files, editing files and running commands, and the eight environment items | You want the AI to work the way the model knows how, with as few tools as possible |
| Nothing | `none` | Nothing, and nothing installed later | Chat only; or use it as a base and turn on a few things yourself |

The shipped default preset is `full`.

## Shipped persona

One persona is shipped, "Software Engineer" (id `software-engineer`), brought by the shipped package "Software Engineer persona" (`base-persona-engineer`). It is for writing code: its persona prompt asks for the simplest method first, verification with independent evidence, stopping once the work is done and verified, and concise speech. The AI can pick it when it dispatches a subagent.

No default persona is set at the factory: new sessions where you do not choose use no persona. Deleting this persona means uninstalling that package; to get it back, install `base-persona-engineer` again (see [Packages](packages.md)).

## Which one a new session uses

- First-run setup: the "Create a persona" step creates a persona (you can skip it), and the one created becomes the default persona; what you choose in the "Choose a preset" step becomes the default preset, and there you can also make a new one with "Custom".
- Terminal: when you open a new session, the place of the input box first shows "Choose a persona" and then "Choose a preset", and you can type only after choosing. The first line of the persona box is "No persona". `↑` and `↓` choose, `Enter` confirms, `e` edits the one under the cursor, and `a` creates a new one; in the preset box, `Esc` goes back to the persona box to choose again. The cursor starts on the one the previous session used. If you do not want to be asked every time, turn on "General → New sessions → Auto-select persona and preset" (`tui.auto_pick`) on the settings page, and new sessions use the defaults directly.
- Web UI: above the input box of an empty session there are two buttons, "Select persona" and "Select preset"; if you do not click them, the defaults apply. When the default preset cannot be used (the file is wrong, or it was deleted), the input box is locked and says "Select a preset"; you can type only after choosing one.
- Command line: `miyu ask --persona <persona>`, `--no-persona` and `--preset <preset>`, written as ids. They affect only a newly started session, and cannot be combined with `-c` or `-s`:

  ```sh
  miyu ask --persona software-engineer --preset dev "Why are this repository's tests slow?"
  ```

- Schedules: `miyu schedule add` takes the same `--persona`, `--no-persona` and `--preset`, which apply to each session it starts new; they cannot be combined with `--session`. See [Letting the AI keep working on its own](automation.md).
- Which persona and preset a session on a chat platform uses follows the platform's own rules, see [Connecting chat platforms](heads/im.md). A session created in a project in the web UI follows the persona and preset the project sets.

## Switching in an open session

- Terminal: type `/persona` or `/preset` and choose in the box. While the AI is answering, the box does not open, and shows "A reply is in progress: stop it or wait for it to finish".
- Web UI: click the session title at the top left of the conversation area, click "Persona" or "Preset" in the menu, choose one, then click "Confirm" (when there is not yet a conversation that can be compacted, it does not ask and switches directly). You can also type `/persona` or `/preset`. A session in a project is decided by the project; typing it says "This session is in a project; the project sets its persona and preset".

When you switch, Miyu first compacts the earlier conversation into a summary under the old persona, and the new one is used from the next turn. After you switch persona, memory is recorded into the new persona's memory from this turn on, and what was recorded before stays with the old persona. Switching preset does not change whether memory is on: it stays as it was when the session started. A subagent's session cannot be switched.

## Defaults

| Key | What it controls | On the settings page |
|---|---|---|
| `persona.default` | Which persona new sessions use by default. With none set, new sessions use no persona; if it points to a persona that no longer exists, that also counts as not set, and `miyu config set` and `miyu check` warn about it | "General → New sessions → Default persona" |
| `preset.default` | Which preset new sessions use by default; `full` as shipped. If it points to a preset that does not exist, opening a new session reports an error and does not quietly switch to another; `miyu config set` accepts it and adds a warning line, and `miyu check` warns too | "General → New sessions → Default preset" |
| `terminal.persona` | Which persona a newly started shell integration session uses, that is, the session you enter when you talk to Miyu straight from the shell. With none set, it follows `persona.default` | "General → Shell integration session" |
| `terminal.preset` | Same as above, for the preset. With none set, it follows `preset.default` | "General → Shell integration session" |

Write ids as values. A change applies to sessions opened later; open ones do not change:

```sh
miyu config set persona.default software-engineer
miyu config set preset.default dev
```

## Writing your own persona

A persona is a folder `~/.miyu/root/personas/<id>/` in the data root (`~/.miyu` by default, and `%USERPROFILE%\.miyu` on Windows). The id is the folder name: it starts with a lowercase letter, contains only lowercase letters, digits, `-` and `_`, and is at most 64 characters. It cannot be one of the Windows reserved names `con`, `nul`, `aux`, `prn`, `com1` to `com9` and `lpt1` to `lpt9`; these are refused on all three systems.

```text
~/.miyu/root/personas/captain/
├── persona.toml          # name, description, and a few settings
├── avatar.png            # avatar, optional
├── background.jpg        # background image, optional
└── prompts/
    ├── persona.md        # persona prompt
    ├── examples.md       # example dialogs
    └── reminders.md      # persona reminders
```

Every part is optional, and an empty folder still counts as a persona. Once you put it there, new sessions can choose it.

`persona.toml`:

```toml
[persona]
name = "Old Captain"                         # the name, cannot be empty
summary = "An assistant who talks like an old sailor"  # a short description, for you; the model does not see it
subagent = true                              # whether the AI can pick it when dispatching a subagent

[knowledge]
bases = ["sea-charts"]          # with this persona, only these knowledge bases can be searched

[appearance]
seed = "#2f6f9f"                # theme color
background_opacity = 40         # how much of the background image shows, 0 to 100
background_focus = [50, 30]     # where the background image is centered, horizontal and vertical, each 0 to 100
background_blur = 10            # how much the background image is blurred, 1 to 100
```

| Field | Description |
|---|---|
| `persona.name` | The name. Can also be written as `{ zh = "…", en = "…", ja = "…" }`, and the interface picks by language |
| `persona.summary` | A short description, written the same way as `name`; can be an empty string |
| `persona.subagent` | `true`: the AI can pick this persona when it dispatches a subagent, and the name and short description are shown to the model together. If not written, it cannot |
| `knowledge.bases` | A list of knowledge base ids; only the ones listed can be searched; `[]` means none can be searched. If not written, all can be searched |
| `appearance.seed` | `#rrggbb`; the terminal and web UI take their colors from it. If not written, colors are taken from the avatar |
| `appearance.background_opacity` | An integer from 0 to 100 |
| `appearance.background_focus` | Two integers, each from 0 to 100 |
| `appearance.background_blur` | An integer from 1 to 100; if not written, no blur |

Only these tables and these fields are recognized; writing anything else is an error.

The files in `prompts/`:

- `persona.md`: the persona prompt: who this persona is, how it speaks, how it treats you. It is put as is at the very start of the system prompt, in any language.
- `examples.md`: example dialogs, placed after the system prompt and before the conversation. A line starting with `user:` is what you say, and a line starting with `assistant:` is what the AI answers; a line with no prefix continues the previous one, and blank lines do not count. It must start with `user:`, alternate question and answer, and end with `assistant:`:

  ```text
  user: What's the weather like today?
  assistant: Calm seas, fair for sailing.

  user: Take a look at this code for me
  assistant: Hand it over, the old captain will have a look.
  ```

- `reminders.md`: persona reminders, a short passage that reminds the AI not to break character. When the preset has "Persona reminders" on, the AI sees it again every 3 turns, and one more sentence is added at the end of the system prompt asking the AI to stay in character even after it has called tools. If you do not want it, delete this file, or turn off "Persona reminders" in the preset (the shipped "Development" and "Minimal" do not have it on).

Put the avatar in `avatar.png`, `avatar.jpg` or `avatar.webp`, and the background image in `background.png`, `background.jpg` or `background.webp`. When changed in the interface, the avatar can be at most 1 MiB and at most 1024 in width and height, and the background image at most 5 MiB and at most 4096 in width and height.

After you change a file, new sessions use the new one; an open session switches to the new persona prompt, example dialogs and persona reminders at the start of its next turn. Check mistakes with `miyu check`, which says which line of which file is wrong and how; an open session that meets a mistake keeps using the old one.

## Writing your own preset

A preset is a file `~/.miyu/root/presets/<id>.toml`, where the id is the file name, written the same way as a persona id. A read-only code review preset that turns on only reading files, finding files and searching contents, and tells the AI the working directory:

```toml
# ~/.miyu/root/presets/review.toml
[preset]
name = "Code review"
summary = "Can only read files, find files and search contents"
icon = "search"
unlisted = "off"

[features]
read = true
glob = true
grep = true
env-workdir = true
```

The `[preset]` table:

| Field | Description |
|---|---|
| `name` | The name, written the same way as a persona's |
| `summary` | A one-line description, for you; not sent to the model |
| `icon` | The icon, written as an icon name from [Lucide](https://lucide.dev) |
| `unlisted` | Whether features not written are on: `on` is on, `off` is off. Features installed later follow it too. `on` if not written |

The other tables:

| Table | How to write it | What it controls |
|---|---|---|
| `[features]` | `<feature id> = true` or `false` | Whether one feature is on |
| `[software]` | `<package id or group name> = true` or `false` | Whether a whole package or a whole group is on |
| `[tools]` | `<tool name> = false` | Turns off a single tool within the features that are on. Only `false` can be written |
| `[limits]` | `unattended_steps = <positive integer>` | The most times a turn can call the model when no one is watching; `500` if not written. It covers sessions on chat platforms, sessions a schedule starts new, `miyu ask`, and, in a session someone is watching, the turns you did not start (such as those run by a schedule or a goal continuing) |

Whether a feature is on is decided in this order: `[features]` names it; `[software]` names the package it is in; `[software]` names the group the package is in; if none of these, `unlisted` decides. Naming something that is not installed is not an error.

Feature ids:

| What | Id |
|---|---|
| Shipped tools | Mostly the same as the tool name, for example `read`, `shell`, `subagent`. The ones that differ: `web_search` is `web-search`, `web_fetch` is `web-fetch`, `send_message` and `sessions` are one feature, `sessions`; `remember`, `memory_search` and `forget` are `memory`; the five `kb_*` are `knowledge`; the three `cron_*` are `schedule`; `schedule_next` is `loop`. For the full table see [Tools the AI can use](tools.md) |
| Shipped features without tools | The environment info items `env-time`, `env-workdir`, `env-permission`, `env-session`, `env-model`, `env-harness`, `env-machine`, `env-profile`; automatic injection of AGENTS docs `project-docs`; calling tools from the command line `clicall`; persona reminders `roleplay` |
| Skills | `skill-<skill name>` |
| Scripts | `script-<tool name>` |
| MCP servers | `mcp-<server name>` |
| Slash command templates | `command-<command name>` |

The groups you can write in `[software]`:

| Group name | Called in the interface | What is in the group |
|---|---|---|
| `basesystem` | Base system | Read files, New file, Edit files, Find files, Search contents, Move to trash, Commands, Background, Call tools from the command line, Subagents, Ask the flagship model, Questions, Show to the user, Messages between sessions, Session history, Usage lookup, Packages |
| `tasks` | Tasks and schedules | To-do list, Long-running goals, Scheduled tasks, Loop tasks |
| `environment` | Injected environment | The eight environment info items, automatic injection of AGENTS docs |
| `persona` | Persona | Persona memory, Persona reminders |
| `research` | Research | Web search, Knowledge base |

To change a little on top of a shipped preset, write only what you changed. For example, to turn off web search in Everything, the file is `full.toml`:

```toml
# ~/.miyu/root/presets/full.toml
[features]
web-search = false
```

After you change the file, new sessions use the new one; an open session switches to it from its next turn. Use `miyu check` to see whether anything is wrong.

### The master switches on the settings page

In settings, each skill, script and MCP server has a switch, recorded in `features.<feature id>` (for example `features.mcp-github`). It only applies to presets with `unlisted = "on"`, and if the preset writes on or off for that item, the preset wins. In a preset with `unlisted = "off"`, anything not named stays off as before.

## Creating and changing in the interface

- Terminal: the "Personas" and "Presets" items of the main menu of the settings page (`/settings`). In the list, `a` creates a new one: fill in a name, and the id can be left empty for Miyu to make up; `Enter` opens one to change. For a persona you can change the name, short description, whether subagents can pick it, avatar, the detailed persona prompt, example dialogs and persona reminders; for the prompts, press `Enter` to write in an editing window, or press `Ctrl+G` to hand it to an external editor (`$VISUAL`, or `$EDITOR` if that is not set, or `vi` if neither is set); on Windows there is no external editor option, so write in the editing window or paste into it. For a preset you can change the name, the description, and the switch of every feature and every tool, toggled with `Space`, `Tab` or `Enter`, and `Ctrl+A` toggles all; each change is saved as you make it. In the window, `d` deletes; for a shipped one or one that came with a package that you changed, `d` restores the shipped version. In the picker for a new session, `e` and `a` open the same windows.
- Web UI: the "Personas" and "Presets" pages in settings can create, change and delete. In an open session, click the session title at the top left; the pencil on the "Persona" row is "Edit this persona".

When you change a shipped one or one that came with a package in the interface, it is saved in your layer, writing only what you changed. A deleted persona goes to the trash and is kept for 7 days; a deleted preset cannot be recovered.

## How the three layers stack

Personas and presets both have three layers, from the bottom up:

1. Shipped: installed with Miyu.
2. Package-provided: the `personas/` and `presets/` in installed packages.
3. Yours: `~/.miyu/root/personas/` and `~/.miyu/root/presets/`.

If the same id is in several layers, the upper one covers the lower one: a persona's `persona.toml` and a preset's `[preset]` are covered field by field, so a field you wrote replaces the one below and a field you did not write follows the one below; files in a persona's `prompts/`, the avatar and the background image are replaced whole when the name is the same; a preset's `[features]` and `[software]` are covered entry by entry. Delete your layer and you are back to what is below. If a package-provided one has the same id as a shipped one, the shipped one is used; if several packages provide the same id, only one of them is used, and `miyu check` reports the ones that were covered.

Packages can also provide personas and presets; for how, see [Things that work as files](../../authors/scripts-skills.en.md).

## When something goes wrong

| What you see | What to do |
|---|---|
| You cannot open a new session, and `miyu ask` reports "preset not found"; `miyu check` warns "preset.default names preset …, which doesn't exist yet; it works once the preset is created." | The default preset was deleted or renamed. Change `preset.default` to one that exists, or choose one when you open the session |
| A persona or preset is marked as an error in the list and cannot be chosen | Use `miyu check` to see which line of which file is wrong |
| When switching persona or preset: "A reply is in progress: stop it or wait for it to finish" | Wait for this turn to finish, or stop it first |
