# Personas and presets

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Every session uses one persona and one preset. This page explains what personas and presets are each responsible for, how to choose them, switch them and set defaults, and how to write your own.

## What personas and presets do

Personas and presets take care of two different things:

- A **persona** decides who the AI is and how it speaks: the persona prompt, example dialogs and persona reminders are all put together into the system prompt sent to the model. You can also use no persona; in that case the AI carries only Miyu's own system prompt.
- A **preset** decides which features are on in this session: which tools, skills, scripts, MCP servers and slash command templates can be used, and what environment information is injected into the conversation. Every session must have a preset.

Personas and presets are chosen separately, and you can combine them however you like. Persona memory follows the persona: sessions that use the same persona share one memory, and sessions with no persona share another; for details, see [Memory](memory.md). If a session's preset does not have `Persona memory` on, that session neither saves nor recalls memories.

## Shipped presets

Miyu ships with the following four presets:

| Name in the interface | Id | What is on | When to use it |
|---|---|---|---|
| Everything | `full` | Everything installed is on, and anything installed later is turned on too | It is the one used by default |
| Development | `dev` | The three groups Base system, Injected environment, and Tasks and schedules; web search, persona memory, and the two skills for writing skills and packages. Nothing else is on, and nothing installed later is turned on | Writing code, when you do not need extras such as extensions and MCP servers |
| Minimal | `minimal` | Only four tools, for reading files, creating files, editing files and running commands, plus the eight environment items | You want the AI to work the way the model itself is good at, with as few tools as possible |
| Nothing | `none` | Nothing is on, and nothing installed later is turned on | Chat only; or use it as a base and turn on a few things yourself |

The shipped default preset is `full`.

## Shipped persona

Miyu ships with one persona, `Software Engineer` (id `software-engineer`), provided by the shipped package `Software Engineer persona` (`base-persona-engineer`). This persona is for writing code: its persona prompt asks for the simplest method first, verifying results with independent evidence, stopping once the work is done and verified, and speaking concisely. The AI can pick this persona when it dispatches a subagent.

No default persona is set at the factory: if a new session does not choose a persona, it uses no persona. Deleting this persona means uninstalling the package that provides it; to get it back, install `base-persona-engineer` again (see [Packages](packages.md)).

## Choosing a persona and preset for a new session

The way you choose a persona and a preset depends on where you are:

- First-run setup: the `Create a persona` step creates a persona (you can skip it), and the persona you create becomes the default persona; the preset you choose in the `Choose a preset` step becomes the default preset, and in this step you can also make a new preset with `Custom`.
- Terminal interface: when you start a new session, the place of the input box first shows `Choose a persona` and then `Choose a preset`, and you can type only after choosing both. The first line of the persona box is `No persona`. Use `↑` and `↓` to choose, `Enter` to confirm, `e` to edit the one under the cursor, and `a` to create a new one; in the preset box, press `Esc` to go back to the persona box and choose again. The cursor starts on the one the previous session used. If you do not want to be asked every time, turn on `General → New sessions → Auto-select persona and preset` (`tui.auto_pick`) on the settings page, and new sessions then use the default persona and preset directly.
- Web interface: above the input box of an empty session there are two buttons, `Select persona` and `Select preset`; if you do not click them, the defaults are used. If the default preset cannot be used (the file is written wrongly, or it was deleted), the input box is locked and shows `Select a preset`, and you can type only after choosing a preset.
- Command line: use `miyu ask --persona <persona>`, `--no-persona` and `--preset <preset>`, with ids as values. These arguments apply only to a newly started session, and cannot be combined with `-c` or `-s`. For example:

  ```sh
  miyu ask --persona software-engineer --preset dev "Why are this repository's tests slow?"
  ```

- Schedules: `miyu schedule add` takes the same `--persona`, `--no-persona` and `--preset`, which apply to each session it starts new; these arguments cannot be combined with `--session`. For details, see [Letting the AI keep working on its own](automation.md).
- Which persona and preset a session on a chat platform uses is decided by the platform's own rules, see [Connecting chat platforms](heads/im.md). In the web interface, a session created in a project uses the persona and preset the project sets.

## Switching in an open session

A session that has already started can also change its persona and preset:

- Terminal interface: type `/persona` or `/preset` and choose in the box that opens. If the AI is answering, the box does not open, and it shows `A reply is in progress: stop it or wait for it to finish`.
- Web interface: click the session title at the top left of the conversation area, click `Persona` or `Preset` in the menu, choose one, then click `Confirm` (if there is not yet a conversation that can be compacted, it does not ask and switches directly). You can also type `/persona` or `/preset`. A session in a project has its persona and preset decided by the project, and typing these commands shows `This session is in a project; the project sets its persona and preset`.

When you switch, Miyu first uses the old persona to compact the earlier conversation into a summary, and the new persona or preset is used from the next turn. After you switch persona, memories are saved into the new persona's memory from this turn on, and what was saved before stays with the old persona. Switching preset does not change whether memory is on; that always follows the setting from when the session was created. A subagent's session cannot switch persona or preset.

## Defaults

The persona and preset that new sessions use by default are decided by the following config keys:

| Key | What it controls | Where on the settings page |
|---|---|---|
| `persona.default` | Which persona new sessions use by default. If it is not set, new sessions use no persona; if it points to a persona that no longer exists, that also counts as not set, and `miyu config set` and `miyu check` warn about it | `General → New sessions → Default persona` |
| `preset.default` | Which preset new sessions use by default; the shipped setting is `full`. If it points to a preset that does not exist, starting a new session reports an error and does not quietly switch to another preset; `miyu config set` still accepts the value but prints an extra warning line, and `miyu check` warns too | `General → New sessions → Default preset` |
| `terminal.persona` | Which persona a shell integration session uses when it is newly started. The shell integration session is the session you enter when you talk to Miyu straight from the shell. If it is not set, it follows `persona.default` | `General → Shell integration session` |
| `terminal.preset` | The same as the previous item, but for the preset. If it is not set, it follows `preset.default` | `General → Shell integration session` |

Write ids as values. A change applies to sessions created afterwards; sessions already open do not change. For example:

```sh
miyu config set persona.default software-engineer
miyu config set preset.default dev
```

## Writing your own persona

A persona is a folder `~/.miyu/root/personas/<id>/` in the data root (`~/.miyu` by default, and `%USERPROFILE%\.miyu` on Windows). The id is the folder name: it must start with a lowercase letter, can contain only lowercase letters, digits, `-` and `_`, and is at most 64 characters long. The id cannot be one of the Windows reserved names `con`, `nul`, `aux`, `prn`, `com1` to `com9` and `lpt1` to `lpt9`; these are refused on all three systems.

```text
~/.miyu/root/personas/captain/
├── persona.toml          # name, description, and a few settings
├── avatar.png            # avatar, optional
├── background.jpg        # background image, optional
└── prompts/
    ├── persona.md        # persona prompt
    ├── examples.md       # example dialogs
    └── reminders.md      # persona reminders
```

Every file is optional, and even an empty folder counts as a persona. Once you put the folder there, new sessions can choose this persona.

`persona.toml` is written like this:

```toml
[persona]
name = "Old Captain"                         # the name, cannot be empty
summary = "An assistant who talks like an old sailor"  # a short description, for you; the model does not see it
subagent = true                              # whether the AI can pick it when dispatching a subagent

[knowledge]
bases = ["sea-charts"]          # with this persona, only these knowledge bases can be searched

[appearance]
seed = "#2f6f9f"                # theme color
background_opacity = 40         # how much of the background image shows, 0 to 100
background_focus = [50, 30]     # where the background image is centered, horizontal and vertical, each 0 to 100
background_blur = 10            # how much the background image is blurred, 1 to 100
```

| Field | Description |
|---|---|
| `persona.name` | The name. It can also be written as `{ zh = "…", en = "…", ja = "…" }`, and the interface picks the name that matches its language |
| `persona.summary` | A short description, written the same way as `name`; it can be an empty string |
| `persona.subagent` | When set to `true`, the AI can pick this persona when it dispatches a subagent, and the name and short description are shown to the model together. If not written, the AI cannot pick it |
| `knowledge.bases` | A list of knowledge base ids; only the listed bases can be searched; write `[]` and none can be searched. If not written, all can be searched |
| `appearance.seed` | In the form `#rrggbb`; the terminal interface and web interface derive their colors from it. If not written, colors are taken from the avatar |
| `appearance.background_opacity` | An integer from 0 to 100 |
| `appearance.background_focus` | Two integers, each from 0 to 100 |
| `appearance.background_blur` | An integer from 1 to 100; if not written, there is no blur |

Miyu recognizes only these tables and these fields; writing anything else is an error.

The files in `prompts/`:

- `persona.md`: the persona prompt, which describes who this persona is, how it speaks and how it treats you. It is put as it is at the very start of the system prompt, and it can be written in any language.
- `examples.md`: example dialogs, placed after the system prompt and before the conversation. A line starting with `user:` is what you say, and a line starting with `assistant:` is what the AI answers; a line with no prefix continues the previous one, and blank lines do not count. The example dialogs must start with `user:`, alternate question and answer, and end with `assistant:`:

  ```text
  user: What's the weather like today?
  assistant: Calm seas, fair for sailing.

  user: Take a look at this code for me
  assistant: Hand it over, the old captain will have a look.
  ```

- `reminders.md`: persona reminders, a short passage that reminds the AI not to break character. If the preset has `Persona reminders` on, the AI sees this passage again every 3 turns, and one more sentence is added at the end of the system prompt asking the AI to stay in character even after it has called tools. If you do not want this, delete this file, or turn off `Persona reminders` in the preset (the shipped `Development` and `Minimal` do not have it on).

Put the avatar in `avatar.png`, `avatar.jpg` or `avatar.webp`, and the background image in `background.png`, `background.jpg` or `background.webp`. If you change them in the interface, the avatar can be at most 1 MiB, with width and height at most 1024; the background image can be at most 5 MiB, with width and height at most 4096.

After you change a file, new sessions use the new content; a session that is already open switches to the new persona prompt, example dialogs and persona reminders at the start of its next turn. If a file is written wrongly, you can check it with `miyu check`, which says which line of which file is wrong and how; an open session that meets a wrongly written file keeps using the old content.

## Writing your own preset

A preset is a file `~/.miyu/root/presets/<id>.toml`, where the id is the file name, written the same way as a persona id. Below is a read-only code review preset that turns on only reading files, finding files and searching contents, and tells the AI the working directory:

```toml
# ~/.miyu/root/presets/review.toml
[preset]
name = "Code review"
summary = "Can only read files, find files and search contents"
icon = "search"
unlisted = "off"

[features]
read = true
glob = true
grep = true
env-workdir = true
```

The fields of the `[preset]` table:

| Field | Description |
|---|---|
| `name` | The name, written the same way as a persona's name |
| `summary` | A one-line description, for you; it is not sent to the model |
| `icon` | The icon, written as an icon name from [Lucide](https://lucide.dev) |
| `unlisted` | Whether features that are not written are on: `on` means on, `off` means off. Features installed later follow it too. `on` if not written |

The other tables:

| Table | How to write it | What it controls |
|---|---|---|
| `[features]` | `<feature id> = true` or `false` | Whether one feature is on |
| `[software]` | `<package id or group name> = true` or `false` | Whether a whole package or a whole group is on |
| `[tools]` | `<tool name> = false` | Turns off a single tool within the features that are on. Only `false` can be written |
| `[limits]` | `unattended_steps = <positive integer>` | The most times a turn can call the model when no one is watching; `500` if not written. It applies to sessions on chat platforms, sessions a schedule starts new, `miyu ask`, and, in a session someone is watching, the turns you did not start (for example turns run by a schedule or by a goal continuing) |

Whether a feature is on is decided in the following order: first, whether `[features]` names it; then, whether `[software]` names the package it is in; then, whether `[software]` names the group that package is in; if none of these names it, `unlisted` decides. Naming something that is not installed is not an error.

The feature ids are:

| What | Id |
|---|---|
| Shipped tools | Mostly the same as the tool name, for example `read`, `shell`, `subagent`. The ones that differ: `web_search` is `web-search`, `web_fetch` is `web-fetch`, `send_message` and `sessions` are one feature, `sessions`; `remember`, `memory_search` and `forget` are `memory`; the five `kb_*` tools are `knowledge`; the three `cron_*` tools are `schedule`; `schedule_next` is `loop`. For the full table, see [Tools the AI can use](tools.md) |
| Shipped features without tools | The environment info items `env-time`, `env-workdir`, `env-permission`, `env-session`, `env-model`, `env-harness`, `env-machine`, `env-profile`; automatic injection of AGENTS docs `project-docs`; calling tools from the command line `clicall`; persona reminders `roleplay` |
| Skills | `skill-<skill name>` |
| Scripts | `script-<tool name>` |
| MCP servers | `mcp-<server name>` |
| Slash command templates | `command-<command name>` |

The groups you can write in `[software]`:

| Group name | Name in the interface | What the group contains |
|---|---|---|
| `basesystem` | Base system | Read files, New file, Edit files, Find files, Search contents, Move to trash, Commands, Background, Call tools from the command line, Subagents, Ask the flagship model, Questions, Show to the user, Messages between sessions, Session history, Usage lookup, Packages |
| `tasks` | Tasks and schedules | To-do list, Long-running goals, Scheduled tasks, Loop tasks |
| `environment` | Injected environment | The eight environment info items, automatic injection of AGENTS docs |
| `persona` | Persona | Persona memory, Persona reminders |
| `research` | Research | Web search, Knowledge base |

If you only want to change a little on top of a shipped preset, write only the part you changed. For example, to turn off web search in Everything, the file is named `full.toml`:

```toml
# ~/.miyu/root/presets/full.toml
[features]
web-search = false
```

After you change the file, new sessions use the new content; a session that is already open switches to it from its next turn. You can use `miyu check` to see whether anything is written wrongly.

### The master switches on the settings page

In settings, each skill, script and MCP server has a switch, recorded in `features.<feature id>` (for example `features.mcp-github`). This switch only applies to presets with `unlisted = "on"`; if the preset writes on or off for that item, the preset takes precedence. In a preset with `unlisted = "off"`, features that are not written stay off.

## Creating and changing in the interface

You can also create and change personas and presets in the interface:

- Terminal interface: use the `Personas` and `Presets` items of the main menu of the settings page (`/settings`). In the list, press `a` to create a new one and fill in a name; the id can be left empty, and Miyu generates one; press `Enter` to open one and change it. For a persona you can change the name, short description, whether subagents can pick it, avatar, the detailed persona prompt, example dialogs and persona reminders; to change the prompts, press `Enter` to write in an editing window, or press `Ctrl+G` to hand them to an external editor (`$VISUAL` is used, or `$EDITOR` if that is not set, or `vi` if neither is set); on Windows there is no external editor option, so you need to write in the editing window or paste into it. For a preset you can change the name, the description, and the switch of every feature and every tool, toggling with `Space`, `Tab` or `Enter`, and `Ctrl+A` toggles all; each change is saved as soon as you make it. In the window, `d` deletes; for a shipped one or one that came with a package that you have changed, `d` restores the shipped version. In the picker for a new session, pressing `e` or `a` opens the same windows.
- Web interface: use the `Personas` and `Presets` pages in settings, where you can create, change and delete. In an open session, click the session title at the top left; the pencil icon on the `Persona` row is `Edit this persona`.

When you change a shipped persona or preset, or one that came with a package, in the interface, the change is saved in your own layer, recording only what you changed. A deleted persona goes to the trash and is kept for 7 days; a deleted preset cannot be recovered.

## How the three layers stack

Personas and presets both have three layers, from the bottom up:

1. Shipped: installed together with Miyu.
2. Package-provided: the `personas/` and `presets/` in installed packages.
3. Yours: `~/.miyu/root/personas/` and `~/.miyu/root/presets/`.

If the same id exists in several layers, the upper layer overrides the lower one: a persona's `persona.toml` and a preset's `[preset]` are overridden field by field, so a field you wrote replaces the one below and a field you did not write keeps the value from below; files in a persona's `prompts/`, the avatar and the background image are replaced whole when the name is the same; a preset's `[features]` and `[software]` are overridden entry by entry. If you delete your own layer, you are back to what the layer below has. If a package-provided one has the same id as a shipped one, the shipped one is used; if several packages provide the same id, only one of them is used, and `miyu check` reports the ones that were overridden.

Packages can also provide personas and presets; for how to make them, see [Things that work as files](../dev/scripts-skills.md).

## Troubleshooting

| What you see | What to do |
|---|---|
| You cannot start a new session, and `miyu ask` reports `preset not found`; `miyu check` warns `preset.default names preset …, which doesn't exist yet; it works once the preset is created` | The default preset was deleted or renamed. Change `preset.default` to a preset that exists, or choose a preset when you start the session |
| A persona or preset is marked with an error in the list and cannot be chosen | Use `miyu check` to see which line of which file is wrong |
| When switching persona or preset, it shows `A reply is in progress: stop it or wait for it to finish` | Wait for this turn to finish, or stop it first |
