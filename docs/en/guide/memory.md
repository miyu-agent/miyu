# Memory

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

The AI remembers what you have talked about with it, and can still recall it the next time you open a new session. This page explains what the AI remembers, when it remembers and recalls things, how to view and change memories, and how to stop it from remembering.

Memory is provided by the shipped package `base-memory`, which is called `Persona memory` in the interface. Once this package is installed, memory is turned on.

## Memory format

A memory is one sentence of at most 120 characters. Each memory has an id, written as `m` followed by a number, for example `m12`. Each memory belongs to one of the following classes:

| Class | Name in the web interface | What it remembers |
|---|---|---|
| `user` | About the user | Things about you |
| `feedback` | Requests for the AI | How you want the AI to work |
| `episode` | What happened | Things you and the AI went through together |
| `reference` | Where things are | Long-lasting facts, and where material is kept |
| `person` | People | One thing about someone else, together with who that person is (a name or a platform id, for example `qq:10086`) |

A memory can also carry an extra line of keywords, separated by commas, at most 200 characters. Keywords are only used to let searches find the memory; the AI does not see this line.

Besides the individual memories, there are two more things, both written when memories are organized:

- What it knows about you: a summary about you.
- Cards for the people it knows: one card per person, at most 400 characters, composed from the memories of the `person` class.

The AI can also search earlier conversations of the same persona, but it only searches the turns that you started.

## Memory and personas

Each persona has its own memory, shared by all the sessions that use that persona. Sessions that use no persona share another one.

- If you switch persona in the middle of a session, new memories are saved into the new persona's memory from the turn of the switch onward; what was saved before stays in the old memory and is not moved over.
- Subagents neither save nor recall memories.

## When memories are saved

Memories can be saved in the following ways:

| Who saves | How |
|---|---|
| Automatic | After a session goes idle, the AI picks out what is worth remembering from the conversation since the last save, and saves it. If the AI already remembered or forgot something itself in a turn, that turn is not looked at again |
| The AI | The AI calls the `remember` tool. This tool can also change a memory: the new memory replaces the old one |
| You | Type `/remember <text>` in a local session. The text is saved in the class `About the user`, and the reply is `Remembered: …` |
| You | Run `miyu memory add`, or click `Add` on the memory page of the web interface |

Automatic saving needs both of these conditions:

1. Since the last automatic save, the AI has answered at least `memory.extract_turns` turns (default 2).
2. The session has been idle for `memory.extract_idle` (default 30 minutes).

Some sessions never go idle, for example when people keep talking in a group. In that case, if `memory.extract_max_turns` turns (default 20) have ended since the last save, or the earliest unsaved turn is older than `memory.extract_max_wait` (default 1 hour), saving stops waiting for idle and runs in the background.

Automatic saving uses a model from the everyday pool (`normal`); if the pool is empty, or all its members are cooling down or failing, it uses the session's own model. For how to configure pools, see [Models](models.md#pools-cheap-ones-for-chores-expensive-ones-for-real-work).

## When memories are recalled

The AI brings memories into the context at the following times:

| When | What is brought in |
|---|---|
| The first turn of a session, and the first turn after compaction | A resident block: what it knows about you, plus the memories saved after it, newest first, at most 3000 bytes in total. If something does not fit, the last line says how many more there are, and tells the AI to search for them with `memory_search` |
| On chat platforms, a turn where someone else speaks | That person's card, brought in only once per stretch of context |
| Every turn you start | Associative recall: memories are looked up from what you said in this turn, at most 3 of them and at most 500 bytes; at most 40 per stretch of context (counted again after compaction), and this number is shared with the automatic recall of knowledge bases. A memory is brought in only when both its keywords and its meaning match; when in doubt, nothing is brought in |
| When the AI looks by itself | The AI calls the `memory_search` tool, which searches memories, people it knows and earlier conversations |

Associative recall needs a semantic model (`models.embedding`, see [Models](models.md#the-three-uses)), and by default it uses the local `embed` package (see [Add-ons](addons.md)). If it is not installed, is set to `off`, or has been changed to a remote model, there is no associative recall, but the resident block, cards and `memory_search` work as usual. If it is not installed or is set to `off`, `memory_search` finds memories by keywords only.

Which memories were recalled is not shown on the timeline. You can see related information in these places:

- Terminal interface: the context breakdown of `/context` lists how many tokens `Resident memory` and `Recalled memory` each take; in `/status`, `recalled N times · remembered N` counts the times the AI called `memory_search` and `remember`.
- When the AI calls a memory tool, the timeline shows a line for it, the same as for other tools.

## Organizing

Organizing takes the newly saved memories together with related older ones and goes through them again. It does the following:

- Duplicate memories are retired, and only one is kept.
- Memories overturned by later ones are retired.
- Memories that are no longer useful are retired.
- Inaccurately worded memories are rewritten: the rewritten text is saved as a new memory, and the old one is retired.
- A new "what it knows about you" is written.
- The card of each person is composed from the memories of the `person` class.
- Memories without keywords get keywords.
- Up to 20 older memories are checked again along the way.

Retired memories can be restored; organizing never empties anything.

Organizing happens at the following times:

- Automatically: after automatic saving has saved new memories, if more than `memory.merge_every` (default 16 hours) has passed since the last organizing, it organizes in the background. If this memory has never been organized, it is organized right away.
- When you type `/dream` in a session: it first saves what this session has not saved yet, then keeps organizing until nothing is left. When it is done, the reply is `Memory organized: …`, which says how many memories were checked, revised and retired, whether the summary was replaced, and how long it took.
- When you run `miyu memory dream`: it organizes the memory of the default persona, or the one given by `--persona` or `-s`.
- When you click `Tidy up` on the memory page of the web interface.

To stop organizing, type `/dream stop` or `/stop` in a session; press `Esc` twice in the terminal interface; press `Ctrl+C` while `miyu memory dream` is running; or click `Stop` in the web interface. The batches already organized are kept, and the batch in progress is organized again next time.

Like automatic saving, organizing uses the everyday pool (`normal`). Each memory keeps the process of its last `memory.dream_keep` organizings (default 20), which you can view under `Tidy-up history` on the memory page of the web interface.

## Viewing and changing memories

You can view and change memories on the command line or in the web interface.

### Command line

```text
miyu memory [<command>] [<options>]
```

With no command, it runs `list`. If you do not write `--persona` or `-s`, it uses the memory of the default persona (`persona.default`); if no default persona is set, it reports `memory unavailable`. For the memory of sessions with no persona, write `--persona _none`.

| Command | What it does |
|---|---|
| `list` | Lists the newest 50 memories, one per line: id, date, text |
| `search <words>…` | Searches memories and lists at most 10, the most relevant first |
| `add <text>…` | Saves a memory and prints `added m…` |
| `edit <id> [<text>…]` | Changes the text: the new text is saved as a new memory and the old one is retired, and it prints `updated, new id m…`. If you only change `--keywords` or `--who`, leave out the text |
| `forget <id>` | Retires a memory |
| `clear session [<id>]` | Clears the memories one session saved. Without a session, it uses the session given by `-s`; if there is no `-s` either, it is the session of the last `miyu ask` |
| `clear me` | Empties this whole memory, including the cards and what it knows about you |
| `dream` | Organizes right now |
| `cards` | Lists the cards of the people it knows |

| Option | What it does |
|---|---|
| `--persona <id>` | Uses the memory of this persona. Cannot be combined with `-s` |
| `-s`, `--session <id>` | Uses the memory that this session uses |
| `--forgotten` | Makes `list`, `search` and `cards` also list retired memories |
| `--class <user\|feedback\|episode\|reference\|person>` | `list` lists only this class; `add` saves into this class, and it is `user` if not written |
| `--why <reason>` | For `forget`: writes down why the memory is retired |
| `--keywords <words>` | For `add` and `edit`: keywords, separated by commas; for `edit`, an empty value removes the keywords |
| `--who <who>` | For `add` and `edit`: who a memory of the `person` class is about. `add --class person` requires this option |
| `--format <text\|json>` | Output format of `list` and `search` |

For example:

```sh
miyu memory search coffee
miyu memory add --keywords editor,vim Use Neovim for coding
miyu memory add --class person --who Lin Lin is a colleague who works on the frontend
miyu memory edit m12 --keywords drinks,breakfast
miyu memory forget m15 --why "changed jobs"
miyu memory --persona captain list --class feedback
```

Cleared memories cannot be brought back; retired memories can be restored by clicking `Restore` on the memory page of the web interface. For all the arguments, see [Command line](cli.md#miyu-memory).

### Web interface

The memory page is the `Memory` page in the settings, and you can also open it directly by typing `/memory` in a session. The terminal interface has no memory page.

- At the top of the page, choose which memory to look at: one per persona, plus one for `No persona`.
- The `Memories` tab: you can search by text and keywords, filter by class, and tick `Show retired`; open a memory to change its text and keywords, retire it or restore it; click `Add` to save a new memory; click `Clear` to empty this memory (the same as `clear me`, and it cannot be brought back); there are also `Tidy up` and `Tidy-up history`.
- The `People` tab: you can view, search and edit the card of each person, and click `Meet someone` to write a new one.

## Turning off and clearing memory

You can keep the AI from remembering at different scopes:

| Scope | What to do |
|---|---|
| One `miyu ask` | Run `miyu ask --no-memory "…"`: the new session neither recalls nor saves memories. Cannot be combined with `-c` or `-s` |
| Sessions using a given preset | Turn off `Persona memory` in the preset: write `memory = false` under `[features]` |
| Everything | Run `miyu pkg remove base-memory`. The saved memories stay in the data root, and they are still there after you install it again (`miyu pkg install base-memory`) |
| One memory | Ask the AI to forget it (the AI calls `forget` to retire it), or run `miyu memory forget <id>` |
| The memories one session saved | Type `/clear-memory` (alias `/reset-memory`) in that session. It does not ask again, and replies `Cleared N memories this session made.`. You can also run `miyu memory clear session <id>` |
| A whole memory | Run `miyu memory clear me`, or click `Clear` in the web interface |

Whether a session has memory on is decided when the session is created, and switching preset later does not change it. `/remember`, `/dream` and `/clear-memory` work only in sessions with memory on; if the session's preset does not have memory on, typing them shows `Preset "…" has memory off.`.

For how to write presets, see [Personas and presets](personas-presets.md).

When you clear one session's memories, only the memories whose source is entirely in this session are cleared: memories you saved yourself (`/remember`, `miyu memory add`) have no source and are not cleared; things that were also said in other sessions are not cleared; cards stay unchanged.

## Settings

You can change the settings of Persona memory under `Packages` on the settings page (`/settings`), or write them into `~/.miyu/etc/config.toml`. A change takes effect from the next turn.

| Key | Default | Allowed values | What it controls |
|---|---|---|---|
| `memory.extract_idle` | `"30m"` | `1m` to `1h` | How long a session must be idle before automatic saving |
| `memory.extract_turns` | `2` | `1` to `100` | The minimum number of turns since the last automatic save before saving again |
| `memory.extract_max_turns` | `20` | `2` to `500` | For a session that never goes idle, how many turns pile up before it stops waiting for idle |
| `memory.extract_max_wait` | `"1h"` | `10m` to `24h` | For a session that never goes idle, how old the earliest unsaved turn gets before it stops waiting for idle |
| `memory.merge_every` | `"16h"` | `1h` to `720h` | How often it organizes automatically |
| `memory.dream_keep` | `20` | `0` to `1000` | How many recent organizings to keep the process of; `0` means it is deleted as soon as organizing is done |

For example:

```toml
[memory]
extract_idle = "10m"
merge_every = "24h"
```

## Sessions on chat platforms

Memory is not split by group or by person: the same persona uses the same memory in every group and every private chat, and can recall everything anywhere. When a memory is saved, it also records which venue and which group it was said in (the group name at the moment of saving). If someone in a group has memories of the `person` class, organizing composes a card for that person, and the card is brought in on the turn where that person speaks.

`/remember`, `/dream` and `/clear-memory` work only in local sessions. For which persona a chat platform session uses and how to set it, see [Connecting chat platforms](heads/im.md).

## Storage location

Memory is stored in the data root:

| Location (the data root is `~/.miyu` by default, `%USERPROFILE%\.miyu` on Windows) | What it is |
|---|---|
| `~/.miyu/root/memory/<persona id>/` | The memory log of this persona; the one for sessions with no persona is `_none` |
| `~/.miyu/var/cache/index/recall/` | The search index, computed from the logs and sessions |

The memory log is append-only: changing a memory writes a new one, retiring and clearing also write another line, and the original text always stays in the log. Do not edit these files by hand; to change memories, use `miyu memory` or the memory page of the web interface.

For backing up memory and moving it to another computer, see [Data and backups](data.md).

## What is sent to the model provider

- Recalled memories and cards go into the context and are sent with each request to the model the session uses.
- Automatic saving and organizing are done by separate requests to a model of the everyday pool (or the session's model), which carry the relevant part of the conversation and the related memories. Before sending, the original text of secrets referenced in the config and common key formats are masked.
- If `models.embedding` is set to a remote model, the text of memories and conversations is sent to that provider to compute vectors. The local `embed` does not send anything off this computer.

## Troubleshooting

| What you see | What to do |
|---|---|
| `miyu memory` reports `memory unavailable` | No default persona is set. Add `--persona <id>`; for the memory of sessions with no persona, write `--persona _none` |
| `/remember` says `Preset "…" has memory off.` | The preset of this session does not have persona memory on. Open a new session with a preset that has persona memory on, or turn it on in the preset |
| `Persona memory not installed.` | Run `miyu pkg install base-memory` |
| `Memory is being organized.` | This memory is being organized. Wait for it to finish |
| `memory too long: N characters, limit 120` | Write the memory shorter, or split it into several |
| The AI never recalls by association | Run `miyu check` and look at the lines about the semantic model at the end; if it is not installed, run `miyu pkg install embed` |
