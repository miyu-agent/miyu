# Events

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

A session is defined by an append-only event log. Heads (interface programs that connect to the core, such as the terminal interface or the web interface) subscribed to the `events` stream receive these events one by one (push `event`); `view.page` without `view` returns these events too. If a head only wants to draw its interface, the [view stream](view.md) is enough, and the head doesn't need to work things out from the events itself.

## Envelope

```json
{"seq": 42, "at": "2026-10-01T06:03:12.345Z", "kind": "message.user", "turn": 41, "by": {"kind": "person"}, "cause": "m1", "body": {…}}
```

| Name | Notes |
|---|---|
| `seq` | The sequence number, starting from 1, with no gaps or repeats within a session. |
| `at` | The time of the event, in UTC, to the millisecond. |
| `kind` | The kind of event; see the tables below. |
| `turn` | Which turn the event belongs to, given as that turn's `turn.started` number; it is omitted when the event belongs to no turn. |
| `by` | Who produced the event: `person` (you; it carries `via` when you were recognized on a platform; words said and commands typed on a local head also carry `head`, which is the `head.kind` that connection gave in its handshake, such as `tui`, `web`, `cli`; it starts with a lowercase letter, contains only lowercase letters, digits, `-` and `_`, is at most 32 long, and is left out when written otherwise), `external` (a person on a platform, with `venue`, `id`, `role`, plus `owner: true` when the bindings recognize you), `model`, `kernel`, `tool` (with `call_id`), `module` (with `id`, for example a package), `harness` (with `name`), `session` (another session). |
| `cause` | Which command caused the event: the request's `id`. |
| `body` | The fields of this kind of event. |

The exact shape of each kind is in the repository's `internal/designs/samples/events/<kind>.jsonl`, one file per kind, each file holding a real event line.

## Recorded events

| `kind` | Meaning |
|---|---|
| `session.created` | The session was created. This is the session's event 1, and it records the venue, working directory, persona, preset, model and so on. |
| `session.policy_changed` | The session's settings changed: the permissions (`permission: {"level", "read_only"}`, with `from` holding the settings before the change in the same two fields; older logs have no `from`), the model, the reasoning effort (`effort: {"level"}`, where `null` goes back to following the config), the context limit (`context: {"tokens"}`, where `null` removes it), the vision model (`vision`, empty when removed), the compaction line (`compaction_line: {"percent"}`, where `null` removes it), or the whole policy. |
| `session.workspace_changed` | The working directory changed. |
| `session.meta_changed` | The title, pin or project changed (`project` is the project id, empty when the session was moved out); the titles the kernel gives unnamed sessions are recorded with this event too. |
| `session.recapped` | A one-line recap of the session, which doesn't enter the AI's context. |
| `session.sealed` | A forked session ran all its turns and was sealed. |
| `command.ran` | A person used a slash command; this event doesn't enter the AI's context. |
| `turn.started`, `turn.ended` | A turn began or ended; the `reason` of `turn.ended` is `completed`, `interrupted`, `error`, `restarted` and so on. |
| `turn.joined` | Messages that were already recorded joined the running turn. |
| `turn.reverted`, `turn.unreverted` | Turns were undone; the last undo was restored. |
| `message.user` | A message from a person (or another session, another agent, someone on a platform); a command the person typed with `!` has `shell: true`, and its `blocks` is the command line. A path-only attachment (see item 3 of `session.send`) is a `{"type": "path", "name", "path", "size"?}` block: it has no blob, and `size` is the byte count the head gave. |
| `message.withdrawn` | Queued messages that the AI hadn't heard yet were handed back. |
| `message.assistant` | One complete model response: text, thinking, tool calls and hosted tools (`hosted_tool`: a tool the provider ran on its own side, such as its web search; the core does not run it and only records it; it has `call_id`, `name`, `args`, and `outcome` when there is a result: `{"text", "failed"?, "cut"?}`, where `cut` means the result was over 64 KiB and its end was cut off). When the model went on to make up the next turn after its answer (a role word at the start of a line, followed by an imitation of the user-side tags or the group message line of this request), that part was cut before the event was written, so only what is left is here; the streamed `model.delta` pieces are unchanged, so treat this event as final. |
| `model.called` | The record of one model request: which model, the usage, the cost, and `error` on failure. When the reply was cut, it carries `cut`, one item per text block: `[{"block", "at", "bytes", "role"}]` (`block` is the block number, the same as `index` in `model.delta`; `at` is the byte offset in that block's original text where the cut starts; `bytes` is how many bytes were cut; `role` is the role word: `user`, `assistant`, `system`, `human`, `tool`). The cut text itself is not recorded; the field is absent when nothing was cut. |
| `tool.result` | The result of one tool call: `status` is `ok`, `error`, `denied`, `cancelled`, `skipped`. |
| `tool.nested` | A `miyu call` from a script finished. It has `id` (`call_12_1#3` under a foreground call, `j7#3` under a background job), `name`, `args`, `status` (`ok`, `error`, `denied`, `needs_approval`, `cancelled`), and, when present, `duration_ms`, `result` (blob), `bytes`, `reason`. This event doesn't enter the AI's context; the ones under a job carry no `turn`. |
| `tool.approval_requested`, `tool.approval_decided` | A person was asked to approve a call; the person's decision. If a request has `expires_at` (a time), it is denied automatically when no one confirms by then: the core records a decision with `decision` `deny` and `by` `kernel`, and the AI gets a "no one confirmed" result and carries on; heads draw a countdown from it. When the config `permission.confirm.timeout` is `0`, the request waits forever and the field is absent. |
| `question.asked`, `question.answered` | The AI asked a set of questions; the person's answers. |
| `context.injected` | A block of facts injected into the context, such as memory or something an extension returned. |
| `context.compacted` | A compaction checkpoint; clearing the context is recorded with this event too (`trigger` is `clear`). If the summary request was too long and the oldest groups had to be cut before the summary could be written, the event carries `truncated` (how many groups were cut: the earliest part is not in the summary); it is left out when nothing was cut. |
| `context.compaction_paused` | Automatic compaction was paused. |
| `job.reported` | A background command ended; a `reason` of `too_chatty` means a watched command printed 120 batches within an hour and was stopped. |
| `shell.ran` | A command the person typed with `!` finished. It has `message` (the number of that message), `exit` or `signal`, `duration_ms`, `text` (the output, with stdout and stderr together; a long one keeps the head and tail, with a line in the middle saying how much was left out), `omitted`; it also has `reason` if the command ended abnormally: `timed_out` (it ran for 120 seconds), `interrupted` (the person interrupted it), `aborted` (the core restarted or crashed; the command is not run again). |
| `job.lines` | A watched background command (`shell` with `watch`) printed a batch of lines. It has `job`, `text` (at most 4000 characters; a cut one has a line in the middle saying how many were left out), `lines`, `omitted`. This event carries no `turn`. |
| `child.reported` | A report sent back by a subagent. |
| `peer.idle` | A session being waited on went idle, or can no longer be waited on. |
| `image.described` | A description of an image: the vision model looked at it for a model that can't see images. |
| `todos.cleared` | The to-do list was cleared. |
| `package.state` | A package's program set its state in this session directly (`{"package", "state"}`; see [Extensions](extensions.md)). |
| `goal.set`, `goal.changed`, `goal.paused`, `goal.resumed`, `goal.ended` | A standing goal was set, changed, paused, resumed or ended. |
| `dream.ended` | A memory consolidation run finished: how many memories it added, revised and retired, whether it wrote the summary, and whether it was stopped. |
| `venue.recalled`, `venue.delivered` | Someone recalled a message on the platform; the AI's message reached the platform. |
| `ext.<prefix>.<name>` | An event recorded by an extension (through `events.append`; the prefix is the manifest's `prefix`, or the package id when there is none). |

Undo, compaction and clearing never delete events: heads have to work out from the history what is in effect and what to draw, or simply use the view stream.

## Transient events

Transient events are not recorded and have no `seq`. They are only pushed to the heads subscribed at that moment and are never replayed (except that when a model request is streaming at the time you subscribe, the core replays its `model.delta`s so far once). Their shapes are in `internal/designs/samples/transient/`.

| `kind` | Meaning |
|---|---|
| `model.delta` | A piece of model output. It has `seen`, `index` (which block), plus one of `start` (the block kind: `text`, `reasoning`, `tool_call`, `hosted_tool`; the last two carry `name`), `text`, `outcome` (a hosted tool's result `{"text", "failed"?, "cut"?}`, the same one that lands in `message.assistant`), `end`. |
| `tool.progress` | A piece of a running tool's output, with `call_id` and `text`. |
| `tool.nested_started` | A `miyu call` from a script passed the checks and is running, with `id` and `name`; when it ends is decided by `tool.nested`. |
| `status` | A request is retrying, or switched provider. |
| `model.changed` | The model, reasoning effort or limits for the session's next requests changed (switching the model or the effort pushes one right away): `effort.from` is `session` (the session's own) or `system` (the config); `why` is `failover` or `turn`. |
| `compaction.started`, `compaction.progress`, `compaction.done` | A compaction started (one prepared in the background), how far the summary has got, and the compaction is done; `compaction.done` carries the same `truncated` as its `context.compacted`. |
| `todos.changed` | The whole current to-do list. |
| `package.state_changed` | What heads see of a package's state in this session changed: `{"package", "state": {"widgets"?}}`; when the state was cleared, `state` is `{}`. |
| `compactable.changed` | Whether there is anything to compact changed: `{"compactable": <bool>}`, the same as `compactable` in the subscribe reply, which tells whether `session.compact` would answer `nothing_to_compact`. |
| `goal.changed` | The whole standing goal as it is now. |
| `session.retitle_failed` | A new title a person asked for ([`session.retitle`](sessions.md#sessionretitle)) failed, and the title is unchanged: `{"error", "human"}`. `error` is that request's error (`class`, `message`, and `status` when there is one); `human` is the line for people, `{"key": "core/sessions/retitle-failed"}`, which is turned into text with the `said` of [`human.get`](misc.md#humanget) (`Failed to change the title`). `by` is the person who asked. A failed title that the core writes by itself is not pushed. |
