# A head's own settings: `prefs.*`

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page covers the settings of a UI package (a package whose manifest has `[ui]`, that is, a head such as the terminal interface or the web interface, an interface program that connects to the core): skin, color scheme, theme, mascot and the like. These settings live in the core's data root and follow the person rather than the address or the device: whether you open the same web interface via `127.0.0.1`, `localhost`, a LAN address or a phone, you see the same settings. The core doesn't interpret the keys; the head decides the keys and values itself. Anything that belongs to one device (column widths, whether the sidebar is collapsed, input history) stays with the head.

| Method | What it does |
|---|---|
| [`prefs.get`](#prefsget) | Reads the whole settings object |
| [`prefs.set`](#prefsset) | Changes some keys and returns the whole result |

**Who can call**: only people can call these methods (through head connections); when an extension or a platform bridge calls them, it gets `local_only`. If a head wants to follow changes made by other heads, it can subscribe to the `prefs` stream (with `package`); after that the core pushes `prefs.changed` (see [Pushes](pushes.md)).

**Where it is stored**: the settings are stored in `prefs.json` in that package's state directory (`var/lib/<package id>/prefs.json`, which is the directory `MIYU_STATE_DIR` points to). The whole file is one JSON object on one line, and on Unix only you can read it. The core owns this file name, so a head must not use it for its own files in the state directory: what a head writes there is read back as settings, and a file in the wrong format is overwritten by the next `prefs.set`. When you remove the package, the settings are removed along with the state directory.

**Limit**: the whole object, serialized as JSON (without whitespace), is at most 64 KiB (65536 bytes).

## `prefs.get`

**Params**: `{"package"}`, the UI package's id. **Response**: `{"values": {…}}`, the whole settings object; it is `{}` if nothing has been set yet.

## `prefs.set`

**Params**: `{"package", "values": {key: value or null}}`. The core merges by top-level key: a key you write is replaced as a whole by the new value (any JSON value; an object also replaces the old one as a whole and is not merged into it), a key written as `null` is deleted, and keys you leave out stay as they are. With `values: {}`, nothing changes.

**Response**: `{"values": {…}}`, the whole merged object. A change is pushed to the other connections subscribed to this package, but not to your own connection, because the response already has the whole object.

## Subscribing

Send `subscribe {"stream": "prefs", "package"}`; the response is `{"values": {…}}`, the whole object at that moment. After that, when other connections make changes, the core pushes `prefs.changed {"package", "values"}`, where `values` is the whole new object, and the head replaces its copy with it as a whole. A connection has one subscription per package, and subscribing again replaces it; sending `unsubscribe {"stream": "prefs", "package"}` stops it. If you read too slowly and fall behind, the core pushes `resync {"stream": "prefs", "package"}`, and you need to subscribe again.

## Errors

| Reason | When |
|---|---|
| `bad_params` | `package` is missing; `values` is missing or not an object; or a subscription has no `package`. |
| `unknown_package` | No such package is installed. |
| `not_a_ui_package` | The package is installed, but it is not a UI package. |
| `prefs_too_big` | The merged object is over 64 KiB, and nothing is changed; `data` has `size` (how many bytes the merged object has) and `limit` (65536). |
| `local_only` | The caller is an extension or a platform bridge. |

```json
→ {"jsonrpc":"2.0","id":"1","method":"prefs.set","params":{"package":"webui","values":{"skin":"paper","mascot":null}}}
← {"jsonrpc":"2.0","id":"1","result":{"values":{"scheme":"dark","skin":"paper"}}}
```
