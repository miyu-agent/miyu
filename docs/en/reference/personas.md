# Personas and presets: `persona.*`, `preset.*`

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

A persona is "who the AI is": the character prompt, example dialogue, roleplay reminders, avatar and theme color. A preset is "what the AI can use": which features are on and which tools are off. Both are files stacked in layers: built-in, from packages, and yours (`root/personas/`, `root/presets/` in the data root); changes are written only to your layer, and a same-named file there covers the ones in the layers below.

| Method | What it does |
|---|---|
| [`persona.list`, `persona.get`](#personalist-personaget) | Lists personas; reads one persona as stacked |
| [`persona.read`](#personaread) | Reads one prompt's text and version |
| [`persona.set`](#personaset) | Creates or changes a persona |
| [`persona.delete`](#personadelete) | Deletes your layer |
| [`persona.avatar`, `persona.background`](#personaavatar-personabackground) | Reads the avatar or the background image |
| [`preset.list`, `preset.get`](#presetlist-presetget) | Lists presets; reads one preset as stacked |
| [`preset.set`](#presetset) | Creates or changes a preset |
| [`preset.delete`](#presetdelete) | Deletes your layer |

**Who can call**: people and extensions can both call the reading methods; `persona.set`, `persona.delete`, `preset.set` and `preset.delete` are for people only, and an extension that calls them gets `local_only`.

**Ids**: an id starts with a lowercase letter, contains only lowercase letters, digits, `-` and `_`, and is at most 64 characters long. Any other id gets `bad_params`.

**Names and summaries** (`name`, `summary`) are picked in the connection's language.

## `persona.list`, `persona.get`

**`persona.list`**: takes no params. The response is `{"personas": [...]}`, sorted by id. Each item has these fields:

| Name | Notes |
|---|---|
| `persona` | The persona's id |
| `name`, `summary` | The name and a one-line summary |
| `avatar`, `background` | The versions of the avatar and the background image; `null` when there is none |
| `seed` | The theme color, as lowercase `#rrggbb`; `null` when there is none |
| `seeds` | Candidate colors picked from the avatar, at most 4; `null` when there is no avatar |
| `background_opacity`, `background_focus` | How much of the background image shows (0 to 100) and its focus `[x, y]`; `null` when there is none |
| `background_blur` | How much the background image is blurred (1 to 100); `null` means no blur |

A persona whose files are wrong has only `persona` and `problem` (what's wrong, in the connection's language), plus `line` when the line is known.

**`persona.get`**: the param is `persona`. The response has the fields above, plus these:

| Name | Notes |
|---|---|
| `prompts` | `{"persona", "reminders"}`: whether the character prompt and the roleplay reminders have any text (booleans); read the text itself with `persona.read` |
| `examples` | How many example exchanges there are |
| `subagent` | Whether the persona can be picked when spawning a subagent |
| `remove` | What deleting does: `restore` (it goes back to the built-in version), `delete` (it is gone; this is also the value for a persona like the built-in Software Engineer that goes away with its package), `null` (there is nothing to delete) |

**Errors**: `unknown_persona`; `persona_invalid` (its files are wrong; comes with `data.problem`, `data.message` and `data.line`).

## `persona.read`

**Params**: `persona`; `prompt` is the one to read: `persona` (the character prompt), `examples` (the example dialogue) or `reminders` (the roleplay reminders).

**Response**: `{"text", "version"}`: the stacked text, and the version of this file in your home layer (both are `null` when there is none). Example dialogue also comes with `pairs: [{"user", "assistant"}…]`.

An editor edits the text and, when saving, sends `version` back as `expect` in `persona.set`.

## `persona.set`

**Params** (give at least one besides `persona`)

| Name | Type | Notes |
|---|---|---|
| `persona` | string | The persona's id; when omitted, a new persona is created and the core picks `persona-<n>` as its id |
| `new` | boolean | Creates a persona with the ID you wrote (needs `persona`): an ID that already exists (built-in, from a package or yours) is refused with `persona_exists` instead of editing that persona |
| `changes` | array | Changes to `persona.toml`, written like the `changes` of `config.set`; the keys are `persona.name`, `persona.summary`, `persona.subagent` and `appearance.seed` |
| `prompts` | object | Maps a prompt name (`persona`, `examples`, `reminders`) to `{"text": <whole>}` or `{"unset": true}`; example dialogue may also be given as `{"pairs": [{"user", "assistant"}…]}`; each one may carry `"expect": <version>` or `null` (the file doesn't exist yet) |
| `avatar`, `background` | object | `{"blob": <hash>}` switches to the uploaded image, and `{"unset": true}` removes the image in your layer; may carry `expect` |
| `seed` | string or `{"unset": true}` | The theme color, as `#rrggbb` |
| `background_opacity` | 0 to 100 or `{"unset": true}` | How much of the background image shows |
| `background_focus` | `[x, y]` or `{"unset": true}` | The focus of the background image, each value from 0 to 100 |
| `background_blur` | 1 to 100 or `{"unset": true}` | How much the background image is blurred; unsetting it means no blur |

**Response**: the same as for `persona.get`, showing the stacked result after the change. All the changes are checked together, and nothing is written if any of them is wrong. Parts that are equal to what your layer already has aren't written.

**Errors**

| `data.reason` | When |
|---|---|
| `bad_params` (`-32602`) | The id is malformed; nothing was given; the prompt name is unknown; a prompt doesn't have exactly one of `text`, `unset` and `pairs`; a line in the example dialogue is empty |
| `persona_invalid` | The changed files would be wrong; comes with `data.problem`, `data.message` and `data.line` |
| `persona_conflict` | `expect` doesn't match (`data.current` is the current value or version); or someone edited the files by hand while they were being written (there is no `data.current` then; read again and retry) |
| `avatar_not_image`, `background_not_image` | The image is not PNG, JPEG or WebP |
| `avatar_too_big`, `background_too_big` | The avatar is over 1 MiB or 1024 pixels, or the background image is over 5 MiB or 4096 pixels; `data` has the measured size and the limit |
| `unknown_attachment` | The `blob` doesn't exist |
| `local_only` | The caller is an extension |

## `persona.delete`

**Params**: `persona`. **Response**: `{"remains"}`: `true` means built-in or package layers remain below and the persona goes back to them (the interface shows this as "restore defaults"); `false` means the persona is gone. Your copy moves to the trash and stays there for 7 days. A persona that lives only in a built-in package of its own, like the built-in Software Engineer, is deleted by removing that package (the same as `package.remove`) when you have no layer of it, and the response is `false`; `package.install {"package": "<package id>"}` brings it back.

**Errors**: `nothing_to_delete` (you have no layer of the persona, and it can't go away with its package); `package_depended` (when its package is being removed, another package depends on that package); `local_only`.

## `persona.avatar`, `persona.background`

**Params**: `persona`. **Response**: `{"avatar" or "background", "media_type", "data"}`: the version, the media type and the image as base64; all of them are `null` when there is no image.

## `preset.list`, `preset.get`

**`preset.list`**: takes no params. The response is `{"presets": [...]}`. The shipped "Everything" (`full`) and "Nothing" (`none`) presets come first, Everything before Nothing; the rest are sorted by id. Each item has `preset`, `icon` (a Lucide icon name, `null` when there is none), `name`, `summary` and `tokens` (how many tokens the system prompt and tool definitions take in a new session opened with this preset, not counting the persona, estimated locally; absent when it cannot be worked out). A broken preset has only `preset`, `problem` and `line`. Everything and Nothing are presets that cannot be changed: these two items have one more field, `fixed: true`, and other presets don't have it; when an interface sees `fixed: true`, it should not offer to change or delete the preset. In Nothing, every switch in the menu is off. No tools (`preset: null`) is not in the list; you can still pass `preset: null` when opening a session or switching presets.

**`preset.get`**: the param is `preset`. The response has these fields:

| Name | Notes |
|---|---|
| `preset`, `name`, `summary`, `icon`, `fixed` | The same as above |
| `unlisted` | `on` or `off` after stacking: whether features the preset doesn't list are on by default |
| `unattended_steps` | The number that `[limits]` gives after stacking: at most how many model requests one turn makes when nobody is watching; `null` when no layer gives a number, which means the built-in 500 applies |
| `features` | Each feature is `{"id", "name", "summary", "package", "on", "by", "installed", "tools"}`; `package` is the package the feature belongs to, used for grouping, and you look up the package's name in [`package.list`](packages.md) (your own scripts, MCP servers and command templates say `~home`; skills outside packages and features that aren't installed have none); `by` says who decided `on`, that is, whether the feature is on: `preset` (the preset says so), `global` (the preset says nothing, and the global switch of the skill, script or MCP server decides, see [`feature.set`](packages.md#featureset); this appears only in presets whose `unlisted` is `on`), `default` (it follows `unlisted`: every feature that a preset with `unlisted` `off` leaves out has this value, and stays off even when its global switch is on); `tools` lists the feature's tools as `{"name", "label", "on"}`, where `label` is the name shown to people (an MCP server's `title` when it gives one, otherwise the tool name without `mcp__<server>__`). Features the preset names that aren't installed come last, with `installed: false`. For a package that connects a platform (its manifest has `[connection]`), only what local sessions can get is listed: a feature with no tool whose `venues` include `local` is left out, and a listed feature shows only its tools with `local`; the same goes for `sections` |
| `sections` | The same features, grouped and ordered so that your interface can draw them as they are, with no translating, sorting or reading ids on your side. Each section is `{"kind", "id", "name", "on", "total", "items"}`: `kind` is `group` (a built-in group: base system, tasks and schedules, injected environment, persona, research; `id` is the group name), `package` (an installed extension with several features gets a section of its own; `id` is the package id), `extensions` (installed extensions with a single feature share this section, one row each, named after the package; left out when there are none), `skills`, `scripts` or `mcp` (these are always there, with `total` 0 when empty), in that order; `on` and `total` count the features that are on and all the features. Each item is `{"kind": "feature", "id", "name", "on", "by"}`; two items with the same name in one section get the package name in brackets; `by` has one more value here, `group` (the preset names the package or group the feature is in, while `preset` means the preset names the feature itself); a feature with several tools also has `tools: [{"id", "name", "on"}]`, and a feature with a single tool doesn't |
| `remove` | The same as in `persona.get` |

`features[].id` is what you write as `features.<id>` in `preset.set`, and `tools[].name` is what you write as `tools.<name>`; don't show them to people.

**Errors**: `unknown_preset`; `preset_invalid` (comes with `data.message` and `data.line`).

## `preset.set`

**Params**

| Name | Type | Notes |
|---|---|---|
| `preset` | string | The preset's id; when omitted, a new preset is created and the core picks `preset-<n>` as its id |
| `new` | boolean | Creates a preset with the ID you wrote (needs `preset`): an ID that already exists (built-in, from a package or yours) is refused with `preset_exists` instead of editing that preset |
| `changes` | array, required, not empty | Each item is `{"key", "value" | "unset": true, "expect"?}`; the keys are `preset.name`, `preset.summary`, `preset.unlisted`, `features.<feature>`, `tools.<tool>` and `limits.unattended_steps` (a positive whole number) |

**Response**: the same as for `preset.get`. An empty string as the summary means "no summary" (it covers the built-in one); only `unset` goes back to the built-in summary.

**Errors**: `bad_params`; `preset_invalid`; `preset_conflict` (`expect` doesn't match; comes with `data.current`); `preset_fixed` (the preset to change has `fixed: true`; nothing is written); `local_only`.

## `preset.delete`

**Params**: `preset`. **Response**: `{"remains"}`, the same as in `persona.delete`. Sessions that are already open keep using the copy they started with.

**Errors**: `nothing_to_delete`; `preset_fixed` (the preset to delete has `fixed: true`; nothing is deleted); `local_only`.
