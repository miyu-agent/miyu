# The bus: `bus.*`

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

The user-space bus lets packages call each other by name: a package declares `provides` (only one package provides a name) or `plugs` (several packages can plug into a name) under `[export]` in its manifest, and heads (interface programs that connect to the core, such as the terminal interface and the web interface) and other packages find and call them by name instead of hard-coding a package id. The core's own methods (sessions, tools, drivers and so on) are not on the bus. To see who provides what and whether it's ready, run `miyu bus list`.

| Method | What it does |
|---|---|
| `bus.call` | Calls a method by name |
| `bus.list` | Lists the names on the bus: who provides them and whether they're ready |

## `bus.call`, `bus.list`

**`bus.call`**: the params are `name`, `method` (the short name: one part, with no dots; the core joins it as `<name>.<method>`), `params` (optional) and `package` (required for a `plugs` name, to pick which package handles the call; for a `provides` name, if you give it, it must be the provider). The core forwards the call the way `package.call` does and returns whatever the package returns; the method answers in the background. Blobs in `params` are passed to the called package (an extension can only pass blobs it can read itself), and blobs in the answer are passed to the caller. An extension must declare `packages.call` to call this method; this is the only way an extension reaches another package, because `package.call` calls by package id and lets an extension reach only itself.

**`bus.list`**: the param is `name` (optional). The response is `{"names": [{"name", "kind", "package", "ready", "methods"}…]}`, sorted by name and then by package: `kind` is `provides` or `plugs`; `ready` means the program is connected and has registered every method it exports under that name (heads decide from it whether to draw an entry); `methods` lists the short names (the part that `bus.call` takes as `method`) of the methods this package exports under the name and has registered right now, sorted alphabetically, and it is empty while the program is not connected: when several packages plug into one name, callers read from it which parts each package implements. With `name`, only that name is listed. To keep following the changes, subscribe to the `bus` stream ([Connection](connection.md)); the core then pushes `bus.changed` ([Pushes](pushes.md)).

**Errors**: `no_provider` (no package provides the name; comes with `data.name`), `package_required` (a `plugs` name was called without `package`; comes with `data.name`), `bad_params` (the short name is empty or has dots), `not_exported` (the joined method isn't in that package's `[export]`); other errors are the same as for `package.call`.

## Well-known names

The shapes of these names are fixed: packages that provide them answer the way described here, and callers call the way described here. Params and answers are JSON objects; fields marked `?` are optional; blobs are written as ids (the `blob` that `blob.put` returns). Errors come back as `method.call` errors with `code` set to one of the strings listed below; the core turns them into `method_failed` and carries the string in `data.code`. Unknown fields get `bad_params`. There is no registry for names: whoever installs first holds a name. For names not listed here, see the provider's documentation for their shapes.

| Name | Kind | Methods | Official provider |
|---|---|---|---|
| `stt` | provides | `transcribe`, `record`, `stop` | `voice-input` |
| `tts` | provides | `synthesize`, `play`, `stop` | `say` |
| `stt.engine` | plugs | `transcribe` | Community speech-recognition engines |
| `tts.engine` | plugs | `synthesize`, `voices` (optional) | Community speech-synthesis engines |

`ready` (`bus.list`) follows registration: `voice-input` registers the three `stt` methods only once its model is downloaded and verified, and `say` registers the three `tts` methods only once the chosen engine is configured. Heads draw the microphone and read-aloud buttons only when the name is `ready`. These methods take one whole sentence in and give one whole sentence out, with no streaming: if you want the first sound to come out quickly, the caller has to split the text into sentences and call once per sentence.

### `stt.transcribe`

Turns a piece of audio into text. The timeout is 120 seconds.

```json
→ {"audio": "<blob>", "language"?: "zh"}
← {"text": "Meeting at three this afternoon", "language": "en", "duration_ms": 2380, "clear": true}
```

- `audio`: 16 kHz mono 16-bit PCM wav is always accepted; wav at other sample rates or channel counts is accepted too, and ogg/opus may be refused. The audio can be at most 10 minutes long.
- `language`: `zh`, `yue`, `en`, `ja`, `ko` or `auto`; when it is omitted, the package's setting is used.
- `clear`: it is `false` when the audio is shorter than 0.5 seconds or has fewer than 2 meaningful characters; `text` is then empty, and this isn't an error.
- `speech`: this field is present only when no speech was heard in the whole recording (even the loudest stretch is only background noise), and it is always `false`: nothing was sent to be recognized, `clear` is `false` and `text` is empty, and this isn't an error. The field is absent when speech was heard. Heads use it to say "no speech heard" rather than "didn't catch that".
- Errors: `bad_audio`, `too_long`, `silent_audio` (the whole recording is digital silence, with a peak of at most 2/32768: the microphone is muted or unplugged, or the system's default input carries no sound; heads use it to say the microphone has no sound), `engine_failed` (the chosen community engine returned an error; `message` is the engine's own).

### `stt.record`

Records from this computer's microphone and transcribes the recording. The timeout is 310 seconds.

```json
→ {"language"?: "zh", "max_ms"?: 60000, "silence_ms"?: 1200}
← {"text": "…", "language": "en", "duration_ms": 4100, "clear": true, "ended": "silence"}
```

- `speech`: the same as for `stt.transcribe`. When `speech` is `false`, the answer also has `device`: the display name of the microphone that was open (for example `fifine Microphone Mono`), omitted when the microphone has no name; heads use it to say "no speech heard, check the microphone, the one in use is …".
- Recording stops after `silence_ms` of silence once the voice stops (default 1200, from 300 to 5000), after `max_ms` at the latest (default 60000, at most 300000), or when `stt.stop` is called. `ended` is `silence`, `stop` or `max`.
- The whole machine shares one microphone lock: if another head or the command line is already recording, the answer is `mic_busy`.
- Errors: `mic_busy`, `no_microphone`, `silent_audio` (the same as for `stt.transcribe`), `engine_failed`.

### `stt.stop`

Stops the recording in progress, no matter who started it.

```json
→ {}
← {"stopped": true}
```

If nothing is recording, the answer is `{"stopped": false}`, and this isn't an error.

### `tts.synthesize`

Turns a piece of Markdown into audio. The timeout is 60 seconds.

```json
→ {"text": "**Sure**, see you at three.", "persona"?: "<persona id>", "format"?: "mp3"}
← {"audio": "<blob>", "media_type": "audio/mpeg", "duration_ms": 1650}
```

- `text`: Markdown text; the provider first turns it into text that can be spoken. It can be at most 5000 characters.
- `persona`: the voice is picked by this persona; when it is omitted, or no voice is configured for the persona, the default voice is used.
- `format`: `mp3` (default) or `wav`.
- Errors: `empty_text` (nothing speakable is left after the conversion), `too_long`, `engine_failed`, `not_configured`.

### `tts.play`

Plays audio through this computer's speakers. The timeout is 600 seconds.

```json
→ {"audio": "<blob>"}   or   {"text": "…", "persona"?: "<persona id>"}
← {"finished": true}
```

- Give either `audio` or `text`; when you give `text`, it is first synthesized the way `synthesize` does it.
- When several requests arrive at once, they are queued in order and don't interrupt each other; requests stopped by `tts.stop` answer `{"finished": false}`.
- The core calls this method too: when a turn nobody spoke in (a schedule or a loop) in a local session produces a voice (a `voice` item in a tool result's `sent`) and no head has that session open, the core sends `{"audio": <blob>}`, without `language`.
- Errors: `bad_audio`, `no_speaker`, and the errors of `synthesize`.

### `tts.stop`

Stops all audio that is playing or queued.

```json
→ {}
← {"stopped": 2}
```

`stopped` is how many items were stopped; it is 0 if nothing was playing.

### `stt.engine.transcribe`

This method is implemented by community speech-recognition engines; the `stt` provider calls the engine chosen in its settings.

```json
→ {"audio": "<blob>", "language": "zh"}
← {"text": "…", "language": "zh"}
```

The `audio` passed to the engine is always 16 kHz mono 16-bit PCM wav, and `language` is always set. Filtering, `clear` and segmenting are the `stt` provider's job; the engine only transcribes. When the engine fails, it returns its own error, and the provider wraps it as `engine_failed`.

### `tts.engine.synthesize`

This method is implemented by community speech-synthesis engines.

```json
→ {"text": "Sure, see you at three.", "voice": "<voice id>", "speed"?: 1.0, "format": "mp3"}
← {"audio": "<blob>", "media_type": "audio/mpeg", "duration_ms"?: 1650}
```

- `text` is already plain text that can be spoken, one sentence of at most 500 characters at a time; `voice` is the engine's own voice id; `speed` ranges from 0.5 to 2.0.
- If the engine can't produce the format that `format` asks for, it returns a format it can produce and states it truthfully in `media_type`.

### `tts.engine.voices`

Optional: lists the voices this engine has. When the engine doesn't register this method, the settings page lets the person type a voice id by hand.

```json
→ {}
← {"voices": [{"id": "female-tianmei", "name": "Sweet female voice", "language"?: "zh"}]}
```
