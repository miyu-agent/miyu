## 软件源

状态：已定（2026-10-19）。项目主人同一天把软件源提前，当面定了末尾「定了的」四条；别的是主会话照推荐定的技术形状。方向沿用 `31-软件包.md` 第八节（2026-10-11）和 `12-进程形态与分发.md` R6；这一份补上「放在哪、怎么从远端查、下、装、升级」，和第八节有出入的以这一份为准。

### 一、放在哪

| 东西 | 在哪 | 谁写 |
|---|---|---|
| 索引 `index.json`、签名 `index.json.sig` | 仓库 `miyu-agent/packages` 的 GitHub Pages：`https://miyu-agent.github.io/packages/` | 那个仓库的 GitHub Actions，每天一次，也能手动触发 |
| 收录规则 `official.toml`、`names.toml`、`blocked.toml`、`sources.toml` | 同一个仓库的 `main` | 项目主人（手写）、Actions（`names.toml` 新占的编号） |
| 包文件 `<编号>-<版本>[-<系统>].miyu` | 各包自己仓库的 Release | 作者打 tag，官方给的 Actions 模板打包、上传 |
| 签名私钥 | `miyu-agent/packages` 的 Actions 密钥，项目主人另存一份 | 项目主人 |
| 签名公钥 | 编进 `miyu`，一份列表（换钥匙时新旧都认一段时间） | 核心 |

- 零成本、零运维：全在 GitHub 上。国内下得慢的以后加镜像（第五节），签名和哈希保证镜像改不了内容。
- Miyu 本身不进软件源：照 R10，谁装的谁升级（AUR、Homebrew、安装脚本）。

### 二、包文件

1. 一个包打成一个文件，zstd 压的 tar，解开是那个包文件夹（`package.toml` 在最上层）；`tar --zstd -xf` 能直接拆开看（31 第八节第 1 条）。
2. **可重现**：同一个文件夹打出来逐字节一样：文件照路径排序、时间写 0、属主写 0、权限只留可执行位。哈希因此只看内容，作者重打一次不变。
3. **系统**：清单 `[package] targets` 可以不写（哪种系统都能装，文件名不带系统）；带了本机程序的写它能跑的几种（`linux-x86_64`、`linux-aarch64`、`macos-aarch64`、`windows-x86_64`），一种一个文件、文件名带系统。装的时候只挑本机的那一个；没有的说「这个包没有本机能用的版本」。「平台」在清单里说的是通讯平台（`[connection] platform`），这里叫「系统」（施工 G-1 起的说法）。
4. **怎么打**：`miyu pkg pack <包目录>` 先照装的那一套查清单（写错的一处都不打），印出文件名、大小、SHA-256。作者的 Actions 模板就是装上 `miyu`、跑这一条、传进 Release。
5. **本机装 `.miyu` 文件**：`miyu pkg install <文件>.miyu` 和装文件夹一样（解进暂存处，再走 31 第三节）。
6. **桌面认得出**（施工 G-14，2026-10-22 项目主人定）：Linux 上 `*.miyu` 挂在已有的 `application/x-zstd-compressed-tar` 名下（shared-mime-info 的定义 `packaging/mime/miyu.xml`，权重 80），解压软件能直接打开看里面；不另开类型、不给图标、不做双击安装。挂在已有类型名下而不是另开子类：File Roller 只认精确的类型名。谁装到哪、谁跑 `update-mime-database` 见 `12-进程形态与分发.md` 第四节。`miyu-source` 的 `tests/mime.rs` 守着它的后缀和 `archive::EXTENSION` 对得上。

### 三、索引

1. **写法**：

   ```json
   {
     "version": 1,
     "generated": "2026-10-19T03:00:00Z",
     "packages": [
       {
         "id": "embed",
         "version": "1.0.0",
         "name": {"zh": "语义模型", "en": "Embedding model"},
         "summary": {"zh": "…", "en": "…"},
         "author": "miyu-agent",
         "origin": "github.com/miyu-agent/miyu-embed",
         "official": true,
         "kind": "worker",
         "provides": {"features": ["…"], "skills": [], "personas": [], "content": ["im"]},
         "capabilities": [],
         "depends": [],
         "files": [
           {"target": null, "url": "https://github.com/…/embed-1.0.0.miyu", "sha256": "…", "size": 61234567}
         ]
       }
     ],
     "blocked": [{"id": "…", "origin": "…", "reason": "…"}]
   }
   ```

   名字、简介、种类（施工 G-11：网页的软件市场照它筛，以前生成的没有）、带了哪几样、能力、依赖都从包文件里的清单读出来，作者不另写一份。一个编号只列一个版本（最新的那一版），旧版不列：要退回旧版靠缓存（第四节第 5 条）。
2. **签名**：ed25519 签整个 `index.json` 的字节，`index.json.sig` 是 `{"key": "<公钥编号>", "signature": "<base64>"}`。验不过、钥匙不认识的整份不收。
3. **不许退回旧索引**：本机存着的那份 `generated` 更新的，拿来的旧索引不收（防有人拿一份签过名的旧索引让人装回有漏洞的旧版）。
4. **收录**（`miyu-agent/packages` 的 Actions，跑核心仓库发的 `miyu-index` 程序，读清单用的就是 Miyu 自己的那一套）：
   - 照 `sources.toml` 一条条收。现在只有一条 `kind = "official"`：`official.toml` 列的仓库（项目主人自己的），各取最新的 Release 里的 `.miyu`。
   - 下下来、查清单、算哈希；读不成、系统和文件名对不上的不收，记进这一趟的报告（Actions 的摘要）。
   - `names.toml`：编号先到先得，第一个收录的仓库占住，永远跟着它（31 第八节第 3 条）。官方的也照这张表走，以后社区的进来不用改规矩。
   - `blocked.toml`：编号或仓库、一句理由；收录时去掉，并写进索引的 `blocked`。
   - `official` 这一格照「来源仓库在不在 `official.toml`」写。
5. **以后接社区自动收录**（这一轮不做，写法先备好）：`sources.toml` 多一条 `kind = "topic"`、`topic = "miyu-package"`，收录程序多一种来源；`names.toml`、`blocked.toml`、`official` 这一格、客户端「社区包没人审过」那一句都已经在，那时只加这一种来源和晾 24 小时（31 第八节第 6 条，那时再问）。

### 四、用户这一头

网络和校验都在核心里做，命令行、两个头、引导、她的工具都走核心的同一套方法。

1. **拿索引**：`miyu pkg update`（`-Sy`）照第五节的地址先后试，验签、比 `generated`，存进 `state/packages/.sync/`（索引原文和签名原文一起存，下次起来再验一遍）。
2. **自动刷新**：不设定时器（核心自己不定时醒，V-6 下）。有人用到软件源的时候（`search`、`install <编号>`、`upgrade`、头打开软件包页问「有几个能升级」）本机那份超过 24 小时就先刷新一次；刷新不成的照旧用本机那份，说一句「软件源连不上，用的是 <时刻> 的索引」。
3. **搜**：`miyu pkg search <词>`（`-Ss`）在本机索引里搜编号、名字、简介；每条写装没装、能不能升级、官方还是社区、被拉黑了没有。
4. **装**：`miyu pkg install <编号>`（`-S`）。
   - 依赖照 pacman 自动补：缺的依赖从软件源一起装，印的那一份把它们列在前面，一起问一次「接着装？」；软件源里也没有的依赖装不上，说清缺哪个。
   - 印的那一份另写来源仓库、官方还是社区（社区的加一句「没人审过」）、下载多大。
   - 下载照第五节先镜像后原址，边下边算 SHA-256，对不上不装；下好的放缓存。之后走本机装 `.miyu` 那一条（第二节第 5 条）。装完带程序的照旧默认不开。
   - 下载给头进度：`package.progress` 推「哪个包、下了多少、一共多少」。
5. **缓存**：`state/packages/.cache/<文件名>`（照 `/var/cache/pacman/pkg`；数据根就是那台「系统」，施工 G-4 上定）。索引里同编号换了版本，旧版本的文件照留；装旧版本就从缓存装 `.miyu` 文件。`miyu pkg clean`（`-Sc`）清掉不是装着那一版的。
6. **升级**：`miyu pkg upgrade`（`-Su`，`-Syu` 先刷新再升）。照 31 第八节第 4 条：索引的那一版和装着的不一样就换（不比大小），来源仓库和装的时候不一样的不升，`packages.hold` 里的跳过，从本机文件夹、本机文件装的不碰。新版要的能力比旧版多的，换上以后多出来的那几样照旧要人批了才开（R6、「扩展不自动升级」）。不自动升级：头上只显示「N 个可升级」，人点了才升。
7. **软件源里没了、被拉黑**：照 31 第八节第 5 条：装着的照用，`list`、`info` 标一句「软件源里没有了」或「被拉黑：理由」，`update`、`check` 时提示一次。
8. **引导**：引导里下载内置语义模型就是 `install embed`，进度照第 4 条。
9. **她的工具**：基础系统「软件包」那件工具多两样：从软件源搜（只读，哪一级都不问）、按编号装（照 31 第六节那张权限表：完全放开直接装，工作区问人一次，卡片写来源仓库、官方还是社区，只读不能装）。升级也照这张表。

### 五、地址和镜像

- 配置 `packages.source`：软件源的地址，默认 `https://miyu-agent.github.io/packages/`。
- 配置 `packages.mirrors`：几个镜像的地址，照先后试，都不成再试原址。一个镜像就是一棵目录：`index.json`、`index.json.sig`，和 `files/<文件名>`。索引从镜像拿也要验签；包文件从镜像拿也要比哈希。
- 以后加别人的软件源（R6「第三方源要人明确信任」）：配置里多一张表，写地址和它的公钥，人自己加就是信任它。这一轮不做，`packages.source` 只认官方那一个。

### 六、核心的方法

| 方法 | 做什么 |
|---|---|
| `package.sync` | 拿索引（`force` 不管 24 小时也拿），回本机索引的时刻、包数 |
| `package.search` | 在本机索引里搜，`query` 空的列全部；每条带 `installed`、`upgradable`、`official`、`blocked` |
| `package.install` | 多一种写法 `{"source": "<编号>"}`；`preview` 照旧只看一眼（依赖、下载多大都在里面） |
| `package.upgrades` | 能升级的几个 |
| `package.upgrade` | 升级，`packages` 不写是全部能升的；`preview` 同上 |
| `package.clean` | 清缓存 |
| `package.progress`（推） | 下载进度 |

### 七、施工拆分

| 步 | 做什么 |
|---|---|
| G-1 | 包文件：`miyu pkg pack`（可重现）、清单的 `targets`、本机装 `.miyu` 文件 |
| G-2 上 | 索引：写法、签名和验签（公钥列表）、`miyu-index` 的 `keygen`、`sign`、`verify` |
| G-2 下 | 收录：`miyu-index build`，`sources.toml` 的来源接口（先做 `official`），下包文件、读清单，`names.toml`、`blocked.toml` |
| G-3 上 | 拿索引：`packages.source`、`packages.mirrors`、`package.sync`、`miyu pkg update`、不许退回旧索引、24 小时的按需刷新 |
| G-3 下 | 搜：`package.search`、`miyu pkg search` |
| G-4 上 | 从软件源装（核心）：下载、镜像先后、哈希、缓存、依赖自动补、进度、本地库记来源 |
| G-4 下 | 从软件源装（命令行）：`miyu pkg install <编号>`、`-S <编号>`，印要装的、问一句；`clean`（`-Sc`） |
| G-5 | 升级：`upgrades`、`upgrade`、`hold`、来源仓库不同的不升、没了和拉黑的提示 |
| G-6 | 她的工具：从软件源搜、按编号装和升级，照权限表 |
| G-7 | 官方仓库 `miyu-agent/packages`：Actions、Pages、钥匙（要项目主人建密钥）；作者的打包模板；第一批官方包（语义模型、表情包、接入QQ 等）发进去 |
| G-8 | 引导里下载语义模型走软件源 |

G-1 到 G-5 在核心仓库里做，测试照本机起一个假的软件源（本地 HTTP 服务、测试用的钥匙）；G-7 碰到项目主人的 GitHub 组织和密钥，做之前说清要建什么、在哪建。
