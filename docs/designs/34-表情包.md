## 表情包

一个第三方写法的软件包 `miyu-memes`（仓库 `miyu-agent/miyu-memes`）：她能存、查、发、改、删表情包；按描述的意思搜；隔一阵提醒她这一轮发一张；网页有它的后台页，终端、网页的配置页能改它的几项；别的软件（接入QQ）经它留的口子往库里放图，放的时候带一句「为什么偷这张」。

这也是一次检验：照第三方作者能拿到的东西（`docs/authors/README.md`）做一个完整的包，看软件包系统缺什么。缺的补进核心，不给这个包开后门。

状态：方向已定（2026-10-16 项目主人定第二节）；第三节起是主会话照推荐写的技术形状，施工前各出图纸。

### 一、为什么要有

- 起因（2026-10-16）：项目主人要一个和旧版一样的表情包功能，做成独立仓库的软件包，顺带检验软件包系统完不完善、规不规范。
- 旧版（`Miyu` 仓库）：`use_meme`（search、show）和 `manage_meme`（add、update、delete）两件工具；库照人格分（`src/memes/<人格>/index.json` 加 `images/`），每张有编号（内容的 sha256）、中英名字、描述（画面上有什么）、用法（什么时候用）、标签；描述用视觉模型生成，按意思搜；每轮按概率（出厂 5%）在她要回的那句话后面塞一段「这一轮必须发表情包」的提醒；QQ 里另有「收集表情包」的插件。
- 照第三方作者今天能拿到的东西，做不出来的四处（第五节补进核心）：
  1. 往上下文里加提醒：清单里有 `context.inject` 这个能力名，协议上还没开放（作者说明第六节第 1 条）。
  2. 按意思搜：embedding 只在核心里（记忆、知识库用），扩展调不到。
  3. 软件之间互相调：`package.call` 只给出示本机令牌、登录令牌的连接（头），扩展调不了别的扩展的方法。
  4. 她发一张图：她的回复只有字，接入QQ 只发纯文字；「她发出去的图」在核心里还没有这回事（设计 33 之后搁置的「展示」讨论，`show_image`）。

### 二、定了的（2026-10-16 项目主人）

1. **整个账号一个库**，几个人格共用。
2. **`miyu-memes` 里不带图**；旧版那一套做成另一个软件包 `miyu-memes-shorin-collection`（仓库同名，只带图和描述、用法，没有程序），想要的自己装，以后写自动安装的脚本也方便（第三节「内容包」）。
3. **她发表情包要像人**：表情包把意思说到了，就不配字。
   - 发一张就是她说的一条，只有一张图。
   - 「发送表情包」发完默认就结束这一轮（核心 4-14「工具结果能结束这一轮」）：像人回一张表情包当最后一句。先说字再甩图，就先写字再调；图后还接着说，调的时候写 `end: false`。不配字是她的选择（一个字不写直接发），不是开关；不再用旧版「调了以后写的字丢掉」的参数。
   - 已经知道编号、知道是什么、什么时候用的，直接发，不用先搜。
   - 她的上下文里不另加一行：她调「发送表情包」的那次调用和结果（`Sent m3f2.`）本来就在历史里；图只给终端、网页、QQ 画，不进她的上下文。
4. **画在哪**：表情包画在正文里，和回答的字一样；「发送表情包」这一步和前面的步骤一起收进时间线的「Used x tools · …」（照终端、网页收起的配置）。
5. **QQ 里**：只发这一轮最后那段字（中间的过程本来就不发）和表情包；先后照表情包是在那段字之前还是之后调的；表情包照 OneBot 图片段带 `sub_type=1`、`subType=1`（QQ 当表情显示，长边约 150px，动图原样；旧版 `outbound.rs` 的 `image_segment`）。
6. **工具分开**：五件，权限、显示名、必填项各是各的（第四节）；全量常驻，不标「要先加载」：发表情包多是顺手一发，先加载多一次来回会让她懒得发。五件常驻约 392 token（magpie 那组实测，合成一件约 245），走缓存。
7. **提醒**：出厂 3%，群、私聊、本机三处都开；配置页能分别关、能改概率。
8. **终端配置页**：「软件包」先列包、进去一包一页（终端那边在做），表情包的几项在「软件包 › 表情包」。

### 三、包里有什么

| 东西 | 写法 | 说明 |
|---|---|---|
| 清单 | `package.toml` | 编号 `miyu-memes`，名字「表情包」，图标 `smile` |
| 程序 | `bin/miyu-memes`（Rust，三个平台各一份） | 扩展：`[process] args = ["serve"]`、`start = "always"`；命令行 `miyu memes …`（导入、导出、查） |
| 工具 | `provide` | 第四节 |
| 配置项 | `[settings]` | 第六节；终端、网页的配置页「软件包 › 表情包」照清单画 |
| 后台页 | `[page] dir = "page"` | 网页的独立整页（第七节）：设置的「软件后台」点进去 |
| 能力 | `capabilities` | `tools`、`context.inject`、`context.system`、`sessions.send_media`（第五节新加；用 embedding 的 `model.embed` 不另设能力，施工 X-17）；给接入QQ 调的方法写在清单 `[export] methods = ["add", "search"]`，不是能力（施工 X-18） |
| 内容包 | 另一个包，例如 `miyu-memes-shorin-collection`：清单只写 `[package]` 和 `[content.miyu-memes] dir = "memes"`（施工 X-22，通用的「给别的包带的内容」），文件夹里 `index.json`、`images/` | `miyu-memes` 经 `content.list`、`content.read` 读进库（`source = pack`，记是哪个包），装卸以后核心推 `content.changed` 再比一遍；卸了内容包，它带来的、没被人改过的一起拿掉，改过的留下 |
| 状态 | `<数据根>/state/packages/miyu-memes/` | `library.db`（SQLite）、`images/<sha256>.<扩展名>`，卸载一起删 |

**一张表情包**：

| 格 | 说明 |
|---|---|
| `id` | 短编号：内容 sha256 的前 8 位十六进制（撞了往后多取），她和人都用它；完整的 sha256 另存，同一张图不存两份 |
| `description` | 画面上有什么，一两句，给她看、拿来搜 |
| `usage` | 什么时候用，一两句，给她看、拿来搜 |
| `source` | 怎么来的、从哪来：`{kind, package?, platform?, venue?, sender?}`，`kind` 是 `ai`（她存的）、`human`（人在后台页传的）、`pack`（内容包带的）、`package`（别的软件经口子放的）；后面几格是别的软件交的，原样存，只给后台页看 |
| `reason` | 为什么存这张：她或别的软件写的一句（偷图的理由），人在后台页看得到；可以没有 |
| `enabled` | 停用的搜不到、发不了，后台页能再开 |
| 用了几次、最后一次 | 后台页排序用 |

### 四、工具

五件，名字带 `meme_` 前缀，全量常驻（第二节第 6 条）。说明、参数写英文短句，照登记簿量 token（包自己的登记簿，第五节第 1 条）。

| 工具 | 显示名 | 参数 | 做什么 | `access` |
|---|---|---|---|---|
| `meme_search` | 挑选表情包 | `query`、`limit`（默认 5） | 按意思（embedding）加关键词搜，交回几条：编号、描述、用法；已经知道编号的不用先搜 | `read` |
| `meme_send` | 发送表情包 | `id`、`end`（默认 `true`） | 发这一张（第五节第 4 条），结果 `Sent <编号>.`；`end` 是真的发完就结束这一轮 | `read`（跟她回的字一样是回话，不往 Miyu 外面发；写 `outbound` 每发一张都要人确认，10-16 端到端实测改） |
| `meme_save` | 保存表情包 | `path`、`description`、`usage`、`reason` | 把一张图存进库：本机文件的路径（她读得到的地方），描述、用法她自己写（她看得见图）；同一张图已经在的，交回已有的编号 | `write` |
| `meme_edit` | 编辑表情包 | `id`、`description`、`usage` | 改描述、用法 | `write` |
| `meme_delete` | 删除表情包 | `id` | 停用（后台页能找回、能真删） | `write` |

- 聊天里别人发的图：图在上下文里没有路径，v1 只收本机文件；QQ 里的图走第五节第 3 条的口子由接入QQ 放进来（以后「偷表情包」）。

### 五、要补进核心的（每条一步施工，先于这个包）

1. **扩展往上下文里加东西**（`context.inject`）：回合开始的挂接点（记忆、知识库用的那一个）也问声明了这项能力、批过的扩展：核心发 `user.append {session, venue, text}`（X-16 补改名），扩展在时限里（出厂 300 毫秒）回 `{content: [{kind, text}]}` 或空的，超时当空的；交回的记成 `context.injected`，`by` 是这个包，排在触发的那句话后面（X-16 补，项目主人 10-16 定插到用户消息尾部），不进前缀。概率由扩展自己掷。提醒的原文是这个包的，进不进登记簿：包的给模型看的字由包自己登记（作者说明加一条），核心的登记簿只管核心的。
2. **扩展用 embedding**（施工 X-17）：核心方法 `model.embed {texts}`（同 `model.call` 不另设能力），照这个账号的 `models.embedding`（本机的 `miyu-embed` 或者远程那一家）算，交回向量和模型的编号（换了模型要重算）。没配 embedding 的回 `embedding_off`，包退回关键词搜。
3. **软件之间互相调**（施工 X-18）：包在清单里写哪几个方法给别的软件调（`[export] methods = ["add", "search"]`，不是能力），声明了 `packages.call` 的扩展可以 `package.call` 这几个；别的方法 `not_exported`、没声明的 `needs_approval`。转过去的 `method.call` 带 `from`（调的包的编号，核心填），被调的照它记 `source = package`。
4. **她发一张图**（施工 X-19）：扩展的工具回答多一格 `sent: [{blob, media_type, width, height, alt?, sticker?}]`（至多 4 张），记进 `tool.result.sent`；**不进给模型的请求**（调用和结果的字已经在历史里）；给头的视图出 `media` 条目，画在正文里、把前面那段时间线收起（第二节第 4 条）；接入QQ 照它发（第二节第 5 条）。原来想的「另记一条 `message.assistant`」不做：她没说这句话，记成工具结果的一格，先后照日志天然对。这一格也是以后 `show_image` 的底子（设计 33 后搁置的「展示」）。

5. **扩展往系统提示词里放一段**（2026-10-16 项目主人提、定：静态、动态统一成一个方法，原来分成的「开会话的扩展给会话插一段」「软件包自己的几行」两步合成这一步）：
   - 一个方法 `system.append {content, session?}`（施工 X-20，名字项目主人定：一眼看得出插在 system 尾部）：不写 `session` 的管它出现的全部会话，写了的只管那一个、优先；`content` 写 `null` 去掉那一层。只想放固定几句的包起来时调一次。
   - 原文照放，不套包的编号，外壳包自己写；每个包一段，照包的编号排，接在整段 system 的最后（26 第四节第 8 块，项目主人定「尾部」）。只插不改人格原文。
   - 工具面上有这个包的工具的会话才带（预设关了、卸了就没有）。
   - 改了下一轮换上，那一轮整段重算一次（system 在最前面，改了后面全要重算，几个包谁前谁后和缓存无关，照编号排就行）；核心重启以后照会话钉住的那份，扩展再设一样的不再断。
   - 要声明新能力 `context.system`、人批过（出厂的算批过；主会话照推荐定，项目主人没有另说）。
   - 只带技能、MCP 服务、没有程序的包调不了方法；以后真有需要再给清单加写法。

### 六、配置项（`[settings]`，终端、网页的配置页照画）

| 键 | 类型 | 出厂 | 说明 |
|---|---|---|---|
| `miyu-memes.reminder_probability` | `int` 0–100 | 3 | 每轮提醒她发一张的概率，百分数 |
| `miyu-memes.reminder_group` | `bool` | 开 | 群里提醒 |
| `miyu-memes.reminder_private` | `bool` | 开 | 私聊里提醒 |
| `miyu-memes.reminder_local` | `bool` | 开 | 本机（终端、网页）提醒 |
| `miyu-memes.max_size_mb` | `int` 1–20 | 5 | 一张最大多少 MiB，超了不收 |

### 七、后台页（网页的独立整页）

- 一屏网格：缩略图、编号、描述的头一行；上面一个搜索框（同她的搜法）和筛选（来源、停用的）。
- 点一张：右边详情，大图、描述、用法、来源、偷图的理由和从哪来、用了几次；改描述、用法，停用、找回、真删。
