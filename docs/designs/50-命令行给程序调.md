## 命令行给程序调

`miyu ask` 照 `claude -p`、`codex exec` 的用法补齐，别的程序能把 Miyu 当成一个命令调：从标准输入喂材料、边跑边读事件、在命令行上挑人格、预设、目录和权限级别。总帮助页、`ask` 的帮助页照 git、GNU 的写法整理。

状态：已定（2026-10-30 项目主人照推荐选了读标准输入、事件流、指定人格预设目录、整理帮助页，另选了「加 `--permission` 级别」）。项目主人以前用命令行把 Codex、Claude Code 接进过自己的程序，觉得好用，问 `miyu` 做不做得到。第二到第五节的细节是技术题，主会话定。施工：AP-1、AP-2 做完。

### 一、现在有的、缺的

有：一句话跑完就退出；标准输出只有回答，过程、思考、用量都在标准错误；`-c`、`-s` 接着说；`--format json` 结束时一行 JSON；退出码 0–5；`--timeout`、`--file`、`--model`、`--add-dir`、`--no-memory`、`--from`。

缺：不读标准输入；没有边跑边出的事件；命令行上挑不了人格、预设、目录、权限级别；帮助页有几处不合规矩（第五节）。

### 二、标准输入

1. 没写消息、标准输入不是终端：读到头，整段就是消息。
2. 消息里有一个词正好是 `-`：去掉它，读标准输入接在消息后面，空一行隔开。例如 `cat 报错.log | miyu ask "为什么失败" -`。
3. 写了消息、没写 `-`：不读标准输入。别的程序拉起 `miyu` 时常常留着一个不关的管道，照 `claude -p` 那样一看到管道就读，会一直等下去；要材料的明写 `-`（同 `codex exec` 的 `-`）。
4. 标准输入是终端、又没写消息：照参数写错报，退出码 2。
5. 读到的不是 UTF-8 的：报「miyu: 标准输入不是 UTF-8 文本」，退出码 2。读到空的、只有空白的：报没有消息，退出码 2。
6. 上限照核心收一句话的上限；超了照核心的拒绝说。

### 三、新会话的几样（只管新开的会话，和 `-c`、`-s` 一起写的照参数写错报）

| 选项 | 做什么 |
|---|---|
| `-C, --cd <目录>` | 在这个目录干活，不用先 `cd`（同 `git -C`、`codex exec -C`）；相对的照现在的目录接 |
| `--persona <编号>` | 用这个人格 |
| `--no-persona` | 不用人格 |
| `--preset <编号>` | 用这个预设 |
| `--permission <级别>` | 这个会话开局的权限级别：`read-only`（只读）、`workspace`（工作区，执行命令在沙盒里）、`full`（完全放开，不启用沙盒）；不写的照配置 |

要确认的步骤照旧：`miyu ask` 里没人能确认的一律跳过、退出码 4。`--permission full` 下本来就不用确认的那些照常做；放宽到哪一级是调用方明写的，`miyu` 不另外加「全都同意」的开关。

### 四、事件流

1. `--format jsonl`：标准输出一行一个事件，边跑边出；标准错误照旧只印出错。退出码和 `text` 一样。
2. 每行一个 JSON 对象，`type` 说是什么，格照名字的字母先后排。形状是命令行自己定的一份，从核心的事件裁出来，不原样转发核心的事件：核心的事件以后加格、改说法，这一份照旧稳定。
3. 几种（细的格写在蓝图 `cli/ask.md`）：

| `type` | 什么时候 | 主要的格 |
|---|---|---|
| `session` | 开始，一次 | `session`、`new`（是不是新开的） |
| `turn.started` | 一轮开始 | `turn` |
| `thinking` | 思考，一段一段 | `text` |
| `text` | 回答，一段一段 | `text` |
| `step` | 一步开始 | `id`、`tool`、`title` |
| `step.done` | 一步结束 | `id`、`ok`、`summary` |
| `agent.reported` | 子代理回报 | `agent`、`text` |
| `compaction` | 压缩了 | `before`、`after` |
| `warning` | 告警（同 `miyu: 警告：` 那几句） | `message` |
| `turn.ended` | 一轮结束 | `turn`、`text`（这一轮的全部回答）、`usage`、`error`? |
| `done` | 最后，一次 | `session`、`exit`（退出码）、`reason`? |

4. `--format json` 照旧：结束时一行。

### 五、帮助页

1. 用法写 `Usage: miyu [<command>] [<options>]`，下面一句「不带命令时打开默认界面」。
2. 命令照用途分组：对话（ask、undo、restore、redo、compact、recap、rename）、内容（memory、kb、schedule）、软件包（pkg、mcp）、设置（config、check、provider、setup）、系统（web、service、sandbox）；软件包加的命令另一组。
3. 总表只列命令和全局选项（`-h`、`-V`），放在 `Options:` 一节里；`ask` 和会话那几条命令的选项挪回各自的帮助页。末尾写「运行 'miyu help <command>' 查看命令的说明」。
4. 占位统一：要填的写 `<名字>`，可以不写的整段用方括号，几个选一的写 `<text|json>`。
5. `ask` 的帮助页加「退出状态」一节，列 0–5；例子加一条给脚本用的（`--format jsonl`、`-`）。
6. 中英文两份同样改，照设计 47 的规矩和 CL-3 的检查。
