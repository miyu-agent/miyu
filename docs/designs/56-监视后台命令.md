## 监视后台命令

放到后台的命令可以选「出一行就叫醒她」：命令一直跑，标准输出每出一批行，记一条事件，会话闲着就开一轮；跑到最长时间照后台命令的规矩停下、报回来，要接着看的她再起一次。照 Claude Code 的 Monitor 做，但不另开一件工具，是 `shell` 后台命令的一种跑法。

状态：已定（2026-11-03 项目主人照推荐定「做成后台命令的一种跑法」，细节主会话照推荐定）。施工 MN-1（上、下两步，见第六节）。

### 一、为什么要

1. 现在有的两样，都只管「等一件事」：后台命令结束了叫醒她（`job.reported`，`docs/blueprint/agents.md` 第四条），到点叫醒她（`schedule_wakeup`、定时任务，`45-定时和循环.md`）。
2. 「每发生一次就告诉我」做不到：盯日志里的报错、盯硬盘占用过线、盯 CI 每一台出结果。只能绕：
   - 起一个「条件成立就退出」的后台命令，叫醒以后她再起一个，中间那段没人看；
   - 或者 `schedule_wakeup` 隔一阵去看一眼，看的间隔里发生的事要等到下一次。
3. 主会话自己天天这么用（硬盘 93% 提醒、CI 逐台出结果），项目主人 2026-11-03 问 Miyu 有没有，照推荐定补上。

### 二、她怎么用

1. `shell` 加一个参数 `watch`（布尔），说明一句：`Implies run_in_background. Each stdout line wakes you.`。写了它的照写了 `run_in_background: true` 走，两个都写、只写 `watch` 一样。
2. 结果那一句（调用之后才用得上的写在这里，不写进说明，`10-自带软件.md` 第九节）：说编号，说「标准输出每一行会叫醒你，只打印要你动手的行；标准错误只进输出文件；跑到 N 分钟停下，要接着看再起一次」。N 照这一轮的 `jobs.max_running`。
3. 用 `jobs` 停、查输出，和别的后台命令一样。

### 三、怎么走

1. **只认标准输出**：写了 `watch` 的命令，标准输出和标准错误分开读。标准输出的行既记事件、也写进 `jobs/<编号>.out`；标准错误只写进 `.out`，不叫醒。不写 `watch` 的后台命令照旧合成一根管道，一个字节不变。理由：报错、进度条一般走标准错误，混进来就是一直叫醒她（Claude Code 同样只认 stdout）。
2. **攒一批再记**：一行到了起一个 200 毫秒的窗口，窗口里到的行合成一批，记一条 `job.output`（第四节）。一批最多 `jobs.report_chars` 个字，超过的留头尾、中间写省了多少个字（截法和 `child.reported` 同一份）。没有换行结尾的半行等到换行、命令结束或者窗口满 4096 字再算一行。
3. **叫醒照回报的规矩**（`docs/blueprint/agents.md` 第三条）：会话闲着，开一轮；正在跑，下一步看到；没人看着的一次性会话只记下；撤销还能恢复的只记下、不开轮；派它的那一轮撤掉了的不叫醒、不渲染。
4. **她忙着的时候不一行一条**：这一轮在跑时到的批次先在执行器里攒着，到她下一步要发请求之前合成一条记下（照样走第 2 条的截法）。一轮里她看到的是「上一步以后又出了这些」，不是几十条事件。
5. **太吵就停**：一条监视一小时里记满 120 条 `job.output` 的，照停掉的规矩整组杀，报 `job.reported`，`reason` 是新的 `too_chatty`，叫醒她一次（她知道是因为太吵停的，改过滤再起）。数的是记下的条数，第 4 条合掉的算一条。
6. **到时停**：最长时间照后台命令的 `jobs.max_running`（默认 30 分钟，最长 2 小时），不另设一个：到了报 `timed_out`、叫醒她，和 Claude Code 的 Monitor 到期一样由她决定要不要再起。命令自己退出的报 `exited`。
7. **核心重启**：照后台命令（`restarted`、`aborted`），监视不自己续上：看的东西可能已经变了，由她决定。
8. **关了「后台运行」的预设**：`watch` 跟 `run_in_background` 一起从工具面上去掉（`Tool::background_parameter` 认两个），硬写的照「这里不能放到后台」说。
9. **Windows**：分开读两根管道照现有的前台做法（前台本来就分开起、再合）；沙盒里的命令一样。

### 四、事件 `job.output`

1. 新的事件种类，落库、进上下文，和 `job.reported` 并列：`{"job": 7, "text": "...", "lines": 3, "omitted": 0}`。`job` 是编号，`text` 是这一批的行（`\r\n` 换 `\n`），`lines` 是这一批原来有几行，`omitted` 是截掉的字数。`by`、`cause` 照 `job.reported`。
2. 渲染给她：照回报的外壳，注明是哪个后台命令（编号、标题）出的。原文和样本照 `26-提示词.md` 的规矩进登记簿、量 token。
3. 是「别处来的」：撤销一轮不删它（`02-内核.md` 第六节），压缩照别的事件一样压。
4. 头看得到：视图流里是一条后台命令的输出，终端、网页照回报那样画一行，点开看全文；改协议照规矩告诉两个头。

### 五、前缀和预算

1. `shell` 多一个参数是一次计划内的冷启动，之后字节不变（`remake-prefix-stability-first`）。说明那一句量 token、进登记簿，受工具面的预算管；超了改字，不提预算。
2. 不另开 `monitor` 工具：多一件工具多一份信封和说明，停、查输出、生命线、重启补记全都得再做一遍。
