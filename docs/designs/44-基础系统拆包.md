## 基础系统拆包

核心不自带非装不可的工具。基础系统从一个必需的内置包拆成十八个普通的内置包，一件工具或一样行为一个包，`sessions` 和 `send_message`、`packages` 和 `package` 两对各合一个；「基础系统」改叫一个组，默认全装。每个包都能关、能卸，卸了名字空出来，别人的同名工具照平常装，这就是「换」。装卸包不再是她的工具：会话里她跑 `miyu pkg`，经 `miyu call` 的通道带着会话身份，照原来的权限表问人。

状态：已定（2026-10-26）。项目主人同一天先问「核心是不是不该自带任何内置工具，别人觉得不好可以方便地卸掉换成自己的」，接着定了几条（第六节）。环境那几块另做一个包 `env`（施工 ENV-1），本设计只认它的存在。

### 一、现在缺什么

- **基础系统是必需的**：清单写 `required = true`（`resources/packages/basesystem/package.toml`），关不了、卸不了（`package_required`），没装时核心起来记一行 `WARN required package missing`。
- **换不了**：基础系统的工具占着 `read`、`shell` 这些名字，别的包带同名工具装的时候撞名被拦。想换一件只能整包卸掉，可整包是必需的。
- **一个包里十几样**：功能（`files`、`commands`、`background`……）只是预设里的开关，同一个包一起装、一起卸。
- **装卸包占工具面**：`packages`、`package` 两份说明每个请求都带，平常对话用不上。

### 二、别家

- **pacman**：`base` 是一个组，组里每个包各自能卸；`pacman -S base` 装回全组。组只是包上的一个标签，没有自己的文件。
- **Claude Code、Codex**：工具都编死在程序里，换不了，只能用权限关掉。我们不取。

### 三、样子

**1. 十八个包**

| 包 | 带的工具 | 跟着它走的 |
|---|---|---|
| `read` | `read` | |
| `write` | `write` | |
| `edit` | `edit` | |
| `glob` | `glob` | |
| `grep` | `grep` | |
| `trash` | `trash` | |
| `shell` | `shell` | 前台不许干等 `sleep`（施工 4-8 补三） |
| `jobs` | `jobs` | 没装或者预设关着的会话没有后台：`shell` 去掉 `run_in_background`，子代理在前台等（施工 T-1 上原来照功能 `background`） |
| `subagent` | `subagent` | |
| `ask_user` | `ask_user` | |
| `todowrite` | `todowrite` | |
| `history` | `history` | |
| `session_usage` | `session_usage` | |
| `sessions` | `sessions`、`send_message` | |
| `packages` | `packages`、`package` | 两件不上工具面，只给会话里的 `miyu pkg`（下面第 4 条）；依赖 `shell` |
| `show` | `show` | 设置 `show.system_hint`（原来 `basesystem.show.system_hint`） |
| `project-docs` | 没有 | 回合开始交仓库里的 `AGENTS.md`（施工 P-14） |
| `clicall` | 没有 | 会话里的命令能经 `miyu call` 调工具（设计 39）；依赖 `shell` |

- 都是出厂的内置包，代码照旧在 `miyu-basesystem` 一个 crate 里，各自登记到自己的包下（`Catalog::in_packages` 一包一组）。资源文件照旧放在 `resources/software/basesystem/`，只是清单拆成 `resources/packages/<编号>/package.toml` 十八份。
- 一个包就是一个开关，包里不再分功能。预设照包开关（`[software] shell = true`），原来写在 `[features]` 里的 `files`、`commands` 这些不认了。
- 依赖照现成的 `needs`：`packages`、`clicall` 写 `needs = ["shell"]`。别的之间没有硬依赖：`edit` 自 ED-1 起不用先 `read`；子代理没有 `jobs` 就在前台等。
- 没有哪个包是必需的。清单的 `required` 一格删掉，连同拒绝 `package_required`、`package.list` 的 `required`（第六节第 5 条）。出厂带哪些包是发版打包时挑的事，核心不替它定。

**2. 组：`basesystem`**

- 清单多一格 `[package] groups = ["basesystem"]`。组的名字、说明（三种语言）写在资源目录 `resources/packages/groups.toml`，一个组一段。
- 只有出厂那一层能写 `groups`，家目录的包写了报 `bad_group`，组名不在 `groups.toml` 里的也报 `bad_group`。这样别人的包混不进「基础系统」。
- `miyu pkg install basesystem`、`package.install {"package": "basesystem"}`：组里卸掉了的出厂包一起装回来。`remove` 照样，一次卸掉全组（pacman `-R` 组名同样）。编号和组名撞了的先认包（现在没有撞的，`groups.toml` 读的时候查）。
- 预设 `[software] basesystem = true` 照组展开成组里每个包；同时写了组里某个包的，照那个包自己的那一行。
- `package.list` 每一项多一格 `groups`，回应顶上多一格 `groups`（编号、名字、说明照连接的语言挑），头照它把组里的包收在一起。设置页「软件包」照组收起来，组上一个开关管全组；怎么画是两个头的事。

**3. 换**

- 不加规则：卸掉出厂的 `shell` 包，`shell` 这个名字空出来，别人的包（编号另起，比如 `fish-shell`）里的工具叫 `shell` 照平常装。出厂的 `shell` 还装着时，装别人的同名工具照现在的冲突规则拦（「冲突」，`packages.md`），说已在哪个包里。
- 跟着 `shell` 的照顾都归 `shell` 包自己，核心不按名字特判（项目主人 2026-10-26 定）：
  - 前台不许干等 `sleep`、`{shell}` 换成哪个 shell、`miyu call` 的通道，本来就在 `shell` 这件工具里，原样跟着包走。
  - 前台会话去掉 `run_in_background`：现在是会话那一层照名字 `shell` 去掉（`miyu-session` 的 `agents.rs`），改成工具自己声明哪个参数只在有后台时给（`Tool::background_parameter`），会话照声明去掉，不看名字。
  - `miyu call` 的那段用法接在哪件工具的说明后面：现在照名字接在 `shell` 后面（`agents/clicall.rs`），改成接在声明了「跑命令」的工具后面（`Tool::runs_commands`）。通道开给它跑的命令、管理员放行它时 `miyu check` 的提醒，也照这一条。
  - 两样是 `Tool` 的方法，内置工具直接实现。扩展经 `provide` 交的工具要用的话，以后在规格里加同名的两格，照它实现这两个方法；没写的就没有。
- 斜杠命令：内置的几条本来就只是包了一层的方法，`/clear`、`/stop`、`/workspace`、`/todo` 背后是内核的 `Clear`、`Interrupt`、`SetWorkspace`、`ClearTodos`，和协议上的方法是同一条路；斜杠的写法是给头、给群里打字用的。照背后那件归属：`/clear`、`/stop`、`/workspace` 是会话本身的操作，归核心（装包撞名时说「核心自带」）；`/todo` 清待办跟着 `todowrite` 包，没装的就没有这条。

**4. 会话里装卸包：`miyu pkg` 走通道**

- 命令行 `miyu pkg` 看见环境变量 `MIYU_CALL_SOCK`（这条命令跑在一个会话里），一律经 `miyu call` 的通道（设计 39 第五节），带这条命令的令牌，不读本机令牌、不连核心的协议；通道连不上的退出码 2，说这里用不了，不退回去走协议（同 MC11：退回去就是借本人的身份，绕过这个会话的权限）。
- 照子命令换成调 `packages` 包的两件：`install`、`remove`、`upgrade`（pacman 写法 `-U`、`-R`、`-S <编号>`、`-Su` 同）调 `package`，`list`、`info`、`search`（`-Q`、`-Qi`、`-Ss` 同）调 `packages`；`info` 写路径的看那个包文件夹（装之前检查）。施工 BS-1 中下更正：命令行没有 `enable`、`disable` 两个子命令，打开扩展照旧是人在包页里开。别的子命令（`files`、`owns`、`check`、`update`、`clean`）在会话里说用不了，退出码 2。
- 通道上新开一种请求 `op: "pkg"`，只能调 `packages` 包的两件。设计 39 第三节第 1 条访问类别那道硬规矩照旧拒 `install`，`op: "pkg"` 是唯一的例外；`miyu call package` 照旧拒。
- 权限照直接调用那条链（`tools/package.md`「问不问人」那张表）：完全放开直接做；工作区每次问人，前台、有人在场的主会话停下来等人确认（同施工 M-7 上），后台任务下面的、子会话里的、没人在场的不问、退出码 4；只读拒。场所会话照设计 39 第三节第 6 条一律调不了，群里装不了包。
- 问人的卡片照旧是看一眼的那一份（包含、需要、一并删除、大小）。`--yes` 在会话里不认：问不问由链判，她跳不过。
- 通道开不开：工具面上有能经 `miyu call` 调的工具，或者会话开着 `packages` 包，两样有一样就开。`clicall` 关着、`packages` 开着的会话，`miyu call` 照「一件都不能调」退出码 2，`miyu pkg` 照常。
- 她怎么知道有 `miyu pkg`：写在写包、写技能的说明里（内置包 `authoring`），用的时候自己看。`packages` 包开着时 system 不另加话；要加的话先实测证明不加不行，再照设计 26 第十节登记。

**5. 迁移**

还没发版，不做迁移（同设计 43 第三节）：家目录里写着 `[software] basesystem` 的预设照组展开，照样能用；写着 `[features] files` 这些的照「不认识的功能」报；`basesystem.show.system_hint` 照不认识的设置报；以前记的「卸掉 basesystem」当没有。

### 四、和别的规矩的关系

- **前缀稳定**：工具登记的先后不变，拆包以后工具面逐字节和现在一样，只少 `packages`、`package` 两件（一次计划内的冷启动）。`request_shape_probe` 比一遍，该变的只变这两件。
- **设计 30、31**：内置包「关就是卸、开就是装回来」照旧，出厂包都有了开关。必需的包这个说法没有了。
- **设计 39**：通道多一种请求 `op: "pkg"`；访问类别那道硬规矩只为它开一个口子。
- **威胁模型（设计 24）**：人批过在沙盒外跑的命令读得到本机令牌，能绕开通道直接以本人身份装包，这一条设计 39 MC10、MC11 时就记着，本设计不加新口子。

### 五、施工拆分

1. **ENV-1**（core-sub2，先做）：环境那七块挪进 `env` 包，「关于你」是其中一项。
2. **BS-1 上**：清单拆成十八份、组（`groups` 一格、`groups.toml`、`bad_group`、装卸组、预设展开）、各包各自登记、跟着走的行为照包判、出厂预设改写、删 `required`（清单一格、`package_required`、列表那一格）、起来时的 `WARN` 去掉。跟着 `shell` 的两处改成照规格的 `background_parameter`、`runs_commands`。`request_shape_probe` 证明工具面只少两件。
3. **BS-1 中**：`packages` 包的两件不上工具面；通道的 `op: "pkg"`；会话里的 `miyu pkg` 走通道、子命令换成调用、不认 `--yes`；`authoring` 里写上 `miyu pkg`（登记）。
4. **BS-1 下**：`package.list` 的 `groups`、斜杠命令的拥有者（`/clear`、`/stop`、`/workspace` 归核心，`/todo` 归 `todowrite`）、协议参考和蓝图跟着改；合完告诉两个头。

### 六、定的

1. 基础系统改成默认装、可卸、可换、可关（项目主人 2026-10-26 定）。
2. 一件工具一个包，`sessions` 和 `send_message`、`packages` 和 `package` 两对各合一个（项目主人 2026-10-26 定）。
3. 装卸包不给她工具，要用走 `miyu pkg`（项目主人 2026-10-26 提）；带会话身份复用 `miyu call` 的通道、照原来的权限表判（主会话研究后照推荐定，项目主人同一天让排期）。
4. 主会话照推荐定的技术题：组只认出厂那一层；不做迁移。
6. 跟着 `shell` 的照顾归 `shell` 包，核心不按名字特判；内置斜杠命令是方法的另一种写法，照背后那件归属（项目主人 2026-10-26 指出，主会话照此改）。
5. 清单的 `required` 删掉（项目主人 2026-10-26 定）：出厂带什么是以后打包时挑的事。
