## 联网搜索（`web_search`、`web_fetch`）

2026-10-18 项目主人定：内置包「联网」（`net`）补上设计 10 第 148 行列着的两件工具，不另开包。搜索来源多家、没配置时依次兜底，被限额的冷却；扩展能登记自己是一个搜索来源。

状态：2026-10-18 项目主人定了第一、三、四节的几条（下面「定了的」）；技术细节主会话照推荐定。第五节是施工拆分。

### 一、她这边

1. **两件工具**，名字照 Claude Code（`WebSearch`、`WebFetch`）改成小写，归「联网」包的两个功能「网络搜索」「抓取网页」，预设能关：

   ```text
   web_search {query, allowed_domains?, blocked_domains?}
   web_fetch  {url, page?}
   ```

2. **`web_search`**：交回几条结果，一条是标题、网址、发布日期（有的才写）、一段摘录。来源给得出长摘录的照给（够她不用再抓页面），给不出的照短摘要。`allowed_domains`、`blocked_domains` 只收结果在这几个域名里的、去掉这几个域名的：来源认 `site:` 的照写进查询，不认的照结果的网址筛。说明三句以内，结果里不写是哪一家来源（模型用不上）。
3. **`web_fetch`**：抓一个网址，**直接交正文**（项目主人定，不照 Claude Code 交给小模型摘要：多一次请求、多等几秒、小模型会漏细节）：HTML 换成 Markdown，纯文字、JSON 照原样；一页至多 30000 个字，太长的分页，交回的最后一行写「第 1/3 页」，下一页带 `page`。同一个会话里抓过的地址十分钟内翻页不重抓。别的种类（图、PDF、压缩包）说一句不支持。
4. **哪里都不问人**（项目主人定）：搜索和抓网页只读、不改东西，访问类别算 `read`，本机的工作区级别不弹确认、只读模式下也能用、群聊私聊里也能用。地址闸照旧：内网、本机、链路本地这些地址抓不了（`net.md`「地址闸」），跳转一跳一跳照查。
5. **她看到的来源字是不可信的**：网页、搜索结果是外面的字。先不加「这是不可信内容」那一类提示（`26-提示词.md`「给模型的字非必要不加」）：实测出了注入再加，加了登记。

### 二、搜索来源

1. **出厂认这几家**（2026-10-18 实测过，见「出处」）：

   | 来源 | 要 key | 接法 |
   |---|---|---|
   | Exa | 免 key 有额度；有 key 的走自己的额度 | MCP over HTTP，`https://mcp.exa.ai/mcp` |
   | Parallel | 免 key | MCP over HTTP，`https://search.parallel.ai/mcp` |
   | Firecrawl | 免 key（按 IP 限流） | MCP over HTTP，`https://mcp.firecrawl.dev/v2/mcp` |
   | AnySearch | 免 key（匿名额度） | REST，`https://api.anysearch.com/v1/search` |
   | You.com | 免 key（每天 100 次） | MCP over HTTP，`https://api.you.com/mcp?profile=free` |
   | DeepSeek | 要 key（模型那边配了 DeepSeek 的照用那把） | REST，`https://api.deepseek.com/v1/tools/search` |
   | SearXNG | 自己搭的，填地址 | REST，`<地址>/search?format=json` |
   | Tavily、Brave | 要 key | REST |
   | 网页抓取 | 免 key | 解析 DuckDuckGo、Bing 这类的搜索结果页，最后兜底 |

2. **没配置时的顺序**（项目主人定，照实测的质量排）：Exa → Parallel → Firecrawl → AnySearch → You.com → DeepSeek（有 key 才算）→ 网页抓取。一家出错（超时、5xx、读不懂）这一次换下一家；全都不成的照最后一家的原因报给她。
3. **配了来源的**：一直先用配的那一家，它用不了才走上一条的顺序（项目主人定）。
4. **限额冷却**（项目主人定）：一家报限额（HTTP 429、它自己说额度用完），冷却 30 分钟；冷却完再被限，1 小时、2 小时，最多 6 小时；冷却着的跳过；成功一次冷却清零；冷却到点自动回到排在前面的那一家。冷却记在核心的内存里，核心重启从头算。
5. **扩展登记自己是一个来源**（项目主人定开这个口子）：声明能力 `search`，经协议登记一个来源（名字、给人看的名字）；核心照下面第五节的方法调它。扩展的来源在设置的下拉里列出来，选了它才用，不进没配置时的顺序（别人的程序不会在人不知道的时候拿到搜索词）。

### 三、设置和界面

1. **设置页一个「搜索来源」下拉**（项目主人定）：`net.search.source`，默认「自动」（第二节第 2 条的顺序），列出厂的几家和扩展登记的；选项后面暗色写这一刻的状态（「冷却到 15:30」「要 key」），用 `config.schema` 已有的 `note`、`available`。要 key、要地址的几家，下面各一格（`net.search.<来源>.key` 是密钥引用，SearXNG 是 `net.search.searxng.url`）。
2. **时间线上写是哪一家**：搜索那一步的结果那一句写来源，例如「搜索 · rust tokio select（Exa）」：工具结果的 `human` 带上来源名，头照常画。
3. **默认会把搜索词发去国外的几家**：设置页这一项的说明里写明。

### 四、不做的

1. 不让小模型替她读网页（第一节第 3 条）。
2. 不算钱：DeepSeek 按次收费，单价会变、免费期怎么认不清楚，算不准的钱不显示。
3. 不缓存搜索结果：同一句隔几分钟再搜，结果本来就可能变。
4. 网页抓取这一家是兜底，不保证一直能用：页面改版、弹验证就跳过。

### 五、施工拆分（草案）

| 步 | 做什么 |
|---|---|
| N-1 | `web_fetch`：抓、地址闸、HTML 换成 Markdown（`htmd`，Apache-2.0）、分页、十分钟的翻页缓存；访问类别 `read`；说明、登记簿、预算 |
| N-2 | `web_search` 的骨架：来源的 trait、顺序和冷却、`net.search.source` 设置；先接免 key 的 Exa、Parallel、Firecrawl、You.com（MCP over HTTP 一份客户端）和 AnySearch。施工时拆成上、下：上是顺序、冷却、五家免 key 的和工具本身（2026-10-18 合了），下是 `net.search.source` 设置、配了的先用（下的前半，工具调用带上这一轮的配置），下拉里写冷却到几点（下的后半） |
| N-3 | 要 key 的几家（DeepSeek、Tavily、Brave、Exa 自己的 key、SearXNG），和最后兜底的网页抓取（照旧版的几家重新实测、挑还能用的） |
| N-4 | `web_fetch` 自己抓不下来的（挡爬虫、要跑脚本的页面），照来源里能抓页面的几家兜底（Exa、Parallel、Firecrawl） |
| N-5 | 扩展登记搜索来源：能力 `search`、登记和调用的两个方法、设置下拉里列出来 |

### 出处

- 2026-10-18 实测：六家免 key 的同一组六条查询，测具在会话的临时目录 `searchbench/bench.py`。Exa、Parallel 排第一档（准、摘录厚，Parallel 最快）；Firecrawl 准、覆盖广；AnySearch 准、摘要薄、背景查不到；You.com 偏弱、每天 100 次；FreeSerp 只收新注册的域名、结果是垃圾，不接；Tavily 免 key 回 401，只接要 key 的。
- opencode 的 `websearch` 也是照 Exa、Parallel 的 MCP 接的。

### 定了的（2026-10-18 项目主人）

1. 在内置包「联网」里做，不另开包。
2. `web_fetch` 直接交正文、分页，不交给小模型摘要。
3. 搜索、抓网页哪里都不问人，群聊私聊里也能用。
4. 设置里一个「搜索来源」下拉，时间线上写是哪一家。
5. 没配置时的顺序照实测的质量排，配了的优先、用不了再兜底；限额冷却 30 分钟、1 小时、2 小时、最多 6 小时，到点自动回退。
6. 开扩展登记搜索来源的口子。
7. 免 key 的网页抓取作兜底，实施时一起优化。
