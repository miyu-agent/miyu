## 命令行文案

`miyu` 印给人看的字，包括报错、提示、确认、结果行和帮助页，都照成熟的 Linux 程序的写法来，不写成对话。

状态：已定（2026-10-29 主会话起草，项目主人当天同意第六节四条推荐）。项目主人 10-29 在虚拟机里第一次以新用户身份敲 `miyu`，说这些提示、帮助页「太 AI 了，没有一个合格的标准的 Linux 程序的感觉」。

### 一、现在的毛病

拿 10-29 在虚拟机里碰到的那一句：

```
The tui interface is not installed (ui.head names it). Install its package, or switch with miyu config set ui.head <id>; no interface is installed yet, so talk to the AI with miyu ask "…" for now.
```

- **没有程序名**：一个只装了核心的人从脚本、管道里看到这句话，分不出是谁说的。`ls`、`git`、`pacman` 报错都以程序名打头。
- **一句话塞好几件事**：出了什么事、为什么、两种办法、现在只能怎样，全挤在一行。
- **解释内部**：`(ui.head names it)` 是给开发的人看的，用户不需要知道是哪个配置项指着它。
- **对话腔**：`for now`、`talk to the AI`、首字母大写加句号，读起来像聊天回复，不像程序的输出。
- **帮助页口语化**：「说一句话，打印 AI 的回答」「看 AI 记了你什么，搜、记、改、忘、清空」「管知识库：列、搜、读、建、加、删、挂目录」，动词堆成一串，又带着「你」。git、systemctl 的帮助页每条都是一个动宾短语。

### 二、照什么来

- **GNU Coding Standards「Formatting Error Messages」**：`程序名: 消息`，消息不以大写字母开头、不带句号；跟文件、行有关的写 `文件:行: 消息`。coreutils、grep、tar 都这样。
- **git 的 `hint:`**：建议另起一行，以 `hint:` 打头，只写照着能敲的命令。中文翻译用「提示：」。
- **pacman、systemctl 的确认和结果**：确认是 `动作？[Y/n]`；结果行短、动词打头、只写做成了什么。
- **中文照 GNU 程序的中文翻译**（Translation Project 的 zh_CN）：程序名前缀照旧是半角 `miyu: `，正文用书面语，例如 `ls: 无法访问 'x': 没有那个文件或目录`。

### 三、规矩

1. **报错**写到标准错误：`miyu: <出了什么事>`。
   - 英文小写开头，中英文都不带句号。
   - 一行只说一件事。必须带的原因跟在冒号后面，例如 `miyu: cannot install foo: package.toml:29: unknown key 'process.system_account'`。
   - 不写「你」，不用对话腔，不说推测。
2. **警告**：`miyu: warning: <消息>`，中文写 `miyu: 警告：<消息>`。照样做，只是提醒。
3. **建议**另起一行：`hint: <能照着敲的命令或一句操作>`，中文写 `提示：…`。可以有几行，一行一个办法。命令用单引号括起来，例如 `'miyu setup'`。
4. **不解释内部**：配置键、模块名、内部编号只在用户要靠它改的时候出现，而且出现在 `hint:` 的命令里，不出现在报错句子里。
5. **结果行**（标准输出，或者标准错误上的进度）：动词打头、过去式或完成态，短，例如 `installed tui 0.8.0`、`已安装 tui 0.8.0`。不写装饰的「·」，不写「成功了！」。
6. **确认**：`<动作> '<对象>'? [Y/n] `，中文写 `<动作> '<对象>'？[Y/n] `。默认的那个大写。
7. **帮助页**：
   - 第一行 `Usage: miyu <COMMAND> [OPTIONS]`，中文 `用法：miyu <命令> [选项]`。
   - 每条说明是一个动宾短语：英文动词打头、首字母大写、不带句号；中文书面语、不带句号。
   - 子命令下面有哪些动作，留给 `miyu <子命令> --help` 去列，总表里只写「管理知识库」，不列「列、搜、读、建」。
   - 别名写在括号里：`undo  Undo the last turn (alias: rewind)`。
8. **用语**：同一个东西全程同一个词，见下表。不用「她」，能不提「AI」就不提，例如「发送消息并打印回复」，不说「打印 AI 的回答」。

| 东西 | 英文 | 中文 |
|---|---|---|
| 会话 | session | 会话 |
| 一轮 | turn | 一轮 |
| 核心进程 | core | 核心 |
| 软件包 | package | 软件包 |
| 界面（终端、网页） | user interface / interface | 界面 |
| 供应商 | provider | 供应商 |
| 模型 | model | 模型 |
| 回复 | reply | 回复 |

9. **退出码**不变，照 `22-命令行.md` 第二节。
10. **检查**：做完以后加一道测试，扫命令行全部给人看的字，挡下以句号结尾的报错、没有程序名前缀的报错、帮助页说明里的「、」串、「她」「你」这些字。

### 五、范围和做法

- **改**：`miyu` 这个程序（`crates/miyu-cli`、`crates/miyu`）印的全部字，连同帮助页、它们的样本和测试。
- **不在这一份里**：
  - 终端界面、网页的界面字，照 `docs/reviews/2026-10-10-界面字照通用软件说法.md`；
  - 给模型看的字，照设计 26；
  - 核心拒绝时的那句话（`仅主人可用。` 这一类）。这句话头和命令行都会印，命令行只给它加上 `miyu: ` 前缀、去掉句号，正文另开一步对齐。
- **分步**：
  - CL-1：这一份定稿；
  - CL-2：照模块逐个改，每改一个模块，样本跟着重出；
  - CL-3：第三节第 10 条的检查进门禁。
- 改之后例子里的 `miyu pkg install tui`，要等打包把终端放进软件源或整合包以后才真跑得通，见打包的设计。

### 六、要拍板的

1. 中文报错的程序名前缀用半角 `miyu: `，和 GNU 程序的中文翻译一致。推荐半角。另一种是全角 `miyu：`。
2. 报错分级照 GNU：只有程序名前缀，警告加 `warning:`。推荐 GNU。另一种是照 git，分 `error:`、`warning:`、`fatal:`。
3. 帮助页的总表不列子命令下面的动作，留给子命令自己的帮助页。推荐不列。
4. 文案里不再用「她」，也尽量不提「AI」，回答一律叫「回复」。推荐这样做。
