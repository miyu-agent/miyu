## 定时和循环

到点叫她跑一轮，照 Claude Code 的两样做：定时任务（`cron_create` 一类、`miyu schedule`）和循环（`/loop`、`schedule_wakeup`）。核心里只有一样东西：到点把一句话交给一个会话跑一轮的「唤醒」，记在一张表里，核心重启不丢。定时任务、固定间隔的循环、她自己定节奏的循环、通讯平台「隔一阵看一眼群」都是它。

状态：已定（2026-10-26）；J-1 上做完（唤醒表、到点、交进会话，图纸 `docs/blueprint/schedules.md`）。原来排期里写「地基完了再排」（J 线定时、AI 智能 loop 要讨论），项目主人同一天提前：onebot 的「隔一阵看一眼群」等着它。定了的见第六节。

### 一、现在缺什么

- 核心一直开着（施工 Z-1 上），可没有一样东西能到点叫她。onebot 群聊的主动回复还靠「抽样」（不冲她来的消息 5% 抽中问判官），项目主人 2026-10-23 定换成「隔一阵看一眼群」，要等核心先有循环。
- 人没法让她「每天早上 8 点给我早报」「每小时看一眼服务器」；她也没法说「过 10 分钟我再看看 CI」。

### 二、别家

- **Claude Code**：
  - `CronCreate {cron, prompt, recurring}`、`CronDelete`、`CronList`：会话里建，到点在这个会话里把 `prompt` 当一条话发进去；会话关了就没了，循环的 7 天后自己过期。
  - `/loop [间隔] <话>`：写了间隔的照 cron 建循环的定时；没写的是「动态」，先跑一次，她每轮结束调 `ScheduleWakeup {delaySeconds, prompt, reason}` 自己定下一次，`stop: true` 结束，范围 60～3600 秒。
  - `/schedule`：云上的独立任务，每次新开一个会话跑。
- **cron / systemd timer**：错过的时点照「错过就跳过」或者「补一次」（`Persistent=`）。

取的：两种都有（会话里的、独立的）；循环分固定间隔和她自己定；她定的间隔有上下限。
不取的：会话关了定时就没（我们的核心常驻，会话随时能接着跑）。

### 三、样子

**1. 唤醒表**

- 全机一张，放在 `state/schedules.db`（SQLite，照用量账本的写法开库）。一行一个任务：编号、谁建的（人、哪个会话里的她、哪个包）、什么时候（cron 写法；某个时刻一次；过多少秒一次）、说什么（`prompt`）、跑在哪（第 2 条）、下一次的时刻、上一次的时刻和结果、是不是循环。
- 核心起来时读一遍，算出下一个到点的，睡到那一刻（不轮询）；表一改就重算。
- 错过的不补（同旧版定时消息的规矩）：核心停着时过了的时点跳过，照现在算下一次，记一行日志。
- 时区照这台机器的；cron 照标准五段写法。

**2. 跑在哪**（项目主人 2026-10-26 照推荐定，同 Claude Code）

- **这个会话**：她在会话里建的默认这样，到点把 `prompt` 当一条话交进这个会话；会话正在跑一轮的，排在这一轮后面。
- **指定的会话**：人建的时候可以指一个已有会话，群的会话也行（「每天晚上在群里说晚安」）。
- **每次新开**：照建时选的人格、预设、工作目录开一个新会话跑一轮，跑完给人发一条系统通知，点开就是那次的会话。人建的不指会话时默认这样。
- 交进会话的那条话不算人说的：记成 `by: schedule`（带任务编号），头画成一行「定时」标记；回合照常，权限照这个会话的。

**3. 谁能建**（项目主人 2026-10-26 定：人和她都能，她建不用问人）

- 人：命令行 `miyu schedule add|list|rm|pause|resume`，协议 `schedule.*`，头的界面以后照它画。
- 她：三件工具，照 Claude Code：`cron_create {cron, prompt, recurring}`（建在这个会话上）、`cron_delete {id}`、`cron_list`。访问类别 `read`（不改文件、不问人）。一个会话里她最多同时挂 20 个，超了报错叫她先删。
- 包：扩展经协议建，只能建在它自己的场所会话上（第 5 条）。

**4. 循环**

- `/loop [间隔] <话>`：斜杠命令（核心的，背后是 `schedule.*`）。
  - 写了间隔（`5m`、`2h`、`every 20m`）的：建一个这个会话上的循环定时，马上先跑一次。
  - 没写的：动态。马上跑一次，这个会话的工具面上她有 `schedule_wakeup {delay_seconds, prompt, reason}`，每轮结束自己定下一次；`stop: true` 结束。下限 60 秒、上限 3600 秒，超了照边界；她不调就不再醒（循环就停了）。
- `/loop off`：停掉这个会话里的循环（动态的和固定间隔的）。人在头上看得到这个会话挂着循环、下一次几点。
- 动态循环醒来交进去的话前面带一个标记，让她知道这是循环在叫她，不是人说的（照 Claude Code 的做法，字照设计 26 登记）。

**5. 通讯平台的「看一眼群」**

- 扩展（onebot）经协议给自己的场所会话开一个动态循环：`schedule.loop {session, prompt}`，她在群里那个会话照样有 `schedule_wakeup`，自己决定隔多久再看一眼；扩展能随时 `schedule.cancel`。
- 看一眼时交进去的是那一段新消息，怎么拼、给不给判官，是 onebot 的事；核心只管按时叫。
- 睡眠时段、限流照 onebot 自己的规矩，它可以在醒来那一刻自己决定跳过。

**6. 包和开关**

- 拆包（设计 44）以后是两个内置包：`schedule`（`cron_create`、`cron_delete`、`cron_list`、`miyu schedule`）、`loop`（`schedule_wakeup`、`/loop`），都在「基础系统」组里，默认装、能关能卸。关了的：她的工具面上没有，表里人建的照旧跑，她建在关了的会话上的到点不跑、记一行。

### 四、和别的规矩的关系

- **前缀稳定**：四件工具是常量，进工具面是一次计划内的冷启动；`schedule_wakeup` 只在开着动态循环的会话里给，换它要掰前缀，所以它跟着 `loop` 包常驻在面上，没开循环的会话里她调了说「没有在跑的循环」。
- **常驻（设计 12）**：建了定时任务、开了循环的，核心本来就一直开着；装了服务的开机就起。
- **给模型的字（设计 26）**：四件工具的说明、循环那一行标记都要登记、量 token，照工具规范写短。
- **权限**：定时、循环交进去的话照这个会话的权限级别跑，和人说的一样；没人在场的会话里要问人的照规矩拒。

### 五、施工拆分

1. **J-1 唤醒表和到点**：`schedules.db`、算下一次、睡到那一刻、错过跳过、交进会话（`by: schedule`）、三种跑在哪；协议 `schedule.add|list|cancel|pause|resume`、事件；端到端测试用假的钟。
2. **J-2 她的工具和 `/loop`**：`cron_create`、`cron_delete`、`cron_list`、`schedule_wakeup`；`/loop` 两种写法和 `/loop off`；登记、量 token。
3. **J-3 命令行和通知**：`miyu schedule …`；每次新开的跑完发系统通知；协议参考、蓝图；告诉两个头画界面。
4. **J-4 场所会话的循环**：`schedule.loop` 给扩展用；onebot 接上「看一眼群」（onebot 那边先拿旧群数据量间隔和成本，出它自己的设计稿）。2026-10-27 改定：核心不另开 `schedule.loop`，`schedule.*` 开放给批过 `sessions.drive` 的扩展，`target` 多一种 `{"package": {}}`（到点推 `schedule.fired` 给它自己）；看群的循环由场所拿这两样拼（项目主人定，施工 J-4）。

### 六、定的

1. 循环照 Claude Code：固定间隔和她自己定节奏两种（项目主人 2026-10-26）。
2. 定时任务人和她都能建，她建不用问人（项目主人 2026-10-26）。
3. 跑在哪照 Claude Code，两种都有：会话里建的跑在这个会话，人建的能指会话、能每次新开（项目主人 2026-10-26 照推荐定）。
4. 主会话照推荐定的技术题：一张表、一种唤醒；错过不补；她一个会话最多 20 个；动态循环 60～3600 秒；交进去的话记 `by: schedule`；`schedule_wakeup` 常驻在 `loop` 包的工具面上。
