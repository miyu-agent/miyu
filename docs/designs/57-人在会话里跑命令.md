## 人在会话里跑命令

人在头的输入框里用 `!` 打一条命令，核心照会话的工作目录跑，命令和输出作为人说的一句话进会话，她接着回。照 Claude Code 的 `!`（bash 模式），差别是她当场回一轮。终端先做，网页以后用同一个方法。

状态：已定（2026-11-03 项目主人定三件：核心照会话目录跑、人打的命令不做任何安全判定、跑完她当场回；排队照普通消息。同一天主会话当面确认「不确认、不进沙盒、所有头都能用」）。形状主会话照推荐定。施工 SH-1（上、下两步，见第五节）。

### 一、她和人看到的

1. 人在终端打 `!git status`，回车：会话里出现一句人说的话，是这条命令，下面是它的输出、退出码；她接着回一轮。
2. 她正在答的时候打：和普通消息一样排队，排着的照普通消息在两步之间交给她（`urgent` 照头发普通消息时怎么带就怎么带）；Ctrl+Enter 照 `session.interrupt {queued: "send"}` 打断、当场跑。
3. 排着还没跑的可以退回（`session.withdraw`、`session.interrupt {queued: "return"}`），退回的不跑。

### 二、方法

`session.send` 加一个参数 `shell`（布尔，默认假）。写了的：`text` 是要跑的命令行，原样跑。

1. **不判权限、不进沙盒**：人亲手打的就是许可。照会话的工作目录、用核心起 `shell` 工具时的那个 shell 和同一套挑过的环境变量（`docs/blueprint/tools/shell.md`「环境变量」）跑，不经沙盒助手、不看权限级别、不弹确认。
2. **只收人**：带 `from` 的（别的 agent 程序）、扩展替人说的、场所会话，一律拒（`shell_not_allowed`）。头登录了就能用：终端、本机网页、局域网里输了访问密码的网页都一样（2026-11-03 项目主人当面定）。
3. **不能带附件**：`shell` 和 `attachments` 一起写的 `bad_params`。空命令 `empty_message`。
4. 其余参数（`urgent`、`prefix`、`cwd`）照 `session.send`：`cwd` 先换目录再排队，跑的时候照跑那一刻会话的工作目录。

### 三、怎么走

1. **收到**：和普通消息一样当场记一条 `message.user`（多一格 `shell: true`，`text` 是命令行），落了盘就回，不等跑完。
2. **什么时候跑**：在她「听到」它的那一刻跑，不是收到时跑。会话闲着，收到就开一轮，这一轮第一件事是跑它；正忙，排着，到它被交给她的那一步（两步之间，或者这一轮结束后由它开下一轮）先跑、再发请求。这样排着的退回了不会已经跑过，几条排着的照先后跑，和人的预期一致。
3. **跑完**：记一条 `shell.ran`（第四节），落了盘再投影发请求。她看到的是「人跑了这条命令，输出是这些」，然后照常回。
4. **超时**：照 `shell` 工具前台的默认 120 秒，到时整组杀、记下到这时的输出，`reason: timed_out`。不开参数调（人要跑长的自己放 `&` 或者开终端）。
5. **打断**：跑着时 `session.interrupt` 整组杀掉这条命令，记 `shell.ran`（`reason: interrupted`，带到这时的输出），这一轮照打断停下、她不回；`queued` 的照原样处理。
6. **输出**：标准输出、标准错误合在一根管道，`\r\n` 换 `\n`；给她和给人的是同一份，截法照 `shell` 工具前台的（头尾两段、中间说省了多少字，`shell/output.rs`）。不另存整份。
7. **撤销**：撤掉这一轮，这句话和 `shell.ran` 照人说的话一起撤；命令已经做的改动不在撤销范围里（同后台命令，`10-自带软件.md` 第七节）。她看过的文件被命令改了的，照「外面改的」算，改之前要重读。
8. **核心重启**：跑到一半的命令照前台命令处理（生命线杀掉），载入时补一条 `shell.ran`（`reason: aborted`），不重跑。

### 四、事件和视图

1. `message.user` 多一格 `shell: true`，没有的不写，老事件一个字节不变。
2. 新事件 `shell.ran`：`{"message": 42, "exit": 0, "duration_ms": 130, "text": "...", "omitted": 0}`，异常结束的多 `reason`（`timed_out`、`interrupted`、`aborted`），被信号杀的写 `signal` 不写 `exit`。`message` 是那条 `message.user` 的序号。
3. 给她看的：那句人话和它的 `shell.ran` 渲染在一起，外壳带 XML 标签，原文进登记簿、量 token（`26-提示词.md`）。不是指令，只陈述「人跑了什么、输出什么」。
4. 视图流：那条 `user` 多 `shell: true`；输出挂在它下面一格 `shell`（`exit`、`signal`、`text`、`omitted`、`reason`、`duration_ms`），还没跑完时是 `shell: {"running": true}`。排着的照普通消息的 `queued: true`，退回的 `withdrawn: true`。

### 五、施工

1. **SH-1 上**（核心）：`session.send` 的 `shell`、拒的几种；跑的时机（开轮第一件、两步之间先跑）；超时、打断、重启补 `aborted`；`shell.ran` 和样本、投影渲染、登记簿。测试：闲着当场跑、她回一轮；忙着排队、到步之间先跑；退回的不跑；打断杀掉、她不回；超时；`from`、场所会话、扩展拒；三个平台。
2. **SH-1 下**（协议、视图流）：参考文档两份、`methods-v1.txt` 不变（还是 `session.send`），视图流的 `shell` 格；合完告诉终端、网页。
