## 项目

状态：已定（2026-10-19 主会话）。界面那一半项目主人同一天看过四版样品定了，写在网页仓库 `docs/blueprint/web.md`「会话整理和项目」（第 12 条是给核心的）；终端照同一套画。这一份是核心这一半：项目这一样东西怎么存、协议怎么改、附加提示词放哪、留言的范围。技术形状是主会话照推荐定的。

「项目」在这里是会话的一个分组，像 ChatGPT、Claude 网页的 Projects。和设计 14 里的**项目配置**（代码仓库里的 `.miyu/config.toml`，回应里的 `untrusted_project`）不是一回事：那个跟着工作目录走，这个跟着会话走。下文说「项目」都是这一个，说那个一律写全「项目配置」。

### 一、项目是什么

一组设置，几个会话归进去。

| 格 | 说明 |
|---|---|
| `project` | 编号，UUIDv7，核心起 |
| `name` | 名称，必写，1 到 40 个字 |
| `description` | 说明，最多 80 个字，可以空 |
| `color` | 颜色，`#rrggbb`；不写是空的，头照自己的默认色画 |
| `workspace` | 在项目里新建会话的工作目录，人看到的写法（`~/src/miyu`）；空的是默认工作区 |
| `persona` | 新建会话的人格编号；`null` 是无人格；不写是照配置 `persona.default` |
| `preset` | 新建会话的预设编号；不写是照 `preset.default` |
| `prompt` | 附加提示词：项目里的会话每一轮都带（第四节），最多 8000 个字，可以空 |
| `open` | 布尔，默认 `false`：能和项目外的会话互相留言（第五节） |
| `created` | 造的时刻 |

1. **存在哪**：数据根的 `projects.json`，只有一份，核心整份重写（同 `logins.json`：先写临时文件再换名，Unix 上 0600，照读到的版本写，中间被人改了的不写）。人的数据，跟着数据根备份；不是给人手改的，读不成的整份当坏了、方法回 `internal_error`，不替人改。
2. **哪个会话在哪个项目**：记在会话自己的日志里，`session.meta_changed` 多一格 `project`（第二节），和标题、置顶同一个事件。会话表照它算，不在 `projects.json` 里另记一份名单：一份事实只记一处。
3. **只有本机的主会话能进项目**：场所会话（通讯平台）、子代理、分叉出来的不能（拒 `bad_params`）。子代理跟着派它的会话。

### 二、协议

| 方法 | 参数 | 回应 |
|---|---|---|
| `project.list` | 无 | `{"projects": [<一项>…]}`，照造的先后 |
| `project.create` | 第一节的格，`name` 必写 | `{"project": <编号>}` |
| `project.update` | `project`，加要改的格；`unset`：要清掉的格名的数组（第 3 条） | `{}` |
| `project.delete` | `project` | `{"moved": <挪出来的会话个数>}` |

1. **订阅**：`subscribe {stream: "projects"}` 先给整张表，之后每变一项推 `projects.changed {"project": <一项>}`，删了推 `{"project": <编号>, "deleted": true}`。和 `sessions` 流同一套：掉队的重新订阅。
2. **会话这边**：
   - `session.create` 多 `project`：没有这个项目拒 `unknown_project`。没写 `persona`、`preset` 的照项目的，项目也没写的照配置。`cwd` 照旧必写：头照项目的 `workspace` 填、带 `chosen`（项目里的目录是人选过的）。
   - `session.set_meta` 多 `project`：编号是移进去，`null` 是移出来。置顶照旧是另一格：界面拖进项目时同时发 `pinned: false`（界面第 5 条），核心不替头改置顶；置顶的项目会话照旧置顶。
   - `session.list` 的一项、`sessions` 流的一项多 `project`（没有的不写）。
   - `session.meta_changed` 多一格 `project`：项目编号，空字符串是移出来（同标题写空的是去掉，施工 H-2 定；协议的 `session.set_meta` 照旧写 `null`）。
3. **清掉一格**：写了值的格换成新值；`unset` 里列的格清掉，回到「没写」（`persona`、`preset` 回到照配置的默认，`workspace` 回到默认工作区）。`persona` 写 `null` 是无人格，和 `session.create` 一样；`name` 不能清。一样格既写了值又列在 `unset` 里的拒 `bad_params`。
4. **删项目**：核心给里面每个会话写一条 `session.meta_changed {"project": ""}`（`by` 是人），再从 `projects.json` 拿掉。会话不删（界面第 8 条）。
5. **出错**：`unknown_project`；`bad_params`（名称空的、太长，颜色不是 `#rrggbb`，`prompt` 超过 8000 个字，场所会话、子代理设 `project`）；人格、预设不存在照 `unknown_persona`、`unknown_preset`（造项目时就查，免得建会话时才发现）。
6. **谁能调**：只给人，扩展不能（同 `package.*`）。

### 三、新会话照项目的默认

只在造的那一刻用：人格、预设照项目（第二节第 2 条），以后改项目的默认不碰已经造好的会话；会话挪进挪出项目也不改它的人格、预设、工作目录。照 ChatGPT：项目只管「新会话从哪开始」和「项目里的会话都知道的那几句话」。

### 四、附加提示词

1. **放哪**：system 里「关于你」后面（`26-提示词.md` 第四节第 2 块的尾巴），一块：

   ```text
   <project_instructions>
   {prompt}
   </project_instructions>
   ```

   原文照放、不转义（同人设、关于你：本人写的）。空的不带。
2. **跟着项目走**：每一轮开始前照这个会话现在在哪个项目、那个项目现在的 `prompt` 算这一块；和上一轮不一样就换上，整段 system 重算一次（同扩展的 `system.append`，`26-提示词.md` 第四节第 8 块）。会话挪进挪出、项目改了提示词，下一轮生效，前缀断一次——人改了才断，照「前缀稳定第一」的口径可以接受。
3. **谁带**：项目里的主会话。子代理不带（同「关于你」：子代理照派它时交的话干活，system 是它自己的那一份）。
4. **登记**：外壳的两个标签是给模型看的字，量 token、照第十节登记；值是人写的，不进登记簿（同人设）。

### 五、留言的范围

改 `cross-session.md` 第九节第 4 条「能看到的」：再照项目筛：

1. 都不在项目里的：互相看得到（现在的样子）。
2. 在同一个项目里的：互相看得到。
3. 一边在项目 A 里、另一边不在或者在 B 里：A 开了 `open` 的，A 的会话和对方互相看得到（对方在 B 里的，还要 B 也开了 `open`）；没开的看不到。
4. 看不到的列不出来、读不了（`history`）、发不到（`send_message`）、订不了空下来的通知，照「没有这个会话」答（`no-session.txt`），不另说「在别的项目里」：她不需要知道墙在哪。
5. 人不受限：人经头往哪个会话说话都行。
6. 子代理照旧只和派它的会话说话（第九节第 2 条），不受项目影响。

### 六、施工拆分

| 步 | 做什么 |
|---|---|
| H-1 | 项目这一样东西：`projects.json`、`project.*` 四个方法、`projects` 流 |
| H-2 | 会话在项目里：`session.create`、`session.set_meta` 的 `project`，会话表、流、事件多一格，删项目挪出来，新会话照项目的默认 |
| H-3 | 附加提示词（量 token、登记）和留言的范围 |

每一步合了把形状发给两个头（网页、终端）。H-1、H-2 合了头就能画左栏、拖动、项目页；H-3 是她那一侧，界面不用等。
