## 认识的人

她记得自己认识的人：他是谁、怎么认识的、喜欢什么、最近怎么样、生日、联系方式。那个人一开口，不管在哪个群、私聊里，她就认出他，想起他的事，像人见到熟人一样。

状态：PN1 到 PN5 已定（2026-10-21 记忆的会话写；PN1 到 PN3 主会话对过，PN4、PN5 项目主人定）。项目主人 2026-10-21 提（「记忆里能有一个新分类吗？就是关于认识人的……这样是不是很拟人？」），看了推荐说「推进吧」。施工照第五节，排在 R-29（记忆是一个整体）以后；编号是 E 线（认识的人）：E-1 上、下、补，主会话在内核那一头做的说话人那一格叫 E-0（原来草稿写的 P-1 和人格、预设那条线撞了，2026-10-21 主会话改成 E 线）。挂接点要拿到这一轮说话的人：主会话在内核那一头给回合开始的挂接点加 `speakers`（E-0）（这一轮触发它的人话里平台身份，照先后去重，最近开口的在后），E-1 补开工以前交。

### 一、现在缺什么

- 四类记忆（`user` 关于主人、`feedback` 主人给的反馈、`episode` 发生过的事、`reference` 参考资料）都是一句一条，关于别人的事散在里面。她要知道「GNU/Rust++ 是谁」，得自己想起去搜，搜到的也是零散几句。
- 常驻的摘要只有一段，写的是主人：别人在里面最多一两句。
- 记下的不知道说的是谁：抽取时标了说话的人（`Owner`、群名片、平台编号，R-13 上），记下来只剩正文。
- R-29 以后记忆在哪儿都想得起（2026-10-21 项目主人定：记忆是一个整体，不按场所、按人隔开），正好：在哪儿认识的都是同一个人。

### 二、别家

- 旧版 Miyu：每个平台上的人一条好感度（「Miyu 对 principal:… 的当前好感度为中立」），别的照普通记忆。
- SillyTavern 的 World Info / 角色卡：一个人物一张卡，提到名字（关键词）时带上。知识库的关键词触发（K-9）就是照它做的。
- Letta（MemGPT）：`human` 记忆块写正在说话的这个人，一个 agent 一块；多个人要自己另开。
- ChatGPT、Claude 的记忆：只记用户本人，不记别人。

取的是：一个人一张卡（SillyTavern），这个人开口时自动带上（Letta 的 `human` 块，照说话的人换），卡由整理时合（同摘要）。

### 三、样子

1. **一类新的记忆 `person`**（界面上叫「认识的人」）：一条记一件关于某个人的事，「他用 RX 7800 XT」「下周六搬去大阪」「是在 Rust 群认识的」。记下时带上**是谁**（`who`）：平台上的人是平台编号（`qq:10086`，同一个号跨群、私聊都是他），没有平台号的（主人在终端里说起朋友）写名字。主人自己的照旧记 `user`，不进这一类。
2. **一个人一张卡**：整理记忆（dream，第七条）时，同一个人的 `person` 条目合成一张卡，写他是谁、怎么认识的、喜好、近况、生日、联系方式，过时的近况换掉；卡里另记他的几个叫法（群名片、外号）。卡是记忆日志里的一条事件（同摘要 `ext.memory.summary`），照旧落盘、可改。
3. **他一开口就认出来**：和她说话的那个人（触发这一轮的最后开口的那个）的平台编号对得上一张卡，就把这张卡带上，放在常驻摘要后面、这一轮的话前面（同联想，不改以前的前缀，缓存不断）。一轮只带这一张，一段上下文里一个人只带一次（PN4）。没有卡的人不带。
4. **她也能主动想起**：她的 `memory_search` 搜得到卡（名字、外号、平台号都算关键词）；她当场记一个人的事用 `remember`，类写 `person`、带上 `who`。
5. **人能看、能改**：协议 `memory.list` 照类列得出卡；网页记忆页多一栏「认识的人」，一人一张；命令行 `miyu memory list --class person`。

### 四、和别的规矩的关系

- 记忆是一个整体（R-29）：卡在哪儿都带，不管是在哪个群认识的。
- 抽取（第六条）：说话的人原来只在拼给模型的那一段里标着，现在抽出来的 `person` 条目照说话人的标记写 `who`（模型交回名字，抽取照这一段的标记换成平台编号）。
- 整理（第七条）：合并照旧整批交回；多交回一样「人卡」，核对照旧（只改这一批里出现过的人的卡）。整理改成会话以后（设计 41）同一个会话里做。
- 常驻摘要照旧只写一段、写主人；人卡另算，不进摘要。

### 五、施工拆分（草案）

0. **E-0：说话的人**（主会话做）。回合开始的挂接点多 `speakers`：这一轮触发它的人话里平台身份，照先后去重，最近开口的在后；E-1 补开工以前交。
1. **E-1 上：类和 `who`**。`person` 这一类、`Saved` 多 `who`；她的 `remember` 收 `who`；抽取照说话人写；协议、命令行列得出、搜得到。
2. **E-1 下：人卡**。整理时合卡、记成事件；改、作废照旧；网页、终端画卡（头的会话）。
3. **E-1 补：认出来**。一轮开始时照说话的人带卡（挂接点同联想），上限、一段只带一次；量 token、缓存。

### 六、决定

**PN1. 新开一类 `person`，主人不进这一类**

- **已定（2026-10-21 主会话对过）：同上第三节第 1 条。** 主人的事照旧 `user`，常驻摘要照旧写主人。
- 未选：不开新类，照旧 `user`/`episode`、只多一格 `who`。人卡要从四类里挑，`user` 原来说的是主人，混进别人会让摘要、联想都乱。
- 重开条件：无。

**PN2. 照平台编号认人，名字只当叫法**

- **已定（2026-10-21 主会话对过）：`who` 是平台编号（`qq:10086`）；群名片、外号记在卡里当叫法，搜得到、不拿来认人。没有平台号的（主人在终端里说起的朋友）写名字，以后这个人上了 QQ、主人说一声「他就是 xxx」再并成一张。**
- 为什么：群名片每个群不一样、谁都能改；平台编号由桥担保、跨群不变。
- 未选：照名字认。同名的、改了名片的都会认错，把别人的事当成他的。
- 重开条件：接了别的平台，同一个人在两个平台上要并成一个。

**PN3. 卡由整理时合，不是每记一条就改**

- **已定（2026-10-21 主会话对过）：同上第三节第 2 条，和摘要一个做法。** 两次整理之间新记的 `person` 条目照旧零散地搜得到，卡下一次整理时更新。
- 未选：每记一条就让模型重写一次卡。每条多一次模型调用。
- 重开条件：整理隔得太久、卡总是旧的。

**PN4. 只带正在和她说话的那一个人的卡**

- **已定（2026-10-21 项目主人）：一轮只带一张卡，触发这一轮、和她说话的那个人的；一张最多 300 个字。** 项目主人：「我们要思考带这个的意义是什么。是让它知道对面是谁从而知道怎么合理地调整自己的说话方式，或者说话内容，又或者工作倾向。所以，我倾向于带一张，和他对话的那个人的就够了。」
- 「和她说话的那个人」：这一轮触发它的那几条人话里最后开口的那个（群里 @ 她、回她的、私聊里的对方）；换了人说话的，下一轮带新的那个人的卡。一段上下文里一个人只带一次，压缩以后重新算。主人没有卡（他的事在常驻摘要里）。话里提到的别人不自动带，她要知道的自己搜。
- 一张 300 字：卡是让她知道对面是谁、怎么相处，不是全部档案；细的事零散的条目里搜得到。
- 未选：一轮最多带 3 张（说话的人里最近开口的几个，记忆的会话原来的推荐）。群里轮流说话时每轮多几张，多出来的几张和这一轮她要回的那个人无关。
- 重开条件：实测里她常常认不出群里同时在聊的另一个人，要搜才知道。

**PN5. 联系方式、生日照记**

- **已定（项目主人 2026-10-21：手机号、QQ 号、生日都在他举的例子里；记忆是一个整体，不加分寸规矩）：照记，照常带。** 遮 key 照旧（抽取、整理遮掉配置里的 key 和常见的 key 写法），手机号不算 key。
