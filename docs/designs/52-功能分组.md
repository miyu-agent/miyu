## 功能分组

预设页、引导页里功能怎么分组、排先后，由核心算好一棵树交给头，终端、网页照同一棵树画。

状态：已定（2026-10-30 项目主人看过样板第三版拍板方案 B，接入通讯平台的会话转来；样板在 im 会话的 scratchpad `feature-groups.html`，GROUPS 就是定下来的清单）。起因：终端拿包编号当小标题、只给多功能包出标题，网页只按编号前缀分「功能 / MCP / 脚本 / 技能」，两头各写一套；QQ 工具一个功能挂了二十件工具，可读性很差。

### 一、分组

出厂的组（`resources/packages/groups.toml`，照这个先后）：

| 组 | 编号 | 有哪些功能 |
|---|---|---|
| 基础系统 | `basesystem` | 读文件、新建文件、编辑文件、找文件、搜内容、删到回收站、运行命令、后台运行、命令行调用工具、子代理、提问、展示给用户、跨会话消息、翻查本会话、用量查询、软件包 |
| 任务和定时 | `tasks` | 待办清单、长期目标、定时任务、循环任务 |
| 注入环境信息 | `environment` | 环境的八块，加上自动注入 AGENTS 文档（组名和 `miyu-base-env` 的包名一致，项目主人同一天补定） |
| 人格 | `persona` | 人格记忆、人设遵循提醒 |
| 查资料 | `research` | 网络搜索、抓取网页、知识库 |

1. 哪个包进哪个组照出厂清单 `[package] groups` 写（设计 44），组表只给名字和先后。待办、定时、循环从 `basesystem` 挪进 `tasks`：预设里写 `basesystem = true` 不再连带它们（项目主人知道）；出厂的常规开发预设另写 `tasks = true`，开的功能和改前一样。
2. 组名也是预设 `[software]` 里能写的词，定了就不轻易改。
3. 出厂组后面：带几个功能的扩展包各自一组（组名是包名，照包编号排）；只带一个功能的扩展（清单没写功能、整包算一个的也算）合进一个「扩展」组，一个扩展一行（名字是包名），工具挂在下面（项目主人同一天补定，样板第四版做法 1）；再后面技能、脚本、MCP 服务各一组（这三类一定各自独立），没有的也列出这一组，头写「还没有…」。没有单功能扩展的不列「扩展」组。

### 三、协议：`preset.get` 多 `sections`

```json
{"sections": [
  {"id": "basesystem", "kind": "group", "name": "基础系统", "on": 16, "total": 16, "items": [
    {"kind": "feature", "id": "write", "name": "新建文件", "on": true, "by": "group"},
    {"kind": "feature", "id": "sessions", "name": "跨会话消息", "on": true, "by": "group",
     "tools": [{"id": "sessions", "name": "列出会话", "on": true}, {"id": "send_message", "name": "发消息", "on": true}]}
  ]},
  {"id": "miyu-im", "kind": "package", "name": "接入通讯平台", "on": 3, "total": 3, "items": ["…"]},
  {"id": "skills", "kind": "skills", "name": "技能", "on": 2, "total": 2, "items": ["…"]},
  {"id": "scripts", "kind": "scripts", "name": "脚本", "on": 1, "total": 1, "items": ["…"]},
  {"id": "mcp", "kind": "mcp", "name": "MCP 服务", "on": 0, "total": 0, "items": []}
]}
```

1. `kind`：`group`（出厂的组）、`package`（带几个功能的扩展包）、`extensions`（单功能扩展合成的那一组）、`skills`、`scripts`、`mcp`。`on`、`total` 是这一组开着的功能、全部功能几个。
2. 组下面直接是功能，不出「包」这一层。功能带了几件工具的，`tools` 列出来（名字是工具的显示名，`on` 照预设的 `[tools]` 关没关）；只有一件、或者工具名就是功能名的不列。
3. `by`：`preset`（预设明写了这个功能）、`group`（预设写的是它所在的包或组）、`global`（全局开关）、`default`（照 `unlisted`）。
4. 名字、说明照连接的语言挑好；同一组里两个功能名字一样的，后面括号带包名。头不翻译、不排序、不认编号。
5. 原来 `preset.get` 的格不动，`sections` 是多出来的。
