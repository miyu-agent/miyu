### 一、知识库是什么，不是什么

- **一个知识库是一个目录**，里面是文档，外加一份派生的索引（N1）。
- **不是记忆**：知识库里是你放进去的文档；记忆是她自己从对话里记下的（`17-记忆.md` 第一节）。
- **不是自述**：「希望 AI 怎么认识你」是你写给她的，属于你（`06-多用户与身份.md` 第六节）。
- **三件事各有各的归属**：
  - 她能查哪几个知识库，由人格决定（`16-人格与预设.md` 第一节）；
  - 这一次开不开知识库，由预设决定。功能全开里开着，开发预设里关着；
  - 能不能用，由权限决定。知识库是资源：读是看里面的文档，改是增删文档，用是让自己的会话从中检索（`06-多用户与身份.md` 第三节）。

### 二、仿 Linux：文档就是文件

| Linux | 知识库 |
|---|---|
| `/usr/share/doc`、man 手册，随软件包装上 | 软件包带来的知识库：只读，随软件源更新 |
| 自己的目录 | 你自己的知识库 |
| `mount` 一个现成的目录 | 把现成的文件夹挂进来，例如你的笔记目录 |
| `updatedb`、`mandb` | 索引：派生数据，随时能删掉重建 |
| `apropos`、`man` | 她用的工具：`kb_search` 搜，`kb_read` 读 |

三种来源（N1）：

| 来源 | 放在哪 | 谁能改 |
|---|---|---|
| 软件包带来的 | 软件包自己的目录（`12-进程形态与分发.md` 第四节） | 只读，随软件源更新。例如 Shorin Wiki，放在软件源里，要的人自己装（N6） |
| 自己的 | `home/<账号>/kb/<名字>/` | 你，以及她（经 `kb_save`） |
| 挂进来的 | 你指定的一个现成目录 | 默认只读（N7），她不改你的文件；你在原处改了，索引跟着更新 |

- 成员挂进来的目录，只能在自己的工作区里，和成员的沙盒边界一致（`11-权限与沙盒.md` 第四节）。

### 三、文档与索引

- **格式**（N2，2026-09-25 确认）：Markdown、纯文本、PDF、网页 HTML。
  - PDF 抽出文字，按页引用；
  - HTML 去掉版式，只留正文；
  - 别的格式先不认，添加时说明不支持。
- **切块**：Markdown 按标题切，PDF 按页和段落切，其余按段落切。每一块都记着出自哪个文档、哪一节或哪一页。
- **检索**：关键词一路加向量一路，两路的排名合并，和记忆是同一套（`17-记忆.md` 第四节，N3）。中文先分词。向量用 `embedding` 这个用途配的模型（`15-模型与供应商.md` 第四节），默认是本机的小模型；向量那一路用不了时只剩关键词。
- **索引是派生数据**，放在 SQLite 里（`07-存储.md` S3），删掉了会重建。
  - 文件变了，只重建变了的那几个文件。每次列、搜之前照指纹（大小、改的时刻）补，不另监视：3000 篇的库不变的重扫 10 毫秒以内（2026-10-12 施工 K-4 量的，技术细节照推荐定）；量出重扫成了瓶颈再照监视配置文件的办法监视（`14-配置.md` 第五节）。
  - 换了向量模型，旧的向量作废，后台慢慢重建；这期间关键词照常能用。
- 旧版在这里踩过的坑：
  - 向量索引存成 JSON，136MB，每查一次要花 2.1 秒去解析；
  - 成员点「重建索引」时，起了一个不带成员身份的子进程，结果重建的是管理员的库，成员的库一块都没建上。

  所以索引放在 SQLite 里，向量按二进制存；建索引时，库的属主明确地传过去，不靠子进程自己去猜。

### 四、她怎么用

三件专门的工具（N4）：

| 工具 | 做什么 |
|---|---|
| `kb_search` | 在她能查的知识库里搜，返回几段摘录，每段带着出处（哪个文档、哪一节或哪一页）和编号 |
| `kb_read` | 按编号读一整节或一整篇，太长就分页 |
| `kb_save` | 把一段内容存进可写的知识库：新建一篇，或者追加到某一篇后面 |
| `kb_edit`、`kb_delete` | N14（2026-10-12 项目主人定，施工 K-3）：照原文改一段；整篇挪进系统回收站（撤销得回来）。建新的库不另给工具：`kb_save` 写到还没有的库就是建它。删整个库不给她 |

- 用专门的工具名，不塞进 `read` 的前缀里。旧版把知识库做成 `read` 的 `kb:` 前缀，实测她想不起来用。
- **系统提示词里列出她能查的知识库**：名字加一句话说明，放在稳定区（`08-上下文投影.md` 第三节）。知识库的说明里可以写明「这方面以我为准」；和网上查到的冲突时，她先信它（旧版回答 Linux 问题就是这个规矩）。2026-10-12 项目主人问有没有必要，施工 K-1 下量了：不列她只有 7/20 想起去搜，列了 19/20，无关的两种都不乱搜（`docs/construction/K-1-她查得到（下）.md`「量了的」）；项目主人看了数定加，施工 K-1 补做了（2026-10-12）。
- **一个库都查不到的会话没有这两件工具**（N13）。

**自动想起**（N5，2026-09-25 确认）：

- 可以给设置项。自动想起要克制：有的条目很长，截断以后给索引，她要全文就自己去查（项目主人定）。
- **每个知识库一个开关，默认关。** 适合角色设定、世界观这类「一提到就该想起来」的内容；文档资料留给她自己去查。
- 打开了的，每轮开始时和记忆一起检索（`17-记忆.md` 第四节），只带相关度够高的最前面几条。
- **每条只带开头一小段，后面接上出处和编号。** 要全文，她自己用 `kb_read` 去读。
- 这一块有总的长度上限，和记忆的召回共用一份预算。宁可少带，不多带。
- 带进来的内容记成 `context.injected` 事件，放在触发消息的前面，以后原样回放（`08-上下文投影.md` C2、`02-内核.md` K2）。

### 五、谁能查到什么

- **哪里都查得到**（N12，2026-10-12 项目主人定）：账号下的全部，人格收窄的照收窄（N11）。群里、别人的私聊里也一样；挂进来的私人笔记也会被搜到。多用户以后，别的账号的库照账号分开（`06-多用户与身份.md` 第五节）。

### 六、管理

- 终端界面和网页各有一个知识库页：列出知识库、添加文档（拖进来就行）、挂一个目录、看索引建到哪了、试着搜一下。
- 命令行：`miyu kb list`、`add`、`remove`、`mount`、`search`、`read`、`reindex`。
- 软件源里的知识库，按软件包的方式装和更新（`12-进程形态与分发.md` 第四节）。

| 方法 | 类型 | 做什么 |
|---|---|---|
| `kb.list` | 查询 | 能看到的知识库、来源、文档数、索引的进度 |
| `kb.search`、`kb.read` | 查询 | 搜索和读，界面上「试着搜一下」用的就是它们 |
| `kb.add`、`kb.remove`、`kb.mount` | 命令 | 添加、删除文档，挂一个目录 |
| `kb.reindex` | 命令 | 重建索引 |

- 只列出、只搜得到调用者有权看到的知识库（第五节）。

### 七、决定

**N1. 知识库是什么**

- **已定：一个目录，加一份派生的索引；有三种来源：软件包带来的、自己的、挂进来的。**
- 未选：旧版的做法，一个统一的目录，默认的知识库另走一套 git 更新。
- 重开条件：出现放不进目录的知识来源。

**N2. 第一版认哪些格式**

- **已定：Markdown、纯文本、PDF、网页 HTML（2026-09-25 确认）。**
- 未选 A：Word、Excel、PowerPoint。要依赖额外的转换工具。
- 未选 B：图片里的文字。要花看图模型的钱。
- 重开条件：有人确实需要别的格式。

**N3. 怎么检索**

- **已定：关键词加向量，两路合并排名，和记忆同一套；索引放在 SQLite 里；文件变了只重建变了的。**
- 未选：旧版把向量存成 JSON。136MB，每查一次解析 2.1 秒。
- 重开条件：实测 SQLite 撑不住某个规模的知识库。

**N4. 她用什么工具**

- **已定：`kb_search`、`kb_read`、`kb_save` 三件专门的工具。**
- 未选：塞进 `read` 的 `kb:` 前缀，也就是旧版的做法。实测她想不起来用。
- 重开条件：无。

**N5. 自动想起**

- **已定：每个知识库一个开关，默认关；只带相关度够高的几条，每条只带开头一小段加出处和编号，要全文她自己去读；和记忆的召回共用一份预算，宁可少带（2026-09-25 确认）。**
- 未选 A：每轮都自动想起。文档类的内容会带进不相干的段落，还要多花 token。
- 未选 B：都只在她主动查时用。角色设定这类东西，她得记得自己去查。
- 重开条件：实测自动想起带进来的内容，大多和当前这一轮不相干。
- **已定（2026-10-12 项目主人）**：开关放在库的 `kb.toml`；判「相关」关键词也算，不只照意思（未选：同记忆的联想只照意思，`embedding` 关着就没有自动想起）。
- **已定（2026-10-13 项目主人看了测评集定，`docs/blueprint/knowledge/eval.md`）**：关键词那一路照标题名算：话里提到了某一段标题的名字才带；再加照意思那一路，门槛 0.60。测评集上闲聊一句不带，带的 94% 对，88% 的回合想起了该想的。未选：普通的关键词搜得到就带（闲聊四成多也带，带的六成多不相干）。重开条件：真用起来点名的想不起、或者闲聊老带东西。

**N6. Shorin Wiki**

- **已定：不随出厂带，放进软件源，要的人自己装（2026-09-25 确认）。**
- 未选：出厂默认装上，也就是旧版的做法。
- 重开条件：无。

**N7. 挂进来的目录她能不能改**

- **已定：默认只读。她要把东西记进知识库，就记进你自己的知识库里。**
- 未选：可以直接改。她可能会改坏你原本的笔记。
- 重开条件：有人确实需要让她直接整理自己的笔记目录。那时逐个目录单独打开，每次改之前问。

**N8. 先后和底子**

- **已定（2026-10-07 项目主人）：先做记忆，知识库复用它的检索底子（蓝图 `recall.md`）。**
- 未选：先做知识库。它简单些，但记忆是陪伴的核心，底子随记忆做出来，知识库直接用。
- 重开条件：无。

**N9. 关键词触发的条目**

- **已定（2026-10-07 项目主人）：加，照 SillyTavern 的 World Info：条目开头写几个关键词，最近的话里出现了就带上，和联想共用一份预算；排在知识库那条线的最后。** 确定、说得清为什么带，适合角色设定、世界观。
- 未选：只用 N5 的按相关度自动想起。
- 重开条件：有角色设定的人格用上以后，发现 N5 已经够用。

**N10. 没有人格时、叫什么**

- **已定（2026-10-08 项目主人）**：知识库是账号级的，不带人格的会话照样能查（「知识库本质是个图书馆性质的东西，谁都可以查」）；和记忆不一样（`17-记忆.md` L17：没有人格时记忆不生效）。这个软件包给人看的名字叫「知识库」（英文 Knowledge base，日文 ナレッジベース）。
- 未选：没有人格时知识库也不生效。
- 重开条件：出现某个库只该给某个人格查的情况。

**N11. 她能查哪几个**

- **已定（2026-10-12 项目主人）**：账号下的全部（N10 图书馆）；人格可以收窄，`persona.toml` 里列了几个的只查那几个（比如角色扮演的人格只用自己的世界观库）。第一节「能查哪几个由人格决定」照这一条落实。
- 未选：只照人格列的，没列的一个都查不到。
- 重开条件：人格多了、每个都要一个个列。

**N12. 群里查得到哪些**

- **已定（2026-10-12 项目主人）**：哪里都查得到：群里、别人的私聊里也能查账号下的全部（人格收窄的照收窄）。知识库是图书馆，谁问都能查；和记忆不一样（记忆是一个大脑、私事靠「谁在听」挡，`17-记忆.md` L18）。挂进来的私人笔记也会在群里被搜到：要避开的别挂进来，或者用收窄了的人格。第五节「群里只查得到分享给这个群的」照这一条改。
- 未选：只查标了分享给这个群的；群里先不能查。
- 重开条件：出现私人笔记在群里被搜出来、造成了实际影响的情况。

**N14. 她能怎么操作知识库**

- **已定（2026-10-12 项目主人：「要允许 AI 操作 kb」）**：她能新建、追加文档（N4 的 `kb_save`），改、删文档（删的挪进系统回收站），建新的库；不能删整个库。排在 K-1 补（系统提示词里列库）以后马上做，照意思找（K-2）往后放。写知识库算「写」：只读级别下不能用，确认照权限级别（`11-权限与沙盒.md`）。施工 K-3 拆成三件：`kb_save`（建库也是它）、`kb_edit`、`kb_delete`；一个库都没有时也给 `kb_save`（好建第一个）；写的几件哪里都给，群里、别人的私聊也给（同一天项目主人定：他知道群友能叫她改、删，删的在回收站、撤销回得去）。
- 未选：只给 `kb_save`（只能新建、追加）；删整个库也给她（一次拿掉很多文档，风险大）。
- 重开条件：她改坏、删错了人的笔记，造成了实际损失。

**N13. 一个库都没有的时候**

- **已定（2026-10-12 项目主人）**：账号下一个库都没有（或人格收窄以后没有）的会话，工具面上没有 `kb_search`、`kb_read`；建了第一个库，下一个回合换上（工具面变了，缓存断一次），删光了下一个回合拿掉。没用知识库的人不为它每次请求多带两件工具。
- 未选：一直给（工具面不变、缓存不为建库断，可没用的人白带这几百 token，她也可能去搜空的库）。
- 重开条件：建库、删库频繁到缓存断得多了。

**后续再定**

- 某个群专属的知识库，例如群里的常见问题：随场所规则再定（`18-通讯平台.md` 第四节）
- 自动想起每轮带几条、每条多长：随上下文预算实测再定
