## 软件包配置项的词汇

包在清单的 `[settings]` 里能声明的配置项多几种写法，照 AstrBot 插件的 `_conf_schema.json` 补齐：选项带显示名、列表里每一项是一组字段、多行文字、小数、滑块、选 Miyu 自己的东西（模型、人格、知识库）。包只声明，核心统一读、查、存、交值，网页、终端照 `config.schema` 统一画。

状态：已定（2026-10-31 项目主人定：四档都做，现在就做。起因：miyu-agent-41 写生图脚本包、看 dsh 这类复杂扩展的配置，现有的词汇声明不出「多个账号，每个有地址、Key、备注」，选项在设置页上只显示 `auto`、`transparent` 这样的值）。参考 https://docs.astrbot.app/dev/star/guides/plugin-config.html 。第二到第五节的写法是技术细节，主会话定。

不照搬 AstrBot 的两处：密钥照旧另存在密钥文件里（它只打码、明文存）；扩展照旧不能写配置（它的插件能自己 `save_config`）。不走 `[page]`：后台页只有网页看得到，值和密钥得扩展自己存，脚本包也带不了。

### 一、选项带显示名

```toml
[settings.background]
type = "option"
choices = [
  { value = "auto", name = { zh = "自动", en = "Auto" } },
  { value = "transparent", name = { zh = "透明", en = "Transparent" }, description = { zh = "要配 png、webp" } },
  { value = "opaque", name = { zh = "不透明", en = "Opaque" } },
]
default = "auto"
```

1. `choices` 照旧收字的数组；也收表的数组：`value` 必写（写法同原来的选项），`name`、`description` 可以不写，写法同项自己的 `name`、`description`（一句字，或者照语言的表）。两种不能混着写。
2. 存的照旧是 `value`。`config.schema` 的 `options` 每一项照连接的语言带 `name`（没写的就是 `value`）、`description`（没写的不带）。
3. 头照 `name` 画下拉，`description` 暗色写在下面。

### 二、列表里每一项是一组字段

```toml
[settings.accounts]
type = "list"
element = "record"
title = "name"                                    # 列表里每一项拿哪个字段当标题
name = { zh = "账号" }

[settings.accounts.fields.name]
type = "text"
name = { zh = "备注" }

[settings.accounts.fields.base_url]
type = "url"
name = { zh = "接口地址" }

[settings.accounts.fields.key]
type = "secret"
name = { zh = "Key" }
```

1. `element = "record"`：每一项是一组字段，字段照 `[settings.<名字>.fields.<字段>]` 一张表写，写法同普通的项（`type`、`default`、`name`、`description`、`hidden`；`layers`、`applies` 跟着整项，字段里不写）。字段不能再是 `list`，也不能再是 `record`。字段名写法同项的名字，不能叫 `fields`。
2. `title`：拿哪个字段当每一项的标题，要是 `text`、`name`、`option` 之一；不写的头照「第几项」写。
3. 配置文件里写成表的数组：`[[<前缀>.accounts]]`，每张表一项；`secret` 字段照旧只能写成 `{ secret = … }`、`{ env = … }` 的引用，密钥另存在密钥文件里。
4. 校验：每一项照字段查，少写必写的（没有默认值的字段算必写）、多写不认识的字段、类型不对的，`miyu check`、`config.set` 报到「第几项的哪个字段」（`key` 写成 `<前缀>.accounts[2].key`，第几项从 0 数）。最多 100 项。
5. `config.set` 整条列表一起换（交对象的数组），不单改某一项。
6. 交值（握手、`extension.config`、改了推给扩展、脚本的 `MIYU_SETTINGS_JSON`）：对象的数组，密钥是解出来的真值，没写的字段照默认值，没有默认值的不放。
7. `config.schema` 这一项：`type: "list"`、`element: "record"`、`title`、`fields`（每个字段一张，格同普通项的 `config.schema`）。
8. 头：画成一张张卡片，`title` 那一格当卡片标题；「加一项」「删这一项」，卡片里照字段的类型画控件；改完整条列表一起存。

### 三、多行、小数、滑块

1. `type = "text"` 多一格 `lines = true`：头画多行的框（放提示词模板这类），不写 `max` 时最多 2000 个字（原来单行默认 200）。核心照配置清单的「几行字」（`lines`）收。
2. `type = "number"`：小数，必写 `min`、`max`，可以写 `step`（头用，核心不查）。核心照配置清单的「小数」（`float`）收。
3. `int`、`number` 写了 `slider = true` 的，头画成滑块（要有 `min`、`max`；`step` 不写的 `int` 是 1、`number` 是范围的百分之一）。`config.schema` 带 `control: "slider"`、`step`。

### 四、选 Miyu 自己的东西

| `type` | 值 | 头画什么 | 核心查什么 |
|---|---|---|---|
| `model` | 模型 `<供应商>/<模型>` 或池 `@<池>` | 照 `model.list`、池的列表挑 | 照配置清单的「引用」查写法；指的供应商、池没有的 `bad_reference` |
| `persona` | 人格的编号 | 照 `persona.list` 挑 | 写法同人格编号；没有这个人格的 `miyu check` 报警告 `unknown_persona`（人格可能以后才建，不挡） |
| `knowledge` | 知识库的编号 | 照 `kb.list` 挑 | 写法同知识库编号；没有的报警告 `unknown_knowledge` |

值都是字。交给扩展、脚本的照原样，核心不替它解析。

### 五、以后再说

- `type = "file"`：上传文件，存进包的状态目录，值是路径。
- 联动：`when = { key = "provider", is = "rightcode" }`，只管画不画，值照存。AstrBot 的文档里没写联动，要另外设计。
- 一张列表里好几种模板的项（AstrBot 的 `templates`）：要了再加 `kind`。
