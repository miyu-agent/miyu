## 包的会话状态

包可以在一个会话里记一份自己的状态：工具结果顺手带上，核心照有效历史记最新的一份，撤销、压缩、清空自然跟着；头照包声明的界面块画。待办（`todowrite`）是第一个用它的包，核心里专为待办写的代码全删掉，`todowrite` 降成官方软件源里的可选包。

状态：草稿（2026-10-28 主会话起草，施工 TW-1）。项目主人 10-27 定了三条（第二节）；10-28 答还没发版、没有人在用，不做升级和老日志的迁移；网页 10-28 对过位置；第七节等终端。

### 一、现在缺什么

- **待办是核心里的特例**：内核有效果 `todo.written`、事件 `todos.cleared`、命令 `ClearTodos`、待办表（`history/todos.rs`）、瞬时事件 `todos.changed`、压缩时把清单写进检查点（`rebuild.rs` 的 `todo_list`）；会话的 `Shown`、`subscribe` 回应的 `todos`、视图流状态的 `todos`、`todos_done`；端点的 `/todo clear`。一个包的功能散在内核、会话、端点、两个头里。
- **扩展做不出同样的东西**：扩展的工具结果（`tool.call` 的回应）只有内容块、`detail`、`data`，交不了效果；界面块的内容只在内存里，程序停了就清，撤销、压缩、重启都跟不上会话。想做「计划」「进度」「清单」这一类的包，只能求核心再加一个特例。
- **`todowrite` 卸不干净**：基础系统拆包（设计 44）以后它是个能卸的内置包，可工具编在核心里、内核认它的效果，卸了只是工具不上工具面。

### 二、项目主人定的（2026-10-27）

1. **通用化**：核心删掉专为待办写的代码（事件、推送、`/todo clear`、压缩和撤销里的待办分支），换成通用的「包在本会话的状态」：扩展工具的结果带一份状态，核心照有效历史记最新一份（撤销、压缩自然跟着），变了推通用的变更，头用界面块画。`todowrite` 是第一个用它的包。
2. **可选包**：`todowrite` 进官方软件源（同 `embed`），新装默认不带。
3. **先后**：排在接入通讯平台的「按人接入」（请求 1～7）之后。

### 三、样子

**1. 一份状态**

```json
{
  "widgets": {
    "todos": {"content": [{"type": "list", "items": [{"title": "读代码", "state": "done"}, {"title": "改测试", "state": "doing"}]}]},
    "todo-count": {"content": [{"type": "text", "text": "1/2"}], "title": {"en": "Todos", "zh": "待办"}}
  },
  "note": "Current todo list:\n- [x] Read the code\n- [ ] Fix the tests",
  "data": {"todos": [...]}
}
```

| 格 | 是什么 | 上限 |
|---|---|---|
| `widgets` | 块的编号到这一块的 `content`（写法同 `widgets.md`「内容」）、可选的 `title`（同 `widget.set`）：头照包声明的跟着会话的那几块画。一个包几块位置不同（侧边栏整份、底栏一小段），各给各的 | 同界面块，照每一块声明的位置查 |
| `note` | 压缩时写进检查点、给模型看的一段英文（同给模型看的字的规矩：CJK 不过半、没有控制字符） | 2000 个字 |
| `data` | 包自己的数据，任意 JSON：核心只存，不看，原样还给包（下面第 5 条） | 16 KiB |

- 都可以不写；三格都不写的 `{}` 是「清掉」。`null` 也是清掉。`widgets` 里没写的块没有内容。
- 写坏了（超上限、块不是这个包声明的 `state = true` 的那几块、内容写法不对、`note` 不合规矩）整份不收，工具结果照常，运行日志一行 `WARN package state dropped package=… why=…`，同 `detail`。

**2. 怎么交**：两条路，记成同一种东西。

- **工具结果带上**：`tool.call` 的回应多一格 `state`（同 `detail`、`data` 的位置）。`error` 是真的不收。
- **程序直接写**：`session.set_state {"session", "state"}`，只给核心拉起的扩展的连接，要 `sessions.drive` 能力（复用，同 J-4 的定时）；会话照旧归主人。界面块上的按钮（例如「清掉待办」）点了，头 `package.call` 给程序，程序照这条写。回合进行中、空闲时都收，不开回合。

**3. 内核**：一种通用的记录，按包分。

- 工具结果上的效果多一种 `package.state {"package", "state"}`（换掉 `todo.written`）；程序直接写的记一条事件 `package.state`（同样的两格，不带回合编号的照 `events.append` 的办法记，回合进行中的带上这一轮）。
- 有效历史另记一张表（照现在的待办表、派出去的任务表的办法）：每个包最近一份没撤掉的。撤销那几轮里写的标成撤掉，恢复的去掉标；压缩不动这张表。
- **清空上下文**（`/clear`、`session.clear`）清掉全部包的状态，和现在清待办一样。
- **压缩**：重建检查点时，每个有 `note` 的包照包的编号排，各写一段原文，接在取回指路（和待办）后面，不另加字（给模型的字非必要不加）。模型照旧只从检查点看到它，平常的回合不另注入。
- 变了才推：落了盘、和上次告诉头的不一样，推一条瞬时的 `package.state_changed {"package", "state"}`（只有 `widgets`，`note`、`data` 不给头）。

**4. 头**：仍然只画界面块。

- 包清单里声明一块跟着会话的界面块（`[[widget]] scope = "session"`），再写 `state = true`：这一块的内容来自这个包在这个会话里的状态，不来自 `widget.set`。核心把状态里 `widgets` 下这一块的 `content`、`title` 交给订阅了这个会话的头（`widget.changed`），程序在不在跑都一样（`running` 照实写，内容不清）。没写 `state = true` 的块照旧只认 `widget.set`。
- `scope = "session"` 现在只给侧边栏；改成也给 `status`（底栏一小段，例如「待办 2/5」）。终端窄屏、网页窄屏靠它。
- 头删掉专为待办画的那几处：`subscribe` 回应的 `todos`、视图流状态的 `todos`、`todos_done`、`todos.changed` 推送都没有了。

**5. 程序读回自己的状态**：`session.state {"session"}` → `{"state": {...} | null}`（只给这个包自己的，`data` 在里面）。`todowrite` 每次整份换，用不着；增量改的包（例如只勾一项）靠它。

**6. `todowrite` 包**

- 一个扩展程序（Rust，和 `embed` 一样放 `miyu-agent/packages`，三平台二进制进官方源），`provide` 一件 `todowrite`：参数、结果那一句、说明的字和现在一字不差（工具面字节不变，缓存不断）。
- 结果带 `state`：`widgets` 里侧边栏那块是一张 `list`（`todo` / `doing` / `done` 照现在的三态）、标题「待办 2/5」，底栏那块一段字「2/5」，`note` 是现在检查点里那段清单的原文，`data` 是整份清单。全部做完的交 `{}` 清掉（项目主人 10-17 定的「全部完成之后直接消失」），头上那一块没了，检查点也不带。
- `/todo clear` 跟着包走：清单 `[[slash]]` 声明，程序收到照 `session.set_state` 写 `{}`。
- 清单 `[[widget]]` 两块：侧边栏一块（全部清单），底栏一块（「待办 2/5」）。
