## 知识库

### 是什么

你放给她查的文档（`19-知识库.md`）：一个知识库是一个目录，里面是文档，外加一份派生的索引（N1）。不是记忆（记忆是她自己从对话里记下的，`memory.md`）。三种来源：你自己的、挂进来的现成目录、软件包带来的（N1，后两种随 K-4、K-8）。

- 知识库是账号级的图书馆：账号下的全部她都能查，人格可以收窄（N10、N11，2026-10-12 项目主人定）；群里、别人的私聊里也查得到（N12，同一天定：和记忆不一样，不照「谁在听」挡）。
- 检索用记忆那一套底子（`recall.md`，N3、N8）：关键词一路先做（K-1 上），照意思那一路随 K-2。
- 仿 Linux：文档就是文件（19 第二节）。真相是目录里的文件，索引随时能删掉照文件重建（`07-存储.md` S1、S3）。

状态：图纸（2026-10-12 起草，照 `19-知识库.md` N1 到 N14、`docs/reviews/2026-10-07-记忆知识库embedding调研.md` 第五节第 7 条）。每一节标着由哪一步做，步子见末尾「施工步子」。做完一步，这一页照做好的样子改写那几节。做好了的：K-1 上（底子、协议）、K-1 下（她的两件工具、人格收窄、知识库这个包）。

### 对外的样子

**一个知识库**（K-1 上）：数据根里 `home/<账号>/kb/<编号>/`（`07-存储.md` 第二节），编号就是目录名，写法同人格的编号（小写字母开头，只有小写字母、数字、`-`、`_`，最多 64 个字符），不合写法的目录不算。目录里：

- `kb.toml`（可以没有）：

  ```toml
  name = "日语笔记"          # 给人看的名字，没写的照编号
  description = "学日语的笔记：语法、单词、例句"   # 一句话说这个库是什么，没写的空着；随 K-1 下进她的系统提示词
  ```

  别的格不认（读进来照规矩报错，`kb.list` 里这个库带 `error`，照没有 `kb.toml` 的样子用）。
- 文档：扩展名是 `.md`、`.markdown`、`.txt` 的文件，子目录里的照样算；以点开头的文件、目录不算；`kb.toml` 不算。别的格式随 K-5（PDF、HTML）。超过 4 MiB 的、不是 UTF-8 的不收，记一行运行日志（「出错」）。

**索引**（K-1 上）：`home/<账号>/index/kb/<编号>.db`，检索库（`recall.md`「库的结构」），派生的。

- 一块一行：键是 `<相对路径>#<第几块>`（路径照 `/` 分，块从 0 起），字是这一块（带着它的标题路径，第二条），时刻是文档改的时刻。
- 每个文档一个指纹：大小加改的时刻（毫秒），记在检索库的 `stamps(source, stamp)` 里（`recall.md`，K-1 上加的一张），来源是相对路径。指纹没变的不重切。

**协议**（K-1 上；原文写法见 `protocol.md`「`kb.*`」）：人经协议查，给知识库页、「试着搜一下」用。照管理员的账号（同 `memory.*`）。不管知识库这个软件包装没装都能用：文件是人的，人随时看得到（她的工具、系统提示词里的那一段随 K-1 下照包开关）。

| 方法 | 类型 | 参数 | 回应 |
|---|---|---|---|
| `kb.list` | 查询 | 没有 | `{"bases": [<一个库>…]}`，照编号排 |
| `kb.search` | 查询 | `query`（不能是空白）；`kb`（只搜这一个，可以不写）、`limit`（1 到 50，不写 10） | `{"hits": [<一块>…]}`，最相关的在前 |
| `kb.read` | 查询 | `kb`、`path`（文档的相对路径）；`page`（从 1 起，不写 1） | `{"text", "page", "pages"}`：文档原文的那一页 |

- 一个库：`{"id", "name", "description", "documents", "chunks"}`，读 `kb.toml` 出错的多一格 `error`（英文的一句为什么）。`documents`、`chunks` 是照文件补完以后的数。
- 一块：`{"kb", "path", "chunk", "heading", "text", "at"}`：哪个库、哪个文档、第几块、标题路径（没有标题的是空的）、这一块的字（不带标题那一行）、文档改的时刻。
- 一页 32 KiB，截在字的边界上；`pages` 是一共几页，空文档是一页空的。
- 出错：`unknown_kb`（没有这个库）、`unknown_document`（库里没有这个文档：不是文档的、不在库里的、`..` 跑出去的都算）、`bad_params`（`query` 空白、`limit` 出范围、编号不合写法、`page` 是 0 或超过 `pages`）。

**她的工具**（K-1 下，19 N4）：知识库这个内置包（`knowledge`，出厂装着；预设照功能开关：全部功能开、基础功能关）带两件，访问类别 `read`。

| 工具 | 做什么 | 参数 |
|---|---|---|
| `kb_search` | 照关键词搜她查得到的库 | `query`；`kb`（只搜这一个，可以不写） |
| `kb_read` | 读一个文档的一页 | `kb`、`path`；`page`（从 1 起，不写 1） |

- `kb_search` 最多 5 块，几个库照名次轮流合（同 `kb.search`）。一块一段：头一行 `[<库>] <路径>: <标题路径>`（没有标题的 `[<库>] <路径>`，照模板，换进去的转义），下面是这一块的字原样（文档是数据，同 `read` 交回文件的内容，末尾的换行去掉），段和段之间空一行。什么都没搜到的说一句，不算出错。
- `kb_read` 一页 32 KiB（同 `kb.read`），交回那一页的字原样；不止一页的末尾另起一行 `(Page 2 of 3.)`。
- 出错如实说，算出错：没有这个库（连同人格没列的，不让她知道有）、库里没有这个文档、没有这一页、读不了、参数不对；这个会话没有知识库的端口（核心没交）的也说一句。
- 原文见 `prompts.md`「`software/knowledge/`」，登记在 `26-提示词.md` 第十节。
- 系统提示词里还没列她查得到哪几个库：K-1 下量了，不列她只有 7/20 想起去搜、列了 19/20，项目主人 2026-10-12 定加，随 K-1 补（19 第三节）。

**人格收窄**（K-1 下，19 N11）：`persona.toml` 的 `[knowledge] bases = ["notes", …]`（`personas.md`）：用这个人格的会话只查得到列着的、在的那几个；空的列表一个都查不到。不写的查账号下的全部。

### 怎么走

**一、哪些库**（K-1 上）：`home/<账号>/kb/` 下每一个合写法的目录是一个库，照编号排。目录不在的当一个都没有。

**二、切块**（K-1 上，`miyu_recall::chunk`，调研第五节第 7 条：200～400 token 一块）：

1. Markdown 照标题切：`#` 到 `######` 开头的一行起一节，一节一块；每块的标题路径是它上面各级标题照层级连起来，中间是 ` › `（`语法 › て形`；K-1 下从 ` > ` 改过来：给她看的字段一律转义，`>` 会写成 `\u003e`），写在这一块的字的头一行（`# 语法 › て形`，没有标题的不写）。代码块（三个反引号起止）里的 `#` 不算标题。
2. 纯文本照段落切：空行分段，连着的几段合成一块。
3. 每块最多 1200 字节（约 300 token）：一节、一段太长的照段落再切，一段自己就超过的照字切（截在字的边界上）；切开的每一块都带着同样的标题路径。只有空白的块不要。
4. 同样的文档切出同样的块（照编号对得上），纯逻辑，有单元测试。

**三、照文件补**（K-1 上）：`kb.list`、`kb.search` 之前先补这个库（在阻塞线程里）：

1. 列出库里的文档，每个算指纹（大小、改的时刻），和 `stamps` 里记着的比。
2. 新的、变了的：读出来、切块，在一个事务里拿掉它原来的块、放进新的、记下新的指纹（`RecallIndex::replace`）。
3. 没了的（`stamps` 里有、目录里没有）：拿掉它的块和指纹。
4. 一个文档读不了、太大、不是 UTF-8：跳过它（原来的块照留），记一行 `WARN knowledge document skipped kb=… path=… why=…`，别的照补。
5. 一个库同一时刻只有一个在补（库一把锁，核心一份登记）：两个请求同时来，后来的等前面的补完。

**四、搜**（K-1 上）：照关键词（`recall.md` 第一条）在每个要搜的库里各找 `limit` 块；几个库的照名次轮流合（每个库的第一名在前，同名次照库的编号），取 `limit` 块。

**五、读**（K-1 上）：照路径直接读目录里的文件（真相），不读索引；一页 32 KiB。

**六、给不给、查哪几个**（K-1 下，19 N11、N13）：

1. 查哪几个：会话的记忆账号（`memory_account`：人格住在谁家；无人格的照属主，系统账号的照管理员）下的全部库；人格收窄的只留列着的、在的那几个，照列的先后（搜的时候同名次照这个先后）。每次调用照那一刻的目录和人格文件算：建了库、改了人格，下一次调用就照新的。人格的文件没了的（会话照快照接着用）当没收窄。
2. 给不给：知识库这个包装着、预设开着、照第 1 款查得到至少一个库，工具面上就有两件；本机的、群里的、别人私聊里的、子代理都一样（N12）。一个都查不到的没有（2026-10-12 项目主人定）。目录、人格文件读不了的当查不到，记一行 `WARN knowledge unreadable error=…`。
3. 什么时候判：造会话时判一次；载入的照快照；每个回合开始照这一刻再判（`actor/persona.rs`，同人格、预设改了下一个回合换上）：该有的两件和快照里的不一样才换快照（建了第一个库下一个回合有，删光了、收窄成空的下一个回合没有），换的时候工具面变了，缓存断一次。预设找不回来的照旧。
4. 端口：每个会话一份（`Shelves`），每次调用造一个端口，碰磁盘的在阻塞线程里做；跳过的文档、读不了的照第三条第 4 款、「出错」记一行（目标 `miyu::session`）。

### 出错
