## `package`

### 是什么

她装、卸软件包，打开她装的扩展（施工 F-10 下，设计 `31-软件包.md` 第六节第 1、2 条，定了的 D、E）。她自己写的技能、脚本、扩展在工作区里照包的样子写好一个文件夹，用这件装上；家目录里的 `skills/`、`scripts/` 照现在的文件权限走，不另开口子（31 第六节第 3 条）。看是另一件 `packages`（只读，`tools/packages.md`）：访问类别是一件工具定死的，看和改分两件。


### 谁能调（施工 BS-1 中，设计 `44-基础系统拆包.md` 第三节第 4 条）

不上工具面（`Tool::command_only`）：tools 数组里没有，她直接调、脚本里的 `miyu call` 调都当不认识。会话里她跑 `miyu pkg`，经 `miyu call` 的通道（`op: "pkg"`）带着会话身份调这一件，照下面的权限问人，卡片照看一眼的那一份；`packages` 包开着的会话才开这条路。以前造的会话照旧在 tools 数组里，字节不变。

### 从软件源装、升级（施工 G-6，设计 `37-软件源.md` 第四节第 9 条、定了的 C）

- `install` 写的没有路径分隔符（`/`、`\`）的是编号，从软件源装（核心的 `package.install {"source"}`，缺的依赖一起装），装好照旧在会话用的预设里打开；有分隔符又不是绝对路径的照旧说要绝对路径。
- `upgrade`：写编号升那一个，写 `all` 升能升的全部（核心的 `package.upgrade`）。升好了说 `Upgraded: <编号> <新版本> (was <旧版本>), …`，没有要升的说 `Nothing to upgrade.`。
- 问人之前看一眼照同一条路（`package.install {"source", "preview"}`、`package.upgrade {"preview"}`），卡片写装哪个（`install`）、升哪个（`upgrade`，全部的写 `all`），看一眼里有来源仓库、官方还是社区、要下多大。权限照下面这张表，和装包文件夹一样。
- 经端口装的没有连接，不推下载进度。

### 问不问人（31 第六节的表）

| 会话的权限级别 | 做法 |
|---|---|
| 完全放开 | 直接做，不问人 |
| 工作区（平常） | 每次都问人一次，不给「这个会话里都放行」 |
| 只读 | 不能做 |

没人能确认的会话（群这些）照现在的规矩：要问的直接拒；完全放开的照样直接做。人在头上、命令行上装卸不受这张表管（人装就是人批的）。

1. **新的访问类别 `install`**（内核 `Access::Install`）：改这台机器上装了什么。算写入（只读时内核拦下），权限策略不报路径、照级别判：完全放开放行，工作区问人且不提规则，只读拒绝。和 `execute` 分开：有沙盒的会话里跑命令不问人，装包要问。
2. **问人的卡片照看一眼的那一份**：要问的时候，执行器先经端口看一眼（装的 `package.install {path, preview: true}`、卸的 `package.remove {package, preview: true}`，名字照英文），整份放进确认请求的说明 `detail.preview`。日志里记下的就是人看到的那一份；头照命令行 `miyu pkg install` 那样列（包含、需要、一并删除、大小）。看不了的（写错的清单、读不了的文件夹）不问，当场照拒绝交回她。
3. 不问的（完全放开）不看这一眼，直接做。

### 拆成两步

| 步 | 做什么 |
|---|---|
| F-10 下上 | 访问类别 `install`、权限策略；工具 `package` 的装（包文件夹）、卸；问人的卡片带看一眼的那一份；端口多装、卸两样 |
| F-10 下下 | 打开装着的扩展、带了服务的包，批它要的能力（问人的那一次一并批）；装上的包在会话的预设里打开（16 第三节：预设不开没列出来的软件的，往那一份同名覆盖里添上这一项） |

### 对外的样子（F-10 下上）

```json
{
  "description": "Install a Miyu package from a folder, or remove an installed one. Check the folder with packages first.",
  "parameters": {"type":"object","properties":{"install":{"type":"string","description":"Absolute path of a package folder to install."},"remove":{"type":"string","description":"Package id to remove."}}}
}
```

- 三个参数写一个（`enable` 施工 F-10 下下：`"Package id to turn on: an extension or MCP servers."`）。`install` 要绝对路径。别的参数不认。
- 打开（F-10 下下）：问人之前看装着的那一份（带了什么、要什么能力），卡片照它；没有开关的、程序不在的当场拒、不问。打开时要的能力一并批。
- 装上的包在会话的预设里打开（F-10 下下）：会话用的预设随每次调用带上（`CallIds::preset`）；那一份预设不开没列出来的软件、也没写这个包的，往家目录那一层的同名覆盖里写 `software.<编号> = true`。
- 装成了：一行，编号、版本（写了的）；接着一行照看一眼的那一份 JSON。卸成了：一行。拒了：照 `packages` 那几句的样子说原因代码，写错的清单带哪里不对、第几行，和装着的包撞了名的（`package_conflict`）照 `packages` 第 5½ 条一处一行（施工 F-8 六补修）。
- 效果：不报（包目录在数据根里，撤销管不到；卸了再装回来）。
- 装的是本机的包文件夹，看文件夹报那个路径是读（同 `packages`）：只碰得到自己工作区的会话装不了工作区外的。
- 装卸以后：开着的会话下一个回合工具面才换（设计 30 第九节）；技能下一回合照新的列（X-11 下）；脚本当场登记（X-12 中）。

### 定了的（主会话，技术题照推荐，2026-10-12）

- **新访问类别，不复用 `execute`**：`execute` 在有沙盒的会话里不问人；装包要照 31 的表问。
- **每次都问，不给规则**：装一次就是一次，不该一劳永逸（同沙盒外跑命令，`beyond`）。
- **卡片里放看一眼的整份**：头不用再回来问一次；日志里留下人看到的东西。
- **端口沿用 `PackagesPort`**，多 `install`、`remove`、`removing`（卸之前看一眼）三样：一件工具一个端口，名字照「软件包的端口」。
