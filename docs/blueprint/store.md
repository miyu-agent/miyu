## 存储

### 是什么

存储的执行器，做真的磁盘读写：找数据根、第一次用时建骨架；会话日志按段写、打开时自检；大内容存成 blob；删掉的会话挪进回收处，满了时限再真删。资源目录和给人看的字另见 `store/resources.md`，会话列表的索引另见 `store/index.md`（施工 3-8 七补）。

### 对外的样子

**环境快照 `Env`**：`Env::current()` 从进程里读一次。找数据根只照快照算，不直接读进程的环境。

| 格 | 取自 | 用来 |
|---|---|---|
| `platform` | 编译的目标：macOS 是 `Macos`，Windows 是 `Windows`，别的（Linux 和别的类 Unix）是 `Linux` | 缓存目录的默认位置 |
| `miyu_home` | 环境变量 `MIYU_HOME` | 数据根 |
| `home` | 标准库的 `std::env::home_dir()` | 数据根、缓存目录 |
| `xdg_cache_home` | `XDG_CACHE_HOME` | Linux 的缓存目录 |
| `local_app_data` | `LOCALAPPDATA` | Windows 的缓存目录 |
| `miyu_resources` | `MIYU_RESOURCES` | 资源目录 |
| `exe` | 程序的位置，顺着链接找到的本体；找不到本体的照原样 | 资源目录 |

没设的、读不到的是空的。空的、相对的算不算数，由用它的地方定。

**系统的语言 `env::locale()`**（施工 8-1）：`LC_ALL`、`LC_MESSAGES`、`LANG` 照这个先后，取第一个设了、不是空的（不是 UTF-8 的当没设），和命令行认界面语言的一样；都没设的是空的。不在快照里，只有核心要用语言、又没有头的时候读一次（生成配置的 Schema 和参考文件，`config.md`「怎么走」第一条第 6 条）。这几个都没设时看系统设置（`system_locale`，用 `sys-locale`：macOS 的首选语言、Windows 的界面语言，Linux 上它看 `LANGUAGE`，施工 8-2）。命令行握手以前也照它挑界面语言（`cli/main.md`）。

**本机是什么系统 `env::os_name()`**（施工 2-7 再补）：核心头一次要时认一次，之后照它，写进新会话 system 核心的几行（`policy.md` 的 `with_core_lines`）。Linux 照 `/etc/os-release`（没有的看 `/usr/lib/os-release`）的 `NAME` 加 `VERSION_ID`：`Arch Linux`、`Ubuntu 24.04`；macOS 照 `/System/Library/CoreServices/SystemVersion.plist` 的 `ProductVersion` 写大版本：`macOS 15`；Windows 照内部版本号（`windows-version`）分 `Windows 10`、`Windows 11`（22000 起），服务器版写 `Windows Server`。认不出的照平台写 `Linux`、`macOS`、`Windows`。只写名字和大版本：小版本常变，变了新会话的 system 就和前一天的不同，跨会话的缓存接不上。只留一行：控制字符换成空格，最长 64 个字。

**生成的文件 `generated::write(路径, 字节)`**（施工 8-1）：和磁盘上已经有的逐字节比，一样的不写，交回 `false`；不一样的在旁边新建临时文件 `.<文件名>.<进程号>-<计数>.tmp`、写进去、同步、关上，改名盖上，再同步目录，交回 `true`；没有的目录建上（Unix 上 0700）。写到一半失败的，临时文件删掉。不顺着链接找本体、不带原来的权限位、Windows 上改名失败不重试：它们是派生的，下次起来再写（`config.md`「怎么走」第一条第 7 条）。

### 怎么走

**1. 找数据根**（`DataRoot::locate`）

1. `MIYU_HOME` 设了、不是空的：就是它。开头是 `~` 的，照家目录接上：整个就是 `~` 的是家目录本身，`~/` 开头的接上后面（Windows 上 `~\` 也算）；`~别人` 不认，照原样当相对路径（施工 4-11：在终端里 `export X=~/…` 加了引号时，`~` 没被 shell 展开）。找不到家目录的，报找不到家目录。接好以后要是绝对路径，相对的报错，不猜。
2. 没设或者是空的：家目录下的 `.miyu`，三个平台一样。家目录没有、不是绝对路径的，报错。

**2. 建骨架**（`DataRoot::prepare`）

1. 建数据根本身，缺的上级一起建。
2. 看顶层有没有 `.miyu-layout`。只看在不在：文件、目录、链接都算。
3. 没有标记：
   1. 目录里有任何东西（只有一个隐藏文件也算）：再看一眼标记，别处可能刚写下；还没有，报错，一个字节都不动它。有旧标记 `.miyu-layout` 的报「旧版 Miyu 的数据根（layout 2），新版不认」（设计 55 第六节第 1 条）。
   2. 目录是空的：只许新建地写标记，内容是 `This directory is a Miyu data root (layout 3).` 加换行；同步这个文件，再同步数据根。别处刚写下了的，也算成。
4. 标记里写的不是这一版的布局（以后的、写坏了的）：报错，不动。空的多看几眼（最多半秒）：别处刚建、还没写进字；半秒后还是空的照写坏了算。
5. 骨架 `etc/`、`etc/private/`、`run/`、`tmp/`，缺的才建；别的由核心起来时建（上一节）或用到时再建。
6. 建两次不出错；两个进程同时第一次用同一个数据根，都成。该是目录的地方是个文件，报错。

**3. 缓存目录**（`cache_root`）：整台机器共用，不跟着 `MIYU_HOME` 变。

| 平台 | 在哪 | 找不到时 |
|---|---|---|
| Linux | `XDG_CACHE_HOME` 设了、不是空的、是绝对路径的：`<它>/miyu`；不然 `~/.cache/miyu` | 要用家目录，家目录却没有、不是绝对路径：报错 |
| macOS | `~/Library/Caches/Miyu` | 同上 |
| Windows | `<LOCALAPPDATA>\Miyu\cache` | `LOCALAPPDATA` 没有、不是绝对路径：报错 |

**4. 建目录、同步**（`durable.rs`，这一页新建的目录都走它）

1. 已经是目录的，不动。
2. 不在数据根里的不建（施工 TMP-1）：往上找，没有一层的顶上有 `.miyu-layout` 的，报 `NotFound`：`<目录> is not inside a Miyu data root (no .miyu-layout above it), not creating it`。数据根被人删了（测试的夹具清掉了临时目录、人删了 `~/.miyu`），后台还在写的库、日志、blob 不再一层层把它建回来：原来一次测试在临时目录里留下五百多个目录。别的 crate 在数据根里写东西建目录的，用 `root::create_inside`，同一个规矩。不在数据根里的不查：建数据根本身（`prepare`）、配置文件（项目目录里的 `.miyu/`）、测这一条本身的测试（`create_dir_anywhere`，crate 里自己用），生成的文件的 `generated::write`（模型目录的缓存在机器的缓存目录里，头也拿它写自己的文件；写进数据根的配置清单、MCP 和扩展登记的缓存、`var/cache/models` 用 `write_inside`）。
3. 缺的上级先一层层建。
4. Unix 上新建的是 0700。同一刻别处建好了的，算成。
5. 新建的每一层，都同步它的上一层：建目录这件事本身才算落盘。
6. 同步目录：Unix 上打开目录、`sync_all`；Windows 上什么都不做。

**5. 会话日志：新建、追加**

1. 一个会话一个目录，一段一个文件，名字是这一段第一条的序号补零到 12 位，加 `.jsonl`：`000000000001.jsonl`。
2. 一行一条事件：事件写成的一行（`Event::to_line`，紧凑的 JSON，`kernel/events.md`）加 `\n`。UTF-8，三个平台都不写 `\r`。
3. 新建（`create`）：建目录，只许新建地建第一段 `000000000001.jsonl`，同步目录。第一段已经有了的报错，不覆盖。
4. 写一批（`write`，施工 V-18）：
   1. 空的一批，什么都不做。
   2. 序号要从下一条起一条接一条；有一条接不上，报错（`InvalidInput`），一个字节都不写。这是调用的一方的 bug。
   3. 整批拼成一块。
   4. 这一段已经写过、而且已经到了上限：先 `sync_data` 这一段，再开下一段，名字照这一批的第一条，只许新建，建好同步目录。一批不拆到两段里，所以一段可以比上限大。断电时不会有后一段、前一段却缺了一截。
   5. 一次写入，不同步。返回时这一批交给了系统：程序崩了照样在，断电要等下一次同步。
   6. 同步（`sync`）：`sync_data` 正在写的那一段，之前写的都落了盘。追加（`append`）是写一批再同步，返回时这一批都落了盘。
5. 一个会话只有一个写者，就是它的 actor（`session/actor.md`），不加锁。

**6. 会话日志：打开、自检**（`SessionLog::open`）

1. 目录里的段：名字正好是 12 位数字加 `.jsonl` 的，照数字排；别的文件不看。目录不存在、一段都没有：「没有这个会话」。
2. 照段的先后读，照 `\n` 分行。序号从 1 数起，跨段接着数。一段照定长的窗口（4 MiB）一窗窗读（施工 V-37 中：原来一段整个读进来，22.7 MB 的会话每读一遍内存里就多一份 22.7 MB 的原文）：只读到打开这一刻的长度（之后才追加的不要）；一窗切在最后一个 `\n` 后面，余下的半行接到下一窗开头，一行比窗口还长的窗口照这一行撑大；交完一窗，这一窗的原文就放掉。一窗读得完的段（几乎所有会话）就在调的线程里读、解；比一窗大的另起一个线程一窗窗读、解，解好的块排着（最多 8 块）交过来，查、交还在调的线程里照先后，这一窗还没交完下一窗已经在读、在解，窗口边上不用等。4 MiB 是一窗里 8 个线程都分得到活的最小的窗口（一个线程至少半 MiB），量过不比整段读慢（1 MiB 慢了快一倍，16 MiB 不更快）。不映射文件：要 `unsafe`，别的进程截短映射着的文件会 `SIGBUS`，Windows 上映射着的文件截不了。
3. 最后一个 `\n` 后面还有字节（半行）：先照打开那一刻的长度从后往前一块块（64 KiB）找最后一个 `\n`，半行该报的先报、该截的先截，再一窗窗读、查每一行。
   1. 不是最后一段：报坏了，行号是整行数加 1。
   2. 最后一段：截到最后一个 `\n`，再 `sync_all`。它一定从未被确认过。截在查这一段的每一行之前：这一段里前面有坏行的，半行照样先截掉，再报坏了。前面的段坏了的，读不到最后一段，不截。
4. 每一整行：要是 UTF-8；要读得出事件；序号要是该来的那一条。不对的报坏了，写明哪一段、第几行（从 1 数）。一段里的行多的（2048 行以上）分几块在几个线程里一起读成事件（照核数，最多 8 块，施工 V-2 下补：一万条事件的会话读、解日志约 23 ms，是重启以后打开大会话的大头），解好一块照先后交一块、查序号（施工 V-15：交的一方用完就放掉，解的线程最多领先交出去的两倍线程数那么多块，`log/open/parse/stream.rs`；施工 V-37 中起照窗口分，块不跨窗，一段整个在一窗里的块和以前一样）；报的还是照先后第一处不对的那一行，先报序号接不上的，再报读不成的那一行，最后才报段名不对（同以前）。一行前后多出来的空白（空格、制表、`\r`）算 JSON 的空白，照样读得出：`\r\n` 结尾的行不算坏。
5. 有事件的段，第一条的序号要和段的名字一样，不一样的报坏了（第 1 行）。
6. 空的段：是最后一段的，名字要是下一条该来的序号，不是的报坏了（第 1 行），是的接着往里写；不是最后一段的，当没有，名字不查。
7. 除了截最后那半行，别的一律只报不修：日志是真相，修错了就是丢了。报坏了的错照段名、行号说得出坏的那一行该是第几条（`OpenError::broken_at`：段的文件名、行号、序号，段名不是序号的没有；施工 YC-6）：`view.page` 照它只读地交坏行以前的，载入照它说 `session_read_only`（`protocol.md`），日志照旧一个字节不动（2026-11-10 项目主人定：只读打开，不给修）。
8. 交回开着的日志（接着往最后一段追加，已有的长度照截后的算）和读出来的全部事件，交给内核载入。

**7. 只读地读**

- `open_each`：同 `open`，只是读出来的事件照先后一块块交给 `每一块`，不攒成一整份（施工 V-15：载入时边读边过账本，压缩以前的用完就放掉，`kernel/session.md`「载入和崩溃」）；它交回 `Stop` 的不读下去，交回没有这个会话。
- `read_events`：和打开时一样自检，只是最后一段末尾的半行跳过、不截，一个字节都不写：会话可能正在往里写。撤销、恢复以后会话重算她看过的（`session/actor.md`），撤销的回应读日志（`protocol.md`），用的都是它。
- `read_segments`：同 `read_events`，只是读一段交一段给 `每一段`，它交回 `false` 就不读下去（施工 6-4：`history` 翻长会话，叫停了不用读完整份；施工 V-45 起 `history` 改用 `read_range` 从第一条一块块读，不再一段段攒成整块，V-49 起再改成 `read_range_only` 只解要的种类）；撤销撤掉压缩时，会话读回更早的一段原来也用它、只留要的那几条（施工 6-9），施工 V-37 下换成 `read_range`。
- `read_marked`（施工 3-8 七补，列会话照索引补时用，`store/index.md`）：同 `read_segments`，只是从 `从哪里` 读起，交回读到了哪里（最后一段、照到的整行末尾、下一条该是几号）。`从哪里` 是空的从头读。和日志对不上的交回空的，一条都不交：记的那一段没了、比记的短了、记的位置前面一个字节不是 `\n`。对得上的照旧自检，只是从中间读起的那一段，报坏了时的行号从记的位置数起，名字和第一条对不对不在那一段查。
- `read_range`（施工 V-37 中）：只读地读第 `从第几条` 到第 `到第几条` 条，照先后一块块交给 `每一块`，不攒成段、不攒成整份；读过 `到第几条` 当场停，后面的段不打开；`到第几条` 是空的读到最后，比 `从第几条` 小的什么都不交；`每一块` 交回 `Stop` 的不读下去。最后一段末尾的半行同 `read_events` 跳过、一个字节不写。不另存索引：一段的名字就是这一段第一条的序号、一行一条、序号连着（第 6 条第 5 款、第 4 款），第 s 条在名字不大于 s 的最后一段的第 `s − 名字 + 1` 行，数换行找到这一行的开头（定长的缓冲流过去，不解），这一行读出来要是第 s 条，从这里读起。对不上的退回从头读、s 以前的不交：名字不大于 s 的那一段是空的、行数不够（不是最后一段），那一行读不成、不是第 s 条；s 在第一段前面的（分叉出来的会话）也从头读。最后一段的整行都在 s 前面的（还没写到），什么都不交。**跳过的那一截不自检**（同 `read_marked`）：前面的行只数换行，不解、不查序号和段名，坏了不报；读起以后的照旧自检，报坏了的行号照那一段的开头数（同从头读）；退回从头读的照 `read_events` 整份自检。用它的（施工 V-37 下；跳过的不自检 2026-11-03 项目主人定）：订阅时补发的那一截，从 `after + 1` 读到 `upto`（`session/actor.md` 第 6 条，经日志的只读入口 `ReadLog::read_range`）；撤销撤掉压缩时读回第 `from` 条起的（`Store::events_from`，`session/actor.md`）；分叉出来的会话读回分叉点以前的底子，`from` 比第一条大的（`Base::events_from`；从第一条读的、整份要的那一处照旧 `read_segments`）；回合索引接上时一块块读底子到分叉点、读自己的整份（`memory.md` 第一条第 6 款，`Base::each`）。载入支线一块块读底子到分叉点、一块块喂内核，分叉时从头一块块读父会话到最后（施工 V-39 中，`session/fork.md`「底子不常驻」，从第一条读的照整份自检）。判官看的记录从头一块块读、边读边记，再读一遍、读回引用的那一条也照它（施工 V-39 上，`venues.md`「判官看的群聊记录」第 3 条；从第一条读的照整份自检）。`history` 从第一条一块块读、边读边挑，放早了再读一遍、整份读也照它（施工 V-45，`tools/history.md`「怎么走」第 3 条；从第一条读的照整份自检；经日志的只读入口 `ReadLog::read_range`，读别的会话的那一份也是）。和原来整份读了再挑的差别只在日志被外人改坏的时候：坏的地方在定位跳过的那一截（`从第几条` 以前）或者读过的终点以后，原来报坏了，现在不读、不报（补发不再回 `session_broken`、撤销读回不再停下会话；载入支线时父会话在分叉点以后、同一段里坏了的，原来读完那一段报坏了，施工 V-39 中起不读、不报）；下次打开这个会话照样整份自检、报出来。

3. 没有的：

   3. 改名成回收处里的那一个：一次改名，要么挪了、要么没挪。回收处里已经有同名的，改名出错，报错。
   4. 同步两头的上一层：`sessions/`、`trash/sessions/`。
   5. 会话目录不在的：写 `deleted_at` 时就出错（找不到），什么都没建。
2. 清（`purge`）：核心起来时清一次（`core.md`「起来的先后」第 14 条）。
   1. 回收处里名字合会话编号写法的才看，别的不是这里放的。回收处还没有的，什么都不做。

   3. `deleted_at` 读不了、写法不对的：留着，报出来（`Purged::failed`）。说不清它删了多久，不猜。

3. blob 不动：删会话以后没人引用的 blob 随存储的回收那一步（第五节，「还没有的」）。找回删了的会话以后再做：回收处里的文件留着，挪回去就是。

**13. 会话的附件落成文件**（`attachments.rs`，施工 3-9 六补；`keep(目录, 名字, 媒体类型, 字节)`）：剪贴板贴的、截图、远程的头传内容的附件没有本机路径，拷成会话目录 `attachments/` 下的一个文件。

1. 名字（`clean`）：路径分隔符、控制字符、Windows 不认的 `:*?"<>|` 换成 `_`；去掉两头的空格和点；截到 180 个字节以内，截在字的边界上，扩展名（带点不长过 16 个字节的）留着、截前面那一段，太长的整个截（鲁棒性 B-8：原来照字符数截 120 个，长中文名超过文件系统一个名字 255 字节的上限，存不进）；Windows 的保留名前面加 `_`；什么都不剩的叫 `attachment`。没有扩展名的照媒体类型斜杠后面那一段补上（只认字母、数字，不长过 15 个字符）。
2. 同名的内容一样的用它，不一样的接 ` (2)`、` (3)`，最多试到 1000。
3. 先在同一个目录里只许新建一个临时文件 `.<名字>.<进程号>-<计数>.tmp`（和生成的文件、配置文件的临时文件同一个写法；鲁棒性 B-7：原来名字是定的，崩溃留下一个，这个名字的附件就再也存不进），写进去、同步，再改名、同步目录。改名前那个名字被占了的，删掉临时文件，试下一个序号。

**14. 库的写前日志**（施工 V-28，`sqlite/idle.rs`、核心的 `wal.rs`；2026-10-31 项目主人批）：数据根里的 SQLite 库（会话列表的索引、用量汇总、汇率、唤醒表、检索库）都是 WAL，提交只往 `-wal` 后面追加；SQLite 自己攒到约 1000 页（约 4 MB）才做一次被动的检查点，做完也不截短。以前核心一直开着时 `-wal` 停在最高水位，被杀时没合回的那一截全留在数据根里（施工 V-27 量过：测具量完直接杀掉核心，一轮真任务以后数据根比好好退出的多出两百多 KB）。

1. 闲时合回：每个写连接开库时装一个提交钩子，提交一次记一下时刻；开库也算一次（上一回被杀留下的 `-wal` 一起合）。核心起来时起一个线程（一个进程一个），等到库有过提交、之后 2 秒（`wal::QUIET`，和请求的 `settle::QUIET` 一样长）再没有提交，把每个 `-wal` 不空的库照 `PRAGMA wal_checkpoint(TRUNCATE)` 合回主库、截成 0 字节，再回去等。照库最后一次写算，不照最后一个请求算（`heap.md` 的「安静下来还一次」）：一轮任务跑着的时候多半没有协议请求，会话照样一批批写索引、用量、回合库，照请求等的话任务跑完以前一直合不上。没有写的时候这个线程一直睡着、不定时醒；一阵写只叫醒它一次：它在等安静的时候，后来的提交只挪时刻、不叫。一轮任务里等模型的那几秒也算安静，那时合一次，几毫秒。
2. 合的时候拿那个库的写连接的锁，一次一个库：同一个库的写排在后面；检索库读的连接不等（`recall.md`，施工 V-14）。合在它自己的线程里做，不在异步运行时里。还有读在读老的一截（别的进程开着这个库读）的，能抄的抄回去、不截，算没合完，等下一阵写以后再合，不为它再起一次；合的时候忙等的时限临时设成 0、合完设回，不拿着写连接的锁干等读的那一方（审计 R3E-4：原来照开库默认的忙等一等 5 秒，这个库的写全排在后面）。
3. `journal_size_limit` 是 0：一直有写、等不到闲的，SQLite 自己做完被动检查点以后的下一次提交把 `-wal` 截到只剩这次提交写的那几页，不停在最高水位。
4. 崩溃安全不变：合是 SQLite 自己的检查点，先同步 `-wal`，抄回主库、同步主库，最后才截短；中途断电，下次开库照 `-wal` 接着合，不丢、不坏。日志是真相、库是派生的（`07-存储.md` 第六节）照旧：断电最多丢最后几次更新，库不坏，丢了的照日志补；唤醒表（真相）照旧 `synchronous = FULL`。
5. 被杀、断电时留在数据根里的：每个开着的库一个 `-shm`（32 KiB，SQLite 的共享内存索引，下次开库重用）、一个 `-wal`：闲下来以后被杀的是 0 字节，还没闲下来就被杀的是最后那一阵的提交，下次开库合回。好好退出时 SQLite 关上连接自己合回、删掉这两个（以前就这样）。
6. 运行日志（`log.md`）：合了的、没合完的一轮一行 `DEBUG wal checkpointed done=… busy=…`，都没有的不记；合不了的一个库一行 `WARN wal not checkpointed db=… error=…`，`db` 是哪一种库（`sessions`、`usage`、`rates`、`schedules`、`recall`），不写路径（路径里有人格的编号）；线程起不来的 `WARN wal checkpoints not started error=…`，库照旧用，`-wal` 照第 3 款缩、好好退出时照第 5 款删。
