## 技能和脚本

### 是什么

- **技能**：一个文件夹，里面一份 `SKILL.md`（开头几行写名字和一句说明，正文教她怎么做一类事），可以带参考资料、脚本。她平时只看到技能的名字和一句说明，用得上时自己读正文（`10-自带软件.md` 第三节：技能不单独设工具，用 `read` 读）。
- **脚本**：一个可执行文件，开头的注释写说明、参数，接进来就是她的一件工具（旧版 Miyu 的做法，实测好用：旧版出厂 17 个，番剧、天气、各家搜索、抖音下载这类）。

已经定了的（不在这里重定）：

- 技能、脚本和别的软件一样是装好的软件，不住在预设里；每个技能、每个脚本自动算一个功能，预设里能逐个开关（`16-人格与预设.md` Y7，`30-插件框架.md` 第三节）。
- 从哪来：软件包里的 `skills/<名字>/SKILL.md`、`scripts/<文件>`；本机自己放的在家目录里，同名的自己放的赢（`31-软件包.md` 第五节）。自己做出来的在做出它的那个预设里打开（16 第三节）。
- 技能的列表在 system 的「技能与知识库」那一段，排在核心和软件包的几行后面（`26-提示词.md` 第三节）；技能正文是她读进来的工具结果，压缩以后照「用过的技能」重建（`09-压缩.md` 第四节，`10-自带软件.md` 的 `file.read` 效果）。

### 技能

1. **写法**：照公开的 Agent Skills 格式（Anthropic 起的头，现在 Claude Code、Codex、Gemini CLI、Cursor 这些都认）：`SKILL.md` 开头的 YAML 写 `name`（小写字母、数字、`-`，和文件夹同名）、`description`（给模型看，英文，说清是什么、什么时候用，可以带人会说的几个中文触发词）；正文随意。给人看的名字、一句说明放在格式自带的 `metadata` 里（`display_name`、`summary` 算英文，`display_name_zh`、`summary_zh`、`_ja` 是另两种：格式的 `metadata` 只收字到字的表，语言写进键里，施工 X-13 下）：给模型的和给人的分开两格（旧版吃过一格两用的亏，设置页中英混杂）。别的格子照格式认、不用。
2. **她看到的**：system 里技能那一段一行一个：名字、一句说明、`SKILL.md` 的路径。只列这个会话的预设里开着的。说明超过 1024 个字的截断（格式的上限）。技能文件夹可以是链接（施工 X-37，2026-10-21 项目主人照别家的做法定：Codex 官方文档写明跟着链接走，Claude Code、opencode 社区里普遍用链接接技能）：指到目录的照它指到的真实位置记，写给她的也是真实的路径（沙盒只放开那一个文件夹，链接本身在藏着的数据根里）；指到文件的不算；断了的、绕回自己的跳过，`miyu check` 照「跳过」报原因。真实位置落在数据根里的，只认这个账号家目录的 `scripts`、`skills`、`commands`、`packages` 下面，落在 `system/`、`state/`、别的账号下的不认，`miyu check` 报 `skill_link_outside`、说指到了哪一片（不收窄的话一个链接就能把 `system/` 下的本机令牌、密钥文件拉进她读得到的地方）；技能文件夹所在的 `skills/` 本身是链接的同样照真实位置查。删链接成的技能（`skill.remove`）只挪链接本身，不碰它指到的文件夹。
3. **读**：她用 `read` 读那个路径，读技能文件夹里别的文件（参考资料）也一样。技能文件夹在数据根里，文件工具平时碰不到（`11-权限与沙盒.md`），开着的技能文件夹单独放开只读（`session/guard.md` 加一条），不问人。技能里带的脚本照她跑命令的规矩跑（沙盒里能读这个文件夹）。
4. **用过的技能**：她读了某个技能的 `SKILL.md`，执行器在效果里记上（`10-自带软件.md` 的 `file.read`），压缩以后照它重读回来（09 第四节）。
5. **会话中途列表变了**（装了、卸了、她自己写了一个）：见「定了的」第 2 条。

### 脚本

1. **写法**：照旧版的开头注释，旧版的 17 个照搬就能用：

   ```python
   #!/usr/bin/env python3
   # Display name: Bangumi
   # 显示名称：番剧信息
   # Description: Bangumi airing calendar and subjects: what airs today, search, details.
   # 描述：查番组计划的放送日历与条目。
   # Timeout: 60
   # Parameters:
   # { "type": "object", "properties": { "query": { "type": "string" } } }
   ```

   `Description` 给模型（英文），`描述`、`显示名称` 给人（双槽，同技能；`显示名称`、`Display name` 也是时间线上这件工具的名字，派它那一刻记进结果，施工 9-8 六补）；`Parameters` 是参数的 JSON Schema，没写的当没有参数；`Timeout` 是秒，没写的 60；`Need load: yes` 和没写的要先加载，`no` 全量（`25-工具加载.md` W9，施工 L-1；没写的先加载是施工 L-3，2026-10-20 项目主人改），个人设置的 `loading.tools.<工具名>` 盖过它（头经 `tool.set_loading` 改，`script.list` 的 `need_load.by` 说是来处还是人改的，施工 X-27）。`Clicall: yes` 的脚本里能经 `miyu call` 调，没写的、`no` 的不能（施工 M-2，2026-10-22 三补改成没写的不能，设计 `39-脚本调工具.md` 第三节），写错的同 `Need load`；个人设置的 `clicall.tools.<工具名>` 盖过它。`Venues` 定给哪种会话（施工 X-43，主会话 2026-10-22 审过）：`local`、`private`、`group` 里的几个，逗号隔开；只有英文的键名（同 `Timeout` 这些给机器读的格），查法和清单的 `venues` 同一份（`miyu_config::package::venues_fit`）；没写的哪种会话都有。写错的（空的、不认识的、重了的）整个脚本跳过，`miyu check` 照 `script_skipped` 报。写了的，工具照它给哪种会话（`Tool::venues`，同扩展、MCP 的工具），不在里面的会话，工具面上没有它：**这才是门**。开头是文件开头连成一段的注释，第一行不是注释的地方就完：开头写完要空一行再写别的注释，不然说明里一句「Timeout: …」会被当成开头读。全局开关 `features.script-<工具名>`、`features.skill-<名字>`（`presets.md`「全局开关」）在头的三页上改，预设没写的照它。技能没有加载方式：工具面上只有技能目录，用到才读正文（`25-工具加载.md` W9）。
2. **她看到的**：一件工具，名字是文件名（去掉扩展名，不合 `[A-Za-z0-9_-]` 的换成 `_`），说明、参数照开头注释。说明、参数多大都收，不按大小挡（2026-10-12 项目主人定）。开头写错的、同名被压掉的不登记，`miyu check` 报出来。脚本可以是链接（施工 X-37，同技能）：指到文件的照它指到的读开头、名字照链接的文件名，指到目录的不算（原来收了、读的时候才报错）；断了的、绕回自己的跳过；真实位置落在数据根里别处的跳过，`miyu check` 报 `script_link_outside`。

128 KiB、Windows 上 32767 个字，超了起都起不来，长的只在标准输入里）；工作目录是会话的工作区；另给它一个能写缓存的目录（`MIYU_SCRIPT_CACHE_DIR`，在系统的临时目录下，能丢的放这里）。持久的状态目录（施工 X-44，主会话 2026-10-22 审过）：`MIYU_SCRIPT_STATE_DIR` 是
