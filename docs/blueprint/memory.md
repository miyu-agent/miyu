## 记忆

### 是什么

她跨会话、压缩以后还想得起来的那一部分（`17-记忆.md`）。它是一个软件包，编号 `memory`，给人看的名字叫「人格记忆」（`core/human` 的 `software/memory`，英文 Persona memory、日文 ペルソナの記憶；2026-10-08 项目主人定）。开不开照预设，默认开；不带人格的会话不生效（17 L17）。四样东西：

- **回合索引**（就是日记）：用这个人格的会话里，人开的每一个回合（人的话加她最后的回答）照日志派生成一条，能搜。不另存：撤销、恢复、删会话自动跟着走。
- **记下的记忆**：她当场记的、后台整理出来的，分四类，只追加，带出处和听众。真相是记忆日志里的 `ext.memory.*` 事件。
- **想起来**：三层。常驻的记忆摘要（第一轮、压缩以后注入一次）、她的工具（搜、记、忘）、每轮的联想（过门槛的两三条，R-8 单独一步）。
- **整理**：会话闲了几分钟、缓存还热的时候，对新的一段发一次抽取请求；隔一段时间合并一次，重写摘要。

### 对外的样子

**范围**（`17-记忆.md` L2、L3，R-3 下）：会话开局时定，之后不改。三种：`persona`（跟着人格）、`session`（只在这个会话里）、`off`（不召回也不记）。

**换了人格**（施工 P-13，`16-人格与预设.md` Y5）：会话中途换了人格，范围不变；跟着人格的，从换的那一条 `session.policy_changed`（带 `persona`）起算新人格那一间的：回合索引把那以前的几轮当底子（只认还没回的人话，不在新的一间记），抽取从那一条以后抽，换之前还没抽的不再抽；以前记的留在原来那一间，不搬。快照换上的那个回合开始当场挪（`Store::rewire`、记忆的端口、`Handle` 的那一间），载入、补齐旧会话照日志里最近一条换成这个人格的算（`memory/recast.rs`）。`session` 的那一间、`off` 的不受影响。

**无人格的那一间**（施工 P-12，2026-10-17 项目主人定，改掉 P-4 上的「无人格记忆不生效」）：无人格的会话照样跟着「人格」走，人格编号写 `_none`（`miyu_store::recall::NO_PERSONA`；人格编号以小写字母开头，撞不上），单独一间（`modules/memory/_none/`、`turns-_none.db`、`memory-_none.db`），无人格的会话共用它，和每个人格的都分开。无人格不是人格：人格列表里没有它；`memory.*`、流 `memory` 的 `persona` 写 `_none` 的就是它（施工 R-12 再补，网页的记忆页没有会话可借），照会话找（写 `session`）的也找得到。P-12 以前造的无人格会话快照里范围是 `off`，载入照快照，照旧不记。

- 默认照人格的 `persona.toml` 的 `[memory] scope`（`persona` 或 `session`；不写是 `persona`，出厂的软件工程师不写；别的值照人格的文件写错了报，`personas.md`）。开会话时能换：`session.create` 多一格 `memory`（`persona`、`session`、`off`，不写照人格的；别的值 `bad_params`）；`miyu ask --no-memory` 就是 `off`。人格与预设走查 E1（2026-10-07）。
- 记进策略快照的 `memory`（开局定、之后不改，正是快照管的；内核不认识「记忆」这个词，不进 `session.created`）。新造的都写明，`persona` 也写；以前造的快照里没有的照 `persona`，字节不变；认不出的照 `off`（宁可不记，不往不知道的地方写）。载入时照快照。
- 子代理一律 `off`（17 第二节，走查 C5）：造子会话时不管交的是什么，快照照写 `off`；以前造的子会话快照里没有这一格，载入时照有没有父会话判。分叉出来的支线（C-8，群里第二个人 @ 她时分的）不算子代理，照父会话的范围（施工 R-13 三补，`memory::subagent`）。派的时候能指定，随 P-2（下）。开不开记忆归预设（走查 E2，施工 P-2 中，`presets.md`）：预设没开 `memory` 的会话，范围一律 `off`，不管 `session.create` 的 `memory` 写了什么；三件工具不在工具面上，回合开始不召回。
- `off`：不接回合索引，工具面上没有三件工具（`miyu ask --no-memory` 的会话前缀因此少 285 个 token）。
- 每个范围一处记忆（一个「房间」）：
  - `persona`：数据根的 `modules/memory/<人格>/` 的记忆日志，`index/recall/turns-<人格>.db`、`memory-<人格>.db`。
  - `session`：会话自己的目录 `sessions/<会话>/memory/` 下：`log/` 记忆日志，`turns.db`、`memory.db`。删会话、进回收处、从回收处恢复都跟着目录走，不另写一行。17 第七节原来写的是「记在这个会话自己的日志里」：会话日志只有会话 actor 一个写的人，工具绕不过它，所以单开一处，放在会话目录里（2026-10-07 施工 R-3 下定）。
- 谁在听照会话关不关定（第九条，R-13 上），记忆放在哪照房间：两样分开。

### 怎么走

**一、回合索引**（R-2 上、下）

1. **哪些回合**：主会话（没有父会话）和分叉出来的支线（施工 R-13 三补：支线自己的回合照支线的编号进，底子里父会话的回合不再记；支线那一轮的触发在底子里的，读底子认得那几句人话，`TurnFeed::primed_on`）里，`turn.started` 的 `trigger` 指的那条 `message.user` 的 `by` 是人（`person`、`external`）的回合；本机的、场所的（群、通讯平台的私聊）都收（R-13 下）。场所会话的回合库里另记一笔它在哪个场所（`places`，`recall.md`「库的结构」）；搜以前的对话哪儿都搜得到全部（R-29，第九条；R-13 下到 R-29 之间一个场所里只搜得到这个场所的）。原来（施工 R-2 再补到 R-13 下之间）场所会话不收、载入时拿掉：那时回合库的条目还没有场所。子代理的会话、别的 harness、别的会话、子代理发来的话开的，回报、通知叫醒的，重启以后接着干的，手动压缩、清空单开的（没有 `trigger`），都不收。群里照记下的几条开的一轮（`session.respond`，`turn.started` 带 `triggers`；被 @ 叫到的、她自己插话的都是）：那几条人话一行一句都进，并进来的（`turn.joined`）接在后面；她这一轮没开口的不收，那是旁听（R-13 再补，2026-10-12 项目主人：「把回复的那次记录进去就行，无论是插话还是直接触发」；原来只收了 `trigger` 指的最后一条，并进来的丢了）。
2. **一条的字**：触发的那句人话（它的字块照先后用换行连起来、去掉前后空白），空一行，她这一轮最后一条字不空的回复（字块连起来、去掉前后空白）。只有一边有字的只写那一边；两边都没字的（只发了图、她一句没说）不收。群里照记下的几条开的一轮见第 1 款（几条一行一句、并进来的接在后面，R-13 再补）；别的回合中途进来、没有触发哪一轮的人话不算进去（R-2 先这样，以后要再说）。时刻是 `turn.started` 的。
3. **什么时候收**：`turn.ended` 落了盘（哪种原因都收：被打断的也是聊过的）。键是 `会话编号/回合编号`（回合编号就是 `turn.started` 的序号）。
4. **放在哪**：一个人格一份检索库（`recall.md`）：`index/recall/turns-<人格>.db`。人格照会话的策略快照（`Snapshot.persona`）。核心一份登记（`RecallIndexes`），用到哪一份才开、开了一直开着；新造的会话到第一次真要写时才开，造会话不多一次开库、建表、同步。范围是 `session` 的放在会话目录里，`off` 的不接（「范围」）。
5. **增量**（`miyu_recall::TurnFeed`，纯逻辑）：会话 actor 每落一批（`Indexed`，照 `store/index.md` 第二条的那一路），把这一批一条条交给它，它交回要放进的、要拿掉的；`turn.reverted` 的那几轮拿掉；`turn.unreverted` 的那几轮它不记得字（省内存，只记还没结束的那一轮），交回「要读回」，执行器把这个会话的日志整份读一遍，照全部事件算出那几轮的字再放进去（恢复很少见）。撤销的每一轮（人开的、不是人开的都算）另埋一块墓碑，恢复时 `TurnFeed` 交 `Restored`，揭掉（R-3 上，第二条第 4 款）。
6. **照到哪**：检索库另记每个来源照到了哪个序号（`marks`），和这一批的放进、拿掉在同一个事务里写；一批里没有要改的不写（每落一批少写一次库），照到的位置落在后面不要紧，载入时多铺一截、交回的还是空的。载入会话时内核本来就拿到整份事件：照它们先把 `TurnFeed` 的状态铺回来，照到的以后的才放进库，补上崩了、更新失败落下的那一截；一条都没照过的会话就是整份补。
7. **删会话**（进回收处）：先埋整个会话的墓碑 `会话编号/`，再拿掉各个回合库里这个会话的全部（键以 `会话编号/` 开头的）和它的 `marks`（R-2 下改成先埋：埋了以后补进来的一批写不进，拿掉以后不会又多出来）。
8. **出错**：更新、补、拿掉失败，记一行 `WARN memory index not updated session=… error=…`，会话照常；照到的位置没往前挪，下次载入照日志补。库用不了（`Opened::Unusable`）的，什么都不写。回合库这一回第一次开记一行：新建的 `INFO memory index created room_kind=… room_id=…`，重建的、用不了的 `WARN memory index rebuilt`、`memory index unusable`（带 `reason`、`error`）；哪一间写种类 `room_kind`（`persona`、`session`）和照数据根的盐算的短号 `room_id`，不写人格名、会话编号（施工 LG-1 下，`log.md`「怎么走」第 7 条第 6 款；R-2 下起由登记记，开库的四处都算）。
9. **补齐旧会话**（R-2 下）：人格那一间的回合库这一回是新建的、重建过的（`Opened::Created`、`Rebuilt`），起一个后台线程，照会话一个个补，做的时候搜得到多少算多少。在跑的补齐登记着，`Memory::settle`（删会话以前、测试里）连它们一起等（R-28）：不等的话删了的会话会被补回来，载入时也会当成已经补过。
   - 什么时候：回合库的登记多一样「第一次开的时候告诉谁」（`RecallIndexes::when_opened`），`Memory::new` 登记它；开库的四处（会话写回合、搜以前的对话、判出处活不活、删会话）都从登记过，谁先开都算。会话那一间不补：只有它自己，载入时本来就整份补。
   - 补哪些：读会话的日志，照最近一次换上的快照，和载入时一样判（第 4 款）：主会话、范围是 `persona`、人格是这一间的，照第 6 款补（照到的位置以后的补，一条都没照过的整份补）。在跑的会话照样补：补的一批落后的检索库不写（`recall.md` 的 `apply`），不会把撤销了的又放回去。
   - 出错：一个会话读不了、快照取不出，记一行 `WARN memory index not backfilled session=… error=…`，跳过，接着补别的；补完记一行 `INFO memory index backfilled room_kind=… room_id=… sessions=…`（补了几个会话）。
   - 还没有的：从回收处恢复的会话补回回合库、揭掉整个会话的墓碑（记忆的出处照目录判，恢复了就算活的，不用等这一步），随会话从回收处恢复那一步。

2. **这一段从会话日志取**（不从内核手里的历史取，2026-10-09 核心的主会话定）：内核手里的历史只有检查点以后的，两次抽取之间压缩过的话那几轮就不在里面。所以闹钟响了，在阻塞线程里读记忆日志里这个会话抽到了哪（`ext.memory.extracted` 最大的 `upto`，底账 `MemoryBook::extracted`）和会话日志（`Store::dir`），送回 actor；actor 照旧核对（记忆还开着、还是那个闹钟或者没有一次在路上），把这一刻的组装器（`Session::assembler`）、群聊近况的预算、称呼、配置拿好，在阻塞线程里拼一份留着一切的历史（施工 PERF-4，`actor/extract/planned.rs`：原来这一段在 actor 上同步做，一万多条事件的大会话要几毫秒到十几毫秒，下一轮的回合开头排在后面；现在就整理那一路照旧在 actor 上，同一个函数）（`History::whole`，压缩替代掉的也在、撤销照算），交给这个会话的组装器渲染上次抽到以后的几段话（`Session::spoken_in`，取法和回顾的请求同一份：人这边的话照主请求的写法，她每一轮最后一条有正文的回答），再看这一段她调过哪些工具（`History::called_since`，同一口径：撤掉的回合两边都不算）。读的时候来了新一轮，这一次作废（不等闲的那一次不作废，只取到读的那一刻结束了的最后一轮，第 1 款）。压缩、重启都不丢；一直不闲的会话照第 1 款攒够了轮、等够了时候也抽（E-5 以前只是晚抽，实测一下午一次都没抽）。
   - **只读上次读到以后那一截**（施工 E-5 补，`memory/extract/prefix.rs`）：一直热闹的会话每 20 轮抽一次，原来每次整份读会话日志（量尺的大会话近十兆、几十毫秒），在 2 核的机器上和正在跑的回合抢 CPU，`一次请求的投影：开着记忆的大会话` 的 p95 顶过 5 毫秒的闸。拼这一段除了上次抽到以后的事件，只要更早的日志里认出来的几样：名字对着平台编号、她被叫过的名字、最后的群名（`Voices`）；渲染上次抽到以后的话照的是这几条自己，派出去的任务只管子代理、别的会话发来的话怎么包，那些话本来不进这一段（第五条）。会话每落一批（`actor/store.rs`），记忆的端口先把这一批折进来（`Calls::heard`），落完拿日志照到哪（`Store::mark`）：这一批里有回合结束的，记一处（日志的位置和那时折出来的几样，最多 64 处，旧的先丢）。抽的时候挑最后一处在上次抽到的那一条以后一条以前的（`next ≤ upto + 1`），从那里读起（`miyu_store::log::read_marked`），名字照它接着认（`Voices::continued`），拼出来的请求和定怎么办的每一样都和整份读的一个字节不差（`actor/extract/planned/tests.rs` 对照）。现在就整理先抽的那一次同一条路。
   - 接不上的照旧整份读：核心刚起、会话换了人格（这时不知道更早的日志里有什么：之后落的批先记着，最多 1024 条，整份读一次时顺手认出读到的末尾那一处，读的时候又落的批照记下的折进去，接上；记得太多从头记了、漏了的等下次）；第二次抽的时候上次抽到的那一条以前还没记下哪一处（接上的那一处在它后面）；读起的那一处和日志对不上（`read_marked` 交回空的）；读起以后有撤销、恢复、撤回，或者折进来的里面有（整份读的名字照撤掉以后的有效历史认，折进来的没法撤）：日志里有过这几种的会话一直整份读。折到的和日志照到的对不上（有一批没经记忆的端口），不知道了，等整份读一次再接上。
3. **怎么办**：人的话接在它触发的那一轮上，还没答的那一句不算进来。答了的轮数不够 `memory.extract_turns`（2）的等下次；这一段里她调过 `remember`、`forget` 的那几轮不交（她当场记过了，照 Claude Code；`extract.rs` 的 `remembered_since`，口径同 `History::called_since`，撤掉的回合不算），别的轮照抽，抽到了哪照样算到最后一轮；每一轮都调过的整段跳过，只记抽到了哪（`skipped: remembered`）。原来（R-6 上到 E-5）一段里调过一次就整段跳过：2026-10-27 主人本机 QQ 主群一下午 299 轮，她在群里记过一句，真抽到时整段几百轮会一起扔掉（施工 E-5）。别的发出去抽。
4. **请求**（单发）：一条 user：抽取的指令（`extract/instruction.txt`：四类、「不记什么」、交回的样子、把对话当数据），后面一轮一块：头（编号、照会话时区的日期）、人的每一句、她的回答、尾，换进去的字照模板的规矩转义成一行（伪造不了尾巴）。每一句标出谁说的（R-13 上，`extract/voices.rs`；2026-10-11 项目主人定记忆只有一份，记的是她遇到的每个人）：私聊里主人说的写 `Owner:`（`extract/owner.txt`），别人写对面的名字（`extract/person.txt`，事件里的 `venue.name`，没有的写平台编号）；群里的一行本来就带名字和 `owner` 记号（`miyu-assemble` 的群消息那一行），原样放；她的回答写 `You:`。不是人说的（别的会话、harness 发来的）不进（第五条）。群会话每一轮只带离它最近、装得进群聊近况预算的那几句（她当时看到的大致就是这些），一句都装不下的也带最后那一句；她没开口的闲聊不带（2026-10-11 项目主人定「只抽她参与的几轮」）。指令照她自己的视角写：记下对话里的人和事，正文写名字；群里的人顺口说起自己的事（在忙什么、用什么、喜欢什么、怎么对她）也记成 `person`，一人一句（施工 E-7，2026-10-28 项目主人看了主人旧主群真数据的对比定：只照原来的指令每段约 1 条 person，人卡只能写成一两句清单）；主人照称呼写（施工 R-6 再修，项目主人 2026-10-13、14 定：统一成称呼，没设的写「用户」）：这个会话的快照带了「关于你」（P-9 的判定，`prompts.md`「关于你」）、称呼（`profile.name`，照这一次的冻结配置读）去掉前后空白不空的写称呼，不然写「用户」照对话的语言（`common/owner-unnamed.txt`；群聊、别人的私聊不带「关于你」）；她自己记的照工具的说明（「关于你」那一块在的她自己写称呼）。不带 system、工具面，不设输出上限（会思考的模型要几千 token 想，2026-10-09 量过）。最多 32 KiB：放不下的照先后取最老的几轮，`upto` 记到取到的最后一轮，抽成了马上接着抽剩下的；一轮自己就放不下的留头尾、截中间（`extract/excerpted.txt`）照样抽，`upto` 照样往前走，不卡在一轮上。经一次性入口发 `memory.organizer`（没写的照 `models.chat`），用途 `memory`，记成用量（`usage.oneshot`），默认不设花费上限（2026-10-07 项目主人定）。这一段开始以后（第一句话的时刻起）作废的、改成新版本的（听众合、没清掉的，新的在前最多 20 条），接在这一段后面：空一行、一句 `extract/dropped.txt`（这些后来忘了、改了，对话里说的已经过时，别再记），下面一条一行照 `memory_search/memory.txt`；一条都没有的不加，请求一字不变（施工 R-6 修，验收手册实测：她照摘要复述了一条，人在别的会话里作废了它，两分钟后这一段被抽，又记了回来；2026-10-13 开发端点实测，不加这一块 5 次抽回 5 次，加了 10 次 0 次，同一段里新的事照样记）。作废的时刻底账记着（`Entry::retired_at`，恢复了的清掉），改掉的照新版本记下的时刻；清空以后还没抽的那几段不在这里管。
5. **交回**：一个 JSON 对象 `{"memories": [{"class", "text", "turn", "about", "who", "people"}]}`，零条是常态（`who` 只有 `person` 那一类写：那个人在这一段里的名字，E-1 上；`people` 只有 `episode` 写：涉及的几个人在这一段里的名字，去掉空白、去重、最多 8 个，不是列表的当没写，E-1 修四）。从第一个 `{` 到最后一个 `}` 取；读不成的整次算失败；一条不合的（类不在四类里、正文空的或超过 120 字、`turn` 不是这一段里的一轮）丢掉，别的照收；`about` 不是 `YYYY-MM-DD` 的当没写（`miyu_recall::extract`）。
6. **记下**：每条记成 `ext.memory.saved`，`by` 是记忆模块（`By::Module`，编号 `memory`），出处是那一轮，听众、场所照谁在听写（第九条第 4 款），群名照那一轮那时的（`place`，E-4 上），`about` 照它写的；`person` 的 `who` 照这一段的说话人换成平台编号（`memory/extract/voices.rs` 的 `names`：名字、平台编号对着他的平台编号；说的是主人的——`Owner`、主人的称呼、主人在群里的名字——改记成 `user`、不写是谁；对不上的照名字留着；`extract.rs` 的 `place_people`，E-1 上；说的是她自己的——`who` 是这一间她的名字，人格的名字几种语言都算、不分大小写，加上这一段里她在场所里被叫过的 `venue.my_name`（E-1 修三）——先挑出来改记成 `episode`、不写是谁，不照名字认，群友的群名片和她同名的也不把她的事记到这个人头上，`memory/her.rs`，E-1 修）。E-1 修四（主人旧主群的真数据实测查出）：名字对不上谁的，是这一段里恰好一个说话人名字的开头（去掉前后空白、不分大小写、至少 2 个字；群名片带着一长串说明，模型只写了前半截）就认成他，对上几个不同的人、对上平台编号本身、对上她的名字的不认；`episode` 的 `people` 照同一个认法换成平台编号，她自己、主人去掉，对不上的照名字；`user` 那一类照她的名字起头的（「我是 Miyu」「Miyu 没有禁言权」，模型照 `You` 写成了第一人称）改记成 `episode`——只看起头，别的写法靠指令（指令另写清：名字里的说明是名字的一部分，关于某个认识的人的事是 `person` 不是 `reference`，她自己的事记 `episode`，不记琐事）；代码在 `memory/extract/place.rs`。E-1 修五（真数据复跑查出是谁带着看不见的双向格式字符、模型在名字后面加了「（QQ 群昵称）」这种注释，都没认成编号、单开了按名字的卡）：认之前先清洗，依次试——去掉控制字符、双向格式字符、零宽字符的；再去掉末尾的省略号、从最后一个左括号起整段去掉的（括号注释、没写完的括号）——每种先照清洗过的全名认（不分大小写），再照前半截认；群名片也照去掉看不见的字以后比。都对不上的照名字留，只去看不见的字、括号照原样（括号是名字自己一部分的不受影响）。记完再记一条 `ext.memory.extracted`（会话、`upto`、`count`）。不去重：合并那一步做（R-7）。中途写不进的，下次重抽这一段（候选可能重一次）。抽完以后人撤掉了那一轮的，抽到的不收回（已知，这一步不管；照第二条第 4 款，出处那一轮撤掉了的本来就不给看）。
7. **遮 key**：发出去以前，这一段里配置引用的密钥的原文、常见的 key 写法（`resources/core/memory/secrets.toml`：几种前缀、前缀后面至少几个字符）换成 `[REDACTED]`；交回的候选再遮一遍（`miyu_recall::redact`）。R-6 下的 fork 式发的前缀和会话已经发给同一家的一样，不改（改了缓存就不中了），只遮交回来的。

9. **日志**（目标 `miyu::session`，带会话编号）：开始 `INFO memory extraction started session=… turns=…`，记下了 `INFO memory extracted session=… count=… took_ms=…`；一次性入口那一行 `model call purpose=memory` 照旧；记不进的 `WARN memory extraction not recorded`；核心起来时字、key 的写法读不出来的 `WARN memory extraction unavailable`，这个核心不抽。
10. **fork 式暂不做**（2026-10-09 项目主人定，原来 10-07 定的「两种照便宜的挑」改成只用单发）：单发只带新的这一段（几百到约 8000 token），能交给便宜的模型（施工 Q-2 起照 `normal` 池），出处的轮次准；fork 式要带整个上下文（照读缓存价，但常有两万到十几万 token），只能照会话自己的模型，模型看不到轮号、出处只能归到这一段的每一轮。照 2026-10-09 量的数，大多数会话单发更便宜。重开的条件：照用量看抽取的费用成了问题（`usage.query` 照用途 `memory` 分得出来）。

**七、合并**（R-7 上做了合并本身，2026-10-10；有了摘要以后常驻那一块交什么随 R-7 下，第三条）

1. **什么时候**：一间（房间）一把锁（`memory/merge.rs` 的 `Merges`）。照主人那边合（R-13 上，`Keeper::as_owner`）：不管是哪个会话抽完以后起的、人叫的，合的都是全部，写一份摘要。每次抽取记下以后（第六条第 6 款，整段跳过的也算）看一眼：这一间上次合并以后有新记的（上次合到的那一条以后、现在算数、听众合、出处活着的；合并自己改出来的不算：`by` 是记忆模块、写了 `replaces` 的）；那以后抽过的会话（`ext.memory.extracted` 里不同的会话）够 `memory.merge_sessions`（起点 5）；离上次合并（那一条 `ext.memory.merged` 的时刻）过了 `memory.merge_every`（起点 24 小时；没合并过的不看时间）。都够了就在后台合，不挡会话；同一间同一时刻只有一个；核心退了的这一回不合，下次抽完再看。
2. **交什么**：一条 user，不带 system、工具面：指令（`software/memory/merge/instruction.txt`）在前，空一行是现在的摘要（`summary.txt`，没有的是 `none.txt`），空一行是新记的那一块（`new.txt` 的标题，下面一条一行，旧的在前），有相关的旧记忆再空一行接那一块（`related.txt`）。摘要从主人写起，主人照配置里的称呼写、没设的写「用户」（施工 R-6 再修；不照起合并的会话判：一间一份摘要，照会话判会在两种写法之间来回翻；摘要只在主人那边交，第三条）。每条新记的照关键词和意思（有向量那一路的，问句等 1 秒）搜，不算新记的、已经交进去的，最多 3 条；一条一行照 `memory_search` 的写法（`m12 feedback 2026-10-08: …`，日期照会话的时区，换进去的字转义成一行）。最多 32 KiB：新记的照先后一条条连着它的相关的加，放不下的停（至少交一条），合完马上接着合剩下的（放不下的、合着的时候又记的；不再看会话数、间隔），没有了才停。发出去以前遮 key（同第六条第 7 款）。不交整个库。
3. **交回**：一个 JSON 对象 `{"revised": [{"id", "text"}], "retired": [{"id", "kind", "by", "why"}], "summary": "…"}`。作废的照规矩核对（施工 R-16，2026-10-19 项目主人定「按照新的做」：模型说的是申请，宁可不删）：`kind` 是 `outdated`（被后记的取代）、`repeat`（和另一条说的一样）、`worthless`（以后用不着：一次性的请求、转眼就过的状态、测试、客套话），没写、写了别的不作废；`outdated`、`repeat` 的 `by` 要是这一次交进去的另一条，`outdated` 的 `by` 要比它记得晚（编号大，不然是弄反了）；`by` 那一条也要作废的，`outdated` 的不作废它，`repeat` 互相指着的只作废先记的那一条。虚构的林夏上量的（`memory/eval.md`「整理」）：不核对时第一次整理误删 12 条，核对以后 0 条。后记的只推翻前一条的一部分的，指令要她改写前一条、去掉过时的那一件、留下别的，不整条作废（施工 E-1 修二，2026-10-26 实测「住东京、喜欢拍照、在 Rust 群认识」因搬家整条作废，没过时的也丢了；只在指令里：哪几件过时核心核对不了）。照规矩取（`miyu_recall::merge`）：从第一个 `{` 到最后一个 `}`，读不成对象的、两个列表写了不是列表的、摘要写了不是字的整次失败；没写的列表当空的；编号不是这一次交进去的、正文空的或超过 120 字的、`why` 空的那一条丢掉，别的照收；同一条写了两次的照头一次，又改又作废的照作废；摘要去掉前后空白，空的当没写（不换掉现在的），超过 600 字的截在最后一个句号、问号、叹号、换行上，一句都放不下的照字截。只交回这些，不给工具：真相是事件，交回几条就够（Codex 给合并的代理开 shell 再关进沙盒，我们不需要）。
4. **怎么落**（`memory/merge/land.rs`）：落的时候还算数、听众合、出处活着的才落。改的记成 `ext.memory.saved`（`replaces` 那一条，类、出处、听众、`about` 照旧的，`by` 是记忆模块；和原文一样的不记）；作废的记成 `ext.memory.retired`（`why` 照它写的，`kind`、`kept` 照核对过的种类和 `by`，R-17）；有摘要的记 `ext.memory.summary`（`text`、`upto`）；最后记 `ext.memory.merged`（`upto` 是交进去的新记的里最后那一条，`given`、`revised`、`retired`）。改的、作废的为什么、摘要再遮一遍 key。真相是事件，只追加：作废的、改掉的原文还在，`memory.list` 带 `forgotten` 看得到。
5. **模型**：照旁路请求登记 `memory/organize` 的档位 `normal`（施工 Q-2，设计 43，`models.md`「旁路请求」）：`normal` 池有成员的发给池里的，池是空的、池里换遍了还没答成的退到后备的模型——抽取是被抽的那个会话这一刻的引用，合并、写关键词没有会话，照 `models.chat`；整理会话钉 `@normal`，池是空的照 `models.chat`，全在冷却照主请求报。原来是 `memory.organizer`（默认 `models.chat`，2026-10-07 项目主人定；旧版最便宜那一挡把整理做坏了），Q-2 去掉。经一次性入口，用途 `memory`，记成用量；不设输出上限。
6. **出错**：发不出去、交回读不成的不动真相，下次抽完再来；每一次都记一条 `ext.memory.merge_failed`（`upto`、`why`、`tries`，R-17）；同一间连着 3 次不成的另记一条 `ext.memory.merged`（`failed: true`，`upto` 是这一次交进去的最后那一条），跳过这一批。成了一次、跳过一次都重新数：这一批从哪起只在这两种时候变；不照这一批合到哪认，新记的一直在加，那样永远到不了三次。失败的次数记在核心里，核心重起来重新数。记忆日志写不进的记一行，下次再来。
7. **日志**（目标 `miyu::session`，带房间的种类和短号，施工 LG-1 下）：一趟合（合到没有剩下的）开始 `INFO memory merging started room_kind=… room_id=… left=… manual=…`，合完 `INFO memory merging ended room_kind=… room_id=… batches=… given=… revised=… retired=… took_ms=…`（R-17）；每一批开始 `INFO memory merge started room_kind=… room_id=… given=… fresh=…`，记下了 `INFO memory merged room_kind=… room_id=… revised=… retired=… took_ms=…`；没成 `WARN memory merge failed room_kind=… room_id=… tries=… error=…`，搜相关的出错 `WARN memory merge search failed`，写不进 `WARN memory merge not recorded`。
8. **摘要什么时候不算数**（R-7 下，忘了就是忘了）：摘要写下以后，人或者她改了、作废了、人恢复了（R-12 下）它合进去的一条（编号不大于摘要的 `upto`；合并自己的改、作废记在摘要前面，不算），或者清空了（整间、一个会话的都算），这一份就不算了：常驻的那一块照没有摘要的样子只列条目（第三条第 2 款），下一次合并照没合并过的从头来（现在算数的都当新记的，摘要照还没有；放不下的分几次，每次接着上一次的摘要写）。底账记着（`MemoryBook::summary`、`summary_stale`），不另写事件。之后才记的、作废之后才记的不碍事。
9. **现在就整理**（R-7 补，2026-10-10 项目主人定：命令叫 `/dream`、界面写「整理记忆」、回执只报数字）：人叫的（`memory.dream`、`/dream`、`miyu memory dream`）不看 `memory.merge_sessions`、`memory.merge_every`，现在就合，放不下的接着合完，交回几样数（`Dreamed`）：交进去几条（新记的加相关的，几次加起来）、改了几条、作废几条、摘要换没换；没有要整理的四样都是零、不发请求。带会话的（`/dream`、带 `session` 的 `memory.dream`，`Handle::dream`）先叫那个会话把还没抽的那一段抽了：同闹钟响了的那一条路（第六条第 2、3 款），只是不等闲、答了一轮就够，她调过 `remember`、`forget` 的照样跳过，放不下 32 KiB 的只抽头一截（剩下的照平常等闲了再抽）；那个会话正忙、正在抽的不抽。抽完了、没得抽、抽不成的都接着合。不带会话的（`Keeper::dream`）直接合。同一间一把锁照旧：定时的那一次在合、别人先叫了的回忙（`memory_busy`），不排队。锁是放下就放的（`merge/merges.rs` 的 `Running`，R-30）：半路被丢下、panic 了也放；人叫的那一趟在自己的任务里跑，叫的那一头半路不等了（连接断了、网页关了）照样合完、放锁。请求、落法、日志同第 2 到 7 款；失败照第 6 款数，回 `dream_failed`，之前合成的几次照样记下了。经一次性入口发 `memory.organizer`；日期带会话的照会话的时区，不带的照核心这台机器的时区。
10. **留痕**（R-17，2026-10-19 项目主人定：照仿 Linux 的原则，一切皆文件、日志式；头要能画进度、列出这次删了什么记了什么改了什么）：每一批发请求以前记 `ext.memory.merging`（`upto` 是这一批新记的里最后那一条，`fresh` 这一批几条新记的，`left` 连它在内还有几条，`manual` 人叫的、后台自己合的都记）；收尾是同一个 `upto` 的 `ext.memory.merged`（合成了，或者连着三次跳过）或 `ext.memory.merge_failed`。订阅着 `memory` 流的头照这几行自己算：头一批的 `left` 是总数，各批收尾的 `fresh` 加起来是合了多少；`merging` 到它收尾之间 `by` 是记忆模块的 `saved`（写了 `replaces` 的是改）、`retired`、`summary` 就是这一批做了什么（同一时刻别的会话可能在抽、人可能在改，照 `by` 分），关键词跟在 `merged` 后面；还没收尾的是正在合（底账 `MemoryBook::merging`）。核心半路停了的那一批，下一回第一次开这一间时补一条 `merge_failed`（`why: interrupted`）：开日志总在合以前，这一回还不会有在合的。一批里面不细分：模型写的那一会儿不推字数（那不是一件事，不进日志）。会话里人叫的先抽的那几条（第 9 款）在第一条 `merging` 前面，带 `ext.memory.extracted`。
11. **顺带重看旧记忆**（R-19，2026-10-19 项目主人照推荐定「每次整理顺带最久没检查过的 20 条，不一次性全量重整」，量过成本再做）：只看新记的和相关的，和新记的不沾边的旧记忆永远不会再被看一眼。一趟整理（合到没有剩下的）开头照底账挑一次轮到的旧记忆：上次重看到的那一条（`MemoryBook::swept`，最后一条 `ext.memory.swept` 的 `upto`）后面、现在算数、听众合的，照编号最多 20 条（`SWEEP`），不够的从头接（轮完一圈从头来）；从头合的（还没合并过、摘要不算了的，第 8 款）全是新记的，不挑。头一个放得下的批带上，放在相关的旧记忆后面，标题 `merge/sweep.txt`；新记的塞满了的照挑好的那一份往后挪，不重挑（重挑会把这一趟刚合完的算成旧的）；已经当相关的交进去的不重复列、也算看过；只重看的一批至少交一条。指令照旧：重复、过时、没价值、相对日期的规矩对它们一样适用。合成了在 `merged` 后面记 `ext.memory.swept`（`upto`、`count`），没合成的不往前走。人叫的整理没有新记的也照样重看这几条（`merging` 的 `fresh`、`left` 是 0，`upto` 是上次合到的那一条）；后台的只在有新记的时候合，顺带重看。成本：一趟多交 20 行，一行约 27 个 token（`prompts.md` 的量法），约 550 个输入 token；量尺见 `memory/eval.md`「整理」的「轮转」。
12. **她正在写什么**（R-21，2026-10-19 项目主人：人叫的整理「能实时把当前处理的条目显示出来，可以给个 5 行左右的滚动刷新区域，这样就像是在窥探梦境一样，很有趣。然后我希望能有一个有趣的进度条」；后台自动的对话里不显示、网页记忆页开着时写一行「正在整理…」，怎么画归头）：模型是一次读完一批、一次写出来的，没有「正在看哪一条」；真实的两样给头：`merging` 带上这一批交的是哪几条（`given`，头等的时候让它们一条条浮过去），模型边写核心边读（`miyu_recall::merge::Watch`，一次性入口的 `OneShot::call_watching` 交来正文的每一段），写完一条改的、作废的就推一条，摘要每多 20 个字、写完推一条（`memory.dreaming`，`protocol.md`「记忆日志的推送」第 7 条）。单条照 `decisions` 的规矩核对（编号是交进去的、字数、种类、`by`），几条之间的核对要看全部、只在落的时候做：推的是她这一刻写的，落的可能少几条，真相是日志。推以前遮过 key；不落盘、不补（同压缩的 `compaction.progress`）；一个核心一路广播（`memory/dreaming.rs`），订阅着这一间的连接照这一间、照听众挑（同 `follow`）。换了端点重来的：交过的条目不再交，摘要的字数从零交起。
13. **叫停**（R-22，2026-10-20 项目主人在终端验收时定：「合完的批留着，正在合的那一批放弃，下次整理再合；不回退」，`/dream stop` 和 `/stop` 两种都要）：会话里人叫的整理（`/dream`、带 `session` 的 `memory.dream`）听着这个会话的叫停（`merge/hush.rs`，放在会话的 `Extractor` 里，从叫的那一刻起听）：`/dream stop` 只停整理，`/stop` 照旧停这一轮和派出去的、连整理一起停。叫停了：正在等模型的那一批丢掉请求（同打断一轮，不记账），记一条 `ext.memory.merge_failed`（`why: stopped`，不写 `tries`：不算没合成，不数次数），合完了的批照旧落着；还没开始合的（抽的时候叫停的：抽的照样抽完）不合；合完一批、顺带补关键词的那一次也停。交回叫停以前合完了的几样数，带 `stopped`。下次整理照没合过的从放弃的那一批接着合。定时的、协议带 `persona` 的、别的会话叫的不听这个会话的叫停；整理时人说话不叫停（头把面板收起，整理在后台合完，一轮对话和这一间的整理本来就并行）。不经会话的那一趟（`miyu memory dream`、网页记忆页的「整理」，都是带 `persona` 的 `memory.dream`）R-23 起也停得下（2026-10-20 项目主人看了 R-22 说只有会话里的停得下「不合理」）：一间另有一份叫停的那一头（`Merges` 里，`Keeper::stop_dream`），人叫的整理不管是哪一路叫的，都同时听叫它的会话的和这一间的；协议的 `memory.dream_stop`（`persona` 或 `session`，照 `find` 找那一间）叫停这一间这时人叫的那一趟，回 `{"stopped": true}`，没有的回 `not_dreaming`；会话的 `/dream stop`、`/stop` 照旧只停这个会话叫的。命令行 `miyu memory dream` 按一次 Ctrl+C 发它、等原来那一条回应印中断了（退出码 3），按两次直接退。
