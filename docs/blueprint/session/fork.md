## 会话分叉：`session.fork`

### 是什么

从一个会话的某一点分叉出一个子会话：它的历史引用父会话到那一点为止的有效历史，不复制，再接上自己的事件。两边请求的前缀逐字节相同，供应商的缓存照样命中（`03-事件模型.md` 第七节「分叉」）。

第一个用它的是通讯平台的支线（`18-通讯平台.md` 第八节、第十六节，Q24，2026-10-07 项目主人定）：主线忙时分叉一条支线回另一个人，跑完一轮就封存，不合回主线。以后终端里「从这里试另一条路」、fork 式摘要（`09-压缩.md`）也走它，这一页先只定支线要的。

状态：定稿（2026-10-11 主会话起草，接入QQ 的会话同一天过目同意、补了四处）。C-8 上（分叉、载入）、C-8 下（封存）做了。

### 对外的样子

**`session.fork {session, seal_after?}`** → `{session: <子会话编号>, upto: <序号>}`

- `session`：父会话，得是主会话（子代理、分叉出来的再分叉 `bad_params`）；没有的 `session_not_found`。记成谁同 `events.append`（核心拉起的扩展是那个包，别的是管理员）。
- 分叉点由核心定，回应里交回（`upto`）：父会话这时在跑一轮的，是这一轮 `turn.started` 之前的那一条（触发这一轮的那条消息在分叉点以内，支线看得到它）；闲着的，是日志的最后一条。只照落了盘的日志算。
- `seal_after`（C-8 下）：跑完几轮就封存，支线写 `1`；不写的不封存（留给以后终端里的分叉）；`0`、不是整数的 `bad_params`。写进子会话 `session.created` 的 `forked`，载入时照它接着数。接着开的一轮（这一轮里排队的、并进来的几条没再请求就结束，内核接着开的；被有计划的重启打断以后接着干的）算同一轮的延续。
- 以后终端里「从这里试另一条路」要的「从指定的序号分叉」随那一步加（项目主人题，先不做界面）。

**子会话照什么来**

| 什么 | 照什么 |
|---|---|
| 属主、场所、工作目录、权限级别 | 父会话这时的 |
| 策略快照（system、工具面） | 父会话这时手上的那一份，原样（同一个哈希）：前缀才逐字节相同 |
| 模型、端点、key | 父会话钉住的那一个（`18` 第八节「要守的三条」第 3 条：换了端点前缀再一样也不命中） |
| 历史 | 父会话到 `upto` 为止的有效历史，载入时照父会话的日志现算，不复制 |
| 记忆、回合索引 | 照父会话的范围（施工 R-13 三补，2026-10-12；原来同子代理不收）：联想、记忆的三件工具照常，支线自己的回合照支线的编号进回合库、带场所；底子里父会话的回合不在支线名下再记（`memory.md` 第一条第 1 款）。2026-10-11 项目主人定群里她也照样记、照样想起、能搜：原来支线里聊的哪里都不留 |

**日志**：子会话的日志接着分叉点往下数：第一条是 `session.created`，序号 `upto + 1`，多一格 `forked: {from, upto}`；`parent` 写父会话（列表、索引照「有父会话」办；记忆照父会话的范围，施工 R-13 三补），`depth` 照子代理那样加一。分叉出来的不是任务：不交回报，子代理那一套（换快照时接的子代理说明、派子代理的层数、问不问人）照主会话办，快照和父会话的一样，前缀才对得上。

**继承来的旁听**（接入QQ 的会话提）：子会话的账本照父会话到分叉点为止「旁听记下的、当过触发的」接着算。分叉点以前就记下的那条（判官慢、主线开轮之前已经记下），支线直接 `session.respond {session: 支线, to: [它在主线里的序号]}`，不用再抄（抄了近况里会出现两遍）；已经当过触发的照样拒 `already_answered`。分叉点以后主线又记下的，才照旁听抄进支线（带 `ambient`）。

**「另一条线正在回」**（接入QQ 的会话 2026-10-11 实测定）：走 `session.respond` 的 `facts`，由桥带一句事实 `Another line is already replying to msg=<编号>.`（两个模型回 A 合计 0/30、回 B 29/30）；行尾标记效果差（一个模型 7/15），核心不拼。主线开轮时同样由桥带。「你已经回过」不要：近况里有回过的 `[you]` 行时不标也不重复。

**开一轮**：同别的会话，`session.respond`、`session.send`。往支线 `session.send` 带 `venue` 格、`ambient` 照常收（命令编号照接入QQ 仓库的 `chat.md` 第七条第 1 条加 `/branch` 去重）。「你另有一条回复正在回 A」这类事实，由桥经 `session.respond` 的 `facts` 交，核心不拼。

**订阅**：子会话是普通会话；`subscribe` 带 `after: upto` 补的只有子会话自己的事件，不重放继承来的那一段。

**封存**（C-8 下）：跑满 `seal_after` 轮、这一轮结束（`turn.ended`）、没有接着开的，同一批记一条 `session.sealed`（订阅着的照常收到，桥照它从投影去掉、退订）；崩了以后载入时收尾的那一轮也照这一条。数轮照日志数（`miyu-kernel` 的 `session/seal.rs`）：有触发的一轮开了算一轮；接着开的，`turn.started` 的 `trigger` 落在上一轮的开头和结尾之间、`triggers` 是空的，不另算；手动压缩、清空单开的那一轮没有触发，不算。之后改对话的命令拒 `session_sealed`：`session.send`（谁发的都拒，别的会话、子代理的话也是）、`session.respond`、`session.note`、`events.append`、斜杠命令、重做、压缩、清空、撤销、恢复、换模型、切权限、换工作区；改标题置顶、打断、回答、回顾照收。封存以后到的回报（后台命令、子代理结束）、空了的通知照记，不叫醒她。这一轮还在跑时 `session.send` 来的，照「排队的消息」并进这一轮（接入QQ 仓库的 `chat.md` 分派的「并进支线」）。封存了的会话没人订阅、没事了，问空闲时当场退下，不等闲够（`session/actor.md`「退下」）；日志留在磁盘上，再用到照常载入，载入的认得封存。

**推送**：子会话是普通会话，订阅它的连接照常收到它的事件（桥照它发群消息、记 `venue.delivered`）。

**主线怎么看到支线说的话**：桥把支线发出去的那几句照旧记成 `venue.delivered`，记在**主线**会话的日志里（`events.append`，`line` 写支线的会话编号）。主线下一轮的群聊近况照日志渲染：`line` 不是自己的，渲染成 `[you]` 行（`18` 第八节「要守的三条」第 1 条：只放这条线历史里没有的）。不跨会话取，主线的投影只读自己的日志。

**列表**：`session.list` 照子会话那样列（带 `parent`），头可以收起来；`venue.sessions` 不列支线：它是「这个场所的会话」，支线短命、跑完就封存，桥自己知道开了哪几条。

### 怎么走

1. 收到 `session.fork`：找到父会话（没有的 `session_not_found`），照它落了盘的日志算分叉点和那一刻的权限、钉住的模型、快照的哈希；父会话不是主会话的 `bad_params`。
2. 写子会话的第一条：`session.created`（`forked`、`parent`、`depth`、快照的哈希同父会话的），序号接着分叉点；快照不另存，同哈希的是同一份 blob。经会话列表的索引写，列表里有这一行。
3. 载入子会话（造好当场载入、以后重启核心以后再载入）：投影 = 父会话日志里到 `upto` 为止的有效历史（照 `03` 第七节「有效历史」算，压缩、撤销、撤回照父会话自己的账本）+ 子会话自己的事件。父会话后来又压缩、撤销，都在 `upto` 之后，不影响（`18` 第八节「主线被撤销、被压缩，都不影响已经分叉的支线」）。她看过的文件照底子加自己的算；用量、任务表只算自己的。
4. 群聊近况的 `[you]` 行：子会话把分叉来源也算「自己的线」，主线自己的回复在支线里不多渲染一遍。
5. 撤销读回日志（撤到还算数的压缩）读到分叉点以前的，接上底子。

### 出错

| 情形 | 怎么办 |
|---|---|
| 父会话没有 | `session_not_found` |
| 父会话是子代理、分叉出来的 | `bad_params` |
| 会话编号写法不对 | `bad_params` |
| 父会话本身是封存了的 | 照样能分叉（历史在） |
| 子会话封存了还发、还照记下的开一轮、还改对话（C-8 下） | `session_sealed` |
| `seal_after` 写 0、不是整数 | `bad_params` |
| 父会话的日志后来读不出（磁盘坏了） | 子会话载入不成，照会话载入失败办 |
