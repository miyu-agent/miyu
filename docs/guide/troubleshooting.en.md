# Troubleshooting

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

If Miyu will not start, cannot connect, does not respond, or shows an error you do not understand, start on this page. Errors that belong to one feature are written in that page's "When something goes wrong" section; this page collects the general ones. Chinese version: [troubleshooting.md](troubleshooting.md).

## Run miyu check first

```sh
miyu check
```

It checks the files you write by hand and that Miyu reads, using what is on disk right now: a file you just edited, before the core has reread it, is checked too. It checks all of the following, and writes no files:

| What is checked | Where |
|---|---|
| System config | `~/.miyu/etc/config.toml` |
| The project config of the current directory | The `.miyu/config.toml` found by searching upward from the current directory |
| The secrets file, and secrets and environment variables that the config refers to but cannot be found | `~/.miyu/etc/private/secrets.toml` |
| Whether the personas, presets, knowledge bases, providers and pools named in the config exist | System config |
| Settings left in the config for packages that have been uninstalled | System config |
| Each persona's `persona.toml` and `prompts/examples.md` | The persona directory |
| Each preset | The preset directory |
| The manifest of each package, shipped and installed by you | The package directory |
| The checks that packages bring themselves | The programs that packages declare |
| Scripts, skills and slash command templates that did not load, and ones covered by another with the same name | Under packages and `~/.miyu/root/` |
| MCP servers written wrongly, and tools that are listed but not registered | System config, package manifests |
| Rows in the schedule table that cannot be read | The schedule table |
| Broken tool descriptions and prompt overrides | The override files |
| Model drivers that extensions provide: not approved by the package, or a key that should be configured but is not | System config |
| Installed package files that were changed or are missing | The package directory |

The `~/.miyu` above is the data root (`~/.miyu` by default, `%USERPROFILE%\.miyu` on Windows), or the environment variable `MIYU_HOME` if you set it. To check only one file, write it after the command:

```sh
miyu check ~/.miyu/root/personas/miyu/prompts/examples.md
```

### How to read the result

One line per problem: the file, the line, the column, "error" or "warning", and what it says. The last part is the total, and below it is the state of the semantic model:

```text
~/.miyu/etc/config.toml:3:9 error: log.level must be error, warn, info, debug, trace or off, not "verbose"
~/.miyu/etc/config.toml:12:1 warning: There is no models.chatt. Did you mean models.chat?
~/.miyu/etc/config.toml:20:7 warning: providers.acme.key refers to the secret acme, which is not set
1 error, 2 warnings
Semantic model: local:granite-embedding-97m-multilingual-r2, indexing
  Memory: engineer 120/120
  Knowledge bases: handbook 30/42
```

- "error": the syntax is wrong and this spot does not count; if the TOML itself cannot be read, the whole file does not count. With errors, the exit code is `1`.
- "warning": keys it does not recognize, and secrets, environment variables, personas, presets or knowledge bases that the config refers to but do not exist yet. Miyu runs anyway; these spots are just not used. With only warnings, the exit code is `0`.
- When there is nothing to report, it prints "no problems".
- The semantic model lines are not problems. They say which model is in use, and how many memories, past conversations and knowledge-base entries have been indexed (indexed/total). When it is not installed it prints "Semantic model: not installed, keyword search only", with a hint to run `miyu pkg install embed`. When it is turned off it prints "Semantic model: off (models.embedding = "off"), keyword search only". When it is switched to a remote model, there is one more line at the end: "No auto recall: memories, knowledge bases (no measured threshold for this model; search still works)". Only the built-in model recalls memories and knowledge bases automatically; other models are used only when searching.

`--format json` prints one line, `{"problems": […]}`. Each problem has `kind`, `file`, `code`, `level` and `message`, and those with a line and column also have `line` and `column`. When everything is checked, there is also `embedding`.

`miyu check` needs the core, and starts it first if it is not running. If the core cannot start, `miyu check` cannot run either: read "The core will not start, or cannot connect" below first, and if that does not help, use [Rescue](rescue.en.md).

## Logs

| Whose | Where |
|---|---|
| The core | `~/.miyu/var/log/core.log`; when it reaches 10 MB it is rotated, and `core.log.1` to `core.log.5` are kept |
| Packages, extensions | `~/.miyu/var/log/<id>/`; what an extension program writes to standard error, the core records here as `stderr` |
| The web UI | `~/.miyu/var/log/webui/web.log` |
| The tray | `~/.miyu/var/log/miyu-applet.log` |
| Terminal crashes | `tui/crash.log` under the cache directory: on Linux `~/.cache/miyu/tui/crash.log` (under `XDG_CACHE_HOME` if you set it), on macOS `~/Library/Caches/Miyu/tui/crash.log`, on Windows `%LOCALAPPDATA%\Miyu\cache\tui\crash.log` |

To see the last few dozen lines:

```sh
tail -n 50 ~/.miyu/var/log/core.log
```

In Windows PowerShell: `Get-Content -Tail 50 $HOME\.miyu\var\log\core.log`.

The core's log has one entry per line, in English, and does not record conversation content or keys. Every time the core starts, it writes one `starting` line with the version and the process id. To record in more detail, change `log.level`:

```sh
miyu config set log.level debug
```

It can be `error`, `warn`, `info` (shipped), `debug`, `trace` or `off`, and the change takes effect on the spot. To record in detail just this once, first run `miyu core stop`, then open it like this: the core it starts logs at `debug` this time, overriding `log.level`.

```bash
MIYU_LOG=debug miyu
```

```powershell
$env:MIYU_LOG = 'debug'
miyu
```

See [Keeping it running, and servers](service.en.md#logs).

## The core will not start, or cannot connect

Heads and the command line connect to the core when they open, and start one if they cannot connect, waiting up to 60 seconds. A data root runs only one core at a time, and it holds `~/.miyu/run/core.lock`.

| What you see | Cause | What to do |
|---|---|---|
| A message that the core could not start, followed by a reason | The core hit an error while starting; what follows the colon is the reason it gave | Fix what the reason says. If the reason is not clear, read the last lines of `core.log` |
| A message that the core did not start and did not say why | The core exited without saying anything | Read the last lines of `~/.miyu/var/log/core.log` |
| A message that it waited too long for the core to start | It was still not up after 60 seconds, most likely because the disk is busy | Try again; if that does not help, read `core.log` |
| A message that another program is starting the core and it waited too long | Another head is starting the core and it was still not up after 60 seconds | Same as above |
| A message that the core could not be launched: … | The program cannot be found, or there is no permission to run it | Reinstall Miyu, see [Installing, upgrading and uninstalling](install.en.md) |
| "… isn't a Miyu data root …" | Something else is at the location of the data root. The data folder of the old 0.7 version reports this too | If it is the data folder of the old 0.7 version, move it aside as the second half of the message says, install the migration package and migrate, see [Migrating from the old 0.7 version](migrate.en.md); if it is not, set `MIYU_HOME` to an empty folder |
| "… is an old Miyu data root, which this version doesn't read …" | A data root left by a development build from before release | Set `MIYU_HOME` to an empty folder |
| "… uses a layout this version doesn't know …" | A newer version of Miyu has written to this data root | Use the version that wrote it, or switch to another data root |
| A message that … is not yours, or that others can enter it, and that Miyu does not connect (Linux, macOS); a message that the other end of the named pipe … is not your own process, and that Miyu does not connect (Windows) | Linux, macOS: the directory that holds the socket is not yours, or other users can enter it, so Miyu does not connect into it. Windows: the program at the other end of the named pipe is not run by your user | Linux, macOS: make that directory enterable by you only, for example `chmod 700 <directory>`. Windows: close the program that holds the pipe and open Miyu again |
| A message that the socket path is too long to fit, and does not fit under the temporary directory either (Linux, macOS) | The data root's path is too long | Use a shorter `MIYU_HOME`, or set `TMPDIR` to a short directory |
| A message that there is something else at …: a file that is not a socket, or another program is listening, and it is left alone (Linux, macOS); a message that the named pipe … is already held by another program, and it is left alone (Windows) | Linux, macOS: something else, a file or a program, holds the socket's location. Windows: another program holds the name of the named pipe | If it is not Miyu's, move it away or close it |
| "lost connection to the core" | The core exited or crashed partway | Read `core.log`, then open Miyu again |

Where the socket is:

| System | Where |
|---|---|
| Linux | `$XDG_RUNTIME_DIR/miyu-<fingerprint>/core.sock` when `XDG_RUNTIME_DIR` is set, otherwise `~/.miyu/run/core.sock`; when the path is too long, it falls back to `$TMPDIR/miyu-<uid>/` |
| macOS | `~/.miyu/run/core.sock`; when the path is too long, it falls back to `$TMPDIR/miyu-<uid>/` |
| Windows | The named pipe `\\.\pipe\miyu-<fingerprint>`, open only to your user |

### The old core is still running

After an upgrade, a core that is already running is still the old version, and a new head that connects to it may report "Protocol version mismatch. Upgrade to the same release.". Stop it, and the next time you open Miyu, the one that starts is the new version:

```sh
miyu core stop
```

If you installed the start-at-boot service and want the service to keep managing it, run `miyu service enable` again, see [Keeping it running, and servers](service.en.md#making-the-service-take-over-now).

If `miyu core stop` says "the core is still running but cannot be reached: the token or socket location in the data root's run/ is gone", then `~/.miyu/run/` was deleted while the core was still open. Following the hint, find the process id on the last `starting` line in `core.log`, and end that process:

```bash
kill <process id>
```

```powershell
Stop-Process -Id <process id>
```

### Too broken to open at all

When the core is broken and no head opens, use `miyu rescue` to enter LiteMiyu's rescue mode and repair it; it does not go through the core. LiteMiyu has only a Linux x86_64 build, and none for macOS or Windows. See [Rescue](rescue.en.md).

## No model configured, or a wrong key

| What you see | What to do |
|---|---|
| "no model configured", with the hint to run `miyu setup`; `miyu ask` exits with code `5` | Run `miyu setup`, see [Models](models.en.md) |
| `miyu check` warns "… refers to the secret …, which is not set" | Store the key with `miyu provider login <name>` |
| `miyu check` warns "… refers to …, which was not set when the core started" | The core started before this variable was set. Run `miyu core stop`, then open Miyu again in the shell where the variable is set. A core started by the start-at-boot service cannot see variables in the shell, see [Keeping it running, and servers](service.en.md#the-service-and-environment-variables) |
| "Model request failed.", authentication failed | The key is wrong or has expired; run `miyu provider login <name>` again |

## The model keeps failing

"Models cooling down. Try again later." and "No model is available." mean that the provider rate-limited you, the quota ran out, or it could not be reached, and Miyu sets that model aside for a while. For how many times it retries, how long the cooldown is, and how to use a pool to switch to another model, see [Models](models.en.md#rate-limits-and-used-up-quota).

## A command was refused, or it keeps waiting for confirmation

| What you see | Cause |
|---|---|
| "Read-only mode, not run" | The session is read-only and cannot write |
| "Miyu's own data, off limits" | The command touched the data root |
| The confirmation box keeps waiting | It is waiting for you to click allow or deny; if nobody clicks in time, it is denied automatically: "No one confirmed in time, denied automatically" |
| "Needs confirmation, no one to confirm"; `miyu ask` exits with code `4` | In `miyu ask` and on chat platforms nobody can confirm on the spot, so the steps that need confirmation are not done |

For switching levels, which commands need confirmation, and how to turn that off, see [Permissions and sandbox](permissions.en.md).

## A package will not install, or an extension will not start

| What you see | What to do |
|---|---|
| "Invalid manifest, cannot install." | `miyu pkg info <package directory>` only looks and does not install, and tells you what is wrong in the manifest |
| "Required packages are missing." | Install what it depends on first; `miyu pkg info <id>` shows the dependencies |
| "Not available for this system." | The package has no build for your kind of system |
| "Package source unreachable." "Package download failed." | Check the network, then try `miyu pkg update` again in a while |
| "<program> not found: … says miyu <name> runs it. Reinstall the package and try again." | Reinstall with `miyu pkg install <id>` |
| "user interface 'tui' is not installed" | Install it back with `miyu pkg install tui` |
| An extension stopped | Read `~/.miyu/var/log/<id>/stderr`, which is the error the extension reported itself |

`miyu pkg check` checks whether the installed files have been changed. For details see [Packages](packages.en.md).

## The terminal display is wrong

| What you see | What to do |
|---|---|
| Icons are boxes or question marks | The font has no Nerd Font icons. Install a Nerd Font, or use plain characters with `miyu config set tui.icons plain` |
| The colors are wrong or too harsh | On the settings page, "Appearance → Color scheme" has "Colors", "Light or dark" and "Paint the background"; the keys are `tui.theme`, `tui.theme_mode`, `tui.theme_background` |
| The command line's output has color codes that look like garbage | Set the environment variable `NO_COLOR=1` |
| The terminal crashed | The crash record is in `tui/crash.log`; for the location see "Logs" above |

If you installed the shell integration, `miyu shellhook doctor` first lists which shells it is installed into, then checks the core, the terminal and the clipboard one by one:

```text
✓ The core is reachable
✗ The terminal doesn't say it's truecolor (COLORTERM isn't truecolor): at most 256 colors
✗ Can't read the terminal's colors: following the terminal uses its 16 colors only (tmux and the like need passthrough)
✓ Ctrl+V reads the clipboard with wl-paste
```

This is how it looks on a Wayland desktop on Linux. Elsewhere the last line reads:

| System | The last line |
|---|---|
| Linux, without Wayland | "Ctrl+V reads the clipboard with xclip" or "… with xsel" |
| macOS | "Ctrl+V reads the clipboard with pbpaste" |
| Windows | "Ctrl+V reads the clipboard with powershell" |

If none is found, it reads "✗ No clipboard command found (…): Ctrl+V can only use the terminal's own paste", and the parentheses list the commands that were tried on this machine.

For terminal settings see [Terminal](heads/tui.en.md).

## The web UI will not open

| What you see | What to do |
|---|---|
| "port 8300 is in use", with the hint to pick another with `miyu web --port <port>` | Use another port. If you never wrote a port, when 8300 is taken it tries 8301 to 8309 in turn, and reports only when all are taken |
| "cannot open a browser; open the address above" | Open the address it printed yourself. On a machine with no desktop, use `miyu web --print` |
| The sign-in page says "Wrong access password" | If you forgot it, run `miyu web --reset` on this computer, and reset it in the page that opens |
| The whole screen says "No access password yet" | On the computer that runs Miyu, set it with `miyu web --settings access` |
| "Too many attempts. Try again in N s" | Wait for the number of seconds it says, then try again |

The web UI's own log is `~/.miyu/var/log/webui/web.log`. For opening it from another device or through a reverse proxy, see [Keeping it running, and servers](service.en.md#opening-the-web-ui-from-other-machines-and-phones).

## A config mistake

- `miyu ask` starts with "the configuration has N errors", with the hint to run `miyu check` to see them. Fix them by the line numbers `miyu check` prints.
- If a whole file cannot be read when the core starts, that file is treated as empty, and the core starts anyway. If you break it by hand while the core is running, the core keeps using the last copy it read successfully.
- When a file cannot be read, `miyu config set` changes nothing and reports "Config file is invalid. Fix it first.". `miyu config edit` checks before saving.
- If one setting does not take effect, `miyu config explain <key>` lists what each layer says, which layer counts, and why a layer that was written does not count.
- "project config … is not trusted; not used this time": in that directory, run `miyu config trust`, read it, then decide.

See [Configuration](config.en.md).

## Reason codes

When the core refuses something, it gives a reason code and one sentence. Interfaces and the command line show the sentence; a program that speaks the protocol directly reads `data.reason`. The common ones:

| Reason code | The sentence shown | What to do |
|---|---|---|
| `no_model` | No model is available. | `miyu setup`, or write a usable one in `models.chat` |
| `cooling` | Models cooling down. Try again later. | Wait, or configure a pool, see [Models](models.en.md) |
| `model_failed` | Model request failed. | Read the details in the interface; for an authentication failure, store the key again |
| `unknown_model` | Model or pool not found. | Write it as `provider/model` or `@pool`, and configure the provider |
| `unknown_provider` | Provider not found. | Configure that provider first, see [Models](models.en.md) |
| `unknown_secret` | Secret not found. | `miyu provider login <name>` |
| `session_not_found` | Session not found. | Write the full id; a deleted session cannot be recovered |
| `turn_running` | A turn is in progress. | Wait for this turn to end, or interrupt it first, then undo, compact or delete |
| `archived` | This is an archive. It can't be continued. | Export again without `--archive` |
| `session_read_only` | The session log is broken; only the part before it can be viewed and the session can't continue. Start a new session to go on. | Start a new session |
| `session_unavailable` | Session can't be read right now. Try again later. | Try again in a while; common with disk errors or too many open files |
| `dir_too_wide` | Directory too broad. | Use a smaller directory |
| `attachment_too_big` | Attachment too large (max 20 MiB; images 5 MiB, 8000 px). | Make it smaller, or give only the path |
| `attachment_in_data_root` | Files in the data directory cannot be attached. | Copy it outside the data root, then attach it |
| `export_exists` | File already exists. | Use another file name; export does not overwrite |
| `unknown_config_key` | Config key not found. | `miyu config get` shows which keys exist |
| `config_invalid` | Invalid config, not saved. | Change the value as the error says; `miyu config explain <key>` shows what can be written |
| `config_file_broken` | Config file is invalid. Fix it first. | `miyu check` |
| `unknown_package` | Package not found. | `miyu pkg search` finds the id |
| `package_invalid` | Invalid manifest, cannot install. | `miyu pkg info <package directory>` shows what is wrong |
| `depends_missing` | Required packages are missing. | Install the dependencies first |
| `extension_off` | Extension disabled. | Turn it on in the packages page |
| `bad_password` | Incorrect access password. | `miyu web --reset` |
| `protocol_mismatch` | Protocol version mismatch. Upgrade to the same release. | Upgrade the head and the core to the same version, and run `miyu core stop` |
| `internal_error` | Internal error. See the runtime log. | Read `core.log`, and report it as described below |

For all reason codes see [Protocol reference: errors](../reference/errors.en.md).

## Reporting a problem

Report it in the core repository: <https://github.com/miyu-agent/miyu/issues>. Attach:

1. The version that `miyu --version` prints.
2. Your system and its version, for example Arch Linux, macOS 15, Windows 11; for a terminal problem, add the name of the terminal program.
3. The output of `miyu check`.
4. A few lines of `core.log` from around the moment of the problem; for a package problem, attach what is in `~/.miyu/var/log/<id>/`; if the terminal crashed, attach that part of `crash.log`.
5. How to make it happen again.

Read it yourself before you paste. Logs and the output of `miyu check` contain your paths, user name, session ids and package names; an exported session carries the conversation, command output and file contents as they are, with nothing masked. Do not paste `~/.miyu/etc/private/secrets.toml`.
