# Memory

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

The AI remembers what you talk about, so it can recall it the next time you open a session. This page covers what it remembers, when it remembers and recalls, how to view and change memories, and how to stop it from remembering. Chinese version: [memory.md](memory.md).

Memory comes from the shipped package `base-memory` ("Persona memory" in the interface). It is on once installed.

## What a memory looks like

A memory is one sentence of at most 120 characters. It has an id, written as `m` plus a number, for example `m12`. Each memory belongs to one class:

| Class | Called in the web UI | What it remembers |
|---|---|---|
| `user` | About the user | Things about you |
| `feedback` | Requests for the AI | How you want the AI to work |
| `episode` | What happened | Things you went through together |
| `reference` | Where things are | Long-lasting facts, where material is kept |
| `person` | People | One thing about someone else, with who that person is (a name or platform id, for example `qq:10086`) |

A memory can carry an extra line of keywords, separated by commas, at most 200 characters. Keywords are only used to find the memory; the AI does not see this line.

There is one more class, `change`: the AI's own notes of how it has changed in a simulated life. Only the AI in a life session can write it, automatic saving and organizing leave it alone, and you can only retire and restore it, see [Simulated life](life.en.md#change-over-life).

Besides the individual memories there are two more things, both written when memories are organized:

- What it knows about you: a short summary.
- Cards for the people it knows: one card per person, at most 400 characters, composed from the memories of the `person` class.

The AI can also search earlier conversations of the same persona (only the turns you started).

## Memory follows the persona

Each persona has its own memory, shared by the sessions that use that persona. Sessions with no persona share another one.

- If you switch persona in the middle of a session, memories are saved into the new persona's memory from the turn of the switch. What was saved before stays in the old one and is not moved.
- Subagents neither save nor recall.

## When it remembers

| Who | How |
|---|---|
| Automatic | After a session goes idle, the AI saves what is worth keeping from what was said since last time. Turns in which the AI already remembered or forgot something itself are not looked at again |
| The AI | Calls the `remember` tool. It can change a memory: the new one replaces the old one |
| You | Type `/remember <text>` in a local session. It is saved in the class "About the user", and the reply is "Remembered: …" |
| You | `miyu memory add`, or "Add" on the memory page of the web UI |

Automatic saving needs both of these:

1. The AI has answered at least `memory.extract_turns` turns (default 2) since the last automatic save.
2. The session has been idle for `memory.extract_idle` (default 30 minutes).

A session that never goes idle (people keep talking in a group) does not wait for idle. When `memory.extract_max_turns` turns (default 20) have ended since last time, or the earliest turn not yet saved is older than `memory.extract_max_wait` (default 1 hour), saving runs in the background.

Automatic saving uses a model from the everyday pool (`normal`). If the pool is empty, or all its members are cooling down or failing, it uses the session's own model. For how to configure pools, see [Models](models.en.md#pools-cheap-ones-for-chores-expensive-ones-for-real-work).

## When it recalls

| When | What is brought in |
|---|---|
| The first turn of a session, and the first turn after compaction | A resident block: what it knows about you, plus what was saved recently, newest first, at most 3000 bytes. If something does not fit, the last line says how many more there are and tells the AI to look with `memory_search` |
| On chat platforms, a turn where someone else speaks | That person's card, once per stretch of context |
| Every turn you start | Associative recall: it looks things up from what you said this turn, at most 3 memories and at most 500 bytes, and at most 40 per stretch of context (counted again after compaction), counting together with the automatic recall of knowledge bases. A memory is brought in only when both the keywords and the meaning match; it prefers bringing nothing |
| When the AI looks by itself | The `memory_search` tool: searches memories, people it knows, and earlier conversations |

Associative recall needs a semantic model (`models.embedding`, see [Models](models.en.md#the-three-uses)). By default it uses the local `embed` package (see [Add-ons](addons.en.md)). If it is not installed, set to `off`, or changed to a remote model, there is no associative recall; the resident block, cards and `memory_search` work as usual. If it is not installed or set to `off`, `memory_search` finds by keywords only.

Which memories were recalled is not shown on the timeline. What you can see:

- Terminal: in the context breakdown of `/context`, how many tokens "Resident memory" and "Recalled memory" take each; in `/status`, "recalled N times · remembered N" counts the times the AI called `memory_search` and `remember`.
- When the AI calls a memory tool, the timeline shows a line as usual.

## Organizing

Organizing takes the newly saved memories together with related older ones and tidies them up:

- Duplicates are retired, and one is kept.
- Memories overturned by later ones are retired.
- Memories that are no longer useful are retired.
- Inaccurate wording is rewritten: saved as a new memory, and the old one is retired.
- A new "what it knows about you" is written.
- The card of each person is composed from the memories of the `person` class.
- Memories without keywords get keywords.
- Up to 20 older memories are looked at again along the way.

Retired memories can be restored; organizing does not empty anything.

When it happens:

- Automatically: after automatic saving has saved something new, if more than `memory.merge_every` (default 16 hours) has passed since the last organizing, it organizes in the background. A memory that has never been organized is organized right away.
- Type `/dream` in a session: it first saves what this session has not saved yet, then organizes until nothing is left. The reply is "Memory organized: …", which says how many were checked, revised and retired, whether the summary was replaced, and how long it took.
- `miyu memory dream`: organizes the memory of the default persona, or the one given by `--persona` or `-s`.
- "Tidy up" on the memory page of the web UI.

To stop: type `/dream stop` or `/stop` in a session; press `Esc` twice in the terminal; press `Ctrl+C` during `miyu memory dream`; click "Stop" in the web UI. The batches already organized are kept; the batch in progress is done again next time.

Organizing uses the everyday pool (`normal`), the same as automatic saving. Each memory keeps the process of the last `memory.dream_keep` organizings (default 20), which you can see under "Tidy-up history" on the memory page of the web UI.

## Viewing and changing

### Command line

```text
miyu memory [<command>] [<options>]
```

With no command it runs `list`. Without `--persona` or `-s`, it uses the memory of the default persona (`persona.default`); if no default persona is set, it reports "memory unavailable". For the memory of sessions with no persona, write `--persona _none`.

| Command | What it does |
|---|---|
| `list` | Lists the newest 50 memories, one per line: id, date, text |
| `search <words>…` | Searches, at most 10 memories, the most relevant first |
| `add <text>…` | Saves a memory, prints "added m…" |
| `edit <id> [<text>…]` | Changes the text: saves a new memory, retires the old one, prints "updated, new id m…". Leave out the text when you only change `--keywords` or `--who` |
| `forget <id>` | Retires a memory |
| `clear session [<id>]` | Clears what one session saved. Without a session, it follows `-s`, and failing that it is the session of the last `miyu ask` |
| `clear me` | Empties this whole memory, including cards and what it knows about you |
| `dream` | Organizes now |
| `cards` | Lists the cards of the people it knows |

| Option | What it does |
|---|---|
| `--persona <id>` | Uses the memory of this persona. Cannot be combined with `-s` |
| `-s`, `--session <id>` | Uses the memory that this session uses |
| `--forgotten` | `list`, `search` and `cards` also list retired ones |
| `--class <user\|feedback\|episode\|reference\|person>` | `list` lists only this class; `add` saves into this class, `user` if not written |
| `--why <reason>` | `forget`: writes why |
| `--keywords <words>` | `add`, `edit`: keywords, separated by commas; for `edit`, an empty value removes them |
| `--who <who>` | `add`, `edit`: who the `person` class memory is about. `add --class person` requires it |
| `--format <text\|json>` | Output format of `list` and `search` |

```sh
miyu memory search coffee
miyu memory add --keywords editor,vim Use Neovim for coding
miyu memory add --class person --who Lin Lin is a colleague who works on the frontend
miyu memory edit m12 --keywords drinks,breakfast
miyu memory forget m15 --why "changed jobs"
miyu memory --persona captain list --class feedback
```

What is cleared cannot be brought back; retired memories can be restored with "Restore" on the memory page of the web UI. For the full table of arguments, see [Command line](cli.en.md#miyu-memory).

### Web UI

The "Memory" page in the settings; type `/memory` in a session to open it directly. The terminal has no memory page.

- At the top you choose which memory: one per persona, and one for "No persona".
- The "Memories" tab: search (text, keywords), filter by class, "Show retired"; open a memory to change its text and keywords, retire it, restore it; "Add"; "Clear" (the same as `clear me`, cannot be brought back); "Tidy up" and "Tidy-up history".
- The "People" tab: view, search and edit the card of each person, and "Meet someone" to write a new one.

## Stopping it from remembering

| Scope | What to do |
|---|---|
| One `miyu ask` | `miyu ask --no-memory "…"`: the new session neither recalls nor saves. Cannot be combined with `-c` or `-s` |
| Sessions using a given preset | Turn off "Persona memory" in the preset: write `memory = false` under `[features]` |
| Everything | `miyu pkg remove base-memory`. What was saved stays in the data root, and is still there after you install it again (`miyu pkg install base-memory`) |
| One memory | Ask the AI to forget it (it calls `forget` to retire it), or `miyu memory forget <id>` |
| What one session saved | Type `/clear-memory` (alias `/reset-memory`) in that session. It does not ask, and replies "Cleared N memories this session made.". Or `miyu memory clear session <id>` |
| A whole memory | `miyu memory clear me`, or "Clear" in the web UI |

Whether memory is on is decided when the session opens and does not change if you switch preset later. `/remember`, `/dream` and `/clear-memory` work only in sessions with memory on; in a session whose preset does not have it on, typing them says "Preset "…" has memory off.".

For how to write presets, see [Personas and presets](personas-presets.en.md).

Clearing one session clears only the memories whose source is entirely in this session: what you saved yourself (`/remember`, `miyu memory add`) has no source and is not cleared; what was also said in other sessions is not cleared; cards are untouched.

## Settings

Change them under the settings of Persona memory in "Packages" on the settings page (`/settings`), or write them into `~/.miyu/etc/config.toml`. A change takes effect from the next turn.

| Key | Default | Allowed | What it controls |
|---|---|---|---|
| `memory.extract_idle` | `"30m"` | `1m` to `1h` | How long a session is idle before automatic saving |
| `memory.extract_turns` | `2` | `1` to `100` | How many turns at least since the last automatic save |
| `memory.extract_max_turns` | `20` | `2` to `500` | For a session that never goes idle, how many turns pile up before it stops waiting for idle |
| `memory.extract_max_wait` | `"1h"` | `10m` to `24h` | For a session that never goes idle, how old the earliest turn not yet saved gets before it stops waiting for idle |
| `memory.merge_every` | `"16h"` | `1h` to `720h` | How often it organizes automatically |
| `memory.dream_keep` | `20` | `0` to `1000` | How many recent organizings to keep the process of; `0` deletes it as soon as organizing is done |

```toml
[memory]
extract_idle = "10m"
merge_every = "24h"
```

## Sessions on chat platforms

Memory is not split by group or by person: the same persona uses the same memory in every group and in every private chat, and recalls everything everywhere. When a memory is saved, it also records which venue and which group (the group name at that moment) it was said in. When someone in a group has memories of the `person` class, organizing composes a card for them, and it is brought in on the turn where they speak.

`/remember`, `/dream` and `/clear-memory` work only in local sessions. For which persona a chat platform session uses and how to set it, see [Connecting chat platforms](heads/im.en.md).

## Where it is stored

| Location (the data root is `~/.miyu` by default, `%USERPROFILE%\.miyu` on Windows) | What it is |
|---|---|
| `~/.miyu/root/memory/<persona id>/` | The memory log of this persona; the one for sessions with no persona is `_none` |
| `~/.miyu/var/cache/index/recall/` | The search index, computed from the logs and sessions |

The memory log is append-only: changing a memory writes a new one, retiring or clearing also writes another line, and the original text stays in the log. Do not edit these files by hand; use `miyu memory` or the memory page of the web UI.

For backups and moving to another machine, see [Data and backups](data.en.md).

## What is sent to the model provider

- Recalled memories and cards go into the context and are sent with each request to the model the session uses.
- Automatic saving and organizing are separate requests to a model of the everyday pool (or the session's model). They send the conversation in question and the related memories. Before sending, the original text of secrets referenced in the config and common key formats are masked.
- If `models.embedding` is set to a remote model, the text of memories and conversations is sent to that provider to compute vectors. The local `embed` does not leave this machine.

## When something goes wrong

| What you see | What to do |
|---|---|
| `miyu memory` reports "memory unavailable" | No default persona is set. Write `--persona <id>`, or `--persona _none` for the memory of sessions with no persona |
| `/remember` says "Preset "…" has memory off." | The preset of this session does not have persona memory on. Open a new session with a preset that has it on, or turn it on in the preset |
| "Persona memory not installed." | `miyu pkg install base-memory` |
| "Memory is being organized." | This memory is being organized. Wait for it to finish |
| "memory too long: N characters, limit 120" | Write the memory shorter, or split it into several |
| The AI never recalls by association | Run `miyu check` and look at the semantic model lines at the end; if it is not installed, `miyu pkg install embed` |
