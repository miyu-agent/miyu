# 安全

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

把一个能跑命令的 AI 放在自己机器上：Miyu 替你挡住了什么、没挡住什么，哪些东西会发出去，几种常见用法该怎么设。

## 信任模型

Miyu 以你这个系统用户的身份跑。开放权限下，AI 能做你在终端里能做的几乎一切：读写你的文件、跑命令、联网。

下面这些防护防的是两件事：AI 一时糊涂做错事，和 AI 被它读到的网页、文件、群消息里的话带偏。它们不是用来关住一个存心找漏洞的程序的。要 AI 碰不到什么，就别让它够得着：用只读，或者别把东西放在它能读的地方。

## Miyu 挡的

| 什么 | 怎么挡 | 讲透在哪 |
|---|---|---|
| AI 改你的文件 | 切到只读：文件工具不写，命令在系统的沙盒里跑，哪里都写不了。Windows 上沙盒只在登录的桌面会话里能用，不在的每条命令都被拒 | [权限和沙盒](permissions.md#两种权限级别) |
| 危险命令 | 开放权限下，破坏性 git 操作、递归删除、关机重启、下载后直接执行、容器使用宿主设备，先问你；删根目录和家目录、格式化磁盘、往磁盘设备直接写、容器拿走整台机器，直接拒。只在 Linux、macOS 上，Windows 上不认，见下一张表 | [权限和沙盒](permissions.md#要确认的命令) |
| AI 用文件工具改 Miyu 自己的数据 | 数据根（默认 `~/.miyu`，Windows 上是 `%USERPROFILE%\.miyu`）里的文件，读、写、编辑的工具都不碰，几处工作区除外 | [权限和沙盒](permissions.md#两种权限级别) |
| 钥匙、登录、浏览器数据 | 只读时，私密目录命令读不到，文件工具读之前先问你 | [权限和沙盒](permissions.md#私密目录) |
| 通讯平台上别人叫 AI 做事 | 群和不是你本人的私聊关起来：文件只碰得到那个会话的工作区，命令在把读也关住的沙盒里跑（Windows 上不能跑命令），不能装包，要确认的事不做；MCP 服务出厂不给它们 | [权限和沙盒](permissions.md#通讯平台上的会话)、[接入通讯平台](heads/im.md#群里的-ai-能做什么) |
| 网页里的话骗 AI 去连本机、内网 | `web_fetch` 和链接卡片不去本机、内网、链路本地这些地址，每一跳重定向都重新查 | [联网搜索和抓网页](web-search.md#碰不到的地址) |
| 装进来路不明的软件包 | 装之前列出它要的能力，你点头才给；软件源的索引验签名，包文件核 SHA-256；社区的包、本机文件装的包标出来 | [软件包](packages.md#软件源) |
| 篡改过的 Miyu 程序 | 安装脚本和 `miyu upgrade` 核签名、核 SHA-256，不对就不装 | [安装、升级、卸载](install.md#脚本核对什么) |
| key 写进文件、日志、命令里 | 配置里只写引用，key 放在密钥文件里（Linux、macOS 上权限是 `0600`，只有你能读写；Windows 上照数据根继承的访问控制）；AI 跑的命令拿不到名字里带 `KEY`、`SECRET`、`TOKEN`、`PASSWORD`、`PASSWD`、`CREDENTIAL` 的环境变量；核心的日志不记 key 和对话内容 | [配置](config.md#密钥)、[工具](tools.md#shell)、[常驻和服务器](service.md#日志) |
| 别的设备连你的网页 | 出厂只听本机；别的设备进来要访问密码（存的是 argon2id 哈希，同一个来源 60 秒错 5 次先拒）；只认 `Host` 是本机地址、这台电脑 IP 的请求，不认域名；对话的连接核对 `Origin` | [网页](heads/web.md#访问和安全)、[常驻和服务器](service.md#从别的机器手机打开网页) |
| 本机别的用户连你的核心 | Linux、macOS 上套接字放在只有你能进的目录里；Windows 上是只对你本人开放的命名管道，连上以后还核对另一头的进程是你的。头连上来还要出示本机令牌 | [出了问题怎么查](troubleshooting.md#核心起不来连不上) |
| 别人的仓库借项目配置放宽权限 | 项目配置只能收紧，现在只认 `permission.start_read_only = true`；没信任的不起作用，内容一变要重新信任 | [配置](config.md#给一个仓库单独设) |
| 别人连进 QQ 的接口冒充 | OneBot 实现连进来要带 Token，没有的被拒 | [接入通讯平台](heads/im.md#接-qq) |

## Miyu 不挡的、挡不全的

| 什么 | 实际是怎样 | 你能做的 |
|---|---|---|
| 换个写法的危险命令 | 受保护的命令只照字面认，刻意绕开的写法认不出 | 不放心的活用只读 |
| Windows 上的危险命令 | 受保护的命令和直接拒的规则只认 bash、zsh 的写法。Windows 上 AI 用 PowerShell，这些规则整套不查：开放权限下删目录、格式化、`git push --force` 都不问、不拒 | 在 Windows 上做没把握的事用只读，见 [权限和沙盒](permissions.md#windows-上不认) |
| 开放权限下的命令 | 不进沙盒。数据根挡的只是文件工具：命令读写得到 `~/.miyu`，包括密钥文件 `~/.miyu/etc/private/secrets.toml` | 同上 |
| 密钥文件 | 三个平台都不用系统的钥匙串，key 照原文写在 `~/.miyu/etc/private/secrets.toml`。Linux、macOS 上 Miyu 每次写它都把权限设成 `0600`；Windows 上不另设权限，照数据根继承的访问控制。以你的身份跑的程序都读得到它 | 别以你的身份跑来路不明的程序；数据根不要放在别的用户也读得到的目录里 |
| 提示词注入 | AI 读到的网页、文件、仓库里的 `AGENTS.md`、群消息、MCP 服务的回答，都进上下文，里面写的话可能带偏它。Miyu 不认这类话；挡得住的只有上面那张表里不看 AI 说什么的规矩 | 读不熟的东西时用只读；别把要紧的确认随手点掉 |
| 你的文件发给模型供应商 | 开放权限下 AI 读得到数据根以外的任何文件；读了的内容进上下文，发给供应商。只读时照样整盘能读，私密目录除外 | 别让 AI 在放着私人文件的目录里乱翻；在意的放进私密目录，用只读 |
| 只读时联网 | 只读的命令照样能联网，读得到的文件发得出去 | 同上 |
| 环境变量 | 去掉带 `KEY` 这些的变量只防顺手带出去，不是一道墙：命令和核心都以你这个系统用户的身份跑，同一个用户的程序之间系统本来不设防，核心进程的环境照样可能被读到（例如 Linux 上的 `/proc/<进程号>/environ`），`{ env = "…" }` 引用的 key 就在那里 | key 用 `miyu provider login` 存进密钥文件 |
| 局域网访问 | 明文 HTTP：同一个网络里的人看得到访问密码、登录令牌和对话 | 只在信得过的网络开；在外面先连 Tailscale、WireGuard 这类加密隧道 |
| SSH 端口转发进来的 | 网页把 `ssh -L` 这类不加头的转发当成本机：不要密码，能改掉访问密码 | 这条路只给自己用 |
| 扩展 | 以你的身份跑，不进沙盒。批给它的能力，它拿去做什么 Miyu 不审。批了「使用模型供应商的 key」的，拿到的是那一家 key 的原文，你换了 key 也跟着拿到新的 | 来路不明的不装，见下面「装社区包之前」 |
| 脚本、MCP 服务 | 开放权限下的脚本、所有 MCP 服务以你的身份跑，不进沙盒 | 只接你看过代码、信得过的 |
| 群里的人用到记忆和知识库 | 群里的 AI 照样有 `remember`、`forget`、`memory_search` 和写知识库的工具，用的是和你同一份记忆、你的知识库 | 给群一个关掉它们的预设，见 [接入通讯平台](heads/im.md#记忆和知识库) |
| 绑定成你本人的平台号 | 它的私聊照你的权限级别办，不关起来。号被别人拿到，就是在这台机器上以你的权限做事 | 只绑你自己用、保管好的号 |
| 抓不下来的网页 | 网址交给 Exa、Firecrawl、Parallel 代抓；只有你内网认得的主机名，连不上时也一样交出去。联网服务选了 DeepSeek 的，要抓的网址先交 DeepSeek | 见 [联网搜索和抓网页](web-search.md#隐私) |
| 撤销 | 只退对话，AI 改过的文件、跑过的命令不回去 | 用 git 这类版本管理，或者先备份，见 [会话](sessions.md#撤销恢复重做) |
| 花费 | 没有自动的花费上限 | 看用量，设请求次数上限，见 [让 AI 自己接着干](automation.md#没人看着时) |

## 哪些东西会离开这台机器

| 发给谁 | 发什么 | 什么时候 | 不想发 |
|---|---|---|---|
| 模型供应商 | 系统提示词、人格、对话、附件、工具的结果、想起的记忆、带进来的知识库片段 | 每次请求模型 | 用本机跑的模型服务，见 [模型](models.md) |
| OpenCode Go 的额度接口（`https://opencode.ai/inference/go/v1/usage`，`providers.<编号>.quota.url` 改了的照改的） | 一次 GET，带着这一家的 key，不带对话 | 会话用的是 OpenCode Go 时，每轮结束在后台问一次。同一家 60 秒内问过的不再问；问不到的不报错 | 不用 OpenCode Go |
| 日常池的模型（没配的是会话的模型） | 要整理的那段对话、相关的记忆，配置里引用的密钥原文和常见的 key 写法先遮掉 | 自动记、整理记忆时 | 预设里关掉人格记忆，见 [记忆](memory.md#不让它记) |
| 远程的语义模型 | 记忆、对话、知识库的字 | `models.embedding` 写了远程模型时 | 用本机的 `embed`，见 [附加软件](addons.md#内置语义模型-embed) |
| 联网服务（你选的那一家，用不了时自动试的几家） | 搜的词 | AI 搜网页时 | 关掉「网络搜索」，见 [联网搜索和抓网页](web-search.md#关掉) |
| 代抓服务（Exa、Firecrawl、Parallel；联网服务选了 DeepSeek 的还有 DeepSeek） | 网址 | 自己抓不下来的网页；选了 DeepSeek 的，AI 每次抓网页先交它 | 关掉「抓取网页」 |
| 网页所在的网站 | 一次普通的访问 | AI 抓网页时；时间线里的链接画成卡片时 | 同上 |
| 远程的 MCP 服务 | AI 调它的工具时给的参数 | 调用时 | 不接、在预设里关 |
| 软件源 `https://miyu-agent.github.io/packages/` | 取索引、下包文件 | `miyu pkg update`；搜、装、升级时本机的索引超过 24 小时 | 不用软件源 |
| models.dev | 取模型目录和各家图标 | 核心在后台，手上那份旧过 `models.catalog.every`（默认 `24h`） | `miyu config set models.catalog.update false` |
| 汇率服务（Frankfurter，备用 open.er-api.com） | 币种和日子，不带用量 | 用量的金额要换成别的币种时 | 不看换算后的金额 |
| GitHub | 问最新的发行版、下载 | 你敲 `miyu upgrade`、跑安装脚本时 | 不敲 |
| 通讯平台 | AI 的回复和它发的文件 | 接了通讯平台时 | 不装 `im` |
| 扩展自己连的地方 | 看那个扩展 | 批了「联网」能力的扩展 | 不批、不装 |

Miyu 没有遥测：不往任何地方报告你的用法、对话、报错，也不发崩溃报告。终端崩了留的调用栈只写在本机的缓存目录里。

## 几种用法怎么设

### 看一个不熟的仓库

1. 用只读开会话：

   ```bash
   miyu ask -C ~/src/unknown-repo --permission read-only "讲讲这个仓库是做什么的"
   ```

   ```powershell
   miyu ask -C $HOME\src\unknown-repo --permission read-only "讲讲这个仓库是做什么的"
   ```

   终端、网页里开了会话以后按 `Shift+Tab` 切到只读。
2. 仓库里的 `AGENTS.md` 每轮都交给 AI，里面写什么 AI 都会读到。只读下它改不了文件，但照样能读你的盘、能联网。
3. 仓库带了 `.miyu/config.toml` 的，`miyu ask` 会说「项目配置 … 尚未信任，本次没有使用」。它只能收紧，信不信都不会放宽权限。
4. 要 AI 动手改之前，先 `git status` 看干净，改完照 diff 看。

见 [权限和沙盒](permissions.md)、[会话](sessions.md)。

### 长时间没人看着跑

1. 定时任务每次新开的会话没人看着：要确认的事一律不做，AI 也不能问你。受保护的命令那几类因此不会跑。
2. 给它一个只开要用的功能的预设，用 `--preset` 指定。
3. 在那个预设里限一轮最多请求几次模型：

   ```toml
   [limits]
   unattended_steps = 100
   ```

4. 只要它读、不要它改的，设 `permission.start_read_only true`，新开的会话就是只读。
5. 隔一阵看用量：终端 `/usage`，网页设置的「用量」页。

见 [让 AI 自己接着干](automation.md#没人看着时)、[人格和预设](personas-presets.md)。

### 接到群里

1. 群里的会话本来就关起来，不用另外设权限。
2. 给群一个收紧的预设，在 im 后台页「群聊默认值」上选它：关掉人格记忆，关掉 `kb_save`、`kb_edit`、`kb_delete`，只留群里用得着的工具。
3. 「谁是你本人」只填你自己的号。
4. 名单以外的群、人出厂只记录不回，别随手打开「陌生群」「陌生私聊」的「是否回复」。
5. NapCat 和 im 在同一台机器上的，把连接的监听地址改成 `127.0.0.1`。出厂是 `0.0.0.0`，只靠 Token 挡。
6. 有内网域名的，写进 `net.internal_domains`，别人让 AI 抓网页时不去。
7. 给群里的人设用量上限、限流，见 [接入通讯平台](heads/im.md#限额和用量)。

### 放到服务器上

1. 用一个专门的系统用户跑核心，数据根放 `/var/lib/miyu`，不用某个人的家目录。仓库里的系统服务样例只有 Linux 的（systemd、OpenRC、runit、dinit）。
2. 网页只听 `127.0.0.1`（出厂就是），从自己的电脑经 `ssh -L` 或者 Tailscale、WireGuard 连进去用。
3. 要别的设备直接打开的，先设一个长的访问密码，再开局域网访问。不要把网页的端口直接放到公网上。
4. 经反向代理的，代理要加 `X-Forwarded-For` 这类转发的头，不加的会被当成服务器本机、不要密码。

见 [常驻和服务器](service.md#放到服务器上)。

### 装社区包之前

1. 看清它是什么：

   ```sh
   miyu pkg info weather
   ```

   看「来源」（官方、社区、本机文件）、「上游」仓库、「需要的能力」。
2. 能力要得比它说的用处多的，不装。例如一个查天气的包要「读取会话」「写入文件」。
3. 社区的包没人审过。装之前去「上游」那个仓库看一眼代码和有没有人用。
4. 别人直接发给你的文件夹、`.miyu` 文件没有签名，比社区的包还少一层核对。
5. 装了以后 `miyu pkg check <编号>` 能看出包里的文件被改过没有。

见 [软件包](packages.md#能力)。

## 发现安全问题

不要在公开的 issue 里贴怎么利用的细节。先只说「发现了一个安全问题，想私下报告」，等项目回复联系的办法。
