# Web UI

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Using Miyu in a browser: what each part of the page is and what it does, all on this page. For deploying on a server and reverse proxies, see [Keeping it running, and servers](../service.en.md). Chinese version: [web.md](web.md).

## Opening it

```sh
miyu web
```

If the web app `miyu-web` is not running, `miyu web` starts it first (and the core too, if that is not running), then hands it to the system browser, and the terminal prints one line: "opened in browser: <url>". The default address is `http://127.0.0.1:8300`.

What hands it to the browser: on Linux `xdg-open`, on macOS `open`, on Windows `cmd /C start "" <url>`. If that command cannot start, or fails and exits within 3 seconds, the hand-off counts as failed and it prints "miyu: cannot open a browser; open the address above". The address is still printed above it.

| Option | What it does |
|---|---|
| `--port <port>` | Which port to listen on this time; only counts when the web app is not running. Shipped value `8300` |
| `--print` | Print the address without opening a browser |
| `--format <text\|json>` | Output format; `json` also does not open a browser |
| `--reset` | Open with a one-time code to reset the access password |
| `--logout` | Make every browser sign in again |
| `--package <id>` | Open this package's page under "Dashboards" directly |
| `--session <id>` | Open this session directly |
| `--settings [<page>]` | Open Settings directly; `access` opens "Access" under "General" |
| `--stop` | Stop the web UI; the core keeps running. Must be used on its own |
| `-h`, `--help` | Print help |

Other ways to open it:

- With the tray installed, click "Open Web Interface" in the tray menu. On Linux and Windows a left click on the tray icon also works; see [Tray](applet.en.md).
- If the browser's address bar offers "Install", you can install the web UI as its own window, named Miyu.

Ports:

- If you never set a port and 8300 is taken, it tries 8301 to 8309 in turn and uses the first free one. If all are taken, or the port you set is taken, it reports "port 8300 is in use"; pick another with `--port`.
- Use `web.port` for a fixed port and `web.listen` for the listen address; see "Access and security" below.

When no browser is connected to the web app and it is not serving files such as images or videos, it exits on its own after `web.idle_seconds` seconds (default `600`), and the next `miyu web` starts it again. It does not exit while LAN access is on. `0` means it never exits; the settings page does not show this item, so change it with a command:

```sh
miyu config set web.idle_seconds 0
```

To close only the web UI and keep the core running: `miyu web --stop`. When the web app runs in the foreground (for example `miyu-web serve` started on a server as in [Keeping it running, and servers](../service.en.md)), press `Ctrl+C` to stop it; on Linux and macOS it also stops on `SIGTERM`.

### Phones and other devices

After you turn on LAN access (see "Access and security"), open this computer's address on a phone or tablet and sign in with the access password. When the window is narrower than 836 pixels, the page switches to its narrow layout:

- The left column folds away. A menu button "Expand sidebar" sits in the top left corner; tap it and the column slides in from the left, swipe left to fold it.
- The right sidebar covers the conversation, with a close button at the top; swipe right to fold it.
- Buttons that normally appear only on hover (copy and edit under your messages, copy and redo at the end of a turn, multi-select in the left column) are always visible.
- On a page opened over plain `http` on the LAN, the browser gives no clipboard access, and a failed copy shows "Can’t copy here. Select the text and copy it manually."

## First run

The first time you open the web UI, first-run setup covers the whole page, one step per screen. The row of small boxes at the top is the step bar. Press `Enter` for the next step, "Back" to go back, and use the top right corner to switch light and dark.

1. Welcome: "Miyu". Click "Start".
2. Interface language: 中文, English, 日本語, or "Follow system".
3. Model: "Select a model provider". Pick one, fill in the key, "Test connection", pick the default model. How to fill these in: see [Models](../models.en.md).
4. Persona: "Create persona". Fill in the name, avatar and detailed prompt. You can "Skip"; if you skip, no persona is used.
5. Appearance: "Appearance". Choose light or dark, main color, color scheme and theme. If you skipped the persona in the previous step, this step is skipped too.
6. About you: "How the AI knows you". Fill in "Preferred name" and "Additional details (optional)"; above them is a "Reply language (optional)" row. If both are empty, the button is "Skip".
7. Preset: "Select preset". Click one; "Custom" lets you tick features yourself.
8. Semantic model: "Turn on the built-in semantic model?". "Yes (recommended)" downloads and installs it; "No" uses keyword search only. If the package source does not have this package and it is not installed, this step is absent.
9. Other devices: "Use on other devices". Choosing "Open" first asks you to set an access password; once set, it shows the address and QR code for other devices. Choosing "Don't open" means only this computer can open it. A page not opened through `miyu web` does not have this step.
10. Done: lists the chosen model, persona and preset. Click "▶ Start chatting" to enter a new session.

If you sign in from another device and are setting the access password for the first time, the first step is "Password", then it continues from the interface language.

When you finish, it writes `ui.welcomed = true`, and neither the terminal nor the web UI shows first-run setup again. Changing the interface language reloads the page and continues from that step; if you close the page midway, it starts over next time. To go through it again:

```sh
miyu config set ui.welcomed false
```

Then reload the page. The persona, preset and appearance can all be changed later on the settings page.

## Page layout

On a wide screen there are three columns: the left column, the conversation area and the right column.

### Left column

From top to bottom:

- Avatar and name: the persona of the session you are viewing, with "Online", "Connecting" or "Offline" under the name. Click the avatar to open this persona's edit card.
- Three rows: "New session", "All sessions", "Projects". When a package adds an entry, a "More" row appears below; click it for a pop-up menu.
- Three sections: "Pinned", "Projects", "Sessions". Click a section header to fold or unfold it. "Sessions" is grouped by time: Recent, Past 7 days, Past 30 days, Older. Sessions opened by shell integration form their own group "Terminal integration"; imported archives form their own group "Archived". At most 20 are listed; "View all" below goes to the all-sessions page.
- The bottom row: the gear opens Settings, and the button next to it switches between light and dark.

One session per row. The mark on the left says its current state: a spinner while running, "Waiting for you", "Interrupted, waiting for input", and a dot for unread. Subagent sessions hang under the session that dispatched them; finished ones fold into "N done".

Hover a row and "⋮" appears on the right. Its menu has: Pin (or Unpin), Move to project, Remove from project (only for sessions in a project), Copy session ID, Rename, Export…, Delete. Delete deletes at once, without asking again.

- Multi-select: hover the "Sessions" header to reveal the multi-select button. Click it and each row gets a checkbox in front; `Shift`-click selects a range, and the header changes to "N selected" with select all, delete and exit. `Esc` leaves multi-select.
- Drag: drag a session onto the "Pinned" section to pin it, drag it back down to unpin, drag it onto a project to move it in. `Esc` cancels while dragging.
- Width: drag the right edge of the left column to change its width; double-click to restore the shipped width. This device remembers it.
- Fold: the button in the top left corner folds and unfolds the left column. Once folded, move the pointer to the left edge of the window and the column floats out.

### Conversation area

- The top left shows the session title, with the project name in front for sessions in a project. Click the title for a card: session ID (click to copy), persona, preset, workspace. Click the persona or preset row to switch; it asks first and compacts the context before switching. The pen on the persona row opens its edit card; the workspace row changes the working directory.
- For a subagent session, the levels above it are listed in front of the title; click one to go to that level. Right above the input box, "Back to “…”" returns to the session that dispatched it.
- In the middle is the timeline; see "Timeline" below. After you scroll up, "Jump to bottom" appears at the bottom.
- A jump bar runs along the right side of the conversation area: a short dash for each message you sent. Move the pointer close to list every message; click one to scroll to it.
- The top right corner holds the right column's toggle, "Expand right sidebar".
- Both side edges of the conversation column can be dragged to change its width; double-click to restore the shipped width.

In an empty session (before your first message), three buttons sit above the input box: "Select persona", "Select preset", "Set workspace". Anything you do not click uses the default. If the default preset or persona cannot be used, the input box is locked and says "Select a preset" or "Select a persona"; you can type only after choosing one.

When you choose a working directory ("Set workspace", a project's "Workspace folder" and the like), the web UI opens the system's folder picker on this computer, one at a time:

| System | What it uses |
|---|---|
| Linux | Tries `zenity`, then `kdialog`; if neither exists or neither can reach the display, falls back to a folder browser drawn by the page |
| macOS | The folder picker of `osascript`; if that fails, falls back to a folder browser drawn by the page |
| Windows | The PowerShell folder picker, on top of other windows |

### Right column

Click the toggle in the top right corner to open the right sidebar, a stack of cards:

| Card | What it lists | Clicking does |
|---|---|---|
| To-do | The AI's to-do list, with "N done" folded | |
| Background tasks | This session's background commands and subagents, with subagents they dispatch nested below; "Stop" and "Stop all" | Background commands: "View output"; subagents: open their session in the main area |
| File changes | Files this session changed, searchable | Shows the diff of this change, "Previous file", "Next file", "Open large view" |
| Shown files | Files the AI showed you with `show` | Opens it in the right column (the preview panel) |
| Scheduled tasks | Scheduled tasks attached to this session | |

When the window is not wide enough, the right column covers the conversation; click outside it or press `Esc` to fold it. The order of the cards, whether each is on, and how many rows each shows at most are set on the settings page under "Packages", in the "Web" section, in "Right sidebar". The left edge of the right column can be dragged to change its width.

The preview panel is where the right column shows files. Its top row:

- A "Preview" / "Source" switch (shown only when both exist).
- The title; click it to list everything shown so far.
- Copy, download, maximize, close. If you came in from the right sidebar, the top left corner is a back button.

Markdown is laid out the same way as answers; code gets line numbers and highlighting; HTML runs directly in an isolated frame without network access; images can be zoomed with the scroll wheel and dragged; PDFs use the browser's own viewer. With an extension that has UI blocks installed, two tabs appear at the top, "Workspace" and "Panel"; the panel holds what extensions put there.

After the right sidebar is turned off under "Packages" on the settings page, the top right corner shows a toggle for the "Preview panel" instead, and the button gets a dot when a new shown file arrives.

## Input box

| Key | What it does |
|---|---|
| `Enter` | Send. Also works while the AI is answering: the message queues, and the status line lets you "Withdraw" it |
| `Shift+Enter`, `Ctrl+J` | New line |
| `Esc` twice (within 1.5 seconds) | Interrupts the AI while it answers; when idle, clears the input box, and pressing `↑` while it is empty brings the text back. In a memory-tidying session it stops the tidying |
| `↑`, `↓` | Browse messages you sent |
| `Ctrl+R` | Input history list, searchable; in the list `Tab` shows the full text and `Enter` puts it in the input box |
| `Ctrl+S` | Stash the message in the box; press again with the box empty to take it back. On a Mac it is also `Ctrl+S`; `⌘S` does not count |
| `Tab`, `Shift+Tab` | Switch the permission level. While the command, `@` or `$` list is open, `Tab` belongs to the list |
| `/` | When focus is not in any input box, puts focus back in the input box |
| `Backspace` | With the cursor at the very start, removes the last attachment |
| `Ctrl+,` (`⌘,` on a Mac) | Open Settings |

The command, file, skill, session and history lists all work the same way: `↑` `↓` to move, `Enter` to choose, `Esc` to close.

`Ctrl+,` and `⌘,` depend on the device that opened the web UI: browsers on Mac, iPhone and iPad take `⌘,`, others take `Ctrl+,`. In forms on a package's full page, both `Ctrl+S` and `⌘S` save.

### Slash commands

Type `/` to pop up the command list. It filters as you type, `Tab` completes, `Enter` runs. The most used ones:

| Command | What it does |
|---|---|
| `/new` | New session |
| `/sessions` | Session list, optionally with a search term |
| `/stop` | Interrupt this turn and stop this session's background commands, subagents and loop |
| `/undo` | Undo the last turn |
| `/redo` | Drop the last turn and run the same message again |
| `/compact` | Compact the context now |
| `/model` | Change this session's model |
| `/persona`, `/preset` | Change persona, preset |
| `/workspace` | Change the working directory |
| `/settings` | Open the settings page |
| `/help` | See the keys and all commands |

All commands: see [Slash commands](../commands.en.md).

### @ files and $ skills

- Type `@` to pop up a file list, searched from the session's working directory. `Tab` enters a folder, `Enter` chooses. Images and the like become attachments; other files become a `[file name]` block in the box, replaced by the path when sent. Backspace deletes the whole block.
- Type `$` to pop up the skill list. The skills you choose go to the AI along with this message; one message can pick several.

### Attachments

- Drag files into the window, paste into the input box, or choose with `@`. On touch devices, the input box has a paper-clip button "Add attachment".
- At most 10 at a time; each at most 20 MiB, images at most 5 MiB and no more than 8000 pixels per side.
- For files over the limits, the web UI looks for the original file on this computer. If found, it hands only the path to the AI, and the card in the box is marked "Path"; if not found, it is marked "Not found", and you click it to fill in the full path.
- Finding the original file goes by name, size and modification time: first the session's workspace, then Downloads, Desktop, Documents, Videos, Pictures and Music under your home folder, and finally the whole home folder. It skips folders starting with a dot, `node_modules`, `target`, the macOS Library and the Windows `AppData`, and searches until the time limit. On Linux with `plocate` installed, and on macOS, it first asks the system's existing index (`plocate`, Spotlight), which answers at once and also finds files on external drives. Windows has no index to ask, so it can only search folder by folder; what it cannot find is "Not found".
- Files inside the data root (default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`) cannot be attachments.

Details: see [Sessions](../sessions.en.md#giving-the-ai-files-and-images).

### The row under the box

| Position | What it is | Clicking does |
|---|---|---|
| Left | Permission level "⏵⏵ Full access" or "⏸ Read-only" | Switches to the other level; see [Permissions and sandbox](../permissions.en.md) |
| Left | Model name | The model menu: two pages, "Models" and "Model pools", `Tab` switches pages. For models with thinking levels, pointing at one expands "Thinking effort" to the right |
| Middle | "Background tasks: N", only while something is running | Lists background commands and subagents, which can be stopped |
| Right | A ring, total tokens (cache hit rate in brackets), cost | A popover in three parts: context, total usage, cost |

The ring shows how much of the window the context fills. While compacting, after a failed compaction, or when over the window, this cell turns red and says "Compacting context", "Context compaction failed" or "Context exceeds the window". Extensions' UI blocks may also sit on the right.

The row above the input box: on the left the run status line (what the AI is doing, how long it has taken, retries); on the right the goal and the next loop time. To-dos sit above it.

## Timeline

Your messages are right-aligned bubbles. Each AI turn is one block: the persona's avatar and name on top, then the process, the answer and the closing line, in that order.

- Process: one line per step. Thinking shows "Thinking" or "Thought"; each tool line has an icon. The turn in progress stays expanded; when done it folds into a one-line summary, which you click to see each step.
- Click a step to expand its details: arguments and result. Commands show the command itself and its output; file edits show the diff, with additions and deletions in different colors. Files too large or not text show "File too large, diff not shown" or "Not a text file, diff not shown".
- When a script called tools, that step shows "Tools called by the script · N" below it; click to see each one.
- Subagents: the step that dispatched one has a robot icon. When it hands back its report, the timeline records a line "Subagent submitted its report · <title>"; click to read the report. A finished background command also records a line; click to see the command and output.
- Compaction and clearing the context each record a line: "Context compacted", "Context cleared".

Answers:

- Markdown layout: headings, lists, tables, formulas, footnotes. Code blocks are highlighted, with "Copy code" in the top right corner.
- mermaid code is drawn as a diagram.
- Image, video and audio addresses on a line of their own in an answer are drawn as cards. Click an image to enlarge it; below it are download, copy image, open in the right column (only for images the AI has shown) and open in a new tab.
- Web links on a line of their own are drawn as link cards, at most three per answer.

Buttons:

- Your messages: on hover, "Copy" and "Edit" appear below. Edit changes the text right in the bubble; `Enter` sends, `Esc` cancels, and the turn runs again with the new text.
- An AI turn: the closing line shows the time, endpoint/model, duration, usage and output speed, followed by "Copy" and "Redo".
- Edit and redo exist only on the latest turn, and not while the AI is answering.

### Confirmations and questions

When the AI needs you to confirm something or asks you a question, the whole input box turns into a drawer. What you typed in the box is kept and comes back once you answer.

Confirmation: the first line says what it wants to do ("Run command", "Write N file(s)", "Install or remove a package" and the like); protected commands are marked "Dangerous command". Below are two choices:

1. "Allow this time"
2. "Don't allow": write a sentence under "Reason (optional)", and the AI sees it

Keys: `↑` `↓` to choose, `Enter` to confirm. If it has a timeout, it shows "Auto-deny in …".

Questions: titled "… is asking", one question per page, `←` `→` to switch questions. A single-choice question is answered as soon as you choose; for multiple choice, `Space` ticks. "Type another answer" lets you write your own, and `N` adds "Notes". The last page is "Review", where `Enter` does "Submit".

`Esc` twice or "Cancel": closes the drawer and interrupts this turn. What you already answered stays on the timeline.

## Projects

A project groups sessions and gives new sessions in the group a preset working directory, persona, preset and a piece of extra prompt. Only the web UI has projects.

### Creating a project

1. Click the "+" on the "Projects" header in the left column (or the last card, "New project", on the "Projects" page of all sessions).
2. In "New project", fill in:

   | Field | Notes |
   |---|---|
   | Name | Required, at most 40 characters |
   | Description | At most 80 characters, shown on the project card |
   | Color | Pick one of twelve, or "+" for your own |
   | Workspace folder | Sessions created in the project work here; if unset, it is "Default workspace" |
   | Persona, Preset | "Default" follows the default in Settings |
   | Extra instructions | Every session in this project gets these instructions, at most 8000 characters |
   | Messages | Switch "Can message sessions outside this project", off by default |

3. Click "Create".

### Sessions in a project

- New: hover the project row to reveal "⋯" and click "New session in project"; or open the project page and click "New in project". The new session uses the project's workspace, persona and preset, and the top left reads "<project name> / New session".
- Putting an existing session in: drag it onto the project in the left column, or "⋮" → "Move to project". Taking it out: "⋮" → "Remove from project", or drag it back down among the sessions. Only main sessions you opened on this computer can go into a project; subagent sessions and chat-platform sessions cannot.
- A session moved into a project keeps its persona, preset and working directory. The extra instructions follow whichever project the session is in now and are added at the start of each turn; once moved out, they are no longer added.
- Typing `/persona` or `/preset` in a session in a project says "This session is in a project; the project sets its persona and preset".
- While messages are off, sessions in a project can only see and message sessions in the same project. Once on, they can message sessions outside the project too.

In the left column each project is one row; click it to expand all its sessions in place. While a project is folded and has running sessions inside, it shows `(N)` in front of its name.

### Changing and deleting

- Change: "⋯" on the project row → "Project settings", or "Project settings" in the top right corner of the project page. The form is the same as for creating; click "Save".
- Delete: "⋯" → "Delete project", then click "Delete"; or click "Delete project" twice in the bottom left of "Project settings". The sessions in the project are deleted with it and cannot be recovered.

Project page (click "Projects" in the left column, then a project card): "‹ All projects" at the top goes back, then the title and description, a block "Defaults for new sessions in this project" listing the workspace folder, persona, preset, extra instructions and messages, and below that the sessions in the project.

## All sessions

Open it with "All sessions" or "View all" in the left column; it takes the place of the conversation area. When the core supports projects, the top has two pages, "Sessions" and "Projects".

The "Sessions" page:

- Top: search, "Select", "New session", "Import session…".
- Filters: "All", "Running", "Unread". On the right, "Recent activity"; click it to switch to "Date created".
- The list is grouped by time. Sessions in projects are not listed here; see them on the project page.
- Multi-select works as in the left column: tick, `Shift` for a range, select all, delete.
- "Import session…" takes an exported `.zip`; imported sessions go into the last group, "Archived". Archives are read-only; opening one says "This is an archive. You can read it but not continue it". How to export: see [Sessions](../sessions.en.md).

`Esc` closes this page.

## Appearance

Appearance sits at the top of "General" on the settings page, in two groups:

- Theme: the "Mascot" row picks "None", "Deniro", or one that comes with an appearance package. When other themes are installed, an extra "Theme" row appears, a drop-down for shapes and materials (rounded corners, shadows, borders, fonts); the shipped one is "Default theme". When another timeline or answer style is turned on, an extra "AI output style" row appears.
- Color scheme: "Mode" picks "Follow system", "Light" or "Dark"; below it, one card per color scheme; "Main color" picks from candidate colors.

Shipped color schemes:

| Color scheme | Where the colors come from |
|---|---|
| Automatic (shipped) | The session persona's main color if it has one, otherwise the desktop wallpaper, otherwise the default colors |
| Follow persona | The persona's chosen main color; if none, colors picked from its avatar |
| Follow wallpaper | This computer's desktop wallpaper, changing on the spot when you change the wallpaper. Not available when opened on another device |

The button at the bottom of the left column also switches light and dark.

"Follow wallpaper" first looks for the colors generated by matugen (Linux `$XDG_CACHE_HOME/miyu/matugen.json`, or `~/.cache/miyu/matugen.json` if that is not set; macOS `~/Library/Caches/miyu/matugen.json`; Windows `%LOCALAPPDATA%\miyu\matugen.json`). If there are none, it looks for the wallpaper image on this computer's desktop:

| System | Where it reads the wallpaper |
|---|---|
| Linux | The desktop settings of KDE, GNOME, XFCE, Cinnamon, MATE (recognized by `XDG_CURRENT_DESKTOP`; Unity, Budgie and Pantheon are read as GNOME); awww, swww, hyprpaper (under Hyprland), swaybg, wpaperd, waypaper; under X11 also feh and nitrogen |
| macOS | The file where the system stores the wallpaper setting; if that cannot be read, it asks System Events, which the first time pops up a dialog asking whether to allow it, and if you do not allow it, it cannot be read. HEIC wallpapers are converted to JPEG with the system's `sips` |
| Windows | `WallPaper` under the registry key `HKCU\Control Panel\Desktop`; if that cannot be read (for example with a slideshow), the copy Windows converted, `%APPDATA%\Microsoft\Windows\Themes\TranscodedWallpaper` |

Video wallpapers cannot be read. How it keeps up with wallpaper changes: it watches the wallpaper image and the settings files and picks colors again on any change (Linux uses inotify, macOS FSEvents, Windows ReadDirectoryChangesW). Tools such as hyprpaper and swaybg that change the wallpaper only through commands and write no file cannot be watched, and neither can switching to another wallpaper program; in both cases it looks again when the browser window regains focus.

Background image per persona: choose one under "Background" in the persona's edit card, and the conversation area of sessions using this persona shows it.

The only shipped theme is "Default theme". A "Pixel" theme also comes along, off by default; turn it on in the "Web" section of "Packages" on the settings page, then choose it under "Theme". The package source has community-made web appearance packages (starting with `webui-theme-`); once installed they appear under "Theme" and "Color scheme". How to install: see [Packages](../packages.en.md). After installing or removing an appearance package, the page says "Appearance "…" changed. Reload the page to apply it."

`/gallery` opens the skin gallery: a session that exists only on this page, with every kind of element laid out, for checking against when you change themes.

## Access and security

Pages opened on this computer with `miyu web`, or by opening `http://127.0.0.1:<port>` directly, need no password. Coming in from another device needs the access password.

The "Access" card at the very bottom of "General" on the settings page (`miyu web --settings access` goes straight here):

- The "Allow local network access" switch, with "On" or "This computer only" next to it. If you turn it on before setting an access password, "Set an access password" pops up first; set it and click "Set and turn on".
- While it is on, a few rows below:
  - "Listen address and port": `0.0.0.0` means every address of this computer; you can also enter just one of them. The port is used both on this computer and on the LAN. When you change it, the web UI moves over on the spot; when the port changes it says "The port is now …; this page stays connected".
  - "Access password": "Set" or "Change". Changing it from another device first asks for the "Current access password".
  - "On another device, open": a QR code and address, with "Copy"; if other network cards have addresses too, click "More addresses". Scan the code with a phone and enter the access password to get in. If other devices cannot connect on macOS, follow the hint and allow incoming connections for `miyu-web` in "System Settings → Network → Firewall → Options".

LAN access is plain HTTP; turn it on only on networks you trust. If you turn off LAN access on another device, that device disconnects at once.

The sign-in page on other devices, "Sign in to Miyu": enter the access password. If you tick "Stay signed in", this browser does not need it again for 30 days; if not, closing the tab means entering it again. If you forget the access password, run `miyu web --reset` on the computer where Miyu is installed; to make every browser sign in again, run `miyu web --logout`.

Not available on other devices (these are only for the computer where Miyu is installed):

- Choosing files with `@`, choosing a working directory for a session or project.
- Buttons that open a folder, which copy the path instead.
- The "Follow wallpaper" color scheme.
- Files over the attachment limits that are handed over as paths only.
- Attaching folders to the knowledge base, adding MCP servers that run local commands.

"LAN Access" and "Open on Your Phone…" in the tray menu do the same thing; see [Tray](applet.en.md). For the config keys for the listen address and port, and the limits of SSH port forwarding and reverse proxies, see [Keeping it running, and servers](../service.en.md#opening-the-web-ui-from-other-machines-and-phones).

## Notifications

When an AI turn finishes, a question is waiting for your answer, or something needs your confirmation, the browser shows a system notification:

- For the session you are viewing, only when this tab is not in the foreground; for other sessions, also in the foreground, silently.
- The title is the name of the session's persona, or "Miyu" without one; the body is "<session title> · Done", "… · Waiting for your answer" or "… · Waiting for your approval". Click it to go back to that session.
- When a scheduled task that opens a new session each time finishes, it shows "Scheduled task finished" or "Scheduled task didn't finish".
- Subagent sessions and one-off sessions do not notify.
- While the tray is running, the tray notifies for sessions not open in the web UI, and the web UI notifies only for sessions open in this tab.

The first time you send a message in the input box, the browser asks once whether to allow notifications. If you do not want them: deny it in the browser, or turn off "Notifications" in the "Web" section of "Packages" on the settings page. Once the tab is closed the web UI no longer notifies; install the tray to keep receiving them.

## What packages add to the web UI

Packages can add a few things to the web UI. They appear once installed and enabled, and go away when disabled:

- Dashboard pages: a full page of the package's own, listed under "Dashboards" on the settings page; click to open. A narrow bar runs along the top of the page with "Back" on the left; the address carries `#package=<id>`, so you can bookmark it or open it in a new tab. `miyu web --package <id>` opens it directly.
- UI blocks: a small piece of text and buttons placed by an extension (weather, build status and the like), shown on the start page of a new session, in the right column's "Panel", on the right of the row under the input box, or as a page of its own. When the program is not running it shows "Not running".
- Appearance: themes, color schemes, mascots; see "Appearance" above.

How to make these: see [Putting things on the interface](../../dev/ui-surfaces.en.md).

## Troubleshooting

| What you see | What to do |
|---|---|
| "port 8300 is in use" | Pick another with `miyu web --port <port>`, or change `web.port` |
| "miyu: cannot open a browser; open the address above" | Open the printed address yourself; on a machine without a desktop use `miyu web --print`. On Linux the hand-off to the browser relies on `xdg-open`; install it if missing |
| "Can't reach the web app" "The web app isn't running." | The web app exited after idling; run `miyu web` in a terminal |
| "Still connecting. …" | If this device uses a proxy or VPN, turn it off or let this address connect directly |
| "Core is outdated" | Upgrade the core, then reload the page |
| "Wrong access password" | Enter it again; if you forgot it, run `miyu web --reset` on the computer where Miyu is installed |
| "Too many attempts. Try again in N s" | Wait the number of seconds it says |
| "No access password yet" | Set it with `miyu web --settings access` on the computer where Miyu is installed, then sign in here |
| "This link was already used or has expired: run miyu web in the terminal again" | Do that; a link with a ticket is valid for 60 seconds and works only once |
| "Your sign-in expired. Enter the access password again" | Enter the access password again |
| "No password is needed on this computer, but the core couldn't be reached this time…" | Run `miyu web` in a terminal to see why |
| "Appearance "…" changed. Reload the page to apply it." | Reload the page |
| "Can’t copy here. Select the text and copy it manually." | Pages opened over plain `http` on the LAN get no clipboard; long-press to select the text and copy it |

The web UI's log is at `~/.miyu/var/log/webui/web.log`. For anything else, see [Troubleshooting](../troubleshooting.en.md#the-web-ui-will-not-open).
