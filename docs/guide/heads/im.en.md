# Connecting chat platforms

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Connect Miyu to QQ or Telegram and talk to the AI in private chats and groups: from installing and connecting accounts, to who can call the AI, what the AI can do in groups, records and usage. Chinese version: [im.md](im.md).

## What it is

The package `im`, called "Connect Messaging" in the interface. It is a resident extension with its own dashboard page (a web page). The `miyu im` command exists only once it is installed. It can be installed on `linux-x86_64`, `macos-aarch64` and `windows-x86_64`; there is no Linux aarch64 build, and there `miyu pkg install im` reports "Not available for this system.".

| Platform | How it connects | What you need to prepare |
|---|---|---|
| QQ | OneBot v11 reverse WebSocket: im opens a port and the OneBot implementation connects to it | A separately installed OneBot v11 implementation, for example NapCat or SnowLuma, signed in to the QQ account the AI will use |
| Telegram | The official bot interface (Bot API); im connects out and opens no port | A bot created in BotFather, and its token |

One im can connect several QQ accounts and several Telegram bots at once; each account is one "connection".

## Installing and opening

1. Install:

   ```sh
   miyu pkg install im
   ```

   The confirmation screen lists these under "Capabilities"; answer `Y` to approve them all at once: Provide tools, Drive sessions, Speak for platform users, Read sessions, Write session records, Network, Call other packages, Add to the system prompt, Show things in the interface, Sign in pages on this machine. What capabilities are: see [Packages](../packages.en.md#capabilities).

2. When asked "Enable 'im' now? [Y/n]", answer `Y`. If you answered no, run this later:

   ```sh
   miyu im start
   ```

   Once it is on, the core starts it every time the core starts. `miyu im stop` turns it off, after which the core no longer starts it.

3. Open the dashboard page, any of three ways:

   ```sh
   miyu im web        # open in a browser; starts im first if it is off
   miyu pkg page im   # same as above; add --print to print only the URL
   ```

   Or type `/im` in the web UI to open it in a new tab.

The dashboard page opens at `http://127.0.0.1:8302/` by default. The link `miyu im web` gives is valid for 1 minute. Opening it on this computer, or jumping over from the web UI or the terminal, needs no sign-in.

The column on the left of the dashboard page: "Home", "Chat settings", "Chat records", "Statistics", "Usage limits"; under "AI", "Personas", "Presets", "Models" (the same data you change on the settings page); under "Software", "Installed", "Dashboards", "Get software"; at the bottom, "Settings".

## Connecting QQ

First install a OneBot v11 implementation (NapCat, SnowLuma and the like) and sign in to the QQ account the AI will use. It must be able to create a WebSocket client, that is, a reverse WebSocket: it connects to im. im does not connect to it.

1. On the Home page of the dashboard, click "New connection", choose "QQ" (labelled "OneBot (NapCat and others)" below), and click "Next".
2. "Create a reverse WebSocket in your OneBot app": the page gives an address, for example `ws://127.0.0.1:8301/ws`. Click "Copy", create a WebSocket client in NapCat's network panel, and enter this address. Click "Done, next".
   - If NapCat is on another machine or in Docker, replace `127.0.0.1` with this machine's address.
   - Change the port right in the address. It must be between `1024` and `65535` and must not clash with another connection or the dashboard page's port. The first connection defaults to `8301`; later ones count up from there.
   - The path can be `/ws` or `/onebot/v11/ws`.
3. "Get the reverse WebSocket token": NapCat most likely generated a token when it created the reverse WebSocket. Paste it here and click "Save and connect". A connection without a token refuses NapCat when it connects.
4. "Your QQ number": enter your own QQ number so the AI recognizes you in private chats and groups (see "Who you are" below). If you do not want to, click "Skip".
5. "Waiting for it to connect": a few seconds after you save on the NapCat side. Once connected it says "Connected", with a line below giving the bot's number and the connected implementation, for example "Bot 10001 · connected through NapCat 4.8.0".

Once connected, the "Connections" column on the Home page has one card per bot: avatar, name, "QQ · <implementation> <version>", "<number> · connected N min". A disconnected card stays and says "disconnected N min, reconnecting". If a token is set but no account has connected yet, the card is "Waiting for NapCat", showing the port. To check from the command line:

```sh
miyu im status
```

When connected it prints "NapCat connected: <implementation> <version>, bot <number>"; when not, it prints "NapCat is not connected" and "NapCat address: ws://127.0.0.1:<port>/ws".

The gear on a card is "Connection settings":

| Field | Notes |
|---|---|
| Listen address | Default `0.0.0.0`: other machines and Docker can connect too, and strangers are kept out by the token. `127.0.0.1` accepts only this machine. Must be an IP |
| Reverse WebSocket port | The port NapCat connects to |
| Reverse WebSocket token | Leave empty to keep it unchanged |
| Address to enter in the OneBot app | The address built from the fields above, which you can copy |

Changes need no restart; NapCat is checked against the new values the next time it connects. When there is more than one connection, a "Remove this connection" button appears below; it takes two clicks to remove.

Connecting several QQ accounts: one OneBot implementation and one connection per account, each with its own port and token. Go through "New connection" again for each one.

## Connecting Telegram

1. In Telegram, find `@BotFather`, send `/newbot`, follow the prompts to choose a name and username, and note the token it gives you.
2. On the Home page of the dashboard, click "New connection", choose "Telegram" (labelled "Bot API" below), and click "Next".
3. "Create a bot in BotFather": paste the token into "Token". Choose one of three for "Proxy":
   - "Follow network settings": follows the core's environment variables `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY` and so on; see [Web search and fetching pages](../web-search.en.md#proxy).
   - "Direct": no proxy.
   - "Custom": write `http://host:port` or `socks5://host:port`; `https://` is accepted too.

   If your network in mainland China cannot reach Telegram, choose a proxy that works. Click "Check and connect".
4. "Check results": whether the token works (with the bot's name, username and number), whether Telegram is reachable, and whether privacy mode is on. Click "Next".
5. "Your Telegram ID": enter your numeric ID on Telegram, or "Skip".
6. "Connected".

The token is stored in the secrets file `~/.miyu/etc/private/secrets.toml` (the data root defaults to `~/.miyu`, on Windows `%USERPROFILE%\.miyu`); the config holds only a reference to it. The gear on the connection card lets you replace the token ("Set; leave empty to keep. Paste the new one if you changed it in BotFather"), change the proxy, and see privacy mode.

### Privacy mode

Bots created by BotFather have privacy mode on by default. While it is on, in groups the bot receives only replies to the AI and commands sent to it; it does not even receive `@` mentions. If you only use it in private chats, you can ignore this. To call it in groups:

1. In Telegram, send `/setprivacy` to `@BotFather`.
2. Pick this bot, then pick `Disable`.
3. For groups it is already in, remove the bot from the group and add it back for this to take effect.

You can also make it a group admin; admins receive every message. After changing it, click "Check again" in the connection settings. Groups where privacy mode is on are marked "Privacy mode" on their session card.

### Other things to know on Telegram

- Only one program can receive messages per token. If the connection card says "Receiving elsewhere too", another program is also using this token.
- Type `/` in a private chat to list Miyu's commands. The `-` in command names is replaced by `_`, for example `/clear_memory`.
- In groups with topics turned on (marked "Topics" on the session card), the whole group is one session, and the AI answers in the original topic.
- If you run your own Bot API server, put its address in `im.tg.api`.

## Who you are

Tell Miyu which account on a platform is you. This is kept in the core's config, and three places change the same data:

- The "Your QQ number" and "Your Telegram ID" step when creating a connection.
- On the dashboard page, "Settings → Bind → Your platform IDs": "New binding" asks you to pick a platform first, then the number; "Unbind" removes it. QQ numbers are digits only; on other platforms no spaces or colons, at most 48 characters.
- On the settings page (type `/settings` in the terminal or the web UI), "Advanced → Platform accounts", or edit `~/.miyu/etc/config.toml` by hand:

  ```toml
  [external.bindings]
  "qq:10001" = "owner"
  "tg:20002" = "owner"
  ```

Once set, this account:

- Has private chats that are not confined sessions; like sessions you open in the terminal, they follow the permission level. Things that need confirmation are not done, since chat platforms have no confirmation box. See [Permissions and sandbox](../permissions.en.md#sessions-on-chat-platforms).
- Gets a direct answer when it calls the AI in a group, skipping the reply judgement.
- Is not subject to rate limits, sleep hours or usage limits.
- Can use commands whose `access` is `admin`, and `/model`, `/persona`, `/preset` and `/loop` in groups.
- Has friend requests to the AI accepted automatically.
- Can have the AI send messages to other groups and private chats and search the chat records of all sessions.

After a change, im picks it up within 60 seconds at most.

## How sessions are split

Under one connection, each group is one session and each private chat is one session. When several people in a group call the AI at the same time, the session opens a few extra branches to answer in parallel; how many at most is the card's "Concurrent replies".

Each session has a card, on the "Chat settings" page of the dashboard. When there is more than one connection, first pick the connection in the drop-down next to the title. The wall has four sections:

| Section | Cards | What they cover |
|---|---|---|
| Defaults | "Group defaults", "Private defaults" | Fields not changed on group cards and private cards follow these |
| Not on the lists | "Other groups", "Other private chats" | Groups and people not on the lists. Shipped: no replies, recorded only |
| Group list | One card per group | Shipped: replies |
| Private allowlist | One card per person | Shipped: replies |

Click "New" to add a group or a person: first choose "Group" or "Private", then search the groups the AI is in or the AI's contacts, or type the number directly, and click "Add and set up". On QQ, people added to the private allowlist have their friend requests to the AI accepted automatically.

An empty field follows the next level down: group cards follow "Group defaults", private cards follow "Private defaults", and the default cards follow the core's settings (default persona `persona.default`, default preset `preset.default`, default model `models.chat`). A field that reads like "Same as group defaults (…)" shows in brackets the value it currently follows.

Shipped, groups and private chats differ:

| | Group | Private |
|---|---|---|
| When it replies | Reply judgement (see the next section) | Every message with text gets a reply; messages with only images or stickers are recorded only |
| Rate limit | 30 turns per 60 seconds; "Other groups" 5 turns per 300 seconds | 5 turns per 300 seconds; people on the private allowlist are not rate limited, shipped |
| Concurrent replies | 3 | One at a time |
| Group messages included when replying | 30 | — |
| Final message only | On | Off |
| Show numbers to the AI | On | On |

### The pages of a card

Click a card to open it:

| Page | What is on it |
|---|---|
| Overview | The "Reply" switch (when off, messages are only recorded); this session's statistics for today, 7 days and 30 days; "Recent decisions" (groups) and "Recent messages" (private): whether each message got a reply and why; the last and next time of the autonomous loop; at the bottom of listed cards, "Remove from group list" or "Remove from allowlist" |
| Persona and models | "AI persona", "Preset", "Extra prompt" (applies only to this session), "Chat model", "Context window", "Vision model", "Reply judgement model", "Group messages included when replying", whether the AI sees the sender's number |
| Triggers | When it speaks, reply judgement, permissions; see the next two sections |
| Scheduled tasks | Create scheduled and repeating tasks for this session; see "Scheduled tasks" below |
| Rate and concurrency | "Rate limit" (messages / seconds), "Sleep hours", three usage-limit fields, "Concurrent replies" |
| Outgoing messages | How it talks, how it sends, long text; see "How messages are shown" |
| Plugins | Which plugins are on in this session |
| Pages added by plugins | Pages that enabled plugins bring to this session, for example "Group admin panel" |
| Live log | What the AI does in this session, one line per event: what it received, how it judged, what it thought, which tools it called, what it sent |
| View session | Only with the web UI installed: opens this session's timeline in a new tab, read-only |

When you change the persona, preset or model, existing sessions switch too: the model switches at once; the persona and preset first compact the context once and take effect from the next turn. If you clear the persona or preset on a card, existing sessions stay as they are; to switch back, pick one on the card.

To have the AI start fresh in a group: on the "Chat records" page of the dashboard, click into the group and use "Delete AI session" in the top right corner (two clicks). It deletes only the AI's context; the chat records stay.

You can also switch from within the chat: you and the people in the card's "Users allowed to run admin commands" can send `/model`, `/persona`, `/preset`:

| Form | What it does |
|---|---|
| `/model` | Says which one is in use, and how to use the command |
| `/model search [<keyword>]` | Lists the choices, numbered |
| `/model <number>`, `/model <name>` | Switches and writes it to this session's card |
| `/model default` | Goes back to following the default |

`/persona` and `/preset` work the same way. When anyone else sends them, they go to the AI as ordinary messages.

## When the AI speaks

### Private chats

People on the private allowlist and you get a reply to every message with text. Other private chats get no replies, shipped.

### Calling the AI in a group

In a group, these two count as calling the AI:

- `@` the AI.
- A message that starts with one of the "Extra trigger words". Case-sensitive. If calling its name should work, put the name in too; the persona's name is not added automatically.

Only replying to the AI's message without an `@` does not count as a call.

In groups where "Reply judgement" is off, the AI replies when called and not otherwise; with "Reply at random" on, messages picked at random also go to the AI.

### Reply judgement

While it is on (the shipped setting for groups), a message that meets any of the conditions below goes to a judge model for a score, and the AI replies only if the score passes the threshold; a message that meets none is recorded only:

| Condition | When it counts |
|---|---|
| Called the AI | See above |
| Follow-up | The same person speaks again within 30 seconds after the AI replied to them |
| Right after the AI spoke | Within 30 seconds after the AI sent a message, from anyone |
| Added while replying | The person the AI is replying to sends more; if it passes, it joins this turn |
| Picked at random | Anything that met no other condition, picked by chance. Off when shipped; when on, 5% by default |
| Possible violation | The message contains a flagged word; the judge model takes a look and replies when the severity reaches 7 (on a 0 to 10 scale) |

- When you, members of the allowlist, or people in the card's "Users who skip the judgement" call the AI, it replies directly without scoring.
- With "Judge even when called" (on when shipped) turned off, anyone who calls the AI gets a direct reply.
- The judge model is a model from the lite pool; if the lite pool is empty, it uses this session's chat model. To pick one, set "Reply judgement model" on the card.
- The threshold is `0.8` when shipped. It rises when the AI has just spoken, when the same person calls too often, and when the AI has replied a lot in this group lately; the card's "Restraint" controls the first of these.
- The threshold, the five weights, the follow-up and observation windows in seconds, and the violation severity threshold are under "Advanced" on the "Triggers" page.
- Flagged words are edited on the dashboard page under "Installed → Group admin → Settings"; messages from you are not checked.

The AI can also decide on its own to stay quiet this turn (the tools `qq_skip_reply`, `tg_skip_reply`).

### Autonomous loop

Every so often the AI glances at the group chat and decides on its own what to say or do. Off when shipped, and available only on listed group cards and private cards:

- Turn on "Autonomous loop" on the "Triggers" page.
- "Glance every": how often it glances when the AI has not set the next time itself, 7 minutes when shipped. When the AI sets it with `qq_glance` or `tg_glance`, its choice wins.
- "Messages per glance" (groups): how many messages not yet replied to since the last glance are passed in at most, 50 when shipped.
- "Extra prompt for the autonomous loop": what to do when glancing, such as what to watch for or collect.

If no new messages arrived in the group since the last glance, it does not call the model and schedules the next glance by the interval. In private chats it does not check for new messages when the time comes; when idle, it lets the AI decide whether to speak. During sleep hours it is postponed until they end.

When glancing in a group, one hint is appended at the end of that turn's request (not kept in the session history): nobody called the AI; it is looking back through the chat like a group member who mostly reads and rarely speaks; it speaks up only for something new: a question nobody answered (quoting that message when it speaks), following up with someone, or a real addition to the topic; it does not repeat what was already said here; staying silent is normal. In a private chat, the hint for that turn only says that nobody called the AI and that it is looking on its own; it does not urge it to say less. If the card has an "Extra prompt for the autonomous loop", it is included in both groups and private chats.

In a group, you and the people in "Users allowed to run admin commands" can send:

| Form | What it does |
|---|---|
| `/loop` | Turns on the autonomous loop for this group, replying "The autonomous loop is on for this group" |
| `/loop off` | Turns it off |

In groups `/loop` has only these two forms; with an interval or text it replies with a line of usage. It switches the card's "Autonomous loop" and does not go to the core. In private chats, `/loop` goes to the core and is the core's loop, with the same forms as in the terminal: a bare `/loop` turns on the core's autonomous loop, which runs with this private chat's session. That is a different thing from "Autonomous loop" on the private card, and turning it on does not turn on that field. For the core's loops, see [Letting the AI keep working on its own](../automation.en.md#loops-loop).

### Scheduled tasks

Listed group cards and private cards have a "Scheduled tasks" page: "New task" asks what to do and when ("Every day at", "Every", "Once at", "Cron (advanced)"). When the time comes, the AI does it in this session, also during sleep hours; it is skipped while "Reply" is off. Tasks can be paused, resumed, edited and deleted. Other ways to use scheduled tasks: see [Letting the AI keep working on its own](../automation.en.md#schedules).

### Making the AI stay quiet in a group

- Just not speaking: turn off "Reply" on the card. The AI keeps recording but does not speak.
- Speaking less: turn off the reply judgement so it replies only when called, or lower the "Rate limit".
- Quiet for part of the day: set "Sleep hours" to something like `23:00-07:00`, in this computer's local time. During that time it replies only to you and members of the allowlist.
- Ignoring the group entirely: "Remove from group list". The group then follows the "Other groups" card, which does not reply when shipped.

### Other cases where messages are only recorded

The reason shows in the card's "Recent decisions" and in the live log:

- "Rate limit reached, recorded only", "Usage limit reached, recorded only": you and members of the allowlist are not subject to these two.
- "Sleep hours, recorded only".
- "The AI is muted, recorded only", or "The AI is muted, will reply when unmuted".
- "Several people repeating the same line, recorded only": someone else said exactly the same thing within the last 2 minutes.
- The message that called the AI was recalled, so this turn stops.

## Who can use it

| List | Where to change it | What it controls |
|---|---|---|
| Group list | New group chat in "Chat settings"; `miyu im access group add <group number>` | The AI replies in listed groups, shipped |
| Private allowlist | New private chat in "Chat settings"; `miyu im whitelist add <number>`; config key `im.whitelist` | Can chat with the AI privately; friend requests to the AI are accepted automatically; not subject to rate limits or sleep hours; gets direct replies when calling the AI in groups |
| Users who skip the judgement | "Triggers" on the group card; `miyu im access skip <group number> add <number>` | Gets direct replies when calling the AI in this group |
| Users allowed to run admin commands | "Triggers → Permissions" on the group card | Counts as an admin in this group; see below |

Turn on "Reply" on the "Other groups" and "Other private chats" cards and the AI also replies to groups and people not on the lists.

`whitelist` and `access` on the command line change only the QQ lists, with plain-digit numbers.

### Requests

- Friend requests: from members of the allowlist and from you, accepted automatically. Others are left alone; handle them yourself in QQ.
- Invitations for the AI to join a group: left alone; handle them yourself in QQ.
- Someone asking to join a group: if the AI is an admin of that group, the group admin plugin is on, and "Rule to pass" is filled in on that group's "Group admin panel", the AI reviews the request against it: approve, reject, or leave it for a human. Anything uncertain or failed is left for a human. Without a rule, it does nothing.

### Admins in a group

People in "Users allowed to run admin commands" on the group card, in that group:

- Count as admins for commands whose `access` is `admin`. QQ group owners and group admins do not count unless they are in this field.
- Can use `/model`, `/persona`, `/preset`, `/loop`.
- Hear the reply when a command is refused; anyone else gets no reply when refused.
- Can have the AI delete group files.

Messages starting with `/` on a chat platform first go to the core as commands; anything it does not recognize goes to the AI as an ordinary message. Who can use which command is set by `commands.<command name>.access`; see [Slash commands](../commands.en.md#who-can-use-them).

In groups, the reply to a successful command is recalled after 3 seconds for the commands in `im.recall_receipts`, which are `clear` and `clear-memory` when shipped; replies to refused commands are always recalled; replies in private chats are not recalled. Change this on the dashboard page under "Settings → General → Commands whose receipts are recalled".

## What the AI can do in groups

Group sessions, and private chats that are not with you, are confined sessions that ignore the permission level:

- File tools reach only this session's workspace; skill folders are read-only.
- Commands run in a sandbox that also confines reads to the workspace. Commands cannot run on Windows, nor on Linux where the sandbox cannot confine Unix sockets.
- It cannot install or remove packages.
- Anything that needs confirmation is never done.

Details: see [Permissions and sandbox](../permissions.en.md#sessions-on-chat-platforms). Also:

- No subagents or goals, and it cannot ask people questions; see [Letting the AI keep working on its own](../automation.en.md).
- MCP servers are given only to local sessions when shipped; add `private` or `group` to `mcp.<server name>.venues` to give them here; see [Config key reference](../config-keys.en.md). Scripts and skills are given according to their `Venues`; see [Extending Miyu](../extending.en.md).
- There are extra limits when other people ask the AI to fetch web pages; see [Web search and fetching pages](../web-search.en.md#when-someone-else-asks-the-ai-to-fetch-on-a-chat-platform).
- What you wrote about yourself in Settings (`profile.about`) is not included in group chats.

### Memory and the knowledge base

The AI in groups still has the memory and knowledge base tools: `remember`, `forget` and `memory_search` use this persona's memory, the same one you use in the terminal; `kb_save`, `kb_edit` and `kb_delete` write to your knowledge base. A single sentence from someone in the group may get the AI to remember, change or dig something up.

To keep groups away from these, give the groups a preset that turns them off and pick it in "Group defaults" or on the group card:

```toml
# add to ~/.miyu/root/presets/group.toml
[features]
memory = false

[tools]
kb_save = false
kb_edit = false
kb_delete = false
```

How to write presets: see [Personas and presets](../personas-presets.en.md); memory: see [Memory](../memory.en.md); knowledge base: see [Knowledge base](../knowledge.en.md).

If you do not want it to act, turn off "Mute tool" and "Kick tool" under "Installed → Group admin → Settings", or turn off group admin under "Plugins" on that group's card.

### Built-in plugins

QQ comes with three plugins. Turn them on and off and change their settings under "Installed" on the dashboard page; turn them on and off per session under "Plugins" on the session card:

| Plugin | What it does |
|---|---|
| Identity | When someone borrows the name of you, the AI or someone in "People and numbers" but the number does not match, it reminds the AI that this is not that person |
| Lookups | Tools for searching chat records, fetching images and files, avatars, group members, group announcements, group files, contacts, activity ranking and token usage |
| Group admin | Muting, kicking, moderation records, flood handling, join approval, flagged words. Groups only |

Group admin adds a "Group admin panel" page to the session card: "Handle floods" (when the same person sends the same thing three times in a row, it recalls the repeats and mutes them; "Within seconds" is 60 when shipped, "Mute minutes" is 10), "Rule to pass" for "Join requests", and recent moderation records and a ranking.

## How messages are shown

The fields on the "Outgoing messages" page:

| Field | Shipped | What it does |
|---|---|---|
| Drop the final period | On | Removes one "。" at the end of a reply |
| Smart quoting | On | When 2 or more other messages followed the original, quotes the original |
| Smart mentions | On (groups) | Adds an `@` when quoting someone; with smart quoting off, `@` only when the reply comes more than 20 seconds later |
| React when it decides to reply | | After deciding to reply, first reacts to that message with an emoji, and removes it after replying (groups) |
| Send in several messages | On | Splits at full stops like a person chatting, sometimes at commas; long messages and messages with line breaks stay as one |
| Pause between messages | On | Pauses between messages according to the typing speed |
| Typing speed | 120 characters/minute | `20` to `600` |
| Send in order | On | Sends the next message only after the previous one went out |
| Final message only | On for groups, off for private chats | Does not send the in-between text the AI says while calling tools |
| Long text | Turn into an image | Long text over the threshold is drawn as an image; on QQ you can also choose "Forward as a bundle" |
| Long text threshold | 300 characters | |
| How this chat talks | | Describe how people here usually talk; the AI sees it every turn (groups) |

Drawing images needs the `render` package; without it, long text is sent in several parts; see [Add-ons](../addons.en.md). Sending stickers needs the `memes` package; it is on once installed and can be turned off per session under "Plugins" on the session card.

What the AI can see:

- Quotes: the quoted message.
- Images: in the message that called the AI and in the message it quotes, at most 4 each, each no larger than 20 MB. Other images, videos and files the AI fetches with `qq_fetch_media`. If the chat model cannot see images, the "Vision model" is used (`models.vision` when the card does not set one).
- Forwarded bundles (QQ): at most 4 expanded per message, nested 3 levels, at most 20 messages each, at most 500 characters per message.

## Limits and usage

Limits are by tokens, on three windows: the last 5 hours, 7 days and 30 days. Once reached, messages are recorded but not replied to; you and members of the allowlist are not limited.

- Per session: on the card's "Rate and concurrency" page, "5-hour token limit", "Weekly token limit", "Monthly token limit". Empty means no limit.
- Per person: the "Usage limits" page of the dashboard. The three fields under "Everyone" apply to everyone, with one person's use added up across all groups and private chats; people under "Set per person" use their own three fields, which replace "Everyone" as a whole set. Below, "Last 30 days" lists the people who used it; red means a limit is reached. Numbers can be written as `200k` or `1.5m`. Stored in `~/.miyu/etc/im/limits.toml`:

  ```toml
  [default]
  limit_5h = 2000000

  [[person]]
  id = "qq:10002"
  limit_month = 50000000
  ```

The "Statistics" page of the dashboard shows today, 7 days and 30 days: tokens and cost, request breakdown, by session, by person, by model, daily trend, messages by hour, and im's own CPU, memory and uptime. CPU and memory are measured with `ps`; Windows cannot measure them, so those two cells stay empty. With more than one connection, you can view by connection.

## Chat records

im stores messages from groups and private chats, group events (mutes, kicks, joins, leaves, recalls), and whether each message got a reply and why, in `~/.miyu/var/lib/im/records.db`. Images and files are recorded only as placeholders and platform IDs; their contents are not stored. Nothing is deleted on its own; it all stays until you clean it up.

The "Chat records" page of the dashboard: one group per connection, listing the groups and private chats that have records, with message counts and sizes. Click one to view its records; at the top you can search by keyword, number or name, and date.

Cleaning up: click "Clean up records", choose the venues and range ("Keep last 7 days", "Keep last 30 days", "Keep last 90 days", "Clear all", "Custom": which period and which sender), and click "Clean up" twice. Cleaned records cannot be restored; the AI's sessions and memory are not affected. The AI cannot delete records itself.

Importing QQ records migrated out of the old Miyu:

```bash
miyu im records import ~/qq-records.jsonl
```

```powershell
miyu im records import "$HOME\qq-records.jsonl"
```

Records already present are not imported twice; if any line is wrong, nothing is imported, and it prints which lines. Migration: see [Migrating from the old 0.7 version](../migrate.en.md).

## Plugins

im can install its own plugins:

- "Installed": installed plugins; turn them on and off, approve capabilities, change settings, see "Where".
- "Get software": im plugins in the package source, searchable and installable.
- "Dashboards": dashboard pages brought by enabled plugins.

### Sponsorships

`im-sponsor` ("Sponsorships") is an im plugin: you or a group's admins can have the AI record a sponsorship, and anyone can ask the AI how much someone has given in total, or for the ranking. Install:

```sh
miyu pkg install im-sponsor
```

It runs as soon as it is installed, appears under "Installed" on the dashboard page, and can be turned on and off per session. Change and delete records on its dashboard page. Other currencies are converted to the default currency at the exchange rate on the day of recording; the default currency is the config key `im-sponsor.currency`, `CNY` when shipped.

## `miyu im` commands

| Command | What it does |
|---|---|
| `miyu im start` | Start; after this the core starts it every time the core starts |
| `miyu im stop` | Stop; after this the core no longer starts it |
| `miyu im restart` | Restart |
| `miyu im status` | Run state and the NapCat connection |
| `miyu im web` | Open the dashboard page in a browser (the link is valid for 1 minute); starts it first if not started |
| `miyu im logs` | Print the runtime log; if standard error has content, it is printed first |
| `miyu im logs -f` | Keep printing newly written log lines |
| `miyu im logs watch [<session>]` | Watch live what the AI does in a session. Write the session as `qq:<group number or the other person's number>`, or leave it out to watch all; when a number is both a group and a private chat, write `qq:group:<number>` or `qq:private:<number>`. `Ctrl+C` exits |
| `miyu im venue show <venue>` | The value and source of every setting of a venue. Write the venue as `<platform>:<bot number>:group:<group number>` or `<platform>:<bot number>:private:<number>` |
| `miyu im records import <file>` | Import chat records from a JSON Lines file |
| `miyu im whitelist [list \| add <number> \| remove <number>]` | View or change the private allowlist; with nothing, it is `list` |
| `miyu im access` | List the private allowlist, the group list, and who skips the judgement in each group |
| `miyu im access whitelist [list \| add <number> \| remove <number>]` | Same as `miyu im whitelist` |
| `miyu im access group [list \| add <group number> \| remove <group number>]` | View or change the group list |
| `miyu im access skip <group number> [list \| add <number> \| remove <number>]` | View or change who skips the reply judgement in this group; the group must be on the group list first |

Add `--help` after any command to print its usage. Wrong usage exits with code `2`, errors with code `1`.

```sh
miyu im venue show qq:10001:group:123456
miyu im access skip 123456 add 20017
```

## `im.*` config keys

All are written to the system config `~/.miyu/etc/config.toml` and take effect at once. Those marked hidden are not listed on the settings page and are changed on the dashboard page; editing by hand works too.

Dashboard page and lists:

| Key | Default | What it does |
|---|---|---|
| `im.web.port` | `8302` | The dashboard page's port, `1024` to `65535`. On the dashboard page, "Settings → Access → Port" |
| `im.web.listen` | `127.0.0.1` | `127.0.0.1` for this computer only, `0.0.0.0` to open to the LAN. On the dashboard page, "Settings → Access → Open to the local network" |
| `im.whitelist` | — | The private allowlist; each item is `qq:<number>`, for example `qq:20017` |
| `im.recall_receipts` | `["clear", "clear-memory"]` | Commands whose replies in groups are recalled after a few seconds, without the slash |

QQ connections (hidden, changed in the connection settings):

| Key | Default | What it does |
|---|---|---|
| `im.qq.hosts` | — | Each connection's listen address, matched one to one with the ports |
| `im.qq.ports` | — | Each connection's port |
| `im.qq.tokens` | — | Each connection's token (secret) |
| `im.qq.host` | `0.0.0.0` | When `im.qq.ports` was never written, the first connection's listen address |
| `im.qq.listen` | `8301` | As above, the first connection's port |
| `im.qq.token` | — | As above, the first connection's token (secret) |

Telegram connections (hidden, changed in the connection settings):

| Key | Default | What it does |
|---|---|---|
| `im.tg.tokens` | — | Each connection's bot token (secret) |
| `im.tg.proxies` | — | Each connection's proxy, matched one to one with the tokens: empty or `env` follows the network settings, `direct` connects directly, anything else is a proxy address |
| `im.tg.api` | `https://api.telegram.org` | The Bot API address; change it only when you run your own Bot API server |

Identity (hidden, "Installed → Identity → Settings"):

| Key | Default | What it does |
|---|---|---|
| `im.qq.identity_on` | `true` | The plugin's main switch |

| `im.qq.identity_card` | `true` | Reminds the AI when someone changes their group card name to match the AI's |
| `im.qq.identity_people` | `[]` | People and numbers; each item is `name=QQ number`, for example `boss=10001` |

Lookups (hidden, turned on and off under "Installed"):

| Key | Default | What it does |
|---|---|---|
| `im.qq.lookup_on` | `true` | The plugin's main switch; when off, none of these tools exist |

Group admin (hidden, "Installed → Group admin → Settings"):

| Key | Default | What it does |
|---|---|---|
| `im.qq.admin_on` | `true` | The plugin's main switch |
| `im.qq.admin_mute` | `true` | The mute tool; when off, the AI does not have it |
| `im.qq.admin_mute_min` | `1` | Shortest mute in minutes, `1` to `43200` |
| `im.qq.admin_mute_max` | `43200` | Longest mute in minutes (30 days), `1` to `43200` |

| `im.qq.admin_records` | `true` | Record mutes, unmutes and kicks in each group |

## Opening the dashboard page from other devices

Turn on "Open to the local network" under "Settings → Access" on the dashboard page, and phones and computers on the same LAN can open it; the URL and a QR code are shown below. Opening it from another device needs a sign-in with the access password set in the web UI; see [Web UI](web.en.md). Do not put im behind a reverse proxy; to use it from the LAN, turn on this switch. If other devices cannot connect on macOS, allow incoming connections for `miyu-im` in "System Settings → Network → Firewall → Options".

## Troubleshooting

| What you see | What to do |
|---|---|
| `miyu im status` prints "NapCat is not connected" | Check that the address entered in NapCat matches what `miyu im status` prints and that the path is `/ws` or `/onebot/v11/ws`; if NapCat is on another machine, replace `127.0.0.1` with this machine's address, and the listen address must be `0.0.0.0` |
| "no token set, NapCat connections will be refused" | Run `miyu im web` and paste NapCat's token in the connection settings |
| The Home page log says "Blocked repeated wrong NapCat tokens (…)" | The tokens on the two sides differ; change it to match NapCat's |
| "port … is in use", "That port is already in use" | Pick another port in the connection settings and change the address in NapCat to match |
| "Token rejected, replace it in the connection settings" or "Wrong token" on the connection card | Get a new token from BotFather and enter it in the connection settings |
| "Can't reach Telegram, reconnecting", "Can't reach Telegram, check the proxy" | Change the proxy in the connection settings; if you chose "Follow network settings", check the core's `HTTPS_PROXY` |
| "Proxy address is wrong, fix it in the connection settings" | Write it as `http://host:port` or `socks5://host:port` |
| "Receiving elsewhere too" | Stop the other program that uses this token |
| "Privacy mode on: @ in groups won't arrive" | Turn it off as in "Privacy mode" above |
| The AI does not reply in a group | Open that group's card and look at "Overview → Recent decisions", or run `miyu im logs watch qq:<group number>`: "not called" means no `@` and no message starting with a trigger word; "Off, recorded only" means this group is not on the list or "Reply" is off; "… below the threshold …" means the judge model decided not to reply; there are also rate limit, usage, sleep and muted cases |
| "model request failed" in the live log | Check that the chat model on the session card and the core's default model work; see [Models](../models.en.md) |
| The card names a persona or preset that does not exist, and this session does not reply | Pick one again on the card |
| `miyu im web` prints "Connect Messaging is not running" | `miyu im start`; if that does not help, look at `miyu im status` and `miyu im logs` |
| "management page port … is in use, the page is unavailable" | Pick another with `miyu config set im.web.port 8312` |
| `miyu im status` prints "Connect Messaging stopped and will not be restarted: …" | Fix the cause it gives, then run `miyu im restart` |
| "Can't reach Connect Messaging" on the dashboard page | im has stopped; `miyu im start` |
