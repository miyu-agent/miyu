# 托盘

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

托盘是系统托盘里的一个 Miyu 图标（macOS 上在菜单栏），程序叫 `miyu-applet`。它看核心在不在跑、起停核心、用浏览器打开网页，浏览器关着时也弹「回答完了」「等你确认」这些通知。它没有自己的窗口，聊天都在网页里，见 [网页](web.md)。

## 装和打开

托盘有两种包：完整的安装包把核心、网页、托盘打在一起（不带终端），装上就能用；只装托盘的包要另外装好核心和网页。各系统有的：

| 系统 | 完整的安装包 | 只装托盘 |
|---|---|---|
| Linux x86_64 | `.deb`、`.rpm` | AUR 的 `miyu-applet`；托盘发行版页面上的 `miyu-applet-<版本>-linux-x86_64.tar.gz` |
| Linux aarch64 | 没有 | AUR 的 `miyu-applet`；`miyu-applet-<版本>-linux-aarch64.tar.gz` |
| macOS Apple 芯片 | `.dmg` | Homebrew 的 cask `miyu-applet` |
| Windows x86_64 | `.msi` | 没有 |

怎么装见 [安装、升级、卸载](../install.md)。

从应用菜单打开「Miyu」。托盘起来以后：

- 用浏览器打开网页首页，网页、核心没在跑的一并拉起来。
- 图标留在托盘里，连着核心看状态。

已经有一个托盘在跑时再打开「Miyu」，不起第二个，只叫在跑的那个再开一次网页。一个数据根（默认 `~/.miyu`，Windows 上是 `%USERPROFILE%\.miyu`）一个托盘；设了 `MIYU_HOME` 的托盘照它的数据根，各跑各的。

托盘自己不拉起核心，只连已经在跑的。核心是别的地方起来的（终端、`miyu web`、服务），托盘照样跟着写「运行中」。

## 点图标

| | Linux | macOS | Windows |
|---|---|---|---|
| 左键 | 打开网页界面 | 出菜单 | 打开网页界面 |
| 右键 | 出菜单 | 出菜单 | 出菜单 |

双击、中键没有单独的动作。

## 菜单

从上往下，组之间一根分隔线：

| 菜单 | 点了 |
|---|---|
| 状态行（不能点） | 见下面「状态」 |
| 「停止」或「启动」 | 停止：先停网页，再停核心（`miyu web --stop`，再 `miyu core stop`）。启动：拉起核心，不开浏览器 |
| 「重新启动」 | 停核心再起，网页不停，开着的页面接着连新的核心 |
| 「打开网页界面」 | `miyu web`：用浏览器打开首页 |
| 「设置…」 | `miyu web --settings`：用浏览器打开网页的设置页。macOS 上 `⌘,` |
| 软件包那几行 | 带后台页、在清单里写了 `[tray]` 的软件包一个一行，点了 `miyu pkg page <编号>`，打开它的后台页。一个都没有的不出这一组 |
| 「局域网访问」（打勾） | 打开、关掉别的设备经局域网打开网页，见下面「局域网」 |
| 「在手机上打开…」 | 局域网开着才有。`miyu web --settings access`：打开网页设置的「访问」，那里有地址和二维码 |
| 「开机时启动」（打勾） | 登录时把托盘起来，见下面「开机时启动」 |
| 「打开日志所在的文件夹」 | 用文件管理器打开 `~/.miyu/var/log/` |
| 「关于 Miyu」 | 一个对话框，写托盘、核心、网页三样的版本 |
| 「退出 Miyu」 | 先停网页和核心，托盘再退。macOS 上 `⌘Q` |

网页太旧、不认 `--settings` 这类参数的，托盘改开网页首页。

### 状态

状态行前面一个小圆点：

| 写的 | 圆点 | 什么时候 |
|---|---|---|
| 「运行中」 | 绿 | 连着核心 |
| 「运行中 · 局域网」 | 绿 | 连着核心，局域网访问开着 |
| 「正在启动…」「正在停止…」 | 黄 | 托盘正在起、停核心 |
| 「没有响应」 | 黄 | 连得上，问出去的迟迟不回 |
| 「已停止」 | 灰 | 核心没在跑 |
| 「出错了」 | 红 | 起不来、连上被拒；下面一行写原因 |

托盘图标本身不跟着状态变，悬停写「Miyu」。

能不能点：

- 正在启动时那一行是灰的「停止」，正在停止时是灰的「启动」。
- 「重新启动」在运行中、没有响应、出错了时能点。
- 「局域网访问」只在运行中能点。

### 局域网

「局域网访问」改的是网页的 `web.listen`：打开写 `0.0.0.0`，关掉回到出厂的 `127.0.0.1`。网页当场换过去，不用重启。

- 还没设访问密码就打开的，托盘不改，先用浏览器打开网页设置的「访问」，在那里设密码、打开。
- 网页没装、托盘还没连上过核心的，不出这一组。

局域网访问是明文 HTTP，只在信得过的网络里打开。别的设备怎么打开、访问密码怎么设，见 [网页](web.md#访问和安全)。

## 关掉以后核心还在不在跑

- 「退出 Miyu」：网页、核心一起停，托盘退出。没停成也照样退，日志里记一行。停核心最多等一分钟，点了图标先没了。
- 「停止」：网页、核心停，托盘留着，写「已停止」。
- 托盘不是从菜单退的（崩了、被结束了），核心照常跑。

## 通知

托盘连着核心时接过后台通知：没在网页里开着的会话，由托盘弹系统通知；网页只弹自己标签页开着的会话，两边不重。

| 通知 | 什么时候 |
|---|---|
| 「回答完了」 | 一轮做完 |
| 「等你回答」 | AI 在问你问题 |
| 「等你确认」 | AI 要做的事要你确认 |
| 「定时任务跑完了」「定时任务没跑完」 | 每次新开会话的定时任务那一轮做完、出错 |
| 「定时任务的记录坏了，已换成新的一份，原来的定时任务都没了」 | 定时任务的记录读不了 |

- 标题是会话人格的名字，人格有头像的带头像；没有人格的写「Miyu」。正文是「<会话标题> · 回答完了」这样，没有标题的照第一句话，再没有的只写原因。
- 子代理、一次性的会话、整理记忆的会话不弹。
- 点通知或通知上的「打开」按钮，用浏览器打开那个会话；定时任务记录坏了那一条打开网页首页。Windows 上托盘退了以后点通知中心里的通知，照样拉起托盘、打开那个会话。
- Linux、Windows 上同一个会话同一种通知，新的换掉旧的；macOS 上一条条留着。

托盘菜单里没有关通知的开关。

## 开机时启动

点「开机时启动」打勾，登录时把托盘起来。开机起来的托盘只常驻，不开浏览器，也不拉起核心。

| 系统 | 写在哪 |
|---|---|
| Linux | `~/.config/autostart/miyu-applet.desktop`（设了 `XDG_CONFIG_HOME` 的在它下面） |
| macOS | `~/Library/LaunchAgents/io.github.miyu-agent.miyu-applet.plist` |
| Windows | 当前用户注册表 `Run` 项里的 `Miyu` |

托盘是照 `MIYU_HOME` 或 `--home` 指的数据根起来的，开机时照同一个数据根起。Linux 桌面的「自动启动」设置里关掉的，托盘照关着算。

和 `miyu service enable` 的区别：

| | 「开机时启动」 | `miyu service enable` |
|---|---|---|
| 登录时起什么 | 托盘 | 核心 |
| 核心 | 不拉起，等你打开网页、终端时才起 | 登录就起，通讯平台、定时任务不用等 |

两个都开：登录时核心由服务起，托盘起来连上它，写「运行中」。这时点托盘「退出 Miyu」或「停止」，核心是正常退出，服务管理器不会再起它，到下次登录才起。只用电脑上的界面、不接通讯平台的，开「开机时启动」就够；要核心一直在后台跑的，装服务，见 [常驻和服务器](../service.md#开机或登录就起来)。

## 三个平台

| 系统 | 在哪 | 要什么 |
|---|---|---|
| Linux | 系统托盘 | GTK 3；桌面的托盘要认 StatusNotifierItem。KDE、waybar 这类自带；GNOME 要装 AppIndicator 扩展才显示 |
| macOS | 菜单栏，图标照菜单栏的颜色画 | Apple 芯片，macOS 12 或更新。不占程序坞 |
| Windows | 通知区域 | 通知要从安装包装好的程序发，才带 Miyu 的名字和图标 |

托盘菜单的字照系统的语言：中文、日文，别的都是英文。

## 日志和它自己的目录

- 日志：`~/.miyu/var/log/miyu-applet.log`，和核心、网页的日志放在一起，满 1 MiB 挪成 `miyu-applet.log.1`。核心一次都没起过时 `var/log/` 还没有，这时不写文件。
- 托盘自己的目录放单实例的锁和通知用的头像：

  | 系统 | 位置 |
  |---|---|
  | Linux | `~/.local/state/miyu-applet`（设了 `XDG_STATE_HOME` 的在它下面） |
  | macOS | `~/Library/Application Support/miyu-applet` |
  | Windows | `%LOCALAPPDATA%\miyu-applet` |

托盘没有别的设置。

## 出了问题

| 看到的 | 怎么办 |
|---|---|
| 看不到托盘图标（Linux） | 桌面的托盘不认 StatusNotifierItem。GNOME 装 AppIndicator 扩展；只认老式托盘的换一个托盘 |
| 「找不到 Miyu 的主程序。重新装一次 Miyu 试试。」 | 托盘找 `miyu` 的顺序：托盘旁边、`PATH`，Linux、macOS 再看 `~/.local/lib/miyu/`、`~/.local/bin/`，macOS 再看 `/opt/homebrew/bin`、`/usr/local/bin`；Windows 上只看托盘旁边和 `PATH`。装在别处的，设环境变量 `MIYU_PROGRAM` 指过去 |
| 「打不开网页界面。」，下面是 `miyu` 的原话 | 照原话办；在终端里敲 `miyu web` 看得更全，网页那边见 [网页](web.md#出了问题) |
| 「等了太久，没有回音。」 | 打开网页最多等 90 秒，停核心最多 70 秒。再点一次；还不行看日志 |
| 状态行「出错了」，下面写数据根认不出这类话 | 照那句话办，见 [出了问题怎么查](../troubleshooting.md#核心起不来连不上) |
| 「Miyu 没能启动。」「Miyu 没能停下来。」 | 看下面那句原因和日志 |
| 「没能改局域网访问。」 | 核心没在跑或不收，等状态是「运行中」再点 |
| 「没能改开机时启动。」 | 自动启动的文件、注册表项写不进去，看下面那句原因 |
| 「还没有日志：Miyu 运行过一次以后才有。」 | 先点「启动」或「打开网页界面」 |
| 点了菜单像没反应 | 正在启动、停止时别的起停不接；等状态行变了再点 |
