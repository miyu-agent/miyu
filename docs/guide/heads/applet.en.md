# Tray

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

The tray is a Miyu icon in the system tray (in the menu bar on macOS); the program is called `miyu-applet`. It watches whether the core is running, starts and stops the core, opens the web UI in your browser, and shows notifications such as "Done" and "Waiting for your approval" even when the browser is closed. It has no window of its own; all chatting happens in the web UI, see [Web UI](web.en.md). Chinese version: [applet.md](applet.md).

## Installing and opening

The tray comes in two kinds of package: the full installer bundles the core, the web UI and the tray (without the terminal) and works as soon as it is installed; the tray-only package needs the core and the web UI installed separately. What each system has:

| System | Full installer | Tray only |
|---|---|---|
| Linux x86_64 | `.deb`, `.rpm` | `miyu-applet` on the AUR; `miyu-applet-<version>-linux-x86_64.tar.gz` on the tray's releases page |
| Linux aarch64 | None | `miyu-applet` on the AUR; `miyu-applet-<version>-linux-aarch64.tar.gz` |
| macOS Apple silicon | `.dmg` | The Homebrew cask `miyu-applet` |
| Windows x86_64 | `.msi` | None |

How to install: [Installing, upgrading and uninstalling](../install.en.md).

Open "Miyu" from the application menu. Once the tray is up, it:

- Opens the web UI's home page in your browser, starting the web UI and the core too if they are not running.
- Stays in the tray as an icon, connected to the core to watch its status.

If a tray is already running and you open "Miyu" again, no second one starts; the running one is told to open the web UI once more. There is one tray per data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`); a tray started with `MIYU_HOME` set follows that data root, and each runs on its own.

The tray does not start the core by itself; it only connects to one that is already running. If the core was started elsewhere (the terminal, `miyu web`, a service), the tray still shows "Running".

## Clicking the icon

| | Linux | macOS | Windows |
|---|---|---|---|
| Left click | Open web interface | Show the menu | Open web interface |
| Right click | Show the menu | Show the menu | Show the menu |

Double click and middle click have no action of their own.

## Menu

From top to bottom, with a separator between groups:

| Menu item | What clicking it does |
|---|---|
| Status line (not clickable) | See "Status" below |
| "Stop" or "Start" | Stop: stops the web UI first, then the core (`miyu web --stop`, then `miyu core stop`). Start: starts the core without opening a browser |
| "Restart" | Stops the core and starts it again; the web UI keeps running and open pages connect to the new core |
| "Open Web Interface" | `miyu web`: opens the home page in your browser |
| "Settings…" | `miyu web --settings`: opens the web UI's settings page in your browser. On macOS, `⌘,` |
| Package lines | One line per package that has a background page and declares `[tray]` in its manifest; clicking runs `miyu pkg page <id>`, which opens its background page. If there are none, this group is not shown |
| "LAN Access" (checkbox) | Turns on or off opening the web UI from other devices over the LAN, see "LAN" below |
| "Open on Your Phone…" | Only there while LAN access is on. `miyu web --settings access`: opens "Access" in the web UI's settings, which has the address and a QR code |
| "Start at Login" (checkbox) | Starts the tray when you log in, see "Start at login" below |
| "Open Log Folder" | Opens `~/.miyu/var/log/` in the file manager |
| "About Miyu" | A dialog showing the versions of the tray, the core and the web UI |
| "Quit Miyu" | Stops the web UI and the core first, then the tray quits. On macOS, `⌘Q` |

If the web UI is too old to understand arguments such as `--settings`, the tray opens the web UI's home page instead.

### Status

The status line has a small dot in front:

| Text | Dot | When |
|---|---|---|
| "Running" | Green | Connected to the core |
| "Running · LAN" | Green | Connected to the core, with LAN access on |
| "Starting…", "Stopping…" | Yellow | The tray is starting or stopping the core |
| "Not Responding" | Yellow | It can connect, but requests get no answer for a long time |
| "Stopped" | Gray | The core is not running |
| "Something Went Wrong" | Red | It failed to start, or the connection was refused; the line below gives the reason |

The tray icon itself does not change with the status; hovering shows "Miyu".

What can be clicked:

- While starting, that line is a grayed-out "Stop"; while stopping, a grayed-out "Start".
- "Restart" can be clicked when the status is running, not responding or something went wrong.
- "LAN Access" can only be clicked while running.

### LAN

"LAN Access" changes the web UI's `web.listen`: turning it on writes `0.0.0.0`, turning it off goes back to the shipped `127.0.0.1`. The web UI switches over at once, with no restart.

- If you turn it on before an access password is set, the tray changes nothing; it first opens "Access" in the web UI's settings in your browser, where you set the password and turn it on.
- If the web UI is not installed, or the tray has never connected to the core yet, this group is not shown.

LAN access is plain HTTP; turn it on only on networks you trust. How to open it from other devices and how to set the access password: [Web UI](web.en.md#access-and-security).

## Whether the core keeps running after you close it

- "Quit Miyu": the web UI and the core stop together, and the tray quits. If stopping fails, it quits anyway and writes a line in the log. Stopping the core waits at most one minute; the icon disappears right after you click.
- "Stop": the web UI and the core stop, the tray stays and shows "Stopped".
- If the tray did not quit from its menu (it crashed or was killed), the core keeps running as usual.

## Notifications

While the tray is connected to the core, it takes over background notifications: for sessions not open in the web UI, the tray shows a system notification; the web UI only notifies for sessions open in its own tabs, so the two do not duplicate.

| Notification | When |
|---|---|
| "Done" | A turn has finished |
| "Waiting for your answer" | The AI is asking you a question |
| "Waiting for your approval" | Something the AI wants to do needs your approval |
| "Scheduled task finished", "Scheduled task didn't finish" | A turn of a schedule that opens a new session each time has finished or failed |
| "The scheduled task records were damaged and replaced with a new set; the old scheduled tasks are gone" | The schedule records could not be read |

- The title is the name of the session's persona, with its avatar if the persona has one; with no persona it says "Miyu". The body looks like "<session title> · Done"; with no title it uses the first sentence, and failing that only the reason.
- Subagents, one-off sessions and memory consolidation sessions do not notify.
- Clicking the notification or its "Open" button opens that session in your browser; the one about damaged schedule records opens the web UI's home page. On Windows, clicking a notification in the notification center after the tray has quit still starts the tray and opens that session.
- On Linux and Windows, a new notification of the same kind for the same session replaces the old one; on macOS they all stay.

The tray menu has no switch to turn notifications off.

## Start at login

Check "Start at Login" to start the tray when you log in. A tray started at login only stays in the tray; it does not open a browser or start the core.

| System | Where it is written |
|---|---|
| Linux | `~/.config/autostart/miyu-applet.desktop` (under `XDG_CONFIG_HOME` if that is set) |
| macOS | `~/Library/LaunchAgents/io.github.miyu-agent.miyu-applet.plist` |
| Windows | `Miyu` in the current user's `Run` registry key |

The tray is started at login for the same data root it was started with, whether set by `MIYU_HOME` or `--home`. If it is turned off in the Linux desktop's autostart settings, the tray counts it as off.

How it differs from `miyu service enable`:

| | "Start at Login" | `miyu service enable` |
|---|---|---|
| What starts at login | The tray | The core |
| The core | Not started; it starts when you open the web UI or the terminal | Starts at login; chat platforms and schedules do not have to wait |

With both on: at login the service starts the core, the tray starts and connects to it, and shows "Running". If you then click "Quit Miyu" or "Stop" in the tray, the core exits normally and the service manager does not start it again until the next login. If you only use the interfaces on the computer and no chat platforms, "Start at Login" is enough; if you want the core always running in the background, install the service, see [Keeping it running, and servers](../service.en.md#starting-at-boot-or-login).

## Three platforms

| System | Where | What it needs |
|---|---|---|
| Linux | System tray | GTK 3; the desktop's tray must support StatusNotifierItem. KDE, waybar and the like have it built in; GNOME needs the AppIndicator extension to show it |
| macOS | Menu bar; the icon is drawn in the menu bar's color | Apple silicon, macOS 12 or later. It does not take a place in the Dock |
| Windows | Notification area | Notifications must come from the program installed by the installer to carry Miyu's name and icon |

The tray menu text follows the system language: Chinese, Japanese, and English for everything else.

## Logs and its own folder

- Log: `~/.miyu/var/log/miyu-applet.log`, next to the core's and the web UI's logs; at 1 MiB it is moved to `miyu-applet.log.1`. If the core has never started, `var/log/` does not exist yet, and no file is written.
- The tray's own folder holds the single-instance lock and the avatars used in notifications:

  | System | Location |
  |---|---|
  | Linux | `~/.local/state/miyu-applet` (under `XDG_STATE_HOME` if that is set) |
  | macOS | `~/Library/Application Support/miyu-applet` |
  | Windows | `%LOCALAPPDATA%\miyu-applet` |

The tray has no other settings.

## When something goes wrong

| What you see | What to do |
|---|---|
| No tray icon (Linux) | The desktop's tray does not support StatusNotifierItem. On GNOME, install the AppIndicator extension; if the tray only supports the old-style tray, switch to another tray |
| "Can't find the Miyu program. Try installing Miyu again." | The order in which the tray looks for `miyu`: next to the tray, `PATH`; on Linux and macOS also `~/.local/lib/miyu/` and `~/.local/bin/`; on macOS also `/opt/homebrew/bin` and `/usr/local/bin`; on Windows only next to the tray and `PATH`. If it is installed elsewhere, set the environment variable `MIYU_PROGRAM` to point there |
| "Can't open the web interface.", followed by what `miyu` said | Act on what it said; typing `miyu web` in a terminal shows more; for the web UI side, see [Web UI](web.en.md#troubleshooting) |
| "No answer for too long." | Opening the web UI waits at most 90 seconds, stopping the core at most 70 seconds. Click again; if it still fails, check the log |
| Status line "Something Went Wrong", with a line below about the data root not being recognized or the like | Do what that line says, see [Troubleshooting](../troubleshooting.en.md#the-core-will-not-start-or-cannot-connect) |
| "Miyu didn't start.", "Miyu didn't stop." | Read the reason on the line below and the log |
| "Couldn't change LAN access." | The core is not running or does not accept it; wait until the status is "Running" and click again |
| "Couldn't change Start at Login." | The autostart file or registry entry could not be written; read the reason on the line below |
| "No logs yet: they appear after Miyu has run once." | Click "Start" or "Open Web Interface" first |
| Clicking the menu seems to do nothing | While starting or stopping, other start/stop requests are ignored; wait for the status line to change before clicking again |
