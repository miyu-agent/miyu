# 软件包

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

找一个软件包、装上、看它要了什么、开关它、升级、卸掉，加别的软件源，和出厂带了哪些包。写包的人看 [写一个 Miyu 软件包](../authors/README.md)。

路径里的 `~/.miyu` 是数据根（默认 `~/.miyu`，Windows 上是 `%USERPROFILE%\.miyu`；设了 `MIYU_HOME` 的照它）。

## 软件包能带什么

一个软件包是一个文件夹，文件夹名就是它的编号。一个包能带下面几样，几样混着带也行：

| 带的 | 你感觉到的 |
|---|---|
| 工具 | AI 多了几件能调的工具 |
| 技能 | AI 多一套做事的办法，你也能在输入框里用 `$技能名` 点名 |
| 脚本 | 一个脚本是一件工具 |
| 斜杠命令 | 多几条 `/命令` |
| 子命令 | 多一条 `miyu <名字>` |
| 界面 | 终端、网页这种和 AI 说话的地方 |
| 外观 | 终端或网页的主题、吉祥物 |
| 人格、预设 | 人格列表、预设列表里多几项 |
| 知识库 | 一套给 AI 查的资料 |
| MCP 服务 | 接一个现成的 MCP 服务 |
| 常驻的程序（扩展） | 接通讯平台、替你做事的程序，核心拉起、一直跑着 |
| 后台页 | 这个包自己的一个网页，在浏览器里管它 |

装上以后有三种样子：

- 开着就跑的：清单里写了一起来就拉起的扩展，装上、批了它要的能力就在后台跑。
- 要你打开的：别的扩展，和只带 MCP 服务的包。装好是关着的，装的时候问一句「现在启用 '<编号>'？[Y/n]」，以后在软件包页里开。
- 只是多了东西的：只带技能、脚本、斜杠命令、人格、知识库的包。没有开关，装上就有，每个技能、脚本、命令在预设里各自开关（见 [人格和预设](personas-presets.md)）。

## 找和装

### 在命令行里

1. 搜：

   ```sh
   miyu pkg search ocr
   ```

   一行一个，`<编号>  <名字>  <说明>`。装着的后面接「（已安装）」，不是官方的接「（社区）」，被拉黑的接「（已拉黑：<理由>）」。写几个词的几个词都要有，不写词的列出全部。一个都没搜到的什么都不印，退出码 `1`。

2. 看一个包的详情：

   ```sh
   miyu pkg info ocr
   ```

   装着的照本机那一份说，没装的查软件源。每行「键 : 值」：软件源里的多「软件源」「来源」「下载大小」，装着的多「被依赖」「安装时间」。其余几行是「编号」「名称」「版本」「描述」「依赖」「推荐」「提供」「需要的能力」「作者」「上游」「许可证」「安装后大小」。没值的那一行不印，「依赖」「推荐」没有的写「无」。只查装着的写 `miyu pkg -Qi <编号>`，只查软件源写 `miyu pkg -Si <编号>`。

3. 装：

   ```sh
   miyu pkg install ocr
   ```

4. 看确认屏，敲 `y` 或直接回车装，别的字是不装（「已取消」）。

5. 装好印「已安装 <编号> <版本>」，接一行「已批准 <编号> 的能力：…」。有开关、还关着的，问「现在启用 '<编号>'？[Y/n]」：答是就打开；答不的印「未启用 <编号>」，以后在软件包页里打开。

`miyu pkg install` 也装本机的东西：

```sh
miyu pkg install ./hello            # 一个装着 package.toml 的文件夹
miyu pkg install ./hello-0.1.0.miyu # 一个 .miyu 包文件
```

带 `/`、`\` 的，是 `.`、`..` 的，以 `.toml`、`.miyu` 结尾的，都当路径；别的当编号。所以当前目录下的文件夹要写成 `./hello`，只写 `hello` 是去软件源找。只想看一眼不装的，写 `miyu pkg info ./hello`：照装的那一套查清单，写错的在这里就报第几行。

`--yes`（`--noconfirm` 同）不问：装、升级、卸载都照「是」做，要的能力一并批准，有推荐的包不装，装好的直接打开。标准输入关着（在脚本里跑）又没写 `--yes` 的，报「已取消：没有收到确认」，提示加 `--yes`。

### 确认屏

从软件源装，先在标准错误上印「正在解析依赖…」「正在检查冲突…」，再印：

```text
软件包 (1)  weather-0.3.0

下载大小    : 1.2 MiB
安装后大小  : 3.4 MiB
来源        : 社区，签名已验证（github.com/ann/weather）
需要的能力  : 联网：访问网络、开端口
              提供工具：给 AI 加能调用的工具

注意：这是个社区包，没有经过官方审核，可能存在风险。
安装 'weather' 并批准它要的能力？[Y/n]
```

- 「软件包 (N)」：这一次要装的，缺的依赖排在前面一起装。有推荐的另一行「推荐 (N)」，主包问完再问一句「同时安装推荐的 N 个软件包？[Y/n]」；推荐的包要能力的，先列「推荐的包要的能力」。
- 「来源」：官方的写「官方，签名已验证」，官方软件源里社区收录的写「社区，签名已验证」接来源仓库，你加的软件源写它的名字。一次装几个、来源不一样的，一个包一行，前面是编号。
- 「需要的能力」：一项一行，「名字：说明」。以前批过、这一次照旧留着的接「（已批准）」。没有要批的，最后一句是「安装 '<编号>'？[Y/n]」。
- 「注意」：社区的包、本机文件装的包才有。

装本机的文件夹、包文件，确认屏是另一种：

```text
将安装 hello 0.1.0
包含：扩展程序、技能 take-notes、脚本 dice
需要：联网：访问网络、开端口
来源：本机文件
大小：12.0 KiB，5 个文件

注意：这个包来自本机文件，没有经过官方审核，可能存在风险。
安装 'hello' 并批准它要的能力？[Y/n]
```

「包含」那一行列它带的：「界面程序」「扩展程序」「小程序」「内置功能」，「命令 miyu <名字>」「后台页」「吉祥物」「主题」「接入 <平台>」「MCP 服务 <名字>」「模型驱动 <名字>」「技能 <名字>」「脚本 <名字>」「斜杠命令 /<名字>」「人格 <编号>」「预设 <编号>」「知识库 <编号>」「N 项设置」。读不成、装上也用不了的技能和脚本列在「无法读取：」后面，带原因。同编号已经装着一份的，第一行接「（替换 <旧版本>）」。

包里的模型驱动在清单里写明了会让供应商自己跑哪些工具的，「包含」下面一个驱动多一行，例如「模型驱动 ag 会让供应商自己跑：search_web、read_url_content」。网页里 AI 替你装包时的确认、「下载软件」里装着的包的详情，也在「包含」下面写这一句。

### 能力

能力是扩展这种常驻的程序要的权限，装的时候列出来、你点头才给。没批的那一项，程序就用不了对应的那几样。出厂的包算批过它声明的全部，「替本机页面换登录票」「使用模型供应商的 key」除外，这两项出厂的包也要你批。

| 确认屏上的名字 | 清单里写 | 说明 |
|---|---|---|
| 提供工具 | `tools` | 给 AI 加能调用的工具 |
| 工具会跑命令 | `tools.commands` | 它提供的工具会跑命令，命令里能以当前会话的身份调用 AI 的工具 |
| 提供命令 | `commands` | 加斜杠命令 |
| 在界面上显示内容 | `widgets` | 在首页、侧边栏、底栏和它自己的整页里显示它的内容 |
| 往上下文里加内容 | `context.inject` | 每一轮开始时往 AI 看到的内容里加东西 |
| 往系统提示词里放内容 | `context.system` | 在 AI 每一轮都看到的系统提示词最后放一段 |
| 拦截工具调用 | `tool.guard` | 工具执行前放行、拒绝，或者先问你 |
| 修改工具结果 | `tool.rewrite` | 工具执行后改写结果 |
| 读取会话 | `events.read` | 读会话里的全部记录 |
| 写入会话记录 | `events.write` | 往会话里追加它自己的记录 |
| 操作会话 | `sessions.drive` | 在会话里发消息、开新会话 |
| 调别的软件 | `packages.call` | 调别的软件包给出来的方法 |
| 提供联网服务 | `search` | 在联网服务里列出来，选了它的，搜索词会交给它 |
| 提供模型驱动 | `model.driver` | 用它的模型时，发给模型的全部对话都经过它 |
| 使用模型供应商的 key | `provider.key` | 会拿到你在模型那边配好的某一家供应商的 key。包写明了是哪一家的，确认屏上写「这个包会拿到你 DeepSeek 的 key」这样的一句。你配的哪一家算那一家，认法同 [联网服务借 DeepSeek 的 key](web-search.md#用-deepseek)，别家的 key 不给 |
| 代平台用户发言 | `act_for_external` | 替聊天平台上的人发消息、命令 |
| 替本机页面换登录票 | `login.page` | 它能让本机打开的页面不用密码登进来 |
| 联网 | `network` | 访问网络、开端口 |
| 读取文件 | `fs.read` | 读指定的文件和目录 |
| 写入文件 | `fs.write` | 写指定的文件和目录 |
| 使用麦克风 | `audio.record` | 录本机麦克风的声音 |
| 放出声音 | `audio.play` | 从本机的音箱、耳机放声音 |
| 写入记忆和知识库 | `memory.write` | 替 AI 记住、改、忘掉记忆，往知识库里加、改、删 |

这一层权限管的是程序经核心能做什么。扩展的程序本身以你的身份在这台机器上跑，不进沙盒。来路不明的包别装，见 [安全](security.md)。

### 在终端、网页里

- 网页：敲 `/market` 打开设置页的「下载软件」。顶上搜索、「N 个可升级」、「刷新软件源」，下面两排筛选（「全部」「已安装」「可升级」「官方」「社区」和按种类），能照「默认」「最新」「下载量」「趋势」排。点一张卡片看详情（来源、许可证、包含、提供、所需权限），按「安装」。社区的包标着「社区软件可能存在风险，避免随意安装」。
- 终端：敲 `/settings`，进「软件包」，第一页「下载软件」。`/` 搜，`空格` 勾选，`Enter` 装，`s` 换排序，`r` 刷新软件源，`,` `.` 换页，`Esc` 返回。装之前一样列来源和能力，问「安装并批准要的能力？ [Y/n]」。

AI 也能替你查软件源、装包（出厂的「软件包」功能）。开放权限下每次先问你，只读下不做，见 [权限和沙盒](permissions.md)。

## 开和关

有开关的是扩展、带 MCP 服务的包、出厂的内置功能包。界面、小程序、吉祥物、外观，和只带技能、脚本的包没有开关，硬去开关的报「不能启用或停用」。

| 在哪 | 怎么做 |
|---|---|
| 网页 | 敲 `/pkg` 打开设置页的「软件包」，每行右边一个开关。基础系统这些组收成一行，点进去是组里的包 |
| 终端 | `/settings` →「软件包」→「已安装」，选中按 `空格` |
| 托盘 | 没有开关。带后台页、清单写了托盘入口的包，开着时在托盘菜单里一行，点了打开它的后台页 |

打开扩展时还有没批的能力，会先列出来问你：网页写「启用前需批准以下权限：」，按「批准并启用」；终端问「打开 <名字> 要批这些能力：」。

出厂的内置功能包，关就是卸掉，开就是装回来，见下面「三层」。

### 只对自己关掉一个包

`packages.<编号>.off` 写 `true`，你的会话里就没有这个包的工具、技能、命令和它往对话里加的话，设置页、预设页也不列它。只对你自己：通讯平台上别人的会话照旧有。哪个包都能这样关，从下一轮起生效：

```sh
miyu config set packages.base-jobs.off true
```

终端设置页里，每个包自己那一页有「把这个包关掉」这一项。

### 包里的东西各自开关

包带的每个技能、脚本、斜杠命令模板、MCP 服务，在预设里各是一个功能，能单独开关，也能一件件关它的工具。见 [人格和预设](personas-presets.md)。

### 包的设置

包能在清单里声明自己的设置项，存在 `~/.miyu/etc/config.toml`，键是 `<前缀>.<名字>`。在网页的「软件包」里点一个包进它的页面改；终端在「已安装」里选中按 `Enter`；或者用 `miyu config set`。见 [配置](config.md#软件包的设置)。

### 后台页

带后台页的包，用浏览器打开它：

```sh
miyu pkg page im
miyu pkg page im --print   # 只印网址
```

网址总会印出来，浏览器没开成的照样复制得到。后台页由包的程序自己起的，程序没在跑时报「<编号> 没有在运行，启用它以后再打开」。网页设置页的「软件后台」、终端「软件包」的第三页「软件后台」列着全部带后台页的包。

## 看

| 命令 | 印什么 |
|---|---|
| `miyu pkg list`（`miyu pkg` 同） | 装着的一行一个，`<编号>  <名字>`。卸掉了的出厂包接「（已卸载）」，清单写错的接「（清单有误：<哪里不对>）」 |
| `miyu pkg files <编号>` | 它装了的文件，一行一个，`<编号> <绝对路径>` |
| `miyu pkg owns <路径>` | 「<路径> 属于 <编号>」；在包的目录里、装的时候没有的，说「不是安装时带的」；哪个包都没有的报「没有软件包包含 <路径>」，退出码 `1` |
| `miyu pkg check [<编号>]` | 装好的文件有没有被改过：一个包没问题的一行「<编号>：正常」，有问题的一个文件一行「已修改」「缺失」「多出」。有改了、少了的退出码 `1`；多出的只是提示，包运行时自己写的也算。出厂的不查；系统包管理器装的只查清单读不读得成、程序在不在 |

都能加 `--format json`，印一行 JSON。

日志：

- 扩展的标准错误：`~/.miyu/var/log/<编号>/stderr`。网页软件包页里停下的扩展有「查看输出」。
- 包带的 MCP 服务的标准错误：`~/.miyu/var/log/mcp/<服务名>.stderr`。
- 核心的运行日志：`~/.miyu/var/log/core.log`。

## 升级和清理

```sh
miyu pkg update    # 拿新的索引
miyu pkg upgrade   # 升级
miyu pkg clean     # 清缓存
```

- `update`：每个软件源一行，「已更新 <源>：N 个包（<时刻>）」。不手动拿也行：搜、装、升级时本机的索引超过 24 小时会自己去拿。连不上时照旧用本机那一份，搜的时候说一句「无法连接软件源，使用本机索引（<时刻>）」。
- `upgrade`：只升从软件源装的包。本机文件夹、包文件装的不碰；出厂的跟着 Miyu 自己升级（`miyu upgrade`）。软件源里的版本和装着的不一样就升，作者撤回了新版的也跟着回去。确认屏一个包一行「将升级 <编号> <旧版本> → <新版本>」，新版多要的能力列在下面「新要：」，问「升级 '<编号>' 并批准新要的能力？[Y/n]」。设置、状态、开关、以前批过的能力都留着。新版多要的能力不批的，打开时再问。
- `clean`：删掉缓存里不是装着那一版的包文件，印「已清理 N 个包文件，释放 <大小>」。

下面四种不升，在标准错误上各说一句，照旧用装着的：

| 说的 | 为什么 |
|---|---|
| 「跳过设为不升级的 <编号>」 | 在 `packages.hold` 里 |
| 「<编号> 已不在软件源中，保留已安装的版本」 | 软件源里没了，或者装它的那个软件源从配置里删了 |
| 「<编号> 已被拉黑：<理由>」 | 软件源拉黑了它。要不要卸你自己定，提示怎么卸 |
| 「<编号> 改由 <仓库> 提供，未升级」 | 这个编号换了来源仓库。换来源就是换了信任的人，不自动升 |

钉住一个包不升：

```bash
miyu config set packages.hold '["im"]'
```

```powershell
miyu config set packages.hold "['im']"
```

写的是整份列表。PowerShell 里照上面这样外面用双引号、里面用 TOML 的单引号字符串，Windows PowerShell 5.1 和 PowerShell 7 都能照抄。

网页「下载软件」顶上有「N 个可升级」和「全部升级」；终端「已安装」里 `u` 升级选中的，`U` 全部升级。

## 卸

```sh
miyu pkg remove ocr
miyu pkg remove --purge ocr   # 连配置一起删
```

确认屏：

```text
将卸载 ocr 0.2.0
包含：扩展程序
会删掉 /home/me/.miyu/var/lib/ocr（3.1 MiB）
配置留在 /home/me/.miyu/etc/ocr，另有 2 项设置

卸载 'ocr'？[Y/n]
```

这两行印的是全路径。上面是 Linux 上的样子；macOS 上是 `/Users/me/.miyu/var/lib/ocr` 这样，Windows 上是 `C:\Users\me\.miyu\var\lib\ocr` 这样。

- 删掉的：包文件夹 `~/.miyu/opt/<编号>/`，`~/.miyu/` 下 `var/lib/`、`var/cache/`、`var/log/`、`tmp/`、`run/` 里它的 `<编号>/`，它带的脚本的状态目录。
- 留下的：配置目录 `~/.miyu/etc/<编号>/`，和 `~/.miyu/etc/config.toml` 里它的设置项。重装同编号照旧用。写了 `--purge`（`-n` 同）才一起删。
- 别的装着的包依赖它的卸不掉，报「其他软件包依赖它，无法卸载」。

网页在一个包的页面里有「卸载」和「卸载并删除配置」；终端「已安装」里选中按 `d`。

## 三层

一个编号可能在三处都有一份：

| 层 | 在哪 | `miyu pkg info` 的「来源」 |
|---|---|---|
| 出厂 | 随 Miyu 一起装的资源目录里的 `packages/<编号>/` | 出厂 |
| 系统的包管理器装的 | Linux：`$XDG_DATA_DIRS` 里每一处的 `miyu/packages/<编号>/`，没设的是 `/usr/local/share/miyu/packages/`、`/usr/share/miyu/packages/`，先列的优先；Linuxbrew 装的不会自己认到，要自己把 Linuxbrew 的 `share` 目录写进 `XDG_DATA_DIRS`。macOS：Homebrew 前缀下的 `share/miyu/packages/<编号>/`，前缀是 `miyu` 所在目录的上一级。Windows 没有这一层，只有出厂的和你装的 | 系统装的 |
| 你装的 | `~/.miyu/opt/<编号>/` | 官方、社区、本地 |

同一个编号几层都有，你装的赢，其次系统包管理器装的，最后出厂的；被盖住的那几份不加载。系统包管理器装的那份比你装的新时，`miyu check` 提一句，说怎么换回去。

- 和出厂的包同编号的装不上，报「编号与内置软件包重复」。
- 卸出厂的、系统包管理器装的：文件不动，只在 `~/.miyu/etc/removed/<编号>` 记一笔，不再加载。系统包管理器装的要删文件，用系统的包管理器。
- 装回来：`miyu pkg install <编号>`。网页的开关、终端「已安装」里的 `空格` 也装得回来。
- 一整组：`miyu pkg remove tasks` 卸掉「任务和定时」整组，`miyu pkg install tasks` 装回组里卸掉的。网页组那一层有「全部卸载」「全部装回」。

## 软件源

默认的软件源是 `https://miyu-agent.github.io/packages/`。`miyu pkg search`、`miyu pkg install <编号>` 用的就是它。

- 索引是 `index.json`，签名是旁边的 `index.json.sig`，Ed25519。官方的公钥编在 `miyu` 里，签名验不过的索引整份不收。本机存的那份每次读都再验一遍。
- 包文件照索引写的 SHA-256 核对，对不上的不装。
- 软件源里有官方的包和社区的包。社区的包是作者给自己的 GitHub 仓库打上 `miyu-package` 话题、软件源每天收一次收进来的，没人审过。分得出来：`search` 的行末有「（社区）」，`info` 的「来源」写「社区，没有经过官方审核」，装之前有「注意」，网页卡片标「社区」。
- 不在任何软件源里的包（别人发给你的文件夹、`.miyu` 文件）没有签名、没人审过，装之前确认屏写「这个包来自本机文件，没有经过官方审核，可能存在风险。」。见 [安全](security.md)。

设置都写在 `~/.miyu/etc/config.toml`，改了当场生效：

| 键 | 默认 | 做什么 |
|---|---|---|
| `packages.source` | `"https://miyu-agent.github.io/packages/"` | 官方软件源的地址。换了地址，那边的索引也得是官方签的 |
| `packages.mirrors` | `[]` | 官方软件源的镜像，照先后试，都不成再试 `packages.source`。镜像改不了内容：照样验签名、比哈希 |
| `packages.hold` | 没有 | 升级时跳过的包的编号 |
| `packages.sources.<名字>.url` | 没有 | 别的软件源放索引的那一层目录 |
| `packages.sources.<名字>.key` | 没有 | 签那个源的索引的 Ed25519 公钥，base64，最多 64 个字 |

加一个朋友的软件源：

```toml
[packages.sources.friends]
url = "https://friends.example.com/miyu/"
key = "bWl5dS1leGFtcGxlLWtleS1ub3QtcmVhbC0wMDAwMDA="
```

- `url` 和 `key` 都写了才算一个源；加了就是信任它，它的索引照这把公钥验。
- 名字不能叫 `official`。
- 装的时候先找官方的，再照名字的先后找你加的。从哪个源装的，升级也只照那个源。
- 确认屏的「来源」写这个源的名字，例如「friends，签名已验证」。

网页的设置页里，这几项在「高级」页「软件源」那一组。

## pacman 写法

用惯 pacman 的，下面这些写法也认：

| pacman 写法 | 同 |
|---|---|
| `miyu pkg -S <编号>…` | 从软件源装这几个 |
| `miyu pkg -Sy` | `update` |
| `miyu pkg -Sy <编号>…` | 先 `update` 再装 |
| `miyu pkg -Ss [<词>…]` | `search` |
| `miyu pkg -Si <编号>` | 只查软件源的 `info` |
| `miyu pkg -Su` | `upgrade` |
| `miyu pkg -Syu` | 先 `update` 再 `upgrade` |
| `miyu pkg -Sc` | `clean` |
| `miyu pkg -U <路径或编号>` | `install` |
| `miyu pkg -R <编号>` | `remove`，`-Rn` 同 `remove --purge` |
| `miyu pkg -Q` | `list` |
| `miyu pkg -Qi <编号>` | 只查装着的 `info` |
| `miyu pkg -Ql <编号>` | `files` |
| `miyu pkg -Qo <路径>` | `owns` |
| `miyu pkg -Qk [<编号>]` | `check` |
| `--noconfirm` | `--yes` |

`-S` 后面什么都不跟的报「没有指定目标」，退出码 `2`。`-Qi`、`-Si` 只接编号，接路径的报错，看文件夹、包文件用 `miyu pkg info <路径>`。

全部参数见 [命令行](cli.md#miyu-pkg)。

## 出了问题

报错印在标准错误上，`miyu: ` 打头。

| 看到的 | 怎么办 |
|---|---|
| `未找到软件包 '<编号>'`、`软件包不存在` | 编号写错了，或者索引旧了：`miyu pkg update` 再搜。装当前目录下的文件夹要写 `./<文件夹>` |
| `软件源连不上` | 网络不通或者地址不对。看 `packages.source`，连不上官方的可以加 `packages.mirrors` |
| `软件包下载失败` | 每一处都没下成，或者下下来的哈希对不上。过一会儿再试，或者换镜像 |
| `不支持本机的系统` | 这个包没有给你这种系统打包 |
| `无法安装 <写的>：package.toml:<行>: …` | 清单写错了，照说的那一行改；不是你写的包，找作者 |
| `无法安装 <写的>：<哪一样> <名字> 已在 <包> 中` | 它带的工具、技能、命令、MCP 服务这些和装着的别的包重名，一处一行。卸掉那一个，或者找作者改名 |
| `编号与内置软件包重复` | 本机的包用了出厂包的编号，改文件夹名 |
| `缺少依赖的软件包` | 依赖的包不在软件源里，或者版本不够 |
| `无法安装 <写的>：…这个包要 Miyu <版本> 以上，先更新 Miyu` | `miyu upgrade` |
| `其他软件包依赖它，无法卸载` | 先卸依赖它的那几个 |
| `不能启用或停用` | 这种包没有开关，见上面「开和关」 |
| `程序未安装` | 包里的程序不在，重装这个包 |
| `扩展权限未批准` | 打开它时批准它要的能力 |
| `已取消：没有收到确认` | 在脚本里跑的，加 `--yes` |
| 网页软件包页上扩展「已停止」「连续失败 5 次，已停止」 | 点进去看「查看输出」，或者看 `~/.miyu/var/log/<编号>/stderr` |
| 软件包页上写「缺少依赖：<编号>」 | 装上缺的那几个 |
