# Security

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Putting an AI that can run commands on your own machine: what Miyu blocks for you, what it does not, what gets sent out, and how to set up a few common uses. Chinese version: [security.md](security.md).

## Trust model

Miyu runs as your system user. Under full access, the AI can do almost everything you can do in a terminal: read and write your files, run commands, go online.

The protections below guard against two things: the AI making a mistake in a moment of confusion, and the AI being led astray by words in the web pages, files and group messages it reads. They are not meant to confine a program that is deliberately looking for loopholes. To keep the AI away from something, keep it out of reach: use read-only, or do not put the thing where the AI can read it.

## What Miyu blocks

| What | How it is blocked | Where it is explained in full |
|---|---|---|
| The AI changes your files | Switch to read-only: file tools do not write, and commands run in the system's sandbox, which can write nowhere. On Windows the sandbox works only in a logged-in desktop session, and where there is none, every command is refused | [Permissions and sandbox](permissions.en.md#two-permission-levels) |
| Dangerous commands | Under full access, destructive git operations, recursive deletes, shutdown and restart, running a download directly, and containers using host devices ask you first; deleting the root and home directories, formatting disks, writing directly to disk devices, and containers taking over the whole machine are refused outright. On Windows the rules recognize PowerShell and cmd syntax, except the kind for writing directly to disk devices | [Permissions and sandbox](permissions.en.md#commands-that-need-confirmation) |
| The AI deletes Miyu's own data | Deleting the whole data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`), things in it, or a directory that contains it asks you first, under the "Recursive delete" kind. Other reads and writes are not blocked, see the next table | [Permissions and sandbox](permissions.en.md#commands-that-need-confirmation) |
| Other people telling the AI what to do on chat platforms | Groups and private chats with someone other than you are locked down: files can reach only that session's workspace, commands run in a sandbox that confines reads too (commands cannot run on Windows), packages cannot be installed, and anything that needs confirmation is not done; MCP servers are not given to them as shipped | [Permissions and sandbox](permissions.en.md#sessions-on-chat-platforms), [Connecting chat platforms](heads/im.en.md#what-the-ai-can-do-in-groups) |
| Words in a web page tricking the AI into connecting to this machine or the internal network | `web_fetch` and link cards do not go to addresses such as localhost, the internal network and link-local addresses, and every redirect hop is checked again | [Web search and fetching pages](web-search.en.md#addresses-it-cannot-reach) |
| Installing a package of unknown origin | Before installing, the capabilities it needs are listed, and they are granted only with your approval; the package source's index has its signature verified and package files are checked against SHA-256; packages from the community and packages installed from a local file are marked | [Packages](packages.en.md#package-sources) |
| A tampered Miyu program | The install script and `miyu upgrade` check the signature and SHA-256, and do not install if they do not match | [Installing, upgrading and uninstalling](install.en.md#what-the-script-checks) |
| Keys ending up in files, logs and commands | The config holds only references, and keys live in the secrets file (on Linux and macOS its permissions are `0600`, so only you can read and write it; on Windows it follows the access control inherited from the data root); commands the AI runs do not get environment variables whose names contain `KEY`, `SECRET`, `TOKEN`, `PASSWORD`, `PASSWD` or `CREDENTIAL`; the core's log does not record keys or conversation content | [Configuration](config.en.md#secrets), [Tools the AI can use](tools.en.md#shell), [Keeping it running, and servers](service.en.md#logs) |
| Other devices connecting to your web UI | As shipped it listens on this machine only; other devices need the access password (stored as an argon2id hash; after 5 wrong tries from the same source within 60 seconds, further tries are refused); only requests whose `Host` is a local address or this computer's IP are accepted, not domain names; the conversation connection checks `Origin` | [Web UI](heads/web.en.md#access-and-security), [Keeping it running, and servers](service.en.md#opening-the-web-ui-from-other-machines-and-phones) |
| Other users on this machine connecting to your core | On Linux and macOS the socket sits in a directory only you can enter; on Windows it is a named pipe open only to you, and after connecting the core also checks that the process at the other end is yours. A head that connects must also present the local token | [Troubleshooting](troubleshooting.en.md#the-core-will-not-start-or-cannot-connect) |
| Someone else's repository loosening permissions through project config | Project config can only tighten; for now only `permission.start_read_only = true` is recognized; one that is not trusted has no effect, and when its content changes it has to be trusted again | [Configuration](config.en.md#settings-for-a-single-repository) |
| Someone connecting to the QQ interface and impersonating | A OneBot implementation that connects must bring a token; one without it is refused | [Connecting chat platforms](heads/im.en.md#connecting-qq) |

## What Miyu does not block, or cannot block completely

| What | How it actually is | What you can do |
|---|---|---|
| Dangerous commands written another way | Protected commands are recognized only by their literal text, and a form written to get around the check is not recognized | Use read-only for work you are unsure about |
| Dangerous commands Windows does not recognize | Commands encoded in `-EncodedCommand`, writing directly to disk devices, `Set-ExecutionPolicy` and deleting from the registry are not recognized by the rules on Windows: under full access they are neither asked about nor refused | Use read-only for anything you are unsure about, see [Permissions and sandbox](permissions.en.md#how-it-is-written-on-windows) |
| Commands and file tools under full access | Commands do not run in the sandbox. Miyu's data root is not guarded separately: commands and file tools can read and write `~/.miyu`, including the secrets file `~/.miyu/etc/private/secrets.toml` and the config and sessions | Same as above |
| The secrets file | None of the three platforms uses the system keychain; keys are written in plain text in `~/.miyu/etc/private/secrets.toml`. On Linux and macOS Miyu sets its permissions to `0600` every time it writes it; on Windows no permissions are set separately and it follows the access control inherited from the data root. Any program that runs as you can read it. So can the AI: at both permission levels file tools and commands can read the data root, this file included, and a key it reads goes into the context and is sent to the model provider | Do not have the AI read it; do not run programs of unknown origin as yourself; do not put the data root in a directory other users can read |
| Prompt injection | Web pages, files, a repository's `AGENTS.md`, group messages and MCP server replies that the AI reads all go into the context, and what they say may lead it astray. Miyu does not recognize such words; only the rules in the table above, which do not look at what the AI says, can stop things | Use read-only when reading things you do not know; do not click through important confirmations casually |
| Your files sent to the model provider | Under both full access and read-only the AI can read any file your system user can read, including `~/.ssh`, browser data, other programs' logins and Miyu's own data root; what it reads goes into the context and is sent to the provider. Read-only only stops writing; it does not hide things for you | Do not let the AI rummage in a directory that holds private files; if you do not want it to read something, put Miyu inside another sandbox yourself, or run it as a different system user |
| Network access in read-only | Read-only commands can still go online, and any file they can read can be sent out | Same as above |
| Environment variables | Removing variables with `KEY` and the like only prevents carrying them out by accident; it is not a wall: commands and the core both run as your system user, the system does not defend programs of the same user against each other, and the core process's environment can still be read (for example `/proc/<pid>/environ` on Linux), which is where a key referenced by `{ env = "…" }` lives | Store keys in the secrets file with `miyu provider login` |
| LAN access | Plain HTTP: people on the same network can see the access password, login tokens and conversations | Turn it on only on a network you trust; when away, connect through an encrypted tunnel such as Tailscale or WireGuard first |
| Connections coming in through SSH port forwarding | The web UI treats forwarding that adds no headers, such as `ssh -L`, as this machine: no password is required, and the access password can be changed | Use this route for yourself only |
| Extensions | They run as you, outside the sandbox. Miyu does not audit what an extension does with the capabilities you grant. One granted "Use a model provider's key" gets that provider's key in plain text, and gets the new one when you change the key | Do not install ones of unknown origin, see "Before installing a community package" below |
| Scripts and MCP servers | Scripts under full access and all MCP servers run as you, outside the sandbox | Connect only ones whose code you have read and trust |
| People in a group using memory and the knowledge base | The AI in a group still has `remember`, `forget`, `memory_search` and the tools that write to the knowledge base, using the same memory as you and your knowledge base | Give the group a preset that turns them off, see [Connecting chat platforms](heads/im.en.md#memory-and-the-knowledge-base) |
| Platform accounts bound as you | Their private chats follow your permission level and are not locked down. If someone gets hold of the account, they act on this machine with your permissions | Bind only accounts that you use yourself and keep safe |
| Pages that cannot be fetched | The URL is handed to Exa, Firecrawl or Parallel to fetch; a host name only your internal network knows is handed out the same way when it cannot be reached. If the web provider is DeepSeek, the URL to fetch goes to DeepSeek first | See [Web search and fetching pages](web-search.en.md#privacy) |
| Undo | Only rolls back the conversation; files the AI changed and commands it ran are not rolled back | Use version control such as git, or back up first, see [Sessions](sessions.en.md#undo-restore-redo) |
| Cost | There is no automatic spending cap | Watch usage and set a limit on the number of requests, see [Letting the AI keep working on its own](automation.en.md#when-nobody-is-watching) |

## What leaves this machine

| Sent to | What is sent | When | To avoid it |
|---|---|---|---|
| Model provider | System prompt, persona, conversation, attachments, tool results, recalled memories, knowledge base snippets brought in | Every request to the model | Use a model service running on this machine, see [Models](models.en.md) |
| OpenCode Go's quota endpoint (`https://opencode.ai/inference/go/v1/usage`, or the changed address if `providers.<id>.quota.url` is changed) | One GET with this provider's key and no conversation | When the session uses OpenCode Go, asked once in the background at the end of each turn. The same provider is not asked again within 60 seconds; a failed query does not report an error | Do not use OpenCode Go |
| A model in the everyday pool (if none is set, the session's model) | The part of the conversation to be processed and related memories; the plain text of secrets referenced in the config and common key formats are masked first | When memories are saved automatically or tidied | Turn off persona memory in the preset, see [Memory](memory.en.md#stopping-it-from-remembering) |
| A remote semantic model | The text of memories, conversations and the knowledge base | When `models.embedding` names a remote model | Use the local `embed`, see [Add-ons](addons.en.md#built-in-semantic-model-embed) |
| Web provider (the one you chose, and the ones tried automatically when it is unavailable) | The search terms | When the AI searches the web | Turn off "Web search", see [Web search and fetching pages](web-search.en.md#turning-it-off) |
| Fetching services (Exa, Firecrawl, Parallel; also DeepSeek if the web provider is DeepSeek) | URLs | Pages Miyu cannot fetch itself; with DeepSeek chosen, every page fetch goes to it first | Turn off "Fetch web pages" |
| The site a page is on | An ordinary visit | When the AI fetches a page; when a link in the timeline is drawn as a card | Same as above |
| Remote MCP servers | The arguments given when the AI calls their tools | At call time | Do not connect them, or turn them off in the preset |
| Package source `https://miyu-agent.github.io/packages/` | Fetching the index and downloading package files | `miyu pkg update`; when searching, installing or upgrading and the local index is more than 24 hours old | Do not use the package source |
| models.dev | Fetching the model catalog and provider icons | The core does it in the background when the copy it has is older than `models.catalog.every` (default `24h`) | `miyu config set models.catalog.update false` |
| Exchange rate service (Frankfurter, with open.er-api.com as backup) | Currencies and dates, no usage | When a usage amount has to be converted to another currency | Do not look at converted amounts |
| GitHub | Asking for the latest release, downloading | When you run `miyu upgrade` or the install script | Do not run them |
| Chat platforms | The AI's replies and the files it sends | When chat platforms are connected | Do not install `im` |
| Places an extension connects to by itself | Depends on that extension | Extensions that were granted the "Network" capability | Do not grant it, or do not install the extension |

Miyu has no telemetry: it does not report your usage, conversations or errors anywhere, and sends no crash reports. When the terminal crashes, the call stack it leaves is written only to the cache directory on this machine.

## Setting up for common uses

### Looking at a repository you do not know

1. Start the session in read-only:

   ```bash
   miyu ask -C ~/src/unknown-repo --permission read-only "tell me what this repository is for"
   ```

   ```powershell
   miyu ask -C $HOME\src\unknown-repo --permission read-only "tell me what this repository is for"
   ```

   In the terminal or web UI, press `Shift+Tab` after opening the session to switch to read-only.
2. The repository's `AGENTS.md` is handed to the AI every turn, and the AI reads whatever it says. In read-only it cannot change files, but it can still read your disk and go online.
3. If the repository has a `.miyu/config.toml`, `miyu ask` says "project config … is not trusted; not used this time". It can only tighten, so trusted or not, it never loosens permissions.
4. Before the AI starts changing things, run `git status` to check the tree is clean, and read the diff after it is done.

See [Permissions and sandbox](permissions.en.md), [Sessions](sessions.en.md).

### Running for a long time unattended

1. A session that a schedule opens each time has nobody watching: anything that needs confirmation is not done, and the AI cannot ask you either. The kinds of protected commands therefore do not run.
2. Give it a preset with only the features it needs turned on, and pick it with `--preset`.
3. In that preset, limit how many times a turn may request the model:

   ```toml
   [limits]
   unattended_steps = 100
   ```

4. If you want it only to read and not to change, set `permission.start_read_only true`, and new sessions are read-only.
5. Check usage now and then: `/usage` in the terminal, the "Usage" page in the web UI settings.

See [Letting the AI keep working on its own](automation.en.md#when-nobody-is-watching), [Personas and presets](personas-presets.en.md).

### Connecting to a group

1. Sessions in a group are locked down already, so no separate permission setup is needed.
2. Give the group a tightened preset and pick it under "Group defaults" on the im backstage page: turn off persona memory, turn off `kb_save`, `kb_edit` and `kb_delete`, and keep only the tools the group needs.
3. Under "Who you are", enter only your own account.
4. Groups and people not on the lists are, as shipped, recorded only and not replied to; do not casually turn on "Reply" for "Other groups" or "Other private chats".
5. If NapCat and im are on the same machine, change the connection's listen address to `127.0.0.1`. As shipped it is `0.0.0.0`, and only the token stands in the way.
6. If you have internal domain names, put them in `net.internal_domains`, so the AI does not go there when someone has it fetch a page.
7. Set usage limits and rate limits for the people in the group, see [Connecting chat platforms](heads/im.en.md#limits-and-usage).

### Putting it on a server

1. Run the core as a dedicated system user, put the data root in `/var/lib/miyu`, and do not use some person's home directory. The system service examples in the repository are for Linux only (systemd, OpenRC, runit, dinit).
2. Have the web UI listen on `127.0.0.1` only (as shipped), and connect from your own computer through `ssh -L`, Tailscale or WireGuard.
3. If other devices need to open it directly, set a long access password first, then turn on LAN access. Do not expose the web UI's port directly to the public internet.
4. Behind a reverse proxy, the proxy must add forwarding headers such as `X-Forwarded-For`; without them the request is treated as coming from the server itself and needs no password.

See [Keeping it running, and servers](service.en.md#running-on-a-server).

### Before installing a community package

1. See what it is:

   ```sh
   miyu pkg info weather
   ```

   Look at "Origin" (official, community, local file), the "Upstream" repository and "Capabilities".
2. If it asks for more capabilities than its stated purpose needs, do not install it. For example, a weather package asking for "Read sessions" and "Write files".
3. Nobody has reviewed community packages. Before installing, look at the code in the "Upstream" repository and whether anyone uses it.
4. A folder or `.miyu` file someone sends you directly has no signature, which is one layer less of checking than a community package.
5. After installing, `miyu pkg check <id>` shows whether the files in the package have been changed.

See [Packages](packages.en.md#capabilities).

## Found a security issue

Do not post details of how to exploit it anywhere public. Report it privately with **Report a vulnerability** on the core repository's Security tab ([open it directly](https://github.com/miyu-agent/miyu/security/advisories/new); you need to be signed in to GitHub); only you and the maintainers can see it. Issues in the other repositories are reported there too. What to include is in [SECURITY.md](../../SECURITY.md#reporting-a-security-issue).
