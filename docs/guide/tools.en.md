# Tools the AI can use

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

The AI reads files, runs commands and goes online by calling tools. This page lists every shipped tool: what it does, whether it still works in read-only, what its limits are, and how to turn one off. Chinese version: [tools.md](tools.md).

## Where tools come from

- From shipped packages: the full tables below.
- From packages and extensions you install: see their own descriptions. For `qq_*` and `tg_*` on chat platforms see [Connecting chat platforms](heads/im.en.md); for the stickers' `meme_*`, and `render_image`, `ocr` and the like, see [Add-ons](addons.en.md).
- Scripts: each file in `~/.miyu/root/scripts/` under the data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`) is one tool, named after the file. For how to write one, see [Things that work as files](../authors/scripts-skills.en.md).
- MCP servers: the tool name is `mcp__<server name>__<tool name>`; characters other than letters, digits, `_` and `-` in the tool name are replaced with `_`, and the whole name is at most 64 characters. A server that declares resources has two more tools, `mcp__<server name>__list_resources` and `mcp__<server name>__read_resource`, which list and read its resources. For how to connect one, see [Extending Miyu](extending.en.md).

Which tools a session has is decided by its preset (see [Personas and presets](personas-presets.en.md)). A few more filters apply:

- The three memory tools exist only in sessions with memory on; the knowledge base's search, read, edit and delete exist only when at least one knowledge base can be found, and `kb_save` is always there so you can create the first one.
- `subagent` is given only to sessions on this machine, and a subagent's own subagents do not have it; `ask_user` only to main sessions on this machine with someone watching; `sessions` only to main sessions on this machine; `send_message`, `todowrite` and `session_usage` only to sessions on this machine.
- Sessions on chat platforms have further limits, see [Connecting chat platforms](heads/im.en.md).

To see which tools this session has now:

- Terminal: type `/tool-list`, which lists the names grouped as built-in, package, MCP and script. `c` copies, `Esc` closes.
- Web UI: click the session title at the top left of the conversation area, then the pencil ("Edit this preset") at the right of the "Preset" row to open the preset and see which features and tools are on.

## shell

- Which shell: decided by the system, looked up once when the core starts, and no config can change it. Your shell startup files are not read (`.bashrc`, `.zshrc` and PowerShell's `$PROFILE` are all skipped). The tool description tells the AI which kind it is, and the AI writes commands in that syntax:

  | | Which one | How it is found | Name given to the AI |
  |---|---|---|---|
  | Linux | bash | `bash` on `PATH`, or `/bin/bash` if not found | `bash` |
  | macOS | zsh | Always `/bin/zsh`, not looked up through `PATH` | `zsh` |
  | Windows | PowerShell 7, or Windows PowerShell 5.1 if there is none | First the one that comes with the tray installer (`.msi`), then `pwsh.exe` on `PATH`, and if neither exists `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe` | `PowerShell 7` or `Windows PowerShell 5.1` |
- Where it runs: this session's working directory. Each call starts a new shell from the working directory, and the previous `cd` and variables are not carried over. If the working directory was deleted or moved, no command can run and the answer is "working directory no longer exists"; switch to another working directory and it works again (see [Sessions](sessions.en.md)).
- Environment variables: the core's whole environment is passed on, minus any variable whose name contains `KEY`, `SECRET`, `TOKEN`, `PASSWORD`, `PASSWD` or `CREDENTIAL` (case-insensitive), and any that start with `MIYU_`. Also set: `GIT_TERMINAL_PROMPT=0`, `PAGER=cat`, `GIT_PAGER=cat`, `NO_COLOR=1`, `TERM=dumb`: git fails at once when it wants a password, and does not page or color.
- Timeout: if the AI does not specify, it waits 120 seconds, and it can specify up to 600. A command that has not finished by then is moved to the background and keeps running if the preset has "Background" on, and the timeline says "timed out, moved to the background as …"; if it is off, or the command starts with `sleep` (`Start-Sleep` on Windows), the whole group is stopped and the timeline says "stopped after … s".
- Stopping: when it is stopped on timeout or when you stop it, on Linux and macOS the command's whole process group is killed, and on Windows `taskkill /T /F` kills the whole process tree. After a command exits by itself, on Linux and macOS any child processes it left in the group that have not exited are killed too; on Windows they are not killed, and the leftovers keep running.
- Background: when the preset has "Background" on, the AI can put a command in the background from the start and immediately gets a job id (for example `j1`), and the result is reported automatically when it finishes. A background command runs at most `jobs.max_running` (default `30m`, can be set from `1m` to `2h`) and is stopped when that is reached. The AI can also have a background command wake it for every line of output, to watch a log.
- Idle waiting: a foreground `sleep` (on Windows `Start-Sleep`) of two seconds or more is not run, and the answer is "foreground sleep isn't allowed": a background task reports by itself when it is done.
- Output too long: at most 30000 characters are shown to the AI; beyond that, half is kept from the start and half from the end, with a note in the middle saying how much was left out. To see all of it, have the AI write the output to a file and read that.
- Dangerous commands: under full access some kinds ask you first and some are refused outright, see [Permissions and sandbox](permissions.en.md#commands-that-need-confirmation). On Windows they recognize PowerShell and cmd syntax, see [How it is written on Windows](permissions.en.md#how-it-is-written-on-windows).

## trash

What is deleted goes into the system trash: on Linux the freedesktop trash, on macOS the Trash, on Windows the Recycle Bin. To get it back, restore it from the system trash. Using `/undo` to undo that turn does not put it back.

## show

The AI shows you images, web pages, documents, audio and video it made or found, directly. Showing the same path again replaces the earlier one.

- Terminal: a card or an image on the timeline; clicking it opens it with the system's program; HTML and PDF are opened automatically once when they arrive. When no program can open it, it writes "No program can open it:" and the path; on Windows the terminal hands the file to the system to open and cannot tell whether a program can open it, so handing it over counts as opened. If the file changes later it writes "File changed", and if it is deleted, "File no longer exists".
- Web UI: put in the "Preview panel" on the right, with the most recently shown first; audio and video play right in the timeline; a file it does not recognize can only be downloaded.

While `show.system_hint` (default `true`) is on, the system prompt has a sentence reminding the AI to use "Show" to show you these things. Turning it off takes effect for new sessions:

```sh
miyu config set show.system_hint false
```

## ask_user

When the AI asks you, the terminal and the web UI both write "… is asking", with the questions and options below. `↑` and `↓` select, `Space` checks an option in a multiple-choice question, and `Enter` submits; every question lets you "Type another answer", and `n` (`N` in the web UI) adds a note; with several questions, `←` and `→` switch between them; press `Esc` twice to cancel. When another session is asking you, the terminal shows `"…" is asking you · /resume to switch`.

The AI waits for your answer indefinitely; the confirmation box's timeout `permission.confirm.timeout` does not apply. Sessions where nobody can answer (subagents, `miyu ask`, chat platforms) do not have this tool.

## advisor

When the AI is stuck, it hands the question to a model in the flagship pool (`flagship`), waits for the answer and carries on. The flagship model sees only the question the AI wrote for it, not this session. The AI can continue from its previous question. The flagship pool is empty as shipped; to put models in it, see [Models](models.en.md).

## subagent

The AI opens another session and dispatches a subagent, which works in the background and sends a report back when done; the AI can choose a model pool and a persona for it (only personas with `subagent = true` are listed), or have it continue from this session's conversation (fork), or allow it to read only and not change anything. The subagent's preset and permissions follow the session that dispatched it, and it does not save memories. For details see [Letting the AI keep working on its own](automation.en.md).

## Turning off a tool

- In the preset: turn that feature or tool off in the preset on the settings page, or write `[features]` and `[tools]` in the preset file. See [Personas and presets](personas-presets.en.md).
- Turning off a whole package: the package's switch under "Packages" on the settings page, recorded in `packages.<id>.off`, and your sessions no longer have its tools:

  ```sh
  miyu config set packages.base-net.off true
  ```

- Skills, scripts and MCP servers also have a master switch `features.<feature id>` (for example `features.mcp-github`), which affects only presets that are fully on by default; a switch written in the preset follows the preset.

All changes take effect from the next turn.

## In read-only

After switching to read-only:

- `write`, `edit`, `trash`, `kb_save`, `kb_edit` and `kb_delete` are not run, and the timeline says "Read-only mode, not run".
- `shell` and scripts run in the sandbox, which can write nowhere. For how the sandbox differs on the three platforms, see [Permissions and sandbox](permissions.en.md#the-three-platforms).
- Tools of MCP servers that are not marked read-only ask you first, every time.
- Everything else works as usual.
