# Knowledge base

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

A knowledge base is a set of documents you hand to the AI to look things up in: notes, manuals, setting books, PDFs. This page covers how to create one, when the AI looks things up, and how to update and delete. Chinese version: [knowledge.md](knowledge.md).

A knowledge base is material you provide, kept as it is, and the AI reads the original when it looks things up. [Memory](memory.en.md) is the individual notes the AI writes down by itself during conversations.

The tools the AI uses to search knowledge bases come from the shipped package `base-knowledge` ("Knowledge base" in the interface). The files of a knowledge base are yours: if this package is not installed, `miyu kb` can still manage them.

## Create one

1. Create an empty base, or mount an existing directory:

   ```bash
   miyu kb new notes --name "Study notes" --description "Japanese grammar and vocabulary"
   miyu kb mount handbook ~/Documents/handbook --name "Team handbook"
   ```

   ```powershell
   miyu kb new notes --name "Study notes" --description "Japanese grammar and vocabulary"
   miyu kb mount handbook $HOME\Documents\handbook --name "Team handbook"
   ```

2. Add files to the base you created:

   ```bash
   miyu kb add notes ~/Downloads/grammar.md ~/Downloads/kanji.pdf
   ```

   ```powershell
   miyu kb add notes $HOME\Downloads\grammar.md $HOME\Downloads\kanji.pdf
   ```

3. Try a search:

   ```sh
   miyu kb search te-form
   ```

A base id starts with a lowercase letter, contains only lowercase letters, digits, `-` and `_`, is at most 64 characters long, and cannot be a Windows reserved name such as `con`, `nul` or `com1`. A wrong one is reported as "invalid knowledge base id".

## Which files it takes

| File | Extensions | How it is cut into passages | Largest |
|---|---|---|---|
| Markdown | `.md`, `.markdown` | By heading | 4 MiB |
| Plain text | `.txt` | By paragraph | 4 MiB |
| PDF | `.pdf` | By page | 64 MiB |
| Web page | `.html`, `.htm` | Converted to text, by heading | 64 MiB |

- Text files must be UTF-8.
- PDFs and web pages need `miyu-extract`, in the same directory as `miyu` (on Windows, `miyu-extract.exe` next to `miyu.exe`), to extract the text; without it they are skipped. Scanned PDFs, or PDFs with only images, have no text and are skipped too.
- Files in subdirectories count as well. Files and directories starting with a dot, and links, do not count. Other extensions do not count.
- `miyu kb add` takes at most 20 MiB per file.

A file that cannot be taken does not block the others. `miyu kb list <kb>` writes why after that document, for example "(unreadable: too large)".

## Added and mounted

| | `miyu kb new` + `add` | `miyu kb mount` |
|---|---|---|
| Where the files are | Copied into `~/.miyu/root/kb/<id>/` (the data root is `~/.miyu` by default, `%USERPROFILE%\.miyu` on Windows) | Stay in the original directory; the base only records where it is mounted |
| The original file changes | The copy does not follow; run `add --replace` again | Follows the next time you search or list |
| Adding and deleting documents | Possible, with `add` and `remove`; the AI can write too | Not possible; read-only, for you and for the AI |
| `delete` | Moves the whole base directory to the system trash | Only unmounts; the directory is untouched |

Write the mounted directory as an absolute path or starting with `~/`; on Windows, one starting with `~\` is accepted too.

You can also put files straight into `~/.miyu/root/kb/<id>/` and change them there; creating a directory under `~/.miyu/root/kb/`, named by the id rules, creates a base. The next time you search or list, Miyu updates the index from the files: new and changed ones are read again, deleted ones are taken out, unchanged ones are left alone.

## miyu kb

```text
miyu kb [<command>] [<options>]
```

With no command it runs `list`. Options can go before or after the command.

| Command | What it does | Prints on success |
|---|---|---|
| `list` | Lists the knowledge bases, one per line: id, name, how many documents; for one that comes from a package it writes "from <package>", for one with it on "auto recall", and then the description | |
| `list <kb>` | Lists the documents in a base | |
| `search <words>…` | Searches all bases, at most 10 passages | |
| `read <kb> <document>` | Reads one page of a document. A page is 32 KiB; a PDF follows its own pages | |
| `new <kb>` | Creates an empty base | created … |
| `edit <kb>` | Changes the name and description, and turns auto recall on or off | updated … |
| `add <kb> <file>…` | Copies files into the base | added <kb>/<document> |
| `remove <kb> <document>` | Removes a document, moving it to the system trash | moved to trash: … |
| `mount <kb> <folder>` | Mounts an existing directory as a read-only base | mounted …: N documents |
| `delete <kb>` | Deletes a whole base | deleted …, moved to trash: … |
| `reindex <kb>` | Deletes the index and rebuilds it from the files | reindexed …: N documents |

| Option | What it does |
|---|---|
| `--kb <kb>` | `search` searches only this base |
| `--page <page>` | `read`: which page to read, page 1 if not written |
| `--name <name>` | `new`, `edit`, `mount`: the displayed name, the id if not written |
| `--description <description>` | `new`, `edit`, `mount`: one sentence saying what this base is |
| `--auto` | `new`, `edit`, `mount`: turns on auto recall |
| `--no-auto` | `edit`: turns auto recall off |
| `--to <dir>` | `add`: the subdirectory of the base to put the files in |
| `--replace` | `add`: replaces an existing document of the same name |
| `--format <text\|json>` | Output format of `list` and `search` |

Write `<document>` as the relative path inside the base, as printed by `list <kb>`.

```bash
miyu kb read notes grammar.md --page 2
miyu kb add notes --to grammar --replace ~/Downloads/grammar.md
miyu kb edit notes --auto
miyu kb search --kb handbook expenses
```

```powershell
miyu kb read notes grammar.md --page 2
miyu kb add notes --to grammar --replace $HOME\Downloads\grammar.md
miyu kb edit notes --auto
miyu kb search --kb handbook expenses
```

## When the AI looks things up

In a session with knowledge bases on:

- The system prompt lists the bases the AI can search: id, name, description. The AI knows when to look things up only if the name and description are clear.
- The AI searches by itself with `kb_search`, and reads the original page by page with `kb_read`.
- For a base with auto recall on, it does not wait for the AI to look: whichever passage your words mention is brought in.

In a session that can search no base at all, `kb_search`, `kb_read`, `kb_edit` and `kb_delete` are not given to the AI; only `kb_save`, so that it can create the first base.

### Auto recall

On every turn you start, it looks in the bases with auto recall on, from what you said this turn:

- If your words contain the last level of the title of a section (for example "te-form" when the title is "Grammar › te-form"), that section is brought in.
- If your words are close in meaning to a passage, that passage is brought in. This needs a semantic model; see "Semantic search" below.

At most 3 passages per turn. A passage is where it is (base, document, heading) plus the first 120 characters, in a block of at most 600 bytes; for the full text the AI uses `kb_read` itself. A passage already brought in during one stretch of context is not brought in again; counted together with the associative recall of memory, at most 40 passages per stretch of context (counted again after compaction).

Auto recall is off by default. Switch: `miyu kb edit <kb> --auto` or `--no-auto`, or "Auto-suggest" on the card on the Knowledge page of the web UI.

### Giving a section an alias

Write keywords on the first line under a Markdown section heading, and the section gets a few more names that trigger auto recall:

```markdown
## The lamp keeper

keys: the lighthouse girl, Eileen, the one who tends the lamp

The lamp keeper lives in the lighthouse on the headland…
```

- The first line starts with `关键词`, `keys` or `キーワード` (case does not matter), followed by `：` or `:`.
- Keywords are separated by `、`, `，`, `,`, `；` or `;`.
- A heading or keyword counts only if it has at least 2 characters.
- This line is not given to the AI.

## The AI writes to knowledge bases

| Tool | What it does |
|---|---|
| `kb_save` | Creates a document, or appends to one. Creates the base if it does not exist yet |
| `kb_edit` | Replaces a piece of text in a document; the original text must occur only once |
| `kb_delete` | Moves a document to the trash |

- It can write only Markdown and plain text, and after writing the file must not exceed 4 MiB.
- It cannot write to mounted bases or bases that come with a package.
- It cannot delete a whole base.
- Under full access the AI can also read and change the documents in `~/.miyu/root/kb/` with the tools that read and write files, and the index is brought up to date from the file's content; under read-only it can only read them.

To stop the AI from writing, pick one:

- Turn off these three in the preset's `[tools]`:

  ```toml
  [tools]
  kb_save = false
  kb_edit = false
  kb_delete = false
  ```

- In a read-only session these three do not run; see [Permissions and sandbox](permissions.en.md).

## Which sessions can search which base

| What it controls | How to write it |
|---|---|
| All sessions | By default every base can be searched: the ones you created, the ones you mounted, and the ones that come with installed packages |
| Sessions using a given persona | In `[knowledge]` of the persona file `persona.toml`, write `bases = ["notes"]`; only the listed ones can be searched; `[]` means none can be searched, and none can be created |
| Sessions using a given preset | Write `knowledge = false` under `[features]`; all five tools are gone, and there is no auto recall |

```toml
# ~/.miyu/root/personas/captain/persona.toml
[knowledge]
bases = ["sea-charts", "handbook"]
```

A base you create or a persona you change is picked up the next time. For how to write personas and presets, see [Personas and presets](personas-presets.en.md).

## Semantic search

Searching a knowledge base looks in two ways, by keywords and by meaning, and ranks the results together. Looking by meaning needs a semantic model: `models.embedding`, which by default uses the local `embed` package (`miyu pkg install embed`, see [Add-ons](addons.en.md) and [Models](models.en.md#the-three-uses)).

- Not installed, or set to `off`: search goes only by keywords; auto recall recognizes only titles and keywords.
- Set to a remote model: search looks both ways, and the text to compute vectors for is sent to that provider; auto recall does not bring things in by meaning, and recognizes only titles and keywords.

When the indexes are built:

- The keyword index: on search, list, mounting a directory, rebuilding, and when the AI uses the knowledge base tools, the base is brought up to date from the files.
- Vectors: filled in the background after a search; for a base with auto recall on, also in the background when it is used. Passages not filled in yet can be found only by keywords.

At the end, `miyu check` prints the index progress. "Knowledge bases: handbook 30/42" means that 30 of the 42 passages of this base have vectors. For how to read it, see [Troubleshooting](troubleshooting.en.md#run-miyu-check-first).

## Knowledge bases that come with packages

A package can also bring a knowledge base. Once installed it can be searched, and the list says "from <package>". It is read-only: you can only switch its auto recall (recorded in `~/.miyu/etc/kb.toml`) and rebuild its index. It goes away with the package when you remove it. If you have a base with the same id, yours is used.

One that is ready-made in the package source is `kb-shorinwiki`:

```sh
miyu pkg install kb-shorinwiki
```

To make one, see [Things that work as files](../authors/scripts-skills.en.md#knowledge-bases).

## Interface

- Web UI: the "Knowledge" page in the settings. Search at the top; one card per base, with the "Auto-suggest" switch on the card; click in to list the documents and read the original; for a base you created you can "Add files" and "Add a folder", drag files in, and delete documents; "Empty base", "Mount a folder", "Rebuild index" and "Delete".
- The terminal has no knowledge base page; use `miyu kb`.

## Where it is stored

| Location | What it is |
|---|---|
| `~/.miyu/root/kb/<id>/` | One base: the documents, and a `kb.toml` |
| `~/.miyu/var/cache/index/kb/` | The index, computed from the files; `reindex` rebuilds it |
| `~/.miyu/etc/kb.toml` | For bases that come with packages, the auto recall switch you changed |

`kb.toml` can be written by hand, and all four fields can be left out:

```toml
name = "Study notes"                       # name, the id if not written
description = "Japanese grammar and vocabulary"  # one-sentence description
auto = true                                # auto recall, off if not written
mount = "~/Documents/notes"                # mounted directory; if written, the documents are there
```

On Windows, write a Windows path in `mount`, as a TOML single-quoted string, with `\` inside left as it is: `mount = 'D:\notes'`.

If there are other fields, or they are written wrongly, the base is used as if it had no `kb.toml`, and `miyu kb list` shows the error with it.

For backups and moving, see [Data and backups](data.en.md).

## When something goes wrong

| What you see | What to do |
|---|---|
| "cannot add X: unsupported format" | Only the formats in the table above are accepted |
| "A mounted knowledge base is read-only." | A mounted base cannot be added to or deleted from; change it in the original directory |
| "A knowledge base from a package is read-only; only auto recall can be switched." | A base that comes with a package allows only switching auto recall and rebuilding the index |
| "Folder cannot be mounted." | The directory does not exist, or cannot be read |
| "miyu-extract is missing" after a document | PDFs and web pages cannot have their text extracted; `miyu-extract` must be in the same directory as `miyu` |
| The AI does not look things up | Try `miyu kb search`; check the persona's `[knowledge]` and whether the preset has knowledge bases on; give the base a clear name and description |
