# Simulated life

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Simulated life opens a dedicated session for a persona, called a life session: the AI wakes up on its own, again and again, according to the persona's character, what it remembers, the news and the real time. Each time it writes what the persona is doing at this moment, then decides what time to wake next. This page covers how to start one, how to look at it, how to stop it, and what it costs. Chinese version: [life.md](life.md).

## How it differs from an ordinary session

A life session is an ordinary session, with three differences:

- It is opened with the hidden preset `life` ("Life Simulation"). The web UI does not list it where you choose a preset; the terminal's picker lists it as usual. It has the seven shipped packages below on, and has no commands and no file tools:

  | Package | Called in the interface | What it does in a life session |
  |---|---|---|
  | `base-env` | Injected environment | Gives the AI environment information, including the current time |
  | `base-net` | Web search | `web_search` and `web_fetch`, for reading the news and the weather. For how to configure search, see [Web search and fetching pages](web-search.en.md) |
  | `base-memory` | Persona memory | `remember`, `memory_search`, `forget` |
  | `base-loop` | Loop tasks | `schedule_wakeup`, with which the AI decides what time to wake next |
  | `base-life` | End of life, Change over life | `end_life`, with which the AI ends this life itself; `note_change`, with which the AI notes how it has changed |
  | `base-roleplay` | Persona reminders | Reminds the AI not to break character |
  | `base-history` | Session history | `history`, for looking back at what it wrote before |

- It runs by itself even when nobody types: the core wakes it up at the due time, and one wake-up is one turn.
- It can end itself with `end_life`, and note how it has changed with `note_change` (see "Change over life" below). These two tools exist only in a life session that has not ended; other sessions opened with the `life` preset do not have them.

A persona has only one life going at a time; different personas each have their own.

## Before you start

- The session must have a persona. `/life` manages the life of the persona that the session you type it in has now; a session with no persona replies "This session has no persona, so it has no life session.". The shipped persona is `software-engineer`; to write one yourself, see [Personas and presets](personas-presets.en.md#writing-your-own-persona).
- Web search must be configured so that the AI can see the news.
- In the persona folder `~/.miyu/root/personas/<id>/` (the data root is `~/.miyu` by default, `%USERPROFILE%\.miyu` on Windows), write `prompts/life.md` to tell the AI how this life is lived (the next section). You can start without it; the shipped one is used.

A life session uses the default model at the moment it is opened.

## Writing prompts/life.md

Each time it wakes up, the AI first reads a fixed explanation (this is a life session, what is noted goes into memory, how to decide the next wake-up), then the whole of `prompts/life.md`, then after a blank line the note it left for itself at the last wake-up (nothing is added if it left none).

Who this persona is goes in `persona.md`; `life.md` only says how the days are lived:

```markdown
<!-- ~/.miyu/root/personas/captain/prompts/life.md -->
Based on your persona, what has happened lately, the news, and the real time and weather, decide what you are doing at this moment. Write only this moment: do not fill in the past, and do not act out the future.
During the day, wake up every hour or two; sleep in a little on weekends; sleep through the night.
Before sleeping, write a diary entry for the day, and use remember to note one or two things about yourself that you want to keep. You do not need to note the news you found.
```

- It is read fresh at every wake-up, so a change is used at the next wake-up.
- If the file does not exist, is empty, or the persona cannot be read, the shipped text is used (in English, with the same meaning as the example above).
- If a persona has several layers (shipped, from a package, yours), the `life.md` of the topmost layer is used, replacing the whole of it; they are not concatenated.

## Start, look, stop

In the terminal or web UI, type these in a session that has this persona:

| Command | What it does | Reply |
|---|---|---|
| `/life` | Shows this persona's life session | If it is running, it says what time it wakes next (in the time zone of the machine the core runs on, to the minute); if it is awake right now, it says so; if it is paused, it replies "Life session paused. Resume it with /life resume."; if there is none, or the last one has ended, it replies with an explanation and does **not** start one |
| `/life new` | Starts a new life and wakes it the first time right away | Says it has started; if one is already going, it first ends it (the same as `/life kill`, memory cleared), then starts the new one, and the reply says the previous one has ended |
| `/life pause` | Pauses: it does not wake when due | The same as `/life` |
| `/life resume` | Continues: wakes once right away, then follows what the AI decided. The note it left for itself last time is still there | The same as `/life` |
| `/life kill` | Ends this life | "Life session ended. What it left in memory was cleared; the session stays read-only." |

- In the terminal it acts as soon as you type it, without asking. `/life new` ends a life that is going, directly.
- In the web UI, before `/life new` and `/life kill` are sent, a card asks first: "Start a new life?" and "End this life?"; they are sent only when you click "End and start over" or "End life"; "Cancel", `Esc`, and clicking outside the card send nothing. `/life`, `pause` and `resume` do not ask.
- When the web UI receives the reply, it opens the life session the reply is about; if you are already looking at it, it does not jump.
- When there is no life that can be paused, continued or ended, `pause`, `resume` and `kill` reply "This persona has no life session.".
- If anything else follows, it replies "Usage: /life [new | pause | resume | kill]".
- Only you can use it. The command does not exist in sessions on chat platforms.

Open the life session and look at the timeline: it is what the AI wrote at each wake-up, and the title is made automatically as usual. You can also speak in it, and the AI treats what you say and do in it as having really happened.

- Terminal: life sessions are in the session list together with the other sessions.
- Web UI: the left column, "All sessions" and `/sessions` do not list life sessions. Click "More → Simulated life" in the left column, and a card pops up with one life per row: the persona name, what the AI wrote about what it is doing now, and the state ("Running · Wakes 14:05", "Paused", "Ended"). Click a row to open that session. While you are looking at a life session, the "More" row in the left column is lit. If you turn off "Simulated life" in the "Web" section of "Packages" on the settings page, the "More" menu no longer has this item; life sessions still do not go into the left column, and typing `/life` still opens one.

### Turning it on in the persona settings in the web UI

Open a persona on the "Personas" page of the web settings, and there is a "Simulated life" switch; the "Create persona" step of the first-run setup has it too.

- Turning it on: it first asks, explaining that it wakes up by itself, that each wake-up is one model request, that it notes things down by itself, and that turning it off counts as a pause. It turns on only after you confirm: where there is no life, or the last one has ended, a new one starts; a paused one continues.
- Turning it off: pauses it, without asking.
- The switch takes effect on the spot; there is no need to click "Save", and it is not written into the persona file. In the first-run setup the persona has not been created yet, so turning it on is only noted for now, and takes effect after you click next and the persona is created.
- To the right of the switch, a line shows the state: "Running · wakes 14:05", "Paused", "The last one has ended", followed by the line the AI most recently wrote about what it is doing now. Where there is a life session, there is an "Open" next to it.
- While the switch is on, a field "Life method" appears below it, which holds the `prompts/life.md` of this persona (see "Writing prompts/life.md" above). If it is empty, the shipped text is used, and the gray text in the field is it. It is saved with "Save"; saving it cleared removes the one you wrote.
- Below "Life method" is the field "Life session context window", which also appears only while the switch is on: the most tokens a life session carries, which is the `[life]` `context` in the persona's `persona.toml`. If it is empty, the shipped number is used, and the gray text in the field shows it. It must be a positive whole number, and one with commas such as `100,000` is accepted too; if it is wrong, clicking "Save" writes under the field "Enter a positive whole number (tokens)". It is saved with "Save", and once saved it governs the life sessions of this persona that have not ended, on the spot; see "Cost" below.

## Each wake-up

1. The core wakes the life session at the due time, and gives the AI the text above.
2. From the time, its memories and what it found, the AI writes what it is doing at this moment. It can save memories, search the web, and look back at what it wrote before.
3. The AI calls `schedule_wakeup` to decide how long until the next wake-up (at least 60 seconds), writes one line about what it is doing now, and can leave a note for its next self.

- If the AI does not decide this turn, it wakes again one hour after this wake-up. The AI cannot stop a life with `schedule_wakeup`; to stop one, use `/life pause`.
- At a wake-up the AI also sees the memories this persona has newly saved in other sessions since the last wake-up.
- The line the AI wrote about what it is doing now is given to the AI at the start of the next turn in the other sessions of the same persona (local ones, ones on chat platforms, forked ones, but not subagents sent out); the same line is not given twice. While the life is paused, it is not given.
- Waking depends on the core. When the core is not running, it does not wake; when the core starts again, the missed wake-ups are made up with only one, and then it goes on as usual. To keep it going all the time, keep the core running; see [Keeping it running, and servers](service.en.md).

## Memory

Memories saved by a life session go into this persona's memory, together with this persona's usual memories, and other sessions can recall them. The automatic saving after a session goes idle works as usual.

After it ends, the memories whose source is entirely in this life session are cleared and cannot be recovered; this session can no longer be found in the search of earlier conversations either. Memories whose source also includes other sessions are kept. A newly started life cannot recall the old one.

## Change over life

The persona files describe what this persona was like to begin with. As the days go by, when the AI notices it has changed (a habit, a taste, a way of talking, how it feels about someone or something), it notes that in the life session with `note_change`. The timeline records this step as "Note a change".

- One note is one sentence of at most 120 characters. At most 10 notes count at a time; when it is full, one has to be updated or dropped first. The AI can update its own notes and drop ones that no longer hold.
- Every session with this persona carries these notes, ahead of the other memories, oldest first. The persona files are not changed by a single character.
- They are a separate memory class, `change`. In other sessions the AI cannot touch them with `remember` or `forget`, and automatic saving, organizing and importing leave them alone. You can retire and restore them (as with other memories, see [Memory](memory.en.md#viewing-and-changing)), but you cannot edit their text; trying to reports "This is a change the AI noted about itself in its life; it can only be retired or restored."
- How often it notes something is up to the AI. The shipped life method has it look back about once a week, and most of the time it notes nothing; if you wrote your own `prompts/life.md`, say so there if you want it to.
- When the life ends, these notes are cleared along with the memories of that life.
- If you do not want this feature: put a `life` in your preset layer that turns off only this, and `end_life` stays:

  ```toml
  # ~/.miyu/root/presets/life.toml
  [features]
  change = false
  ```

## Ending

There are two kinds of ending, and they do the same thing:

- You type `/life kill`, or `/life new` ended the old one. The turn that is running is interrupted on the spot.
- The AI calls `end_life` and ends it itself, and must write last words. That turn finishes being said as usual. On the timeline this step is recorded as "End this life".

After it ends:

- It does not wake again, and cannot be brought back.
- The session stays, view only, and you cannot keep talking in it: speaking in the terminal reports "Session sealed", and the input box of the web UI is locked and says "This life has ended. You can only read it". The timeline can still be browsed as usual, and for one the AI ended itself, the last words are at the end.
- The memory of this life is cleared; see the previous section.

To start a new one, use `/life new`.

## Cost

Each wake-up is one round of model requests, whether or not you are looking. A life session counts as a session nobody is watching, and each turn makes at most `500` model requests; for the rules, see [Letting the AI keep working on its own](automation.en.md#when-nobody-is-watching).

- Context limit: when opened, it is set from the `[life]` `context` in the persona's `persona.toml`, and if nothing is written, to 100000 tokens (if the model needs a minimum larger than that, the minimum is used). The larger the limit, the more each wake-up carries and the more it costs. It can be changed in three places:
  - The life that is running: type `/context` in the life session, for example `/context 64k`. It is not changed back at wake-up.
  - "Life session context window" on the persona page of the web UI: once saved, the life sessions of this persona that have not ended (running or paused) are switched to the new number on the spot, and ones started later follow it too. Between this and what `/context` changed, whichever came later counts.
  - For lives started later: write it in the persona's `persona.toml`, for example:

    ```toml
    [life]
    context = 64000
    ```

    Editing this file by hand does not touch life sessions that are already open; only newly started ones follow it.
- Number of requests per turn: put a `life` on your preset layer, writing only this item:

  ```toml
  # ~/.miyu/root/presets/life.toml
  [limits]
  unattended_steps = 50
  ```

  An open life session switches to it from the next turn.

- To see how much was spent: `/usage` in the terminal; the "Usage" page in the web settings can show it per session, see [Models](models.en.md#usage-and-cost).
- There is no automatic cap on cost. If you no longer want it, use `/life pause` or `/life kill`.

## When something goes wrong

| What you see | What to do |
|---|---|
| "This session has no persona, so it has no life session." | Type `/life` in a session that has a persona |
| `/life new` reports that the schedules are full (`too_many_schedules`) | All schedules together can number at most 200. The life session has been opened and counts as paused; delete a few schedules, then `/life resume` |
| It has not woken for a long time | Type `/life` to see whether it is paused; check whether the core is running |
| What the AI wrote does not match the news | Check whether [Web search and fetching pages](web-search.en.md) is configured |

For the `life.*` methods that head authors need, see [Life sessions: `life.*`](../reference/life.en.md).
