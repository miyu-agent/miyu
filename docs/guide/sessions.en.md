# Sessions

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Each stretch of conversation with the AI is a session. This page covers how to start a new session, continue an earlier one, choose the directory it works in, go back one turn, deal with a full context, and rename, export, import and delete sessions. Chinese version: [sessions.md](sessions.md).

Session data is kept in the data root (`~/.miyu` by default, `%USERPROFILE%\.miyu` on Windows). Each session has an id, written as a UUID: hexadecimal digits in groups of 8-4-4-4-12, like `0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90`. The terminal and the web UI often show its last 8 digits, called the short id.

## Starting a new session

Terminal:

1. Type `miyu`. Typing just `miyu` opens the interface named by "Default interface" (`ui.head`) in settings, which is the terminal as shipped. When standard input or standard output is not a terminal (in a script or a pipe), it prints only the help, with exit code `2`.
2. In the box, first choose a persona, then a preset; you can type only after you have chosen. For what personas and presets are, see [Personas and presets](personas-presets.en.md).
3. Type your first message and press Enter.

Whether opening the interface starts a new session or continues the most recent one depends on "General → Display → On start, open" (`ui.startup`) on the settings page: "A new session" (`new`, shipped) or "The most recent session" (`recent`). When you are already in the interface, type `/new` to start a new one.

Web UI:

1. Click "New session" in the left column.
2. Above the input box are three buttons, "Select persona", "Select preset" and "Set workspace"; the ones you do not click use the defaults.
3. Type your first message. The session is created only when the first message is sent.

Command line: `miyu ask "<message>"` starts a new session, says this one message, prints the answer and exits:

```bash
miyu ask "What is this project for?"
cat error.log | miyu ask "Why did it fail?" -
miyu ask -C ~/src/app --preset full "Run the tests and fix the failures"
```

```powershell
miyu ask "What is this project for?"
miyu ask --file error.log "Why did it fail?"
miyu ask -C $HOME\src\app --preset full "Run the tests and fix the failures"
```

If you give no message, the whole message is read from standard input; if a word in the message is exactly `-`, standard input is read and put after it. All the arguments of `miyu ask`:

| Argument | What it does | Can it be written with `-c`, `-s` |
|---|---|---|
| `-c`, `--continue` | Continues the session that the last `miyu ask` started | Not with `-s` |
| `-s`, `--session <id>` | Continues this session | Not with `-c` |
| `-C`, `--cd <directory>` | Works in this directory. The directory must already exist. If not given, it is the directory you were in when you typed the command | No |
| `--add-dir <directory>` | Also counts another directory as part of this session's workspace; it can be written several times | Yes. If written when continuing, the ones added before are replaced as a whole by the ones written this time |
| `--persona <persona>` | Uses this persona | No; and not with `--no-persona` either |
| `--no-persona` | Uses no persona | No |
| `--preset <preset>` | Uses this preset | No |
| `--permission <read-only\|full>` | The permission level at the start: read-only or full access, see [Permissions and sandbox](permissions.en.md) | No |
| `--model <model>` | Uses this model or `@pool`. A session you continue is switched to it from then on, see [Models](models.en.md) | Yes |
| `--no-memory` | This session neither recalls nor saves memories, see [Memory](memory.en.md) | No |
| `--file <file>` | Attaches a file; it can be written several times, see "Giving the AI files and images" below | Yes |
| `--format <text\|json\|jsonl>` | The output format. `text` (shipped) prints as it arrives; `json` prints one JSON on the last line; `jsonl` prints one event per line | Yes |
| `--timeout <duration>` | How long to wait at most, for example `30s`, `10m`, `1h`; without a unit it is seconds. When it is reached, the turn is interrupted, with exit code `3` | Yes |
| `--from <name>` | When another agent calls it, reports its own name, for example `claude-code`, and this message is recorded as coming from it | Yes |

If the AI sent out subagents, `miyu ask` waits until they have all reported back and the answer is finished before it exits. The exit codes:

| Exit code | Meaning |
|---|---|
| `0` | The turn ended as usual |
| `1` | An error, for example the core cannot be reached, a refusal, or a model error |
| `2` | Wrong arguments |
| `3` | Interrupted (`Ctrl+C`), or `--timeout` was reached |
| `4` | The turn ended, but some steps needed your confirmation and were not done |
| `5` | No model is available |

## Continuing an earlier session

Terminal:

- Type `/sessions` (alias `/resume`) to open the session list, which you can search; `Enter` switches to one. In the list, `Ctrl+P` pins, the space bar ticks several, and `Ctrl+D` deletes.
- `/jump` lists what you said in this session; pick one to jump to it.
- The first line of `/status`, "Session ID", is the full id; the sidebar shows the short id `#…`.
- To open a given session straight from the shell, use `miyu tui --resume <id>`; if it cannot be opened, it reports an error and exits.

Web UI:

- The left column lists sessions grouped by time. Click "View all sessions" to go to the all-sessions page, where you can filter and search.
- Type `/sessions <word>` to open the session list above the input box, searched with that word.
- In the "⋮" (Session actions) menu on the right of each session there is "Copy session ID".
- To open a given session straight from the shell, use `miyu web --session <id>`.

Command line:

```sh
miyu ask -c "How do I run the tests?"                           # continue the one the last miyu ask started
miyu ask -s 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90 "Keep going"    # continue the given one
```

`-c` recognizes only sessions that `miyu ask` started; for sessions started in the terminal or the web UI, use `-s` with the full id. If you have never used `miyu ask`, `-c` reports "no session from 'miyu ask' to continue". To get the id in a script, use `--format json`; the `session` in the last line is the id.

`miyu undo`, `restore`, `redo`, `compact`, `recap`, `rename` and `session export` also take `-s <id>`; if you leave it out, they use the session that the last `miyu ask` started.

## Which directory a session works in

Each session remembers one working directory, and when the AI runs commands or writes relative paths, they are counted from there. Once the session is open it keeps using it, and it changes only when you change it explicitly; when you change it in one interface, the other interfaces follow.

The working directory of a new session:

| Where it starts | Working directory |
|---|---|
| Terminal | The directory the terminal was opened in; if you changed it with `/workspace <path>` before starting the session, the changed one |
| Web UI | If you did not click "Set workspace", the session's own default workspace `~/.miyu/root/workspace/<session id>/`, shown in the interface as "Default workspace" |
| `miyu ask` | The directory you were in when you typed the command; if you wrote `-C`, that |

To change the working directory:

- Terminal: `/workspace <path>`; a relative path is counted from the directory the terminal is in.
- Web UI: `/workspace <path>`; without a path, it opens a menu for choosing a directory. Before a new session is opened, click "Set workspace".
- Command line: `-C` applies only to newly started sessions; a session you continue uses the directory it remembers, and when that differs from the directory you are in, a line "· Session working directory: …" is printed at the start.

In the web UI the path must be absolute or start with `~`: on Linux and macOS write `/…` or `~/…`; on Windows write `C:\…` or `C:/…`, and `~/…` and `~\…` are accepted too. Inside the data root, only the part under `~/.miyu/root/workspace/` can be a working directory, and anything else is reported as unusable; for a `miyu ask` typed inside the data root, the session's default workspace is used instead, with the message "working directory … is too broad; using …".

A working directory that is too broad still works, and commands start from there; when you switch to it with `/workspace`, the reply says "Workspace switched to … (broad directory).". The root directory (`/` on Linux and macOS, and a drive root such as `C:\` on Windows) counts as too broad on all three platforms; on Windows the home directory itself and the directory that contains the data root count as well. On Windows the terminal usually opens in the home directory. To have the AI work in a project, `cd` into the project directory before typing `miyu`; write `-C <directory>` for `miyu ask`; for a session that is already open, type `/workspace <path>` to switch.

A directory added with `--add-dir` cannot be `~` itself, the home directory, the root directory, or a directory that holds the data root, and it cannot be inside the data root either; if you write one, the whole command is not accepted.

## Undo, restore, redo

Undo goes back only in the conversation; it does not change files back. Files the AI changed and commands it ran in the undone turn stay on disk as they were. To get files back, use version control such as git, or your own backup; Miyu has no command that changes files back. `/files` in the terminal and the file changes block in the web UI's right column show which files this session changed and the diff of each step, so you can change them back by hand from the diffs.

| | Terminal, web UI | Command line |
|---|---|---|
| Undo the last turn | `/undo` (alias `/rewind`) | `miyu undo` (alias `miyu rewind`) |
| Restore what you just undid | `/restore` | `miyu restore` |
| Undo the last turn and run it again with the same message | `/redo`; in the web UI, click "Redo" at the end of the AI's turn | `miyu redo` |
| Undo the last turn and run it again with a different message | `/edit`; in the web UI, click "Edit" below your message | `miyu redo <new message>` |

Undo:

- What is undone is the last turn: your message and the AI's answer, which the AI can no longer see from then on. Things that came from elsewhere are kept, such as a subagent's report, a schedule firing, or a message from another session; what is undone is only the AI's response to them.
- The background commands and subagents that turn sent out and that are still running are stopped together, and the reply says how many were stopped.
- If a compaction or a clear happened in the undone turns, the context goes back to before the compaction or clear.
- In the terminal and the web UI, the message you undid is put back in the input box. If the AI is answering and you have a message queued that has not been sent, `/undo` first takes back the queued message.

Restore has to be done before you send the next message. If you undid several times in a row, you can restore them one at a time. After a redo, you cannot restore.

Redo and edit work only on the last turn, and only if that turn was started by your message; they do not work while the AI is answering.

## When the context is full

Each request the AI makes carries the session's context. When the context reaches a certain fraction of the model's window, Miyu automatically compresses the older part into a summary, keeps the most recent part verbatim, and carries on.

To see how much is used:

- The terminal sidebar says "Context": used / window size · percentage. `/context` opens the details, showing how much each block takes.
- In the web UI, below the input box there is a context cell, and `/context` opens the same details.
- It is also in `/status`.

To compact by hand:

```sh
/compact                         # in the terminal or the web UI
/compact keep the details of the database migration   # what follows is your request for the summary
miyu compact -s <id> keep only the conclusions      # on the command line
```

The two settings for automatic compaction are on the settings page under "Advanced → Compaction", or you can use `miyu config set`:

| Key | On the settings page | Shipped value | What it does |
|---|---|---|---|
| `compaction.line` | Compaction line | `85` | At what percentage of the window the context is used up before it compacts automatically; it can be `20` to `95`. A model with a small window has to leave room for the answer, so it actually compacts earlier: with a 200,000-token window, setting it above 85 has no effect, and only a million-token window can reach 95 |
| `compaction.prepare` | Prepare compaction early | `true` | When nearing the line, it compacts the older part in the background ahead of time, and swaps it in when the line is reached, so there is no stop to wait. When turned off, it compacts only when the line is reached |

Both take effect from the next turn. To change them only for the current session:

- `/compact-line 70`: this session compacts at 70%, and it can be `20` to `95`; `/compact-line off` goes back to following the settings; typing just `/compact-line` says what it is now and where it comes from.
- `/context 128k`: sets a context limit for this session; the number can be followed by `k` (thousand) or `m` (million); `/context off` or `/context unset` removes it, and the model's window applies. A limit so small that a compaction line cannot be worked out is not accepted, and the web UI shows "The context cap must be at least …".

If you do not want the earlier content any more:

- `/clear` (alias `/reset`) clears the context; the session stays the same, and the reply is "Context cleared.". If you type `/undo` after clearing, it undoes the last turn from before the clear, and the clear is undone along with it.
- Or use `/new` to start a new session.

## Recap

`/recap` or `miyu recap` has the AI write a recap: what is being done, what has been finished, what is left. It makes one model request and does not start a new turn. On the command line it prints only this text to standard output, so you can pipe it.

## Stopping

- Terminal: while the AI is answering, press `Esc` twice to interrupt, and the queued messages are sent afterwards; press `Ctrl+C` to interrupt, and the queued messages go back to the input box.
- Web UI: while the AI is answering, press `Esc` twice to interrupt.
- Command line: press `Ctrl+C`, with exit code `3`.
- `/stop`: interrupts this turn, keeps the queued messages without sending them, and then stops the background commands and subagents this session sent out, along with this session's loop. The reply is "All stopped.".

## Renaming

As shipped, the AI titles a session from the conversation.

- Terminal, web UI: `/rename <title>` changes it to this; typing just `/rename` has the AI pick a new one from the last few turns; `/rename -` removes the title you gave.
- Web UI: "Rename" in the "⋮" menu on the right of the session, which edits it right in the list.
- Command line: `miyu rename <title>`, where several words are joined with spaces; without a title, the AI picks a new one. When it is done, it prints nothing.

## Export and import

Two formats:

- Raw bundle (ZIP): the original session log, the subagents' sessions, the fork source and the attachments are all inside; use it to move a session to another machine or another data root. The bundle also has a `transcript.md` that you can read directly. What is exported is not masked, so keep it safe yourself.
- Markdown: for people to read, or to paste to another AI. Keys you have configured are replaced in it.

Markdown has three uses:

| The command line's `--for` | In the interface | What it looks like |
|---|---|---|
| `read` (shipped) | Conversation only, as Markdown | With a title, time span, model and usage; thinking and long output are folded |
| `agent` | For another agent to continue | Opens with a note that this is a session transcript, tools are written with real names and raw arguments, it starts from the last compaction by default, has no thinking, and is all in English |
| `chat` | For a web chat | Opens with a token estimate, each tool takes one line, subagents show only their reports, and there is no thinking |

Command line:

```bash
miyu session export                                   # the session of the last miyu ask, written to ./miyu-session-<first 8 characters of the id>.zip
miyu session export 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90 -o ~/backup/app.zip
miyu session export --md --for agent --last 20 -o -    # the Markdown of the last 20 turns, to standard output
miyu session import ~/backup/app.zip                     # prints the id of the newly imported session
miyu session import old-session.zip --archive               # import as a read-only archive
```

```powershell
miyu session export
miyu session export 0198c2a4-7e1b-7c3d-9a2f-4b5c6d7e8f90 -o $HOME\backup\app.zip
miyu session export --md --for agent --last 20 -o -
miyu session import $HOME\backup\app.zip
miyu session import old-session.zip --archive
```

| Argument | What it does |
|---|---|
| `export [<id>]` | Exports. If you give no id, it is the session of the last `miyu ask`. When done, it prints where it wrote |
| `-o`, `--output <file>` | Writes to this file. If not given, it is `miyu-session-<first 8 characters of the id>.zip` in the current directory, or `.md` for Markdown. For Markdown, `-` writes to standard output |
| `--md` | Exports as Markdown |
| `--for <read\|agent\|chat>` | The use of the Markdown; can only be written with `--md` |
| `--last <turns>` | Takes only the last few turns of the Markdown; can only be written with `--md` |
| `import <file>` | Imports a raw bundle and prints the id of the newly imported session; one that already exists with the same content is not imported again |
| `--archive` | Imports as a read-only archive: you can view and search it, but cannot continue the conversation |

An exported file cannot be written into the data root, and an existing file with the same name is not overwritten.

Terminal: type `/export`, first choose the use ("Full archive" or one of the three Markdown ones), then "Copy to clipboard" or "Save as a file". An archive can only be saved as a file; Markdown over 512 KiB can also only be saved as a file. The file is written in the directory the terminal is in. Copying goes through the terminal's OSC 52; if the terminal does not support OSC 52, the copy does not go in, and no error is reported, see [Terminal](heads/tui.en.md).

Web UI: "Export…" in the "⋮" menu on the right of the session. For Markdown you can choose the range (All, Current context, Last turns), whether to include thinking, and how tools are written, and then "Copy" or "Download"; "Full archive" can only be downloaded. Import is "Import session…" at the top of the "All sessions" page; choose a `.zip`.

Archives are in their own group in the session list, "Archived".

## Giving the AI files and images

What you can give: images, PDFs, text and other files. The AI sees images directly; for kinds the model cannot read, the interface tells you. One attachment is at most 20 MiB; an image is at most 5 MiB and no more than 8000 pixels on each side.

Terminal:

- Drag the file into the terminal window, or type `@` and choose from the list. Images, PDFs, audio and video become attachments; other files and directories are written into the message as paths, and the AI reads them itself if it wants to see them.
- `Ctrl+V` pastes an image from the clipboard as an attachment. In Windows Terminal, use `Alt+V` to paste an image.
- A message over 1 MB is automatically turned into a text attachment and sent.
- For a file over the size limit, only the path is given to the AI.

Web UI:

- Drag files into the window, paste in the input box, or type `@` and choose from the list. On devices you touch with a finger, there is a paperclip button below the input box.
- At most 10 at a time.
- For a file over the limit, the web UI finds the original file on this computer and gives only the path to the AI; if it cannot find it, click it and fill in the full path. If the web UI is open on another device, a file over the limit cannot be sent.

Command line: `--file <file>`, which can be written several times:

```sh
miyu ask --file screenshot.png --file log.txt "Does this error match the screenshot?"
```

Files inside the data root cannot be attachments.

## Todos

When the AI does a multi-step job, it makes a todo list. You can see it in the web UI's right column; `/todo` lists the current todos and the state of each (pending, in progress, completed), and `/todo clear` empties them.

## Deleting a session

- Terminal: `/delete` deletes the current session and switches to a new one. You cannot delete while the AI is answering; interrupt first. In the `/sessions` list, press `Ctrl+D` twice to delete the selected one, and tick several with the space bar to delete them together.
- Web UI: "Delete" in the "⋮" menu on the right of the session; or "Select" in the left column to tick several and delete them together.

When you delete a session, the sessions of the subagents it sent out are deleted with it, and any that are running are stopped first. A deleted session is moved to `~/.miyu/root/trash/sessions/<session id>/` and kept for 7 days, and the core clears those that have reached 7 days the next time it starts. Miyu has no command that brings one back into the session list.

## When something goes wrong

| What you see | What to do |
|---|---|
| "no session from 'miyu ask' to continue" | `-c` recognizes only sessions that `miyu ask` started. For sessions started in the terminal or the web UI, use `-s <id>` |
| "working directory … is too broad; using …" | `miyu ask` was typed inside the data root. Move outside the data root, or give a directory with `-C` |
| "Nothing to restore" | After the undo, a new message was already sent, or a redo was done, so it cannot be restored |
| "Can't redo" | The last turn was not started by your message, or this session has no turn yet |
| "This is an archive and can't be continued" | A session imported with `--archive` can only be viewed. To continue the conversation, import the raw bundle again without `--archive` |
| "The context cap must be at least …" | The limit set with `/context` is too small; raise it by the number in the hint |
