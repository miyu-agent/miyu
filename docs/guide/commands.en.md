# Slash commands

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Every command you can use by typing `/` in the input box is listed on this page: what each one does, what arguments it takes, and where it works in the terminal, the web UI and chat platforms. The session commands (undo, compact, export and so on) are covered in detail in [Sessions](sessions.en.md). Chinese version: [commands.md](commands.md).

## How to type them

- Type `/` in the input box. A command list pops up above it and narrows as you type; names or aliases that start with what you typed come first. Select with `↑` `↓`, complete with `Tab`, run with `Enter`.
- Write arguments after the command name, with one space: `/compact keep the interface changes`.
- A name that is not in the list is left to the core to recognize. If the core does not recognize it either, the terminal tells you why it cannot run; in the web UI, if there is text after it, it is sent to the AI as an ordinary message. Anything after `/` that does not look like a command name (a command name starts with a Latin letter and contains only Latin letters, digits, `-` and `_`), such as `/hello!` or `/home/me`, is treated as an ordinary message from the start.
- `/help` lists the keys and all commands.

There are two kinds of commands:

- Core commands: the ones the core registers, plus those from packages and the ones you add yourself. They work in the terminal, the web UI and chat platforms, and both the terminal and the web UI list them in the command list.
- Head commands: they exist only in that interface, see "Terminal commands" and "Web UI commands" below.

When both sides have the same name (`/clear`, `/stop`, `/context`, `/workspace` and so on), the interface does it its own way, and the description follows the core.

## Core commands

| Command | Alias | Arguments | What it does | Details |
|---|---|---|---|---|
| `/clear` | `/reset` | | Clears the context; the session stays | [Sessions](sessions.en.md) |
| `/stop` | | | Interrupts this turn, keeps queued messages without sending them, and stops this session's background commands, subagents and loop | [Sessions](sessions.en.md) |
| `/workspace` | | `<path>` | Changes this session's working directory. Without a path, it says what the current one is. Only you can use it | [Sessions](sessions.en.md) |
| `/context` | | `[<value> \| unset]` | With a value, sets this session's context limit, for example `128k` or `1m`; `unset` or `off` removes it; without one, it says the current limit and the compaction line | [Sessions](sessions.en.md) |
| `/todo` | | `[clear]` | Lists the todos; `clear` empties them | [Sessions](sessions.en.md) |
| `/remember` | | `<text>` | Records a memory | [Memory](memory.en.md) |
| `/dream` | | `[stop]` | Organizes memory now; `stop` stops the organizing | [Memory](memory.en.md) |
| `/clear-memory` | `/reset-memory` | | Clears the memories recorded in this session | [Memory](memory.en.md) |
| `/goal` | | `[[--rounds <rounds>] <goal> \| pause \| resume \| clear]` | Without arguments, shows progress; with a goal, sets a goal, or changes the existing one, and `--rounds` sets the maximum number of rounds; `pause` pauses, `resume` continues, `clear` removes it | [Letting the AI keep working on its own](automation.en.md) |
| `/loop` | | `[[<interval>] <text> \| off]` | Says the text once every interval, written as `5m` or `2h`; without an interval, the AI decides when the next one is; with nothing at all, the AI decides what to do and when; `off` stops this session's loop. With an interval but no text, it replies with the usage | [Letting the AI keep working on its own](automation.en.md) |
| `/life` | | `[new \| pause \| resume \| kill]` | Without arguments, shows the life session; `new` starts a new one, ending the current one first if there is one; `pause` pauses, `resume` continues, `kill` ends it | [Simulated life](life.en.md) |

`/todo`, `/remember`, `/dream`, `/clear-memory`, `/goal` and `/loop` follow their packages: if the package is not installed, or the session's preset has that feature off, the command is not listed. `/life` is always listed; typed in a session with no persona, it looks across all personas: when only one persona has a life, that is the one, when several do it lists them, and `/life new` needs the session to have a persona first; `/life new` and `/life kill` do not ask first in the terminal and pop up a confirmation card in the web UI; the memories of the life that ended are cleared.

In the web UI, a core command typed in a new session that has not been opened yet does not open a session; it says one line on the spot. `/goal <goal>` and `/loop <text>` are the exceptions: like a first message, they open the session first. Typing just `/loop` does not open a session and shows the hint "Type what to say on each loop"; to start an autonomous loop, send a first message to open the session and then type it.

## Packages and commands you add yourself

These also count as core commands, and sit in the command list together with the ones above:

| Where it comes from | What it looks like | What happens when you type it |
|---|---|---|
| Command template: `root/commands/<name>.md` under the data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`), that is `~/.miyu/root/commands/<name>.md`, or under a package's `commands/` | `/<name> arguments` | The template body is sent to the AI as a message from you |
| A command declared by an extension (`[[slash]]` in the manifest) | `/<name> arguments` | The extension's program handles it and sends you back a piece of text |
| An MCP server's prompt | `/<server>:<prompt> arguments`, for example `/github:review-pr 123` | The content fetched is sent to the AI as a message from you. Works only in sessions on this machine |
| A full page that an extension provides | `/<name>` | Opens that page |

When a template in `~/.miyu/root/commands/` has the same name as one in a package, yours wins; when it has the same name as a core command registered above, the core's wins. Each template and each MCP server is switched on or off separately in a preset; typing one that the preset has off says "Preset "…" has /… off." (with the preset name and the command filled in). For how to write templates and extension commands, see [Extending Miyu](extending.en.md).

## Who can use them

On chat platforms, who can use a core command is set by `commands.<command name>.access`. The settings page has no entry for it; change it with `miyu config set`:

| Value | Who can use it |
|---|---|
| `admin` | You, and the people you put under "Users allowed to run admin commands" on the group card in the chat platform's backstage page. The platform's own group owners and group admins do not count, see [Chat platforms](heads/im.en.md) |
| `anyone` | Anyone |
| `off` | Turned off, nobody can use it; typing it says "/<name> is turned off." |

If it is not set, the command's own setting applies (the one an extension writes in `[[slash]]`); if there is none, it is `admin`. In the terminal and the web UI, the person talking is always you, so only `off` has any effect.

```sh
miyu config set commands.clear.access anyone       # anyone in the group can /clear
miyu config set commands.remember.access off       # turn off /remember
```

A change takes effect on the spot. It governs only core commands; head commands are not affected.

## In chat platforms

When you send the AI a message that starts with `/` on a chat platform, the core first tries to recognize it as a command, and what the core does not recognize is sent to the AI as an ordinary message. Only core commands work (the ones under "Core commands" above, plus template and extension commands; MCP prompts do not), and who can use them depends on `commands.<command name>.access`. The terminal's and the web UI's own commands (`/undo`, `/compact`, `/new` and so on) do not exist here. For platform details, see [Chat platforms](heads/im.en.md).

## Other ways to write in the input box

| What you write | Where | What it does |
|---|---|---|
| `$<skill name>` | Terminal, web UI | Names a skill: type `$` to pop up the skill list, and the body of the skill you pick goes to the AI along with this message. One message can name several |
| `@<path>` | Terminal, web UI | Pops up a file list to pick a file. Images and the like are taken as attachments; other files and directories are written into the message as paths, see [Sessions](sessions.en.md) |
| `!<command>` | Terminal | Type `!` as the first character of the box to enter command mode; Enter runs the command directly in the session's working directory, without a permission prompt and outside the sandbox; the command and its output are handed to the AI together. It runs for at most 120 seconds and cannot take attachments. With the box empty, press `Backspace` or `Esc` to go back to normal |
