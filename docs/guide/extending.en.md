# Extending Miyu

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Without writing a resident program, you can add four kinds of things to your own Miyu: skills, scripts, slash command templates and MCP servers. The first three are files; MCP servers are written into the config. Chinese version: [extending.md](extending.md).

| | What it is | Where it goes |
|---|---|---|
| Skill | A `SKILL.md` that teaches the AI a way of doing something | `~/.miyu/root/skills/<name>/SKILL.md` |
| Script | One file is one tool for the AI | `~/.miyu/root/scripts/<file>` |
| Slash command template | A `.md`; when you type `/<name>`, the body is sent to the AI as something you said | `~/.miyu/root/commands/<name>.md` |
| MCP server | Hooks up an existing MCP server and gives its tools to the AI | A `[mcp.<name>]` table in `~/.miyu/etc/config.toml` |

In paths, `~/.miyu` is the data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`; if `MIYU_HOME` is set, that one). Create the three folders above if they do not exist.

In presets, each of the four is a feature that can be switched on its own: a skill is `skill-<name>`, a script is `script-<tool name>`, a template is `command-<name>`, and an MCP server is `mcp-<server name>`. See [Personas and presets](personas-presets.en.md).

Ones that are written wrongly, or have the same name as something else, do not appear; `miyu check` says which and why.

## Skills

A skill is a folder with a `SKILL.md` in it. The format is the public Agent Skills format, so skills that Claude Code, Codex and the like read work here as they are.

### Writing one

`~/.miyu/root/skills/weekly-report/SKILL.md`:

```markdown
---
name: weekly-report
description: "Write the weekly report from this week's git log and notes/. Use when the user asks for a weekly report, 周报."
metadata:
  display_name: Weekly report
  display_name_zh: 写周报
  summary: Weekly report from git log and notes
  summary_zh: 照 git 记录和笔记写周报
---

# Weekly report

1. Run `git log --since="1 week ago" --oneline` in the workspace.
2. Read every file under `notes/` changed this week.
3. Write `reports/YYYY-WW.md` with three sections: Done, In progress, Blocked.
```

Between the two `---` lines at the top is YAML, and after it is the body.

| Field | Notes |
|---|---|
| `name` | 1 to 64 characters, only lowercase letters, digits and `-`; `-` is not at the start or end and not doubled. Same as the folder name. A different name is used as written; a missing or invalid one falls back to the folder name, and `miyu check` gives one warning for each; one where both are invalid is not taken |
| `description` | For the AI: say what it is and when to use it. Required. Anything over 1024 characters is cut. Put it in double quotes: a value with a "colon and space" in it and no quotes is not valid YAML; Miyu can re-read it as one whole sentence, but gives a warning |
| `display_name`, `summary` under `metadata` | The name and one line for you. Chinese and Japanese go in `display_name_zh`, `summary_zh`, `display_name_ja`, `summary_ja` |
| `disable-model-invocation` | With `true`, the AI does not use it on its own; only you can name it |
| `user-invocable` | With `false`, you cannot name it; it is only for the AI itself |

Other fields (`license`, `compatibility`, `allowed-tools` and so on) are recognized and not used. Other files kept in the folder (reference material, bundled scripts) can be read by the AI but not changed; a bundled script is not a tool, so say in the body how to run it.

### When the AI reads it

Normally the AI sees only each skill's name, its `description` and the path of its `SKILL.md`, and reads the body itself when it thinks it is useful. So `description` must say when to use it. The AI must have a tool for reading files (the shipped "Read files") for skills to be listed.

You can also name one: type `$` in the input box of the terminal or the web UI, and a list of skills pops up; pick one, or type `$weekly-report` directly. You can name several in one message. The bodies of the skills you named go ahead of that message, and all of it goes to the AI together. If the session's preset has the skill off, naming it reports `Preset "<preset>" has the skill $<name> off.`

### After you add one

- Once it is in the folder, open sessions see it from the next turn too.
- The "Skills" page of the web UI settings page (`/settings`) lists all skills, marked "Your own", "From packages" or "Shared", each with a switch; "Open folder" opens `~/.miyu/root/skills/`.
- Type `$` in the input box and see whether it is in the list.

For the same name, the one in `~/.miyu/root/skills/` wins, then the one a package brings, and last the ones in other folders.

### Reading skills in other folders

Other apps (Codex, opencode and the like) often install skills in `~/.agents/skills`. Once you turn it on, Miyu recognizes them too:

```sh
miyu config set skills.external.enabled true
```

Or turn on "Read Skills from other folders" at the top of the web UI "Skills" page. Which folders to read is `skills.external.dirs`, `["~/.agents/skills"]` when shipped; write `~/…` or an absolute path, in order, and for the same name the one listed first wins. On Windows `~\…` is accepted too:

```bash
miyu config set skills.external.dirs '["~/.agents/skills", "~/src/team-skills"]'
```

In PowerShell, use double quotes outside and TOML single-quoted strings inside; it can be copied as is in both Windows PowerShell 5.1 and PowerShell 7:

```powershell
miyu config set skills.external.dirs "['~/.agents/skills', '~/src/team-skills']"
```

Both take effect from the next turn. Miyu does not delete skills in these folders; to delete one, delete it in that folder.

### When it is written wrongly

`miyu check` reports skills that were skipped, and why: the top has no section wrapped in two `---` lines, the YAML cannot be read, there is no `description`, or neither the name nor the folder name is written validly. Ones that were taken but are not in the proper format get a warning of their own:

| Warning | What it means |
|---|---|
| The name does not match the folder; the skill goes by the written name <name> | Make them the same |
| The name is missing or not 1 to 64 lowercase letters, digits and single hyphens; the skill goes by its folder name <name> | Add `name` |
| The front matter is not valid YAML | Put quotes around values that have a colon |
| The description is longer than 1024 characters; the rest was cut | Make it shorter |
| `compatibility` should be text of at most 500 characters | Make it shorter |
| `metadata` should map text keys to text values | Values cannot be numbers, lists or nested tables |
| Same name as <other>, which covers it; this one is not used | Pick another name |

## Scripts

One file is one tool. The comments at the top of the file give the description and the parameters, and the AI calls it as it calls any other tool.

### Writing one

Shell, with no parameters, `~/.miyu/root/scripts/disk-free.sh`:

```sh
#!/bin/sh
# Description: Show used and free space of every mounted disk.
# 描述：看每块盘用了多少、还剩多少
# Display name: Disk free
# 显示名称：磁盘空间
# Timeout: 10

df -h
```

It is started by `#!/bin/sh`, so on Windows `sh` must be found on `PATH` for it to start. On Windows, write the same thing as PowerShell, `~/.miyu/root/scripts/disk-free.ps1`, used on Windows only:

```powershell
# Description: Show used and free space of every mounted disk.
# 描述：看每块盘用了多少、还剩多少
# Display name: Disk free
# 显示名称：磁盘空间
# Timeout: 10

Get-PSDrive -PSProvider FileSystem
```

Python, with parameters, `~/.miyu/root/scripts/c_to_f.py`:

```python
#!/usr/bin/env python3
# Description: Convert a temperature between Celsius and Fahrenheit.
# 描述：摄氏度和华氏度互换
# 显示名称：温度换算
# Clicall: yes
# Parameters:
# {"type": "object",
#  "properties": {"value": {"type": "number"}, "to": {"type": "string", "enum": ["C", "F"]}},
#  "required": ["value", "to"]}

import json
import sys

args = json.load(sys.stdin)
v = float(args["value"])
if args["to"] == "F":
    print(f"{v} °C = {v * 9 / 5 + 32:.1f} °F")
else:
    print(f"{v} °F = {(v - 32) * 5 / 9:.1f} °C")
```

The tool name follows the file name: the last extension is removed, characters that are not letters, digits, `_` or `-` become `_`, and it is at most 64 characters. The ones above are `disk-free` (the `.sh` and `.ps1` have the same name, so keep only one) and `c_to_f`. Subfolders and files starting with a dot do not count.

### The header comments

The header is the run of `#` or `//` comment lines starting at the first line of the file, with the `#!` line counted in it; it ends at the first line that is not a comment. Leave a blank line after the header before any other comment, or a "Timeout: …" in a later comment is read in too. Each line is "Key: value"; the colon can be the full-width Chinese colon or the ordinary one.

| Key | Notes |
|---|---|
| `Description` | One line for the AI. Required |
| `描述` | One line of description for you |
| `Display name`, `显示名称` | The name for you, in English and in Chinese |
| `Parameters` | The JSON Schema of the parameters; the top level must be `"type": "object"`. It can be on the same line, or from the next line on across several lines, until it makes one complete JSON. Leaving it out means no parameters |
| `Timeout` | The most seconds it may run, a positive integer, `60` by default. At the limit the whole group of processes is killed |
| `Clicall` | `yes` (or `true`): when the AI writes a script inside a command, it can also call this one with `miyu call`, and the result goes to that command and stays out of the conversation. Unset means `no`. It suits scripts that only read or look things up; do not set it on ones that change things, send things or cost money |
| `Venues` | Which sessions get it: some of `local` (the terminal and the web UI on this machine), `private` (private chats on a chat platform) and `group` (groups), comma separated, for example `Venues: local, private`. Unset means every kind |
| `Scope` | Narrows further within `Venues`: `any` (the default), `local` (sessions on this machine), `local_main` (the main session on this machine, not given to subagents), `local_main_attended` (the main session on this machine, and someone is watching), `spawn` (on this machine, and the subagent depth has not reached the limit) |
| `Role` | Only `read_file` is recognized: it says this tool reads text files |

A script with no `Description`, or with a wrong value in `Parameters`, `Timeout`, `Clicall`, `Venues`, `Scope` or `Role`, is not taken as a whole. A key name for `Role` or `Scope` that is one letter off, such as `role` or `Scpoe`, also counts as wrong. Other keys are recognized and not used.

### How it runs

- How it is started depends on whether the first line has `#!`:

  | | With `#!` | Without `#!` |
  |---|---|---|
  | Linux, macOS | Started as written: the interpreter, the arguments after it, the script | The file is run directly, and needs the executable permission: `chmod +x ~/.miyu/root/scripts/<file>` |
  | Windows | If the interpreter is written as an absolute path that exists on this machine, that one is used; otherwise the interpreter's name is looked up on `PATH`, with `env` taking the name after it and `python3` turned into `python`: `#!/usr/bin/env python3` looks for `python`, and `#!/bin/sh` looks for `sh` | By extension: `.py` uses `python`, `.ps1` uses Windows PowerShell (`powershell`, which reads no profile and ignores the execution policy), `.js` uses `node`, `.cmd` and `.bat` use `cmd /C`; anything else is run directly |

  Miyu does not bring interpreters; install the ones you use. On Windows, once Python and Node are installed, `python` and `node` must be found on `PATH`.
- Arguments: one JSON object from the AI, which you can read in full from standard input; when it is at most 30 KiB, a copy is also in the environment variable `MIYU_ARGS_JSON`. A long one is only on standard input, so reading standard input is the safest.
- Result: standard output and standard error go to the AI in the order written, at most 30000 characters, and if there is more, half the head and half the tail are kept. An exit code other than `0` counts as failure, and the reason goes in the output.
- Progress: print a whole line starting with `miyu-progress: `, and you see it in the interface while the AI does not. Write it to standard error and flush at once, for example in Python `print("miyu-progress: 3/10", file=sys.stderr, flush=True)`.
- The working directory is the session's working directory. Python reads and writes standard input and output as UTF-8 (`PYTHONUTF8=1`).
- `miyu call` cannot be called from inside a script.

The folders given to scripts:

| Environment variable | What it is |
|---|---|
| `MIYU_CACHE_DIR` | A writable cache folder, one per script under `~/.miyu/var/cache/scripts/`. What was not touched for 30 days is cleared, so keep only what you can make again |
| `MIYU_STATE_DIR` | A state folder that stays (a login, where the last run stopped), one per script. If you delete the script, the state folder is still there, and `miyu check` tells you where |
| `MIYU_IMAGES_DIR` | An empty folder for handing over images, a new one for every call |
| `MIYU_PICTURES_DIR`, `MIYU_VIDEOS_DIR`, `MIYU_DOCUMENTS_DIR`, `MIYU_DOWNLOADS_DIR` | `pictures`, `videos`, `documents` and `downloads` under `~/.miyu/root/`; put files meant for you here. Only sessions on this machine have them, so check they exist before using them |
| `MIYU_CALLER_VENUE` | The kind of session it was called in: `local` on this machine, and the venue id on a chat platform |
| `MIYU_CALLER_OWNER` | Whether the person speaking this turn is you yourself: `1` or `0`. It only tells the script and stops no one; to stop callers, use `Venues` |
| `MIYU_MODEL`, `MIYU_EFFORT` | This turn's model and reasoning effort. Absent when no model is settled yet |

### Handing over images

To have the AI see an image directly, copy it into `MIYU_IMAGES_DIR`:

```python
import os, shutil
shutil.copy("chart.png", os.environ["MIYU_IMAGES_DIR"])
print("Drew 1 chart.")
```

- Taken in file-name order, at most 4; PNG, JPEG, GIF and WebP are recognized, by file content and not by extension.
- One over 5 MiB, or with a side over 8000 pixels, is scaled down first; one that cannot be scaled down is not handed over.
- Only regular files directly in this folder count, and links are not followed.
- The AI does not know about an image that was not handed over; the run log has a `script image dropped` line.
- A call that was killed at its timeout hands over no images; one with an exit code other than `0` still does.

### Under which permissions it runs

It follows the rules for commands the AI runs (see [Permissions and sandbox](permissions.en.md)):

- Full access: not in the sandbox, and the script has all the permissions of your system user.
- Read-only: in the sandbox, and it can write only its own cache, state and image folders and the four folders above, and nowhere else.
- Groups and strangers' private chats on chat platforms: it runs in the sandbox and can write only that session's workspace and its own cache, state and image folders. On Windows no scripts run in these two kinds of session, and on Linux scripts do not run where the sandbox cannot confine Unix sockets either; see [Permissions and sandbox](permissions.en.md#sessions-on-chat-platforms).

The script file itself is in the data root, which the sandbox can still read. Scripts that touch hardware or need `sudo` do not work in the sandbox. On Windows, ones that use WMI (`Get-CimInstance`, `Get-WmiObject`, `wmic` and the like) cannot connect inside the sandbox either; to use them, switch to full access. For the other differences between the sandboxes of each system, see [Permissions and sandbox](permissions.en.md#the-three-platforms).

### After you add one

- When one is added, changed or deleted, the core knows at once, and the tools change from the next turn, with no restart.
- In the terminal, type `/tool-list` to see which tools this session has. The "Scripts" page on the web UI settings page lists all scripts, each with a switch, and "Open folder" opens `~/.miyu/root/scripts/`.
- For the same tool name, the one in `~/.miyu/root/scripts/` wins over one a package brings. One with the same name as another tool is not registered.

A script can also be a link pointing to a file you keep elsewhere, and what the link points at counts; a broken one is skipped. One pointing elsewhere in the data root is not recognized.

### When it is written wrongly

`miyu check` reports:

| What you see | What to do |
|---|---|
| This script was skipped: `Description is missing or empty` | Add `Description` |
| This script was skipped: `Parameters is not valid JSON: …` | The JSON is unfinished or wrong |
| This script was skipped: `Parameters must be a JSON object schema` | Write `"type": "object"` at the top level |
| This script was skipped: `Timeout "…" is not a positive number of seconds` | Write a positive integer |
| This script was skipped: `Clicall "…" is not yes or no` | Write `yes` or `no` |
| This script was skipped: `Venues "…" must list some of local, private, group, each once` | Write only these three, with no repeats |
| This script was skipped: `Role …`, `Scope …` | Write the key names and values as in the table above |
| Script <name> has the same name as another tool and was not registered | Rename the file |
| The core has not picked up script <name> yet | You just added it; check again in a while; if it stays like this, restart the core |
| There is a state folder for the script …, but no such script now | If you do not need it, delete that folder |

## Slash command templates

A Markdown file whose file name is the command name. When you type `/<name> arguments`, the body is expanded with the arguments and sent to the AI as something you said; the timeline shows the line you typed.

### Writing one

`~/.miyu/root/commands/commit-msg.md`:

```markdown
---
description: Draft a commit message for the staged changes
argument-hint: "[style]"
metadata:
  summary_zh: 给暂存的改动写提交说明
---

Read `git diff --cached` and draft a one-line commit message.
Style: $ARGUMENTS
```

Type `/commit-msg short`, and what the AI receives is the body, with `$ARGUMENTS` replaced by "short".

- Name: starts with a lowercase letter, only lowercase letters, digits and `-`, at most 32 characters. Subfolders, files starting with a dot and files that are not `.md` do not count.
- The top section can be left out, and then the whole file is the body.

| Field | Notes |
|---|---|
| `description` | The line in the command list |
| `argument-hint` | A hint for what follows the name |
| `summary_zh`, `summary_ja` under `metadata` | The line in Chinese and in Japanese |

Other fields (`allowed-tools`, `model` and so on) are recognized and not used.

### Arguments

- `$ARGUMENTS` is replaced by all the text after the name, with leading and trailing whitespace removed.
- `$ARGUMENTS[0]` is the first word and `$ARGUMENTS[1]` the second, split on whitespace. Put a value with spaces in English double quotes: for `/commit-msg "very short"`, `$ARGUMENTS[0]` is `very short`. One that is not there is replaced by nothing.
- If the body has no `$ARGUMENTS` at all and you added text, it is appended to the end of the body after a blank line.

### After you add one

- It is looked up each time you type, so a change needs no restart.
- Type `/` in the terminal or the web UI and see whether it is in the command list.
- For the same name, yours wins over one a package brings; one with the same name as a command that comes with Miyu does not count, and the built-in wins.
- Who can use it is the same as for the commands that come with Miyu; see [Slash commands](commands.en.md).

`miyu check` reports "This slash command was skipped: …" (the YAML at the top cannot be read, or is not a table), "Same name as <other>, which covers it; this one is not used" and "Same name as Miyu's built-in /<name>; this one is not used".

## MCP servers

An MCP (Model Context Protocol) server can be connected in two ways: Miyu starts a program on this machine and talks to it over standard input and output; or it connects to an address (Streamable HTTP).

### Writing it into the config

One `[mcp.<name>]` table per server, written into `~/.miyu/etc/config.toml`. Open it with `miyu config edit`, which checks it before saving; `miyu config set` cannot change these tables. It takes effect once saved, with no restart.

One that starts a program on this machine:

```toml
[mcp.notes]
command = ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/home/me/notes"]
env = { LOG_LEVEL = "warn" }
```

On Windows, write paths the Windows way, as TOML single-quoted strings, with each `\` left as it is:

```toml
[mcp.notes]
command = ["npx", "-y", "@modelcontextprotocol/server-filesystem", 'C:\Users\me\notes']
env = { LOG_LEVEL = "warn" }
```

One that connects to an address:

```toml
[mcp.acme-docs]
url = "https://mcp.example.com/mcp"
bearer = { secret = "acme-docs" }
headers = { X-Workspace = "team-a" }
venues = ["local", "private"]
timeout_ms = 120000
clicall = false
```

Store the secret that `bearer` refers to in the secrets file first:

```sh
miyu provider login acme-docs
```

What you paste is not shown.

| Field | Notes |
|---|---|
| Table name `<name>` | The server name: starts with a lowercase letter, only lowercase letters, digits and `-`, at most 32 characters |
| `command` | The command and its arguments, one word per item, not through a shell. Write the first item as an absolute path, as `~/…` (on Windows `~\…` is accepted too), or as just a name to be looked up on `PATH` (`npx`, `uvx`, `docker` and the like). On Windows, a bare name is looked up on `PATH` as `.exe`, `.cmd` and `.bat`; `npx` and `uvx` are `.cmd` and are found all the same. `~` is replaced only in the first item; the arguments after it are given to the program as written. Write only one of this and `url` |
| `env` | Goes with `command`: environment variables for the server |
| `url` | The server's address. Starts with `https://`; `http://` only connects to servers on this machine. Write only one of this and `command` |
| `bearer` | Goes with `url`: the token, sent as `Authorization: Bearer <value>` |
| `headers` | Goes with `url`: other request headers. Names use only letters, digits and `-`; `Authorization`, `Mcp-Session-Id`, `MCP-Protocol-Version`, `Mcp-Method` and `Mcp-Name` cannot be written |
| `venues` | Which sessions get it: some of `local`, `private` and `group`. `["local"]` by default, which gives it only to sessions on this machine |
| `timeout_ms` | The longest to wait for one call, in milliseconds, `1000` to `3600000`, `600000` by default |
| `clicall` | Whether the AI can call this server's tools with `miyu call` inside a command. Yes by default; `true`, `false`, or `"yes"`, `"no"`. For servers that write things or send things, write `false` |

The values of `env`, `bearer` and `headers` are written as text, or as a reference: `{ secret = "<secret name>" }` takes it from the secrets file, and `{ env = "<variable name>" }` takes it from the core's environment variables. Write the token as a reference; do not put its value in the config.

You can also press "Add server" on the "MCP" page of the web UI settings page (`/settings`), choose "Local" or "URL", and fill in the form.

If the config has one with the same name as one a package brings, the one in the config wins, and the one in the package does not start.

### Servers that need a browser login

For a server that accepts only browser authorization and cannot give you a personal token: write only `url` and no `bearer`. Once connected it stays at "Sign-in required", and then:

1. Type `miyu mcp login <server name>`.
2. In the address it prints and opens by itself, click agree. If the browser did not open, open the printed address yourself.
3. When you see "logged in, <server name> connected", you are done.

If the browser is on another machine: after authorizing, paste the whole address in the browser's address bar back into the command line and press Enter. It waits at most 10 minutes. The token is stored in the secrets file, and the core renews it by itself when it is about to expire. When you no longer need it, type `miyu mcp logout <server name>`.

The web UI "MCP" page and the "MCP" page of the terminal settings page also have "Sign in". A server with `bearer` written does not go through sign-in.

### What the AI sees

| What the server gives | What it becomes in Miyu |
|---|---|
| Tools | Tools of the AI, named `mcp__<server name>__<tool name>`. Characters that are not letters, digits, `_` or `-` become `_`, at most 64 characters; a description is at most 2048 characters |
| Resources | Two more tools: `mcp__<server name>__list_resources` lists them page by page, and `mcp__<server name>__read_resource` reads one by its address. If the server has a tool of the same name itself, that one is used |
| Prompts | A slash command `/<server name>:<prompt name>`, in the command list. The text after it is split on whitespace and matched to the arguments the prompt declares, in order, with the last argument taking the whole rest; put a value with spaces in English double quotes. What comes back is sent to the AI as something you said. It works only in sessions on this machine |
| Instructions (`instructions`) | Put at the end of the AI's system prompt, one passage per server, at most 4000 characters |

The read-only mark: a tool the server marks `readOnlyHint: true` does not ask you under any permission mode; one that is not marked is treated like the network kind, so under full access it does not ask, and under read-only it asks you every time. See [Permissions and sandbox](permissions.en.md).

### After you add one

- The "MCP" page of the terminal settings page lists how each server is doing now, "Off", "Starting", "Running", "Reconnecting", "Stopped" or "Sign-in needed", and how many tools it has. The web UI "MCP" page lists them too, and can "Restart", "Edit" and "Remove".
- In the terminal, type `/tool-list` to see whether the tools are there.
- Tools and prompts the server lists but that were not registered: the web UI says "The server lists these, but Miyu didn't register them", and `miyu check` reports them too.

### When it is written wrongly or will not start

- `miyu check` reports "Badly written MCP server: …", with the line number. The one that is written wrongly does not start, and the others work as usual.
- The working directory of a program on this machine is `~/.miyu/var/lib/mcp/<server name>/` (also in the environment variable `MIYU_STATE_DIR`), and it is not in the sandbox. Standard error is in `~/.miyu/var/log/mcp/<server name>.stderr`; if it does not start, look there first.
- One that does not start or that crashed is retried after a while, and stops after 5 failures in a row. After you fix it, press "Restart" on the "MCP" page.
- For a server started with `npx` or `uvx`, you must first install Node, Python and the like yourself.

## Doing more

If you want a program that keeps running, an interface or dashboard page of your own, or you want to give these to other people, make a package: see [Writing a Miyu package](../authors/README.en.md) and [Writing an extension](../authors/extensions.en.md). Put skills, scripts and templates in the package folder's `skills/`, `scripts/` and `commands/`; the format is the same as on this page.

You can also have the AI help you write them. The shipped "Authoring" brings two skills:

- `skill-creator` (writes skills): writes a skill the way a package would have it, checks it and installs it.
- `package-creator` (writes scripts and packages): makes a script into a tool and puts it in a package, checks it and installs it.

In the input box, type `$skill-creator` or `$package-creator` followed by what you want, or say "write a skill" or "write a tool", and the AI reads them by itself. What both skills write are packages; once installed you manage them on the Packages page, see [Packages](packages.en.md).
