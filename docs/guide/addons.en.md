# Add-ons

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

The official package source has four packages you install separately: `embed` (Built-in semantic model), `ocr` (OCR), `render` (Render) and `memes` (Memes). This page has one section per package: what you get once it is installed, how to install it, how to use it, its settings, and what to do when something goes wrong. For the common steps of installing, switching and removing packages, see [Packages](packages.en.md). Chinese version: [addons.md](addons.md).

In paths, `~/.miyu` is the data root (by default `~/.miyu`, on Windows `%USERPROFILE%\.miyu`; if `MIYU_HOME` is set, that one).

| Id | Name | What you get | Supported systems |
|---|---|---|---|
| `embed` | Built-in semantic model | Memories, knowledge bases and stickers can be searched by meaning | Linux x86_64, Linux aarch64, macOS (M series), Windows x86_64 |
| `ocr` | OCR | The tool `ocr` and the command `miyu ocr` | Linux x86_64, macOS (M series), Windows x86_64 |
| `render` | Render | The tool `render_image`, and long replies turned into images on chat platforms | Linux x86_64, macOS (M series), Windows x86_64 |
| `memes` | Memes | Five `meme_*` tools, a dashboard page, a chat platform plugin | Linux x86_64, macOS (M series), Windows x86_64 |

On a system not listed in the table, installing reports "Not available for this system".

## Built-in semantic model (embed)

Without it, finding memories and finding in knowledge bases go only by keywords: if you ask "what editor do I use", the entry that says "Neovim for writing code" does not match. With it installed, search also goes by meaning, and the two results are ranked together. It computes on this machine and does not use the network; the text of your memories and conversations does not leave this machine.

Install:

```sh
miyu pkg install embed
```

The model is granite-embedding-97m-multilingual-r2 (multilingual, 4-bit quantized). Its files are in the package and downloaded with it, about 65 MB for the three files together. The package's program `miyu-embed` has no command to type; the core starts it only when it needs it: it computes one sentence at a time, on a single thread, and exits when there has been no new work for 10 minutes, and is started again next time. It looks at the first 512 tokens of a sentence at most.

First-run setup has this step too: "Turn on the built-in semantic model?", described as "Much better search in memories, knowledge bases, stickers and more, at a much higher memory use and extra CPU on each search". Choose "Yes" and it downloads and installs right then, and writes `models.embedding = "local"`; choose "No" and it writes `"off"`, and only keyword search is used. If the package source has no package that works on this machine, there is no such step.

### Taking effect and building the index

Installing or removing takes effect at once, with no restart of the core. If `models.embedding` is not written, it is `local`, and it is used once installed:

| `models.embedding` | What computes |
|---|---|
| `local` (default) | The `embed` on this machine |
| `off` | Nothing computes; search goes only by keywords |
| `provider/model` | That provider's model; the text of memories and conversations is sent to it |

```sh
miyu config set models.embedding local
```

You do not need to rebuild the index by hand. Vectors are stored separately per model; when you switch models, the new one is filled in and the old ones stay. When you search memories, record a new one, or search a knowledge base, the ones that do not have vectors yet are filled in in the background. Ones not yet filled in can be found only by keywords.

To see how far it has got, run `miyu check` and look at the last few lines:

```text
Semantic model: local:granite-embedding-97m-multilingual-r2, indexing
  Memory: software-engineer 120/120
  Past conversations: software-engineer 300/815
  Knowledge bases: handbook 30/42
```

Each cell is "built/total". If it is not installed, it prints "Semantic model: not installed, keyword search only", and the next line hints `miyu pkg install embed`; with `off` written it prints "Semantic model: off (models.embedding = "off"), keyword search only". With a remote model, the end has one more line, "No auto recall: memories, knowledge bases (no measured threshold for this model; search still works)": only the built-in model automatically recalls memories and knowledge bases, and other models are used only when searching.

### Without it

- Memories: the AI does not associate, and `memory_search` goes only by keywords. See [Memory](memory.en.md).
- Knowledge bases: search goes only by keywords, and automatic recall uses only titles and keywords. See [Knowledge base](knowledge.en.md).
- Stickers: `meme_search` goes only by keywords.

If the shipped "Persona memory" (`base-memory`) has been removed, `embed` is not used even when it is installed.

## OCR (ocr)

Reads the Chinese and English text in images on this machine, and gives it back line by line, from top to bottom. You do not need to install Tesseract or Python separately.

```sh
miyu pkg install ocr
```

After installing it is off; after the confirmation screen it asks "Enable 'ocr' now? [Y/n]", and you answer yes. While it is off the AI has no `ocr` tool, but `miyu ocr` still works.

The models are not in the package: once it is turned on, the package's program downloads them in the background, about 16 MB, from the [oar-ocr release](https://github.com/GreatV/oar-ocr/releases/tag/v0.3.0), and uses them only after checking against the SHA-256 written into it; they are stored in `~/.miyu/var/cache/ocr/paddleocr/`. It follows the system's proxy settings (`HTTPS_PROXY` and the like). The models are the mobile ones from PaddleOCR: PP-OCRv5 to find text and PP-OCRv4 to recognize it.

### Recognizing on the command line

```sh
miyu ocr screenshot.png    # print the text in the image, line by line
miyu ocr                   # see whether the models are downloaded
```

| Form | What it prints |
|---|---|
| `miyu ocr <image>` | The text in the image, line by line. The path is relative to the current directory. If the models are not downloaded, they are downloaded first |
| `miyu ocr` | If downloaded, `model: ready (<model directory>)`; if not, `model: not downloaded yet (16 MB, downloaded the first time it is used)` |
| `miyu ocr -h`, `miyu ocr --help` | Usage |

An error when it cannot recognize is printed on standard error, starting with `miyu ocr: `, exit code `1`.

### The tool ocr the AI uses

The only parameter is `path`: the path of the image, relative to the workspace or absolute. It gives back the text line by line; if it recognized no text at all, it gives back `No text found in the image.`. It waits at most 180 seconds per call. It only reads files, so it works under read-only too.

When the AI writes a script inside a command, it can also use `miyu call ocr --path <image>` to recognize in bulk, and gets `{"lines": [{"text", "box", "score"}]}`: `box` is the left, top, right and bottom of this line on the original image (in pixels), and `score` is the confidence from 0 to 1. For `miyu call`, see the [command line reference](cli.en.md#miyu-call).

### What it recognizes

- Formats: PNG, JPEG, WebP, GIF, BMP, TIFF. They are recognized by file content, and the extension does not count. Phone photos are turned upright by their EXIF.
- Size: a file of at most 50 MiB and at most 80 million pixels.
- Text: Chinese, English, digits and common symbols. Horizontal printed text is recognized best.

What it does not do well: shots taken at an angle, vertical text, handwriting, Japanese kana and Korean.

### When something goes wrong

| What you see | What to do |
|---|---|
| `could not download https://github.com/…` | Cannot reach GitHub. Set up a proxy and try again; the next call downloads again |
| `the download's SHA-256 is …, expected …` | The download was damaged or swapped, and was not installed. Try once more |
| `not an image this tool reads (PNG, JPEG, WebP, GIF, BMP, TIFF)` | The file is not one of these image kinds |
| `the image is larger than 50 MiB`, `the image is too large (…)` | The image is too big; shrink it or cut it up first |
| `no such file: <path>` | The path is wrong. The path of `miyu ocr` is relative to the current directory |

## Render (render)

Draws Markdown as PNG images. It is mainly for chat platforms: when a reply is too long, im draws it as an image and sends that, see [Chat platforms](heads/im.en.md#how-messages-are-shown). In the terminal and the web UI you can also have the AI draw.

```sh
miyu pkg install render
```

It runs once installed, with no need to turn it on. It downloads no models.

### What it can draw

- Headings, paragraphs, lists, quotes and horizontal rules. A single line break inside a paragraph still breaks the line.
- Code blocks, colored when the language is recognized.
- Tables, with the header bold; when a table spans columns, the continuation columns repeat the header first.
- Formulas: `$$…$$` on a line of its own is drawn as a formula; inline `$…$` is replaced with Unicode notation.
- Mermaid diagrams: a code block whose language is `mermaid` is drawn as a diagram. If there are more than 200 nodes and edges, it is drawn as a code block.
- Links: drawn as an image they cannot be clicked, so `(address)` is added after the text. An image `![description](address)` is not drawn, and only the description and the address are kept.
- HTML mixed in: `<br>` becomes a line break, `<b>`, `<i>`, `<s>` and `<code>` become styles, and other tags keep only the text.

At most 20000 characters at a time, and at most 30 seconds of drawing. Long text is split into columns and pages automatically: a page is at most 5000 pixels tall, the image comes out close to square, and there is a pixel limit on several pages together; past it, it reports too long.

### The tool render_image the AI uses

Give either `markdown` (the text to draw) or `path` (a `.md` or `.markdown` file in the workspace), not both. The drawn images are saved as files, and it gives back each page's path and size; it does not send them to you by itself. To look at them, ask the AI to use "Show to the user" (`show`).

- Sessions on this machine: saved in `~/.miyu/root/pictures/`.
- Sessions on chat platforms: saved in `rendered/` in the workspace.

The file name is `render-<a string of characters>-<page>.png`. Something drawn before with the same text, the same settings and the same version of the program is given back as the image that already exists. It has to write files, so it cannot be used under read-only.

```text
Draw the comparison table above as an image and show it to me
```

### Fonts

It uses system fonts first: on Linux it asks fontconfig for a Chinese sans-serif and monospace; on macOS it uses PingFang SC, Menlo and the like; on Windows it uses Microsoft YaHei, Consolas and the like. If a font named in the settings has no Chinese, the body text is switched to a system font that has Chinese. If there is no font with Chinese at all, it cannot draw; see "When something goes wrong" below. It downloads no fonts.

### Settings

| Key | Name in the interface | Default | Notes |
|---|---|---|---|
| `render.theme` | Colours | `paper` | `paper` paper color, `light` near white, `dark` dark grey |
| `render.font` | Font | empty | The font family name for body text, at most 128 characters. Empty follows the system sans-serif |
| `render.code_font` | Code font | empty | The font family name for code. Empty follows the system monospace |
| `render.font_size` | Font size (px) | `36` | `14` to `56` |

A change takes effect at once:

```sh
miyu config set render.theme dark
miyu config set render.font "Noto Serif CJK SC"
```

### For use by other packages

`render`'s name on the bus is `render`, with the method `render.markdown`: another package hands over Markdown and an optional color scheme, and gets back images page by page. If you write packages, see [the bus](../reference/bus.en.md).

The command `miyu render` is for the core to start the package's program; if you type it, it prints only `usage: miyu-render serve`.

### When something goes wrong

| What you see | What to do |
|---|---|
| `no font with Chinese characters is installed; …` | Install a font with Chinese: on Linux install Noto Sans CJK (for example the `noto-fonts-cjk` package); on Windows install Microsoft YaHei or Noto Sans CJK; on macOS check whether the system fonts have been disabled |
| `markdown is longer than 20000 characters` | Split it and draw it in several parts |
| `took too long to draw` | It did not finish in 30 seconds, most likely because the image is too big. Draw it in pieces |
| `the renderer is busy` | An earlier one that timed out has not finished drawing; try again in a while |
| `too long to draw` | It went over the pixel limit; split it and draw in several parts |
| A Mermaid diagram was drawn as code | The diagram is written wrongly, or has too many nodes and edges |

## Memes (memes)

A sticker library: each image has a "Description" (what is drawn in it, what text is on it) and a "Usage" (when it fits in a chat). The AI picks one from the library by meaning and sends it, and can also save an image it sees in a chat.

```sh
miyu pkg install memes
```

It runs once installed, with no need to turn it on. The library is in `~/.miyu/var/lib/memes/library.db`. In a session that cannot show images, this package counts as off.

### The five tools the AI uses

| Tool | Name in the interface | What it does | Parameters |
|---|---|---|---|
| `meme_search` | Pick a sticker | Search by meaning, and give back each one's id, description and usage | `query` (what you want to express, required), `limit` (1 to 20, default 5) |
| `meme_send` | Send a sticker | Send one on its own. By default the turn ends after it is sent; write `end` as `false` to keep talking | `id` (required), `end` |
| `meme_save` | Save a sticker | Save one into the library: a file on this machine, or the nth image of a message in a chat | `reason` (why to save it, required), `path`, or `msg` plus `index` (counted from 1, default 1); `description`, `usage` |
| `meme_edit` | Edit a sticker | Change one's description or usage | `id` (required), `description`, `usage` |
| `meme_delete` | Delete a sticker | Disable one; it can be restored in the dashboard page | `id` (required) |

`meme_save`, `meme_edit` and `meme_delete` write, so they cannot be used under read-only.

Searching by meaning needs the built-in semantic model (`embed`) or the remote model set in `models.embedding`; without one, search goes only by keywords.

When the library has images that can be sent, before each turn's reply the AI gets a dice roll; on a hit, a reminder is added to what the AI is given, asking it to pair this turn with a sticker. For the probability, see the settings below.

### Adding images to the library

- Upload them yourself: on the dashboard page press "Upload", drop in or choose an image, and write a description and usage (required), or press "Let AI write".
- Install an image pack:

  ```sh
  miyu pkg install memes-shorin-collection
  ```

  This is a ready-made set of images (38). They go into the library once installed, and leave it when removed. On the dashboard page, the source of an image pack is "Sticker pack".
- The AI saves them in a chat: ask it to ("save that last image as a sticker"), and it calls `meme_save`. If the AI saw the image itself, it writes the description and usage itself; if it did not write them, they are left to the model that looks at images (`models.vision`), which also judges whether it is a sticker: screenshots, photos, documents and charts are not taken. Where `models.vision` is not set, the AI cannot save one unless it wrote the description itself.

An image already in the library is not saved twice, and the original id is given back. A single image over the limit is shrunk before it is saved; animated images are not shrunk, and one over the limit is not taken.

### The dashboard page

```sh
miyu pkg page memes
```

What "Dashboards" on the web UI settings page opens, and "Open panel" on the im plugin card, is this too.

- The top row: a "Search" box; a source filter ("All sources", "Saved by AI", "Uploaded", "Sticker pack", "Other apps": ones saved in through the bus by other packages); "Show disabled"; "Rebuild search index"; "Upload".
- Below is a grid; click one to see its details: the big image, the "Description" and "Usage" you can change, and "Source", "Reason", "Uses" and "Size". The buttons are "Save", "Disable" (for a disabled one it is "Enable"), "Delete" and "Describe again".
- "Describe again" and "Let AI write" use the model that looks at images to write and fill the boxes in, and you look it over before pressing "Save". If no vision model is set, it says "No vision model configured".
- "Delete" deletes for good, and asks "Delete this sticker permanently?". The AI's `meme_delete` only disables.

### On chat platforms

Stickers are a plugin of im, on by default, and switched per group and per private chat under "Plugins" on the session card. Where it is off, the AI has none of these five tools and does not remind itself to send stickers. See [Chat platforms](heads/im.en.md#plugins).

### Settings

| Key | Name in the interface | Default | Notes |
|---|---|---|---|
| `memes.reminder` | Remind her to send stickers | `true` | Turn it off and no dice are rolled |
| `memes.reminder_probability` | Chance per reply (%) | `3` | `0` to `100` |
| `memes.max_size_mb` | Largest image (MiB) | `5` | `1` to `20` |

A change takes effect at once:

```sh
miyu config set memes.reminder_probability 10
```

The command `miyu memes` is for the core to start the package's program; if you type it, it prints only `usage: miyu-memes serve`. Other packages save into the library and look in it through the name `memes` on the bus (`memes.add`, `memes.search`); see [the bus](../reference/bus.en.md).

### When something goes wrong

| What you see | What to do |
|---|---|
| `Not saved: no vision model could describe it (…)` | Set `models.vision` (see [Models](models.en.md#the-three-uses)), or have the AI look at the image and write the description and usage itself |
| `Not saved: it is a screenshot, photo, document or chart, not a sticker.` | The model that looks at images judged that this is not a sticker. If you really want to save it, upload it yourself on the dashboard page |
| `msg works only in a chat.` | `msg` works only in a session on a chat platform; in a session on this machine use `path` |
| Dashboard page: "This image cannot be shrunk small enough to upload (animations are not shrunk)" | Use a smaller one, or raise `memes.max_size_mb` |
| Dashboard page: "The vision model does not accept images. Choose another in settings" | The model set in `models.vision` cannot take images; switch to another |
| Dashboard page: "Semantic model is off" | Install `embed`, or `models.embedding` is written as `off` |
